# ethereum-optimism/infra Monthly Report (June 2026)

## 🚀 Highlights
In June 2026, development focused heavily on hardening the Superchain’s interoperability layer, specifically addressing stability issues within `op-reth` and `proxyd`. Key achievements included the implementation of a new "agreement" validation strategy for interop transactions and the resolution of critical Consensus Layer (CL) sync recovery deadlocks. The team also prioritized operational resilience by initiating comprehensive runbooks for invalid interop message recovery and improving developer experience through the stabilization of local devnets and the `op-e2e-fuzz` testing suite.

## 🛠️ Key Developments

### Proxyd Enhancements & Interop Validation
Significant work was dedicated to making `proxyd` more robust for interop-heavy environments.
*   **Agreement Strategy:** Introduced an additive `agreement` interop-validation strategy that fans out requests to multiple supervisors and combines verdicts via quorum agreement ([#640](https://github.com/ethereum-optimism/infra/pull/640)).
*   **Consensus Routing:** Added output-root split protection to halt CL consensus if unresolvable splits occur, ensuring data integrity across backends ([#646](https://github.com/ethereum-optimism/infra/pull/646)).
*   **Genesis Support:** Fixed a bug allowing CL backends to report block height 0, facilitating smoother network starts ([#645](https://github.com/ethereum-optimism/infra/pull/645)).
*   **Observability:** Added specific metrics for interop validation outcomes to improve monitoring ([#642](https://github.com/ethereum-optimism/infra/pull/642), [#643](https://github.com/ethereum-optimism/infra/pull/643)).

### Infrastructure & Tooling Updates
*   **Peer Management:** The `peer-mgmt-service` was updated to support external peers, allowing nodes to remain reachable internally without exposing a public RPC address ([#647](https://github.com/ethereum-optimism/infra/pull/647)).
*   **Documentation:** Updated `op-conductor-ops` to reflect its transition to a standard installable Python package layout ([#639](https://github.com/ethereum-optimism/infra/pull/639)).
*   **Dependency Management:** Initiated a more aggressive synchronization strategy for `op-revm` to stay aligned with upstream `revm` releases, specifically targeting support for the Amsterdam hardfork.

## 🐛 Issues & Triage

### Closed Issues
*   **Interop Recovery:** Resolved a critical issue where the `op-reth` transaction pool failed to resume after a failsafe event. The fix identified that both `op-reth` and `op-rbuilder` required restarts to clear evicted state ([#21149](https://github.com/ethereum-optimism/infra/issues/21149)).
*   **Devstack Fixes:** Corrected a configuration error in the interop preset where the Execution Layer was incorrectly shared between the supernode and light node sequencer ([#21158](https://github.com/ethereum-optimism/infra/issues/21158)).
*   **Mainnet Readiness:** Closed the setup for `op-challenger-runner` using `kona` and `op-reth`, confirming historical proof support for OP Mainnet ([#19517](https://github.com/ethereum-optimism/infra/issues/19517)).

### New & Active Issues
*   **CL Sync Deadlocks:** A major investigation is ongoing regarding `op-supernode/op-reth` sync stalls. The team identified a cyclic deadlock in `reth`'s `StateTrieOverlayManager` involving `rayon` computes. Two candidate fixes are being vetted for upstream submission ([#21076](https://github.com/ethereum-optimism/infra/issues/21076)).
*   **Test Flakiness:** The `op-e2e-fuzz` suite has been plagued by 15-minute timeouts. The root cause was identified as the package `init()` running full genesis pipelines for all hardfork modes at startup, oversubscribing CPU resources ([#21191](https://github.com/ethereum-optimism/infra/issues/21191)).
*   **Protocol Limits:** Discussions are maturing around adding a protocol-level cap for sequencer rebates to prevent excessive computation via 100% refunds ([#20709](https://github.com/ethereum-optimism/infra/issues/20709)).

## 💬 Community & Collaboration
The month saw deep technical coordination between the infrastructure and protocol teams, particularly regarding the `op-reth` stack. There is a clear shift toward manual operational safety, as evidenced by the decision to move away from auto-recovery in `op-conductor` in favor of human-led runbooks for complex reorg scenarios ([#20006](https://github.com/ethereum-optimism/infra/issues/20006)). Collaboration with the upstream `reth` team remains a priority as the infra team works to resolve low-level concurrency bugs discovered during high-load sync testing.

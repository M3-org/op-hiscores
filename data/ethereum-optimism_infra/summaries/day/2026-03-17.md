# ethereum-optimism/infra Daily Update (Mar 17, 2026)

## OVERVIEW 
Today's development focused on enhancing transaction logging in `proxyd` and addressing several flaky tests across various Optimism components, improving CI stability.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced Transaction Forwarding Logging
A new feature has been added to `proxyd` to improve observability of `sendRawTransaction` forwarding. When enabled, `proxyd` will now log detailed information including the transaction hash, request ID, backend, backend group, and duration after a backend responds. This enhancement provides better insights into transaction processing and performance. ([#569](https://github.com/ethereum-optimism/infra/pull/569))

## ACTIVE ISSUES

### op-node: On the Initial EL Sync UX and Correctness ([#17631](https://github.com/ethereum-optimism/infra/issues/17631))
Discussion continues on the behavior of `op-node` marking the reached target as finalized after initial EL Sync, even if the block is not actually finalized.
- **trianglesphere** proposed a solution involving continuing EL sync to the unsafe head and using a different finalization gadget to set the finalized head. Options for the finalization gadget include a command-line flag, an RPC URL for a trusted checkpoint provider, looking at L1 for the last finalized head, or an arbitrary delay of 12 hours to 10 days after EL sync finishes. They lean towards a command-line flag or a 12-hour fallback.
- **karlfloersch** expressed support for the operational simplicity of delaying the finalized head by the sequencing window.
- **trianglesphere** also clarified that this issue is more likely to be hit with light CL and that sequencer nodes are typically fully synced before service.

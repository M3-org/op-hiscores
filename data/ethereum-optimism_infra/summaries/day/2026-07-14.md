## ACTIVE ISSUES

### Reth Integration Test Flakiness
The `reth-optimism-node` integration test `p2p_version::peers_negotiate_eth_69` continues to experience intermittent `SIGSEGV` crashes during teardown [#20973]. A recent recurrence on an unrelated branch confirms its non-deterministic nature. The issue is suspected to stem from a race condition during runtime teardown, specifically related to the payload builder service switching to `spawn_critical_os_thread` and discarding its `JoinHandle`, leading to orphan OS threads accessing freed Tokio internals.

### Kona Host Game Review
The issue regarding the soundness review of host game input and witness generation for Kona [#18430] was reopened. This is due to a remaining TODO in the `OPSuccinctDataFetcher` at `rust/kona/sp1/crates/host/src/fetcher.rs:168` that references this issue, specifically regarding adding retries for all requests.

### RPC Default Binding Address
The discussion around defaulting RPC binding to `127.0.0.1` instead of `0.0.0.0` for services [#16487] was closed as "not planned." The reasoning is that for Docker images, `0.0.0.0` is the correct default to ensure reachability from outside the container. Switching to `127.0.0.1` would require additional overrides, adding complexity without significantly improving security, as privileged APIs are already opt-in.

### Pre-Regolith Test Removal in op-e2e
The issue concerning the removal of pre-Regolith tests in `op-e2e` or fixing `op-reth`'s system transaction return type [#21451] is being folded into a larger effort [#21744]. This larger effort aims to retire the in-process `op-geth` L2 EL in `op-e2e` system tests, which would resolve the pre-Regolith test dependency by likely deleting them and requiring Bedrock/Regolith co-activation.

# ethereum-optimism/infra Daily Update (Jun 11, 2026)

## OVERVIEW 
The day saw significant progress in `proxyd` stability and maintainability with bug fixes for instrumentation and IPv6 address parsing, alongside a major refactor for transaction filtering. Several long-standing issues related to `op-program` and `superchain-ops` tooling were also closed.

## KEY TECHNICAL DEVELOPMENTS

### `proxyd` Stability and Refactoring
Two critical bug fixes were implemented for `proxyd`, addressing issues with unserviceable request instrumentation and correctly parsing IPv6 remote addresses. A substantial refactoring unified the transaction filter on the submission path, improving code organization and maintainability.
- Bug Fixes: [#657](https://github.com/ethereum-optimism/infra/pull/657), [#656](https://github.com/ethereum-optimism/infra/pull/656)
- Code Refactoring: [#654](https://github.com/ethereum-optimism/infra/pull/654)

### Development Workflow Improvements
The `proxyd` linting process was standardized to match CI, ensuring local development environments align with continuous integration checks.
- Other Work: [#650](https://github.com/ethereum-optimism/infra/pull/650)

## CLOSED ISSUES

### `op-program` Deprecation and Related Fixes
Several issues related to `op-program` were closed due to its deprecation. This includes switching CI jobs to `kona-proof`, rebuilding program prestate, and fixing `vm-compat` for go1.25.
- [#19789](https://github.com/ethereum-optimism/infra/issues/19789), [#17867](https://github.com/ethereum-optimism/infra/issues/17867), [#18334](https://github.com/ethereum-optimism/infra/issues/18334)

### `superchain-ops` Tooling and Documentation Enhancements
Improvements were made to the `superchain-ops` tooling, including addressing issues with monorepo dependency updates, checking Ledger device connections, and updating documentation for simulation links.
- [#424](https://github.com/ethereum-optimism/infra/issues/424), [#417](https://github.com/ethereum-optimism/infra/issues/417), [#789](https://github.com/ethereum-optimism/infra/issues/789)

Issues concerning the `AccountAccessParser` and simulation logic were resolved, specifically regarding dynamically finding slots for normalized hashing and handling tightly packed variables. Stack signing now also validates the selected signer against the target Safe.

## ACTIVE ISSUES

### `syncmode.offset-el-safe` Failure with `--minimal` Nodes
Discussion on issue [#21465](https://github.com/ethereum-optimism/infra/issues/21465) regarding `default syncmode.offset-el-safe` failing for `--minimal` nodes continued. The root cause was identified: `--minimal` prunes block bodies, which are necessary for `op-node`'s EL sync to read L1-info deposit transactions. Therefore, `--minimal` is not a supported `op-reth` configuration. The recommended solution is to **never prune block bodies** on an OP Stack node. Instead, prune only state and receipt segments. Documentation is being updated to reflect supported pruning configurations and the `--syncmode.offset-el-safe` flag, relaxing the previous "no pruning" language. The issue highlights that `op-node` cannot safely pick an `offset-el-safe` due to its inability to read the execution client's pruning configuration, and lowering the offset to `0` is dangerous.

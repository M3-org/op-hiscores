# ethereum-optimism/infra Daily Update (May 27, 2026)

## OVERVIEW 
Today's development focused on enhancing `proxyd` with a new interop filter client and addressing several critical issues related to `op-supernode` stability and `op-reth` bootstrapping.

## KEY TECHNICAL DEVELOPMENTS

### `proxyd` Interoperability Client Update
The `proxyd` service was updated to switch from `op-geth`'s `InteropClient` to the `optimism` monorepo's `InteropFilterClient`. This change improves the handling of access lists and bumps the `optimism` dependency to the latest develop HEAD. ([#635](https://github.com/ethereum-optimism/infra/pull/635))

## NEWLY OPENED PULL REQUESTS

- [#636](https://github.com/ethereum-optimism/infra/pull/636) chore(deps): bump go.opentelemetry.io/otel from 1.40.0 to 1.41.0 in /proxyd: This PR updates the OpenTelemetry Go dependency in the `proxyd` service.

## CLOSED ISSUES

### Supernode Stability and Flaky Tests Resolved
Several issues related to `op-supernode`'s robustness and flaky tests were closed today. This includes fixes for `op-supernode`'s rewind/invalidation path, which was prone to deadlocks and infinite retry loops ([#20929](https://github.com/ethereum-optimism/infra/issues/20929)). Additionally, a recurring flaky test, `TestSupernodeResyncResumesAtActivation_PostActivation`, was addressed ([#20944](https://github.com/ethereum-optimism/infra/issues/20944)), and another flake, `TestSupernodeLogBackfill_HappyPath`, was closed as the underlying issue was already fixed on `develop` ([#20690](https://github.com/ethereum-optimism/infra/issues/20690)).

### `op-reth` Bootstrap Incompatibility Fixed
An issue where `op-reth`'s minimal Bedrock bootstrap (`init-state --without-ovm`) was incompatible with storage v2, leading to node panics, has been resolved. This was confirmed to be fixed in `op-reth/v2.2.5`. ([#20821](https://github.com/ethereum-optimism/infra/issues/20821))

### L2CM Feature Flag Drift Prevention
An issue concerning silent drift between feature flag definitions and the CI matrix for L2CM was closed. The resolution involves documenting all necessary updates when adding new dev or system features. ([#20340](https://github.com/ethereum-optimism/infra/issues/20340))

## NEW ISSUES

### Supernode CL Sync Recovery Stall
A new issue has been opened regarding `op-supernode`/`op-reth` CL sync recovery stalling when `SafeDB`/bookkeeping references an EL-missing block. This was observed during recovery of `bn-interop-jnt-v2` supernode 3. ([#21076](https://github.com/ethereum-optimism/infra/issues/21076))

## ACTIVE ISSUES

### L2CM DevFeatures Removal
Issue [#20084](https://github.com/ethereum-optimism/infra/issues/20084) discusses the removal of the `DevFeatures` system to make L2CM the default codepath. The latest comment indicates that this issue has been removed from the L2CM project and is now a general backlog item.

### L2CM Integration into L2 Genesis
Issue [#20903](https://github.com/ethereum-optimism/infra/issues/20903) focuses on refactoring `L2ContractsManager` to be the source of truth for predeploy setup at L2 Genesis. Recent comments explore potential implementation strategies, including refactoring `L2Genesis.s.sol` to etch proxies, preinstalls, and `ConditionalDeployer`, and executing the NUT bundle. A potential complication highlighted is the bidirectional mapping between forks and contract releases, which could introduce complexity.

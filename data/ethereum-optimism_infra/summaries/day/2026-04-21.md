Today, development focused on resolving several long-standing issues, including output root mismatches in Kona and the deprecation of `toml` dependency. A new pull request was opened for `proxyd` to skip consensus polling for forced candidate backends.

## CLOSED ISSUES

### Kona Interoperability and Output Root Mismatch Resolution
Several issues related to Kona's interoperability and output root mismatches were closed. This includes [#19848](https://github.com/ethereum-optimism/infra/issues/19848), which addressed an output root mismatch after deposit-only block replacement during message expiry consolidation. The resolution involved multiple merged prerequisites, including configurable message-expiry windows, challenger passing `--depset-cfg` to `kona-host`, and removing an obsolete replacement deposit transaction.

### Contract Feature Flag Integration
Issues concerning the integration of feature flags for OPSuccinct in contracts were closed. This includes [#18419](https://github.com/ethereum-optimism/infra/issues/18419) for creating the feature flag and [#18420](https://github.com/ethereum-optimism/infra/issues/18420) for adding it to OPCM `_devFeatureBitmap`.

### Documentation Dependency Cleanup
The issue [#20017](https://github.com/ethereum-optimism/infra/issues/20017), which involved removing the unused `toml` npm dependency from the documentation, was closed.

### Kona Interop Application Behaviors and Conditional Deployment
The issue [#18742](https://github.com/ethereum-optimism/infra/issues/18742) regarding Kona interop application behaviors was closed as the work had been completed. Additionally, [#19311](https://github.com/ethereum-optimism/infra/issues/19311), concerning the conditional deployment of `CrossL2Inbox` in `kona-node` and interop, was closed following a relevant pull request.

### Op-Geth Deprecation Clarification
The issue [#20203](https://github.com/ethereum-optimism/infra/issues/20203), which inquired about the mandatory use of `op-reth` and the continued use of `op-geth` with `op-node`, was closed with a clarification that `op-geth` can be used until May 31st.

## ACTIVE ISSUES

### Flaky Test: `TestUnsafeGapFillAfterUnsafeReorg_RestartL2CL`
The issue [#19936](https://github.com/ethereum-optimism/infra/issues/19936) reports a flaky test `TestUnsafeGapFillAfterUnsafeReorg_RestartL2CL`. Recent comments confirm its flakiness on both `op-geth` and `op-reth` environments, indicating the underlying race condition is not specific to `reth`. A fix investigation has been launched.

### Kona-Interop: Review Access of Internally Created Blocks
Discussion on [#19266](https://github.com/ethereum-optimism/infra/issues/19266) highlights a potential issue in `kona-interop`'s consolidation logic. While the specific concern about re-querying replaced, non-canonical blocks was addressed, a new problem was identified: generated receipts for replacement blocks are not stored. This could lead to consolidation failures if other messages reference these deposit-only blocks.

### Flaky Test: `TestReorgUnsafeHead`
Issue [#20198](https://github.com/ethereum-optimism/infra/issues/20198) reports a flaky test `TestReorgUnsafeHead`. A proposed fix in ethereum-optimism/optimism#20201 (draft) addresses the root cause: asynchronous updates of `UnsafeL2` and `latestHead` in `op-node` leading to stale data being used by the sequencer. The fix involves replacing `time.Sleep` with a poll on `SyncStatus().UnsafeL2.Hash` before starting the sequencer.

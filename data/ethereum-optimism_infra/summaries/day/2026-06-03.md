## ACTIVE ISSUES

### `op-supernode`/`op-reth` CL Sync Recovery Stalls ([#21076](https://github.com/ethereum-optimism/infra/issues/21076))
The issue describes stalls in CL sync recovery for `op-supernode` when `op-reth`'s EL-missing block references cause bookkeeping discrepancies. Recent comments confirm a successful 6-hour soak test with a two-patch fix addressing a cyclic deadlock in `reth`'s `StateTrieOverlayManager` and `DeferredTrieData` machinery. The fix prevents locks from being held across blocking `rayon` computes. The issue is now flagged for the `reth` team for an upstream fix.

### SDM: Add a Limit for SDM Refunds ([#20709](https://github.com/ethereum-optimism/infra/issues/20709))
Discussion on this issue revolves around adding a protocol-level upper bound for sequencer rebates. The latest comments suggest enforcing `MAX_GAS_LIMIT` regardless of the refund amount, effectively capping the maximum computation a sequencer can perform, even with 100% refunds. It's believed this can be hardcoded in the node software.

### State-persistent Partial DoS in OptimismPortal2 ([#20820](https://github.com/ethereum-optimism/infra/issues/20820))
A brief comment "Wtf man" was added, indicating concern or surprise regarding the issue of a state-persistent partial DoS vulnerability in `OptimismPortal2` via high-gas deposits.

### Add Test for `relayMessage` Gas Changes ([#14609](https://github.com/ethereum-optimism/infra/issues/14609))
This issue, which was previously closed, has been reopened. The reason for reopening is that there are still TODOs in the codebase referencing it, specifically in `L1CrossDomainMessenger.t.sol` and `L2CrossDomainMessenger.t.sol`. These TODOs are waiting for a stable Foundry release that includes `foundry-rs/foundry#9904` to enable `default.isolate = true` for tests, which would allow checking for EVM gas schedule changes that could cause `relayMessage` to fail.

## ACTIVE ISSUES

### op-geth Decoupling: Migrating Tests and Client Implementation
Discussions on [#20265](https://github.com/ethereum-optimism/infra/issues/20265) (opgeth-decoupling: migrate tests) highlighted two key considerations for test migration:
- **Receipt index-correlation breaks:** Tests that correlate `txs[i]` with `receipts[i]` by position will break when migrating to `InfoAndUserTxs` due to the exclusion of synthetic `0x7E`/`0x7D` transactions. Tests must filter receipts in lockstep or use paired accessors.
- **Lagoon's trailing `0x7D` post-exec tx:** Lagoon+ chains include a `0x7D` post-exec tx, requiring tests to handle this in the same way as deposits, especially when fetching full L2 blocks.

On [#20264](https://github.com/ethereum-optimism/infra/issues/20264) (opgeth-decoupling: make op-service/sources the OP-aware eth client), the design for L2 transaction representation was resolved:
- **No `optypes.Transaction` wrapper:** Instead of a wrapper, L2 transaction accessors will be partitioned by transaction class.
- **New `apis.EthClient` methods:** `InfoAndUserTxs` (excludes synthetic OP types), `InfoAndDeposits` (deposits as op-core structs), and `InfoAndFirstDeposit` (header + first tx) will be added.
- **Lagoon's `0x7D` routing:** The `0x7D` PostExecTx in Lagoon+ blocks is a canonical block transaction and must be routed out by accessors, similar to `0x7E` deposits.

For [#20262](https://github.com/ethereum-optimism/infra/issues/20262) (opgeth-decoupling: create op-core/types), a design note clarified:
- **Transition-only helpers:** `*types.Transaction` helpers like `IsDepositTx` are temporary and will be deleted after the final cutover to upstream go-ethereum, as upstream `*types.Transaction` cannot hold deposit or post-exec transactions.
- **`PostExecTx` as canonical block transaction:** In Lagoon, `PostExecTx` is a canonical block transaction, participating in the L2 block tx list, which necessitates its handling in the decode path.

Regarding [#20263](https://github.com/ethereum-optimism/infra/issues/20263) (opgeth-decoupling: swap call-sites to op-core/*), it was noted that:
- **`optypes` helpers are transition scaffolding:** The `optypes` helpers are temporary and designed to allow call sites to drop dependency on op-geth's `Transaction` methods before the L2 transaction representation changes. They are not meant for building new long-lived APIs.
- **Prefer direct decoding:** Where possible, direct decoding to `optypes.DepositTx` via `UnmarshalDepositTx` is preferred over routing through `*types.Transaction` helpers.

# ethereum-optimism/infra Daily Update (Mar 12, 2026)
## OVERVIEW 
Today's development focused on a critical bug fix in `proxyd` to address transaction validation service errors. Discussions on existing issues highlighted concerns about repository size and a critical error in `op-node` related to deposit attribute failures.

## KEY TECHNICAL DEVELOPMENTS

### `proxyd` Transaction Validation Fix
A bug in `proxyd` causing warning logs due to clients canceling transaction validation requests has been fixed. This involved separating the context for the transaction validation middleware to prevent premature cancellations. ([#567](https://github.com/ethereum-optimism/infra/pull/567))

## NEWLY OPENED PULL REQUESTS
A new pull request was opened to update the `black` dependency from version 25.1.0 to 26.3.1 in the `/op-conductor-ops` directory. ([#568](https://github.com/ethereum-optimism/infra/pull/568))

## CLOSED ISSUES
No issues were closed today.

## NEW ISSUES
A critical issue was reported concerning the `op-node` where a `CriticalErrorEvent` for deposits-only attribute failures leads to a permanent node crash loop. This can occur under specific conditions, particularly involving the SuperAuthority deny path. ([#19509](https://github.com/ethereum-optimism/infra/issues/19509))

## ACTIVE ISSUES

### Repository Size Bloat
The issue regarding the `optimism` repository's significant size bloat due to binaries and artifacts in its history continues to be a concern. A recent comment highlighted that the `.git` directory is 1.04 GB (packed), with the history being approximately 6.5 times larger than the current codebase. The commenter expressed frustration that cloning the repository takes over 2 hours and questioned why this issue isn't prioritized, noting that rust crates are not published to `crates.io` and can cause download timeouts. ([#19241](https://github.com/ethereum-optimism/infra/issues/19241))

### `op-node` Critical Error Event for Deposits-Only Attributes
Discussion on the newly opened issue [#19509](https://github.com/ethereum-optimism/infra/issues/19509) included an alternative approach suggested by Claude ([#19465](https://github.com/ethereum-optimism/optimism/pull/19465)) and Claude's attempt at writing tests to reproduce the issue ([#19466](https://github.com/ethereum-optimism/optimism/pull/19466)). The commenter noted that the proposed tests are too narrowly scoped and that integration tests would provide more confidence in a fix.

### Mismatch in Batcher Configuration Description
A pull request ([#2000](https://github.com/ethereum-optimism/infra/pull/2000)) was opened to address the issue where the configuration variable `max-blocks-per-span-batch` has an incorrect description and example, which actually belongs to `check-recent-txs-depth`. ([#1933](https://github.com/ethereum-optimism/infra/issues/1933))

# ethereum-optimism/infra Daily Update (Mar 12, 2026)
## OVERVIEW 
Today's development focused on a critical bug fix in `proxyd` to address transaction validation service errors. Additionally, new issues were raised concerning repository size and node stability, alongside a new pull request for dependency updates.

## KEY TECHNICAL DEVELOPMENTS

### `proxyd` Transaction Validation Fix
A bug in `proxyd` causing transaction validation service errors due to client cancellations was fixed. This involved separating the context for the transaction validation middleware to prevent premature cancellations. ([#567](https://github.com/ethereum-optimism/infra/pull/567))

## NEWLY OPENED PULL REQUESTS
A new pull request was opened to update the `black` dependency from version 25.1.0 to 26.3.1 in the `/op-conductor-ops` directory. ([#568](https://github.com/ethereum-optimism/infra/pull/568))

## CLOSED ISSUES
No issues were closed today.

## NEW ISSUES

### Critical Node Stability Concerns
A new critical issue was reported regarding the `op-node` where a `CriticalErrorEvent` for `DepositsOnlyPayloadAttributesRequestEvent` failures can lead to a permanent node crash loop. This is particularly concerning under conditions involving the SuperAuthority deny path. ([#19509](https://github.com/ethereum-optimism/infra/issues/19509))

## ACTIVE ISSUES

### Repository Bloat and Cloning Challenges
Discussion continues on the significant size of the `optimism` repository, with the `.git` directory being 1.04 GB (packed) compared to 157 MB of actual content at HEAD. A recent comment highlights the severe impact, stating it takes over 2 hours to clone the repository and questions why this isn't prioritized, noting the difficulty for teams to work with or import the codebase. ([#19241](https://github.com/ethereum-optimism/infra/issues/19241))

### `op-node` Critical Error Event Handling
The issue regarding `op-node` crashing due to `CriticalErrorEvent` for `DepositsOnlyPayloadAttributesRequestEvent` failures is being actively discussed. An alternative approach suggested by Claude (PR #19465) and Claude's attempt at writing unit tests (PR #19466) were mentioned, though the latter is considered too narrowly scoped for confidence in the fix, emphasizing the need for integration tests. ([#19509](https://github.com/ethereum-optimism/infra/issues/19509))

### Mismatched Batcher Configuration Description
A pull request ([#2000](https://github.com/ethereum-optimism/infra/pull/2000)) has been opened to address the mismatch in the description and example for the `max-blocks-per-span-batch` configuration variable, which currently incorrectly references `check-recent-txs-depth`. ([#1933](https://github.com/ethereum-optimism/infra/issues/1933))

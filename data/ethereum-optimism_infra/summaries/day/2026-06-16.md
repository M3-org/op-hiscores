# ethereum-optimism/infra Daily Update (Jun 16, 2026)
## OVERVIEW 
Today's development focused on a critical bug fix in `proxyd` to improve log readability for unexpected block tags. Additionally, several issues related to ZK Dispute Game bond claiming and ZK execution support were actively discussed and some were closed.

## KEY TECHNICAL DEVELOPMENTS

### Improved Logging for `proxyd`
A bug fix was implemented in `proxyd` to ensure that unexpected block tags are logged as decimal integers instead of hexadecimal values, making them easier to read and interpret. This change enhances the clarity of `proxyd`'s logging output. ([#661](https://github.com/ethereum-optimism/infra/pull/661))

### ZK Dispute Game Bond Claiming Resolution
The issue concerning the handling of `address(0)` bond credit claiming in `ZKDisputeGame` was closed, with the work being tracked in a new issue in the `optimism` repository. This decision was made after discussions concluded that the scenario is unlikely and an honest challenger should prevent such occurrences. ([#19743](https://github.com/ethereum-optimism/infra/issues/19743), [#21420](https://github.com/ethereum-optimism/infra/issues/21420))

## ACTIVE ISSUES

### ZK Execution Support in `vm-runner`
Discussions on [#18325](https://github.com/ethereum-optimism/infra/issues/18325) continued regarding updating `vm-runner` to support ZK proof programs. The latest comment suggests extracting relevant parts of the proposer to minimize new code. Earlier discussions noted that actual ZK execution would need to be in Rust due to `sp1` dependency, with options to embed the Rust executor or add an option to `vm-runner`.

### ZK Proofs in CI and Local Development
The issue [#21409](https://github.com/ethereum-optimism/infra/issues/21409) is actively discussing the strategy for ZK proofs in CI and local development. The latest comment recommends using a mock prover. It also suggests that if production infrastructure for local proving is established, proving on op-sepolia via the regular proposer fast-finality path could be considered, but proving in CI is deemed too expensive for minimal benefit.

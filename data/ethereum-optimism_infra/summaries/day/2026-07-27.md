# ethereum-optimism/infra Daily Update (Jul 27, 2026)
## OVERVIEW 
Today's development focused on enhancing `proxyd` with new per-RPC-call metrics for usage and error-rate SLOs, migrating `bailiff` to a Wolfi base for improved security, and updating CI factory pins.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced `proxyd` Metrics and Stability
`proxyd` received significant updates, including the addition of per-RPC-call metrics to track usage and error rates. These new metrics, `proxyd_rpc_calls_total`, provide detailed insights into individual JSON-RPC calls, their outcomes, and associated metadata like backend name, method, status code, and transport. This enhancement is crucial for monitoring and maintaining the service level objectives (SLOs) of `proxyd`. ([#676](https://github.com/ethereum-optimism/infra/pull/676))

### Infrastructure Security and Build Process Improvements
The `bailiff` Dockerfile was migrated from Alpine to `chainguard/wolfi-base:latest` for both build and runtime stages, aligning it with the security practices of other services in the repository. This change improves the security posture of the `bailiff` service. Additionally, CI factory pins were updated to the latest `main` commit, ensuring that `build-images.yaml` and `build-images.apko.yaml` workflows use the most recent and stable versions of `ethereum-optimism/factory` actions and reusable workflows. ([#675](https://github.com/ethereum-optimism/infra/pull/675), [#677](https://github.com/ethereum-optimism/infra/pull/677))

## ACTIVE ISSUES

### PreimageOracle Gas Reserve for Glamsterdam Upgrade
Discussion continues on increasing `PreimageOracle.PRECOMPILE_CALL_RESERVED_GAS` before the Glamsterdam upgrade ([#19380](https://github.com/ethereum-optimism/infra/issues/19380)). The latest comment from joshklop suggests that the issue might be stale as written, as the current `100_000` gas reserve is primarily for precompile call setup, not for guaranteeing entire function completion. The EIP-8037/8038 drafts would make the proposed `200_000` insufficient if the goal is whole-function completion, potentially requiring a reserve closer to `400_000`. The recommendation is to either close the issue as unnecessary for correctness (while adding Amsterdam gas-estimation/regression coverage) or rewrite it to explicitly guarantee whole-function success at the guard threshold with an updated value.

### Flaky Test: `TestUnsafeChainNotStalling_CLSync` Regression
The `TestUnsafeChainNotStalling_CLSync` family of tests is regressing again after a previous fix ([#21041](https://github.com/ethereum-optimism/infra/issues/21041)). A recent occurrence on 2026-07-27 showed a total EL-backfill stall, where the follower `op-reth` failed to re-establish a peer connection after the sequencer's `op-reth` disconnected. This indicates an EL peer-management defect rather than a test budget issue. The previous analysis by pauldowman on 2026-05-26 also concluded that the bug was an `op-reth` Engine API stall, not a test budget problem, and suggested that a fix for a similar issue (`fix(op-reth): clamp sync_target past best_block in advance_sync`) might resolve it. Further investigation into the EL peer-management defect is warranted.

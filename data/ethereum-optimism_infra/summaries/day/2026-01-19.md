The migration of Docker builds from CircleCI to GitHub Actions has been completed, streamlining the CI/CD process. This involved updating configuration files to use GitHub Actions for pushing to the `images` registry and removing deprecated CircleCI jobs, while retaining testing, linting, and binary release functionalities. ## ACTIVE ISSUES

### op-supernode: Reset Handling
Discussions continued regarding the `op-supernode`'s reset handling, particularly concerning the `engine_forkchoiceUpdatedV1` behavior. The team is exploring several options, including a temporary hack to update to a synthetic block, aligning with existing reorg mechanisms, or adding a new Engine API method. The current plan is to proceed with the temporary hack for now and revisit other options later. ([#18740](https://github.com/ethereum-optimism/infra/issues/18740))

### op-reth: Batcher Throttling
The discussion on `op-reth` batcher throttling highlighted that `op-reth` provides both throttle mechanisms implemented in its payload builder, but lacks corresponding tests. In contrast, `op-rbuilder`'s payload builder includes comprehensive tests for data availability, block size limits, and transaction size limits. ([#18764](https://github.com/ethereum-optimism/infra/issues/18764))

### op-reth <-> op-geth Connection Flakiness
A pull request related to fixing the `op-reth` <-> `op-geth` connection flakiness in system tests was brought to attention. This issue, previously identified as a critical bug affecting test stability and potential production compatibility, is being actively addressed. ([#18570](https://github.com/ethereum-optimism/infra/issues/18570))

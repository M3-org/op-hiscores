# ethereum-optimism/infra Daily Update (May 14, 2026)
## OVERVIEW 
Today's development focused on refactoring the `proxyd` component to improve consensus tracking by bundling CL sync body data. Active discussions continued on several flaky tests and a batcher synchronization issue.

## KEY TECHNICAL DEVELOPMENTS

### `proxyd` Consensus Tracking Refactor
The `proxyd` component saw a significant refactor to bundle `CLSyncBody` and `CLL1Num` into `ConsensusTrackerState`. This change ensures these critical consensus layer synchronization bodies and L1 numbers travel through a single Redis key, improving error handling and consistency with existing execution layer fields. ([#622](https://github.com/ethereum-optimism/infra/pull/622))

### Persistent Flakiness in Acceptance Tests
Several acceptance tests continue to exhibit flakiness, indicating underlying timing or synchronization issues. `TestELSyncSafeRetractedByOffset` ([#20334](https://github.com/ethereum-optimism/infra/issues/20334)) failed again, even after increasing retry attempts, suggesting a deeper bug. Similarly, `TestWithdrawal_Permissioned` ([#20345](https://github.com/ethereum-optimism/infra/issues/20345)) and `TestNotTruncateDatabaseOnRestartWithExistingDatabase` ([#20649](https://github.com/ethereum-optimism/infra/issues/20649)) also experienced repeated failures, with the latter showing timeouts where the safe head failed to catch up to the unsafe head. Discussions highlight the need for further investigation beyond simple retry increases.

### `op-batcher` Rollup Config Synchronization
The issue of `op-batcher` not staying in sync with `op-node` rollup configurations ([#18178](https://github.com/ethereum-optimism/infra/issues/18178)) remains active. A new comment reported a similar issue when starting a node from scratch with `op-reth` and `op-node`, encountering an error related to parsing L1 info deposit transactions. This suggests the problem might be broader than initially thought, affecting various components during node synchronization.

# ethereum-optimism/infra Daily Update (Apr 15, 2026)
## OVERVIEW 
Today's focus was primarily on refining the L2 Contract Messenger (L2CM) upgrade mechanism, with several related issues being closed or updated. A new feature for `proxyd` was proposed to add a startup metric with build information. Discussions continued on supporting SuperDisputeGame deployment and sequencer RPC endpoint redundancy.

## KEY TECHNICAL DEVELOPMENTS

No completed work to report today.

## NEWLY OPENED PULL REQUESTS
A new pull request, [#604](https://github.com/ethereum-optimism/infra/pull/604), was opened to add a `proxyd_up` metric with build information at startup for the `proxyd` service.

## CLOSED ISSUES

### L2CM Upgrade Mechanism Refinements
Several issues related to the L2 Contract Messenger (L2CM) upgrade mechanism were closed. This includes the overall tracker for L2CM upgrades [#18871](https://github.com/ethereum-optimism/infra/issues/18871), the audit fixes review and approval milestone [#20085](https://github.com/ethereum-optimism/infra/issues/20085), and the L2CM FMA Action Items Tracker [#19345](https://github.com/ethereum-optimism/infra/issues/19345). Additionally, the task to add interop migration path to L2CM [#19309](https://github.com/ethereum-optimism/infra/issues/19309) was closed as the agreed approach for interop contracts is "all or nothing" deployment.

### Sequencer RPC Endpoint Redundancy
The issue [#763](https://github.com/ethereum-optimism/infra/issues/763) regarding support for multiple sequencer RPC endpoints for transaction forwarding was closed. The discussion concluded that using generic proxy solutions like HAProxy or Nginx is a more suitable approach than implementing bespoke failover logic within `op-geth`.

### L2CM Predeploy Access Control
The issue [#19313](https://github.com/ethereum-optimism/infra/issues/19313) concerning adding `ProxyAdminOwnedBase` access control to predeploy `initialize()` functions was closed as a duplicate of another issue.

## NEW ISSUES

No new issues were opened today.

## ACTIVE ISSUES

### L2CM Interop Hard Fork Implementation
Issue [#20082](https://github.com/ethereum-optimism/infra/issues/20082) discusses implementing the interop hard fork activation using the L2CM upgrade mechanism in both `kona-node` and `op-node`. The latest comment from maurelian clarifies that this is a simple task requiring `L1Block.setFeature(Features.INTEROP)` to be called if `depset.len > 1`.

### SuperDisputeGame Deployment Support
Issue [#19652](https://github.com/ethereum-optimism/infra/issues/19652) focuses on adding support for deploying the SuperDisputeGame contract type through `op-deployer` and `netchef`. The latest update from jelias2 indicates a decision to use a dedicated directory for `netchef` to pull a custom `op-deployer` build, enabling the use of the latest contracts and feature flags for SuperDisputeGame deployment.

### L2CM Audit Finding #15
Issue [#20077](https://github.com/ethereum-optimism/infra/issues/20077) addresses Audit Finding #15, which is an informational finding regarding CGT upgrades and the replaying of a renounced `LiquidityController` owner. maurelian's latest comment confirms that this finding has been fixed by a specific pull request in the `optimism` repository.

### L2CM Support for op-chain-ops
Issue [#19102](https://github.com/ethereum-optimism/infra/issues/19102) discusses adding L2CM support for `op-chain-ops`, specifically enabling `interopgen` to use L2CM for L2 genesis deployments. maurelian's latest comment links this issue to another related issue, [#20079](https://github.com/ethereum-optimism/infra/issues/20079).

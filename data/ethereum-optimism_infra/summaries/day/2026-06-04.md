# ethereum-optimism/infra Daily Update (Jun 4, 2026)
## OVERVIEW 
Today's development focused on enhancing `proxyd` with a new interop validation strategy and fixing a critical bug related to CL backend initialization at network genesis. Several new pull requests were opened to further improve `proxyd`'s functionality and metrics.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced `proxyd` Interoperability and Validation
A new additive `agreement` interop-validation strategy was added to `proxyd`. This strategy concurrently fans out `checkAccessList` requests to all configured supervisor URLs and combines verdicts by quorum agreement, ensuring robust validation.
- feat(proxyd): add agreement interop validation strategy ([#640](https://github.com/ethereum-optimism/infra/pull/640))

### `proxyd` Consensus Layer Backend Fix
A bug in `proxyd`'s CL consensus mode was fixed, allowing CL backends to report block height `0` at network genesis. Previously, `updateCLBackend` rejected any backend reporting block height `0` for `unsafe`, `safe`, `local_safe`, or `finalized`, which was problematic when `op-node` reports block height `0` for all safety levels at genesis.
- fix(proxyd): allow CL backends at network genesis (block 0 with valid hash) ([#645](https://github.com/ethereum-optimism/infra/pull/645))

## ACTIVE ISSUES

### `op-e2e-fuzz` Flakiness Investigation
The `op-e2e-fuzz` CircleCI job intermittently fails with "Too long with no output (15m)". The root cause has been identified as `op-e2e/config`'s package `init()` running a full genesis pipeline for all alloc types and hardfork modes at binary startup, leading to minutes of CPU usage before any fuzz body execution. This oversubscribes the 8-vCPU box when 3 concurrent `go test -fuzz` processes run. The fix involves generating each alloc type lazily and once. A draft PR ([#21238](https://github.com/ethereum-optimism/optimism/pull/21238)) is in progress.
- [Flake] op-e2e-fuzz: 'Too long with no output (15m)' — parallel buffers fuzz output until job completion ([#21191](https://github.com/ethereum-optimism/infra/issues/21191))

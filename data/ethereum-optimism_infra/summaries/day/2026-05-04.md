# ethereum-optimism/infra Daily Update (May 4, 2026)
## OVERVIEW 
Today saw significant progress in interop testing and infrastructure improvements, with several issues related to prestate builds, supernode functionality, and interop stress testing being closed. A new feature for op-conductor-ops was also initiated.

## KEY TECHNICAL DEVELOPMENTS

*   **Interop Testing & Validation:** Extensive stress testing on interop functionality confirmed the robustness of message validation, even with aged messages, after a critical RLP decoding fix. This provides confidence in the system's ability to handle diverse scenarios within the expiry window.
*   **Infrastructure Tooling Enhancements:** Improvements were made to the prestate build process for Kona, allowing for faster local development. Additionally, missing fault proof tests were successfully ported to the `op-acceptance-test` and `supernode` frameworks, leading to a bug fix in `supernode`.
*   **Supernode Functionality Refinement:** A decision was made to close an issue regarding fetching super roots for unsafe data, opting for independent construction of expected super roots in tests rather than relying on `op-supernode` for this specific use case.

## NEWLY OPENED PULL REQUESTS
A new pull request, [#615](https://github.com/ethereum-optimism/infra/pull/615), was opened to migrate `op-conductor-ops` to use `apko` and `melange`, indicating a move towards more streamlined and reproducible build processes for this component.

## CLOSED ISSUES

*   **Interop Readiness & Chain Creation:** The issue [#15884](https://github.com/ethereum-optimism/infra/issues/15884) concerning the creation of new chains post-interop was closed. It was determined that L2 genesis can be generated with interop enabled in a dependency set of 1, and creating combined dependency sets in initial deployment is out of scope.
*   **Supernode and Prestate Build Improvements:** Several issues related to `op-supernode` and prestate builds were closed. This includes [#19059](https://github.com/ethereum-optimism/infra/issues/19059) regarding fetching super roots for unsafe data, which was closed as "won't fix" due to a workaround in tests. Issue [#19057](https://github.com/ethereum-optimism/infra/issues/19057) for adding a fast Kona prestate build was closed, indicating successful implementation of a faster, non-Docker build process.
*   **Fault Proof Test Migration & Bug Fixes:** The migration of "after head" tests to `op-supernode` was completed, closing [#20370](https://github.com/ethereum-optimism/infra/issues/20370). This migration also led to the discovery and fix of a bug in `supernode`. Additionally, [#20500](https://github.com/ethereum-optimism/infra/issues/20500), a duplicate issue regarding `op-challenger` using the incorrect prestate URL, was closed.

## NEW ISSUES
No new issues were opened today.

## ACTIVE ISSUES

*   **Interop Expiry Window Stress Testing:** Issue [#15285](https://github.com/ethereum-optimism/infra/issues/15285) is actively being discussed regarding stress testing the interop expiry window. Recent updates from live devnet testing indicate that a Kona interop running in Cannon/MIPS against old initiating messages, after an EIP-2935 proof decoding fix, completed cleanly. The cost scaled linearly with message count, suggesting that moving to a 7-day expiry window is unlikely to cause completion issues. The analysis is considered sufficient, pending the RLP decoding fix being merged with a test.
*   **L2CM Betanet Acceptance Testing:** Issue [#20089](https://github.com/ethereum-optimism/infra/issues/20089) for L2CM acceptance testing on Betanet was marked as a duplicate of [#18839](https://github.com/ethereum-optimism/infra/issues/18839).
*   **Super Root Chain Update Runbook:** Issue [#20473](https://github.com/ethereum-optimism/infra/issues/20473) discusses updating the super root chain from permissioned to permissionless with OPCMv2. It was suggested to defer this until after interop has shipped, as it's a documentation update only required when a chain has upgraded to SuperDisputeGame (U20 at least) and then wants to move from permissioned to permissionless. The interop release is a precondition for this, so it shouldn't block the release.

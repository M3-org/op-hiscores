## ACTIVE ISSUES
- **op-supernode: Reset Handling**
  Discussions continued on [#18740](https://github.com/ethereum-optimism/infra/issues/18740) regarding the best approach for reset handling in op-supernode. The latest plan is to initially implement a workaround by updating to a synthetic block and then back to the desired block, as shown in a previous commit by Changwan. Long-term, adding a new engine API method or modifying existing EL FCU behavior are preferred options. The current FCU behavior does not allow moving the unsafe head back to a canonical block on op-geth, leading to the need for these alternative solutions.

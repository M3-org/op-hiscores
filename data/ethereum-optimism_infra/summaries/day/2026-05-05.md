# ethereum-optimism/infra Daily Update (May 5, 2026)
## OVERVIEW 
The day saw a significant consolidation of image build workflows, streamlining the CI process. Additionally, several issues related to `op-node` stability and contract removal were closed, indicating progress in core infrastructure.

## KEY TECHNICAL DEVELOPMENTS

### CI/CD Workflow Streamlining
*   Consolidated `branches.yaml` and `tags.yaml` into a single `build-images.yaml` for standardized image builds using the `factory/actions/plan` action, unifying legacy `detect-changes` and `parse-tag` functionalities ([#616](https://github.com/ethereum-optimism/infra/pull/616)).

## NEWLY OPENED PULL REQUESTS
*   A new pull request, [#617](https://github.com/ethereum-optimism/infra/pull/617), was opened to update the `postcss` dependency from version 8.5.3 to 8.5.14 in the `/replica-healthcheck` directory.

## CLOSED ISSUES

### `op-node` Stability Improvements
*   The issue where `op-node` would get stuck in EL sync mode after a restart when reth already had synced data has been closed, with fixes implemented to stabilize `op-node` driving `op-reth` ([#18468](https://github.com/ethereum-optimism/infra/issues/18468)).

### Contract Removal and Refactoring
*   The issue concerning the removal of the `ProtocolVersions` contract and its deployment paths has been closed, indicating successful completion of this refactoring effort ([#20309](https://github.com/ethereum-optimism/infra/issues/20309)).

## NEW ISSUES

### `op-challenger` Flag Consolidation
*   A new issue, [#20547](https://github.com/ethereum-optimism/infra/issues/20547), proposes consolidating per-VM flags into global flags within `op-challenger` to simplify configuration.

### `op-node` Superroot Support
*   Issue [#20552](https://github.com/ethereum-optimism/infra/issues/20552) was opened to add support for `superroot_atTimestamp` in `op-node` for non-interop chains, which is crucial for fault dispute games after the super-roots upgrade.

## ACTIVE ISSUES

*   **`op-node` stuck in EL sync mode after restart when reth already has synced data** ([#18468](https://github.com/ethereum-optimism/infra/issues/18468)): This issue has been closed by sebastianst, who stated that several fixes have been implemented to stabilize `op-node` driving `op-reth`. He invited reopening the issue if the exact problem persists. Previously, louisliu2048 suggested changing the sync mode from EL sync to CL sync as a temporary fix.

*   **alloy-op-evm: drop dead-on-read `sender` / `evm_gas_used` fields on `OpTxResult`** ([#20463](https://github.com/ethereum-optimism/infra/issues/20463)): sebastianst commented that `evm_gas_used` might be in use in a specific pull request within the `optimism` repository, suggesting it might not be a dead-on-read field.

*   **SDM: move PoC2 functionality into `develop`** ([#20216](https://github.com/ethereum-optimism/infra/issues/20216)): geoknee noted that acceptance tests and benchmarking tooling are still outstanding for this functionality. Previously, geoknee also mentioned a related PR that was under review.

*   **Remove ProtocolVersions contract and its deployment paths** ([#20309](https://github.com/ethereum-optimism/infra/issues/20309)): This issue has been closed by sebastianst, confirming that the task was completed by a specific pull request.

*   **Consolidate per-VM flags into global flags in op-challenger** ([#20547](https://github.com/ethereum-optimism/infra/issues/20547)): ajsutton provided a counterpoint, explaining that the current pattern of per-VM flags is used because different game types sometimes require different configuration file formats, citing `op-program` and `kona` as examples with incompatible `l2-genesis`.

*   **op-node: support superroot_atTimestamp for non-interop chains** ([#20552](https://github.com/ethereum-optimism/infra/issues/20552)): ajsutton clarified that the same `--supernode-url` flag should be used, and the naming should be consistent with `supernode` for exact compatibility with `superroot_atTimestamp`. They also emphasized that the API needs to work and return a super root for the single chain `op-node` runs even before interop activates, as super dispute games must be adopted prior to interop.

# ethereum-optimism/infra Daily Update (Jul 29, 2026)
## OVERVIEW 
Today's focus was on enhancing CI/CD security and automation with the addition of Renovate CVE autobump and a dependency-review PR gate. Discussions continued on SDM devnet rollout and `op-reth` CLI flag auditing.

## KEY TECHNICAL DEVELOPMENTS

### CI/CD Security and Automation
Significant updates were made to the CI/CD pipeline to bolster security and automate dependency management. A new workflow was introduced to automatically bump CVEs using Renovate, ensuring that the project stays up-to-date with security patches [#680](https://github.com/ethereum-optimism/infra/pull/680). Additionally, a dependency-review PR gate was added to automatically check for high/critical vulnerabilities introduced by pull requests, failing them if such issues are detected [#678](https://github.com/ethereum-optimism/infra/pull/678).

### Code Ownership and Governance
The `cloud-security` team was made the sole owner of CI and dependency-config files, including workflows, actions, Renovate configuration, and `CODEOWNERS` itself. This change centralizes governance over security-critical configurations, allowing the security team to manage and merge related changes directly [#679](https://github.com/ethereum-optimism/infra/pull/679).

## ACTIVE ISSUES

### SDM Devnet Rollout and Benchmarking [#21273](https://github.com/ethereum-optimism/infra/issues/21273)
The rollout of an alpha/beta devnet for SDM is progressing, with the `sdm-net-0` spec merged and `netchef` completing terraform and L2 contract deployment. The team is currently awaiting approval of generated artifacts and k8s manifests. Key gaps identified for achieving parity with the `kupcake` devnet include:
- **Contracts and Transaction Load:** The SSD inventory lacks load generation, so the plan is to deploy contract categories and run `contender` against the public RPC.
- **SDM Grafana Dashboard:** The existing SDM dashboard needs to be ported to `premium`'s metric names.
- **Policy Hot-Enable/Disable:** This feature, requiring protocol code, needs revival with the Core team as the previous implementation was closed unmerged.
Risks to verify include `rpc-2/sync-2` running `kona-node` CLs, which may not derive post-exec transactions. The plan outlines completing the rollout, verifying SDM live, standing up load, porting the dashboard, reviving the hot-toggle, and conducting baseline benchmarks.

### Auditing `op-reth` CLI Flags [#21687](https://github.com/ethereum-optimism/infra/issues/21687)
Discussions continue regarding auditing `op-reth` CLI flags and addressing unsupported combinations. The recent update to documentation about supported pruning configurations was noted. There's a debate on whether to remove the "minimal" pruning option or adjust its defaults and clarify its experimental nature, as it's a preset of different pruning settings.

### Kona-sp1-proposer Game Defense Strategy [#22111](https://github.com/ethereum-optimism/infra/issues/22111)
A discussion has started regarding the `kona-sp1-proposer`'s strategy for defending challenged games. The current sentiment is against making immediate changes, as the challenger's bond is kept for every valid game proven, which is higher than the proving cost. It's acknowledged that "proof of whale" attacks are a known weakness, and until bond economics improve, the defense would involve blacklisting or retiring games.

### `op-reth` Reth Dependency Update [#22115](https://github.com/ethereum-optimism/infra/issues/22115)
The `op-reth-premium` team is awaiting an upstream `reth` change (PR 26431) before updating its `reth` dependency. This change is expected to provide a cleaner solution for the state-root wait issue, potentially removing a proxy channel and detached OS thread, which would improve sequencing liveness and eliminate a potential unbounded resource leak.

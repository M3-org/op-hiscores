# ethereum-optimism/infra Daily Update (Mar 25, 2026)
## OVERVIEW 
Today's development focused on significant infrastructure upgrades, including bumping Go versions, migrating to Docker Hardened Images for enhanced security, and optimizing runtime dependencies. A critical bug fix for CircleCI stats was also implemented.

## KEY TECHNICAL DEVELOPMENTS

### Infrastructure Modernization and Security Hardening
Major updates were implemented to enhance the security and efficiency of the infrastructure. Go versions were bumped to 1.26 across most modules, and Docker Hardened Images (DHI) were adopted for all Dockerfiles to reduce the attack surface. This also included adding Dockerfile smoke tests to verify the changes. ([#579](https://github.com/ethereum-optimism/infra/pull/579))

### Runtime Dependency Optimization
Unused runtime dependencies were removed from `proxyd`, `op-ufm`, and `peer-mgmt-service` to streamline their Docker images. This involved switching their base images from `dhi.io/alpine-base:3.23-dev` to `dhi.io/alpine-base:3.23` and removing unnecessary `apk add` packages. ([#580](https://github.com/ethereum-optimism/infra/pull/580))

### CircleCI Stats Flaky Status Fix
A bug in the `cci-stats` service was fixed where `mapFlakyStatus` incorrectly used `strings.HasPrefix` to detect `FLAKY_PASS`/`FLAKY_FAIL` markers. The Go test framework embeds these markers in the middle of messages, so `Contains` is now used for accurate detection. ([#578](https://github.com/ethereum-optimism/infra/pull/578))

### Kona Guest Panic Deserializing ChainList.json
Issue [#19654](https://github.com/ethereum-optimism/infra/issues/19654) regarding the kona guest program panicking during cannon VM execution due to a missing `name` field in `chainList.json` was closed today. The issue was fixed by PR #19730.

### Flaky Test: TestCLELDivergence
Discussion continues on the flaky `TestCLELDivergence` ([#19681](https://github.com/ethereum-optimism/infra/issues/19681)). The latest comments indicate that the issue might be mitigated by https://github.com/ethereum-optimism/optimism/pull/19733, but there's a debate on whether to keep the issue open until the flakiness completely disappears or close it and rely on `/report-flake` to reopen if it recurs. Previous analysis suggested the test's comment was incorrect about the cause of resets, and the observed resets are likely part of the initial derivation pipeline lifecycle rather than an in-progress EL sync issue. The core question remains whether the observed reset behavior is correct or a bug in the reset logic.

## NEW ISSUES
### Supernode L1 Verification Logic
A new issue was opened concerning `op-supernode`: VerifiedRequiredL1 uses MIN of per-chain L1s instead of MAX ([#20481](https://github.com/ethereum-optimism/infra/issues/20481)). This issue highlights that `Superroot.atTimestamp` in `op-supernode` tracks `minVerifiedRequiredL1` as the MIN of per-chain `verifiedL1` values, then publishes it as `SuperRootResponseData.VerifiedRequiredL1`, which may be incorrect.

## ACTIVE ISSUES
### Fatal Panic in op-reth Upgrade
Discussion continued on the fatal panic in StateRootTask when upgrading op-reth from 1.x to 2.x on OP Stack chains ([#20462](https://github.com/ethereum-optimism/infra/issues/20462)). New findings indicate that the `--engine.legacy-state-root` flag does not fix the panic. While the flag changes the strategy from `StateRootTask` to `Parallel`, the same `alloy-trie-0.9.5` branch assertion panic occurs. The crash block changed, suggesting the panic is not block-specific but triggered non-deterministically during parallel trie computation against 1.x database state, indicating a shared bug in both parallel trie code paths.

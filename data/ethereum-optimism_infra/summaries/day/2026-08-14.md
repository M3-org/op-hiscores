## NEW ISSUES
### Kona Node L2 Block Info Derivation Optimization
A new issue, [#22432](https://github.com/ethereum-optimism/infra/issues/22432), was opened to discuss optimizing the derivation of `L2BlockInfo` and `SystemConfig` in `kona-node` without fetching full L2 blocks. The initial proposal aimed to fetch only necessary header fields and the first transaction, but a correction noted that the Engine API port does not support the required `eth_getTransactionByBlockNumberAndIndex` methods. A revised plan suggests serving these lookups locally from decoded payloads within `InsertTask` to avoid full block fetches.

### Kona Node L2 Block Info Derivation Optimization
On issue [#22432](https://github.com/ethereum-optimism/infra/issues/22432), "kona-node: derive L2BlockInfo and SystemConfig without fetching full L2 blocks," a significant correction was posted by @sebastianst. The initial "Proposed fix" was deemed not implementable as the Engine API port, used by both kona and op-node for L2 block access, does not expose `eth_getTransactionByBlockNumberAndIndex` or `...ByBlockHashAndIndex`. This constraint likely explains why both clients currently fetch full blocks. A revised plan suggests serving these derivations locally by leveraging `InsertTask` which already decodes payloads into `OpBlock` and computes `L2BlockInfo`. This approach would remove the derivation hot-path fetch entirely without requiring new EL capabilities. Follow-up actions include wiring `BufferedL2Provider` into the node and potentially adding `eth_getTransactionByBlock{Number,Hash}AndIndex` to op-reth's auth module for cold lookups.

The `cci-stats` tool received significant updates to improve its robustness. ### Kona Node L2 Block Info Derivation Optimization
A new issue, [#22432](https://github.com/ethereum-optimism/infra/issues/22432), was opened to address the inefficiency of deriving `L2BlockInfo` and `SystemConfig` in `kona-node`. Currently, both `kona` and `op-node` fetch full L2 blocks for this process, even though only a few header fields and the first transaction are needed.

### Kona Node L2 Block Info Derivation Optimization
On issue [#22432](https://github.com/ethereum-optimism/infra/issues/22432), "kona-node: derive L2BlockInfo and SystemConfig without fetching full L2 blocks," a significant correction was provided by `sebastianst`. The initial proposed fix, which involved minimal fetching over the Engine API port, was deemed not implementable because the Engine API port exposes a limited subset of `eth_` namespace methods, excluding `eth_getTransactionByBlockNumberAndIndex`.

A revised plan was proposed: instead of shrinking the fetch, the derivation's L2 lookups should be served locally. This involves feeding `kona-providers-local::BufferedL2Provider` from the engine and layering it in front of `AlloyL2ChainProvider`. This approach would remove the derivation hot-path fetch entirely without requiring new EL capabilities or flags. The comment also outlined follow-up actions, including removing dead code in `kona`, wiring `BufferedL2Provider` into the node, and potentially adding `eth_getTransactionByBlock{Number,Hash}AndIndex` to `op-reth`'s auth module for cold lookups.

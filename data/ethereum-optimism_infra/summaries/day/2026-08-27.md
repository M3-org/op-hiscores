# ethereum-optimism/infra Daily Update (Aug 27, 2026)
## OVERVIEW 
Today, a new passive transaction UX monitor was added to proxyd to observe transaction forwarding. Significant progress was made on issue cleanup, with several starter example repositories being analyzed for consolidation and archiving. A critical issue regarding the kona-node sequencer getting stuck in a forkchoiceUpdated loop was also opened.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced Transaction Monitoring in Proxyd
A new passive transaction-UX monitor (`tx_monitor`) has been integrated into proxyd. This feature observes successfully forwarded `eth_sendRawTransaction` and `eth_sendRawTransactionConditional` hashes, providing valuable insights into transaction user experience. ([#726](https://github.com/ethereum-optimism/infra/pull/726))

## CLOSED ISSUES

### Supernode Interoperability Wedge Resolved
The `op-supernode` cross-safe wedge issue, which occurred after an invalid-message replacement, has been closed. Analysis revealed it was a single occurrence over 7.5 weeks, with the root cause identified as chain 901 rejecting batches due to a parent-hash mismatch. The issue is now linked to a known oscillation problem rather than a distinct cross-safety bug. ([#22325](https://github.com/ethereum-optimism/infra/issues/22325))

### Kona RollupConfig Leniency Confirmed
The issue regarding `RollupConfig` silently accepting unknown `rollup.json` keys in kona-node has been closed as "not planned." The leniency is deliberate to support loading configurations with retired keys, ensuring compatibility with older `rollup.json` files. ([#22682](https://github.com/ethereum-optimism/infra/issues/22682))

## NEW ISSUES

### Kona-node Sequencer Stuck in ForkchoiceUpdated Loop
A new critical issue has been identified where a kona-node sequencer can become permanently wedged in a `forkchoiceUpdated` loop, consuming significant CPU, if the engine reorgs its unsafe head while the sequencer is building a block. ([#22681](https://github.com/ethereum-optimism/infra/issues/22681))

### SuperchainERC20 Compatibility Checking Gap
A new issue highlights the lack of a supported method for developers to check if a token address is SuperchainERC20 compatible. This capability was previously present in an archived repository, and its absence creates a gap in developer tooling. ([#1020](https://github.com/ethereum-optimism/infra/issues/1020))

## ACTIVE ISSUES

### Kona-node NetworkActor Stalling
Discussion on [#22646](https://github.com/ethereum-optimism/infra/issues/22646) (kona-node: NetworkActor stalls the p2p swarm for the duration of a remote-signer HTTP call) indicates that a developer is planning to pick up this issue. Key questions raised include the overflow policy for the queue (comparing it to a similar fix in #22585) and whether to land the deadline change separately from other restructuring. The developer also plans to confirm the stalling behavior with injected latency.

### Starter Examples Documentation Audit
On [#1014](https://github.com/ethereum-optimism/infra/issues/1014) (Starter examples: audit docs references before any archiving), a comprehensive reference map has been completed, confirming that no live documentation links any of the six starter repos or the four archive-sweep repos. This means archiving these repositories will not break published documentation. The sweep also identified a few internal README cross-references that will need minor adjustments.

### Starter Examples Consolidation Strategy
Discussion on [#1015](https://github.com/ethereum-optimism/infra/issues/1015) (Starter examples: consolidate into a single examples repo) has led to a recommendation to consolidate five of the six `superchain-starter*` repositories into the existing `superchain-starter` repo, as they share a common template. The `superchainerc20-starter` repo, being a distinct project and the most popular, will remain independent. The consolidation will involve a plain copy with pointers to original repos rather than a subtree merge to maintain readability.

### Archive Sweep for Abandoned Repos
For [#1017](https://github.com/ethereum-optimism/infra/issues/1017) (Archive sweep: abandoned and dead-since-2024 repos), an inbound-link check has been completed for all four target repositories, confirming no live documentation links them. The `superchainerc20-compatibility` repo's original purpose was reconstructed, revealing it provided checks for SuperchainERC20 compliance. While some checks are now obsolete due to contract changes, the core capability of checking token interop compatibility remains relevant and has been logged as a follow-up issue ([#1020](https://github.com/ethereum-optimism/infra/issues/1020)). The main blocker for archiving these repos is now organizational admin permissions.

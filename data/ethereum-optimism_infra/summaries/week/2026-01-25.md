# ethereum-optimism/infra Weekly Report (Jan 25 - 31, 2026)

## 🚀 Highlights
This week, development focused on refining the core infrastructure for the Superchain, specifically targeting the `op-supernode` SyncStatus API and protocol-level withdrawal mechanisms. Significant effort was directed toward stabilizing internal services by addressing metadata handling bugs and resolving deployment artifact inconsistencies. The team also prioritized protocol security and correctness through planned updates to EIP-1559 parameter decoding and cross-chain root claim verification.

## 🛠️ Key Developments

### Superchain Infrastructure & API Refinement
Work continued on defining the operational interface for the Superchain ecosystem.
*   **`op-supernode` SyncStatus API:** The team finalized the definition for the SyncStatus API ([#18947](https://github.com/ethereum-optimism/infra/issues/18947)). The interface is now designed to provide a comprehensive view of the network, including `op-node` status for every chain, verification activity metrics, and interop-specific data such as the latest verified timestamp and current L1 status.
*   **Withdrawal Security:** Discussions progressed on updating `OptimismPortal2.proveWithdrawalTransaction` to utilize chain-specific root claims ([#18517](https://github.com/ethereum-optimism/infra/issues/18517)). This change is critical for long-term cross-chain security but has been moved to the backlog to await the U19 execution and necessary updates to FaultDisputeGames.

### Service Stability and Bug Fixes
Several fixes were implemented to improve the reliability of internal tooling and services.
*   **Metadata Handling:** A fix was introduced in [#543](https://github.com/ethereum-optimism/infra/pull/543) to resolve errors caused by missing test metadata within services.
*   **`op-alloy` Decoding:** Work began on fixing EIP-1559 parameter decoding within `op-alloy` ([#18951](https://github.com/ethereum-optimism/infra/issues/18951)). The goal is to ensure the system correctly identifies and catches zero elasticities early in the decoding process.

## 🐛 Issues & Triage

### Closed Issues
*   **Test and Deployment Cleanup:** The team successfully closed issues related to OPCM v2 checks ([#18536](https://github.com/ethereum-optimism/infra/issues/18536)) following the successful merger of the CGT (Custom Gas Token) PR. Additionally, resource locator issues for v7_0_0 artifacts ([#18633](https://github.com/ethereum-optimism/infra/issues/18633)) were resolved as the underlying files were deprecated and removed.

### New & Active Issues
*   **Service Failures:** A new issue ([#542](https://github.com/ethereum-optimism/infra/issues/542)) was opened regarding failures in the `cci-stats` service. This is currently under investigation to determine the root cause of the reported bug.
*   **Protocol Dependencies:** The delay in implementing `rootClaimByChainId` ([#18517](https://github.com/ethereum-optimism/infra/issues/18517)) represents a strategic pause; the team is carefully sequencing this update to avoid potential withdrawal delays for users during the transition to the U19 upgrade.

## 💬 Community & Collaboration
The week saw active technical coordination between maintainers and the broader community. Notably, the fix for EIP-1559 decoding in `op-alloy` ([#18951](https://github.com/ethereum-optimism/infra/issues/18951)) attracted immediate community interest, with external contributors stepping forward to assist with the implementation. This highlights a healthy collaborative environment for the project's foundational libraries. Discussions around the `op-supernode` API also demonstrated a high level of alignment on how to best surface L2 verification data for acceptance testing and node operators.

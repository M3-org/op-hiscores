# ethereum-optimism/infra Weekly Report (Mar 1 - 7, 2026)

## 🚀 Highlights
This week, development focused on hardening infrastructure tooling and optimizing the `op-acceptor` testing suite to improve CI efficiency. Significant attention was directed toward the Kona protocol and the L2 Contracts Manager (L2CM), specifically addressing discrepancies between Kona and `op-node` and documenting critical safety conventions for delegate calls. The team also began proactive investigations into the "Glamsterdam" hardfork, analyzing how shifting gas pricing for precompiles might impact Cannon’s acceleration and proof generation.

## 🛠️ Key Developments

### `op-acceptor` & CI Optimization
Efforts were concentrated on reducing CI wait times and improving the reliability of the `op-acceptor` service.
*   **Test Runtime Optimization:** Implemented a `RuntimeCache` to track wall-clock execution times, allowing the system to sort and run the longest tests first to optimize the critical path ([#557](https://github.com/ethereum-optimism/infra/pull/557)).
*   **Execution Logic Refinement:** Fixed a bug in `op-acceptor` to ensure the `--exclude-gates` flag correctly handles named test exclusions in gateless mode ([#560](https://github.com/ethereum-optimism/infra/pull/560)).
*   **CI Environment Fixes:** Resolved a `go-release` failure by ensuring `zstd` is installed for `mise` archive extraction, supporting `.tar.zst` formats ([#561](https://github.com/ethereum-optimism/infra/pull/561)).
*   **Dependency Management:** Updated `opentelemetry` SDK to version 1.40.0 ([#558](https://github.com/ethereum-optimism/infra/pull/558)).

### Infrastructure & Tooling Maintenance
*   **Configuration Cleanup:** Updated `mise.toml` to resolve deprecated aliases and backends, ensuring future compatibility with the version manager ([#556](https://github.com/ethereum-optimism/infra/pull/556)).
*   **Performance:** A new PR was opened to optimize `proxyd` performance when handling large JSON responses ([#559](https://github.com/ethereum-optimism/infra/pull/559)).

## 🐛 Issues & Triage

### Closed Issues
*   **Deprecations:** Support for Flashblocks in Geth was closed following the deprecation of `op-geth` ([#756](https://github.com/ethereum-optimism/infra/issues/756)).
*   **Deduplication:** Several tracking issues for L2 contract upgrades ([#18843](https://github.com/ethereum-optimism/infra/issues/18843)) and VM runner support for the supernode API ([#19008](https://github.com/ethereum-optimism/infra/issues/19008)) were closed as duplicates to streamline project management.

### New & Active Issues
*   **Glamsterdam Gas Impacts:** A critical investigation is underway regarding increased gas costs for precompiles and call data for large preimages. This is essential to ensure that `cannon` acceleration remains functional and that proofs do not break under new pricing models ([#19375](https://github.com/ethereum-optimism/infra/issues/19375)).
*   **L2CM Safety:** New documentation is being drafted for the "no-storage-variables" convention in `L2ContractsManager` to prevent storage collisions during `DELEGATECALL` execution ([#19391](https://github.com/ethereum-optimism/infra/issues/19391)).
*   **Kona Protocol Stability:** Multiple issues are active regarding discrepancies between Kona and `op-node`, including Brotli channel disagreements ([#19333]), frame parsing mismatches ([#19335]), and orphaned sources in `kona-derive` ([#19340]).
*   **EL Sync Correctness:** Ongoing debate continues regarding `op-node` behavior during initial Execution Layer sync, specifically how it marks targets as finalized and whether Snap Sync should be capped by the finalized L2 state ([#17631](https://github.com/ethereum-optimism/infra/issues/17631)).

## 💬 Community & Collaboration
The week saw high engagement from contributors volunteering to resolve Kona-related vulnerabilities and protocol discrepancies. There is a clear cross-pollination of work between the `infra` and `optimism` repositories, particularly regarding L2CM upgrade commands and the transition to `CANNON_KONA` as the default respected game type ([#18640](https://github.com/ethereum-optimism/infra/issues/18640)). Technical discussions involving key contributors like `ajsutton`, `karlfloersch`, and `sebastianst` highlight a rigorous peer-review process for protocol-level changes.

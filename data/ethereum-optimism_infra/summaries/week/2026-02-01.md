# ethereum-optimism/infra Weekly Report (Feb 1 - 7, 2026)

## 🚀 Highlights
This week focused on hardening core infrastructure components, specifically enhancing the reliability of the `proxyd` service through advanced health-checking mechanisms. Significant technical discourse centered on the architectural direction of `op-supernode` and the integration of Flashblocks within the execution layer. Additionally, the team investigated cross-tooling discrepancies between the Optimism SDK and Viem regarding withdrawal validation, highlighting a critical area for improving developer experience and protocol consistency.

## 🛠️ Key Developments

### Proxy Service Robustness
The primary technical achievement this week was the enhancement of `proxyd` to improve backend reliability and service resilience.
*   **Healthcheck and Drain Functionality:** A significant update was merged to introduce configurable HTTP probe workers. This allows `proxyd` to actively monitor backend health and automatically exclude failing backends from the pool. This feature, ported from Uniswap's improvements, ensures higher uptime and more intelligent traffic routing ([#534](https://github.com/ethereum-optimism/infra/pull/534)).

## 🐛 Issues & Triage

### Active Technical Discussions
*   **`op-supernode` State Management:** Discussions progressed regarding the safe label adjusting mechanism for `op-supernode`. The current consensus is leaning toward the Consensus Layer (CL) maintaining a full set of pointers as the sole controller of the engine. This strategy aims to prevent state synchronization issues between multiple controllers and ensures compatibility with existing interop-aware data structures ([#18976](https://github.com/ethereum-optimism/infra/issues/18976)).
*   **Flashblocks Integration:** Efforts to bring Flashblocks support to `op-geth` are underway. Community members have shared progress on versions of `op-geth` that include both Firehose Live Tracer and Flashblock(s) support, signaling a move toward faster block pre-confirmations ([#756](https://github.com/ethereum-optimism/infra/issues/756)).
*   **Withdrawal Validation Discrepancies:** An investigation into `BlockNotFoundError` during L1 withdrawal proving revealed a potential inconsistency. While the Optimism SDK performs `isValidOutputRoot` validation, Viem’s current withdrawal guides do not, which can lead to errors if users attempt to prove withdrawals before state roots are published to L1 ([#1956](https://github.com/ethereum-optimism/infra/issues/1956)).

# ethereum-optimism/infra Weekly Report (Aug 2 - 8, 2026)

## 🚀 Highlights
This week focused heavily on hardening infrastructure stability through critical memory leak resolutions and a comprehensive sweep of security dependencies. Significant fixes were deployed to the `replica-healthcheck` and `op-ufm` services to address resource exhaustion, while the project established a new centralized dashboard for tracking CVEs. Development also progressed on performance benchmarking for the Superchain Dependency Manager (SDM), alongside ongoing investigations into `op-node` synchronization challenges with the `op-reth` backend.

## 🛠️ Key Developments

### Infrastructure Stability & Memory Management
A primary focus this week was resolving persistent resource leaks across core infrastructure components to ensure long-term service reliability.
*   **Replica Healthcheck:** Switched to `StaticJsonRpcProvider` for both reference and target RPC providers to mitigate a suspected memory leak. This update also included a fix for a latent null-dereference bug in the `getBlock` logic ([#694](https://github.com/ethereum-optimism/infra/pull/694)).
*   **User Fault Monitoring (op-ufm):** Implemented a significant fix for memory leaks within the provider transaction pool and RPC clients. This addressed an issue where in-flight transaction tracking lists were growing indefinitely ([#685](https://github.com/ethereum-optimism/infra/pull/685)).

### Security & Dependency Maintenance
The team conducted an extensive update of the Go module ecosystem to ensure compliance with the latest security patches.
*   **Go Module Updates:** Numerous PRs were merged to update core libraries including `golang.org/x/crypto`, `net`, `sys`, and `text`, as well as networking modules like `pion/stun`, `pion/dtls`, and `quic-go/webtransport-go` ([#697](https://github.com/ethereum-optimism/infra/pull/697) - [#705](https://github.com/ethereum-optimism/infra/pull/705)).
*   **Frontend Security:** Updated the `postcss` dependency to `v8.5.23` to address potential vulnerabilities ([#707](https://github.com/ethereum-optimism/infra/pull/707)).
*   **Vulnerability Tracking:** Launched a new Renovate CVE Dashboard ([#706](https://github.com/ethereum-optimism/infra/issues/706)) to provide a centralized view of detected dependencies and pending security updates.

## 🐛 Issues & Triage

### Closed Issues
*   **CI Optimization:** Successfully reduced the CI makespan by shifting the workflow toward merging smaller, incremental pull requests rather than monolithic updates ([#21186](https://github.com/ethereum-optimism/infra/issues/21186)).
*   **op-reth Proofs History:** Resolved concerns regarding `op-reth` proofs history lagging after shutdowns. The team determined that consistency should be managed at startup, as the proofs execution extension (exex) naturally catches up as the chain produces blocks ([#22089](https://github.com/ethereum-optimism/infra/issues/22089)).

### New & Active Issues
*   **SDM Benchmarking:** Discussions are active regarding the rollout of an alpha/beta devnet for the Superchain Dependency Manager (SDM). Current efforts involve using `op-benchmark` and specialized scripts to generate load and test slot usage/refunds ([#20176](https://github.com/ethereum-optimism/infra/issues/20176), [#21273](https://github.com/ethereum-optimism/infra/issues/21273)).
*   **Sync & Peering Challenges:** `op-node` continues to face difficulties syncing with the `op-reth` backend when using execution-layer sync. Logs indicate persistent ECIES unreadable stream errors and peering disconnects ([#20974](https://github.com/ethereum-optimism/infra/issues/20974)).
*   **Integration Test Flakes:** The `reth-optimism-node` integration tests are under instrumentation to capture stack traces for a SIGSEGV occurring during teardown in the `peers_negotiate_eth_69` test ([#20973](https://github.com/ethereum-optimism/infra/issues/20973)).

## 💬 Community & Collaboration
The week was characterized by high-velocity maintenance, particularly in the security domain, where the team coordinated a large volume of dependency PRs. Collaboration was most visible in the troubleshooting of the `op-reth` synchronization issues, with contributors providing detailed breakdowns of pod logs and connection errors to isolate peering difficulties. The transition to smaller PRs for CI optimization also reflects a shift in team workflow toward more modular and review-friendly contribution patterns.

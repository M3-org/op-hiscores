# ethereum-optimism/infra Weekly Report (May 24 - 30, 2026)

## 🚀 Highlights
This week’s development focused on hardening infrastructure security and improving the reliability of the `op-conductor-ops` suite. Significant effort was directed toward migrating core service base images to Chainguard for enhanced security and refining CI/CD pipelines to ensure accurate semantic versioning during Docker releases. However, the week was also characterized by intensive debugging of deep-seated integration issues between `op-node` and `op-reth`, specifically regarding Engine API stalls and SIGBUS crashes that continue to impact test stability and node performance.

## 🛠️ Key Developments

### Infrastructure Tooling & Cluster Management
The team introduced more granular control over sequencer/conductor pairs to streamline deployment workflows.
*   **Cluster Bootstrapping:** A new `bootstrap-standby-cluster` command was added to `op-conductor-ops`. This allows for the creation of fresh Raft clusters while keeping conductors paused and sequencers unstarted, facilitating safer initialization of standby environments [#634](https://github.com/ethereum-optimism/infra/pull/634).

### Security & Container Optimization
A concerted effort was made to improve the security posture and build reliability of the project's containerized services.
*   **Hardened Base Images:** The base images for `proxyd`, `op-conductor-ops`, and `replica-healthcheck` were migrated to Chainguard alternatives to reduce the attack surface and improve compliance [#625](https://github.com/ethereum-optimism/infra/pull/625).
*   **Build Fixes:** To resolve build-time failures, lifecycle scripts are now ignored in the `replica-healthcheck` image [#632](https://github.com/ethereum-optimism/infra/pull/632).

### CI/CD & Build Determinism
Improvements were made to the automation pipeline to ensure consistent releases and build outputs.
*   **Tagging Logic:** The CI pipeline was updated to forward plan matrix tags correctly to the Docker publish workflow. This ensures that releases use proper semver tags rather than sanitized GitHub reference names [#633](https://github.com/ethereum-optimism/infra/pull/633).
*   **Semver Consistency:** The team identified an issue where `generate-semver-lock` produced nondeterministic output when multiple Forge artifacts with different optimizer settings mapped to the same key [#21032](https://github.com/ethereum-optimism/infra/issues/21032).

## 🐛 Issues & Triage

### New & Active Issues
*   **Reth Engine API & SIGBUS Crashes:** Investigation continues into `op-reth` experiencing SIGBUS crashes during deep FCU (Forkchoice Updated) rewinds. The current hypothesis involves `ftruncate` operations on mmap pages being accessed by other threads. The team is seeking coordination with the Reth core team to resolve this concurrency issue [#20934](https://github.com/ethereum-optimism/infra/issues/20934).
*   **Test Flakiness (TestUnsafeChainNotStalling_CLSync):** A recurring regression in this test family was traced back to `op-reth` Engine API stalls rather than test logic. Logs indicate `context deadline exceeded` errors during `newPayloadV3` calls. The team is currently rebasing to verify if recent fixes resolve the stall [#21041](https://github.com/ethereum-optimism/infra/issues/21041).
*   **L2CM Structural Gaps:** Discussions were reopened regarding the `L2ContractsManager` and the need for a single source of truth for predeploys to prevent silent failures during upgrades [#19260](https://github.com/ethereum-optimism/infra/issues/19260). Additionally, the team decided to mitigate feature flag drift by adding explicit documentation in `DevFeatures.sol` and `devFeatures.go` [#20340](https://github.com/ethereum-optimism/infra/issues/20340).
*   **Engine API Workarounds:** The team has opted to maintain a retry-verify loop in `op-supernode` to handle an `op-reth` race condition, as upstream fixes have stalled [#19772](https://github.com/ethereum-optimism/infra/issues/19772).

## 💬 Community & Collaboration
Collaboration this week was heavily focused on cross-component debugging, particularly between the infrastructure and protocol teams. The technical discussions on issues [#20934](https://github.com/ethereum-optimism/infra/issues/20934) and [#21041](https://github.com/ethereum-optimism/infra/issues/21041) demonstrate a high level of coordination required to diagnose race conditions in the execution client. There is also a clear emphasis on long-term maintainability, as seen in the consensus to improve documentation for feature flags to prevent CI matrix drift.

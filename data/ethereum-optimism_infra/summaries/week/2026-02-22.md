# ethereum-optimism/infra Weekly Report (Feb 22 - 28, 2026)

## 🚀 Highlights
This week, development focused on optimizing the contributor experience through improved testing efficiency and expanded hardware compatibility. Key updates included the introduction of runtime-based test sorting to reduce CI bottlenecks and the addition of native ARM64 support for `op-acceptor`, benefiting developers on Apple M-series hardware. Meanwhile, technical discussions centered on refining Superchain infrastructure, specifically regarding `op-batcher` ordering logic and Superroot SLA definitions.

## 🛠️ Key Developments

### Infrastructure & Tooling Enhancements
Efforts were made to streamline the local development environment and CI pipelines to improve developer velocity.
*   **Testing Optimization:** A new feature was introduced to optimize test execution by sorting tests based on their previous runtimes. By front-loading longer-running tests, the system aims to maximize parallelization and reduce overall CI wait times ([#557](https://github.com/ethereum-optimism/infra/pull/557)).
*   **Environment Configuration:** The `mise.toml` configuration was updated to resolve deprecated aliases and refine backend settings, ensuring the development environment remains compatible with current tooling ([#556](https://github.com/ethereum-optimism/infra/pull/556)).

### Cross-Platform Compatibility
*   **Native ARM64 Support:** `op-acceptor` now includes a Linux/arm64 release binary. By updating `.goreleaser.yaml`, the project enabled native execution on ARM64 architectures, significantly improving performance and Docker compatibility for developers using Apple M-series CPUs by eliminating the need for emulation ([#555](https://github.com/ethereum-optimism/infra/pull/555)).

## 🐛 Issues & Triage

### Closed Issues
*   **RPC Performance:** An issue regarding `eth_getLogs` memory exhaustion and general RPC performance was triaged and closed as a duplicate of existing work ([#769](https://github.com/ethereum-optimism/infra/issues/769)).

### Active Issues & Discussions
*   **`op-batcher` Ordering:** Investigation continues into `op-batcher` failures related to post-Holocene ordering in concurrent mode. Recent activity suggests a potential upstream fix in the main `optimism` repository ([#18507](https://github.com/ethereum-optimism/infra/issues/18507)).
*   **Superroot SLA Clarification:** Discussions are ongoing regarding the `op-supernode` Superroot SLA. The current focus is on defining how to handle unavailable roots, with a proposal to treat Optimistic Roots as "best-effort" and omit missing data from the map rather than providing placeholder values ([#19180](https://github.com/ethereum-optimism/infra/issues/19180)).

## 💬 Community & Collaboration
The week's activity reflects a strong focus on maintainability and cross-repository coordination. Collaboration is evident in the triage of RPC performance issues and the synchronization between the `infra` and `optimism` repositories regarding protocol upgrades like the Holocene hardfork. The technical dialogue surrounding Superroot SLAs indicates active coordination between maintainers to define robust standards for Superchain interoperability.

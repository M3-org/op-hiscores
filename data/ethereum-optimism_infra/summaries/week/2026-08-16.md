# ethereum-optimism/infra Weekly Report (Aug 16 - 22, 2026)

## 🚀 Highlights
This week focused on hardening infrastructure reliability and concluding significant performance benchmarks for the State Diff Merkle (SDM) feature. Key achievements included enhancing CircleCI pipeline stability through API retry mechanisms and image streamlining, alongside critical security dependency rollups across the service stack. The team also successfully validated that SDM introduces no measurable CPU or memory overhead, clearing the path for broader production confidence. Efforts to resolve persistent test flakiness in interop and storage proof components remain a primary focus for CI health.

## 🛠️ Key Developments

### CI/CD Infrastructure & Reliability
Significant effort was directed toward stabilizing the CI pipeline and modernizing runner images.
*   **CircleCI API Resilience:** The `cci-stats` tool was updated to include retry mechanisms for transient 5xx errors, preventing pipeline failures due to temporary API unavailability ([#716](https://github.com/ethereum-optimism/infra/pull/716)).
*   **Runner Image Streamlining:** The team worked on transitioning to the `circleci-runner-wolfi` base image. This included removing redundant `protoc` and `protobuf-dev` dependencies to leverage the monorepo's `mise.toml` for version pinning ([#717](https://github.com/ethereum-optimism/infra/pull/717)).
*   **Image Maintenance:** The `ci-base-clang` image was migrated to be built directly within the `infra` repository to ensure long-term availability and easier updates ([#719](https://github.com/ethereum-optimism/infra/pull/719), [#720](https://github.com/ethereum-optimism/infra/pull/720)).
*   **Database Optimization:** Optimized `cci-stats` performance by replacing inefficient `test_results` indexes with a more performant composite index ([#721](https://github.com/ethereum-optimism/infra/pull/721)).

### Security & Dependency Management
*   **Module Updates:** A security update for `golang.org/x/mod` (v0.40.0) was rolled out across several core components, including `op-signer`, `op-txproxy`, and `proxyd` ([#714](https://github.com/ethereum-optimism/infra/pull/714)).
*   **Dependency Rollups:** Foundational Go dependencies were synchronized across services to resolve `gnark-crypto` conflicts and align `geth` consumer versions ([#722](https://github.com/ethereum-optimism/infra/pull/722)).

### Protocol & Service Improvements
*   **Proxyd Refinement:** Implemented a fix to evict out-of-order buckets in the sliding window rate-limiter to improve accuracy ([#718](https://github.com/ethereum-optimism/infra/pull/718)).

## 🐛 Issues & Triage

### Closed Issues
*   **SDM Performance Benchmarking:** Following extensive A/B testing, the SDM feature was confirmed to have no measurable impact on CPU or RSS at 10-30 TPS. Gas accounting showed a 60.9% saving on repeated-slot workloads, and the issue was closed as production-ready ([#20176](https://github.com/ethereum-optimism/infra/issues/20176)).
*   **P2P Connectivity:** The long-standing flakiness between `op-reth` and `op-geth` was resolved via peer-ID normalization. The `SKIP_P2P_CONNECTION_CHECK` workaround has been removed, re-enabling full verification in Rust e2e jobs ([#18570](https://github.com/ethereum-optimism/infra/issues/18570)).
*   **Kona-node Config:** A request for inline base64 handling for L1 chain configs was closed; the team determined this should be handled at the deployment layer via file mounting ([#22491](https://github.com/ethereum-optimism/infra/issues/22491)).

### New & Active Issues
*   **Interoperability Flakes:** Investigation continues into the `TestSupernodeLightSequencerInteropInvalidMessageReplacement` flake. Analysis confirmed a race condition in assertions rather than an environmental failure, leading to a split in tracking for different signature failure modes ([#22234](https://github.com/ethereum-optimism/infra/issues/22234), [#22325](https://github.com/ethereum-optimism/infra/issues/22325)).
*   **Storage Proof Race Conditions:** `TestStorageProofUsingSimpleStorageContract` resurfaced as a flake. Current evidence suggests the proofs indexing engine may be starving during CI runs, requiring an investigation into worker progress and potential timeout increases ([#20376](https://github.com/ethereum-optimism/infra/issues/20376)).
*   **PCD Benchmarking:** The `[PCD] Default-X benchmarking` issue was reopened due to lingering TODOs in `op-deployer` causing CI failures, signaling incomplete cleanup or documentation ([#20916](https://github.com/ethereum-optimism/infra/issues/20916)).

## 💬 Community & Collaboration
The week was characterized by high-intensity debugging of CI flakes and performance validation. The collaboration between infrastructure and protocol engineers was evident in the SDM benchmarking, where detailed tracing and gas accounting analysis were used to validate protocol changes. The automated `todo-issue-checks` CI job played a visible role in maintaining repository hygiene by reopening stale issues with active code references, ensuring that technical debt in `op-deployer` remains visible to the team.

# ethereum-optimism/infra Weekly Report (Mar 15 - 21, 2026)

## 🚀 Highlights
This week focused heavily on hardening the Optimism infrastructure through significant CI/CD stabilization and the resolution of long-standing flaky tests. A major milestone was reached with the complete migration of the monorepo's build system from Makefiles to Justfiles, streamlining the developer experience. While the team addressed critical node synchronization logic and investigated "bad block" reports on Base Mainnet, they also introduced enhanced observability features for `proxyd` to better track transaction performance across the Superchain.

## 🛠️ Key Developments

### Proxyd Enhancements & Connectivity
The `proxyd` component received updates aimed at improving both observability and security for node operators.
*   **Enhanced Transaction Logging:** Introduced detailed logging for `sendRawTransaction` events. When enabled, the system now captures `tx_hash`, `req_id`, and `duration_ms`, providing better visibility into backend performance ([#569](https://github.com/ethereum-optimism/infra/pull/569)).
*   **Secure Upstreams:** A new pull request was opened to add backend mTLS support for websocket upstreams, ensuring more secure communication between the proxy and its backends ([#570](https://github.com/ethereum-optimism/infra/pull/570)).

### Infrastructure & Tooling Migration
*   **Makefile to Justfile Migration:** The project successfully completed the transition of all Makefiles to Justfiles across the monorepo. This involved seven migration PRs and updates to CI scripts, Dockerfiles, and documentation ([#19546](https://github.com/ethereum-optimism/infra/issues/19546)).
*   **Dependency Management:** Updated `google.golang.org/grpc` within the `/op-ufm` (User Facing Monitoring) package to maintain security and compatibility ([#571](https://github.com/ethereum-optimism/infra/pull/571)).

### CI Stability and Test Refactoring
Significant effort was directed toward reducing "noise" in the CI pipeline by fixing non-deterministic tests.
*   **Flaky Test Stabilization:** Resolved several race conditions and timeout issues in tests including `TestBreakTimestampInvariant`, `TestExpiredMessage`, and `TestImplementations`.
*   **Test Deduplication:** Progressed on merging `op-e2e` and `op-acceptance-tests` to reduce maintenance overhead, successfully moving three major test suites to the shared `superfaultproofs` package ([#19010](https://github.com/ethereum-optimism/infra/issues/19010)).

## 🐛 Issues & Triage

### Closed Issues
*   **Supernode Reporting:** Fixed a bug where `op-supernode` incorrectly reported the derived L1 instead of the verified L1 ([#18651](https://github.com/ethereum-optimism/infra/issues/18651)).
*   **Blob Archiver:** An issue regarding missing endpoint support for beacon fallbacks was triaged and moved to the dedicated `blob-archiver` repository ([#19623](https://github.com/ethereum-optimism/infra/issues/19623)).

### New & Active Issues
*   **Base Mainnet "Bad Block" Investigation:** A critical issue was reported regarding an "invalid gas used" error on Base Mainnet (block 43504471), leading to persistent payload insertion failures ([#778](https://github.com/ethereum-optimism/infra/issues/778)).
*   **op-node Sync Logic:** Ongoing debate continues regarding how `op-node` handles finalization during initial Execution Layer (EL) sync. Proposals include using a "finalization gadget" based on L1 timestamps to prevent the node from incorrectly marking unfinalized blocks as finalized ([#17631](https://github.com/ethereum-optimism/infra/issues/17631)).
*   **op-reth Stability:** Users reported memory leaks in `op-reth` database transactions on World Chain and state root mismatches on Base. Some users have opted to switch to specific forks (e.g., the Base fork of `op-reth`) while these upstream issues are investigated ([#19212](https://github.com/ethereum-optimism/infra/issues/19212), [#19532](https://github.com/ethereum-optimism/infra/issues/19532)).
*   **CI Resource Contention:** The `memory-all-opn-op-geth` job continues to hang. Investigation suggests that RPC calls within polling loops are using overly broad contexts, causing indefinite blocks when CI resources are constrained ([#19563](https://github.com/ethereum-optimism/infra/issues/19563)).

## 💬 Community & Collaboration
The week was characterized by high-quality technical troubleshooting between the Optimism core team and ecosystem partners like Base and World Chain. Community members provided detailed logs and reproduction steps for `op-reth` memory leaks and state root mismatches, which has been vital for cross-repo coordination. There is also active collaboration on the `kona-interop` block hash oracle, with contributors working to ensure robust integration tests for historical block lookups ([#18288](https://github.com/ethereum-optimism/infra/issues/18288)).

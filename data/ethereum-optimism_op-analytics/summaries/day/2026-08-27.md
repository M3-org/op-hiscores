# ethereum-optimism/op-analytics Daily Update (Aug 27, 2026)
## OVERVIEW 
Today's focus was on addressing critical issues within the `op-analytics` repository, including a significant pull request to replace Blocknative for blob base fee and Eth migration, alongside in-depth discussions and resolutions for several long-standing issues related to `op-supernode` and `kona-node` stability.

## KEY TECHNICAL DEVELOPMENTS

No new features, bug fixes, code refactoring, documentation enhancements, tests added, or other work were completed today.

## NEWLY OPENED PULL REQUESTS
- A new pull request, [#1800](https://github.com/ethereum-optimism/op-analytics/pull/1800), was opened to replace Blocknative with a public RPC for blob base fee and migrate Eth.

## CLOSED ISSUES

- **Supernode Interoperability Stability:** The `op-supernode` cross-safe wedge issue, [#22325](https://github.com/ethereum-optimism/op-analytics/issues/22325), was closed after extensive investigation revealed it to be a single occurrence in 7.5 weeks, with the root cause identified as a parent-hash mismatch on chain 901 during invalidation recovery.
- **Kona Genesis Configuration Leniency:** The issue regarding `kona-genesis` silently accepting unknown `rollup.json` keys, [#22682](https://github.com/ethereum-optimism/op-analytics/issues/22682), was closed as "not planned." The leniency was determined to be deliberate to support retired keys, and existing superchain-registry config tests cover unmodeled fields.

## NEW ISSUES

- **Kona Node Sequencer Wedging:** A new issue, [#22681](https://github.com/ethereum-optimism/op-analytics/issues/22681), was opened to address a critical problem where a `kona-node` sequencer can become permanently wedged in a `forkchoiceUpdated -38002` loop if the engine reorgs its unsafe head while a block build is in progress.
- **SuperchainERC20 Compatibility Gap:** A new issue, [#1020](https://github.com/ethereum-optimism/op-analytics/issues/1020), was created to highlight the lack of a supported way for developers to check if a token address is SuperchainERC20 compatible, a capability previously provided by the `superchainerc20-compatibility` repository, which is slated for archiving.

## ACTIVE ISSUES

- **NetworkActor Stalling in Kona Node:** In [#22646](https://github.com/ethereum-optimism/op-analytics/issues/22646), `jdodinh` expressed interest in picking up the issue. They raised two questions regarding the overflow policy (parity with [#22585](https://github.com/ethereum-optimism/op-analytics/issues/22585)) and whether the deadline change could be landed separately. They also plan to confirm the stalling behavior by running a `kona-node` sequencer against a signer with injected latency.
- **Starter Examples Documentation Audit:** For [#1014](https://github.com/ethereum-optimism/op-analytics/issues/1014), `jefr90` completed the reference map, concluding that no live documentation links any of the six starter repos or the four archive-sweep repos, thus archiving will not break published docs. They also noted that the `docs` repo was archived in April 2026, and current documentation builds from the monorepo.
- **Consolidating Starter Examples:** In [#1015](https://github.com/ethereum-optimism/op-analytics/issues/1015), `jefr90` provided a detailed migration analysis, recommending consolidating five `superchain-starter*` repos into the existing `superchain-starter` repo, while leaving `superchainerc20-starter` independent due to its distinct nature and popularity. They suggested a plain copy with a pointer to the original for history preservation and identified three external README links that need fixing.
- **Archiving Abandoned Repos:** For [#1017](https://github.com/ethereum-optimism/op-analytics/issues/1017), `jefr90` confirmed that no live documentation links any of the four repos slated for archiving. They also reconstructed the purpose of `superchainerc20-compatibility`, noting its checks are partially obsolete due to changes in the OP Stack but that the capability remains relevant. The main blocker for archiving is the need for org admin permissions.
- **SuperchainERC20 Compatibility Checking:** In [#1020](https://github.com/ethereum-optimism/op-analytics/issues/1020), `jefr90` provided a correction and additional context, noting that the mint/burn permission checks might become valid again if [#22259](https://github.com/ethereum-optimism/optimism/pull/22259) (reviving `SuperchainTokenBridge` and `SuperchainERC20`) is merged. This potential revival, coupled with the need for token interop for Ink, significantly raises the priority of this issue, as a checker would address confusion arising from tokens that appear compatible but are not. The suggested sequencing is to hold this issue until [#22259](https://github.com/ethereum-optimism/optimism/pull/22259) resolves.

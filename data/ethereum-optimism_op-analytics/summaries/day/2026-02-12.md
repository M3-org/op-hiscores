# ethereum-optimism/op-analytics Daily Update (Feb 12, 2026)
## OVERVIEW 
The day focused on critical bug fixes, addressing a ClickHouse concurrent session error and a CircleCI BigQuery authentication issue. These improvements enhance the stability and reliability of data processing and CI/CD pipelines.

## KEY TECHNICAL DEVELOPMENTS

### ClickHouse Stability Improvements
A significant bug causing concurrent session errors in ClickHouse was resolved by ensuring each thread in `ThreadPoolExecutor` uses a new ClickHouse client. This prevents conflicts and improves the robustness of data processing, particularly in `get_qualified_txs`. Additionally, safeguards were added for empty DataFrames. ([#1794](https://github.com/ethereum-optimism/op-analytics/pull/1794))

### CI/CD Authentication Fix
A critical fix was implemented for CircleCI BigQuery authentication failures. The issue, stemming from an oversized `google.subject` in OIDC v2 tokens, was resolved by prioritizing the use of OIDC v1 tokens, which have a shorter `sub` claim. This ensures the smooth operation of daily CI/CD pipelines. ([#1793](https://github.com/ethereum-optimism/op-analytics/pull/1793))

## ACTIVE ISSUES

### Kona Hint Format Optimization
Discussion continues on issue [#19125](https://github.com/ethereum-optimism/op-analytics/issues/19125) regarding changing the Kona hint format from string serialization to a binary format. The latest comments highlight a debate between "making things right" (binary format for correctness) and "making things fast" (potential performance gains). A key concern is backward compatibility, with the host program needing to support existing string-based hints. The proposer is exploring approaches to preserve compatibility while implementing the binary format.

### Multi-Sequencer RPC Endpoint Support
The discussion on issue [#763](https://github.com/ethereum-optimism/op-analytics/issues/763) revolves around supporting multiple sequencer RPC endpoints for `op-geth` with automatic failover. The latest comment emphasizes that while infrastructure-level redundancy is ideal, this change offers optional client-side failover as a defense-in-depth measure against CDN or regional failures, without replacing proper sequencer high availability. This addresses concerns about user-unfriendliness and the need for a single, highly reliable URL.

### Flaky test: `TestSupernodeLightSequencerInteropInvalidMessageReplacement` [#21635](https://github.com/ethereum-optimism/op-analytics/issues/21635)
The `TestSupernodeLightSequencerInteropInvalidMessageReplacement` test is exhibiting flakiness in CI. The root cause has been identified: in follow-mode light sequencer runs, `FollowSource` could process an upstream local-safe head ahead of the current unsafe head, leading to stale queued build work. This stale build would then hit a "missing parent header" error, stopping the light sequencer. A draft PR ([ethereum-optimism/optimism#21637](https://github.com/ethereum-optimism/optimism/pull/21637)) has been created to address this by forcing a reset of active sequencers on upstream local-safe advance/divergence, clearing stale build states, and dropping stale queued build-start events.

### Re-enable or retire fuzzing [#21636](https://github.com/ethereum-optimism/op-analytics/issues/21636)
An audit of all Go fuzz tests in the repository was conducted. The audit revealed that the current time-bounded exploration (`go test -fuzz ... -fuzztime 10–60s`) in CI jobs has limited value because there is no committed corpus, seeds are sparse, and deterministic value is already covered by regular unit tests. The recommendation is to retire all six PR-time fuzzing jobs as they offer minimal benefit beyond the existing seed subtests and incur CI costs and maintenance overhead. The fuzz functions themselves will be kept as they continue to run as deterministic seed tests in normal unit test jobs. A separate ticket might be opened for a more effective nightly fuzzing job, but only if it includes a committed seed corpus, meaningful fuzz time, and crash-artifact persistence. The issue is being closed via PR #21639.

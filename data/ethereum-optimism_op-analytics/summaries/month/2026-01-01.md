# ethereum-optimism/op-analytics Monthly Report (January 2026)

## 🚀 Highlights
In January 2026, the `op-analytics` project focused on refining data extraction pipelines and streamlining the scope of its testing infrastructure. Key technical achievements included enhancing system configuration data with new fee and gas scalar fields and resolving critical serialization bugs in Dune data sources. The month was also characterized by a significant "housekeeping" effort, where several acceptance test issues for flashblocks and rollup-boost were closed or re-scoped to better align with the project's infrastructure capabilities and benchmarking milestones.

## 🛠️ Key Developments

### Data Pipeline & Schema Enhancements
The team implemented several updates to improve the depth and reliability of data ingested into the analytics platform.
*   **System Configuration:** Added `minBaseFee` and `daFootprintGasScalar` fields to system configuration pulls, providing better visibility into L2 economic parameters ([#1780](https://github.com/ethereum-optimism/op-analytics/pull/1780)).
*   **Clickhouse Integration:** Initiated updates to the System Config Transform within Clickhouse to ensure downstream data consistency ([#1782](https://github.com/ethereum-optimism/op-analytics/pull/1782)).
*   **Bug Fixes:** Resolved a critical date serialization issue in the Dune dextrades data source, ensuring accurate time-series data for decentralized exchange trades ([#1779](https://github.com/ethereum-optimism/op-analytics/pull/1779)).

### Infrastructure & Operations
Maintenance work ensured the stability of the underlying analytics stack.
*   **Dagster Configuration:** Updated Dagster Helm values and Makefiles to optimize the orchestration of data workflows ([#1781](https://github.com/ethereum-optimism/op-analytics/pull/1781)).

## 🐛 Issues & Triage

### Closed Issues
*   **Acceptance Test Re-scoping:** A large batch of issues related to flashblocks and rollup-boost (including sequencer failover and kill-switch tests) were closed ([#314](https://github.com/ethereum-optimism/op-analytics/issues/314), [#316](https://github.com/ethereum-optimism/op-analytics/issues/316), [#317](https://github.com/ethereum-optimism/op-analytics/issues/317), [#318](https://github.com/ethereum-optimism/op-analytics/issues/318), [#350](https://github.com/ethereum-optimism/op-analytics/issues/350)). These were determined to require infrastructure manipulation beyond the current scope of `op-acceptance-tests`.
*   **Load Testing:** Flashblocks load testing ([#379](https://github.com/ethereum-optimism/op-analytics/issues/379)) was moved to the Benchmarking Milestone for future automation.
*   **Validation Fixes:** A long-standing concurrent map read/write error during chain validation checks was resolved and closed ([#668](https://github.com/ethereum-optimism/op-analytics/issues/668)).
*   **Developer Support:** Clarified OP Stack compatibility regarding Base-style minimal contracts, confirming standard L1 smart contract functionality with documented exceptions ([#18709](https://github.com/ethereum-optimism/op-analytics/issues/18709)).

### New & Active Issues
*   **Kona & SyncStatus:** Significant discussion persists regarding the `SyncStatus` RPC endpoint. The team is working to ensure `current_l1` correctly reflects the derivation cursor rather than the L1 head without introducing unnecessary complexity ([#18673](https://github.com/ethereum-optimism/op-analytics/issues/18673)).
*   **Supernode Integration:** Multiple active issues ([#18651](https://github.com/ethereum-optimism/op-analytics/issues/18651), [#18667](https://github.com/ethereum-optimism/op-analytics/issues/18667)) highlight dependencies on interoperability support within the supernode for accurate L1 reporting.
*   **Protocol Readiness:** Work is pending on OPCM to generate Pectra rollup configuration fields ([#14816](https://github.com/ethereum-optimism/op-analytics/issues/14816)).

# ethereum-optimism/superchain-ops Weekly Report (Jan 25 - 31, 2026)

## 🚀 Highlights
This week focused on refining protocol upgrade infrastructure and enhancing the robustness of the Superchain's operational tooling. Key activities included streamlining artifact management for upcoming releases and upgrading core development dependencies like Foundry to maintain modern standards. Significant technical discussions also centered on the `op-supernode` SyncStatus API and interop-ready withdrawal proofs, ensuring the ecosystem remains prepared for multi-chain scalability and seamless cross-chain functionality.

## 🛠️ Key Developments
While no major features were finalized this week, significant groundwork was laid through infrastructure updates and operational rehearsals.

### Tooling & Infrastructure Upgrades
Efforts to maintain a high-standard development environment resulted in several key updates:
- **Foundry Dependency Upgrade:** Development tooling was updated to v1.4.3 to ensure compatibility with the latest smart contract testing features ([#1358](https://github.com/ethereum-optimism/superchain-ops/pull/1358)).
- **Submission Robustness:** New simulation requirements were introduced for task PR submissions, aimed at catching errors early and enhancing the reliability of new feature deployments ([#1357](https://github.com/ethereum-optimism/superchain-ops/pull/1357)).

### Operational Security & Testing
- **OPSC Rehearsal:** A new rehearsal was initiated specifically to test the removal of a signer, a critical security procedure for maintaining the integrity of the Optimism Security Council (OPSC) operations ([#1359](https://github.com/ethereum-optimism/superchain-ops/pull/1359)).

## 🐛 Issues & Triage
The project saw active movement in refining protocol checks and planning for future interoperability requirements.

### Closed Issues
- **Protocol Upgrade Refinement:** Checks for OPCM v2 (Optimism Protocol Configuration Manager) were refined following the successful merge of the Custom Gas Token (CGT) PR, allowing for the removal of redundant validation logic ([#18536](https://github.com/ethereum-optimism/superchain-ops/issues/18536)).
- **Artifact Management:** An issue regarding Resource Locators for v7_0_0 artifacts was closed as the team streamlined the management of work-in-progress files ([#18633](https://github.com/ethereum-optimism/superchain-ops/issues/18633)).

### New & Active Issues
- **`op-supernode` SyncStatus API:** Intensive discussion is underway to define how the supernode reports sync status across multiple chains. The focus is on ensuring the API reports `op-node` status for every chain and verification activity, including the latest verified L2, to simplify acceptance testing ([#18947](https://github.com/ethereum-optimism/superchain-ops/issues/18947)).
- **Withdrawal Proof Updates:** The update to `OptimismPortal2.proveWithdrawalTransaction` has been moved to the backlog. This is a strategic postponement, as the update depends on the U19 execution and requires FaultDisputeGames to support new `rootClaimByChainId` methods to prevent withdrawal disruptions ([#18517](https://github.com/ethereum-optimism/superchain-ops/issues/18517)).
- **`op-alloy` Decoding:** Work is beginning on fixing EIP-1559 parameter decoding within `op-alloy` to ensure zero elasticities are caught early in the process ([#18951](https://github.com/ethereum-optimism/superchain-ops/issues/18951)).

## 💬 Community & Collaboration
Collaboration this week was characterized by deep technical design discussions and community interest in core library maintenance. The `op-supernode` API definition saw significant back-and-forth between contributors to ensure the interface meets the needs of interop testing. Additionally, the `op-alloy` decoding issue ([#18951](https://github.com/ethereum-optimism/superchain-ops/issues/18951)) attracted community interest, with external contributors expressing a desire to assist in the fix, signaling healthy engagement with the project's underlying libraries.

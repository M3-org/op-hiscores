# ethereum-optimism/superchain-ops Weekly Report (Mar 8 - 14, 2026)

## 🚀 Highlights
This week, development focused on aligning the Superchain infrastructure with recent protocol upgrades and addressing critical stability issues within the `op-node` and `op-reth` environments. Significant effort was directed toward updating dispute game templates to accommodate breaking changes in U18 OPCM, while the team also tackled a permanent node crash loop related to deposits-only attributes. Discussions regarding repository health surfaced as a major concern, with contributors highlighting how historical bloat and large binaries are impacting developer experience and CI/CD efficiency.

## 🛠️ Key Developments

### Protocol & Governance Infrastructure
*   **Dispute Game Template Updates:** The `addGameType` and `setDisputeGame` templates were updated to align with breaking changes introduced in U18 OPCM. These modifications specifically address implied proxies within `src/template` and `test/tasks` to ensure compatibility with the latest protocol standards ([#1378](https://github.com/ethereum-optimism/superchain-ops/pull/1378)).
*   **Fee Vault Management:** A new feature was implemented to update the Arena-Z Sepolia fee vault recipient ([#1381](https://github.com/ethereum-optimism/superchain-ops/pull/1381)).
*   **Upgrade Task Management:** New functionality was introduced to allow for the cancellation of upgrade tasks, providing more flexibility during deployment cycles ([#1382](https://github.com/ethereum-optimism/superchain-ops/pull/1382)).

### Derivation & Node Stability
*   **Derivation Pipeline Hardening:** An audit of external input error handling was completed. The pipeline now ensures that malformed L1 inputs do not halt the derivation process, increasing the resilience of the network ([#19491](https://github.com/ethereum-optimism/superchain-ops/issues/19491)).
*   **Span Batch Handling:** The team resolved an issue where span batch extraction failures in the `BatchQueue` were returning `Critical` errors. The fix preserves historical behavior for pre-Holocene networks by flushing instead of halting ([#19511](https://github.com/ethereum-optimism/superchain-ops/issues/19511)).
*   **Configuration Consistency:** A mismatch between the description and examples for the `max-blocks-per-span-batch` variable was corrected to prevent operator confusion ([#2000](https://github.com/ethereum-optimism/superchain-ops/pull/2000)).

## 🐛 Issues & Triage

### Closed Issues
*   **Documentation Migration:** The tracking issue for Rust Docs Hosting was closed as the scope has been integrated into the broader documentation migration project ([#1985](https://github.com/ethereum-optimism/superchain-ops/issues/1985)).

### New & Active Issues
*   **Critical Node Crash Loop:** A high-priority issue ([#19509](https://github.com/ethereum-optimism/superchain-ops/issues/19509)) was identified where `op-node` enters a permanent crash loop due to `CriticalErrorEvent` during deposits-only attributes failures. Developers are currently debating whether to solve this via unit tests or more comprehensive integration tests ([#19465](https://github.com/ethereum-optimism/optimism/pull/19465), [#19466](https://github.com/ethereum-optimism/optimism/pull/19466)).
*   **`op-reth` Memory Leak:** Investigation continues into a memory leak on World Chain v1.10.1 triggered by long-running database read transactions. Users are currently testing if the v1.11.0 upgrade provides a permanent resolution ([#19212](https://github.com/ethereum-optimism/superchain-ops/issues/19212)).
*   **Repository Bloat:** A significant discussion emerged regarding the 1.04 GB size of the `.git` directory. Contributors noted that cloning the repository can take over two hours, citing un-published Rust crates and historical binaries as the primary causes of this friction ([#19241](https://github.com/ethereum-optimism/superchain-ops/issues/19241)).

## 💬 Community & Collaboration
The week was characterized by active technical debate regarding testing strategies for protocol-level errors. Maintainers like `ajsutton` and contributors like `incompleteloop` provided critical feedback on repository maintenance and the limitations of current unit testing for complex state failures. There is a clear push from the community to improve the "Developer Experience" focus area by addressing the repository size and dependency management issues that currently hinder new contributors. Collaboration between the Optimism core team and ecosystem partners (such as World Chain) remains vital for identifying and patching edge-case memory leaks in execution clients.

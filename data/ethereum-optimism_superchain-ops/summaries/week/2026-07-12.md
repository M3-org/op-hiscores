# ethereum-optimism/superchain-ops Weekly Report (Jul 12 - 18, 2026)

## 🚀 Highlights
This week, development focused on refining Safe multisig workflows and addressing architectural debt within the OP Stack's dispute and testing frameworks. Key progress was made in streamlining Safe owner rotations and presigning capabilities, alongside critical discussions regarding the `op-revm` synchronization for the Amsterdam hardfork. The team also tackled persistent integration test flakiness and finalized decisions on RPC default configurations to balance security with containerized accessibility.

## 🛠️ Key Developments

### Safe Task Management & Owner Rotations
Significant work was dedicated to improving the flexibility and reliability of Safe multisig operations, particularly concerning owner transitions.
*   **Presigning Workflows:** Introduced an override allowing new Safe owners to presign follow-up tasks before the transaction adding them as an owner has officially executed ([#1497](https://github.com/ethereum-optimism/superchain-ops/pull/1497)).
*   **Simulation Accuracy:** Fixed a bug where Safe task simulations incorrectly modified the root owner list, which previously disrupted first-owner rotations ([#1499](https://github.com/ethereum-optimism/superchain-ops/pull/1499)).
*   **Owner Preservation:** Opened a new PR to ensure the preservation of Safe owners during simulation overrides ([#1498](https://github.com/ethereum-optimism/superchain-ops/pull/1498)).

### Protocol & Dispute Game Refinement
Discussions centered on simplifying the interaction between the `op-challenger` and the `AnchorStateRegistry`.
*   **Dispute Game Interface:** Proposed adding `closeGame()` to the generic `IDisputeGame` interface to resolve issues where the `SuperPermissionedDisputeGame` lacked a method to update the anchor state registry ([#21678](https://github.com/ethereum-optimism/superchain-ops/issues/21678), [#21708](https://github.com/ethereum-optimism/superchain-ops/issues/21708)).

## 🐛 Issues & Triage

### Closed Issues
*   **RPC Default Configuration:** Issue [#16487](https://github.com/ethereum-optimism/superchain-ops/issues/16487) was closed as "not planned." The team determined that `0.0.0.0` remains the appropriate default for Docker reachability, concluding that security should be managed via opt-in privileged APIs rather than restrictive bind addresses.

### New & Active Issues
*   **`op-revm` Synchronization:** There is active pressure to update the `op-revm` crate to version v111 to support the Amsterdam hardfork and ensure compatibility with Hardhat 3 ([#21069](https://github.com/ethereum-optimism/superchain-ops/issues/21069)).
*   **Kona Soundness:** Issue [#18430](https://github.com/ethereum-optimism/superchain-ops/issues/18430) was reopened after a TODO was identified in the `kona` fetcher, indicating that mandatory request retries are still missing.
*   **Test Flakiness:** The `reth-optimism-node` integration tests continue to suffer from non-deterministic SIGSEGV failures during teardown ([#20973](https://github.com/ethereum-optimism/superchain-ops/issues/20973)). The root cause appears to be a race condition involving unjoined critical OS threads.
*   **E2E Test Modernization:** Efforts are underway to retire the in-process `op-geth` L2 execution engine in system tests, folding older pre-Regolith test issues into a broader cleanup effort ([#21451](https://github.com/ethereum-optimism/superchain-ops/issues/21451)).

## 💬 Community & Collaboration

# ethereum-optimism/superchain-ops Weekly Report (Jan 18 - 24, 2026)

## 🚀 Highlights
This week was defined by the successful execution of the **Upgrade 18 (U18)** deployment across both Sepolia and Mainnet environments, marking a significant milestone for the Superchain ecosystem. Alongside these deployments, the team achieved a massive boost in developer productivity by resolving an Etherscan API rate-limiting bug that reduced simulation times from 30 minutes to under a minute. Technical focus also shifted toward hardening the protocol, with deep-dive investigations into `op-reth` batcher throttling and complex reset handling strategies for `op-supernode`.

## 🛠️️ Key Developments

### Superchain Upgrade 18 (U18) Deployments
The primary focus of the week was the rollout of U18 across a wide array of networks, ensuring parity and updated protocol logic across the Superchain.
*   **Sepolia Rollout:** Successfully deployed U18 to Sepolia instances for OP, Ink, Metal, Mode, Zora, Arena-Z, Soneium, and Uni [#1332](https://github.com/ethereum-optimism/superchain-ops/pull/1332).
*   **Mainnet Rollout:** Followed up with Mainnet deployments for OP, Ink, Metal, Mode, Zora, Arena-Z, Swell, Soneium, and Uni [#1334](https://github.com/ethereum-optimism/superchain-ops/pull/1334).

### Security Operations & Governance
Maintenance of security infrastructure and governance rehearsals remained a priority to ensure operational readiness.
*   **Rehearsal Refactoring:** Refactored security council rehearsal scripts and related files to improve the reliability of upgrade simulations [#1333](https://github.com/ethereum-optimism/superchain-ops/pull/1333).
*   **Signer Management:** Rotated anonymous signers for FuS and FoS on Mainnet to maintain security hygiene [#1348](https://github.com/ethereum-optimism/superchain-ops/pull/1348).
*   **New Tasks:** Initiated an OPSC R1 welcome rehearsal [#1350](https://github.com/ethereum-optimism/superchain-ops/pull/1350) and added a betanet task to enable revenue sharing [#1349](https://github.com/ethereum-optimism/superchain-ops/pull/1349).

### Performance & Developer Experience
A critical fix addressed a bottleneck in the development workflow.
*   **Simulation Speedup:** By unsetting the `ETHERSCAN_API_KEY` to prevent rate limiting, simulation times were reduced from ~30 minutes to ~35 seconds, a significant improvement for local testing and CI workflows [#1351](https://github.com/ethereum-optimism/superchain-ops/pull/1351).

## 🐛 Issues & Triage

### Active Technical Discussions
*   **`op-supernode` Reset Handling ([#18740](https://github.com/ethereum-optimism/superchain-ops/issues/18740)):** Developers are debating how to handle `engine_forkchoiceUpdatedV1` behavior. The current path involves a temporary workaround using synthetic blocks, while long-term solutions under consideration include a new engine API method or deeper integration with existing reorg mechanisms.
*   **`op-reth` Batcher Throttling ([#18764](https://github.com/ethereum-optimism/superchain-ops/issues/18764)):** Analysis revealed that while `op-reth` has throttling mechanisms, it lacks the robust testing suite found in `op-rbuilder`. Future work will likely involve backfilling tests for data availability and block size limits.
*   **P2P Connection Flakiness ([#18570](https://github.com/ethereum-optimism/superchain-ops/issues/18570)):** A high-priority investigation is underway regarding intermittent connection failures between `op-reth` and `op-geth`. This is viewed as a major bug affecting test stability and production compatibility.

### Ongoing Efforts
*   **Forge Deployer Conversion ([#17215](https://github.com/ethereum-optimism/superchain-ops/issues/17215)):** This long-standing architectural migration remains active, with contributors coordinating on the original implementation details.

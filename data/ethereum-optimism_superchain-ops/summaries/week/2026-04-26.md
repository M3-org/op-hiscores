# ethereum-optimism/superchain-ops Weekly Report (Apr 26 - May 2, 2026)

## 🚀 Highlights
This week focused on enhancing the stability of the Superchain infrastructure through critical CI/CD fixes and protocol-level debugging. Key achievements included resolving a persistent test crash in the `kona-host-client-offline-cannon` suite and refining the L2CM upgrade process via bundle canonicalization. The team also made significant progress in diagnosing a fresh-genesis boot issue in LightCL and continued to investigate intermittent flakiness in core node synchronization tests.

## 🛠️ Key Developments
While much of the week was dedicated to infrastructure maintenance and debugging, several pull requests were initiated to update the Superchain ecosystem's configuration and templates.

### Registry and Template Management
- **Superchain Registry Updates:** A new pull request was opened to bump the superchain registry version ([#1409](https://github.com/ethereum-optimism/superchain-ops/pull/1409)), ensuring the ops repository remains aligned with the latest network configurations.
- **Standardized Templates:** The introduction of a new U19 template ([#1408](https://github.com/ethereum-optimism/superchain-ops/pull/1408)) suggests ongoing work to standardize operational procedures across the Superchain.

### Testing and Infrastructure
- **CI Stability:** Developers resolved a significant crash in the `kona-host-client-offline-cannon` test. By bind-mounting a corrected `mips64-unknown-none.json` and refreshing the witness tar, the CI now correctly verifies successful runs rather than masking panics ([#19895](https://github.com/ethereum-optimism/superchain-ops/issues/19895)).
- **Test Environment:** A dedicated PR ([#1407](https://github.com/ethereum-optimism/superchain-ops/pull/1407)) was opened specifically for testing purposes to validate environment configurations.

## 🐛 Issues & Triage

### Closed Issues
- **L2CM Upgrade Process:** The team successfully closed the issue regarding Bundle Canonicalization for L2CM Upgrades ([#19307](https://github.com/ethereum-optimism/superchain-ops/issues/19307)). This marks a milestone in automating the workflow for updating bundled NUTs (Network Upgrade Tokens) per hardfork.
- **CI Job Failures:** As noted in the developments section, the resolution of the Cannon builder target specification ([#19895](https://github.com/ethereum-optimism/superchain-ops/issues/19895)) has improved the reliability of the offline-cannon test suite.

### New & Active Issues
- **LightCL Genesis Boot Logic:** A critical observation was made regarding `safe_l2` and `finalized_l2` values remaining at zero during fresh-genesis boots ([#20295](https://github.com/ethereum-optimism/superchain-ops/issues/20295)). The investigation suggests that genesis `L2BlockRef`s are being incorrectly treated as "unset" because the system relies on block numbers (which are zero for both cases). A fix involving full block identity checks is under discussion.
- **Persistent Test Flakiness:** The `TestReorgUnsafeHead` test ([#20198](https://github.com/ethereum-optimism/superchain-ops/issues/20198)) remains a challenge. Despite previous attempts to fix it, the issue recurred this week. The proposed solution involves replacing `time.Sleep` with a more robust polling mechanism on `SyncStatus`.
- **`op-alloy` Dependency Conflict:** Users are reporting a trait implementation conflict between `NetworkWallet<Optimism>` and `EthereumWallet` ([#20281](https://github.com/ethereum-optimism/superchain-ops/issues/20281)). While a fix exists in the main `optimism` repository, the community is awaiting a new release on crates.io to resolve the downstream breakage.

## 💬 Community & Collaboration
The week's activity was characterized by deep technical troubleshooting between core contributors. **karlfloersch** provided pivotal insights into the LightCL genesis issue, while **pauldowman** and **ajsutton** collaborated on the asynchronous update mechanisms within `op-node`. There is a notable community demand for maintenance updates on the `op-alloy` crate, as evidenced by the discussions in issue [#20281](https://github.com/ethereum-optimism/superchain-ops/issues/20281), highlighting the importance of timely releases for downstream developer experience.

# ethereum-optimism/superchain-ops Weekly Report (Apr 5 - 11, 2026)

## 🚀 Highlights
This week, development focused on critical protocol stability and a comprehensive audit of the repository's dependency footprint. Engineers identified and began addressing a significant receipt root mismatch bug affecting older OP Stack chains, a discovery that has broader implications for cross-chain validation. Alongside these security and consensus efforts, the team initiated a major cleanup of the monorepo, targeting unused Go, npm, and Python dependencies to optimize the build pipeline. The project also neared a significant milestone with progress tracked under the Monorepo Milestone ([#10000](https://github.com/ethereum-optimism/superchain-ops/issues/10000)).

## 🛠️ Key Developments

### Protocol Security & Consensus
*   **L2ContractsManager Storage Protection:** Resolved a critical security concern regarding potential storage variable collisions in `L2ContractsManager`. The fix ensures safety when the manager is executed via `DELEGATECALL` ([#19315](https://github.com/ethereum-optimism/superchain-ops/issues/19315)).
*   **Receipt Root Validation:** Investigation into `op-reth` revealed that receipt tries were being incorrectly built for pre-Canyon rules. The team is working on a fix to ensure Canyon-awareness during trie encoding and to gate the `receipt_root_bloom` shortcut to prevent unconditional trust of precomputed data ([#19930](https://github.com/ethereum-optimism/superchain-ops/issues/19930)).

### Infrastructure & Tooling
*   **Configuration Templates:** Introduced a new feature template for `SetBatcherAndSigner`, streamlining the configuration process for chain operators ([#1393](https://github.com/ethereum-optimism/superchain-ops/pull/1393)).
*   **Dependency Optimization:** Launched a multi-language audit to reduce technical debt. This includes identifying "High Priority" Go dependencies for removal ([#19996](https://github.com/ethereum-optimism/superchain-ops/issues/19996)), as well as pruning unused npm packages, dead Docker images, and bloated Python requirements ([#20016](https://github.com/ethereum-optimism/superchain-ops/issues/20016)).

## 🐛 Issues & Triage

### Closed Issues
*   **Storage Collision Resolution:** The potential for `DELEGATECALL` collisions in the `L2ContractsManager` was successfully mitigated ([#19315](https://github.com/ethereum-optimism/superchain-ops/issues/19315)).
*   **Dependency Audit Scoping:** The initial broad issue for dependency cleanup ([#20016](https://github.com/ethereum-optimism/superchain-ops/issues/20016)) was closed in favor of more granular, language-specific tasks to streamline the removal process.

### New & Active Issues
*   **Receipt Root Mismatch ([#19930](https://github.com/ethereum-optimism/superchain-ops/issues/19930)):** This remains the most critical active issue. Testing has confirmed that this mismatch exists across multiple older OP Stack rollups, indicating a systemic issue in how `op-reth` handles legacy consensus rules.
*   **Monorepo Milestone ([#10000](https://github.com/ethereum-optimism/superchain-ops/issues/10000)):** Activity continues toward a major project milestone, with recent comments indicating the team is approaching the #20000 mark in total contributions/issues.

## 💬 Community & Collaboration
The week was characterized by deep technical troubleshooting regarding consensus logic. The discussion surrounding the receipt root mismatch ([#19930](https://github.com/ethereum-optimism/superchain-ops/issues/19930)) showed high levels of collaboration between contributors to pinpoint the specific failure in `proof.rs` and `validation/mod.rs`. Additionally, the systematic approach to dependency cleanup suggests a coordinated effort to improve the developer experience by reducing build times and repository bloat.

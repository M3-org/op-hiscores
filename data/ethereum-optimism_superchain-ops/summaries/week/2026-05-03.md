# ethereum-optimism/superchain-ops Weekly Report (May 3 - 9, 2026)

## 🚀 Highlights
This week focused on critical infrastructure upgrades and security maintenance for the Superchain, headlined by the integration of the **ZK-Dispute Game** into the Optimism Contracts Manager (OPCM). Significant progress was made on interoperability (interop) stress testing, confirming the system's resilience when handling old message references. Additionally, the team executed a vital security update with the rotation of the Mainnet deputy pause keys and resolved long-standing synchronization issues between `op-node` and `op-reth`.

## 🛠️ Key Developments

### OPCM Upgrades & ZK Integration
The project advanced its contract management capabilities to support new dispute game types.
*   **ZK-Dispute Game Integration:** Upgraded the OPCM fixture to v7.1.17, which now requires a `ZK_DISPUTE_GAME` entry in the dispute game configurations ([#1410](https://github.com/ethereum-optimism/superchain-ops/pull/1410)).
*   **Automation Tooling:** Introduced a task generator for devnet OPCM upgrades to streamline the deployment of new contract versions ([#1415](https://github.com/ethereum-optimism/superchain-ops/pull/1415)).

### Security & Infrastructure Maintenance
Critical updates were deployed to ensure the stability and security of the Mainnet and devnet environments.
*   **Mainnet Key Rotation:** Successfully rotated the `DeputyPauseModule` Deputy E key on Mainnet ([#1399](https://github.com/ethereum-optimism/superchain-ops/pull/1399)).
*   **Configuration Refactoring:** Improved devnet flexibility by making `safeAddressString` configurable via `config.toml` ([#1413](https://github.com/ethereum-optimism/superchain-ops/pull/1413)) and creating an address overrides table for devnets ([#1414](https://github.com/ethereum-optimism/superchain-ops/pull/1414)).
*   **Cleanup:** Removed the deprecated `ProtocolVersions` contract and unused test-only libraries to reduce technical debt ([#20309](https://github.com/ethereum-optimism/superchain-ops/issues/20309), [#1417](https://github.com/ethereum-optimism/superchain-ops/pull/1417)).

### Interoperability & Supernode Progress
Development continued on the "interop" roadmap, focusing on cross-chain consistency and performance.
*   **Interop Stress Testing:** Concluded testing on the expiry window for interoperability. Results confirmed that while processing old logs is resource-intensive, the system terminates cleanly and is limited by L2 gas limits rather than validation logic ([#15285](https://github.com/ethereum-optimism/superchain-ops/issues/15285)).
*   **Supernode Enhancements:** Migrated "after head" tests to `op-supernode`, leading to a bug fix, and implemented a workaround for SuperRoots regarding unsafe data ([#20370](https://github.com/ethereum-optimism/superchain-ops/issues/20370), [#19059](https://github.com/ethereum-optimism/superchain-ops/issues/19059)).

## 🐛 Issues & Triage

### Closed Issues
*   **Node Synchronization:** Resolved a persistent issue where `op-node` would hang in Execution Layer (EL) sync mode upon restarting when paired with `reth` ([#18468](https://github.com/ethereum-optimism/superchain-ops/issues/18468)).
*   **Challenger Configuration:** Fixed a configuration error in `op-challenger` where the Cannon prestate URL was incorrectly used for `SuperPermissionedGameType` instead of the Kona URL ([#20500](https://github.com/ethereum-optimism/superchain-ops/issues/20500)).
*   **Kona Prestates:** Achieved the ability to build fast Kona prestates outside of Docker environments ([#19057](https://github.com/ethereum-optimism/superchain-ops/issues/19057)).

### New & Active Issues
*   **Superroot Support:** A new requirement emerged for `op-node` to support `superroot_atTimestamp` for non-interop chains to facilitate the transition to fault dispute games ([#20552](https://github.com/ethereum-optimism/superchain-ops/issues/20552)).
*   **Flag Consolidation:** Discussions are underway regarding consolidating per-VM flags in `op-challenger` into global flags, though maintainers noted challenges due to varying config formats for different game types ([#20547](https://github.com/ethereum-optimism/superchain-ops/issues/20547)).
*   **Runbook Deferral:** The update for the Super Root Chain permissionless upgrade runbook has been deferred until after the interop release ([#20473](https://github.com/ethereum-optimism/superchain-ops/issues/20473)).

## 💬 Community & Collaboration
Technical discussions this week highlighted a strong focus on refining the developer experience for the Superchain. Maintainers like **sebastianst** and **ajsutton** were active in troubleshooting EL sync issues and defining the API requirements for superroot support. The collaboration between the protocol and tooling teams is evident in the coordinated effort to align `op-node` capabilities with the upcoming interop and ZK-dispute game milestones.

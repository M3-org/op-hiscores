# ethereum-optimism/superchain-ops Weekly Report (May 24 - 30, 2026)

## 🚀 Highlights
This week, the `superchain-ops` project focused heavily on diagnosing deep-seated stability issues within `op-reth` and refining the architectural integrity of the L2 Contracts Manager. A significant portion of the effort was dedicated to investigating `SIGBUS` crashes and Engine API stalls that are impacting CI reliability and node performance. Additionally, the team addressed security posture following a comprehensive vulnerability report and worked toward better synchronization of feature flag definitions across the stack.

## 🛠️ Key Developments
While no major pull requests were merged during this specific reporting window, the technical focus remained on stabilizing the core infrastructure and improving the developer experience through better documentation of system features.

*   **System Feature Synchronization:** The team established a plan to mitigate silent drift between feature flag definitions and the CI matrix. This involves implementing explicit documentation within `DevFeatures.sol` and `devFeatures.go` to ensure all necessary update locations are accounted for when new system features are introduced ([#20340](https://github.com/ethereum-optimism/superchain-ops/issues/20340)).
*   **Protocol Workarounds:** The team reached a consensus on maintaining the `FCU` retry-verify workaround in `RewindToTimestamp` for `op-supernode`. This decision follows the closure of upstream PRs and a lack of synchronous application in the Reth engine API ([#19772](https://github.com/ethereum-optimism/superchain-ops/issues/19772)).

## 🐛 Issues & Triage
The week saw a high volume of activity regarding protocol stability and contract integrity, with several complex issues being reopened for deeper investigation.

### New Issues
*   **Security Vulnerabilities:** A significant report ([#1431](https://github.com/ethereum-optimism/superchain-ops/issues/1431)) was submitted by 0xRAM Labs, identifying 11 potential vulnerabilities within the repository's smart contracts.
*   **Build Determinism:** A bug was identified in the generation of `semver-lock.json` ([#21032](https://github.com/ethereum-optimism/superchain-ops/issues/21032)). The issue arises when multiple Forge artifacts share a semver key but use different optimizer settings, leading to nondeterministic output.
*   **CI Regressions:** The `TestUnsafeChainNotStalling_CLSync` test family reported new flakes ([#21041](https://github.com/ethereum-optimism/superchain-ops/issues/21041)), which have been traced back to Engine API timeouts rather than simple test budget issues.

### Active & Reopened Issues
*   **`op-reth` Stability:** Investigation continues into `SIGBUS` crashes and infinite retry loops during deep FCU rewinds ([#20934](https://github.com/ethereum-optimism/superchain-ops/issues/20934)). Current hypotheses point to a race condition involving `File::set_len` during reorg flows, requiring coordination with the Reth core team.
*   **L2 Contracts Manager (L2CM) Refactoring:** Issue [#19260](https://github.com/ethereum-optimism/superchain-ops/issues/19260) was reopened to address a TODO regarding the "single source of truth" for predeploys. This highlights a need to refactor how implementation knowledge is synchronized across various data structures in `L2ContractsManager.t.sol`.

## 💬 Community & Collaboration
Collaboration this week was characterized by intensive cross-team diagnostic work. The investigation into `op-reth` stability ([#20934](https://github.com/ethereum-optimism/superchain-ops/issues/20934)) shows active engagement between Optimism contributors and the Reth core team to resolve low-level file system race conditions. Furthermore, the adversarial review of CI flakes ([#21041](https://github.com/ethereum-optimism/superchain-ops/issues/21041)) demonstrates a rigorous internal peer-review process, shifting the focus from superficial test fixes to addressing underlying Engine API stalls. The involvement of external security researchers (0xRAM Labs) also indicates ongoing external scrutiny of the Superchain's smart contract infrastructure.

# ethereum-optimism/superchain-ops Weekly Report (Feb 1 - 7, 2026)

## 🚀 Highlights
This week focused on advancing the Superchain’s operational readiness through betanet upgrades and security rehearsal preparations. Key technical efforts centered on refining the `op-supernode` architecture, specifically regarding how it manages "Safe" labels and interacts with the Execution Layer. The team also implemented stricter quality controls for task submissions and addressed critical synchronization bugs in `op-node`. Overall, the week demonstrated a strong push toward protocol stability and more robust cross-chain interoperability standards.

## 🛠️ Key Developments

### Betanet & Infrastructure Upgrades
Significant work was completed to enhance the functionality of the Sepolia betanet, particularly regarding revenue sharing mechanisms.
*   **RevShare Implementation:** Added tasks to upgrade and configure RevShare functionality for the `revshare-beta-1` chain, bringing it to the U18 version. This included comprehensive environment files, validation documents, and TOML configurations ([#1365](https://github.com/ethereum-optimism/superchain-ops/pull/1365)).
*   **Security Council Readiness:** Prepared for "OPSC Rehearsal 3: Nested Upgrade" by adding necessary configuration and environment files to simulate complex governance-led upgrades ([#1367](https://github.com/ethereum-optimism/superchain-ops/pull/1367)).

### Operational Standards & Tooling
The project improved the workflow for contributors and underwriters to ensure higher quality in operational tasks.
*   **Task Submission Guidelines:** Updated `NEW_TASK_GUIDE.md` to include a "Before Submitting Your Task for Review" section. This mandates that task authors meet specific simulation requirements before seeking underwriter review, streamlining the approval process ([#1357](https://github.com/ethereum-optimism/superchain-ops/pull/1357)).
*   **Flashblocks Support:** Progress was made on integrating Flashblocks support within `op-geth` to facilitate event processing from WebSockets and block reconstruction for live tracing ([#756](https://github.com/ethereum-optimism/superchain-ops/issues/756)).

## 🐛 Issues & Triage

### Closed Issues
*   **`op-supernode` L1 Polling:** Resolved a bug where using HTTP L1 URLs caused disabled polling and stale L1 head updates for virtual nodes ([#19012](https://github.com/ethereum-optimism/superchain-ops/issues/19012)).

### New & Active Issues
*   **`op-supernode` Architecture:** A significant technical debate is ongoing regarding "Safe" label adjustments. The core question is whether `op-supernode` should directly control Execution Layer labels or if the Consensus Layer should remain the sole engine controller via a virtual node to avoid stateful conflicts ([#18976](https://github.com/ethereum-optimism/superchain-ops/issues/18976)).
*   **Sync UX & Correctness:** Discussions continued on the "buggy" behavior of `op-node` marking initial EL sync targets as finalized. Proposals include fixing the code to only advance the unsafe reference while keeping safe/finalized labels at genesis until verified ([#17631](https://github.com/ethereum-optimism/superchain-ops/issues/17631)).
*   **Interoperability Testing:** The `TestInteropReadiness` acceptance test remains skipped. It is slated to be unskipped once the super Dispute Game (DG) supports explicit output roots ([#18616](https://github.com/ethereum-optimism/superchain-ops/issues/18616)).
*   **SDK Discrepancies:** A `BlockNotFoundError` in the ETH bridge tutorial revealed a potential gap in Viem’s implementation of withdrawal actions compared to the Optimism SDK, specifically regarding `isValidOutputRoot` validation ([#1956](https://github.com/ethereum-optimism/superchain-ops/issues/1956)).

## 💬 Community & Collaboration
The week was characterized by deep technical coordination between maintainers (such as `trianglesphere`, `sebastianst`, and `ajsutton`) on the fundamental design of the Superchain's node architecture. The dialogue around `op-supernode` and `op-node` sync logic indicates a highly collaborative effort to resolve legacy design choices that are now viewed as technical debt. Additionally, the focus on the Security Council rehearsal highlights active coordination between the development team and the governance entities responsible for securing the network.

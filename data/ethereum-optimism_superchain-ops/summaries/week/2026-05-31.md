# ethereum-optimism/superchain-ops Weekly Report (May 31 - June 6, 2026)

## 🚀 Highlights
This week focused heavily on stabilizing interoperability infrastructure and advancing the U19 betanet environment. Significant progress was made in debugging Consensus Layer (CL) synchronization stalls and refining the `op-supernode` initialization process. While the Interop Proofs Devnet reached a major milestone with successful withdrawal verification on Sepolia, new challenges emerged regarding transaction pool recovery and reorg handling following invalid interop messages. The team is now prioritizing the creation of recovery runbooks and improving system observability through new metrics.

## 🛠️ Key Developments

### Infrastructure & Multisig Robustness
- **Multisig Gas Handling:** A critical fix was implemented in `MultisigTask._execTransaction` to tolerate negative per-call gas refunds. This improvement prevents unnecessary transaction failures and ensures more robust execution for multisig operations ([#1443](https://github.com/ethereum-optimism/superchain-ops/pull/1443)).
- **Gas Configuration:** A new proposal was introduced to double the gas target for both OP Mainnet and OP Sepolia to accommodate growing network demands ([#1446](https://github.com/ethereum-optimism/superchain-ops/pull/1446)).

### Betanet & Network Updates
- **U19 Betanet Progression:** Multiple tasks (086-089) were successfully executed on Sepolia, marking steady progress in betanet deployment ([#1444](https://github.com/ethereum-optimism/superchain-ops/pull/1444)). 
- **Feature Flags & Corrections:** Updates were initiated for the U19 betanet v2 ([#1442](https://github.com/ethereum-optimism/superchain-ops/pull/1442)), including a permissionless flip for `karst-u19-alpha` and corrections for `CANNON_KONA` ([#1447](https://github.com/ethereum-optimism/superchain-ops/pull/1447)).
- **Prestate Management:** Work is ongoing to update U19 betanet prestates and set game argument templates ([#1445](https://github.com/ethereum-optimism/superchain-ops/pull/1445)).

## 🐛 Issues & Triage

### Closed Issues
- **Interop Proofs Devnet:** The devnet issue was successfully closed after the final withdrawal was proven on an anvil fork of Sepolia. The project is now moving into the finalization delay phase ([#20489](https://github.com/ethereum-optimism/superchain-ops/issues/20489)).
- **Security Audit:** Feedback regarding `doc.go` from the Lumi Security Audit was addressed and closed ([#21124](https://github.com/ethereum-optimism/superchain-ops/issues/21124)).

### New & Active Issues
- **Sync & Initialization Blockers:** A critical flaw was identified where `op-supernode` becomes permanently stuck if the Execution Layer (EL) is unreachable at startup ([#21136](https://github.com/ethereum-optimism/superchain-ops/issues/21136)). Additionally, investigations continue into CL sync recovery stalls, with A/B testing suggesting the issue lies within the `op-node`/`op-reth` Engine API path ([#21076](https://github.com/ethereum-optimism/superchain-ops/issues/21076)).
- **Interop Recovery Challenges:** New issues highlight that `op-reth` fails to resume accepting interop transactions after a failsafe event without a full restart of both the node and the block builder ([#21149](https://github.com/ethereum-optimism/superchain-ops/issues/21149)). This has prompted the need for a formal "Invalid Interop Message Recovery" runbook to handle large reorgs ([#21161](https://github.com/ethereum-optimism/superchain-ops/issues/21161)).
- **Backlog Recovery:** The `op-supervisor` is currently struggling to drain cross-safe backlogs faster than real-time after a stall, potentially requiring manual sequencer recovery mode ([#21117](https://github.com/ethereum-optimism/superchain-ops/issues/21117)).

## 💬 Community & Collaboration
Technical coordination remains high regarding the synchronization of `op-revm` with upstream `revm` releases. Contributors (including Wodann and Sebastianst) are aligning on dependency management strategies to ensure the Optimism stack stays current with the latest REVM versions, specifically targeting support for the Amsterdam hardfork ([#21069](https://github.com/ethereum-optimism/superchain-ops/issues/21069)). There is also active collaboration between developers to improve observability, as seen in the proposal for new failsafe-state gauge metrics to better monitor interop health ([#21151](https://github.com/ethereum-optimism/superchain-ops/pull/21151)).

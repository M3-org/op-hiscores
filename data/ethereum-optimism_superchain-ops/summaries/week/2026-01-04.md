# ethereum-optimism/superchain-ops Weekly Report (Jan 4 - 10, 2026)

## 🚀 Highlights
This week's efforts centered on enhancing the stability and reliability of the Superchain ecosystem. Development focused on critical investigations into node behavior, particularly Kona's handling of L1 reorgs, which led to a detailed root cause analysis. Work also progressed on routine Superchain maintenance with updates to betanet configurations. While no major features were merged, significant groundwork was laid for future interoperability and fault-proof enhancements, highlighted by active discussions and community members stepping up to tackle key testing and configuration challenges.

## 🛠️ Key Developments
Work completed this week focused on operational maintenance and improving internal processes.

- **Superchain Network Maintenance:** Ongoing maintenance of the Superchain test networks included updating U18 betanet task addresses to reflect recent network redeployments ([#1329](https://github.com/ethereum-optimism/superchain-ops/pull/1329)). The status of tasks related to adding and setting respected game types was also updated, marking progress in the betanet environment ([#1331](https://github.com/ethereum-optimism/superchain-ops/pull/1331)).

- **CI & Developer Experience:** The CI configuration was refined to improve the clarity of failure notifications. Mentions of "evm-safety-team" were replaced with "security-oncall" to ensure alerts are routed to the correct team for triage ([#1328](https://github.com/ethereum-optimism/superchain-ops/pull/1328)).

## 🐛 Issues & Triage
Discussions this week were dominated by deep dives into node stability, future interop requirements, and critical bug fixes.

- **Closed Issues:** A community inquiry about OP Stack compatibility with minimal smart contracts was resolved, confirming general compatibility and providing a reference to documentation on differences from L1 Ethereum ([#18709](https://github.com/ethereum-optimism/superchain-ops/issues/18709)).

- **New & Active Issues:**
    - **Kona Node Stability:** A significant investigation into L2 reorgs caused by L1 reorgs ([#18676](https://github.com/ethereum-optimism/superchain-ops/issues/18676)) identified key issues in Kona, including stale cache data in the `origin_selector` and a lack of L1 canonical validation. Another active discussion on Kona's `optimism_syncStatus` RPC ([#18673](https://github.com/ethereum-optimism/superchain-ops/issues/18673)) focused on correcting the `current_l1` value to reflect the actual derivation cursor.
    - **`op-supernode` Dependencies:** Progress on several issues related to `op-supernode` ([#18651](https://github.com/ethereum-optimism/superchain-ops/issues/18651), [#18667](https://github.com/ethereum-optimism/superchain-ops/issues/18667)) and `op-challenger` ([#18669](https://github.com/ethereum-optimism/superchain-ops/issues/18669)) is currently blocked pending the implementation of interop support and a `syncStatus` API within the supernode.
    - **Fault Proofs & Interop:** In preparation for interoperability, an issue to extend the `IDisputeGame` interface was reopened to track remaining work ([#18516](https://github.com/ethereum-optimism/superchain-ops/issues/18516)). A new issue was also opened to improve the `addGameType` template by fetching contract addresses on-chain, aiming to streamline the review process ([#1330](https://github.com/ethereum-optimism/superchain-ops/issues/1330)).
    - **Critical Bug Investigation:** The `eth_simulatev1` bug ([#739](https://github.com/ethereum-optimism/superchain-ops/issues/739)), which impacts transaction simulation, remains a high priority. A potential fix is being developed in the `op-geth` repository, highlighting cross-project coordination.

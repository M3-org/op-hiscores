# ethereum-optimism/superchain-ops Weekly Report (Jul 19 - 25, 2026)

## 🚀 Highlights
This week focused on critical infrastructure readiness for the Ink Mainnet migration and achieving a major milestone in the `op-geth` decoupling initiative. Significant progress was made in modularizing the OP Stack by transitioning call-sites to `op-core/*`, while the team also resolved several configuration issues related to super-root migration runbooks. Technical efforts were balanced between these structural improvements and the rigorous debugging of persistent integration test flakes in `reth-optimism-node` and interop sequencers.

## 🛠️ Key Developments

### Ink Mainnet Migration
Preparations for the Ink Mainnet launch are underway, focusing on transitioning infrastructure from Gelato to OP Enterprise.
*   **Signer and Proposer Rotation:** Added preparatory tasks for the on-chain cutover of the batcher unsafe signer and proposer rotation ([#1490](https://github.com/ethereum-optimism/superchain-ops/pull/1490)).
*   **Fee-Vault Updates:** Initiated the update of the Ink Mainnet fee-vault recipient to OP Enterprise ([#1505](https://github.com/ethereum-optimism/superchain-ops/pull/1505)).

### OP Stack Modularity & Decoupling
The project reached a significant milestone in decoupling `op-geth` from the core services to improve stack flexibility.
*   **Call-site Migration:** Successfully closed the effort to swap call-sites to `op-core/*` across `op-node`, `op-service`, and `op-batcher` ([#20263](https://github.com/ethereum-optimism/superchain-ops/issues/20263)). This was finalized through the landing of [#21791](https://github.com/ethereum-optimism/superchain-ops/pull/21791) and [#21904](https://github.com/ethereum-optimism/superchain-ops/pull/21904).
*   **Batcher Design Correction:** Refined the `op-batcher` migration strategy. It was determined that the batcher will move to a payload-native approach using `*eth.ExecutionPayloadEnvelope` via `PayloadByNumber`, as the previously considered `InfoAndUserTxs` dropped critical data required for batch building ([#20264](https://github.com/ethereum-optimism/superchain-ops/issues/20264)).

## 🐛 Issues & Triage

### Closed Issues
*   **Runbook Maintenance:** Updated super-root migration runbooks for `SUPER_PERMISSIONED` fault game types, ensuring `op-challenger` is correctly configured and unsupported types are removed ([#21709](https://github.com/ethereum-optimism/superchain-ops/issues/21709)).
*   **Kona Node Parity:** Determined that the `syncmode.offset-el-safe` flag is unnecessary for Kona Node, as its existing post-EL-sync reset mechanism already handles the necessary retractions without risking finalization regressions ([#21243](https://github.com/ethereum-optimism/superchain-ops/issues/21243)).
*   **Acceptance Testing:** Closed the issue regarding Kona sequencer support in `TestSequencerPreset`, noting it as potentially resolved by recent upstream changes ([#18675](https://github.com/ethereum-optimism/superchain-ops/issues/18675)).

### New & Active Issues
*   **Reth Integration Flakes:** Investigation continues into a `SIGSEGV` flake in `reth-optimism-node` ([#20973](https://github.com/ethereum-optimism/superchain-ops/issues/20973)). While a "detached payload thread" was ruled out as the cause, developers are considering a workaround ([#20983](https://github.com/ethereum-optimism/optimism/pull/20983)) while attempting to capture core dumps in CI for a definitive fix.
*   **Interop Logic:** A fix was proposed for a flake in `TestSupernodeLightSequencerInteropInvalidMessageReplacement` ([#21635](https://github.com/ethereum-optimism/superchain-ops/issues/21635)). The proposed solution ([#21913](https://github.com/ethereum-optimism/optimism/pull/21913)) prevents stale Engine API calls by rejecting non-derived build starts with mismatched parent block IDs.

## 💬 Community & Collaboration
The week was characterized by deep technical coordination between core contributors. Notable collaboration occurred regarding the security and coverage of SDM/Kona proofs, with contributors requesting secure channels to discuss sensitive technical concerns ([#21344](https://github.com/ethereum-optimism/superchain-ops/issues/21344)). Additionally, the resolution of the `op-geth` decoupling issues involved significant cross-component review, ensuring that changes to `op-service` and `op-batcher` remained compatible with the broader Superchain architecture.

# ethereum-optimism/superchain-ops Weekly Report (Apr 12 - 18, 2026)

## 🚀 Highlights
This week focused on streamlining the Superchain's operational infrastructure through significant progress on L2 Contract Management (L2CM) and Docker workflow migrations. Key technical milestones included the consolidation of `kona-node` development tasks and the completion of NUT (Network Upgrade Transaction) bundle work for `op-node`. Routine security maintenance was also addressed through scheduled signer rotations for FUS and FOS, ensuring continued protocol integrity.

## 🛠️ Key Developments

### L2CM and Node Upgrades
Significant effort was directed toward enhancing the L2 Contract Management (L2CM) capabilities for both `kona-node` and `op-node`.
*   **Kona-node Enhancements:** Development focused on supporting dev feature flag injection ([#20081](https://github.com/ethereum-optimism/superchain-ops/issues/20081)), implementing additional upgrade gas mechanisms ([#18831](https://github.com/ethereum-optimism/superchain-ops/issues/18831)), and enabling the execution of NUT transactions from JSON ([#18836](https://github.com/ethereum-optimism/superchain-ops/issues/18836)). All ongoing `kona-node` L2CM work has now been consolidated into a single tracking issue ([#20065](https://github.com/ethereum-optimism/superchain-ops/issues/20065)).
*   **Op-node NUT Integration:** The team completed the work required for `op-node` to read and execute NUT transactions from JSON ([#18835](https://github.com/ethereum-optimism/superchain-ops/issues/18835)), marking the completion of the NUT bundle work for this component.

### Infrastructure & Security Operations
*   **Signer Rotations:** As part of the April operational rotation for FUS and FOS, signer `0xc222ab08333109243B1f4E2a80e3D0A190714AB5` was successfully replaced by `0xa2A58E31C03C59e34ab4d996d811DA0C035BfDea` ([#1394](https://github.com/ethereum-optimism/superchain-ops/pull/1394)).
*   **Docker Workflow Migration:** The project successfully closed out several issues related to migrating Docker build workflows to the `images.json` configuration ([#20058](https://github.com/ethereum-optimism/superchain-ops/issues/20058), [#20059](https://github.com/ethereum-optimism/superchain-ops/issues/20059), [#784](https://github.com/ethereum-optimism/superchain-ops/issues/784)), standardizing the build process across repositories.

## 🐛 Issues & Triage

### Closed Issues
*   **Workflow Cleanup:** Several Docker-related issues were closed as they were either completed or deemed not applicable to single-image repositories, reducing technical debt in the CI/CD pipeline.
*   **Feature Completion:** The closure of multiple NUT and L2CM-related issues indicates a transition from active development to consolidation for these protocol upgrade features.

### New & Active Issues
*   **Sequencer Reliability:** A high-priority discussion continues regarding supporting multiple sequencer RPC endpoints for transaction forwarding ([#763](https://github.com/ethereum-optimism/superchain-ops/issues/763)). The debate centers on whether to implement a bespoke fallback client within `op-geth` or to utilize external reverse proxies like HAProxy, Nginx, or `proxyd` to handle failover and health checks.
*   **Security Outreach:** A new inquiry was opened by the security firm Hashlock, expressing interest in auditing or providing services for the `superchain-ops` repository ([#1395](https://github.com/ethereum-optimism/superchain-ops/issues/1395)).

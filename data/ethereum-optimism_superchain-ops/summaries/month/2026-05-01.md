# ethereum-optimism/superchain-ops Monthly Report (May 2026)

## 🚀 Highlights
In May 2026, development focused on hardening the Superchain infrastructure through critical registry updates and the refinement of dispute monitoring capabilities. A significant portion of the month's activity involved triaging complex synchronization and state root issues arising from the transition to `op-reth` 2.x and the integration of the Supernode. The team also began addressing configuration nuances for the upcoming interoperability release, specifically regarding Cannon prestate templates for the OPCM upgrade path.

## 🛠️ Key Developments

### Superchain Registry & Configuration
The core registry was updated to ensure the system utilizes the most current upstream data.
*   **Registry Synchronization:** A critical update to the `lib/superchain-registry` submodule was merged, affecting numerous configuration and task files across `src/tasks` and `test/fixtures`. This ensures that all deployment and operational tasks are aligned with the latest Superchain specifications ([#1409](https://github.com/ethereum-optimism/superchain-ops/pull/1409)).

### Dispute Monitoring Enhancements
The project clarified and confirmed the multi-game monitoring capabilities of the dispute infrastructure.
*   **Hybrid Monitoring:** Technical discussions confirmed that a single `op-dispute-mon` instance is capable of simultaneously monitoring both CANNON and SUPER_CANNON_KONA games. This is achieved by providing both `rollup-rpc` and `supernode-rpc` endpoints, streamlining the operational overhead for node operators managing diverse game types.

## 🐛 Issues & Triage

### Closed Issues
*   **op-dispute-mon Querying:** Resolved questions regarding the ability of `op-dispute-mon` to query Supernode VNs for output roots, confirming support for concurrent game monitoring ([#20476](https://github.com/ethereum-optimism/superchain-ops/issues/20476)).

### New & Active Issues
*   **StateRootTask Fatal Panic:** A high-priority issue persists involving a non-deterministic assertion failure in `alloy-trie` when upgrading `op-reth` from 1.x to 2.x. The panic occurs during parallel trie computation, and initial attempts to mitigate it using the `--engine.legacy-state-root` flag have been unsuccessful ([#20462](https://github.com/ethereum-optimism/superchain-ops/issues/20462)).
*   **Supernode Calculation Errors:** A bug was identified in `op-supernode` where `VerifiedRequiredL1` is incorrectly calculated as a minimum rather than a maximum of per-chain values. This impacts the accuracy of published `SuperRootResponseData` ([#20481](https://github.com/ethereum-optimism/superchain-ops/issues/20481)).
*   **OPCM Upgrade Templates:** Discussions are underway regarding the `OPCMUpgradeV700` template. It was noted that `SUPER_PERMISSIONED_CANNON` should utilize `cannonKonaPrestate` instead of the standard `cannonPrestate`. There is ongoing debate on whether to include this fix in the V700 or V800 upgrade cycle to best support the interop release ([#1412](https://github.com/ethereum-optimism/superchain-ops/issues/1412)).

## 💬 Community & Collaboration
The month saw active technical coordination between contributors regarding protocol-level optimizations. Notably, there is renewed interest in deduplicating Engine API validations within `Miner.prepareWork`, with community members stepping up to move validation logic (such as Jovian L1 attribute checks) directly into the Engine API ([#688](https://github.com/ethereum-optimism/superchain-ops/issues/688)). This indicates a healthy collaborative effort to clean up legacy technical debt while preparing for new protocol features.

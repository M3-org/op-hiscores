## ACTIVE ISSUES

### L2 Reorg Due to L1 Reorg Investigation
Discussions on [#18676](https://github.com/ethereum-optimism/superchain-ops/issues/18676) continued with a detailed root cause analysis. Key findings include:
- **L1 Origin Selector Caching:** The `origin_selector` in Kona does not refresh cached `self.next` values, leading to stale data during L1 reorgs.
- **Missing L1 Canonical Validation:** Kona lacks proper validation of L1 origin validity or orphan status, unlike `op-node`.
- **No Proper Reset During Block Building:** Kona does not implement a reset mechanism similar to `op-node` when L1 inconsistencies are detected during block building.
Possible fixes proposed include strengthening Kona's L1 origin selector, adding unit tests for L1 inconsistency cases, revising reset logic, and enabling more monorepo acceptance tests targeting Kona.

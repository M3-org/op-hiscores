## ACTIVE ISSUES

### Flaky Test: `TestUnsafeGapFillAfterUnsafeReorg_RestartL2CL`
This flaky test continues to be a concern, with recent occurrences on both `memory-all-opn-op-geth` and `memory-all-opn-op-reth`. The latest comment from ajsutton confirms that the underlying race condition is not specific to `op-reth`, despite previous markings. An investigation into a fix is underway.
- [#19936](https://github.com/ethereum-optimism/superchain-ops/issues/19936)

### Flaky Test: `TestReorgUnsafeHead`
A new flaky test, `TestReorgUnsafeHead`, was reported today. A proposed fix in a draft PR (ethereum-optimism/optimism#20201) addresses the root cause, which is identified as asynchronous updates in op-node's `StatusTracker.data.UnsafeL2` and `Sequencer.latestHead` leading to stale data being used during sequencer startup. The fix involves replacing time-based waits with a poll on `SyncStatus().UnsafeL2.Hash`.
- [#20198](https://github.com/ethereum-optimism/superchain-ops/issues/20198)

### Kona-interop: Review access of blocks created internally
Discussion on this issue highlights a potential problem where, during block replacement, generated receipts are not stored, which could lead to consolidation failures if a deposit-only block is referenced by other messages. The current logic overwrites the reference in the pending state with the replaced block, but the lack of receipt storage remains a concern.
- [#19266](https://github.com/ethereum-optimism/superchain-ops/issues/19266)

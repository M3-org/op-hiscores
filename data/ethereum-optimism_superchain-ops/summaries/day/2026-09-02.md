## ACTIVE ISSUES

### Superchain Registry Consumption by Go Modules
Discussion continues on [#22678](https://github.com/ethereum-optimism/superchain-ops/issues/22678) regarding the unconsumable nature of `op-core/superchain` by downstream Go modules due to `superchain-configs.zip` being gitignored.

**Key Points from Latest Comments:**
- **Current Status:** The issue persists despite recent PRs ([#22700](https://github.com/ethereum-optimism/optimism/pull/22700) and [#22709](https://github.com/ethereum-optimism/optimism/pull/22709)) that partially addressed it by reducing the number of affected packages. The core problem remains: `superchain-configs.zip` is still gitignored, and the published module lacks the zip file.
- **Impact:** Genuine registry consumers like `op-deployer`, `op-conductor`, `op-challenger`, `op-dispute-mon`, `op-supernode`, `op-interop-filter`, op-node's non-`rollup` packages, and `op-service/flags` are still unbuildable by downstream Go modules. Two service modules in other OP Labs repos are currently blocked.
- **Correction on Supersim:** An earlier assessment that `supersim` was affected was corrected. `supersim` is unblocked by reachability work and does not require the zip to be shipped.
- **Git LFS Not an Option:** `git-lfs` is not a viable solution because `cmd/go` builds module zips from raw git data, and `proxy.golang.org` does not run `lfs smudge`.
- **Import-Graph Measurement:** Analysis shows that initially 206 of 560 monorepo packages reached the bundle. After cleanup efforts (splitting loaders, deleting dead code), this number drops to ~109, primarily genuine data consumers.
- **Cost of Committing the Zip:** Quantified analysis of `op-geth`'s history shows that committing the zip would cost approximately 3 MB/year in `.git` growth, which is significantly less than previously assumed. This cost has been managed by `op-geth` without incident.
- **Loose Files vs. Zip:** Storing loose files instead of a zip offers minimal storage difference but would provide reviewable diffs.
- **Submodules:** Embedding directly from the `superchain-registry` submodule is not feasible as `//go:embed` cannot escape its package directory, and submodule content is absent from published modules.
- **Reducing Package Reach:** Efforts are underway to reduce the number of packages that depend on the bundle, as some current dependencies are accidental. This includes fixing `op-service/opprof` and splitting `op-core/interop/depset`. A `depguard` test has been added to prevent new accidental dependencies.

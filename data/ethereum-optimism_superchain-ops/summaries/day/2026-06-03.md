# ethereum-optimism/superchain-ops Daily Update (Jun 3, 2026)

## OVERVIEW 
Today's focus was on diagnosing and addressing critical issues related to node synchronization and stability, particularly within the op-reth and op-supernode components. Significant progress was made in identifying root causes of stalling and wedging, with a new feature PR opened for U19 templates.

## KEY TECHNICAL DEVELOPMENTS

### Node Synchronization and Stability Diagnostics
Extensive debugging and analysis were performed on issues causing op-supernode and op-reth to stall during CL sync recovery. A root cause for a cyclic deadlock in reth's `StateTrieOverlayManager` and `DeferredTrieData` machinery was identified and a two-patch fix is currently soaking. This work is detailed in the comments for [#21076](https://github.com/ethereum-optimism/superchain-ops/issues/21076).

### Fuzz Testing Reliability Improvements
Efforts were made to address intermittent failures in the `op-e2e-fuzz` CircleCI job, which was experiencing "Too long with no output" timeouts. A draft PR was created to bound unbounded RPC/engine calls and add line buffering for better diagnostics, aiming to pinpoint the exact cause of the hangs. This is discussed in [#21191](https://github.com/ethereum-optimism/superchain-ops/issues/21191).

### U19 Upgrade Preparation
A new feature pull request was opened to introduce U19 templates, specifically for the OPCMUpgradeV700 permissioned upgrade and the SetDisputeGameArgs/Impl. This indicates ongoing work towards future protocol upgrades. [#1448](https://github.com/ethereum-optimism/superchain-ops/pull/1448)

## ACTIVE ISSUES

### State-Persistent Partial DoS in OptimismPortal2 [#20820](https://github.com/ethereum-optimism/superchain-ops/issues/20820)

### SDM: Add a Limit for SDM Refunds [#20709](https://github.com/ethereum-optimism/superchain-ops/issues/20709)
Discussion today focused on capping the maximum computation a sequencer can perform, even with 100% refunds from SDM, by enforcing `MAX_GAS_LIMIT`. It was suggested that this limit could be hardcoded in the node software.

### CL Sync Recovery Stalling [#21076](https://github.com/ethereum-optimism/superchain-ops/issues/21076)
Significant progress was reported today. The root cause of the CL-sync op-reth engine wedge was identified as a cyclic deadlock in reth's `StateTrieOverlayManager` and `DeferredTrieData` machinery. A two-patch fix has been applied and is currently undergoing a soak test, showing continuous CL-sync for both jnt-v2 chains without wedges for several hours. The issue was reproduced and root-caused to two distinct sites where locks are held across `rayon` compute operations.

### Add Test for Gas Changes Causing RelayMessage Failure [#14609](https://github.com/ethereum-optimism/superchain-ops/issues/14609)
This issue was reopened today because existing TODOs in the codebase still reference it. The TODOs indicate a need to update tests to use `default.isolate = true` once a stable Foundry release with `foundry-rs/foundry#9904` is available, which would allow checking for EVM gas schedule changes affecting `relayMessage`.

### Op-E2E-Fuzz: 'Too Long with No Output' Flake [#21191](https://github.com/ethereum-optimism/superchain-ops/issues/21191)
Today's comments clarified that the issue is a hang, not slow setup, as healthy runs are much shorter than the 15-minute timeout. A draft PR has been created to address this by bounding RPC/engine calls in `FuzzFjordCostFunction` to fail faster and adding `--line-buffer` to stream progress, which will help diagnose the exact stall point in future occurrences. The underlying trigger for the hang is still unidentified.

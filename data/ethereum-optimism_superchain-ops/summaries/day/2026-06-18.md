# ethereum-optimism/superchain-ops Daily Update (Jun 18, 2026)
## OVERVIEW 
Today's development focused on adding a new template for `SystemConfigGasLimit` to streamline gas limit adjustments. Discussions continued on `kona-node` issues and the consistency of the SDM operator flag.

## KEY TECHNICAL DEVELOPMENTS

### System Configuration Templates
A new minimal `L2TaskBase` template, `SystemConfigGasLimit.sol`, was added. This template specifically handles calls to `SystemConfig.setGasLimit` without including EIP-1559 parameters, serving as a gas-limit-only counterpart to the existing `SystemConfigGasParams` template. ([#1474](https://github.com/ethereum-optimism/superchain-ops/pull/1474))

- A new pull request, [#1476](https://github.com/ethereum-optimism/superchain-ops/pull/1476), was opened to add a Swell L1 ownership-transfer task (055).

## CLOSED ISSUES

### Proposer Integration
Issue [#21461](https://github.com/ethereum-optimism/superchain-ops/issues/21461), concerning proposer integration with a self-hosted proving cluster, was closed as it was determined that `sp1-cluster` is already supported, making the proposed modifications unnecessary.

### L2 Calldata Compression Research
A research proposal for L2 Calldata Compression Proof ([#21471](https://github.com/ethereum-optimism/superchain-ops/issues/21471)) was closed. The reason cited was that closed-source algorithms are not suitable for an L2, and an open-source, audited implementation would be required for consideration.

No new issues were opened today.

## ACTIVE ISSUES

### Kona-node: SafeDB
Discussion on [#20278](https://github.com/ethereum-optimism/superchain-ops/issues/20278) regarding `kona-node`'s SafeDB continued. The latest comment from geoknee emphasizes the need for SafeDB to integrate well with interop and proofs, while also suggesting a careful design approach rather than blindly adopting existing `op-node` solutions.

### Kona-node: Implement `syncmode.offset-el-safe`
Issue [#21243](https://github.com/ethereum-optimism/superchain-ops/issues/21243) focuses on adding `syncmode.offset-el-safe` to `kona-node` for parity with `op-node`. sebastianst noted that while `kona` doesn't persist the safe head, its EL node will, potentially mitigating the issue. He also reiterated the need for a SafeDB in `kona` (referencing [#20278](https://github.com/ethereum-optimism/optimism/issues/20278)) which should prioritize the SafeDB head over the EL's safe head once implemented. geoknee highlighted the interaction with [#20278](https://github.com/ethereum-optimism/optimism/issues/20278) and suggested fixing this ticket soon, adding a TODO to prefer the safe DB when available.

### SDM: Improve Consistency of Opt-in Operator Flag
On issue [#21360](https://github.com/ethereum-optimism/superchain-ops/issues/21360), the discussion centered on standardizing the SDM opt-in flag. einar-oplabs confirmed that the scope would be narrowed to `op-reth` and `op-node`. There was a clarification from nonsense that `protocol_active` is for consensus/fork checks, not the operator opt-in. einar-oplabs agreed to use `operator_sdm_opt_in` as the consistent name for the flag, acknowledging that it clearly conveys the operator's choice to enable or disable SDM.

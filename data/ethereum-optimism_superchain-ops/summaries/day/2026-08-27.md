# ethereum-optimism/superchain-ops Daily Update (Aug 27, 2026)
## OVERVIEW 
Today's focus was on internal maintenance and addressing critical sequencer stability issues. Significant progress was made in analyzing and closing a long-standing supernode interop issue, and new pull requests were opened for system configuration and task execution improvements.

## KEY TECHNICAL DEVELOPMENTS

No completed work was reported for this period.

## NEWLY OPENED PULL REQUESTS

- A fix to avoid ephemeral `MultisigTask` self-address was proposed in [#1528](https://github.com/ethereum-optimism/superchain-ops/pull/1528).

## CLOSED ISSUES

- **Supernode Interop Stability Confirmed**
  The issue [#22325](https://github.com/ethereum-optimism/superchain-ops/issues/22325), concerning `op-supernode` cross-safe wedges after invalid-message replacement, has been closed. Analysis revealed it was a single occurrence in 7.5 weeks, with the root cause identified as chain 901 derivation rejecting batches due to a parent-hash mismatch. The issue is now linked to an existing oscillation problem rather than a distinct cross-safety bug.

- **Kona Genesis RollupConfig Leniency Confirmed**
  Issue [#22682](https://github.com/ethereum-optimism/superchain-ops/issues/22682), regarding `kona-genesis` silently accepting unknown `rollup.json` keys, was closed as "not planned." The leniency is deliberate to support retired keys, and restoring strictness would make Kona stricter than `op-node` and break existing configurations.

## NEW ISSUES

- **Sequencer Stability Concerns**
  A new issue, [#22681](https://github.com/ethereum-optimism/superchain-ops/issues/22681), reports that a `kona-node` sequencer can get stuck in a `forkchoiceUpdated -38002` loop after derivation force-includes a block off its unsafe chain. This can lead to the process becoming unusable.

- **SuperchainERC20 Compatibility Gap**
  Issue [#1020](https://github.com/ethereum-optimism/superchain-ops/issues/1020) highlights that there is currently no supported way for developers to check if a token address is SuperchainERC20 compatible. This capability is deemed critical, especially with the potential revival of `SuperchainTokenBridge`.

## ACTIVE ISSUES

- **Sequencer NetworkActor Stalling**
  Issue [#22646](https://github.com/ethereum-optimism/superchain-ops/issues/22646) describes how `kona-node`'s `NetworkActor` can stall the p2p swarm during remote-signer HTTP calls. A contributor has offered to pick up the issue, raising questions about overflow policy parity with other modules and the possibility of landing a deadline fix separately from larger restructuring. The contributor plans to confirm the stalling behavior by injecting latency into a signer.

- **Starter Examples and Repo Cleanup**
  Issue [#1014](https://github.com/ethereum-optimism/superchain-ops/issues/1014), concerning auditing documentation references for starter examples, has been updated. A comprehensive sweep confirmed that no live documentation links any of the six starter repos or the four archive-sweep repos, meaning archiving will not break published docs. The issue's premise that archiving would break published docs is no longer true. The blast radius for cross-references within READMEs is self-contained, with only three external fix-ups needed.

- **Consolidating Starter Examples**
  Issue [#1015](https://github.com/ethereum-optimism/superchain-ops/issues/1015) discusses consolidating starter examples. Analysis suggests consolidating five `superchain-starter*` repos into the existing `superchain-starter` repo, while leaving `superchainerc20-starter` independent due to its distinct nature and popularity. The recommended approach is a plain copy with a pointer to the original for history preservation. The issue also notes that if `super-cli` is deprecated, its stripping should be part of this consolidation.

- **Archive Sweep for Abandoned Repos**
  Issue [#1017](https://github.com/ethereum-optimism/superchain-ops/issues/1017) focuses on archiving abandoned and dead repos. An inbound-link check confirmed no live documentation links any of the four target repos. The `superchainerc20-compatibility` repo's original purpose was to check SuperchainERC20 compatibility, a capability now logged as [#1020](https://github.com/ethereum-optimism/superchain-ops/issues/1020). Archiving is currently blocked by the need for organizational admin permissions. The issue also highlights the need to determine supported alternatives for starter/boilerplate repos before writing archive notices.

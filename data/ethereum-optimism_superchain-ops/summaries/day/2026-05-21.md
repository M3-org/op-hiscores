# ethereum-optimism/superchain-ops Daily Update (May 21, 2026)
## OVERVIEW 
Today's focus was on CI pipeline stability, with a key update to remove `circleci_ip_ranges` flags and route fork-sim RPCs via secrets context. Several long-standing flaky tests and critical issues received significant attention and diagnostic updates.

## KEY TECHNICAL DEVELOPMENTS

*   **CI Pipeline Refinements**
    *   Removed `circleci_ip_ranges` flags and migrated fork-simulation jobs to use `circleci-repo-rpc-secrets` context for improved security and stability in CI environments ([#1429](https://github.com/ethereum-optimism/superchain-ops/pull/1429)).

## NEWLY OPENED PULL REQUESTS
*   **Type A Migration Exercise Tasks:** A new pull request has been opened to address Type A Migration Exercise Tasks ([#1430](https://github.com/ethereum-optimism/superchain-ops/pull/1430)).

## CLOSED ISSUES

*   **Kona Production Readiness Evaluation**
    *   The evaluation of Kona's production-readiness against `op-node` regarding interop and proofs has been completed and closed, with all consensus-critical and liveness-related issues resolved ([#20444](https://github.com/ethereum-optimism/superchain-ops/issues/20444)).
*   **L2CM Standard Validator Assertions**
    *   The issue regarding adding missing standard validator assertions in L2CM has been closed, with the decision that the proposed changes offer minimal value for the potential breaking changes they might introduce ([#20805](https://github.com/ethereum-optimism/superchain-ops/issues/20805)).
*   **L2CM Ownership Renunciation Prevention**
    *   The issue concerning preventing ownership renunciation in the SystemConfig has been closed, as it was determined that a system config owner should not renounce ownership, and recovery is possible via security council upgrade if such an event were to occur ([#20807](https://github.com/ethereum-optimism/superchain-ops/issues/20807)).
*   **Flaky Test: `TestSequenceWindowExpired`**
    *   A flaky test related to `TestSequenceWindowExpired` in `op-e2e/actions/proofs` has been addressed and closed, with a fix proposed to track Bob's nonce locally in the test to prevent `txpool.ErrAlreadyKnown` issues during chain-head churn ([#20941](https://github.com/ethereum-optimism/superchain-ops/issues/20941)).

## NEW ISSUES

*   **CI Flakiness in `required-contracts-ci`**
    *   A new issue has been opened to track flakiness in the `required-contracts-ci` check within the CI pipeline, specifically due to infrastructure issues causing `curl` errors and failures to resolve target branches ([#20952](https://github.com/ethereum-optimism/superchain-ops/issues/20952)).

## ACTIVE ISSUES

*   **Flaky Test: `TestFlashblocksStream` ([#19883](https://github.com/ethereum-optimism/superchain-ops/issues/19883))**
    *   The issue has been root-caused to a port collision where `rollup-boost`'s RPC port was being pre-allocated and then reused, leading to `EADDRINUSE` errors. A fix has been proposed in PR #20938 to adopt a `0` + read-back pattern for the RPC port, similar to other ports, which is expected to resolve this flake.
*   **Flaky Test: `TestTruncateDatabaseOnELResync` ([#19897](https://github.com/ethereum-optimism/superchain-ops/issues/19897))**
    *   The flake has recurred with a new failure mode related to the post-restart EL sync. The issue is that `LocalSafe` remains at 0 until `op-geth` completes snap-sync for at least one payload, and the fixed 90-attempt window is often insufficient under loaded CI conditions. A fix is recommended to convert the post-restart sync to a progress-aware pattern using `MatchedWithProgressFn`, similar to a previous fix for initial sync, to account for variable EL snap-sync times.
*   **Kona: Very high cardinality for exported metrics ([#19927](https://github.com/ethereum-optimism/superchain-ops/issues/19927))**
    *   The issue of high cardinality for exported metrics in Kona remains open, with a recent comment requesting attention from relevant team members.
*   **Receipt Root Mismatch ([#19930](https://github.com/ethereum-optimism/superchain-ops/issues/19930))**
    *   Users are continuing to experience receipt root mismatch issues, particularly on chains like Manta Pacific and Zora Sepolia, when syncing with `op-reth`. The problem appears to be related to pre-Canyon hardforks and how `op-reth` handles receipt trie encoding. A PR (ethereum-optimism/optimism#20002) has been identified as a potential fix, and using a binary built from it seems to alleviate the issue.
*   **Flaky Test: `TestFlashblocksTransfer` ([#19934](https://github.com/ethereum-optimism/superchain-ops/issues/19934))**
    *   A recent failure on May 21, 2026, confirmed that the port-collision root cause identified in #19883 is also affecting this test. The fix proposed in #20938 is expected to resolve this specific manifestation. The discussion highlights that this test has historically surfaced multiple distinct root causes, and future flakes not related to port-collision should be filed as new issues.
*   **Flaky Test: `TestReorgUnsafeHead` ([#20198](https://github.com/ethereum-optimism/superchain-ops/issues/20198))**
    *   The test recurred on May 21, 2026, with a new symptom: `Condition never satisfied` while awaiting balance updates, indicating a failure in the faucet funding during test setup. This is being investigated as a fresh flake, distinct from the original reorg assertion failure.
*   **Bug(op-reth): proofs-history exex SIGBUS crash and infinite retry loop during deep FCU rewinds ([#20934](https://github.com/ethereum-optimism/superchain-ops/issues/20934))**
    *   A PR has been raised for fixes related to aggressive retrying and log flooding during rewinds. However, the SIGBUS crash is still under investigation, as it appears to be a lower-level issue tied to rewind/truncation interactions.
*   **op-supernode: rewind/invalidation is not robust to partial-progress states or slow ELs ([#20929](https://github.com/ethereum-optimism/superchain-ops/issues/20929))**
    *   A sloppy reproduction has been put together to further investigate the `op-supernode` rewind/invalidation path's tendency to deadlock in infinite retry loops without clear fault surfacing.

## ACTIVE ISSUES

*   **Support multiple sequencer RPC endpoints for transaction forwarding** ([#763](https://github.com/ethereum-optimism/superchain-ops/issues/763))
    *   Discussion continues regarding the best approach to support multiple sequencer RPC endpoints for `op-geth` with automatic failover.
    *   `sebastianst` suggested using generic existing tools like HAProxy, Nginx, Envoy Proxy, or Caddy as a reverse proxy solution instead of implementing bespoke fallback client logic within `op-geth`. This would allow `op-geth` to continue pointing to a single `localhost` endpoint while leveraging established proxy solutions for redundancy and health checking.
    *   `yashvardhan-kukreja` recommended using `proxyd` for its routing strategies (fallback, multicall) to abstract multiple RPC URLs.
    *   Earlier comments from `brendontan03` highlighted the need for client-side failover as a defense-in-depth measure against CDN failures, while `ajsutton` questioned the user-friendliness of multiple URLs and suggested focusing on ensuring a single URL remains highly available.

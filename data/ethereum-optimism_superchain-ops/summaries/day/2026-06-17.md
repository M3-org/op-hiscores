# ethereum-optimism/superchain-ops Daily Update (Jun 17, 2026)
## OVERVIEW 
Today's focus was on preparing for the Ink Sepolia migration to OP Enterprise, with new tasks added and documentation updated. Discussions also continued on SDM consistency and ZK game proving.

## KEY TECHNICAL DEVELOPMENTS

### Ink Sepolia Migration Preparation
Three new tasks were added to facilitate the Ink Sepolia rollup-operator migration from Gelato to OP Enterprise, scheduled for June 22, 2026. These tasks include setting the batcher unsafe signer, proposer rotation, and fee vault updates. The task numbers and status for Ink Sepolia were also updated. ([#1464](https://github.com/ethereum-optimism/superchain-ops/pull/1464), [#1473](https://github.com/ethereum-optimism/superchain-ops/pull/1473))

## CLOSED ISSUES

### Optimism Sepolia Sync Issues Resolved
An issue regarding Optimism Sepolia sync problems after the Karst activation was closed. The problem was identified as a known bug in `op-reth` where nodes running `--chain op-sepolia` do not automatically activate Karst via the Superchain Registry, requiring manual configuration of the Karst timestamp. ([#21455](https://github.com/ethereum-optimism/superchain-ops/issues/21455))

## ACTIVE ISSUES

### SDM Consistency Improvement
Discussions on [#21360](https://github.com/ethereum-optimism/superchain-ops/issues/21360) focused on improving the consistency of the SDM opt-in operator flag across `op-node`, `op-reth`, and `op-rbuilder`. The scope will be narrowed to `op-reth` and `op-node`. There's also a need to standardize the naming of the `protocol_active` flag.

### ZK Games Acceptance Tests and Proving
On [#18326](https://github.com/ethereum-optimism/superchain-ops/issues/18326), the discussion revolved around adding acceptance tests for ZK games, including scenarios for valid and invalid proposals. A key point raised is the need for a mock prover and provisioning GPUs in CI for these tests. Issue [#21418](https://github.com/ethereum-optimism/superchain-ops/issues/21418), which also discussed local/mock proving for CI and debugging, was identified as a duplicate of [#18326](https://github.com/ethereum-optimism/superchain-ops/issues/18326).

### Kona Host Game Review
For [#18430](https://github.com/ethereum-optimism/superchain-ops/issues/18430), the latest comment emphasizes the need to ensure that `kona-host` data fetchers retry indefinitely and are sufficiently reliable, similar to existing fetchers.

## ACTIVE ISSUES

### EL Sync and Pruning Configuration
Discussion on issue [#21465](https://github.com/ethereum-optimism/superchain-ops/issues/21465) regarding `syncmode.offset-el-safe` failing for `--minimal` nodes continued. The root cause was identified as `--minimal` pruning block bodies, which are necessary for `op-node`'s EL sync to read L1-info deposit transactions. The recommended fix is to **never prune block bodies** on an OP Stack node, only pruning state and receipt segments. The issue highlights that `--minimal` and `--prune.bodies.distance` are not supported `op-reth` configurations. Documentation updates are in progress to reflect supported pruning configurations and the `--syncmode.offset-el-safe` flag, while relaxing overly strict "no pruning" language.

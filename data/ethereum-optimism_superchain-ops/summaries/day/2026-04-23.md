## CLOSED ISSUES

**Flaky Test Resolution**
- The flaky test `TestRelayWithInvalidMessagesSteady` was closed ([#20254](https://github.com/ethereum-optimism/superchain-ops/issues/20254)). The root cause was identified as the sampler goroutine not properly handling non-context errors like `dial tcp` timeouts, leading to non-deterministic failures. A fix has been drafted to warn and continue on such errors.

**Protocol Sync Deprecation**
- The issue regarding `op-node: remove req-resp p2p sync` ([#14108](https://github.com/ethereum-optimism/superchain-ops/issues/14108)) was closed in favor of a new issue in the protocol-team repository.

## NEW ISSUES

**Sequencer Engine Reset Behavior**
- A new issue, [#20294](https://github.com/ethereum-optimism/superchain-ops/issues/20294), was opened to address an `op-node` behavior where a sequencer configured as "LightCL" performs a needless engine reset on every restart, potentially rewinding EL heads. This issue is related to [#20295](https://github.com/ethereum-optimism/superchain-ops/issues/20295).

## ACTIVE ISSUES

**Kona Interop Block Access Review**
- In [#19266](https://github.com/ethereum-optimism/superchain-ops/issues/19266), the discussion revolves around reviewing access to internally created blocks within Kona-proofs interop. The latest comments confirm that deposit-only block receipts should be available from the canonical chain. A test has been written to confirm this behavior. An additional issue was discovered where, during block replacement, generated receipts are not stored, potentially causing consolidation failures if other messages reference deposit-only blocks.

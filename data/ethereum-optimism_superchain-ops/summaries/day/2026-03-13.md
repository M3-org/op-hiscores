# ethereum-optimism/superchain-ops Daily Update (Mar 13, 2026)
## OVERVIEW 
Today's development focused on updating dispute game templates to align with U18 OPCM breaking changes. Several issues related to derivation pipeline error handling, span batch extraction, and Rust docs hosting were closed. A new pull request was opened to cancel upgrade tasks.

## KEY TECHNICAL DEVELOPMENTS

### Dispute Game Template Updates
The `addGameType` and `setDisputeGame` templates were updated to reflect breaking changes introduced in U18 OPCM, specifically regarding implied proxies. This involved modifications to `src/template` and `test/tasks` files. ([#1378](https://github.com/ethereum-optimism/superchain-ops/pull/1378))

## NEWLY OPENED PULL REQUESTS
A new pull request, [#1382](https://github.com/ethereum-optimism/superchain-ops/pull/1382), was opened to cancel upgrade tasks.

## CLOSED ISSUES

### Derivation Pipeline and Batch Handling Improvements
An audit of the derivation pipeline's external input error handling was completed, ensuring that malformed L1 inputs do not halt derivation. ([#19491](https://github.com/ethereum-optimism/superchain-ops/issues/19491)) Additionally, an issue regarding span batch extraction failure in `BatchQueue` returning `Critical` instead of flushing was closed, with the decision to preserve historical behavior for pre-Holocene networks. ([#19511](https://github.com/ethereum-optimism/superchain-ops/issues/19511))

### Rust Documentation Hosting
The issue concerning Rust Docs Hosting was closed, as it has been captured within the broader docs migration project. ([#1985](https://github.com/ethereum-optimism/superchain-ops/issues/1985))

## NEW ISSUES
No new issues were reported today.

## ACTIVE ISSUES

### op-reth Memory Leak
The issue [#19212](https://github.com/ethereum-optimism/superchain-ops/issues/19212) concerning a memory leak triggered by "The database read transaction has been open for too long" warning in `op-reth` continues to be active. A user reported experiencing this issue on World Chain v1.10.1, leading to node crashes. The user inquired if upgrading to v1.11 resolved the problem. Previously, another user confirmed they had not yet upgraded to v1.11.0 but had not observed the behavior in the last 7 days on v1.10.2.

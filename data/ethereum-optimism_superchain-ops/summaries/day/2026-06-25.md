## CLOSED ISSUES
### Kona Host and `eth_getProof` Usage Investigation
The issue [#21510](https://github.com/ethereum-optimism/superchain-ops/issues/21510) regarding the investigation of `eth_getProof` usage in `kona-host` was closed. It was determined that `eth_getProof` usage is not a problem as long as the `kona` host uses `op-reth` with `proofs-history` enabled, which is already a requirement. The RPC call resolves quickly enough for fault proving, so no action is needed.

### `kona-sp1` Rollup Config Hash Replacement
The issue [#18493](https://github.com/ethereum-optimism/superchain-ops/issues/18493) concerning the replacement of the rollup config hash with an L2 chain ID in `kona-sp1` was closed. This change is no longer relevant as the input commitment no longer includes the `l2ChainID`.

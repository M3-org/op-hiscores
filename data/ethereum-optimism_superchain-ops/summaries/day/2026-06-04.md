# ethereum-optimism/superchain-ops Daily Update (Jun 4, 2026)
## OVERVIEW 
The day saw significant feature additions, including new U19 templates for OPCM upgrades and dispute game arguments, alongside a config-driven storage-code whitelist for MultisigTask. Several issues were closed, addressing high-cardinality metrics, sequencer re-anchoring, and op-reth transaction pool behavior.

## KEY TECHNICAL DEVELOPMENTS

### U19 Template and Dispute Game Enhancements
New U19 templates were introduced, featuring a permissioned upgrade path for OPCMUpgradeV700 and mechanisms to set dispute game arguments and implementations. This work consolidates changes from multiple in-flight branches, streamlining future upgrades and dispute game configurations. ([#1448](https://github.com/ethereum-optimism/superchain-ops/pull/1448), [#1445](https://github.com/ethereum-optimism/superchain-ops/pull/1445))

### MultisigTask Configuration Improvements
A new feature was added to `MultisigTask` that allows for a config-driven, per-slot storage-code whitelist. This enables tasks to exempt specific storage slots from code presence checks, enhancing flexibility and control during state diff verification. ([#1450](https://github.com/ethereum-optimism/superchain-ops/pull/1450))

## CLOSED ISSUES

### Infrastructure and Metrics Optimization
An issue regarding very high cardinality for exported metrics in Kona was closed, with a fix implemented in a related pull request. This addresses potential performance and monitoring challenges. ([#19927](https://github.com/ethereum-optimism/superchain-ops/issues/19927))

### Sequencer Stability and Sync Testing
A follow-up issue concerning the follow-mode sequencer's `latestHead` failing to re-anchor after a `forceReset` under EL-sync was closed. The issue was deemed resolved after extensive testing and a related fix, with no further reproductions. Additionally, the integration of `op-supernode` with `op-sync-tester` was partially shipped, with the remaining parts to be skipped. ([#21125](https://github.com/ethereum-optimism/superchain-ops/issues/21125), [#21096](https://github.com/ethereum-optimism/superchain-ops/issues/21096))

### Transaction Pool and Test Reliability
An issue where `op-reth`'s interop transaction pool did not resume after a failsafe was disabled was closed, with a fix implemented in a related pull request. This ensures proper transaction processing after failsafe events. A flaky test in `op-e2e-fuzz` related to "Too long with no output" was also closed, with the root cause identified as excessive CPU usage during binary startup and a fix in draft. Another flaky test, `TestL2OutputSubmitter/honest`, was closed as filed in error, as the test was not actually run for the PR it was reported against. ([#21149](https://github.com/ethereum-optimism/superchain-ops/issues/21149), [#21191](https://github.com/ethereum-optimism/superchain-ops/issues/21191), [#21231](https://github.com/ethereum-optimism/superchain-ops/issues/21231))

### Test Suite Maintenance
An issue regarding `op-up`'s `TestRun` not being executed in CI due to a dependency on the `op-reth` binary was closed. This is no longer applicable as `op-up` has been deleted. ([#21202](https://github.com/ethereum-optimism/superchain-ops/issues/21202))

## ACTIVE ISSUES
### op-reth-test-engine Development Progress
The development of `op-reth-test-engine` is underway, with an implementation plan involving a stacked series of PRs. The first PR, [#21216](https://github.com/ethereum-optimism/superchain-ops/pull/21216), focuses on the foundation, including an `EphemeralChain` and `TestEngine` wrapper. The approach emphasizes reusing the existing `op-reth` stack for core functionalities like `OpChainSpec`, `OpNode` provider, and `init_genesis`, rather than reimplementing storage or block building. The "in-memory only" design is achieved through an ephemeral reth DB under a tmpfs temp directory. Future PRs will cover one-shot block execution, stateful in-flight payload builder, lib API finalization, and OP-semantics golden-vector tests. ([#20415](https://github.com/ethereum-optimism/superchain-ops/issues/20415))

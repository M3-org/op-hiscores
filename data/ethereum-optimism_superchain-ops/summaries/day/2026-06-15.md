## ACTIVE ISSUES

### op-geth Decoupling Progress
- **`opgeth-decoupling: migrate tests` ([#20265](https://github.com/ethereum-optimism/superchain-ops/issues/20265))**: Discussions highlight two key points for test migration:
    - Receipt index-correlation breaks under class-partitioned accessors, requiring tests to filter receipts in lockstep or use paired accessors.
    - Lagoon adds a trailing `0x7D` post-exec tx to L2 blocks, meaning tests fetching full L2 blocks on Lagoon+ presets need similar routing treatment as deposits.
- **`opgeth-decoupling: make op-service/sources the OP-aware eth client` ([#20264](https://github.com/ethereum-optimism/superchain-ops/issues/20264))**: The design resolution for L2 transaction representation suggests partitioning L2 tx accessors by tx class instead of using an `optypes.Transaction` wrapper. New accessors like `InfoAndUserTxs`, `InfoAndDeposits`, and `InfoAndFirstDeposit` are proposed. It's noted that Lagoon makes `0x7D` routing load-bearing, as `PostExecTx` is a canonical block transaction.
- **`opgeth-decoupling: create op-core/types (DepositTx with differential test, Receipt)` ([#20262](https://github.com/ethereum-optimism/superchain-ops/issues/20262))**: A design note clarifies that `*types.Transaction` helpers (`IsDepositTx`, `SourceHash`, etc.) are transition-only and will be deleted at cutover to upstream go-ethereum. `PostExecTx` is confirmed as a canonical block transaction in Lagoon.
- **`opgeth-decoupling: swap call-sites to op-core/* across op-node, op-service, op-batcher` ([#20263](https://github.com/ethereum-optimism/superchain-ops/issues/20263))**: A note emphasizes that the `optypes` helpers for deposit/post-exec are transition scaffolding. Call sites should prefer decoding raw bytes to `optypes.DepositTx` directly if possible, rather than building new long-lived APIs on top of these temporary helpers.

### OPCMUpgradeV700 Prestate Issue
- **`OPCMUpgradeV700: SUPER_PERMISSIONED_CANNON should use cannonKonaPrestate, not cannonPrestate` ([#1412](https://github.com/ethereum-optimism/superchain-ops/issues/1412))**: Recent comments indicate this issue is no longer relevant as the super permissioned dispute game no longer uses prestates. It's suggested that the V800 template should be used instead, and support for `SUPER_PERMISSIONED_GAME` in V700 might be removed to prevent misuse.

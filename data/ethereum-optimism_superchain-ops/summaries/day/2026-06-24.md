## ACTIVE ISSUES
*   **Flaky Test: FuzzDetectNonBijectivity in op-service/eth ([#21539](https://github.com/ethereum-optimism/superchain-ops/issues/21539))**
    The discussion centers on a flaky test (`FuzzDetectNonBijectivity`) in `op-service/eth/blob_test.go`. The core problem is that the test asserts that flipping a random bit in an encoded blob should either result in a decoding error or different decoded data. However, both `op-node` and `kona` silently mask out the top two bits of the first byte of the blob, meaning if one of these bits is flipped, the data decodes to the same value without an error, causing the test to fail. The latest comment clarifies that the blob code is not bijective specifically for these top two bits of the first field element. A potential fix would involve returning an error when these bits are set, but this could impact existing blobs on-chain and might require a hardfork. It's noted that honest batchers should not post malformed blobs, suggesting the issue might not be critical in practice, but the test's premise is flawed given the current encoding/decoding behavior.

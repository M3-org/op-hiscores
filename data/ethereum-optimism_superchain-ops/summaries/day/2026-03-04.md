# ethereum-optimism/superchain-ops Daily Update (Mar 4, 2026)
## OVERVIEW 
Today's focus was on preparing for upcoming network upgrades and addressing potential impacts on gas pricing and precompile acceleration. Several new pull requests were opened to support revshare tasks and update dispute game templates.

## KEY TECHNICAL DEVELOPMENTS

No completed work was reported for this day.

- **Revshare Task Implementations:** Two new pull requests were opened to implement revshare tasks for various chains. [#1380](https://github.com/ethereum-optimism/superchain-ops/pull/1380) focuses on U19 revshare for Sepolia additional op-chains, while [#1379](https://github.com/ethereum-optimism/superchain-ops/pull/1379) addresses Revshare Mainnet Tasks for Ink and Soneium.

## CLOSED ISSUES

No issues were closed today.

## NEW ISSUES

- **L2 Contracts Manager Documentation:** A new issue [#19391](https://github.com/ethereum-optimism/superchain-ops/issues/19391) was opened to document the "no-storage-variables" convention for L2ContractsManager, highlighting potential collisions with `ProxyAdmin` storage slots if not followed.
- **Glamsterdam Gas Pricing Impact Investigation:** Issue [#19375](https://github.com/ethereum-optimism/superchain-ops/issues/19375) was created to investigate the impact of Glamsterdam's increased gas costs on precompile acceleration, particularly concerning fault proofs.
- **Flashblocks WS Endpoint Rate Limiting:** A user reported encountering 429 rate limit errors when connecting to the flashblocks WS endpoint, leading to the creation of issue [#19366](https://github.com/ethereum-optimism/superchain-ops/issues/19366).

## ACTIVE ISSUES

- **op-node: On the Initial EL Sync UX and Correctness** [#17631](https://github.com/ethereum-optimism/superchain-ops/issues/17631): The discussion continues regarding the behavior of `op-node` marking the target as finalized after initial EL Sync, even if the block isn't truly finalized. Karlfloersch raised questions about whether this bug is specific to light CL/interop, how it's currently mitigated, and why light CL might make it more likely. Previous comments from trianglesphere, axelKingsley, and sebastianst debated the implications of EL sync and snap sync on finalization and derivation, with sebastianst suggesting a fix to only advance the unsafe ref while keeping safe and finalized at genesis.

- **Set default respected game type to CANNON_KONA** [#18640](https://github.com/ethereum-optimism/superchain-ops/issues/18640): This issue, aiming to make `CANNON_KONA` the primary game type after Upgrade 18, was moved back to "in progress" by stevennevins due to anticipated changes from an upcoming PR.

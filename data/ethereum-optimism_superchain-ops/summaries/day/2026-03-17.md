## ACTIVE ISSUES

### op-node: On the Initial EL Sync UX and Correctness ([#17631](https://github.com/ethereum-optimism/superchain-ops/issues/17631))
Discussion continues regarding the behavior of `op-node` marking the target of initial EL Sync as finalized, even if not truly finalized.
- **Latest Proposal:** `trianglesphere` suggests continuing EL sync to the unsafe head but using a different finalization gadget to set the finalized head. Options for this gadget include a command-line flag, an RPC URL for a trusted checkpoint provider, looking at L1 for the last finalized head, or an arbitrary delay for the finalized head. `trianglesphere` leans towards a command-line flag or a 12-hour fallback.
- **Impact on Derivation:** This approach would remove the ability to do derivation on `op-geth` if the unsafe chain doesn't match the derived chain, but this is deemed acceptable as `op-geth` is being deprecated.
- **Flakiness and Light CL:** `trianglesphere` notes that light CL makes this issue substantially more likely to occur.
- **Clarification on Mitigation:** `karlfloersch` inquired if this bug is specific to light CL/interop or if it's present without it, and how it's currently mitigated.

## ACTIVE ISSUES

### Post-Migration OPCM Upgrades
Discussions continued on making post-migration OPCM upgrades work for every chain in an interop set ([#21731](https://github.com/ethereum-optimism/superchain-ops/issues/21731)). The latest comments focused on two primary approaches:
- **Option 1: Resolve `ProxyAdmin` during upgrade:** This approach involves all chains upgrading shared components, with `OPContractsManagerMigrator.migrate` being idempotent. While it might waste some gas, it aligns with previous expectations and avoids silent non-upgrades. Concerns were raised about potential inconsistencies during upgrades and the need for careful post-upgrade checks.
- **Option 2: Skip updating shared components if `ProxyAdmin` doesn't match:** This would mean only chain 0 in a dependency set upgrades these contracts. However, this could lead to partial upgrades if chain B is upgraded before chain A, potentially causing incompatibility between shared and non-shared contracts.
The current leaning is towards Option 1, despite the concerns, as the alternative presents greater risks of silent failures or unapplied configurations. The discussion also emphasized the need for shared components to be backward compatible or fail gracefully if upgraded independently.

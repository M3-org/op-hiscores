# ethereum-optimism/superchain-ops Daily Update (May 27, 2026)
## OVERVIEW 
The day's development focused on preparing for Upgrade 19 betanet tasks and migrating a devnet to OP-operated infrastructure. Several critical issues related to supernode stability and op-reth compatibility were also addressed and closed.

## KEY TECHNICAL DEVELOPMENTS

### Upgrade 19 Betanet Preparations
Four Sepolia tasks were added for Upgrade 19 on the OP Labs Betanets, including both permissioned and permissionless configurations. A CI fix was also implemented to clear a stale fork-block pin. ([#1420](https://github.com/ethereum-optimism/superchain-ops/pull/1420))

### Devnet Migration Tasks
Six Sepolia tasks were scaffolded to facilitate the migration of the `migrations-sop-1` devnet from Partner-operated to OP-operated infrastructure. These tasks cover adding game types, setting respected game types, transferring system config ownership, setting batcher unsafe signers, proposer rotation, and fee vault updates. ([#1430](https://github.com/ethereum-optimism/superchain-ops/pull/1430))

### Prestate and Hash Updates
Updates were made to the prestates and hashes for the U19 betanet tasks, ensuring accuracy and consistency. ([#1432](https://github.com/ethereum-optimism/superchain-ops/pull/1432))

## NEWLY OPENED PULL REQUESTS
No new pull requests were opened today.

## CLOSED ISSUES

### Supernode Stability and Resync Fixes
Multiple issues related to `op-supernode`'s rewind/invalidation path and resync capabilities were addressed. This includes fixes for deadlocking in infinite retry loops and ensuring robust recovery from partial-progress states. ([#20929](https://github.com/ethereum-optimism/superchain-ops/issues/20929), [#20690](https://github.com/ethereum-optimism/superchain-ops/issues/20690), [#20944](https://github.com/ethereum-optimism/superchain-ops/issues/20944))

### L2CM Feature Flag Management
An issue concerning silent drift between feature flag definitions and the CI matrix in L2CM was closed. The resolution involves documenting all necessary updates when adding new dev or system features. ([#20340](https://github.com/ethereum-optimism/superchain-ops/issues/20340))

### op-reth Bootstrap Compatibility
A critical issue where `op-reth` minimal Bedrock bootstrap was incompatible with storage v2, causing node panics, has been resolved. The fix was confirmed with an upgrade to `op-reth/v2.2.5`. ([#20821](https://github.com/ethereum-optimism/superchain-ops/issues/20821))

## NEW ISSUES

### Smart Contract Security Inquiry
A new issue was opened by Hashlock.com, offering smart contract security audit services. ([#1433](https://github.com/ethereum-optimism/superchain-ops/issues/1433))

### Supernode CL Sync Recovery Stall
A new issue was identified where `op-supernode/op-reth` CL sync recovery can stall if `SafeDB`/bookkeeping references an EL-missing block. This was observed during the recovery of `bn-interop-jnt-v2` supernode 3. ([#21076](https://github.com/ethereum-optimism/superchain-ops/issues/21076))

### [PCD Milestone 1.5] Integrate L2CM into L2 Genesis ([#20903](https://github.com/ethereum-optimism/superchain-ops/issues/20903))
Discussion revolves around refactoring `L2ContractsManager` to be the source of truth for predeploy setup at L2 Genesis. One suggestion is to refactor `L2Genesis.s.sol` to etch proxies, preinstalls, and ConditionalDeployer, then execute the NUT bundle. A potential complication is the bidirectional mapping between forks and contract releases, where each contract release would need to reference a specific `<fork>_upgrade_bundle.json` for genesis file generation, which could introduce complexity.

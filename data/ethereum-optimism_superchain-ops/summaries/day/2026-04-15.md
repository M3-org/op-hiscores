## CLOSED ISSUES

### L2CM Upgrade Mechanism Refinements
Several issues related to the L2CM (L2 Contract Messenger) upgrade mechanism were closed. This includes the overall tracker for L2CM Upgrades [#18871](https://github.com/ethereum-optimism/superchain-ops/issues/18871), which was closed as all work is now tracked in a dedicated project. The milestone for audit fixes review and approval [#20085](https://github.com/ethereum-optimism/superchain-ops/issues/20085) was closed as a duplicate. Additionally, the task to add an interop migration path to L2CM [#19309](https://github.com/ethereum-optimism/superchain-ops/issues/19309) was closed, as interop contracts are now deployed as "all or nothing," which is already handled by the L2CM implementation. The FMA Action Items Tracker [#19345](https://github.com/ethereum-optimism/superchain-ops/issues/19345) was also closed as a duplicate, with all open issues copied to a new tracker.

### Sequencer RPC Endpoint Redundancy
The issue concerning support for multiple sequencer RPC endpoints for transaction forwarding [#763](https://github.com/ethereum-optimism/superchain-ops/issues/763) was closed. The discussion concluded that using existing generic proxy solutions like HAProxy or Nginx is a more pragmatic approach than implementing bespoke failover logic within `op-geth`.

## ACTIVE ISSUES

### L2CM Audit Finding #15: CGT Upgrades
Issue [#20077](https://github.com/ethereum-optimism/superchain-ops/issues/20077) discusses Audit Finding #15, an informational severity finding regarding CGT upgrades and the replaying of a renounced `LiquidityController` owner. The latest comment from maurelian confirms that this issue has been fixed by a pull request in the `optimism` repository.

### L2CM Interop Hard Fork Implementation
Issue [#20082](https://github.com/ethereum-optimism/superchain-ops/issues/20082) focuses on implementing the interop hard fork activation using the L2CM upgrade mechanism in `kona-node` and `op-node`. This is noted as the first real use of L2CM for a production hard fork beyond Karst. maurelian's latest comment clarifies that this is a simple task, requiring `L1Block.setFeature(Features.INTEROP)` to be called if `depset.len > 1`.

### SuperDisputeGame Deployment Support
Issue [#19652](https://github.com/ethereum-optimism/superchain-ops/issues/19652) tracks the effort to add support for deploying the `SuperDisputeGame` contract type via `op-deployer` and `netchef`. The latest comment from jelias2 indicates a decision to use a dedicated directory for `netchef` to pull a custom `op-deployer` build, enabling the use of the latest contracts and feature flags for `SuperDisputeGame` deployment.

### L2CM Support for op-chain-ops
Issue [#19102](https://github.com/ethereum-optimism/superchain-ops/issues/19102) addresses the need to add L2CM support to `op-chain-ops`, as `interopgen` currently hardcodes `UseL2CM: false` when building L2 genesis. maurelian's latest comment links this issue to another related issue, [#20079](https://github.com/ethereum-optimism/superchain-ops/issues/20079).

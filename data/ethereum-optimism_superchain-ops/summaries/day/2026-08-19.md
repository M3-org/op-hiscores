## ACTIVE ISSUES

*   **Flaky Test: `TestStorageProofUsingSimpleStorageContract` ([#20376](https://github.com/ethereum-optimism/superchain-ops/issues/20376))**
    *   The issue was reopened due to a recurrence of the flake, presenting a different symptom but the same underlying race condition.
    *   The current error indicates a 30-second timeout because the proofs store did not index block 2 in time, despite the validator EL advancing to block 17.
    *   Analysis suggests the proofs ExEx store on the validator never advanced past genesis, and the proofs indexing engine on the sequencer appeared starved, only processing blocks in a burst during teardown.
    *   The problem is identified as a flake rather than a regression, as the PR diff was CI-only, the job previously passed, and sibling tests using the same `WaitForProofsStoreBlock` path succeeded.
    *   Suggested directions include raising the `require.Eventually` timeout in `WaitForProofsStoreBlock` and investigating why the proofs indexing worker makes no progress for extended periods.

*   **[PCD] Default-`X` benchmarking ([#20916](https://github.com/ethereum-optimism/superchain-ops/issues/20916))**
    *   The issue was reopened twice today by the `todo-issue-checks` CI job because two TODOs in `op-deployer` still reference it.
    *   These TODOs relate to enforcing a reasonable minimum for the `X` offset (between L1 anchor's timestamp and L2 `genesis_time`) and replacing a placeholder value with a benchmark based on L2 genesis deployment time.
    *   The latest comment requests that if the work is complete or no longer planned, the TODO comments should be updated or removed, and the issue re-closed to prevent further CI failures.

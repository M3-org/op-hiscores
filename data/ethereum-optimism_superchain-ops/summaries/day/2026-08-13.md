# ethereum-optimism/superchain-ops Daily Update (Aug 13, 2026)
## OVERVIEW 
Today's focus was on critical ownership transfers within the Superchain ecosystem, specifically moving Ink SystemConfig ownership from the Foundation Operations Safe to the Foundation Upgrade Safe. Several key issues related to op-batcher and op-deployer functionalities were also closed.

## KEY TECHNICAL DEVELOPMENTS

### SystemConfig Ownership Transfer
*   Transferred ownership of the Ink `SystemConfigProxy` from the Foundation Operations Safe (FOS) to the Foundation Upgrade Safe (FUS) on both the Ink and Ink Sepolia networks. This change is a follow-up to the completed Gelato → OP Enterprise rollup-operator migration ([#1515](https://github.com/ethereum-optimism/superchain-ops/pull/1515)).

## CLOSED ISSUES

### Fault Proofs and Dispute Games
*   The issue regarding `sdm-net-0` not registering permissionless fault proofs was closed, with the decision to proceed with permissioned fault proofs due to their simplicity and existing implementation ([#22348](https://github.com/ethereum-optimism/superchain-ops/issues/22348)).

### Op-Deployer Enhancements
*   Changes and new OPCM options for ZK dispute games within `op-deployer` have been completed and the corresponding issue was closed ([#21429](https://github.com/ethereum-optimism/superchain-ops/issues/21429)).

### Op-Batcher Sequencing Window Recovery
*   An investigation into why `op-batcher` sequencing-window expiry recovery does not work well with span-batches was closed as "wontfix." Recovery mode is only supported with the batcher in singular-batch mode, and supporting span-batch recovery is not deemed necessary ([#16036](https://github.com/ethereum-optimism/superchain-ops/issues/16036)).

## NEW ISSUES
No new issues were opened today.

## ACTIVE ISSUES
*   **op-batcher: investigate why sequencing-window expiry recovery does not go well with span-batches** ([#16036](https://github.com/ethereum-optimism/superchain-ops/issues/16036)): This issue was closed today as "wontfix." The latest comments indicate that recovery mode with span batches may be impossible or much harder, and supporting it is not needed. Recovery mode is only supported with the batcher in singular-batch mode. The issue was previously marked low priority as sequencing-window expiries should ideally not happen, and operators can switch to singular batches for recovery.
*   **op-deployer changes / new OPCM options** ([#21429](https://github.com/ethereum-optimism/superchain-ops/issues/21429)): This issue was closed today, with the latest comment confirming that the work is done.
*   **sdm-net-0: restore permissionless fault proofs (register type-0 game implementation)** ([#22348](https://github.com/ethereum-optimism/superchain-ops/issues/22348)): This issue was closed today. The decision was made to use permissioned fault proofs instead, as they are simpler and already implemented on `sdm-net-0`. The permission model is considered orthogonal to SDM, and the SDM execution remains identical.

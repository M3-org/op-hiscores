## ACTIVE ISSUES

**Optimizing Safe-Head Advancement in op-node**
Discussion continues on [#15393](https://github.com/ethereum-optimism/superchain-ops/issues/15393) regarding the `op-node`'s behavior of sending a single aggregate safe-head advancement FCU message per channel. The latest comment from 0x416e746f6e on January 12, 2026, highlights that a previous attempt to fix the issue might have been misapplied, leading to the current version still performing an FCU on every safe head update instead of buffering them. This refers to a related pull request ([#18385](https://github.com/ethereum-optimism/optimism/pull/18385)) in the `optimism` repository. Earlier discussions included a merged PR ([#18234](https://github.com/ethereum-optimism/optimism/pull/18234)) that was expected to help, and an implementation in `kona-node` that sends only one FCU per span batch in the happy-path. The core problem identified is the "FCU spam" due to every pending safe update event having `Concluding = true`, triggering an FCU. Suggestions include modifying the logic to set `Concluding = false` for in-between promote pending safe updates and `Concluding = true` only for the last one. The impact of frequent FCU calls on performance, especially with varying network RTT, has also been a key point of discussion.

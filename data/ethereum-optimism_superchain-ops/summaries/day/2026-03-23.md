### Flaky Test: L2CLB Unsafe Head Did Not Expose Target Block
- Issue [#19681](https://github.com/ethereum-optimism/superchain-ops/issues/19681) saw extensive discussion regarding the `TestCLELDivergence` flaky test.
    - A key point of investigation was the `ErrEngineResetReq` and whether it's an expected part of the initial derivation pipeline lifecycle or indicative of an issue during EL sync. It was suggested that the reset is likely due to a fresh restart/initial pipeline initialization, not an in-progress EL sync.
    - The intent of the test is to ensure that even if the CL receives an unsafe head, the EL should not update its head due to missing data.
    - A potential race condition was identified where the event system processes `UnsafeUpdateEvent` and `ResetEvent` within a single drain cycle, making an intermediate state unobservable.
    - A critical question was raised: Is the reset in step 3 (where the `StatusTracker`'s `UnsafeL2` resets) correct behavior? The test expects the CL's unsafe head to persist, implying the divergence should be stable. If the reset is incorrect, it points to a bug in the reset logic.

### Interop Phase 3: Removing Chains From Shared Dispute Games
- On [#19692](https://github.com/ethereum-optimism/superchain-ops/issues/19692), a question was raised to understand the use cases for removing a chain from a shared dispute game and if this implies actual removal from the interop set.

### CGT Chains and Shared Dispute Games
- Issue [#19711](https://github.com/ethereum-optimism/superchain-ops/issues/19711) highlighted a potential issue for custom gas token (CGT) chains joining interop sets. It was noted that enabling the correct predeploys in the interop fork for CGT chains would require workarounds, specifically not deploying/enabling the current `SuperchainETHBridge`/`ETHLiquidity` contracts.

### Review Kona-Interop Block Hash Oracle
- Progress on [#18288](https://github.com/ethereum-optimism/superchain-ops/issues/18288) was updated with the opening of [#19726](https://github.com/ethereum-optimism/superchain-ops/pull/19726) to add a fixture-based integration test for `OracleInteropProvider::header_by_number` in `kona-proof-interop`.
    - The new test uses real OP Mainnet state/storage trie proof data to build an in-memory mock oracle, forcing the full production path for EIP-2935 block hash lookups. This approach is significantly faster than a full acceptance test.
    - Once [#19726](https://github.com/ethereum-optimism/superchain-ops/pull/19726) merges, the old action test (`TestInteropFaultProofs_DeepCanonicalBlockQuery`) can be removed.

### Overlap Between CGT and ETHLiquidity Contracts

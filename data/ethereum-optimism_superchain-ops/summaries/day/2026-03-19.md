## ACTIVE ISSUES

### Initial EL Sync UX and Correctness
Discussion on [#17631](https://github.com/ethereum-optimism/superchain-ops/issues/17631) continues to focus on the correctness and user experience of the `op-node`'s initial EL Sync. The latest comments reiterate that the current implementation is incorrect as it sets safe and finalized heads based on the unsafe head, rather than L1's finalization gadget. Option 2 (setting safe/finalized to unsafe head minus sequencer window) is proposed as a balanced approach for correctness and UX, requiring derivation of approximately 12 hours of data.

### Review Kona-Interop Block Hash Oracle
The discussion on [#18288](https://github.com/ethereum-optimism/superchain-ops/issues/18288) revolves around ensuring the `kona-interop` program's block hash oracle, which uses EIP-2935, is robust. The latest comments confirm that the core goal is to have an integration/acceptance test that verifies block hash lookups prior to the current history window, potentially by moving existing action tests to acceptance tests and leveraging time travel capabilities in `op-acceptance-test` to generate sufficient chain history.

### Non-Terminating CI Job: memory-all-opn-op-geth
The issue [#19563](https://github.com/ethereum-optimism/superchain-ops/issues/19563) details a recurring problem with the `memory-all-opn-op-geth` CI job hanging. Recent comments indicate a root cause analysis identified a mutex deadlock in `VirtualNode` during shutdown, involving `VirtualNode.Start()`, `OpNode.Stop()`, and event loop goroutines. A fix PR has been created to address this by releasing the mutex before calling `inner.Stop()` and adding a defensive timeout to `Supernode.Stop()`. The issue was closed as the fix is believed to resolve the problem.

### Flaky: TestInteropFaultProofs_ConsolidateValidCrossChainMessage
The issue [#19656](https://github.com/ethereum-optimism/superchain-ops/issues/19656) tracks a flaky test `TestInteropFaultProofs_ConsolidateValidCrossChainMessage`. The latest comments confirm another occurrence of the flake in CI, with the test timing out after 2 hours. A root cause has been identified as a race condition in `op-service/testutils/tcpproxy/proxy.go` where `handleConn` holds a mutex while dialing upstream, leading to untracked connections and blocking `wg.Wait()`. A fix PR has been created to release the mutex before dialing and check `p.stopped` before registering connections.

# ethereum-optimism/superchain-ops Daily Update (May 4, 2026)
## OVERVIEW 
The day saw a significant feature addition with the OPCM upgrade to v7.1.17, incorporating the ZK_DISPUTE_GAME slot. Several issues related to interop, supernode functionality, and testing were closed, indicating progress in these areas.

## KEY TECHNICAL DEVELOPMENTS

### OPCM Upgrade and ZK-Dispute Game Integration
A new feature was added to bump the OPCM v700 upgrade fixture to use the new devnet OPCM at `0x15c65ee282777e4a2856fdf26d33ee4d5bab30c4` (v7.1.17). This upgrade now requires a 7th `ZK_DISPUTE_GAME` entry in `disputeGameConfigs` per `OPContractsMan`. ([#1410](https://github.com/ethereum-optimism/superchain-ops/pull/1410))

## NEWLY OPENED PULL REQUESTS
A new pull request, [#1413](https://github.com/ethereum-optimism/superchain-ops/pull/1413), was opened to refactor the `SetBatcherAndOrSigner` functionality, making `safeAddressString` configurable via `config.toml`.

## CLOSED ISSUES

### Interoperability Enhancements and Testing
Several issues related to interop were closed. This includes ensuring new chains can be created post-interop ([#15884](https://github.com/ethereum-optimism/superchain-ops/issues/15884)), with the decision to ship a new OPCM that deploys new chains into their own dependency set. The stress testing of the expiry window for interop was also concluded ([#15285](https://github.com/ethereum-optimism/superchain-ops/issues/15285)), with findings indicating that the system handles repeated old log stress cleanly after an EIP-2935 decoding fix.

### Supernode and Testing Improvements
Work on `op-supernode` saw the closure of an issue regarding SuperRoots for unsafe data ([#19059](https://github.com/ethereum-optimism/superchain-ops/issues/19059)), with a workaround implemented in tests. The ability to build fast Kona prestates outside of Docker was also achieved ([#19057](https://github.com/ethereum-optimism/superchain-ops/issues/19057)). Additionally, missing "after head" tests were migrated to `op-supernode` ([#20370](https://github.com/ethereum-optimism/superchain-ops/issues/20370)), leading to a bug fix in `supernode`.

### Challenger Configuration Fixes
An issue concerning `op-challenger` was closed, which addressed the incorrect use of the Cannon prestate URL instead of the Kona prestate URL for `SuperPermissionedGameType` ([#20500](https://github.com/ethereum-optimism/superchain-ops/issues/20500)). This was identified as a duplicate of a previously addressed issue.

## NEW ISSUES
No new issues were opened today.

## ACTIVE ISSUES

### Interop: Stress Test Expiry Window ([#15285](https://github.com/ethereum-optimism/superchain-ops/issues/15285))
The issue was closed today, with the latest comments confirming that the analysis is sufficient to be confident about validating old message references without performance problems. A fix for Kona EIP-2935 proof decoding was implemented and merged, which resolved prior failures during consolidation. Stress testing on a devnet showed that repeated old log stress is expensive but terminates cleanly, with costs scaling linearly with message count. The practical upper bound appears to be the L2 gas/block limit rather than interop validation.

### Runbook: Update Super Root Chain from Permissioned to Permissionless with OPCMv2 ([#20473](https://github.com/ethereum-optimism/superchain-ops/issues/20473))
The latest comment suggests deferring this documentation update until after interop has shipped, as it's only required when a chain has upgraded to SuperDisputeGame (U20 at least) and then wants to move from permissioned to permissionless. The interop release is a precondition for this, so it shouldn't block the release.

# ethereum-optimism/superchain-ops Daily Update (May 15, 2026)
## OVERVIEW 
Today's focus was primarily on addressing and investigating flaky tests, particularly those related to withdrawal proofs and EL sync timeouts. Discussions also continued on the Interop Proofs Devnet and the status of op-reth nodes for mainnet.

## KEY TECHNICAL DEVELOPMENTS

No new features, bug fixes, code refactoring, documentation enhancements, or tests were added today.

No new pull requests were opened today.

## CLOSED ISSUES

### CI Performance Enhancements
An issue regarding enabling `eatmydata` in CI to improve performance was closed today [#20787](https://github.com/ethereum-optimism/superchain-ops/issues/20787). It was determined that `eatmydata` would not be effective for Go binaries due to static linking, and the focus shifted to more targeted solutions for dynamically linked components like `op-reth`'s mdbx commits.

### Interop Activation Gate Fix
The issue concerning the Kona `init-chain` interop activation gate being disabled when `interop_time` is `None` [#20578](https://github.com/ethereum-optimism/superchain-ops/issues/20578) was closed, with a fix implemented in a related pull request.

## ACTIVE ISSUES

### Flaky Test: `TestWithdrawal_CannonKona` [#19964](https://github.com/ethereum-optimism/superchain-ops/issues/19964)
This flaky test was reopened after a new variant was observed. The latest comments indicate a race condition where the L2 EL (op-reth) hasn't persisted state at a specific block when the test immediately requests a storage proof. A draft fix has been opened to wrap the `GetProof` call with a bounded `Eventually` retry mechanism for transient EL errors.

### Flaky Test: `TestELSyncSafeRetractedByOffset` [#20334](https://github.com/ethereum-optimism/superchain-ops/issues/20334)
This test continues to exhibit flakiness, with recent occurrences showing a CrossSafe sync timeout during preset setup. The verifier's safe head lags the sequencer, even after increasing retry attempts. This suggests a persistent sync timing issue or a potential bug rather than just a timeout.

### Interop Proofs Devnet [#20489](https://github.com/ethereum-optimism/superchain-ops/issues/20489)
Discussions confirm that this devnet will be used for long-term internal testing, with no immediate plans for spinning it down. The "Definition of Done" for this initiative includes successful superdispute games, withdrawals, proofs team approval, and working flashblocks and conductor re-orgs with interop.

### `op-challenger-runner` uses `op-reth` for OP Mainnet [#19517](https://github.com/ethereum-optimism/superchain-ops/issues/19517)
The team is still awaiting op-reth nodes with proofs history enabled for mainnet to proceed with setting up `op-challenger-runner` with Kona using an op-reth node.

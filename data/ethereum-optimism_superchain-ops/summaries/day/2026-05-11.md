# ethereum-optimism/superchain-ops Daily Update (May 11, 2026)
## OVERVIEW 
Today's development focused on executing a Sepolia task, refactoring a template for configurable safe addresses, and introducing new templates for SystemConfig ownership transfer and guarding against specific Cannon game types. Several flaky tests were also actively investigated and addressed.

## KEY TECHNICAL DEVELOPMENTS

### Template Refinements and New SystemConfig Ownership Transfer
A significant refactoring was completed to make the `SetBatcherAndOrSigner` template more robust by requiring explicit safe address configuration, preventing reliance on hardcoded values ([#1413](https://github.com/ethereum-optimism/superchain-ops/pull/1413)). Additionally, a new template and example task were introduced for transferring SystemConfig ownership, enhancing operational flexibility ([#1406](https://github.com/ethereum-optimism/superchain-ops/pull/1406)).

### Sepolia Task Execution and Cannon Game Type Guard
A specific task on the Sepolia network, task 75 related to deputy pause key rotation, was successfully executed ([#1419](https://github.com/ethereum-optimism/superchain-ops/pull/1419)). Furthermore, a new guard was implemented within the `OPCMUpgradeV800.sol` template to prevent issues with specific Cannon respected game types ([#1421](https://github.com/ethereum-optimism/superchain-ops/pull/1421)).

## ACTIVE ISSUES

### Persistent Flakiness in Sync-Related Tests
Several flaky tests related to synchronization and reorg recovery continue to be a focus. `TestUnsafeGapFillAfterSafeReorg` ([#19884](https://github.com/ethereum-optimism/superchain-ops/issues/19884)) and `TestFollowL2_ReorgRecovery` ([#19967](https://github.com/ethereum-optimism/superchain-ops/issues/19967)) were both reopened after resurfacing, with root cause analysis and a fix identified in PR #20651. `TestELSyncSafeRetractedByOffset` ([#20334](https://github.com/ethereum-optimism/superchain-ops/issues/20334)) also resurfaced, failing even with an increased retry budget, suggesting a deeper underlying sync timing issue or bug.

### Client Library Withdrawal Proving
Progress was made on the issue of client libraries needing to use timestamps instead of block numbers for proving withdrawals ([#18614](https://github.com/ethereum-optimism/superchain-ops/issues/18614)), with an upstream viem PR opened to address this.

### New Flaky Test Identified
A new flaky test, `TestNotTruncateDatabaseOnRestartWithExistingDatabase` ([#20649](https://github.com/ethereum-optimism/superchain-ops/issues/20649)), was reported and its root cause analysis and fix were identified in PR #20652.

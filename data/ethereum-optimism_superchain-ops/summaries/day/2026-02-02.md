## ACTIVE ISSUES

### `op-supernode`: Safe Label Adjusting ([#18976](https://github.com/ethereum-optimism/superchain-ops/issues/18976))
Discussion continued on how to manage the `Safe` label across the Execution Layer (EL), Consensus Layer (CL), and Superchain. A key point of contention is whether the `op-supernode` should directly control the EL's `Safe` and `Finalized` labels, or if the CL should remain the sole controller of the engine. The latest comment suggests having the CL maintain a full set of pointers and remain the sole controller of the engine, with the `op-supernode` controlling the engine via the virtual node/CL. This approach aims to avoid conflicts from multiple stateful controllers and leverage existing interop-aware data structures in the `op-node` engine controller.

### Flashblocks support within Geth ([#756](https://github.com/ethereum-optimism/superchain-ops/issues/756))
The discussion highlights the internal addition of Flashblocks support in `op-geth` for processing events from WebSockets and reconstructing blocks for live tracing. The latest comment provides a link to the `op-geth` version that includes Firehose Live Tracer and Flashblocks support, indicating active development and potential for integration into the main `op-geth` branch.

### Feedback: `BlockNotFoundError` in Step 5 (Prove the withdrawal on L1) ([#1956](https://github.com/ethereum-optimism/superchain-ops/issues/1956))
The issue concerns a `BlockNotFoundError` encountered during the L1 withdrawal proof step in the ETH bridge tutorial. The latest comment points out that while Optimism SDK packages include `isValidOutputRoot` validation, Viem's withdrawal guide and actions do not appear to perform equivalent output root validation. This suggests a potential gap in Viem's implementation that could lead to issues when the state root has not yet been published to L1.

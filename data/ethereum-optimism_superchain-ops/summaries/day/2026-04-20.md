## ACTIVE ISSUES

*   **Flaky Test: `TestFlashblocksStream`** ([#19883](https://github.com/ethereum-optimism/superchain-ops/issues/19883))
    *   The flaky `TestFlashblocksStream` test has resurfaced with a new failure mode. The latest failure indicates an assertion error where "0" is not greater than "1", suggesting the test expected at least one flashblock but received none. A fix has been proposed in a related `optimism` pull request, identifying the root cause as an incorrect test assertion regarding `payload_id` vs. `block_number` in flashblock sequences.

*   **`op-supernode`: SuperRoots for the Unsafe** ([#19059](https://github.com/ethereum-optimism/superchain-ops/issues/19059))
    *   Discussion continues on whether `supernode` should return super roots for unsafe data, even if it lacks semantic meaning. The latest comment suggests that if assumptions about the root's value are not made, querying ELs for a `latest` value might be equally effective. It's also noted that supernodes aren't primarily meant to rely on unsafe data, and the urgency for this task appears low, potentially leading to it being deferred. A recent change in `optimism` (PR #19972) was highlighted, allowing EL-synced nodes to support proofs immediately by adjusting FCU targets for retraction.

*   **`kona-node`, `interop`: Conditionally Deploy `CrossL2Inbox`** ([#19311](https://github.com/ethereum-optimism/superchain-ops/issues/19311))
    *   An e2e test has been developed to verify the conditional deployment of `CrossL2Inbox` as part of a larger issue. The test passes locally with recent changes, and it's confirmed that the fix needs to ensure `kona-derive` (and `kona-proof`) do not generate spurious `CrossL2Inbox` deployments, rather than focusing solely on `kona-node`.

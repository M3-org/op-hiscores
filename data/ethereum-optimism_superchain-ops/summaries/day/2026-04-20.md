## ACTIVE ISSUES

### Flaky Test: `TestFlashblocksStream`
The `TestFlashblocksStream` continues to be a flaky test ([#19883](https://github.com/ethereum-optimism/superchain-ops/issues/19883)). The issue was reopened today after resurfacing with a different failure mode, now indicating an assertion failure where the test expects at least one flashblock but received zero. A fix has been proposed in a related PR in the `optimism` repository, with the root cause identified as an incorrect test assertion regarding flashblock sequences being keyed by `payload_id` rather than `block_number`.

### Supernode Functionality for Unsafe SuperRoots
Discussion continues on whether `op-supernode` should return SuperRoots for unsafe data ([#19059](https://github.com/ethereum-optimism/superchain-ops/issues/19059)). The latest comments suggest that if assumptions about the root's value are not made, querying ELs for a `latest` value might be just as effective. There's a proposal to find alternative means to determine if a node considers a given height or hash as "observed," rather than relying on unsafe data within the Superroot API, as supernodes are not primarily meant to rely on unsafe gossip. The urgency for this task is considered low, and it may be marked as "deferred."

### Conditional Deployment of CrossL2Inbox
The issue regarding the conditional deployment of `CrossL2Inbox` in `kona-node` and `interop` ([#19311](https://github.com/ethereum-optimism/superchain-ops/issues/19311)) is expected to be closed by a pending PR in the `optimism` repository. An e2e test has been developed to verify this behavior, confirming that the fix works locally. The focus is on ensuring that `kona-derive` (and `kona-proof`) do not generate spurious `CrossL2Inbox` deployments.

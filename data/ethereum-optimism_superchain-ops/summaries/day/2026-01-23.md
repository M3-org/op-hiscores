# ethereum-optimism/superchain-ops Daily Update (Jan 23, 2026)
## OVERVIEW 
Today's development focused on a critical bug fix in the `SuperchainAddressRegistry` to support `op-contracts v6.0.0` and mark a Sepolia task as executed. Additionally, a new rehearsal was added, and a security check was implemented for `just sign-stack` commands.

## KEY TECHNICAL DEVELOPMENTS

### Superchain Address Registry Updates
A significant bug fix was implemented in the `SuperchainAddressRegistry` to ensure compatibility with `op-contracts v6.0.0`'s `gameArgs` and to correctly mark a Sepolia task as executed. This involved a refactor to simplify the code. ([#1353](https://github.com/ethereum-optimism/superchain-ops/pull/1353))

### Security Enhancements for Signing Operations
A crucial security improvement was made by adding a check to `just sign-stack` to verify that the signer is an owner of the safe, mirroring an existing check in `just sign`. ([#1354](https://github.com/ethereum-optimism/superchain-ops/pull/1354))

### Rehearsal and Configuration Additions
A new rehearsal for incoming singers in January 2026 was added, including necessary environment and configuration files. ([#1350](https://github.com/ethereum-optimism/superchain-ops/pull/1350))

## NEWLY OPENED PULL REQUESTS
- A new feature pull request, [#1356](https://github.com/ethereum-optimism/superchain-ops/pull/1356), was opened to add a betanet task for revenue sharing.

## CLOSED ISSUES
- **L1 Beacon Client Logging Improvement:** Issue [#17749](https://github.com/ethereum-optimism/superchain-ops/issues/17749), which discussed emitting a log when the L1 beacon client falls back to a sidecar endpoint, was closed. The latest comment indicates a decision to remove the fallback mechanism entirely.

# ethereum-optimism/op-geth Monthly Report (March 2026)

## 🚀 Highlights
In March 2026, development on `op-geth` focused on critical protocol alignment and the beginning of a transition phase for the client. A major milestone was the initiation of an upstream merge with `go-ethereum` v1.17.1, ensuring the codebase remains synchronized with the latest Ethereum mainnet standards. Significant effort was directed toward refining transaction pool behavior for interoperability, specifically handling reorgs to maintain cross-chain state integrity. However, the month also signaled a strategic shift, as certain features like Flashblocks support were deprecated in light of the planned deprecation of the `op-geth` client itself.

## 🛠️ Key Developments

### Upstream Synchronization & Maintenance
The project initiated a substantial update to align with the broader Ethereum ecosystem.
*   **Go-Ethereum Merge:** A major pull request was opened to merge `go-ethereum` v1.17.1 into `op-geth`, incorporating the latest upstream features and security fixes ([#774](https://github.com/ethereum-optimism/op-geth/pull/774)).
*   **Test Suite Refactoring:** To improve CI reliability and developer experience, the `eth/downloader` module's `receiptreference_test.go` was refactored to use sub-tests and local testing contexts, enhancing test isolation ([#771](https://github.com/ethereum-optimism/op-geth/pull/771)).
*   **Backend Configuration:** A fix was introduced to correctly set Karst overrides within the `eth/backend` ([#773](https://github.com/ethereum-optimism/op-geth/pull/773)).

### Transaction Pool & Interoperability
Refining how the sequencer handles transactions during chain reorganizations was a priority for maintaining Superchain consistency.
*   **Interop Reorg Handling:** Developers implemented a mechanism to drop interop transactions from the `txpool` during reorgs. This prevents the processing of transactions that may rely on invalidated cross-chain states ([#772](https://github.com/ethereum-optimism/op-geth/pull/772)).
*   **Filter Implementation:** New requirements were identified for `op-reth` to implement interop transaction pool filters and reorg eviction, including validation against the supervisor ([#19411](https://github.com/ethereum-optimism/op-geth/issues/19411)).

## 🐛 Issues & Triage

### Closed Issues
*   **Feature Deprecation:** Flashblocks support ([#756](https://github.com/ethereum-optimism/op-geth/issues/756)) was officially closed due to the upcoming deprecation of `op-geth`.
*   **Redundancy Cleanup:** Several issues were closed as duplicates or unnecessary, including L2 contract upgrade tracking ([#18843](https://github.com/ethereum-optimism/op-geth/issues/18843)), VM runner support for the supernode API ([#19008](https://github.com/ethereum-optimism/op-geth/issues/19008)), and batcher/sequencer time control ([#19009](https://github.com/ethereum-optimism/op-geth/issues/19009)).

### New & Active Issues
*   **Kona Protocol Discrepancies:** A cluster of issues emerged regarding the `kona` implementation, including disagreements with `op-node` on brotli channels ([#19333](https://github.com/ethereum-optimism/op-geth/issues/19333)), batch decoder panics ([#19334](https://github.com/ethereum-optimism/op-geth/issues/19334)), and frame parsing mismatches ([#19335](https://github.com/ethereum-optimism/op-geth/issues/19335)).
*   **Gas Pricing Risks:** Investigation began into how "Glamsterdam" gas pricing changes impact precompile acceleration. There are concerns regarding `requiredGas` adjustments to match L1 costs and the potential impact on fault proofs ([#19375](https://github.com/ethereum-optimism/op-geth/issues/19375)).
*   **Memory Management:** Monitoring continues for a database read transaction memory leak affecting Base mainnet archive nodes ([#19212](https://github.com/ethereum-optimism/op-geth/issues/19212)).

## 💬 Community & Collaboration
The month saw active volunteerism from the community, particularly in addressing the `kona` protocol vulnerabilities and discrepancies. Contributors stepped forward to handle batch decoder panics and frame parsing issues, showing a strong interest in the security of the OP Stack's Rust-based components. Collaboration between maintainers and contributors was also evident in the cleanup of orphaned code in `kona-derive` ([#19340](https://github.com/ethereum-optimism/op-geth/issues/19340)), where existing PRs were cross-referenced to prevent redundant work. The discussion around gas pricing ([#19375](https://github.com/ethereum-optimism/op-geth/issues/19375)) involved sharing external technical documentation (Notion), indicating a high level of coordination on complex protocol changes.

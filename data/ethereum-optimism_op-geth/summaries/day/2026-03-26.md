## NEW ISSUES

### Breaking Change in StorageKeys
A new issue [#780](https://github.com/ethereum-optimism/op-geth/issues/780) was opened reporting a breaking change in `StorageKeys` value, where `null` is returned instead of `[]` in `v1.101701.0`. Initial investigation points to `SortedFunc` in `access_list_tracer.go` as the cause, which returns `nil` for empty slices.

## ACTIVE ISSUES

### Flaky Test: `TestPreinteropFaultProofs_TraceExtensionActivation`
Discussion on [#19760](https://github.com/ethereum-optimism/op-geth/issues/19760) indicates that a proposed PR (ethereum-optimism/optimism#19745) is expected to fix this flaky test. The root cause was identified as a nonce race condition during the `migrateSuperRoots` process, which the PR addresses by simplifying the migration and avoiding ownership reassignments.

### Interop Tx Pool Eviction Behavior on Reorg
A question was raised on [#19351](https://github.com/ethereum-optimism/op-geth/issues/19351) regarding the behavior of interop transactions in the mempool during a reorg, specifically whether existing interop transactions are explicitly dropped or if periodic re-evaluation handles this.

### Karst-Specific Upgrade Transactions Removal
Discussion on [#19369](https://github.com/ethereum-optimism/op-geth/issues/19369) outlines the necessary updates to `UpgradeUtils.getTransactionCount()` and `GasLimits` struct when removing Karst-specific upgrade transactions from `GenerateNUTBundle.s.sol`.

### Investigation into Array of Predeploys for Upgrade Safety
The issue [#19260](https://github.com/ethereum-optimism/op-geth/issues/19260) received a detailed comment highlighting a structural pipeline gap in the upgrade process. It was noted that `L2DevFeatureFlags` was initially omitted from the NUT bundle's deployment, which was later fixed. However, a deeper concern was raised about the lack of a centralized source of truth for implementations and automated tests to validate completeness across multiple data structures. The comment also pointed out a latent issue with `ConditionalDeployer` that could lead to a critical failure if not addressed.

### Prove Withdrawals Using Chain-Specific Root Claim
The issue [#18517](https://github.com/ethereum-optimism/op-geth/issues/18517) is being reviewed for closure, with a question raised about whether the approach has changed to use `rootClaimByChainId` based on the game type.

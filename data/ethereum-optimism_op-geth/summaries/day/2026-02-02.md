## ACTIVE ISSUES

### op-supernode: Safe Label Adjusting
Discussions continued regarding the `op-supernode`'s handling of safe labels, particularly concerning the interaction between the Execution Layer (EL) and Consensus Layer (CL). A key update suggests having the CL maintain a full set of pointers (Unsafe, Safe, Finalized) and remain the sole controller of the engine, with the supernode controlling the EL's safe and finalized states directly. This approach aims to prevent conflicts between multiple stateful controllers and aligns with existing interop-aware data structures in the `op-node` engine controller. The potential impact on RPC responses from virtual nodes and the need for an "authority" object within the virtual node were also considered ([#18976](https://github.com/ethereum-optimism/op-geth/issues/18976)).

### Flashblocks Support within Geth
The conversation around integrating flashblocks support into `op-geth` saw a new comment from `maoueh`, who provided a link to their `op-geth` version which already includes Firehose Live Tracer and Flashblock(s) support. This highlights existing implementations and potential avenues for merging this functionality into the main `op-geth` repository ([#756](https://github.com/ethereum-optimism/op-geth/issues/756)).

### Feedback: `BlockNotFoundError` in Step 5 (Prove the withdrawal on L1)
Further analysis of the `BlockNotFoundError` during L1 withdrawal proving on Sepolia revealed that the Optimism SDK includes a validation step for the output root, which appears to be missing in Viem's withdrawal guide and related actions. This omission can lead to using contaminated output roots, especially when `waitToProve` is executed immediately after a withdrawal is initiated on L2. The discussion suggests that adding a similar output root validation to Viem's implementation could resolve the issue ([#1956](https://github.com/ethereum-optimism/op-geth/issues/1956)).

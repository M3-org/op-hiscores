# ethereum-optimism/op-geth Daily Update (May 29, 2026)
## OVERVIEW 
Today's development focused on a critical bug fix in receipt encoding for PostExec transactions, ensuring consistent byte representation. Additionally, the team updated the Superchain registry and streamlined the CI pipeline by removing an unnecessary Docker image signing step.

## KEY TECHNICAL DEVELOPMENTS

### Receipt Encoding Fix
A bug was fixed in the `Receipts.EncodeIndex` function to correctly include `PostExecTxType` in typed-receipt cases. This ensures that `DeriveSha` produces the same bytes as `Receipt.MarshalBinary` for PostExec receipts, with an extended test case to validate this behavior ([#797](https://github.com/ethereum-optimism/op-geth/pull/797)).

### Superchain Registry Update
The Superchain registry was updated, reflecting the latest configurations and ensuring compatibility across the Superchain ecosystem ([#798](https://github.com/ethereum-optimism/op-geth/pull/798)).

### CI Pipeline Optimization
The `binary_signer` attestation step was removed from the `docker-release` job in the CI pipeline, as it was no longer needed and caused failures, thus streamlining the build process ([#799](https://github.com/ethereum-optimism/op-geth/pull/799)).

## ACTIVE ISSUES

### Flaky Test: `TestReorgUnsafeHead` ([#20198](https://github.com/ethereum-optimism/op-geth/issues/20198))
The root cause of this flaky test has been identified and a fix is in progress. The issue stems from the test picking the next block's parent by reading the EL's mutable `eth.Unsafe` label, which can lag op-reth's post-forkchoice canonical-tag swap, leading to reorgs being silently undone. The proposed fix involves using the `ReorgExact` DSL poll to wait for the divergence height to reorg and explicitly taking the confirmed conflicting block as the parent.

### Interop Proofs Devnet ([#20489](https://github.com/ethereum-optimism/op-geth/issues/20489))
Progress is being made on the Interop Proofs Devnet. Playing a SuperFaultDisputeGame, including resolution, has been completed. The team is currently working on fixing the `op-chain-ops` script for proving withdrawals, as the first withdrawal initiated on the devnet will require a 7-day waiting period before finalization. This is the last remaining item to verify for proofs.

### [L2CM] Add `setWithdrawalRoute` to FeeVaults ([#20806](https://github.com/ethereum-optimism/op-geth/issues/20806))
This issue is currently blocked due to a problem with L2 contract semver modifications. The `L2ContractsManager_DowngradeNotAllowed()` function prevents upgrading a contract to a lower semver, which causes CI failures when an L2 contract's semver is bumped. This is considered a deficiency in the test setup rather than a bug in L2CM, and a solution is being sought to address this.

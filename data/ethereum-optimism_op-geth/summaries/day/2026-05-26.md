## ACTIVE ISSUES

### Engine API Stalling and Flaky Tests
Investigation into the `TestUnsafeChainNotStalling_CLSync` family of flaky tests revealed that the issue is not a test budget bug but an `op-reth` Engine API stall. The L2CL verifier was observed to be stalled at block 40, with `engine_newPayloadV3` / `forkchoiceUpdated` RPC calls timing out. The current hypothesis suggests a potential `op-reth` issue, possibly related to an upstream `reth` mmap/ftruncate race, similar to a recently fixed issue [#21041](https://github.com/ethereum-optimism/op-geth/issues/21041).

### Nondeterministic Semver Lock Generation
A new bug was reported where `generate-semver-lock` can produce nondeterministic `semver-lock.json` output when multiple Forge artifacts, such as `L2ProxyAdmin`, map to the same semver key but are compiled with different optimizer settings [#21032](https://github.com/ethereum-optimism/op-geth/issues/21032).

### Proofs-History Exex Crashes and Retries
Discussions continued on the `proofs-history` exex, which experiences SIGBUS crashes and infinite retry loops during deep FCU-triggered rewinds. A possible race condition involving `File::set_len(ftruncate)` truncating mmap pages while another thread reads them is being investigated. A PR for fixes related to aggressive retrying and log flooding has been raised, but the SIGBUS crash requires further investigation, with input from the Reth core team pending [#20934](https://github.com/ethereum-optimism/op-geth/issues/20934).

### L2CM Feature Flag Management
A decision was made to address the silent drift between feature flag definitions and the CI matrix by documenting all necessary update locations when adding new dev or system features. This documentation will be placed as comments in `DevFeatures.sol` and `devFeatures.go` [#20340](https://github.com/ethereum-optimism/op-geth/issues/20340).

### L2CM Predeploy Upgrade Safety
The issue regarding adding an array of predeploys to increase upgrade safety was reopened due to a persistent TODO referencing it in the codebase. The TODO at `packages/contracts-bedrock/test/L2/L2ContractsManager.t.sol:1060` indicates that a proper single source of truth for predeploys is still needed. The discussion highlights a structural gap in the upgrade pipeline where implementation knowledge is distributed across multiple independently maintained data structures, leading to potential silent failures in future upgrades [#19260](https://github.com/ethereum-optimism/op-geth/issues/19260).

### FCU Retry-Verify Workaround
A discussion on the `op-supernode`'s `RewindToTimestamp` using a retry-verify loop for FCU to work around an `op-reth` race condition concluded that this workaround might be a necessary compromise, as an upstream PR to fix `reth`'s engine API to apply results synchronously was closed due to lack of interest [#19772](https://github.com/ethereum-optimism/op-geth/issues/19772).

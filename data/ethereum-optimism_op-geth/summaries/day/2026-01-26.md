## ACTIVE ISSUES
### op-batcher: Stay in Sync with op-node Rollup Config
Discussion continued on how the `op-batcher` should handle rollup configuration changes. A suggestion was made to treat outdated rollup config as a critical error and restart the process, allowing the batcher to reload the configuration automatically. Earlier discussions explored making the operator explicitly provide the rollup config to the batcher or using signals from the active endpoint provider to trigger reloads [#18178](https://github.com/ethereum-optimism/op-geth/issues/18178).

### Sequencer-Defined Metering Design Document
The scope of this issue has been expanded to include an initial Proof of Concept (PoC), as it is currently blocking the design document. The initial devnet deployment is planned for January 30, 2026, after which the design can be evaluated and basic benchmarking performed [#360](https://github.com/ethereum-optimism/op-geth/issues/360).

### op-deployer: "transaction gas limit too high"
A user inquired about the status of this issue and which `op-deployer` version should be used for alt-da. Previous comments indicated that the issue stems from the Fusaka hardfork enforcing a transaction gas limit cap, making large transactions too big for the network. It was suggested that transactions might need to be broken down or optimized. An older version of `op-deployer` was noted, with a recommendation to use v0.5.0* for the latest contract release, though its post-Fusaka compatibility was not yet fully tested [#17912](https://github.com/ethereum-optimism/op-geth/issues/17912).

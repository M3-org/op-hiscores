## ACTIVE ISSUES

### op-deployer: "transaction gas limit too high"
Discussion continued on an issue where `op-deployer:v0.2.6` fails to deploy contracts due to a "transaction gas limit too high" error [#17912](https://github.com/ethereum-optimism/op-geth/issues/17912). A user inquired if the issue was fixed and which `op-deployer` version to use for alt-da. Previously, it was noted that the Fusaka hardfork enforces a transaction gas limit cap, making large transactions invalid. The suggestion was to break down large transactions or optimize them, and to use `v0.5.0*` of `op-deployer`, though its compatibility post-Fusaka was not yet confirmed.

### op-batcher: stay in sync with op-node rollup config
The discussion around the `op-batcher` not re-fetching the rollup config after startup continued [#18178](https://github.com/ethereum-optimism/op-geth/issues/18178). A new suggestion was to treat an outdated config as a critical error and restart the batcher, allowing it to reload the configuration. Earlier suggestions included making the operator explicitly provide the rollup config to the batcher or having the active endpoint provider signal when the config needs reloading.

### Add Sequencer-Defined Metering Design Doc
The scope of this issue has been expanded to include an initial Proof of Concept (PoC) for Sequencer-Defined Metering, as it is currently blocking the design document's progress [#360](https://github.com/ethereum-optimism/op-geth/issues/360). The initial devnet deployment is planned for January 30, 2026, after which the design can be evaluated and basic benchmarking performed.

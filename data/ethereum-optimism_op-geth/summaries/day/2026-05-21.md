## ACTIVE ISSUES

### Flaky Test: `TestFlashblocksStream` [#19883](https://github.com/ethereum-optimism/op-geth/issues/19883)
The flaky `TestFlashblocksStream` test, which was failing with `Address already in use (os error 98)`, has been root-caused. The issue stemmed from the `rollup-boost` RPC port being pre-allocated and then released, allowing other processes to claim the same port before the Rust subprocess could bind to it. A fix has been proposed in PR #20938, which adopts a "0 + read-back" pattern for RPC ports, eliminating the pre-allocation race condition. This fix is expected to auto-close the issue upon merge.

### Flaky Test: `TestTruncateDatabaseOnELResync` [#19897](https://github.com/ethereum-optimism/op-geth/issues/19897)
This flaky test has resurfaced with a new failure mode. The test now fails during the post-restart `InSync(LocalSafe, 90)` check, where the `LocalSafe` head remains at 0. The root cause is similar to a previously fixed issue, where the verifier's EL snap-sync takes too long under loaded CI conditions, causing the fixed-attempt wait to time out. A recommended fix is to convert the post-restart sync to a progress-aware pattern using `MatchedWithProgressFn`, similar to a previous fix for initial sync, to account for variable snap-sync times.

### Kona: Very high cardinality for exported metrics [#19927](https://github.com/ethereum-optimism/op-geth/issues/19927)
A user inquired about the status of this issue, indicating a continued need for it to be addressed.

### Receipt Root Mismatch [#19930](https://github.com/ethereum-optimism/op-geth/issues/19930)
Users continue to report encountering the `receipt root mismatch` issue on various chains, including Manta Pacific and Zora Sepolia, when syncing with `op-reth`. The problem appears to occur with OP deposit blocks containing a single type 0x7e transaction. A proposed PR (ethereum-optimism/optimism#20002) is suggested as a workaround to get through the Canyon hardfork. The core problem is believed to be in `op-reth/crates/consensus/src/proof.rs`, where the receipt trie encoding for pre-Canyon rules is incorrect, and in `validation/mod.rs`, where the precomputed `receipt_root_bloom` is unconditionally trusted.

### Flaky Test: `TestFlashblocksTransfer` [#19934](https://github.com/ethereum-optimism/op-geth/issues/19934)
This test continues to be flaky, with a recent failure on May 21, 2026, showing the same port-collision root cause as #19883. The test hung for 30 minutes after `rollup-boost` failed to start due to `Address already in use`. A fix proposed in #20938 is expected to resolve this specific manifestation. It was noted that this issue has accumulated several distinct root causes over time, and future non-port-collision flakes should be filed as new issues.

### Flaky Test: `TestReorgUnsafeHead` [#20198](https://github.com/ethereum-optimism/op-geth/issues/20198)
This flaky test recurred on May 21, 2026, with a new symptom: `Condition never satisfied` while awaiting balance updates, and faucet errors indicating `context canceled` and `context deadline exceeded`. This suggests the test is failing during setup due to issues with funding addresses, rather than the original reorg-related assertion. This new failure mode is being investigated as a fresh flake.

# ethereum-optimism/op-geth Daily Update (May 19, 2026)
## OVERVIEW 
The day saw significant progress in closing out several long-standing issues related to interop hard fork implementation, supervisor RPC namespace migration, and brotli channel divergence. A new feature for `eth_baseFee` RPC method was proposed.

## KEY TECHNICAL DEVELOPMENTS

- **New RPC Method Implementation**
    - A new pull request was opened to implement the `eth_baseFee` RPC method, enhancing the Ethereum API capabilities. [#792](https://github.com/ethereum-optimism/op-geth/pull/792)

## NEWLY OPENED PULL REQUESTS
- A new feature to implement the `eth_baseFee` RPC method was proposed in [#792](https://github.com/ethereum-optimism/op-geth/pull/792).

## CLOSED ISSUES

- **Interop Hard Fork and Supervisor Migration**
    - The implementation of the interop hard fork using the L2CM upgrade mechanism in `kona-node` and `op-node` was completed and tracked in a separate project, leading to the closure of [#20082](https://github.com/ethereum-optimism/op-geth/issues/20082).
    - The replacement of the supervisor RPC namespace with an interop filter namespace was finalized, closing [#20005](https://github.com/ethereum-optimism/op-geth/issues/20005).

- **Brotli Channel Divergence Resolution**
    - All identified concerns regarding Kona and op-node disagreements on brotli channels were addressed, including a critical wrapper bug fix and an upstream brotli fix, resulting in the closure of [#19333](https://github.com/ethereum-optimism/op-geth/issues/19333).

- **Dispute Game Test Migration**
    - The migration of remaining dispute game tests from `op-e2e/super_test.go` to `op-acceptance-tests` was completed, closing [#20814](https://github.com/ethereum-optimism/op-geth/issues/20814).

- **`debug_executePayload` Investigation**
    - An investigation into the necessity of `debug_executePayload` and related crates concluded that they are not removable as dead code, being an active, opt-in fast-path with a maintained server implementation in `op-reth`. The issue was closed as "wontfix" [#20879](https://github.com/ethereum-optimism/op-geth/issues/20879).

## NEW ISSUES

- **Flaky Test Identification**
    - A new issue was opened to track a flaky test, `TestSupernodeInterop_SafeHeadProgression`, observed in pipeline 125516, indicating a potential EL safe label race with CL cross-safe. [#20851](https://github.com/ethereum-optimism/op-geth/issues/20851)
    - Another flaky test, `TestChallengerCountersPreGenesisGame`, was identified and reported, requiring investigation into its intermittent failures. [#20869](https://github.com/ethereum-optimism/op-geth/issues/20869)

## ACTIVE ISSUES

- **SDM: Flashblocks Integration** [#20175](https://github.com/ethereum-optimism/op-geth/issues/20175)
    - The integration of SDM with flashblocks flows, updating `rollup-boost` and `op-rbuilder`, and adding integration tests, is currently blocked by another issue: `https://github.com/ethereum-optimism/optimism/issues/20599`.

- **Interop Proofs Devnet** [#20489](https://github.com/ethereum-optimism/op-geth/issues/20489)
    - The team is actively testing networks and documenting results in a Notion database. This devnet is intended for long-term internal testing. The Definition of Done (DoD) includes a superdispute game played, withdrawals, proofs team approval, flashblocks working with interop, and conductor re-orgs working.

- **Spin up devnet** [#20691](https://github.com/ethereum-optimism/op-geth/issues/20691)
    - The plan is to await the readiness of `glamsterdam-devnet-4` images before attempting a full devnet deployment in the infrastructure. Currently, efforts are focused on getting a local devnet running using `bal-devnet-6` images.

- **[flake] TestSupernodeInterop_SafeHeadProgression — EL safe label race with CL cross-safe** [#20851](https://github.com/ethereum-optimism/op-geth/issues/20851)
    - A fix PR has been opened to address the flake observed in pipeline 125516.

- **flaky test: `TestChallengerCountersPreGenesisGame`** [#20869](https://github.com/ethereum-optimism/op-geth/issues/20869)
    - Investigation into the flaky test is complete, and a proposed fix has been submitted in #20874. The root cause was identified as a timing issue where the migration consumed the full budget, causing a collision with the `plannedRollupStartBlockNumber`. The fix involves increasing the `preGenesisRollupStartBlockDelay` and implementing a post-migration L1-head re-read with a fast-fail invariant.

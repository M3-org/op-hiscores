# ethereum-optimism/op-geth Daily Update (Mar 17, 2026)
## OVERVIEW 
Today's focus was on stability and correctness, with a critical bug fix for interop transaction filtering during reorgs and several internal corrections to block processing and configuration. Flaky tests were a major theme, with multiple investigations and fixes.

## KEY TECHNICAL DEVELOPMENTS

### Transaction Pool Stability & Block Processing
A critical bug was addressed that previously caused interop transactions to not be dropped correctly during reorgs if a supervisor RPC URL wasn't explicitly set, enhancing the robustness of the transaction pool ([#776](https://github.com/ethereum-optimism/op-geth/pull/776)). Additionally, an issue where system transactions resulted in invalid blocks after the Regolith upgrade was resolved, ensuring correct block finalization ([#777](https://github.com/ethereum-optimism/op-geth/pull/777)).

### Configuration & Overrides
A typo in the `eth/backend` configuration was corrected, specifically regarding the Karst override, improving the accuracy of system settings ([#773](https://github.com/ethereum-optimism/op-geth/pull/773)).

## NEWLY OPENED PULL REQUESTS
No new pull requests were opened today.

## CLOSED ISSUES

### Flaky Test Resolution
Several flaky tests were investigated and closed today, significantly improving CI stability. This includes `TestBreakTimestampInvariant` ([#18137](https://github.com/ethereum-optimism/op-geth/issues/18137)), `TestExpiredMessage` ([#19588](https://github.com/ethereum-optimism/op-geth/issues/19588)), `TestImplementations` ([#19583](https://github.com/ethereum-optimism/op-geth/issues/19583)), `TestSuperchain` ([#19586](https://github.com/ethereum-optimism/op-geth/issues/19586)), and `TestExecMsgDifferTxIndex` ([#19589](https://github.com/ethereum-optimism/op-geth/issues/19589)). The root causes ranged from nonce races and missing sync propagation to overly tight timeouts and resource contention in CI environments.

### Supernode Reporting & Interop Review
The issue regarding the Supernode reporting the current verified L1 instead of the current derived L1 was closed, with a fix implemented in a related PR ([#18651](https://github.com/ethereum-optimism/op-geth/issues/18651)). The review of the Kona-interop block hash oracle is nearing completion, with the remaining task being an integration test for block lookups prior to the history window ([#18288](https://github.com/ethereum-optimism/op-geth/issues/18288)).

### Glamsterdam Gas Pricing Impacts
The investigation into Glamsterdam gas pricing impacts on precompile acceleration was closed, with the required work being tracked in a separate issue ([#19375](https://github.com/ethereum-optimism/op-geth/issues/19375)).

### Blob Archiver Endpoint Support
An issue regarding the blob-archiver not supporting the `/eth/v1/beacon/blobs/` endpoint was opened and immediately closed, as it was determined to be an issue with the `blob-archiver` repository rather than `op-geth` ([#19623](https://github.com/ethereum-optimism/op-geth/issues/19623)).

## ACTIVE ISSUES

### Initial EL Sync UX and Correctness ([#17631](https://github.com/ethereum-optimism/op-geth/issues/17631))
Discussion continues on the behavior of `op-node` during initial EL Sync, specifically how it marks the reached target as finalized even if not truly finalized. The latest comments propose continuing EL sync to the unsafe head but using a different finalization gadget to set the finalized head. Options for this gadget include a command-line flag, an RPC URL for a trusted checkpoint provider, looking at L1 for the last finalized head, or an arbitrary delay. The discussion also touched on whether this bug is specific to light CL/interop or if it's present without it, and how sequencer nodes are currently mitigating this.

### Supernode Test Coverage ([#19010](https://github.com/ethereum-optimism/op-geth/issues/19010))
Progress is being made on ensuring comprehensive test coverage for Supernode, mirroring the previous Supervisor coverage. A draft PR has been opened for the first batch of deduplication in `op-e2e/actions/interop/proofs_test.go`, deleting three tests that are now fully covered by equivalent tests in `op-acceptance-tests` via the shared `superfaultproofs` package. Ten tests remain in `op-e2e` that cover unique scenarios not yet ported.

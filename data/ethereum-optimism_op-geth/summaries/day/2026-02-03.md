# ethereum-optimism/op-geth Daily Update (Feb 3, 2026)
## OVERVIEW 
The day's development focused on tooling improvements for Superchain synchronization and addressing issues related to L1 head updates in op-supernode. Discussions also continued on the initial EL Sync UX and correctness, and the concept of "SuperRoots for the unsafe" was introduced.

## KEY TECHNICAL DEVELOPMENTS

### Superchain Synchronization Tooling
A change was implemented to replace `dasel` with `yq` for reading TOML files in the `sync-superchain.sh` script, aiming for a more stable and widely-adopted tool for Superchain synchronization. This change is an alternative to a newly opened pull request that sought to address `dasel` compatibility issues. ([#762](https://github.com/ethereum-optimism/op-geth/pull/762))

## NEWLY OPENED PULL REQUESTS
- **sync-superchain: add dasel v3 compatibility** ([#761](https://github.com/ethereum-optimism/op-geth/pull/761)): This pull request aims to add compatibility for `dasel` version 3 in the `sync-superchain` script.

## CLOSED ISSUES

### op-supernode L1 Polling Fix
An issue where HTTP L1 URLs in `op-supernode` inadvertently disabled L1 polling, preventing virtual nodes from receiving L1 head updates, has been closed. This was resolved by a related pull request. ([#19012](https://github.com/ethereum-optimism/op-geth/issues/19012))

## NEW ISSUES

### SuperRoots for Unsafe Data
A new issue has been opened to discuss the potential utility of `op-supernode` returning super roots even when no verified or safe data exists at a referenced timestamp, specifically for unsafe data. The discussion questions the expected verification work on such unsafe data. ([#19059](https://github.com/ethereum-optimism/op-geth/issues/19059))

## ACTIVE ISSUES

### Initial EL Sync User Experience and Correctness
Discussions continued regarding the behavior of `op-node` marking the reached target as finalized after initial EL Sync, even if the block is not actually finalized. The conversation explored whether Snap Sync should follow the finalized L2 as a maximum target and the implications of re-running derivation on a snap-synced node. It was noted that the current behavior was an intended design, but is now considered buggy. Suggestions include running derivation from a prior L1 block and then consolidation to verify alignment with the EL-synced unsafe chain. ([#17631](https://github.com/ethereum-optimism/op-geth/issues/17631))

### Enable Skipped Acceptance Tests for Interop Proofs
This issue, which was previously closed, has been reopened due to a remaining skipped test (`TestInteropReadiness`) in the codebase, despite other related tests being enabled. The `TestInteropReadiness` test is still skipped with a TODO referencing this issue, indicating it needs to be unskipped once the super DG supports explicit output roots. ([#18616](https://github.com/ethereum-optimism/op-geth/issues/18616))

## ACTIVE ISSUES
- **Flaky Test: TestInteropFaultProofs_ConsolidateValidCrossChainMessage** [#19656](https://github.com/ethereum-optimism/op-geth/issues/19656): This issue, concerning a flaky test that causes subtests to time out, was closed today. The root cause was identified as a race condition in `op-service/testutils/tcpproxy/proxy.go` where `handleConn` held a mutex while dialing upstream, leading to untracked goroutines and test hangs. A fix PR (ethereum-optimism/optimism#19662) was created to release the mutex before dialing and check `p.stopped` before registering connections.
- **Non-terminating CI job: memory-all-opn-op-geth** [#19563](https://github.com/ethereum-optimism/op-geth/issues/19563): This issue was reopened today as the `memory-all-opn-op-geth` job hung again, with `TestChallengerPlaysGame` and `TestProposer` in `interop/proofs` hitting the 2-hour subtest timeout. These specific test failures are now being tracked in separate issues ([#19672](https://github.com/ethereum-optimism/op-geth/issues/19672) and [#19673](https://github.com/ethereum-optimism/op-geth/issues/19673)). Previously, a draft fix was opened for a different hanging issue related to RPC calls within polling loops not respecting timeout contexts.
- **On the Initial EL Sync UX and Correctness** [#17631](https://github.com/ethereum-optimism/op-geth/issues/17631): Discussion continued on the correctness and user experience of initial EL sync. The current implementation is deemed incorrect because it sets safe and finalized heads based on the unsafe head after initial EL sync, rather than L1 finalization. Option 2, proposed by @trianglesphere, suggests setting safe/finalized to the unsafe head minus the sequencer window, balancing correctness with improved UX by reducing derivation time compared to starting from genesis. Option 3, allowing external provision of safe/finalized values, offers the best UX but adds complexity and trust dependencies.
- **[tracking]: Review kona-interop block hash oracle** [#18288](https://github.com/ethereum-optimism/op-geth/issues/18288): The discussion focused on ensuring an integration/acceptance test exists for looking up block hashes prior to the current history window. It was noted that an existing action test covers this, and the goal is to transition this to an acceptance test using `op-acceptance-test`'s time travel capabilities (`presets.WithTimeTravelEnabled()` and `sys.AdvanceTime`) to generate sufficient chain history. The challenge lies in generating enough L2 blocks after L1 time travel.

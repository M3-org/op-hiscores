## ACTIVE ISSUES

### Support for Multiple Sequencer RPC Endpoints
Discussion continues on [#763](https://github.com/ethereum-optimism/op-geth/issues/763) regarding supporting multiple sequencer RPC endpoints for transaction forwarding. The latest comments suggest using existing generic proxy solutions like HAProxy or Nginx instead of implementing a bespoke fallback client within `op-geth`. This approach would allow `op-geth` to point to a local proxy, leveraging established tools for failover and health checking. One comment also suggested using `proxyd` for its routing strategies. Previous discussions acknowledged the benefit of client-side failover as a defense-in-depth measure against CDN failures, while also noting that infrastructure-level redundancy is ideal.

## CLOSED ISSUES

Two issues were closed today: [#18536](https://github.com/ethereum-optimism/op-geth/issues/18536), which involved removing checks for OPCM v2 usage, and [#18633](https://github.com/ethereum-optimism/op-geth/issues/18633), related to adding a resource locator for v7_0_0 artifacts. ## NEW ISSUES

**Potential Division-by-Zero in Base Fee Calculation**
A new issue, [#757](https://github.com/ethereum-optimism/op-geth/issues/757), was opened to report that `CalcBaseFee` can panic with a division-by-zero error if `elasticity == 0` is decoded from Optimism extraData.

## ACTIVE ISSUES

**Withdrawal Proving with Chain-Specific Root Claim**
Discussion on [#18517](https://github.com/ethereum-optimism/op-geth/issues/18517) regarding proving withdrawals using a chain-specific root claim continued. The latest comment suggests moving this to the backlog, as updating `OptimismPortal2` depends on the U19 execution and must be done separately from the FaultDisputeGame upgrade to ensure continuous withdrawal functionality.

**op-supernode SyncStatus API Definition**
On [#18947](https://github.com/ethereum-optimism/op-geth/issues/18947), the discussion focused on defining the `SyncStatus` API for `op-supernode`. It was decided that the interface should include the `op-node` SyncStatus for every chain, the sync status of every verification activity, and for interop activity, the latest verified timestamp and the current L1.

**Fixing EIP-1559 Parameters Decoding in op-alloy**
Issue [#18951](https://github.com/ethereum-optimism/op-geth/issues/18951) addresses fixing EIP-1559 parameters decoding in `op-alloy` to properly catch zero elasticities early. A community member expressed interest in taking on this task.

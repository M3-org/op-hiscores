# ethereum-optimism/op-geth Daily Update (Jun 2, 2026)
## OVERVIEW 
Today's development focused on addressing interop transaction pool issues and planning for invalid interop message recovery. A new pull request was opened to add a Karst deprecation kill switch.

## KEY TECHNICAL DEVELOPMENTS

## NEWLY OPENED PULL REQUESTS
- A new pull request, [#802](https://github.com/ethereum-optimism/op-geth/pull/802), was opened to add a Karst deprecation kill switch to the consensus/beacon.

## CLOSED ISSUES

## NEW ISSUES
- **Interop Transaction Pool Resilience:** A new issue, [#21149](https://github.com/ethereum-optimism/op-geth/issues/21149), was opened to address a problem where `op-reth`'s transaction pool does not resume accepting interop transactions after the `op-interop-filter` failsafe is disabled, requiring a restart.
- **Invalid Interop Message Recovery:** Issue [#21161](https://github.com/ethereum-optimism/op-geth/issues/21161) was created to develop and test a runbook for recovering a chain after an invalid interop message triggers a reorg, noting that several systems do not handle large reorgs smoothly.

## ACTIVE ISSUES
- **Spin up devnet** ([#20691](https://github.com/ethereum-optimism/op-geth/issues/20691)): The latest update indicates that a local devnet is now running, with plans to establish a long-running devnet next. Previously, the plan was to await `glamsterdam-devnet-4` images before attempting a full devnet.
- **`op-revm` support** ([#21069](https://github.com/ethereum-optimism/op-geth/issues/21069)): Discussion revolved around keeping `op-revm` in sync with new `revm` releases. It was confirmed that `op-revm` aims to stay in sync, with dependency updates often coinciding with `reth` updates. The user expressed particular interest in `REVM`'s latest release (v111) due to its Amsterdam hardfork support and shared type definitions, which would benefit `op-revm` despite L1 changes not immediately affecting the OP stack.
- **op-reth: interop tx pool does not resume after failsafe is disabled (requires restart)** ([#21149](https://github.com/ethereum-optimism/op-geth/issues/21149)): An update from remediation on `interop-bench-3` revealed that restarting `op-reth` alone was insufficient to restore interop after clearing the failsafe. It was found that `op-rbuilder` (also reth-based) was holding the evicted state. The remediation now requires restarting both `op-reth` and `op-rbuilder` on the affected chain's sequencers. A failsafe-state gauge metric is proposed in [#21151](https://github.com/ethereum-optimism/op-geth/issues/21151) to improve observability.
- **Invalid interop message recovery runbook** ([#21161](https://github.com/ethereum-optimism/op-geth/issues/21161)): It was suggested that the runbook should cover issues such as [#21149](https://github.com/ethereum-optimism/op-geth/issues/21149), [#20006](https://github.com/ethereum-optimism/op-geth/issues/20006), and [#21125](https://github.com/ethereum-optimism/op-geth/issues/21125), in addition to ensuring the failsafe is disabled again.

# ethereum-optimism/op-geth Weekly Report (Feb 1 - 7, 2026)

## 🚀 Highlights
This week, development focused on hardening the Superchain infrastructure and refining the synchronization logic between the Execution Layer (EL) and Consensus Layer (CL). Key efforts included stabilizing the `sync-superchain` tooling by migrating to more robust dependency handlers and addressing critical UX issues regarding initial EL sync correctness. Significant architectural discussions also took place regarding the `op-supernode`'s role in managing safe labels and the potential integration of Flashblocks to reduce operational complexity for node operators.

## 🛠️ Key Developments

### Tooling & Scripting Enhancements
Efforts were made to improve the reliability of internal scripts used for Superchain management.
*   **Migration to `yq`:** The `sync-superchain` script was updated to use `yq` instead of `dasel` for TOML processing. This change addresses stability and compatibility issues, leveraging a more widely adopted tool for configuration management ([#762](https://github.com/ethereum-optimism/op-geth/pull/762)).
*   **Dependency Management:** The project’s `fork.yaml` reference was bumped from `v1.16.5` to `v1.16.8` to ensure alignment with the latest protocol specifications ([#760](https://github.com/ethereum-optimism/op-geth/pull/760)).

### Flashblocks & Performance
*   **Flashblocks Support:** Discussions progressed regarding merging Flashblocks and Firehose Live Tracer support directly into the main `op-geth` repository. This move is aimed at reducing the high disk space consumption and operational overhead currently associated with running archive versions of alternative clients like Reth ([#756](https://github.com/ethereum-optimism/op-geth/issues/756)).

## 🐛 Issues & Triage

### Closed Issues
*   **L1 Polling Fix:** A bug was resolved where `op-supernode` instances configured with HTTP L1 URLs failed to poll for updates, preventing virtual nodes from receiving L1 head updates ([#19012](https://github.com/ethereum-optimism/op-geth/issues/19012)).

### New & Active Issues
*   **Initial EL Sync UX:** Significant debate continues regarding how `op-node` handles finalization markers during initial sync. Current behavior may incorrectly mark targets as finalized before they are verified. Proposed fixes include running derivation from prior L1 blocks to ensure alignment with the EL-synced unsafe chain ([#17631](https://github.com/ethereum-optimism/op-geth/issues/17631)).
*   **Safe Label Management:** Developers are weighing whether the CL should remain the sole controller of the EL engine or if `op-supernode` should take a more active role. The goal is to prevent stateful controllers from falling out of sync while maintaining interop-aware data structures ([#18976](https://github.com/ethereum-optimism/op-geth/issues/18976)).
*   **Interop Proof Testing:** Acceptance tests for interop readiness (`TestInteropReadiness`) remain a priority. The tests are currently skipped pending support for explicit output roots in the super DG ([#18616](https://github.com/ethereum-optimism/op-geth/issues/18616)).
*   **Withdrawal Validation:** Analysis of a `BlockNotFoundError` in the ETH bridge tutorial revealed a lack of output root validation in certain SDK/viem actions, leading to timing issues when users attempt to prove withdrawals before state roots are published to L1 ([#1956](https://github.com/ethereum-optimism/op-geth/issues/1956)).

## 💬 Community & Collaboration
The week saw active technical coordination between contributors like `ajsutton`, `Inphi`, `sebastianst`, and `axelKingsley`, particularly regarding the nuances of Snap Sync and the transition from unsafe to safe heads. There is a clear collaborative push to move experimental features (like Flashblocks) into the core codebase to improve the developer experience for those managing large-scale node infrastructure. Discussions around `op-supernode` and "SuperRoots" for unsafe data ([#19059](https://github.com/ethereum-optimism/op-geth/issues/19059)) indicate a forward-looking focus on optimizing data availability and retrieval within the Superchain ecosystem.

# ethereum-optimism/op-geth Weekly Report (May 17 - 23, 2026)

## 🚀 Highlights
This week, the `op-geth` project focused heavily on refining the Interop hard fork infrastructure and resolving technical debt across the OP Stack. Significant progress was made in migrating RPC namespaces and finalizing the L2CM upgrade mechanism, signaling a transition toward broader project-level tracking for interoperability features. While development activity was concentrated mid-week, the team successfully addressed critical data divergence issues in Brotli channels and initiated work on expanding the Ethereum API surface with new RPC methods.

## 🛠️ Key Developments

### RPC & API Enhancements
The project is expanding its compatibility with standard Ethereum interfaces while refining internal communication protocols.
*   **New `eth_baseFee` Method:** A new pull request was introduced to implement the `eth_baseFee` RPC method, which will improve the node's utility for developers requiring direct access to base fee data [#792](https://github.com/ethereum-optimism/op-geth/pull/792).
*   **Namespace Migration:** The `supervisor` RPC namespace has been successfully migrated to a dedicated `interop filter` namespace, streamlining how interoperability-related queries are handled [#20005](https://github.com/ethereum-optimism/op-geth/issues/20005).

### Interoperability & Protocol Stability
Significant effort was directed toward the Interop hard fork and ensuring consistency across different node implementations.
*   **Hard Fork Implementation:** The Interop hard fork, utilizing the L2CM upgrade mechanism within `kona-node` and `op-node`, has reached a milestone where it is now being tracked under the broader Interop project umbrella [#20082](https://github.com/ethereum-optimism/op-geth/issues/20082).
*   **Brotli Channel Resolution:** Developers resolved a divergence issue where Kona and `op-node` disagreed on Brotli channels, ensuring data consistency across the stack [#19333](https://github.com/ethereum-optimism/op-geth/issues/19333).
*   **Code Auditing:** An investigation into `debug_executePayload` determined that the code is not redundant; it remains an active, opt-in fast-path maintained for `op-reth` compatibility [#20879](https://github.com/ethereum-optimism/op-geth/issues/20879).

## 🐛 Issues & Triage

### Closed Issues
*   **Test Suite Migration:** Dispute game tests were successfully moved from `op-e2e/super_test.go` to `op-acceptance-tests` to improve the organization of the testing framework [#20814](https://github.com/ethereum-optimism/op-geth/issues/20814).
*   **Protocol Alignment:** Issues regarding the Interop hard fork and Brotli channel divergence were closed following successful implementation and bug fixes.

### New & Active Issues
*   **Flaky Test Management:** Two significant flakes were identified this week. `TestSupernodeInterop_SafeHeadProgression` is experiencing a race condition between EL safe labels and CL cross-safe status [#20851](https://github.com/ethereum-optimism/op-geth/issues/20851), and `TestChallengerCountersPreGenesisGame` is currently under investigation with a fix in progress [#20869](https://github.com/ethereum-optimism/op-geth/issues/20869).
*   **Devnet Deployments:** Efforts are ongoing to spin up a long-term internal testing network for Interop Proofs. This is currently dependent on the availability of `glamsterdam-devnet-4` images, with local testing proceeding on `bal-devnet-6` in the interim [#20489](https://github.com/ethereum-optimism/op-geth/issues/20489), [#20691](https://github.com/ethereum-optimism/op-geth/issues/20691).
*   **Blockers:** The integration of SDM with Flashblocks (including updates to `rollup-boost` and `op-rbuilder`) remains blocked by an external dependency [#20175](https://github.com/ethereum-optimism/op-geth/issues/20175).

## 💬 Community & Collaboration
The activity this week reflects a high degree of coordination between the `op-geth`, `kona`, and `op-node` contributors, particularly regarding the resolution of the Brotli channel divergence and the Interop hard fork. The migration of tests to `op-acceptance-tests` suggests an ongoing effort to standardize quality assurance across different teams within the Optimism Collective. While no new external contributors were highlighted, the rapid identification and PR-generation for flaky tests indicate a highly responsive maintainer group.

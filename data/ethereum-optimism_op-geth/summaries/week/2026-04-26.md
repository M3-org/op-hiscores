# ethereum-optimism/op-geth Weekly Report (Apr 26 - May 2, 2026)

## 🚀 Highlights
This week, development focused on strengthening the integration between `op-geth` and the Superchain ecosystem through enhanced registry transparency and configuration updates. Significant progress was made in stabilizing the CI pipeline by resolving long-standing test crashes and addressing edge cases in genesis boot logic for LightCL. While core infrastructure like the L2CM upgrade process reached completion, the team continues to navigate challenges regarding flaky reorg tests and dependency conflicts within the `op-alloy` ecosystem.

## 🛠️ Key Developments

### Superchain Registry & Configuration
Efforts this week centered on improving how `op-geth` consumes and tracks Superchain configurations to ensure better reproducibility for downstream users.
*   **Registry Transparency:** A new feature was implemented to expose the specific commit hash of the `superchain-registry` used to generate the embedded `superchain-configs.zip`. This allows consumers to pin specific registry versions for consistent environments [#785](https://github.com/ethereum-optimism/op-geth/pull/785).
*   **Version Bump:** The `superchain-registry` was updated to commit `cc07e96d91a1647cbce7eef6572098bece1f7fca`, which includes the addition of the new `safer_safes_addr` field [#788](https://github.com/ethereum-optimism/op-geth/pull/788).

### Protocol & Transaction Logic
*   **L2CM Upgrades:** The implementation of the Bundle Canonicalization process for L2CM upgrades has been finalized and closed [#19307](https://github.com/ethereum-optimism/op-geth/issues/19307).
*   **Transaction Ancestry:** A new PR was opened to ensure that when a bitcoin attributes deposited transaction is identified, the system correctly verifies the presence of the transaction and all its ancestors [#787](https://github.com/ethereum-optimism/op-geth/pull/787).

## 🐛 Issues & Triage

### Closed Issues
*   **CI Stability:** Developers resolved a persistent crash in the `kona-host-client-offline-cannon` CI test. The fix involved correcting a target specification in the builder and refreshing the committed witness tar [#19895](https://github.com/ethereum-optimism/op-geth/issues/19895).

### New & Active Issues
*   **LightCL Genesis Boot:** A critical observation was made regarding `safe_l2`, `local_safe_l2`, and `finalized_l2` values appearing as zero on fresh-genesis boots. The root cause appears to be `L2BlockRef` checks that only compare block numbers, failing to distinguish between an "unset" state and the actual genesis block (Block 0). A fix involving full block identity checks is currently under discussion [#20295](https://github.com/ethereum-optimism/op-geth/issues/20295).
*   **Flaky Tests:** `TestReorgUnsafeHead` remains a known issue. Despite previous attempts to fix asynchronous updates of `UnsafeL2`, the test continues to fail under CI load, suggesting deeper edge cases in reorg logic [#20198](https://github.com/ethereum-optimism/op-geth/issues/20198).
*   **Dependency Conflicts:** Users reported a trait conflict in `op-alloy` due to outdated versions on crates.io. This has sparked community questions regarding the maintenance status of the `op-alloy` crate [#20281](https://github.com/ethereum-optimism/op-geth/issues/20281).
*   **Security:** A new Wiz scan overview was initiated for the `optimism` branch to maintain high security standards [#786](https://github.com/ethereum-optimism/op-geth/issues/786).

## 💬 Community & Collaboration
The week was characterized by deep technical troubleshooting between maintainers. Notable collaboration occurred between contributors like **karlfloersch** and **pauldowman**, particularly in diagnosing the nuances of genesis state handling and CI flakes. There is an active feedback loop regarding the `op-alloy` library, where community members are seeking clarification on release schedules to resolve breaking trait conflicts, highlighting the importance of timely upstream dependency management for the Superchain ecosystem.

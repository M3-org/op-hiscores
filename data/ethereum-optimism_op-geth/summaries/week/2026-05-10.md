# ethereum-optimism/op-geth Weekly Report (May 10 - 16, 2026)

## 🚀 Highlights
This week, development focused heavily on stabilizing the testing infrastructure and refining the technical roadmap for Interop Proofs. Significant progress was made in diagnosing flaky withdrawal tests, leading to a draft fix that addresses timing discrepancies between L1 head timestamps and dispute game creation. Additionally, the team established a clear "Definition of Done" for the Interop Proofs Devnet, ensuring alignment across the Superdispute game, flashblocks, and conductor re-orgs. Refactoring efforts also began on the Engine API to improve error handling consistency.

## 🛠️ Key Developments

### Engine API & Protocol Refinement
Work began on improving the robustness of the Engine API and message validation logic to support more reliable cross-chain interactions.
*   **Error Handling Refactor:** A new pull request, [#790](https://github.com/ethereum-optimism/op-geth/pull/790), was initiated to refactor Engine API errors, aiming for better error categorization and response consistency.
*   **Unsafe Head Validation:** Discussions continued regarding the validation of executing messages at the unsafe head ([#20553](https://github.com/ethereum-optimism/op-geth/issues/20553)). A new implementation strategy was proposed in [#20650](https://github.com/ethereum-optimism/optimism/pull/20650), which includes updating `proxyd` to utilize interop filters for "cross-unsafe" queries and making failsafes optional to support re-orgs.

### Interop Proofs Devnet Roadmap
The team formalized the requirements for the Interop Proofs Devnet ([#20489](https://github.com/ethereum-optimism/op-geth/issues/20489)). The project's "Definition of Done" now explicitly requires:
*   A successful Superdispute game and functional withdrawals.
*   Integration of flashblocks with interoperability features.
*   Validation of conductor re-orgs and final approval from the Proofs Team.

## 🐛 Issues & Triage

### New & Active Issues
*   **Flaky Withdrawal Tests:** The `TestWithdrawal_Cannon` ([#19963](https://github.com/ethereum-optimism/op-geth/issues/19963)) remains a high-priority active issue. Investigation revealed that the `OptimismPortal_InvalidProofTimestamp()` error stems from `estimateGas` being evaluated against an L1 head that is older than the dispute game's creation time. 
*   **Proposed Fix:** A draft PR ([#20677](https://github.com/ethereum-optimism/optimism/pull/20677)) was created to ensure the system waits for `l1.head.Time() > game.createdAt()` before retrying prove transactions, which should eliminate transient precondition failures.
*   **Supernode Investigation:** An investigation into the `op-supernode` function `superroot_atTimestamp` was conducted and subsequently closed as the reported behavior was determined not to be a bug.

## 💬 Community & Collaboration
Collaboration this week was characterized by deep technical synchronization between the Proofs and Protocol teams. The discussion surrounding the Interop Proofs Devnet ([#20489](https://github.com/ethereum-optimism/op-geth/issues/20489)) demonstrates a high degree of coordination on cross-functional requirements like flashblocks and conductor stability. Furthermore, the rapid transition from identifying a flaky test failure mode to a draft fix in the broader `optimism` repository ([#20677](https://github.com/ethereum-optimism/optimism/pull/20677)) highlights an efficient feedback loop between testing and protocol development.

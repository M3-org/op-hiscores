# ethereum-optimism/op-geth Weekly Report (May 24 - 30, 2026)

## 🚀 Highlights
This week, the `op-geth` team focused on enhancing infrastructure efficiency and addressing complex synchronization issues within the Superchain stack. A significant milestone was the optimization of the Docker runtime environment, transitioning to a leaner base image to reduce the project's footprint. Development also prioritized upstream alignment with the opening of a merge for `v1.17.3`. However, the week was marked by persistent challenges regarding `op-reth` Engine API stability, specifically involving nondeterministic crashes and stalls that are currently being investigated in coordination with the Reth core team.

## 🛠️ Key Developments

### Infrastructure & Image Optimization
Efforts were made to streamline the deployment and runtime efficiency of the `op-geth` client.
*   **Docker Runtime Refactor:** The project successfully migrated its Docker runtime base image from `alpine:3.22` to `chainguard/static:latest`. This change results in a significantly more compact and secure runtime environment ([#794](https://github.com/ethereum-optimism/op-geth/pull/794)).

### Upstream Integration
Maintaining parity with the core Geth codebase remains a priority for the protocol's stability.
*   **Geth Version Merge:** A new pull request was initiated to merge `v1.17.3` into the `op-geth` codebase, ensuring the latest upstream improvements and security patches are integrated ([#795](https://github.com/ethereum-optimism/op-geth/pull/795)).

## 🐛 Issues & Triage

### New & Active Issues
The team is currently navigating several high-priority technical hurdles involving both build determinism and cross-client compatibility.

*   **Engine API & op-reth Stability:** A critical regression was identified in the `TestUnsafeChainNotStalling_CLSync` test family. Investigations suggest an `op-reth` Engine API stall rather than a test budget issue, with RPC calls timing out during block verification ([#21041](https://github.com/ethereum-optimism/op-geth/issues/21041)). Additionally, a SIGBUS crash related to `File::set_len(ftruncate)` during deep rewinds in Reth remains open, pending feedback from Reth maintainers ([#20934](https://github.com/ethereum-optimism/op-geth/issues/20934)).
*   **Build Determinism:** A bug was reported in `generate-semver-lock` where the output becomes nondeterministic when multiple Forge artifacts share a semver key but use different optimizer settings ([#21032](https://github.com/ethereum-optimism/op-geth/issues/21032)).
*   **L2 Contracts Manager (L2CM):** Work remains pending on creating a single source of truth for predeploys to increase upgrade safety ([#19260](https://github.com/ethereum-optimism/op-geth/issues/19260)). To prevent silent drift between feature flags and CI, the team decided to implement strict documentation requirements within `DevFeatures.sol` and `devFeatures.go` ([#20340](https://github.com/ethereum-optimism/op-geth/issues/20340)).

## 💬 Community & Collaboration
Collaboration this week was characterized by deep adversarial reviews and cross-project troubleshooting. The investigation into the `op-reth` Engine API stalls ([#21041](https://github.com/ethereum-optimism/op-geth/issues/21041)) demonstrates active coordination between L2 client developers to isolate bugs in the synchronization layer. Furthermore, the team highlighted a security concern for the broader contributor community regarding the use of AI tools for contract debugging, warning against potential data exfiltration of proprietary rollup configurations and bridge parameters. There is also ongoing pragmatism regarding upstream workarounds; the team has opted to maintain a local workaround for a Reth race condition in `RewindToTimestamp` after the upstream PR was closed as stale ([#19772](https://github.com/ethereum-optimism/op-geth/issues/19772)).

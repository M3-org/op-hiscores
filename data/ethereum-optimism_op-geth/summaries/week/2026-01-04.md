# ethereum-optimism/op-geth Weekly Report (Jan 4 - 10, 2026)

## 🚀 Highlights
This week's efforts focused on expanding the Superchain ecosystem and hardening the protocol. Development was initiated to integrate the new Karst L2 chain and enable its Osaka upgrade, signaling active growth. Concurrently, significant discussions addressed the state of ZK game integration, inconsistencies in the `optimism_syncStatus` RPC endpoint, and the future requirements for supernode functionality. These conversations, alongside improvements to CI and testing, underscore a dual focus on building new features while ensuring the stability and correctness of the existing infrastructure.

## 🛠️ Key Developments
Work this week centered on preparing for new chains, enhancing test environments, and refining protocol parameters.

- **L2 Chain Expansion & Upgrades:** Preparations began for onboarding new chains to the Superchain. Work was started to add the Karst L2 chain ([#744](https://github.com/ethereum-optimism/op-geth/pull/744)) and subsequently enable the Osaka upgrade for it ([#745](https://github.com/ethereum-optimism/op-geth/pull/745)).

- **Testing & CI Enhancements:** The testing and integration pipeline received several improvements. A new CI check was added to validate code generation ([#741](https://github.com/ethereum-optimism/op-geth/pull/741)). To ensure more predictable test environments, a new test was introduced to normalize the `OptimismTestConfig` by setting `JovianTime` to zero ([#742](https://github.com/ethereum-optimism/op-geth/pull/742)).

- **Protocol Refinements:** A pull request was opened to refine EIP-1559 consensus parameters by requiring a non-zero elasticity, aiming for greater network stability ([#743](https://github.com/ethereum-optimism/op-geth/pull/743)).

## 🐛 Issues & Triage
Discussions this week clarified the status of future features, addressed inconsistencies in core components, and triaged community reports.

- **Closed Issues:** An issue regarding OP Stack compatibility with minimal contracts was resolved ([#18709](https://github.com/ethereum-optimism/op-geth/issues/18709)). The resolution clarified that smart contracts generally work as expected and provided a link to documentation on differences from L1 Ethereum.

- **New & Active Issues:**
    - **Supernode & RPC Inconsistencies:** A significant portion of discussion revolved around the `optimism_syncStatus` RPC endpoint, which incorrectly reports the latest L1 head instead of the derivation cursor ([#18673](https://github.com/ethereum-optimism/op-geth/issues/18673)). Relatedly, several issues concerning supernode functionality ([#18651](https://github.comcom/ethereum-optimism/op-geth/issues/18651), [#18667](https://github.com/ethereum-optimism/op-geth/issues/18667), [#18669](https://github.com/ethereum-optimism/op-geth/issues/18669)) were identified as dependent on future interop support, highlighting a key area for upcoming development.
    - **ZK Game Integration:** In response to an inquiry ([#18692](https://github.com/ethereum-optimism/op-geth/issues/18692)), the team clarified that `OptimisticZkGame.sol` is not yet production-ready and that work is ongoing to integrate `op-succinct` contracts into the standard OP Stack.
    - **Vulnerability Management:** A critical vulnerability report ([#18703](https://github.com/ethereum-optimism/op-geth/issues/18703)) was addressed, with the reporter directed to the ImmuneFi escalation process, demonstrating a clear procedure for security concerns.

## 💬 Community & Collaboration
The week saw active engagement from both core maintainers and the wider community, with several contributors expressing interest in taking on new work.

- Team members like `ajsutton`, `op-will`, and `pauldowman` were active in providing detailed clarifications on complex topics such as ZK integration, RPC behavior, and supernode dependencies.
- There was notable interest from the community to contribute, with `DeborahOlaboye` volunteering for issues related to Pectra config fields ([#14816](https://github.com/ethereum-optimism/op-geth/issues/14816)) and flaky acceptance tests ([#16972](https://github.com/ethereum-optimism/op-geth/issues/16972)), and `crStiv` inquiring about adding Kona support to acceptance tests ([#18675](https://github.com/ethereum-optimism/op-geth/issues/18675)).

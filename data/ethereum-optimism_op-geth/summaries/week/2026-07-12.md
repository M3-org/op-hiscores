# ethereum-optimism/op-geth Weekly Report (Jul 12 - 18, 2026)

## 🚀 Highlights
This week, development focused on refining block header structures and advancing the integration of dispute game mechanics within the OP Stack. A significant technical update was introduced to include balances in block header and hash calculations, signaling a shift in how state is represented at the protocol level. Meanwhile, the team engaged in critical architectural discussions regarding the `op-revm` release cadence and the simplification of the `op-challenger` dispute game handling to ensure better alignment with downstream tools like Hardhat 3.

## 🛠️ Key Developments

### Protocol & State Representation
Work has begun on modifying the core block structure to enhance data availability and verification within the execution engine.
*   **Block Header Modifications:** A new pull request was opened to add balance information directly to the block header and hash calculation ([#804](https://github.com/ethereum-optimism/op-geth/pull/804)). This change impacts how block hashes are derived and may have implications for state transition validation.

## 🐛 Issues & Triage

### New & Active Issues
The week's activity was dominated by discussions on dependency management and the refinement of the Superchain's dispute logic.

*   **`op-revm` Support and Release Strategy:** There is ongoing pressure to synchronize `op-revm` crate releases with the broader ecosystem. Specifically, contributors are seeking updates to support "Glamsterdam" in Hardhat 3. The current strategy involves syncing updates with `reth` dependency bumps, but there is an active call for clearer changelogs and a more predictable release cadence ([#21069](https://github.com/ethereum-optimism/op-geth/issues/21069)).
*   **Dispute Game Refinement:** Significant attention is being paid to the `SuperPermissionedDisputeGame`. Currently, a lack of a `closeGame()` method in this specific game type prevents the `AnchorStateRegistry` from advancing after finality.
    *   Proposals include adding `closeGame()` to the generic `IDisputeGame` interface to standardize behavior ([#21708](https://github.com/ethereum-optimism/op-geth/issues/21708)).
    *   This is part of a broader effort to simplify `op-challenger` logic once the transition to these new game types is complete ([#21678](https://github.com/ethereum-optimism/op-geth/issues/21678)).

# ethereum-optimism/op-geth Weekly Report (Mar 22 - 28, 2026)

## 🚀 Highlights
This week, development focused heavily on hardening the L2 contract upgrade process and resolving stability issues within the test suite. Significant progress was made in streamlining the L2CM (L2 Contract Management) workflow through deterministic bundle generation and enhanced feature flag support. While the team successfully mitigated several flaky tests impacting the CI/CD pipeline, a new regression regarding `StorageKeys` serialization was identified in the latest release. Ongoing architectural discussions also highlighted a need for a more centralized "source of truth" for upgrade implementations to prevent structural gaps in the deployment pipeline.

## 🛠️ Key Developments
The technical focus this week centered on the infrastructure required for secure and predictable network upgrades.

### L2CM Upgrade Enhancements
The team completed a series of improvements to the L2 Contract Management system to ensure deterministic and repeatable upgrades across the Superchain.
*   **Deterministic Bundling:** Implemented a Solidity script for creating deterministic JSON NUT bundles [#18834](https://github.com/ethereum-optimism/op-geth/issues/18834).
*   **Tooling & Automation:** Added `just` commands to streamline the generation of NUT bundles [#18840](https://github.com/ethereum-optimism/op-geth/issues/18840) and the execution of L2 upgrade fork tests [#18841](https://github.com/ethereum-optimism/op-geth/issues/18841).
*   **Feature Management:** Introduced support for dev feature flags within the upgrade framework [#18838](https://github.com/ethereum-optimism/op-geth/issues/18838).

### Protocol & Upgrade Safety
Refinements to the upgrade utility scripts and gas logic were addressed to support the removal of legacy transactions.
*   **Karst Removal:** Discussions finalized the necessary updates for `UpgradeUtils.getTransactionCount()` and the `GasLimits` struct to facilitate the removal of Karst-specific upgrade transactions [#19369](https://github.com/ethereum-optimism/op-geth/issues/19369).
*   **Withdrawal Logic:** The team reviewed the transition to using `rootClaimByChainId` for proving withdrawals based on specific game types [#18517](https://github.com/ethereum-optimism/op-geth/issues/18517).

## 🐛 Issues & Triage

### Closed Issues
*   **Flaky Test Mitigation:** The `TestCLELDivergence` issue [#19681](https://github.com/ethereum-optimism/op-geth/issues/19681) was closed following the implementation of a mitigation strategy, though it remains under observation.
*   **Upgrade Workflow:** Several issues related to the L2CM pipeline (as noted in Key Developments) were successfully resolved, marking a milestone in upgrade tooling maturity.

### New & Active Issues
*   **StorageKeys Regression:** A breaking change was reported in `v1.101701.0` where `StorageKeys` returns `null` instead of an empty array `[]` [#780](https://github.com/ethereum-optimism/op-geth/issues/780). This was traced to the use of `SortedFunc` in `access_list_tracer.go`.
*   **Fault Proof Stability:** Work continues on resolving `TestPreinteropFaultProofs_TraceExtensionActivation` [#19760](https://github.com/ethereum-optimism/op-geth/issues/19760). The root cause was identified as a nonce race condition during `migrateSuperRoots`, with a fix currently in progress via a related PR in the optimism monorepo.
*   **Mempool Behavior:** Investigation is underway regarding how interop transactions are handled in the transaction pool during a chain reorg, specifically whether they are explicitly dropped or re-evaluated [#19351](https://github.com/ethereum-optimism/op-geth/issues/19351).
*   **Pipeline Gaps:** A critical discussion emerged regarding the lack of a centralized source of truth for predeploy implementations [#19260](https://github.com/ethereum-optimism/op-geth/issues/19260). This gap led to the initial omission of `L2DevFeatureFlags` from NUT bundles and highlighted a potential failure point in the `ConditionalDeployer`.

## 💬 Community & Collaboration
Collaboration this week was characterized by deep technical audits of the upgrade pipeline. Maintainers engaged in significant dialogue regarding the "structural pipeline gap" in upgrade safety, demonstrating a proactive approach to protocol security. There was also cross-repository coordination, as evidenced by the fix for flaky fault proof tests originating in the main `optimism` repository to resolve issues appearing in `op-geth`. The rapid response to the `StorageKeys` breaking change indicates a high level of alertness toward maintaining API compatibility for downstream users.

# ethereum-optimism/op-geth Weekly Report (Jun 14 - 20, 2026)

## 🚀 Highlights
This week, the project reached a significant milestone with the formal renaming of the "Interop" hardfork to **Lagoon**, triggering a sweep of configuration updates across the OP Stack. Development efforts were heavily concentrated on the `opgeth-decoupling` initiative, focusing on how the L2 client handles synthetic transactions and preparing for upstream compatibility with go-ethereum. Additionally, maintainers executed a major repository cleanup, closing numerous stale issues to streamline the project's focus on core protocol security and the upcoming Lagoon transition.

## 🛠️ Key Developments

### Lagoon Hardfork Integration
The transition from "Interop" to "Lagoon" was formalized across the codebase. This involved renaming core parameters and ensuring JSON consistency for the hardfork's activation.
*   **Configuration Updates:** Renamed `InteropTime` to `LagoonTime` and `IsInterop` to `IsLagoon` within `params.ChainConfig`.
*   **Data Consistency:** Updated JSON tags from `interopTime` to `lagoonTime` in `core/genesis.go`, `params/config.go`, and `superchain/chain.go` [#803](https://github.com/ethereum-optimism/op-geth/pull/803).

### Protocol Decoupling & Transaction Handling
Significant architectural discussions and work progressed regarding the separation of Optimism-specific logic from the core execution engine.
*   **L2 Transaction Representation:** A new design resolution proposes partitioning L2 transaction accessors by class (e.g., `InfoAndUserTxs`, `InfoAndDeposits`) rather than using a generic wrapper. This ensures that upstream go-ethereum compatibility is maintained while handling L2-specific data.
*   **Lagoon Synthetic Transactions:** Developers are addressing the introduction of the `0x7D` post-execution transaction. Unlike previous versions where only the `0x7E` deposit was synthetic, Lagoon makes the `0x7D` transaction a canonical part of the L2 block, requiring updates to receipt indexing and routing logic.
*   **Transition Scaffolding:** Helpers like `IsDepositTx` are being treated as temporary "scaffolding" to be removed after the final cutover, with a long-term shift toward decoding raw bytes directly into `optypes.DepositTx` or `optypes.PostExecTx` structs.

## 🐛 Issues & Triage

### Closed Issues
The team conducted an extensive cleanup of the backlog, resolving or closing several categories of issues:
*   **Developer Tooling & UX:** Closed stale issues regarding Ledger detection, wallet support in justfiles, and environment variable configurations for signatures ([#457](https://github.com/ethereum-optimism/op-geth/issues/457), [#400](https://github.com/ethereum-optimism/op-geth/issues/400), [#372](https://github.com/ethereum-optimism/op-geth/issues/372)).
*   **Infrastructure & Testing:** Refined the testing suite by closing broad coverage checks in favor of more specific issue tracking for proof generation and upgrade tasks ([#351](https://github.com/ethereum-optimism/op-geth/issues/351), [#637](https://github.com/ethereum-optimism/op-geth/issues/637), [#698](https://github.com/ethereum-optimism/op-geth/issues/698)).
*   **Bug Fixes:** A critical SIGBUS crash in `op-reth` during deep FCU rewinds was resolved via an upstream fix ([#20934](https://github.com/ethereum-optimism/op-geth/issues/20934)).

### New & Active Issues
*   **Integration Test Migration:** Active discussions ([#20265](https://github.com/ethereum-optimism/op-geth/issues/20265), [#20264](https://github.com/ethereum-optimism/op-geth/issues/20264)) highlight a potential blocker: tests that correlate transactions and receipts by index will break under the new `InfoAndUserTxs` model due to the exclusion of synthetic transactions.
*   **ZK Monitoring:** Work on monitoring ZK games ([#18323](https://github.com/ethereum-optimism/op-geth/issues/18323)) was consolidated, noting that significant refactoring is required to separate ZK-specific properties from generic dispute monitoring.

## 💬 Community & Collaboration
The week was characterized by high-level technical coordination regarding the `opgeth-decoupling` strategy. Discussions across issues [#20262](https://github.com/ethereum-optimism/op-geth/issues/20262) through [#20265](https://github.com/ethereum-optimism/op-geth/issues/20265) show deep collaboration between maintainers to define the "durable shape" of the OP Stack's interaction with go-ethereum. The focus remains on creating a sustainable, upstream-friendly architecture while managing the complexities of the Lagoon hardfork's new transaction types.

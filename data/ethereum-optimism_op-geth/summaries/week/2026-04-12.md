# ethereum-optimism/op-geth Weekly Report (Apr 12 - 18, 2026)

## 🚀 Highlights
This week, development activity focused on refining infrastructure workflows and evaluating architectural proposals for sequencer redundancy. While no new features or code refactors were merged into the codebase, the team successfully triaged workflow migration issues and engaged in critical design discussions regarding transaction forwarding. The primary theme of the week was maintaining a lean repository structure and leveraging existing infrastructure tools over adding internal complexity to the client.

## 🛠️ Key Developments
There were no new technical developments, features, or bug fixes completed during this period. The focus remained on repository maintenance and architectural planning.

## 🐛 Issues & Triage
The week's activity centered on resolving infrastructure questions and debating the implementation of high-availability features for node operators.

### Closed Issues
*   **Docker Build Workflow Migration:** The team evaluated a proposal to migrate Docker build workflows to an `images.json` configuration ([#784](https://github.com/ethereum-optimism/op-geth/issues/784)). The issue was closed as "not applicable" because `op-geth` functions as a single-image repository, and the proposed change did not align with the current repository structure.

### Active Issues
*   **Support for Multiple Sequencer RPC Endpoints:** Significant discussion continued regarding [#763](https://github.com/ethereum-optimism/op-geth/issues/763), which proposes supporting multiple sequencer RPC endpoints for transaction forwarding. While the original goal was to provide client-side failover as a defense-in-depth measure against regional or CDN failures, current consensus is leaning toward recommending generic proxy solutions (such as HAProxy or Nginx). This approach favors using established infrastructure tools for redundancy rather than introducing complex failover logic directly into the `op-geth` client.

## 💬 Community & Collaboration
Collaboration this week was characterized by technical architectural debate. The discussion surrounding sequencer RPC endpoints ([#763](https://github.com/ethereum-optimism/op-geth/issues/763)) highlights an active effort between contributors to balance the desire for protocol-level resilience with the need to keep the client codebase maintainable. The decision-making process emphasizes a "separation of concerns," encouraging operators to use specialized networking tools for load balancing and failover rather than relying on bespoke client-side implementations.

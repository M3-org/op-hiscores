# ethereum-optimism/op-geth Weekly Report (Feb 22 - 28, 2026)

## 🚀 Highlights
This week, development focused on hardening the stability and security of the OP Stack through critical RPC performance triage and architectural refinements for the L2 Contracts Manager (L2CM). A significant vulnerability regarding `eth_getLogs` memory exhaustion was identified and addressed by aligning with upstream `go-ethereum` fixes. Meanwhile, the community engaged in deep technical discussions regarding state scheme fallbacks for full nodes and the refinement of Superroot SLAs within the `op-supernode` framework. The overall theme was one of maintenance and rigorous failure mode analysis to ensure the robustness of the Superchain ecosystem.

## 🛠️ Key Developments
While no new code was merged into the main branch this week, significant progress was made in the design and verification phases of several protocol components:

### Protocol Security & RPC Stability
Efforts were concentrated on identifying a memory exhaustion vulnerability in the `eth_getLogs` RPC method. Similar to upstream `go-ethereum`, wide block ranges could trigger unbounded state scans, leading to Out-of-Memory (OOM) errors on RPC nodes. The team determined that this will be resolved by pulling in upstream fixes rather than implementing OP-specific changes, ensuring long-term maintainability ([#768](https://github.com/ethereum-optimism/op-geth/issues/768)).

### L2 Contracts Manager (L2CM) & Upgrade Infrastructure
Extensive Failure Mode Analysis (FMA) was conducted for the L2CM. Key focus areas included:
*   **Upgrade Atomicity:** Ensuring error-swallowing patterns are avoided to prevent partial or failed upgrades.
*   **Storage Integrity:** Strategies to prevent `L2ProxyAdmin` storage corruption by avoiding unnecessary storage variables.
*   **Testing Frameworks:** Proposals for CI jobs to verify deterministic JSON NUT bundles and new acceptance tests to verify the existence of deployment proxies across all target L2 chains before fork activation ([#18830](https://github.com/ethereum-optimism/op-geth/issues/18830), [#18834](https://github.com/ethereum-optimism/op-geth/issues/18834), [#18870](https://github.com/ethereum-optimism/op-geth/issues/18870)).

## 🐛 Issues & Triage
### Closed Issues
*   **RPC Performance:** The critical vulnerability regarding `eth_getLogs` memory spikes was closed after being triaged and linked to upstream Geth fixes ([#768](https://github.com/ethereum-optimism/op-geth/issues/768), [#769](https://github.com/ethereum-optimism/op-geth/issues/769)).
*   **Devnet Maintenance:** A bug report regarding invalid proposals on `sepolia-devnet-0` was closed as the environment is deprecated ([#19301](https://github.com/ethereum-optimism/op-geth/issues/19301)).

### New & Active Issues
*   **State Scheme Fallback:** A new issue was raised concerning the `makeEnv` historical state fallback being unreachable on full nodes using path-based state schemes. A community-proposed fix is currently under evaluation ([#767](https://github.com/ethereum-optimism/op-geth/issues/767)).
*   **Supernode & Batcher Logic:** Discussions continue on `op-batcher` failing to account for post-Holocene ordering in concurrent mode ([#18507](https://github.com/ethereum-optimism/op-geth/issues/18507)). Additionally, the `op-supernode` Superroot SLA is being refined to handle missing "Optimistic Roots" by either excluding them or using empty values to maintain system stability ([#19180](https://github.com/ethereum-optimism/op-geth/issues/19180)).
*   **Reorg Handling:** New inquiries surfaced regarding the pruning of the Denylist during L1 reorgs and potential duplication of efforts in this area ([#19289](https://github.com/ethereum-optimism/op-geth/issues/19289)).

## 💬 Community & Collaboration
The week was characterized by high-quality technical feedback and cross-repository coordination. Notable collaboration occurred between the `op-geth` and `optimism` repositories regarding `op-batcher` logic. The community also showed proactive engagement in the L2CM upgrade path, with contributors providing detailed feedback on failure modes and testing infrastructure. The offer from a contributor to provide a PR for the path-based state scheme issue ([#767](https://github.com/ethereum-optimism/op-geth/issues/767)) highlights a healthy, self-starting developer ecosystem.

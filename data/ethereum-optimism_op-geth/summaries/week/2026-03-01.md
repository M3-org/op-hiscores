# ethereum-optimism/op-geth Weekly Report (Mar 1 - 7, 2026)

## 🚀 Highlights
This week, development focused on hardening the transaction pool and refining the testing infrastructure to ensure protocol stability during chain reorganizations. A significant update was implemented to handle interop transactions more robustly, preventing invalid cross-chain states. While the team addressed several discrepancies within the Kona protocol, the project also signaled a strategic shift by closing certain feature requests, such as Flashblocks support, due to the planned deprecation of `op-geth`.

## 🛠️ Key Developments

### Transaction Pool & Reorg Handling
The team implemented critical changes to how the transaction pool manages interoperability.
*   **Interop Transaction Filtering:** To prevent issues arising from invalid cross-chain states, the `txpool` now filters and removes interop transactions when discarded blocks are walked during a reorg ([#772](https://github.com/ethereum-optimism/op-geth/pull/772)). This ensures that transactions depending on invalidated cross-chain data do not persist in the pool.

### Testing Infrastructure & Refactoring
Efforts to improve code maintainability and test reliability continued within the core modules.
*   **Downloader Test Isolation:** The `eth/downloader` module saw a refactor of `receiptreference_test.go`. By transitioning to sub-tests and passing local `testing.T` instances rather than relying on a global context, the team improved test isolation and reduced potential flakiness ([#771](https://github.com/ethereum-optimism/op-geth/pull/771)).

## 🐛 Issues & Triage

### Closed Issues
*   **Deprecation Adjustments:** The request for Flashblocks support ([#756](https://github.com/ethereum-optimism/op-geth/issues/756)) was closed, as further feature development is being curtailed in light of `op-geth` deprecation.
*   **Duplicate Cleanup:** Several issues regarding L2 contract upgrades ([#18843](https://github.com/ethereum-optimism/op-geth/issues/18843)) and VM runner support for the supernode API ([#19008](https://github.com/ethereum-optimism/op-geth/issues/19008)) were closed as they are being tracked in the main `optimism` repository.

### New & Active Issues
*   **Glamsterdam Gas Pricing:** A new investigation was launched into how the Glamsterdam upgrade's gas pricing affects precompile acceleration ([#19375](https://github.com/ethereum-optimism/op-geth/issues/19375)). There are concerns regarding increased costs for large preimages and potential impacts on proofs.
*   **Kona Protocol Discrepancies:** Multiple issues were identified regarding the Kona stack, including disagreements between Kona and `op-node` on brotli channels ([#19333](https://github.com/ethereum-optimism/op-geth/issues/19333)), panics in the `kona-protocol` batch decoder ([#19334](https://github.com/ethereum-optimism/op-geth/issues/19334)), and frame parsing mismatches ([#19335](https://github.com/ethereum-optimism/op-geth/issues/19335)).
*   **Access Control:** Discussions are ongoing regarding adding `ProxyAdminOwnedBase` access control to predeploy initialization functions ([#19313](https://github.com/ethereum-optimism/op-geth/issues/19313)).

## 💬 Community & Collaboration
The week saw active community engagement, particularly surrounding the Kona protocol. Multiple developers volunteered to tackle bugs related to brotli channel divergence and batch decoder panics. There was also a collaborative effort to clean up orphaned code in `kona-derive` ([#19340](https://github.com/ethereum-optimism/op-geth/issues/19340)), where community members coordinated to ensure that existing pull requests were prioritized over redundant new fixes. This indicates a healthy, proactive contributor base focused on protocol alignment and code quality.

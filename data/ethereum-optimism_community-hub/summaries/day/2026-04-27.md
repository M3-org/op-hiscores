### LightCL Genesis State Observation
The observation regarding zero `safe_l2`/`local_safe_l2`/`finalized_l2` on fresh-genesis boot for LightCL [#20295](https://github.com/ethereum-optimism/community-hub/issues/20295) received significant attention. karlfloersch identified a likely root cause: genesis `L2BlockRef`s are being treated as unset state due to comparisons relying solely on `Number`. This prevents valid upstream genesis refs from passing "is this ahead?" checks when the current local value is unset and the upstream value is the real genesis block. A related sync-status case was also noted. A recommended fix involves distinguishing "unset" from "genesis" using a full zero-value check or block identity, rather than just block number, and accepting updates when the current ref is `eth.L2BlockRef{}` and the incoming ref is non-zero, or when the incoming number is greater. A regression test for `--l2.follow.source` fresh-genesis boot was also suggested. karlfloersch also inquired if a related PR [#20352](https://github.com/ethereum-optimism/optimism/pull/20352) might have addressed this issue.

## ✅ Completed Work

### Core Infrastructure & Interoperability Enhancements
*   Upgraded `libp2p` to v0.49.0 and `golang.org/x/mod` to v0.40.0 to address security vulnerabilities across multiple services. ([ethereum-optimism/infra#724](https://github.com/ethereum-optimism/infra/pull/724), [ethereum-optimism/infra#723](https://github.com/ethereum-optimism/infra/pull/723))
*   The `kona-safedb` crate was introduced, providing a 1-to-1 Rust port of `op-node`'s `safedb` package, crucial for fault proofs and interop. ([ethereum-optimism/optimism#21522](https://github.com/ethereum-optimism/optimism/pull/21522))
*   The vestigial cross-unsafe chain-head concept was removed from Go-side components (`op-node`, `op-service`, `op-devstack`), streamlining the codebase. ([ethereum-optimism/optimism#22555](https://github.com/ethereum-optimism/optimism/pull/22555))
*   `kona-node` now consistently resets the engine upon a pipeline reset, ensuring proper state synchronization after L1 reorgs. ([ethereum-optimism/optimism#22551](https://github.com/ethereum-optimism/optimism/pull/22551))
*   The `op-alt-da` component now allows for a configurable input-size limit, providing more control over Keccak derivation and batcher validation. ([ethereum-optimism/optimism#22496](https://github.com/ethereum-optimism/optimism/pull/22496))

### Developer Experience & Documentation Improvements
*   New guidelines were added to `AGENTS.md`, requiring developers to watch CI after pushing and run local review agents before opening a PR, aiming to improve code quality. ([ethereum-optimism/optimism#22574](https://github.com/ethereum-optimism/optimism/pull/22574), [ethereum-optimism/optimism#22572](https://github.com/ethereum-optimism/optimism/pull/22572))
*   The final security review report for Upgrade 20 (Cantina) was added to the documentation, enhancing transparency on protocol security. ([ethereum-optimism/optimism#22559](https://github.com/ethereum-optimism/optimism/pull/22559))
*   Release history pages for `op-reth` (v2.4.2) and `op-contracts` (v8.0.0-rc.3) were updated to reflect the latest versions. ([ethereum-optimism/optimism#22564](https://github.com/ethereum-optimism/optimism/pull/22564))

### Fault Proofs & Dispute Game Updates
*   The `op-challenger move --attack` command now supports Zero-Knowledge (ZK) challenges, detecting the on-chain game type and calling appropriate ZK game bindings. ([ethereum-optimism/optimism#22575](https://github.com/ethereum-optimism/optimism/pull/22575))
*   The `OPContractsManagerMigrator.migrate()` function now validates dispute game configurations, preventing the registration of invalid games. ([ethereum-optimism/optimism#22441](https://github.com/ethereum-optimism/optimism/pull/22441))
*   The `kona-sp1-proposer` now avoids using `CpuProver` in network mode, replacing it with `LightProver` when setting SP1 keys for network proofs. ([ethereum-optimism/optimism#22588](https://github.com/ethereum-optimism/optimism/pull/22588))
*   The `kona-sp1` proposer now preserves the selected L1 header hash in `L1BlockRef` and uses it for all block-pinned proposer sync reads, addressing previous data anchoring issues. ([ethereum-optimism/optimism#22549](https://github.com/ethereum-optimism/optimism/pull/22549))

On Mar 5, 2026, Optimism's development focused heavily on `op-reth` interoperability and memory leak investigations, alongside significant contract bug fixes and security enhancements in the `optimism` repository. Documentation received updates across several repositories, and infrastructure improvements were made to `op-conductor-mon` for enhanced security.

## 🚨 Needs Attention
- **Urgent Discussions**: The `op-reth` memory leak issue ([#19212](https://github.com/ethereum-optimism/superchain-ops/issues/19212), [#19212](https://github.com/ethereum-optimism/op-geth/issues/19212), [#19212](https://github.com/ethereum-optimism/specs/issues/19212), [#19212](https://github.com/ethereum-optimism/docs/issues/19212), [#19212](https://github.com/ethereum-optimism/infra/issues/19212), [#19212](https://github.com/ethereum-optimism/optimism/issues/19212)) requires confirmation on whether the problem persists in `v1.11.0` after an upgrade, as it has not recurred on `v1.10.2` for some users but has been observed repeatedly on multiple nodes.
- **Urgent Discussions**: The new feature request for `op-reth` interop transaction pool filtering and reorg eviction ([#19411](https://github.com/ethereum-optimism/superchain-ops/issues/19411), [#19411](https://github.com/ethereum-optimism/op-geth/issues/19411), [#19411](https://github.com/ethereum-optimism/specs/issues/19411), [#19411](https://github.com/ethereum-optimism/docs/issues/19411), [#19411](https://github.com/ethereum-optimism/infra/issues/19411), [#19411](https://github.com/ethereum-optimism/optimism/issues/19411)) has an open question regarding the necessity of "Periodic re-validation."

## ✅ Completed Work
### Core Protocol Security & Stability
- Critical bug fixes were implemented in bedrock contracts, including enforcing `onlyDelegateCall` and preventing CREATE2 collisions ([#19272](https://github.com/ethereum-optimism/optimism/pull/19272)).
- A fix was introduced to make `OPContractsManagerUtils.upgrade()` forward-compatible with OpenZeppelin v5's `Initializable` storage layout ([#19286](https://github.com/ethereum-optimism/optimism/pull/19286)).
- `op-conductor-mon` received security enhancements through Go module dependency updates and hardened container images ([#563](https://github.com/ethereum-optimism/infra/pull/563), [#562](https://github.com/ethereum-optimism/infra/pull/562)).

### Documentation & Developer Experience
- The blob hint data specification in the fault-proof documentation was updated to reflect recent changes ([#890](https://github.com/ethereum-optimism/specs/pull/890)).
- Bridging tutorial content and structure were updated to introduce "Deposited" concepts ([#1980](https://github.com/ethereum-optimism/docs/pull/1980)).
- The oracles page was updated to include DIA, expanding data provider listings ([#1995](https://github.com/ethereum-optimism/docs/pull/1995)).
- Information regarding guardian risks within the OP Stack protocol documentation was updated ([#1993](https://github.com/ethereum-optimism/docs/pull/1993)).
- 25 unreferenced tutorial assets and scripts were removed, streamlining the `docs` repository ([#1994](https://github.com/ethereum-optimism/docs/pull/1994)).

### Testing & Monitoring Improvements
- Test coverage for the `L2ProxyAdmin` contract was expanded by reusing existing `ProxyAdmin` tests ([#19377](https://github.com/ethereum-optimism/optimism/pull/19377)).
- CI notifications for `contracts-bedrock` jobs were updated to include `@security-oncall` mentions on failure ([#19367](https://github.com/ethereum-optimism/optimism/pull/19367)).
- Metrics were added to `op-dispute-mon` to support multi-supernode functionality, tracking errors and disagreements ([#19105](https://github.com/ethereum-optimism/optimism/pull/19105)).

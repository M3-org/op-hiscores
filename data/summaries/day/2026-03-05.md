This daily digest for Mar 5, 2026, highlights significant progress in enhancing contract security and compatibility, improving testing infrastructure, and refining documentation across the Optimism ecosystem. Key efforts included critical bug fixes in `contracts-bedrock` addressing audit findings, updates to fault-proof documentation, and security hardening for `op-conductor-mon`. A recurring theme is the ongoing investigation into an `op-reth` database memory leak and the proposal for new interop transaction pool features to achieve feature parity with `op-geth`.

## 🚨 Needs Attention
- **Urgent Discussions**: The `op-reth` database memory leak ([#19212](https://github.com/ethereum-optimism/superchain-ops/issues/19212), [#19212](https://github.com/ethereum-optimism/op-geth/issues/19212), [#19212](https://github.com/ethereum-optimism/specs/issues/19212), [#19212](https://github.com/ethereum-optimism/docs/issues/19212), [#19212](https://github.com/ethereum-optimism/infra/issues/19212), [#19212](https://github.com/ethereum-optimism/optimism/issues/19212)) requires further investigation, specifically an upgrade to `v1.11.0` to determine if the issue persists.
- **Urgent Discussions**: The necessity of "Periodic re-validation" for the proposed `op-reth` interop transaction pool filter ([#19411](https://github.com/ethereum-optimism/infra/issues/19411)) needs clarification.

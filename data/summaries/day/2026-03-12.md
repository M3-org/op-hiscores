On Mar 12, 2026, significant progress was made on the Rust-based derivation pipeline with new testing DSLs and critical bug fixes, alongside a major cleanup of deprecated development tools. However, a critical `op-node` error causing permanent crash loops due to deposits-only attribute failures emerged as a major concern, compounded by ongoing issues with the `optimism` repository's excessive size hindering development.

## 🚨 Needs Attention
- **Urgent Discussion**: `op-node` Critical Error Event for Deposits-Only Attributes ([#19509](https://github.com/ethereum-optimism/infra/issues/19509)) - This critical error leads to permanent node crash loops, especially under SuperAuthority deny path conditions, and requires immediate attention and robust integration tests for proposed fixes.
- **Urgent Discussion**: Repository Size Bloat ([#19241](https://github.com/ethereum-optimism/infra/issues/19241)) - The `optimism` repository's 1.04 GB `.git` directory makes cloning a 2-hour process and hinders development; prioritization of this issue is questioned.
- **Pull Request to Review**: `optimism` PR [#19465](https://github.com/ethereum-optimism/optimism/pull/19465) - An alternative approach to fixing the `op-node` critical error is proposed and needs review.
- **Pull Request to Review**: `optimism` PR [#19466](https://github.com/ethereum-optimism/optimism/pull/19466) - Claude's attempt at writing tests for the `op-node` critical error is noted as too narrowly scoped and requires broader integration tests.

## ✅ Completed Work
### Derivation Pipeline Enhancements & Bug Fixes
- A new scenario-oriented DSL was added for derivation tests in Rust, improving readability and test focus ([#19496](https://github.com/ethereum-optimism/optimism/pull/19496)).
- Critical bug fixes were implemented in `BlobSource::load_blobs` to prevent silent over-fill issues ([#19364](https://github.com/ethereum-optimism/optimism/pull/19364)).
- A new Claude Code skill was added to automate Rust formatting fixes ([#19488](https://github.com/ethereum-optimism/optimism/pull/19488)).
- `#[ignore]` attributes were replaced with `nextest` binary filtering for integration tests ([#19489](https://github.com/ethereum-optimism/optimism/pull/19489)).
- The `proxyd` transaction validation service error was fixed by separating the context for the transaction validation middleware ([#567](https://github.com/ethereum-optimism/infra/pull/567)).

### Build System Modernization & Cleanup
- Build targets were migrated from `Makefile` to `justfile` for `op-e2e` ([#19475](https://github.com/ethereum-optimism/optimism/pull/19475)), `cannon` ([#19474](https://github.com/ethereum-optimism/optimism/pull/19474)), and `linter` ([#19473](https://github.com/ethereum-optimism/optimism/pull/19473)).
- The deprecated `devnet-sdk` and `kurtosis-devnet` were removed, with live pieces re-homed into `op-service`, `op-core`, and `op-devstack` ([#19506](https://github.com/ethereum-optimism/optimism/pull/19506)).

### `op-node` Derivation Error Handling Improvements
- Malformed span batch transaction data is now dropped as `NotEnoughData` ([#19502](https://github.com/ethereum-optimism/optimism/pull/19502)).
- Missing beacon endpoint errors are now classified as `CriticalError` after Ecotone activation ([#19501](https://github.com/ethereum-optimism/optimism/pull/19501)).
- Pre-Delta span batches and bad channel decompression are handled as `NotEnoughData` for immediate drops ([#19500](https://github.com/ethereum-optimism/optimism/pull/19500), [#19499](https://github.com/ethereum-optimism/optimism/pull/19499)).

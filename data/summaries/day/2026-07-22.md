Jul 22, 2026 - Daily Project Summary

Today, the Optimism project saw significant progress in enhancing the `op-deployer` tool and overhauling public documentation for the OP Stack, alongside the successful integration of the `bailiff` service into the monorepo. A major focus also remained on addressing several recurring flaky tests and advancing ZK execution support for `vm-runner`, with new occurrences of light-sequencer oscillation during recovery highlighting a critical correctness concern.

## 🚨 Needs Attention
- **Urgent Discussions**:
    - `ethereum-optimism/infra`: Discussion continues on [#18325](https://github.com/ethereum-optimism/infra/issues/18325) regarding ZK execution support for `vm-runner`, with benchmark results showing high memory usage but feasibility for continuous L2 head checks. Input is needed on how to proceed with the Rust dependency for actual ZK execution.
    - `ethereum-optimism/infra`: The recurrence of `TestSupernodeInteropChainLag` in [#19610](https://github.com/ethereum-optimism/infra/issues/19610) suggests further investigation is needed despite a previous fix.
    - `ethereum-optimism/infra`: A new occurrence of `TestNotTruncateDatabaseOnRestartWithExistingDatabase` in [#20649](https://github.com/ethereum-optimism/infra/issues/20649) points to a "pre-restart baseline-race" that needs to be addressed by re-landing a fix in PR [#21975](https://github.com/ethereum-optimism/optimism/pull/21975).
    - `ethereum-optimism/infra`: The `TestSupernodeInterop_SafeHeadProgression` flake in [#20851](https://github.com/ethereum-optimism/infra/issues/20851) recurred, indicating the need to re-evaluate the existing fix.
    - `ethereum-optimism/infra`: The light-sequencer oscillation during recovery, now upgraded to a correctness problem in [#21964](https://github.com/ethereum-optimism/infra/issues/21964), requires immediate attention as it can lead to incorrect safe/finalized block relabeling.
    - `ethereum-optimism/optimism`: A new issue [#21961](https://github.com/ethereum-optimism/optimism/issues/21961) highlights a potential divergence between Go and Rust implementations for post-exec transaction payload validation, which could lead to latent correctness problems.

## ✅ Completed Work
### OP Stack Development & Deployment Tooling
- **`op-deployer` Enhancements**: The `op-deployer` tool now allows prestates to be committed before chain deployment, verifies contracts by default on Etherscan/Blockscout, and removed deprecated commands, streamlining chain setup and verification. ([#21611](https://github.com/ethereum-optimism/optimism/pull/21611), [#21947](https://github.com/ethereum-optimism/optimism/pull/21947), [#21945](https://github.com/ethereum-optimism/optimism/pull/21945), [#21929](https://github.com/ethereum-optimism/optimism/pull/21929))
- **Bailiff Service Monorepo Integration**: The `bailiff` Go application has been successfully integrated into the monorepo, enabling monorepo-based building and publishing of its image. ([#672](https://github.com/ethereum-optimism/infra/pull/672))
- **Fee Vault Configuration**: New features were added to allow in-place updates of L2 fee-vault predeploy configurations via owner-gated setters, and Ink Mainnet's fee vault recipient was updated. ([#1504](https://github.com/ethereum-optimism/superchain-ops/pull/1504), [#1505](https://github.com/ethereum-optimism/superchain-ops/pull/1505))

- **Core Component Updates**: `op-core` received updates for OP transaction JSON codecs and consensus receipt encoding, and `op-alloy` was updated to include post-exec transactions in subblock payloads. ([#21907](https://github.com/ethereum-optimism/optimism/pull/21907), [#21894](https://github.com/ethereum-optimism/optimism/pull/21894), [#21950](https://github.com/ethereum-optimism/optimism/pull/21950), [#21957](https://github.com/ethereum-optimism/optimism/pull/21957))

([#1507](https://github.com/ethereum-optimism/superchain-ops/pull/1507), [#1506](https://github.com/ethereum-optimism/superchain-ops/pull/1506))

## ✅ Completed Work

### Kona Node Stability and Performance
*   Fixed a misleading guest warning in `super_range.rs` for the Kona SP1 proposer, ensuring accurate host-side dependency reporting ([#22592](https://github.com/ethereum-optimism/optimism/pull/22592)).
*   Improved Kona node's system configuration lookup by serving it from imported blocks, optimizing `SystemConfig` reconstruction during block building and derivation ([#22466](https://github.com/ethereum-optimism/optimism/pull/22466)).
*   Optimized beacon blob deserialization by directly allocating to final heap locations, improving memory efficiency ([#22517](https://github.com/ethereum-optimism/optimism/pull/22517)).
*   Addressed a critical crash loop in Kona engine by skipping unsafe-head staleness checks for seals atomic with their build, resolving issues during deep backlog re-derivation ([#22557](https://github.com/ethereum-optimism/optimism/pull/22557)).
*   Hardened online preimage fetching in `kona-host` by explicitly routing HTTP(S) RPCs through Alloy's Reqwest transport and loading platform-native certificate roots ([#22604](https://github.com/ethereum-optimism/optimism/pull/22604)).
*   Ensured Kona SP1 proposer defaults proof strategies to `auction` instead of `reserved` ([#22593](https://github.com/ethereum-optimism/optimism/pull/22593)).
*   Retained admitted proof request ownership in Kona SP1 to prevent orphaned SPN requests when concurrent range-proof chunks fail ([#22627](https://github.com/ethereum-optimism/optimism/pull/22627)).

### Interoperability and Documentation Enhancements
*   Refined interop message expiry checks to use subtraction, preventing potential `uint64` overflow issues that could lead to messages never expiring or incorrect wrapping behavior ([#22609](https://github.com/ethereum-optimism/optimism/pull/22609)).
*   Updated the Superchain registry pin for World Chain Karst activations and regenerated dependent Go and Rust artifacts ([#22624](https://github.com/ethereum-optimism/optimism/pull/22624)).

*   Updated release documentation for `op-node v1.19.5`, `kona-node v1.6.4`, and `op-batcher v1.16.13`, reflecting the newest GitHub releases ([#22614](https://github.com/ethereum-optimism/optimism/pull/22614)).
*   Required Holocene span batches to retain Delta's overlap checks before streaming singular batches, clarifying that only remaining full span-batch checks are deferred ([#928](https://github.com/ethereum-optimism/specs/pull/928)).

### Lokahi Multi-Chain Node Development
*   Implemented persistent state for the Lokahi interop node, including the verified store, per-chain log stores, and the invalidated-output archive ([#22603](https://github.com/ethereum-optimism/optimism/pull/22603)).
*   Landed the verification round loop for Lokahi, which observes chains, makes decisions, and applies them ([#22605](https://github.com/ethereum-optimism/optimism/pull/22605)).
*   Implemented `supernode_syncStatus` and `superroot_atTimestamp` RPCs for Lokahi, with careful consideration for differences from the Go `op-supernode` ([#22615](https://github.com/ethereum-optimism/optimism/pull/22615)).
*   Enabled sequencer mode for Lokahi, allowing per-chain sequencing with configurable depths and key management ([#22618](https://github.com/ethereum-optimism/optimism/pull/22618)).

*   Landed the N-chain service composition and config for Lokahi, enabling it to run N chains in one process ([#22599](https://github.com/ethereum-optimism/optimism/pull/22599)).
*   Implemented the cross-safe promotion lifecycle and finality for Lokahi, routing promotions through Kona's external promoter entry point ([#22610](https://github.com/ethereum-optimism/optimism/pull/22610)).

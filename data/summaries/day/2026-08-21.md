On Aug 21, 2026, the Optimism project made significant strides in enhancing the Kona node's stability and performance, particularly in handling system configurations and proof requests, alongside substantial progress on the `lokahi` multi-chain interop node. Key developments included optimizing beacon blob deserialization, fixing critical crash loops during deep catch-ups, and hardening online preimage fetching, while `lokahi` saw the implementation of its verification round loop, persistent stores, and sequencer mode, moving closer to N-chain functionality. Documentation was also updated with a new AI agent for deletion reviews, and routine Superchain registry maintenance was performed.

    - `ethereum-optimism/infra` [#22533](https://github.com/ethereum-optimism/infra/issues/22533): Two gaps remain for `lokahi`'s `sysgo` component: shared-supernode presets still turn `lokahi` away, and `lokahi` cannot resolve an unsafe block signer or sequencer P2P key.

## ✅ Completed Work

### Kona Node Stability and Performance
- Served system config lookups from imported blocks to reduce redundant reconstructions, improving node efficiency. [#22466](https://github.com/ethereum-optimism/optimism/pull/22466)
- Optimized beacon blob deserialization for better memory management. [#22517](https://github.com/ethereum-optimism/optimism/pull/22517)
- Fixed a critical crash loop during deep catch-ups by skipping unsafe-head staleness checks for atomic seals. [#22557](https://github.com/ethereum-optimism/optimism/pull/22557)
- Hardened online preimage fetching in `kona-host` for increased reliability. [#22604](https://github.com/ethereum-optimism/optimism/pull/22604)
- Resolved a critical issue causing the `kona-node` to crash loop during deep catch-ups. [#22342](https://github.com/ethereum-optimism/optimism/issues/22342)

### SP1 Prover Enhancements
- Fixed a misleading guest warning in `super_range.rs` for the SP1 prover. [#22592](https://github.com/ethereum-optimism/optimism/pull/22592)
- Ensured the proposer retains admitted proof request ownership to prevent orphaned SPN requests. [#22627](https://github.com/ethereum-optimism/optimism/pull/22627)
- Set default proof strategies for `kona-sp1-proposer` to `auction`. [#22593](https://github.com/ethereum-optimism/optimism/pull/22593)
- Closed an issue where concurrent range-proof failures could orphan submitted SPN requests. [#22621](https://github.com/ethereum-optimism/optimism/issues/22621)

### Lokahi Multi-Chain Interop Node Core Functionality
- Implemented the verification round loop, enabling the node to observe chains, make decisions, log them, and apply them, including handling cold starts and backfilling log stores. [#22605](https://github.com/ethereum-optimism/optimism/pull/22605)
- Integrated persistent stores for verified data, logs, and invalidated outputs for the interop actor. [#22603](https://github.com/ethereum-optimism/optimism/pull/22603)
- Enabled sequencer mode, allowing Lokahi to configure and run Kona's `SequencerActor` per chain. [#22618](https://github.com/ethereum-optimism/optimism/pull/22618)
- Landed the `lokahi` N-chain service composition and configuration, allowing `lokahi node --config <file>` to run N chains in one process. [#22599](https://github.com/ethereum-optimism/optimism/pull/22599)
- Implemented the `sysgo` component and the first slice of the admin/test RPC for Lokahi. [#22602](https://github.com/ethereum-optimism/optimism/pull/22602)
- Implemented cross-safe promotion lifecycle and finality, routing promotions through Kona's existing external promoter entry point. [#22610](https://github.com/ethereum-optimism/optimism/pull/22610)

### Documentation and Superchain Registry Updates
- Added a `deletion-reviewer` AI agent and its review guide, along with an opt-in `watch-reviews` skill for Claude. [#22577](https://github.com/ethereum-optimism/optimism/pull/22577), [#22580](https://github.com/ethereum-optimism/optimism/pull/22580)
- Clarified the message expiry check as a subtraction to prevent `uint64` overflows. [#22609](https://github.com/ethereum-optimism/optimism/pull/22609)
- Updated the Superchain registry pin for World Chain Karst activations. [#22624](https://github.com/ethereum-optimism/optimism/pull/22624)
- Updated release documentation for `op-node`, `kona-node`, and `op-batcher`. [#22614](https://github.com/ethereum-optimism/optimism/pull/22614)
- Removed an unused `op_contracts_manager_addr` field from the Sepolia devnet configuration. [#1304](https://github.com/ethereum-optimism/superchain-registry/pull/1304)
- Scheduled Karst Timestamps for World Chain in both mainnet and Sepolia configurations. [#1313](https://github.com/ethereum-optimism/superchain-registry/pull/1313)
- Performed an automated codegen update to `addresses.json`. [#1312](https://github.com/ethereum-optimism/superchain-registry/pull/1312)
- Refined Holocene span batches to require overlap checks before streaming singular batches. [#928](https://github.com/ethereum-optimism/specs/pull/928)
- Aligned interop message expiry boundary restatements with the normative invariant. [#932](https://github.com/ethereum-optimism/specs/pull/932)
- Resolved the issue regarding interop message-expiry boundary restatements being stricter than the normative invariant. [#931](https://github.com/ethereum-optimism/specs/issues/931)

### Devstack and Testing Improvements
- Abstracted `stack.SupernodeTestControl` in the devstack to be RPC-shaped for out-of-process implementation. [#22546](https://github.com/ethereum-optimism/infra/issues/22546), [#22547](https://github.com/ethereum-optimism/infra/issues/22547)

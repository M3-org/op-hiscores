Optimism's development today focused heavily on core protocol stability and efficiency, with significant progress in resolving sequencer starvation issues and improving CI test reliability. Documentation clarity was also a key area of improvement, alongside ongoing efforts to address flakiness in Supernode interop tests and refine the ZK dispute game.

## 🚨 Needs Attention
- **Urgent Discussion**: `op-supernode`'s cross-safe mechanism can wedge after an invalid-message replacement, particularly when a local-safe on one chain stalls, indicating a critical potential supervisor/cross-safety issue ([#22325](https://github.com/ethereum-optimism/optimism/issues/22325)).
- **New Issue**: The `op-node` sequencer's `Stop` function can block indefinitely while waiting for a head that may never arrive, raising concerns about sequencer stability ([#22318](https://github.com/ethereum-optimism/optimism/issues/22318)).
- **New Issue**: The sequencer compensates the seal deadline with a static constant instead of the measured seal duration, which could lead to inefficiencies ([#22320](https://github.com/ethereum-optimism/optimism/issues/22320)).
- **Blocked PR**: A draft PR ([#22321](https://github.com/ethereum-optimism/optimism/pull/22321)) is up to fix a specific flakiness signature in `TestSupernodeLightSequencerInteropInvalidMessageReplacement` by retrying `AwaitTxInBlock`/`AwaitTxNotInBlock` DSL checks, but the underlying cross-safety issue is being tracked separately.

## ✅ Completed Work
### Core Protocol Stability & Performance
- **Sequencer Starvation Eliminated**: The sequencer now runs on its own goroutine, preventing block production from competing with derivation and resolving long-standing issues related to sequencer starvation and block building delays ([#22241](https://github.com/ethereum-optimism/optimism/pull/22241), [#19263](https://github.com/ethereum-optimism/optimism/issues/19263), [#22232](https://github.com/ethereum-optimism/optimism/issues/22232)).
- **SDM Policy Refinement**: The SDM refund policy was isolated behind a test-only fixture, removing it from public production binaries while maintaining generic post-execution policy hooks and verifier support ([#22289](https://github.com/ethereum-optimism/optimism/pull/22289)).
- **Post-Execution Transaction Validation**: A latent Go↔Rust divergence where the post-execution (0x7D) transaction payload was not validated on decode has been closed, with `op-node` and Kona now treating `PostExecTxs` as opaque bytes during derivation ([#21961](https://github.com/ethereum-optimism/optimism/issues/21961)).

### Documentation & Developer Experience
- **Documentation Clarity Improvements**: Multiple documentation issues were addressed, including fixing unreachable links, dead in-tree links, mis-archived snap-sync guides, and disambiguating colliding frontmatter page titles ([#22317](https://github.com/ethereum-optimism/optimism/pull/22317), [#22314](https://github.com/ethereum-optimism/optimism/pull/22314)).
- **Kona Node Actor List Correction**: The Kona node actor list and extension mechanism were corrected for accuracy ([#22313](https://github.com/ethereum-optimism/optimism/pull/22313)).
- **New Chain Run Guide**: A new "Choose how to run your chain" fork page was added to improve user guidance ([#22312](https://github.com/ethereum-optimism/optimism/pull/22312)).
- **Retired Stale Pages**: Stale op-reth OP Stack run pages were retired to ensure documentation remains current ([#22316](https://github.com/ethereum-optimism/optimism/pull/22316)).

### CI/CD & Testing Enhancements
- **CI Test Efficiency**: Test jobs were sharded by historical timing and parallelism was widened to significantly improve CI efficiency ([#22202](https://github.com/ethereum-optimism/optimism/pull/22202)).
- **ZK Dispute Game Test Fix**: A metrics port collision in the `kona-sp1-proposer` was resolved, fixing a flaking test related to concurrent challenged games ([#22300](https://github.com/ethereum-optimism/optimism/pull/22300), [#22299](https://github.com/ethereum-optimism/optimism/issues/22299)).
- **`op-node` Flag Registration**: The `l2.follow.source.rpc-timeout` flag was properly registered in `op-node` ([#22297](https://github.com/ethereum-optimism/optimism/pull/22297)).
- **Conductor System Coverage**: User-visible conductor behaviors were ported to focused acceptance tests, and superseded `op-e2e` coverage was removed, addressing the flaky `TestSequencerFailover_ConductorRPC` test ([#22244](https://github.com/ethereum-optimism/optimism/pull/22244), [#21902](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/21902), [#22094](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22094)).
- **Tooling Updates**: The milestone for `op-deployer` and Tooling Runbook, which introduced changes to `op-deployer` and new requirements for `intent.json`, has been completed ([#22114](https://github.com/ethereum-optimism/optimism/issues/22114)).

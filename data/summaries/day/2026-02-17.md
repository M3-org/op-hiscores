On Feb 17, 2026, Optimism saw significant progress in enhancing L2 contract management with new batch upgrade capabilities and critical infrastructure improvements, alongside a major go-ethereum version update and security-focused signer rotations in the Superchain. A key challenge emerged with a reported memory leak in `op-reth` related to long-open database read transactions.

## 🚨 Needs Attention
- **Urgent Discussion**: `op-reth` is experiencing a critical bug where long-open database read transactions trigger memory leaks, leading to nodes consuming all available memory, requiring immediate investigation and resolution ([#19212](https://github.com/ethereum-optimism/optimism/issues/19212)).

## ✅ Completed Work
### Protocol & Core Infrastructure Enhancements
- **Go-Ethereum Version Update**: The `op-geth` repository was updated to merge `go-ethereum v1.16.9`, impacting cryptography and peer-to-peer networking ([#765](https://github.com/ethereum-optimism/op-geth/pull/765)).
- **Consensus Parameter Validation**: Optimism parameters are now validated within the consensus beacon in `op-geth`, enhancing the robustness of the consensus mechanism ([#766](https://github.com/ethereum-optimism/op-geth/pull/766)).
- **`op-acceptor` Stability Improvements**: A bug affecting the `op-acceptor` base image was fixed in `infra`, enhancing the reliability of the component ([#554](https://github.com/ethereum-optimism/infra/pull/554)).
- **Protocol Upgrade Specification**: A new feature was added to `specs` to include the `ConditionalDeployer` upgrade step within the transaction execution sequence, detailing its handling within the protocol ([#892](https://github.com/ethereum-optimism/specs/pull/892)).

### L2 Contract Management and Superchain Operations
- **L2 Contract Batch Upgrades**: A significant feature was added to `optimism` to extend the `ProxyAdmin` predeploy, now `L2ProxyAdmin`, to support batch upgrades of L2 predeploy contracts via the xFork L2ContractsManager, improving efficiency and flexibility ([#19135](https://github.com/ethereum-optimism/optimism/pull/19135)).
- **Sepolia Signer Rotation**: A major update in `superchain-ops` involved rotating a signer on all four Sepolia Safes, replacing Pete with Eli, and adding a `ChainGovernorSafe` entry to `addresses.toml` for Sepolia ([#1376](https://github.com/ethereum-optimism/superchain-ops/pull/1376)).
- **Soneium U18 Execution Feature**: A new feature was added to `superchain-ops` to enable the execution of soneium U18, expanding operational capabilities ([#1377](https://github.com/ethereum-optimism/superchain-ops/pull/1377)).

### Deployment Process & CI/CD Refinements
- **Deployment Process Streamlining**: The deployment process in `optimism` saw improvements with the removal of default L1 and L2 PAOs and relocation of documentation, streamlining `op-deployer` ([#19166](https://github.com/ethereum-optimism/optimism/pull/19166)).
- **CI/CD and Testing Infrastructure Improvements**: Several fixes and enhancements were made to the CI/CD pipeline and testing infrastructure in `optimism`, including adjusting `reproducible-prestate` for parallel builds ([#19184](https://github.com/ethereum-optimism/optimism/pull/19184)), fixing a Devin client timeout ([#19219](https://github.com/ethereum-optimism/optimism/pull/19219)), improving `DelayedWETH` address loading ([#19206](https://github.com/ethereum-optimism/optimism/pull/19206)), adding an acceptance test for block-level throttling ([#19079](https://github.com/ethereum-optimism/optimism/pull/19079)), and optimizing CI builds for Rust binaries ([#19204](https://github.com/ethereum-optimism/optimism/pull/19204)).

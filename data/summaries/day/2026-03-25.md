## ✅ Completed Work
### ZK Dispute Game Advancements
- Replaced `OptimisticZkGame` with a spec-compliant `ZKDisputeGame` as game type `10`, implementing the full game lifecycle within the OP Stack dispute infrastructure. ([ethereum-optimism/optimism#19606](https://github.com/ethereum-optimism/optimism/pull/19606))
- Added a comprehensive Failure Mode Analysis (FMA) document for the ZK Dispute Game, detailing 8 failure modes, risk assessments, mitigations, detection strategies, recovery paths, and audit requirements, including a consolidated action items table with 30 items. ([ethereum-optimism/design-docs#369](https://github.com/ethereum-optimism/design-docs/pull/369))
- Removed interop bridge contracts from the L2ContractsManager upgrade flow, updating `IMPLEMENTATION_COUNT` from 28 to 23. ([ethereum-optimism/optimism#19650](https://github.com/ethereum-optimism/optimism/pull/19650))
- Completed the review and addressed the tracking issue for the `kona-interop` block hash oracle, which uses EIP-2935 for efficient block hash lookups. ([ethereum-optimism/optimism#18288](https://github.com/ethereum-optimism/optimism/issues/18288))
- Closed several issues related to contract refactoring for the ZK dispute game, including the removal of the access manager, replacement of `rollupConfigHash` with `l2ChainID`, and ensuring MCP compatibility. ([ethereum-optimism/optimism#18418](https://github.com/ethereum-optimism/optimism/issues/18418), [ethereum-optimism/optimism#18421](https://github.com/ethereum-optimism/optimism/issues/18421), [ethereum-optimism/optimism#18417](https://github.com/ethereum-optimism/optimism/issues/18417))

### Infrastructure Modernization and Security Hardening
- Bumped Go versions to 1.26 across most modules and adopted Docker Hardened Images (DHI) for all Dockerfiles to reduce the attack surface, including Dockerfile smoke tests. ([ethereum-optimism/infra#579](https://github.com/ethereum-optimism/infra/pull/579))
- Removed unused runtime dependencies from `proxyd`, `op-ufm`, and `peer-mgmt-service` to streamline Docker images by switching base images to `dhi.io/alpine-base:3.23` and removing unnecessary `apk add` packages. ([ethereum-optimism/infra#580](https://github.com/ethereum-optimism/infra/pull/580))
- Fixed a bug in the `cci-stats` service where `mapFlakyStatus` incorrectly used `strings.HasPrefix` to detect `FLAKY_PASS`/`FLAKY_FAIL` markers, now using `Contains` for accurate detection. ([ethereum-optimism/infra#578](https://github.com/ethereum-optimism/infra/pull/578))

### Devstack and Derivation Improvements
- Introduced central dispatch functions (`startL2ELForKey`, `startL2CLForKey`) in `op-devstack` to respect `DEVSTACK_L2EL_KIND` and `DEVSTACK_L2CL_KIND` across all single-chain runtimes. ([ethereum-optimism/optimism#19653](https://github.com/ethereum-optimism/optimism/pull/19653))
- Fixed a bug in Kona's L1Retrieval stage where the data availability provider was not cleared on re-orgs, preventing stale calldata or blobs from persisting. ([ethereum-optimism/optimism#19687](https://github.com/ethereum-optimism/optimism/pull/19687))
- Enabled the L1 Geth client in `op-devstack` to expose its user RPC over HTTP for Kona connectivity. ([ethereum-optimism/optimism#19742](https://github.com/ethereum-optimism/optimism/pull/19742))

### Testing Infrastructure and CI/CD Refinements
- Updated `op-acceptance-tests` to make spamming tests compatible with `op-reth` by extracting relevant logic from existing throttling tests. ([ethereum-optimism/optimism#19676](https://github.com/ethereum-optimism/optimism/pull/19676))
- Migrated interop acceptance tests to use supernode-based presets and added a flag to `op-up` for spinning up a 2-chain interop devnet. ([ethereum-optimism/optimism#19754](https://github.com/ethereum-optimism/optimism/pull/19754), [ethereum-optimism/optimism#19747](https://github.com/ethereum-optimism/optimism/pull/19747))
- Removed the `TestInteropFaultProofs_DeepCanonicalBlockQuery` action test, as it used `op-supervisor` instead of `op-supernode` for EIP-2935 block hash verification. ([ethereum-optimism/optimism#19753](https://github.com/ethereum-optimism/optimism/pull/19753))
- Optimized CI by skipping Rust gate and devnet workflows for documentation-only pull requests and removed the `devnet-metrics-collect` job and workflow. ([ethereum-optimism/optimism#19739](https://github.com/ethereum-optimism/optimism/pull/19739), [ethereum-optimism/optimism#19744](https://github.com/ethereum-optimism/optimism/pull/19744))

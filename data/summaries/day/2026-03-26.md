On Mar 26, 2026, significant progress was made in enhancing the L2 Contract Manager (L2CM) upgrade system and resolving several long-standing flaky tests across multiple repositories. A critical breaking change in `op-geth`'s `StorageKeys` value was identified, requiring immediate attention, while `op-node` performance was improved through batching `safe-head FCU` calls.

## 🚨 Needs Attention
- **Urgent Discussions**:
    - **ethereum-optimism/infra**: The breaking change in `op-geth` v1.101701.0 where `StorageKeys` values are now `null` instead of `[]` ([#780](https://github.com/ethereum-optimism/infra/issues/780)) requires investigation into its impact on systems relying on previous behavior.
    - **ethereum-optimism/optimism**: Weekly fork testing of L2CM upgrades for all supported chains has been proposed to prevent issues where the ProxyAdmin owner could upgrade predeploys without version checks ([#19766](https://github.com/ethereum-optimism/optimism/issues/19766)).
    - **ethereum-optimism/optimism**: The `op-reth` project sends `chainID=0` in `supervisor_checkAccessList ExecutingDescriptor` when `--rollup.supervisor-http` is configured ([#19768](https://github.com/ethereum-optimism/optimism/issues/19768)).
    - **ethereum-optimism/optimism**: `op-supernode` needs to track the FCU retry-verify workaround in `RewindToTimestamp` to address an `op-reth` race condition ([#19772](https://github.com/ethereum-optimism/optimism/issues/19772)).
- **Blocked Issues/PRs**:
    - **ethereum-optimism/infra**: The issue regarding proving withdrawals using chain-specific root claims ([#18517](https://github.com/ethereum-optimism/infra/issues/18517)) is awaiting confirmation on whether the approach has changed to `rootClaimByChainId` and if it can be closed.
    - **ethereum-optimism/infra**: The investigation into adding an array of predeploys to increase L2CM upgrade safety ([#19260](https://github.com/ethereum-optimism/infra/issues/19260)) highlights a deeper structural pipeline gap that needs to be addressed to prevent future silent failures.
    - **ethereum-optimism/infra**: Clarification is needed on whether interop transactions in the mempool are explicitly dropped during a reorg or if periodic re-evaluation handles this ([#19351](https://github.com/ethereum-optimism/infra/issues/19351)).
    - **ethereum-optimism/infra**: Updates to `UpgradeUtils.getTransactionCount()` and `GasLimits` struct are required when removing Karst-specific upgrade transactions from `GenerateNUTBundle` ([#19369](https://github.com/ethereum-optimism/infra/issues/19369)).

## ✅ Completed Work

### L2CM Upgrade System Enhancements
- Creation of a Solidity script for deterministic JSON NUT bundles was completed, streamlining the upgrade process ([#18834](https://github.com/ethereum-optimism/infra/issues/18834), [#18840](https://github.com/ethereum-optimism/infra/issues/18840), [#19248](https://github.com/ethereum-optimism/optimism/pull/19248)).
- Dev feature flag support was implemented in the L2 upgrade system, improving testing flexibility ([#18838](https://github.com/ethereum-optimism/infra/issues/18838), [#19324](https://github.com/ethereum-optimism/optimism/pull/19324)).
- `just` commands were added for generating NUT bundles and running L2 upgrade fork tests, enhancing developer tooling ([#18840](https://github.com/ethereum-optimism/infra/issues/18840), [#18841](https://github.com/ethereum-optimism/infra/issues/18841), [#19464](https://github.com/ethereum-optimism/infra/pull/19464)).
- A crucial fix was applied to ensure contracts are built before generating NUT bundles, preventing issues with uncompiled source contracts ([#19763](https://github.com/ethereum-optimism/optimism/pull/19763)).

### Flaky Test Resolution
- The flaky test `TestCLELDivergence` was closed after mitigation efforts and clarification on expected derivation pipeline behavior ([#19681](https://github.com/ethereum-optimism/infra/issues/19681), [#19733](https://github.com/ethereum-optimism/optimism/pull/19733)).
- The flaky test `TestPreinteropFaultProofs_TraceExtensionActivation` was closed, with a fix identified for a nonce race condition ([#19760](https://github.com/ethereum-optimism/infra/issues/19760)).

### Performance and Stability Improvements
- `op-node` performance was improved by batching `safe-head engine_forkchoiceUpdated` calls to one per derived L1 block ([#19638](https://github.com/ethereum-optimism/optimism/pull/19638)).
- `op-alloy-evm` now includes an `OpEvm::into_inner` method for better interoperability ([#19735](https://github.com/ethereum-optimism/optimism/pull/19735)).
- `contracts-bedrock` received `l2cm IR low` fixes, resolving an upgrade edge case with `ConditionalDeployer` ([#19785](https://github.com/ethereum-optimism/optimism/pull/19785)).
- `kona-proof` received multiple fixes to its derivation logic, preventing malicious trace-extension challenges ([#19775](https://github.com/ethereum-optimism/optimism/pull/19775)).
- The issue where `op-reth` was sending `chainID=0` in `supervisor_checkAccessList ExecutingDescriptor` was resolved ([#19768](https://github.com/ethereum-optimism/optimism/issues/19768)).

### CI/CD and Tooling Enhancements
- CI workflows were updated to enable SBOM attestation by default for Docker image builds, enhancing supply chain security ([#19769](https://github.com/ethereum-optimism/optimism/pull/19769)).
- Rust CI jobs were downsized from `xlarge` to `medium` to reduce resource consumption ([#19777](https://github.com/ethereum-optimism/optimism/pull/19777)).
- `op-reth` now includes `chain_id` in its `ExecutingDescriptor` for supervisor txpool validation ([#19771](https://github.com/ethereum-optimism/optimism/pull/19771)).
- `cargo-auditable` is being used for Rust image builds to embed full crate dependency trees ([#19770](https://github.com/ethereum-optimism/optimism/pull/19770)).
- `op-contracts` validation files were updated to v6.0.0 for mainnet and sepolia ([#1204](https://github.com/ethereum-optimism/superchain-registry/pull/1204)).

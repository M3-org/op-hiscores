## ✅ Completed Work
### OP Stack Execution Layer & Core Component Improvements
- **`op-reth` Test Engine Integration**: An ephemeral, OP-flavored execution layer was introduced for `op-reth-test-engine`, allowing `op-e2e/actions` to run OP execution layers without embedding `op-geth` in-process. ([#21216](https://github.com/ethereum-optimism/optimism/pull/21216))
- **Block Gas Limit Enforcement**: The `SystemConfig`-derived block gas limit is now enforced against pre-refund EVM gas under SDM/PostExec, resolving issues with block gas accounting. ([#21250](https://github.com/ethereum-optimism/optimism/pull/21250))
- **Public API for OP Pool**: A public API for the op pool has been added. ([#21305](https://github.com/ethereum-optimism/optimism/pull/21305))
- **EVM Gas Limit Enforcement Resolved**: The issue of enforcing a block gas limit on pre-refund EVM gas under SDM/PostExec has been resolved by capping the maximum computation a sequencer can perform. ([#20709](https://github.com/ethereum-optimism/optimism/issues/20709))

### `proxyd` Reliability & Interoperability Enhancements
- **Fail-Closed Interop Filtering**: `proxyd` now defaults to fail-closed interop filtering, with the safest `agreement` strategy as the default. ([#649](https://github.com/ethereum-optimism/infra/pull/649))
- **`AvgSlidingWindow` Race Condition Fix**: A critical race condition in `AvgSlidingWindow` access within `proxyd` was fixed, improving concurrent operation synchronization. ([#653](https://github.com/ethereum-optimism/infra/pull/653))
- **`proxyd` Terminology Refinement**: "Supervisor" was renamed to "interop-filter" across `proxyd`'s code, metrics, and documentation for clarity. ([#648](https://github.com/ethereum-optimism/infra/pull/648))
- **`TestMulticall` Stability Improvement**: A race condition in the `TestMulticall` assertion was addressed, enhancing integration test stability. ([#652](https://github.com/ethereum-optimism/infra/pull/652))

### Codebase Streamlining & Operator Ergonomics
- **`op-acceptor` Removal**: The deprecated `op-acceptor` component was entirely removed from the `infra` repository, streamlining the codebase. ([#651](https://github.com/ethereum-optimism/infra/pull/651))
- **`op-proofs` CLI Improvements**: The `op-proofs` CLI now includes default backfill on `init`, shared CLI arguments, and window-based targets for a better operator experience. ([#21277](https://github.com/ethereum-optimism/optimism/pull/21277))
- **EIP-1559 Parameter Validation**: Zero elasticity in EIP-1559 parameters decoding within `op-alloy` is now rejected, pushing validation down for early failure on invalid parameters. ([#21292](https://github.com/ethereum-optimism/optimism/pull/21292))
- **EIP-1559 Parameter Decoding Resolved**: The issue of properly catching zero elasticities during EIP-1559 parameter decoding has been addressed by pushing validation to the `op-alloy` level. ([#18951](https://github.com/ethereum-optimism/optimism/issues/18951))

### CI/CD & Interoperability Stability
- **CI Stale Binaries Fix**: A CI issue where stale binaries were served due to the rust target-dir build cache was resolved. ([#21310](https://github.com/ethereum-optimism/optimism/pull/21310))
- **`TestReorgUnsafeHead` Deflaked**: The `TestReorgUnsafeHead` batcher race in op-acceptance-tests was deflaked. ([#21307](https://github.com/ethereum-optimism/optimism/pull/21307))
- **`op-supernode` Interop Cycle Fix**: `op-supernode` now errors instead of silently dropping chains during interop cycle detection when `db.OpenBlock` fails, preventing invalid blocks from being treated as valid. ([#21303](https://github.com/ethereum-optimism/optimism/pull/21303))

On Jan 22, 2026, Optimism significantly advanced its CI/CD infrastructure by migrating Docker builds to GitHub Actions and enhanced developer experience with comprehensive documentation for `op-reth` historical proofs. Concurrently, core protocol development saw improvements in deployment processes with a new feature flag for forge scripts and internal refactoring for stricter integer conversions, while critical discussions continued on unifying withdrawal proof mechanisms across the Superchain.

## 🚨 Needs Attention
- **Urgent Discussions**:
    - **Withdrawal Proof Mechanism Enhancements**: Input is needed on [#18517](https://github.com/ethereum-optimism/ecosystem/issues/18517) to ensure `OptimismPortalInterop` is updated to use `IDisputeGame.rootClaim(uint256)` for verifying L2 chain output root proofs, aligning with changes for `OptimismPortal2.proveWithdrawalTransaction`.
    - **Updating Withdrawal Script for Interoperability**: Progress on [#18615](https://github.com/ethereum-optimism/ecosystem/issues/18615) to update the `op-chain-ops/cmd/withdrawal` script is dependent on the completion of [#18517](https://github.com/ethereum-optimism/ecosystem/issues/18517) to simplify the implementation of pre-interop and post-interop withdrawal transaction proving.

## ✅ Completed Work
### CI/CD & Infrastructure Improvements
- **Docker Build Migration to GitHub Actions**: The `ethereum-optimism/ecosystem` project successfully migrated Docker builds from CircleCI to GitHub Actions, streamlining the CI/CD pipeline and leveraging GitHub Actions for more efficient build and publish operations. ([#972](https://github.com/ethereum-optimism/ecosystem/pull/972))
- **Improved Test Stability**: The `ethereum-optimism/optimism` project increased the timeout for contracts tests to prevent flakes, enhancing the reliability of the CI/CD pipeline. ([#18914](https://github.com/ethereum-optimism/optimism/pull/18914))

### Developer Tooling & Documentation
- **Enhanced Node Operator Documentation for Historical Proofs**: The `ethereum-optimism/docs` project added comprehensive documentation and a dedicated tutorial for running `op-reth` with the historical proofs Execution Extension (ExEx), significantly improving guidance for advanced node configurations. ([#1949](https://github.com/ethereum-optimism/docs/pull/1949))
- **Forge Deployer Enhancements**: The `ethereum-optimism/optimism` project completed the conversion of `DeploySuperchain` to use Forge and created a default flag for using Forge in `op-deployer`, marking significant progress in integrating Forge into the deployment process. ([#17215](https://github.com/ethereum-optimism/optimism/issues/17215), [#18761](https://github.com/ethereum-optimism/optimism/issues/18761))
- **Enhanced Deployment with Forge Script Feature Flag**: A new feature flag was added to the `op-deployer` in `ethereum-optimism/optimism` to enable the execution of forge scripts, streamlining the deployment process. ([#18881](https://github.com/ethereum-optimism/optimism/pull/18881))

### Core Protocol Refactoring
- **Internal Refactoring for Strict Uint64 Conversion**: Across `op-challenger`, `op-dispute-mon`, and `op-program` components in `ethereum-optimism/optimism`, calls to `big.Int.Uint64()` were replaced with `bigs.Uint64Strict`, enhancing the robustness of integer conversions. ([#18902](https://github.com/ethereum-optimism/optimism/pull/18902))

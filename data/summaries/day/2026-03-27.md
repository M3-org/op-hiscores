On Mar 27, 2026, Optimism's development focused on refining L2 contract architecture and enhancing the `proxyd` component. Key achievements include updating L2CM specifications, adding feature flags to `L1Block` for production customization, and significant refactoring within `proxyd`'s consensus tracking. Several long-standing issues related to `L2ProxyAdmin` refactoring and L2CM access control were closed across multiple repositories, indicating progress in foundational smart contract infrastructure.

## ✅ Completed Work
### L2 Contract Architecture & Access Control Refinement
- The L2CM specifications were updated to reflect changes in the bundle format and gas allocation handling ([ethereum-optimism/specs#897](https://github.com/ethereum-optimism/specs/pull/897)).
- New feature flags were added to `L1Block` for production system customization, enabling depositor-only features and public checking ([ethereum-optimism/optimism#19668](https://github.com/ethereum-optimism/optimism/pull/19668)).
- Informational findings from an internal review of L2 Contracts Manager were resolved, improving contract robustness ([ethereum-optimism/optimism#19783](https://github.com/ethereum-optimism/optimism/pull/19783)).
- The issue regarding adding `ProxyAdminOwnedBase` access control to predeploy `initialize()` functions for L2CM was closed, with the work confirmed as completed ([ethereum-optimism/specs#19313](https://github.com/ethereum-optimism/specs/issues/19313), [ethereum-optimism/superchain-registry#19313](https://github.com/ethereum-optimism/superchain-registry/issues/19313), [ethereum-optimism/ethereum-optimism.github.io#19313](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19313), [ethereum-optimism/infra#19313](https://github.com/ethereum-optimism/infra/issues/19313), [ethereum-optimism/optimism#19313](https://github.com/ethereum-optimism/optimism/issues/19313)).
- The issue proposing to refactor `L2ProxyAdmin` to use the `Initializable` pattern was closed, with the conclusion that there was no strong reason to implement this change ([ethereum-optimism/specs#19182](https://github.com/ethereum-optimism/specs/issues/19182), [ethereum-optimism/superchain-registry#19182](https://github.com/ethereum-optimism/superchain-registry/issues/19182), [ethereum-optimism/ethereum-optimism.github.io#19182](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19182), [ethereum-optimism/infra#19182](https://github.com/ethereum-optimism/infra/issues/19182), [ethereum-optimism/optimism#19182](https://github.com/ethereum-optimism/optimism/issues/19182)).

### Superchain Migration & Interoperability Improvements
- Prestates for kona-client 1.2.13 were added to the `validation/standard` directory, ensuring compatibility with the latest client release ([ethereum-optimism/superchain-registry#1205](https://github.com/ethereum-optimism/superchain-registry/pull/1205)).
- The `op-devstack` now utilizes EIP-7702 SetCode for OPCM migration delegatecalls, streamlining the migration process and replacing a complex deploy-transfer-execute-restore pattern ([ethereum-optimism/optimism#19745](https://github.com/ethereum-optimism/optimism/pull/19745)).
- Weekly L2 fork tests were introduced to ensure compatibility across different OP Stack chains and prevent unexpected reverts during upgrades ([ethereum-optimism/optimism#19793](https://github.com/ethereum-optimism/optimism/pull/19793)).

### `proxyd` Component Refactoring
- The `proxyd` component saw a significant refactoring of its `ConsensusTracker` interface, replacing a multi-method interface with a simpler `GetState()`/`SetState()` approach ([ethereum-optimism/infra#588](https://github.com/ethereum-optimism/infra/pull/588)).

### Documentation & Testing Infrastructure
- Rust documentation was migrated from Vocs to Mintlify, unifying the documentation platform and improving accessibility ([ethereum-optimism/optimism#19778](https://github.com/ethereum-optimism/optimism/pull/19778)).
- Contract test coverage was significantly improved for `LegacyMintableERC20` and `ETHLiquidity` through fuzz tests and event emission assertions ([ethereum-optimism/optimism#19557](https://github.com/ethereum-optimism/optimism/pull/19557), [ethereum-optimism/optimism#19665](https://github.com/ethereum-optimism/optimism/pull/19665)).
- A new test was added to verify double upgrade calls for OPCM, ensuring upgrade path resilience ([ethereum-optimism/optimism#19724](https://github.com/ethereum-optimism/optimism/pull/19724)).
- The flaky test `TestPreinteropFaultProofs_TraceExtensionActivation` was closed, with the fix implemented in [#19745](https://github.com/ethereum-optimism/optimism/pull/19745) addressing a nonce race condition ([ethereum-optimism/optimism#19760](https://github.com/ethereum-optimism/optimism/issues/19760)).

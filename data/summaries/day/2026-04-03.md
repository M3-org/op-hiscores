On Apr 3, 2026, Optimism's development focused heavily on refining core infrastructure and documentation. Significant progress was made in streamlining contract management by removing legacy components and enhancing testing reliability within the `optimism` repository, alongside critical bug fixes. Documentation for the Actions SDK was expanded, and interop specifications were refined, indicating a push towards improved system architecture and developer support.

## ✅ Completed Work
### Core Protocol Refinements & Legacy Component Removal
- The legacy OPContractsManager v1 was entirely removed from Solidity code, simplifying the contract architecture in `ethereum-optimism/optimism`. ([#19795](https://github.com/ethereum-optimism/optimism/pull/19795))
- Issues related to Interop Phase 3, specifically the ability to remove chains from shared dispute games, including core removal, contract implementation, deployment tooling, and runbooks, were closed in `ethereum-optimism/optimism`. ([#19692](https://github.com/ethereum-optimism/optimism/issues/19692), [#19705](https://github.com/ethereum-optimism/optimism/issues/19705), [#19706](https://github.com/ethereum-optimism/optimism/issues/19706), [#19707](https://github.com/ethereum-optimism/optimism/issues/19707), [#19715](https://github.com/ethereum-optimism/optimism/issues/19715))
- The `op-supernode` task for merging chains into shared dispute games ([#19701](https://github.com/ethereum-optimism/optimism/issues/19701)) and the OPCM function for unmerging ([#19015](https://github.com/ethereum-optimism/optimism/issues/19015)) were closed in `ethereum-optimism/optimism`.
- The `ETHLiquidity` contract was re-added to L2 predeploys in `ethereum-optimism/optimism`. ([#19460](https://github.com/ethereum-optimism/optimism/issues/19460))

### Testing & CI Enhancements
- A flaky test, `TestExecutePayloadSuccess`, in `op-reth` was fixed by adding `WaitForBlockNumber` synchronization, improving test stability in `ethereum-optimism/optimism`. ([#19899](https://github.com/ethereum-optimism/optimism/pull/19899))
- The CI now runs reth and kona against all acceptance tests, expanding test coverage in `ethereum-optimism/optimism`. ([#19787](https://github.com/ethereum-optimism/optimism/pull/19787))
- The requirement for deploy config JSON files when running Solidity unit tests was removed by adding a `_initDefaults()` function to `DeployConfig.s.sol`, simplifying the testing setup in `ethereum-optimism/optimism`. ([#18922](https://github.com/ethereum-optimism/optimism/pull/18922))
- The issue concerning the flaky `TestExecutePayloadSuccess` test in `op-reth` was closed in `ethereum-optimism/optimism`. ([#19898](https://github.com/ethereum-optimism/optimism/issues/19898))

### Infrastructure & Code Quality
- Code refactoring was completed in the `proxyd` component, extracting the `updateELBackend` function to encapsulate EL block fetches and their validation, enhancing code clarity and modularity in `ethereum-optimism/infra`. ([#595](https://github.com/ethereum-optimism/infra/pull/595))

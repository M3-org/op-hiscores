On Feb 6, 2026, significant progress was made on refining deployment processes and fixing critical contract logic within the `optimism` repository, alongside updates to preimage hint documentation in `specs`. A cross-cutting issue regarding `proxyd`'s handling of out-of-range RPC calls in CI workflows, particularly affecting `superchain-ops`, emerged as a key area of discussion, with a new issue and PR opened in `infra` to address it.

## 🚨 Needs Attention
- **Urgent Discussions**:
    - **CI Failing RPC Calls on `superchain-ops`**: Discussion continues across multiple repositories (`docs`, `specs`, `ethereum-optimism.github.io`, `superchain-ops`, `op-analytics`, `infra`, `optimism`) on issue [#17688](https://github.com/ethereum-optimism/docs/issues/17688) regarding `forge_test` CI workflow failures due to RPC calls returning "block is out of range." `sebastianst` suggests `proxyd` should return `null` for future blocks instead of an error, linking to a related `infra` issue. Input is needed to determine the best path forward for `proxyd` behavior.
- **Blocked Issues/PRs**:
    - **`proxyd` Error Responses for Unfound Blocks**: Issue [#546](https://github.com/ethereum-optimism/infra/issues/546) was created to report that `proxyd` incorrectly returns HTTP and JSON errors when a requested block is not found, instead of the Ethereum specs-compliant `null` response. This is directly related to the CI failures and requires resolution.
    - **`proxyd` Block Request Handling PR**: Pull request [#547](https://github.com/ethereum-optimism/infra/pull/547) aims to fix `proxyd`'s behavior by forwarding out-of-range block requests to the backend. This PR needs review and merging to address the `proxyd` issue.

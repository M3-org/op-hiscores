Apr 20, 2026

Today, significant progress was made on Superchain interoperability with new log backfill features in `op-supernode` and critical bug fixes for Kona's `CrossL2Inbox` deployment, resolving state divergence issues. Operations were streamlined with a new Superroot upgrade template and fixes for the Deputy Pause Module, while CI/CD infrastructure saw substantial improvements, including enhanced fault proof testing stability.

    - `ethereum-optimism/superchain-ops`: Discussion continues on whether `op-supernode` should return SuperRoots for unsafe data, with a proposal to find alternative means to determine if a node considers a given height or hash as "observed" rather than relying on unsafe data within the Superroot API. ([#19059](https://github.com/ethereum-optimism/superchain-ops/issues/19059))

## ✅ Completed Work
### Superchain Operations & Interoperability Enhancements
- **Superroot Upgrade Template**: A new operations template for Superroot upgrades was added, streamlining future upgrade processes. ([#1397](https://github.com/ethereum-optimism/superchain-ops/pull/1397))
- **Deputy Pause Module Fixes**: A critical bug in the Sepolia Deputy Pause Module key rotation task was fixed, involving re-signing the DPM rotation and migrating off the FoundationOperationsSafe. ([#1402](https://github.com/ethereum-optimism/superchain-ops/pull/1402))
- **`CrossL2Inbox` Conditional Deployment**: Resolved a state divergence issue in Kona by conditionally deploying `CrossL2Inbox` transactions based on the number of dependent chains, ensuring consistency with `op-node` during single-chain Interop activation. ([#20147](https://github.com/ethereum-optimism/optimism/pull/20147))
- **Kona Proof Driver Fix**: Fixed an error in the Kona proof driver where `is_interop_active()` was incorrectly passed a block number instead of a block timestamp, which could lead to premature Interop activation. ([#20162](https://github.com/ethereum-optimism/optimism/pull/20162))
- **Interop Log Backfill**: Introduced a new feature in `op-supernode` to enable interop log backfill depth and validation gating, allowing pre-ingestion of logs from a specified depth to the local safe head. ([#19973](https://github.com/ethereum-optimism/optimism/pull/19973))

### CI/CD and Testing Infrastructure Improvements
- **`mise` Version Pinning**: Pinned the `mise` version in the `docker-build-prep` GitHub Action to prevent build failures related to `just` installation. ([#20170](https://github.com/ethereum-optimism/optimism/pull/20170))
- **CircleCI Refactoring**: Refactored CircleCI configuration to streamline gate jobs, replacing multiple `ci-gate-skip` jobs with a single, always-succeeding `ci-gate` job. ([#20190](https://github.com/ethereum-optimism/optimism/pull/20190))
- **Fault Proof Test Stability**: Unmarked several Interop fault proof tests as flaky, indicating improved stability and reliability of these tests. ([#20159](https://github.com/ethereum-optimism/optimism/pull/20159))
- **Provenance Attestation**: Added a GitHub Actions workflow to verify the provenance attestation of the `ci-base-clang` image, enhancing supply chain security for Rust jobs. ([#20171](https://github.com/ethereum-optimism/optimism/pull/20171))
- **Test Parameter Overrides**: Updated `op-acceptance-tests` to allow overriding `-count` and `-timeout` parameters in `just test` commands, providing more flexibility for test execution and flake triage. ([#20161](https://github.com/ethereum-optimism/optimism/pull/20161))
- **`ci-base-clang` Pinning**: Pinned the `ci-base-clang` image for Rust jobs in CircleCI and removed runtime `apt-install` steps, improving build consistency and speed. ([#20135](https://github.com/ethereum-optimism/optimism/pull/20135))

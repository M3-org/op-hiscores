Optimism's development today focused heavily on documentation and core code refactoring within the `optimism` monorepo, alongside addressing critical testing infrastructure issues in `supersim` and `optimism` related to flaky acceptance tests caused by metrics port collisions. Significant progress was made on improving CI/CD pipelines and enhancing dispute monitoring, while a key pipeline improvement tracker was closed due to `op-node` deprecation.

- Refactored `op-core`, `op-service`, and `op-chain-ops` to clean up receipt wrapping constructors and codecs, improving code maintainability. [#22295](https://github.com/ethereum-optimism/optimism/pull/22295), [#22292](https://github.com/ethereum-optimism/optimism/pull/22292)
- Removed outdated TODOs referencing an old issue in `op-node`, cleaning up the codebase. [#22292](https://github.com/ethereum-optimism/optimism/pull/22292)

### Infrastructure & Testing Improvements
- Enhanced CI/CD by paging protocol-oncall for `go-tests-full` develop failures and building the superchain bundle in `go-release`. [#22212](https://github.com/ethereum-optimism/optimism/pull/22212), [#22233](https://github.com/ethereum-optimism/optimism/pull/22233)
- Updated `op-reth` e2e tests to use `RUST_BINARY_PATH_OP_RETH` and added `busybox` and `apk-tools` to APKO images for better debugging. [#22290](https://github.com/ethereum-optimism/optimism/pull/22290), [#22287](https://github.com/ethereum-optimism/optimism/pull/22287)

### Dispute Monitoring & Proposer Updates
- Updated `op-dispute-mon` to normalize fault bond snapshots, streamlining the monitoring process. [#22226](https://github.com/ethereum-optimism/optimism/pull/22226)
- Implemented a fast finality mode for `kona-sp1-proposer`, allowing it to prove games without waiting for a challenge, and renamed its super root RPC configuration. [#22173](https://github.com/ethereum-optimism/optimism/pull/22173), [#22308](https://github.com/ethereum-optimism/optimism/pull/22308]

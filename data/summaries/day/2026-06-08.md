On June 8, 2026, Optimism's development focused heavily on enhancing interoperability and cross-chain messaging, alongside a significant milestone in decoupling `op-program` from the monorepo. Key achievements include improved interop filter validation, a new CLI for cross-chain messaging smoke-testing, and the complete removal of `op-program` from the main repository, streamlining the codebase. Additionally, there were critical bug fixes related to dispute game implementation and ongoing efforts to centralize core infrastructure configurations.

## ✅ Completed Work
### Interoperability and Cross-Chain Messaging Enhancements
*   A new feature in `op-reth` now enables multi-endpoint quorum validation for the interop filter, improving reliability of interop checks by fanning out requests and combining results by quorum agreement ([#21195](https://github.com/ethereum-optimism/optimism/pull/21195)).
*   A new CLI tool was introduced under `op-chain-ops` for smoke-testing interop cross-chain messaging against running L2 chains, including a `roundtrip` subcommand for bridging ETH ([#21262](https://github.com/ethereum-optimism/optimism/pull/21262)).
*   `proxyd` now includes a new Prometheus metric, `proxyd_rpc_interop_validations_total`, to track interop validation outcomes, enhancing monitoring capabilities ([#643](https://github.com/ethereum-optimism/infra/pull/643)).

### `op-program` Decoupling and Monorepo Cleanup
*   `op-e2e` was decoupled from `op-program` references ([#21257](https://github.com/ethereum-optimism/optimism/pull/21257)).
*   The `op-program` docker image was removed ([#21285](https://github.com/ethereum-optimism/optimism/pull/21285)).
*   `op-program` was dropped from the `op-challenger` docker image ([#21284](https://github.com/ethereum-optimism/optimism/pull/21284)).
*   The `op-program` directory was entirely deleted from the monorepo ([#21271](https://github.com/ethereum-optimism/optimism/pull/21271)).
*   `op-challenger` was updated to no longer require `--cannon-server` for the permissioned game type ([#21270](https://github.com/ethereum-optimism/optimism/pull/21270)).
*   The long-standing effort to remove `op-program` from the monorepo has been successfully closed ([#20276](https://github.com/ethereum-optimism/optimism/issues/20276)).

### Core Infrastructure and Bug Fixes
*   A bug was fixed in `SetDisputeGameImpl` where disabling the CANNON_KONA implementation did not properly zero out `initBonds`, ensuring proper initialization and cleanup of dispute game parameters ([#1453](https://github.com/ethereum-optimism/superchain-ops/pull/1453)).
*   EVM hardfork to `OpSpecId` resolution and eth-base mapping were aligned across `kona-client`, `op-revm`, and `alloy-op-evm` for consistency with `op-geth` ([#21291](https://github.com/ethereum-optimism/optimism/pull/21291)).
*   A new `op-core/params` package was created to centralize OP-Stack chain configuration, including `OptimismConfig`, `ChainConfig`, and chain config loaders, as part of the `op-geth` decoupling plan ([#21287](https://github.com/ethereum-optimism/optimism/pull/21287)).
*   The issue related to creating `op-core/params` for `OptimismConfig`, `ChainConfig`, and `LoadChainConfig` as part of the `op-geth` decoupling plan has been closed ([#20260](https://github.com/ethereum-optimism/optimism/issues/20260)).
*   An automated daily job updated the `addresses.json` file in the superchain registry, ensuring it remains current ([#1254](https://github.com/ethereum-optimism/superchain-registry/pull/1254)).

### Documentation Updates
*   Documentation for chain operators was updated to refocus prestate tutorials on `kona-client`, archiving `op-program` specific tutorials ([#21000](https://github.com/ethereum-optimism/optimism/pull/21000)).
*   A draft for the Kona-client prestate verification step for Upgrade 19 was added ([#21059](https://github.com/ethereum-optimism/optimism/pull/21059)).
*   The releases index documentation was updated to display the latest stable versions for components ([#21280](https://github.com/ethereum-optimism/optimism/pull/21280)).
*   The issue concerning the update of the SuperZKDG design document has been closed ([#21038](https://github.com/ethereum-optimism/optimism/issues/21038)).

### Reactive Runtime Config Reload for `op-node`
Discussion is ongoing regarding the problem of stale signer windows in `op-node` verifier nodes when the unsafe block signer address is rotated. A proposed solution involves adding a reactive reload mechanism that triggers an early runtime config reload when a gossip block fails signature verification. An alternative suggestion is to implement a grace period where both old and new keys are accepted, or to reconsider the policy for config loading frequency to reduce the 10-minute interval. A draft PR [#19982](https://github.com/ethereum-optimism/ecosystem/pull/19982) has been created.
- [#19981](https://github.com/ethereum-optimism/ecosystem/issues/19981)

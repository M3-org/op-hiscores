## ACTIVE ISSUES
### `op-reth` Upgrade Panic Diagnosis
Further investigation into the fatal panic in `StateRootTask` when upgrading `op-reth` from 1.x to 2.x on OP Stack chains revealed that the `--engine.legacy-state-root` flag does not resolve the issue. The panic, an assertion failure in `alloy-trie-0.9.5/src/nodes/branch.rs`, persists even when the strategy changes to "Parallel," indicating a shared bug in both parallel trie code paths. The crash block also shifted, suggesting the panic is not block-specific but rather triggered non-deterministically during parallel trie computation against 1.x database state [#20462](https://github.com/ethereum-optimism/ecosystem/issues/20462).

### `op-dispute-mon` and Supernode Integration Clarification
A discussion clarified that `op-dispute-mon` can monitor both CANNON and SUPER_CANNON_KONA games simultaneously by passing both a rollup-rpc and supernode-rpc. It was also noted that `op-supernode` can expose `op-node` RPC endpoints, simplifying integration and negating the need for two `op-dispute-mon` instances during the transition period [#20476](https://github.com/ethereum-optimism/ecosystem/issues/20476).

### `op-supernode` L1 Verification Logic
An issue was raised regarding `op-supernode`'s `VerifiedRequiredL1` calculation, which currently uses the minimum of per-chain `verifiedL1` values instead of the maximum. This could lead to incorrect reporting of the required L1 verification status. It was also noted that acceptance tests for this functionality are pending migration [#20481](https://github.com/ethereum-optimism/ecosystem/issues/20481).

# ethereum-optimism/ecosystem Daily Update (Apr 14, 2026)
## OVERVIEW 
Today, the ecosystem repository saw significant progress in streamlining Docker build processes by migrating to a JSON-based configuration. Several issues related to Network Upgrade Transactions (NUTs) and Kona-node L2CM work were closed, indicating a push towards consolidation and completion of ongoing tasks.

## KEY TECHNICAL DEVELOPMENTS

*   **Streamlined Docker Build Configuration:** The Docker build matrix has been refactored to use a centralized `images.json` file, improving maintainability and consistency across builds. This change also updates the `build.yaml` workflow to leverage the `detect-changes` composite action. ([#993](https://github.com/ethereum-optimism/ecosystem/pull/993))

## ACTIVE ISSUES

*   **Support multiple sequencer RPC endpoints for transaction forwarding** ([#763](https://github.com/ethereum-optimism/ecosystem/issues/763)): The discussion revolves around the best approach to achieve reliability for sequencer RPC endpoints. While the initial proposal involved adding client-side failover within `op-geth`, recent comments suggest leveraging existing generic proxy solutions like HAProxy, Nginx, Envoy Proxy, or Caddy. It's argued that these external tools are more pragmatic, widely available, and avoid adding bespoke failover logic to `op-geth`, allowing operators to use familiar infrastructure. A strong suggestion was made to use `proxyd` for its routing strategies. The original proponent of the client-side solution highlighted that it provides defense-in-depth against CDN failures, complementing infrastructure-level redundancy.

## ACTIVE ISSUES

*   **Withdrawal Proofs and Chain-Specific Root Claims**:
    *   Discussion on [#18517](https://github.com/ethereum-optimism/ecosystem/issues/18517) regarding proving withdrawals using chain-specific root claims highlighted that while `OptimismPortalInterop` changes are complete, `OptimismPortal2` cannot be updated until U19 is executed. The issue was moved to the backlog, emphasizing the need for a separate protocol upgrade for `OptimismPortal2` after FaultDisputeGames support the new `rootClaimByChainId(uint256)` method to avoid user delays.

*   **`op-supernode` SyncStatus API**:
    *   Further discussion on [#18947](https://github.com/ethereum-optimism/ecosystem/issues/18947) clarified the requirements for the `op-supernode` SyncStatus API. It should include the `op-node` SyncStatus for every chain, the sync status of every verification activity, and for interop activity, the latest verified timestamp and the current L1. Additionally, it was suggested that SyncStatus should report the latest verified L2 to simplify acceptance testing.

*   **`op-alloy` EIP-1559 Parameters Decoding Fix**:
    *   On [#18951](https://github.com/ethereum-optimism/ecosystem/issues/18951), a community member expressed interest in taking on the task of fixing EIP-1559 parameters decoding to properly catch zero elasticities at the `op-alloy` level, ensuring early failure detection.

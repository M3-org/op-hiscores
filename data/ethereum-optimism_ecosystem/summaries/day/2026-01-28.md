## ACTIVE ISSUES

### OptimismPortal Withdrawal Proofs
Discussion on [#18517](https://github.com/ethereum-optimism/ecosystem/issues/18517) regarding proving withdrawals using chain-specific root claims highlighted a dependency on the U19 upgrade and the `FaultDisputeGames` supporting a new `rootClaimByChainId(uint256)` method. The issue has been moved to the backlog, as the `OptimismPortal2` upgrade must occur separately from the `FaultDisputeGame` upgrade to prevent withdrawal delays for users.

### op-supernode SyncStatus API
The discussion on [#18947](https://github.com/ethereum-optimism/ecosystem/issues/18947) for introducing a `SyncStatus` API in `op-supernode` clarified the required interface. It should include the `op-node SyncStatus` for every chain, the sync status of every verification activity, and for interop activity, the latest verified timestamp and the current L1. Additionally, the `SyncStatus` should report on the latest verified L2 to simplify acceptance testing.

### op-alloy EIP-1559 Parameter Decoding
On [#18951](https://github.com/ethereum-optimism/ecosystem/issues/18951), which addresses fixing EIP-1559 parameter decoding in `op-alloy`, a community member expressed interest in taking on the task, indicating potential progress on this issue. The goal is to catch zero elasticities during decoding at the `op-alloy` level to ensure early failure.

# ethereum-optimism/ecosystem Daily Update (May 5, 2026)
## OVERVIEW 
Today's development focused on standardizing CI image builds and addressing several long-standing issues, including an `op-node` sync problem and the removal of the `ProtocolVersions` contract.

## KEY TECHNICAL DEVELOPMENTS

### CI/CD Pipeline Enhancements
*   Standardized image builds by migrating the `build-images.yaml` workflow to a unified factory plan action, improving consistency and efficiency in the CI pipeline ([#1006](https://github.com/ethereum-optimism/ecosystem/pull/1006)).

## NEWLY OPENED PULL REQUESTS
No new pull requests were opened today.

## CLOSED ISSUES

### `op-node` Synchronization Fixes
*   The issue where `op-node` was getting stuck in EL sync mode after a restart when Reth already had synced data has been resolved with recent fixes to stabilize `op-node` driving `op-reth` ([#18468](https://github.com/ethereum-optimism/ecosystem/issues/18468)).

### Contract Removal and Simplification
*   The `ProtocolVersions` contract and its associated deployment paths have been successfully removed, simplifying the contract architecture now that `op-node` no longer monitors it ([#20309](https://github.com/ethereum-optimism/ecosystem/issues/20309)).

## NEW ISSUES

### `op-challenger` Flag Consolidation
*   A new issue has been opened to consolidate per-VM flags into global flags within `op-challenger` to streamline configuration, though it's noted that different game types may require distinct config file formats ([#20547](https://github.com/ethereum-optimism/ecosystem/issues/20547)).

### `op-node` Superroot Support
*   A new issue proposes adding support for `superroot_atTimestamp` in `op-node` for non-interop chains, which is crucial for fault dispute games after the super-roots upgrade ([#20552](https://github.com/ethereum-optimism/ecosystem/issues/20552)).

## ACTIVE ISSUES

### `alloy-op-evm` Field Review
*   Discussion continues on whether to drop the `sender` and `evm_gas_used` fields from `OpTxResult` in `alloy-op-evm` as they currently have no consumers. A recent comment suggests `evm_gas_used` might be utilized in an open pull request ([#20463](https://github.com/ethereum-optimism/ecosystem/issues/20463)).

### SDM PoC2 Functionality
*   Progress on moving PoC2 functionality into `develop` is ongoing. The latest update indicates that acceptance tests and benchmarking tooling are still outstanding for this effort ([#20216](https://github.com/ethereum-optimism/ecosystem/issues/20216)).

# ethereum-optimism/ecosystem Weekly Report (Apr 12 - 18, 2026)

## 🚀 Highlights
This week focused on optimizing core infrastructure and consolidating protocol upgrade mechanisms. Significant progress was made in streamlining the Docker build pipeline through centralized configuration, enhancing maintainability across the repository. The team also reached a major milestone in Network Upgrade Transaction (NUT) implementation, completing the `op-node` bundle work and consolidating `kona-node` L2CM tasks. These efforts collectively improve the reliability of the OP Stack's deployment workflows and protocol upgrade execution.

## 🛠️ Key Developments

### CI/CD & Build Infrastructure
The project underwent a significant refactor of its containerization strategy to improve consistency and developer experience.
*   **Docker Build Migration:** The Docker build matrix was migrated to a centralized `images.json` configuration. This refactor simplifies the `build.yaml` workflow by leveraging the `detect-changes` composite action, ensuring more efficient and maintainable image builds ([#993](https://github.com/ethereum-optimism/ecosystem/pull/993), [#994](https://github.com/ethereum-optimism/ecosystem/issues/994)).
*   **Security & Publishing:** Efforts to modernize the release pipeline include a transition to a trusted publisher model ([#992](https://github.com/ethereum-optimism/ecosystem/pull/992)) and routine security maintenance via dependency updates for `follow-redirects` ([#991](https://github.com/ethereum-optimism/ecosystem/pull/991)).

### Protocol & Node Implementation
Work continued on refining how the OP Stack handles network upgrades and transaction execution.
*   **NUT Bundle Completion:** All work related to updating `op-node` to read and execute Network Upgrade Transactions (NUTs) from JSON has been completed ([#18835](https://github.com/ethereum-optimism/ecosystem/issues/18835)).
*   **Kona-node Consolidation:** The `kona-node` L2CM (L2 Chain Manager) work, specifically regarding upgrade gas mechanisms and NUT transaction execution, was consolidated into a single tracking issue to better manage the remaining implementation steps ([#20081](https://github.com/ethereum-optimism/ecosystem/issues/20081)).

## 🐛 Issues & Triage

### Closed Issues
*   **Workflow Cleanup:** A series of issues related to the legacy Docker build workflow were closed as the project successfully migrated to the new JSON-based system ([#20058](https://github.com/ethereum-optimism/ecosystem/issues/20058), [#20059](https://github.com/ethereum-optimism/ecosystem/issues/20059), [#784](https://github.com/ethereum-optimism/ecosystem/issues/784)).
*   **Feature Consolidation:** Several granular issues regarding `kona-node` gas mechanisms and JSON execution were merged into a unified tracking effort to reduce project management overhead ([#18831](https://github.com/ethereum-optimism/ecosystem/issues/18831), [#18836](https://github.com/ethereum-optimism/ecosystem/issues/18836)).

### New & Active Issues
*   **Sequencer Redundancy:** A significant technical discussion is ongoing regarding support for multiple sequencer RPC endpoints for transaction forwarding in `op-geth` ([#763](https://github.com/ethereum-optimism/ecosystem/issues/763)). The current consensus is shifting away from building bespoke failover logic within the client, favoring the use of industry-standard infrastructure tools like HAProxy, Nginx, or Envoy to handle load balancing and health checks.

## 💬 Community & Collaboration
The week's activity reflects a strong emphasis on architectural consensus and infrastructure best practices. The discussion surrounding sequencer RPC endpoints ([#763](https://github.com/ethereum-optimism/ecosystem/issues/763)) highlights a collaborative effort to balance client-side resilience with established infrastructure-level solutions. Furthermore, the consolidation of multiple tracking issues into centralized tasks suggests an active effort by maintainers to streamline the contribution pipeline and provide clearer roadmaps for protocol-level features like NUTs and `kona-node` development.

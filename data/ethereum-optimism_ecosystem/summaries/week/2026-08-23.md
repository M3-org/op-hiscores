# ethereum-optimism/ecosystem Weekly Report (Aug 23 - 29, 2026)

## 🚀 Highlights
This week focused heavily on repository consolidation and the technical refinement of the Superchain interop stack. A major audit of the ecosystem's starter repositories was completed, paving the way for a streamlined developer experience by merging redundant examples into a unified `superchain-starter` repo. On the protocol side, engineers addressed critical stability issues within the Kona node and `op-supernode`, specifically targeting sequencer wedges and cross-chain safety. While significant progress was made in identifying architectural gaps in the sequencer's engine client, execution on repository archiving remains temporarily blocked by organizational permission requirements.

## 🛠️ Key Developments

### Ecosystem Cleanup & Documentation
Efforts this week centered on reducing technical debt and improving the discoverability of developer resources through repository consolidation and documentation updates.
*   **Starter Repo Consolidation:** A comprehensive migration analysis ([#1015](https://github.com/ethereum-optimism/ecosystem/issues/1015)) recommended merging five `superchain-starter*` repositories into a single entity to simplify maintenance. The `superchainerc20-starter` will remain independent due to its unique nature and high adoption.
*   **Superseded Application Removal:** The `autorelayer-interop` application was officially removed as it has been superseded by newer tooling ([#1018](https://github.com/ethereum-optimism/ecosystem/pull/1018)).
*   **Documentation Maintenance:** A new PR ([#1019](https://github.com/ethereum-optimism/ecosystem/pull/1019)) was opened to update the `README` with current supported surface information, ensuring developers have accurate entry points to the ecosystem.

## 🐛 Issues & Triage

### Closed Issues
*   **Supernode Interop Stability:** Issue [#22325](https://github.com/ethereum-optimism/ecosystem/issues/22325) regarding `op-supernode` cross-safe wedges was closed. Investigation revealed the root cause was a parent-hash mismatch on a specific chain (901) causing batch rejection, rather than a systemic cross-safety bug.
*   **Kona Configuration Leniency:** The team decided to maintain leniency in `RollupConfig` for unknown keys in Kona ([#22682](https://github.com/ethereum-optimism/ecosystem/issues/22682)). This supports retired keys and ensures compatibility with the superchain-registry.

### New & Active Issues
*   **Kona Node Sequencer Stability:** A critical wedge in the `forkchoiceUpdated` loop is being addressed ([#22681](https://github.com/ethereum-optimism/ecosystem/issues/22681)). While a partial fix is in progress ([#22686](https://github.com/ethereum-optimism/ecosystem/pull/22686)), three significant gaps remain: lack of timeouts in the `QueuedSequencerEngineClient`, `SealTask` errors failing to trigger resets, and parent-selection lag.
*   **Network Stalls:** Investigation is ongoing into `NetworkActor` stalls during remote-signer HTTP calls ([#22646](https://github.com/ethereum-optimism/ecosystem/issues/22646)). Developers are planning to test injected latency to confirm if these calls are blocking the p2p swarm.
*   **SuperchainERC20 Tooling:** A new requirement emerged ([#1020](https://github.com/ethereum-optimism/ecosystem/issues/1020)) to provide a supported method for developers to verify if a token address is SuperchainERC20 compatible, as this functionality was lost during the archiving of older repositories.
*   **Archiving Blockers:** The archiving of four "dead" repositories (`superchainerc20-compatibility`, `optimism-starter`, `scaffold-op`, `optimism-mud-starter`) is currently pending org-admin permissions, though the impact audit is complete ([#1017](https://github.com/ethereum-optimism/ecosystem/issues/1017)).

## 💬 Community & Collaboration
The week demonstrated strong internal coordination between protocol engineers and developer relations. The audit of starter examples ([#1014](https://github.com/ethereum-optimism/ecosystem/issues/1014)) involved a detailed cross-reference check against live documentation, ensuring that the proposed repository deletions would not result in broken links for the community. Furthermore, the Kona node issues saw active engagement from contributors offering to reproduce sequencer stalls using latency injection, highlighting a collaborative approach to debugging complex p2p and networking issues.

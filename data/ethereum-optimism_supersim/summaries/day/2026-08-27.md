## CLOSED ISSUES

### Supernode Interoperability Issue Resolved
The issue [#22325](https://github.com/ethereum-optimism/supersim/issues/22325), concerning `op-supernode` cross-safe wedges after invalid-message replacement, was closed. Analysis revealed it was a single occurrence in 7.5 weeks, with the root cause identified as chain 901 rejecting batches due to a parent-hash mismatch after a reorg. The issue is now linked to an existing oscillation problem rather than a distinct cross-safety bug.

### Rollup Configuration Leniency Confirmed
Issue [#22682](https://github.com/ethereum-optimism/supersim/issues/22682), regarding `kona-genesis` silently accepting unknown `rollup.json` keys, was closed as "not planned." The leniency is deliberate to support loading configurations with retired keys, and superchain-registry config tests cover fields not yet modeled by Kona.

## NEW ISSUES

### Automating OP Stack Upgrades
A new issue, [#425](https://github.com/ethereum-optimism/supersim/issues/425), was created to automate the OP Stack upgrade cadence for `supersim`, highlighting that the monorepo pin was 14 months stale before the recent upgrade.

### Kona-node Sequencer Wedging
Issue [#22681](https://github.com/ethereum-optimism/supersim/issues/22681) was opened, reporting that a `kona-node` sequencer can get permanently wedged in a `forkchoiceUpdated` loop when the engine reorgs its unsafe head while the sequencer has a block building.

### SuperchainERC20 Compatibility Gap
A new issue, [#1020](https://github.com/ethereum-optimism/supersim/issues/1020), was created to track the lack of a supported way for developers to check SuperchainERC20 token compatibility, a capability previously offered by an archiving repository.

## ACTIVE ISSUES

### Kona-node NetworkActor Stalling
In [#22646](https://github.com/ethereum-optimism/supersim/issues/22646), the discussion revolves around `NetworkActor` stalling the p2p swarm during remote-signer HTTP calls. A contributor expressed interest in picking up the issue, asking for clarification on overflow policy and whether a proposed deadline change could be landed separately from larger restructuring. They also plan to confirm the stalling behavior with injected latency.

### Starter Examples Documentation Audit
Issue [#1014](https://github.com/ethereum-optimism/supersim/issues/1014) saw a comprehensive update confirming that no live documentation links any of the six starter repos or four archive-sweep repos, meaning archiving them will not break published docs. The sweep also identified a small number of cross-references in READMEs that would need fixing if certain repos are archived.

### Consolidating Starter Examples
In [#1015](https://github.com/ethereum-optimism/supersim/issues/1015), a migration analysis was provided, recommending consolidating five `superchain-starter*` repos into the existing `superchain-starter` repo, while leaving `superchainerc20-starter` independent due to its distinct nature and popularity. The analysis suggests a plain copy with pointers to originals for history preservation and notes that the fix-up list for inbound links is small.

### Archive Sweep for Abandoned Repos
Issue [#1017](https://github.com/ethereum-optimism/supersim/issues/1017) received an update confirming that no live documentation links any of the four repos targeted for archiving. The issue also detailed the original purpose of `superchainerc20-compatibility` and noted that its `SuperchainTokenBridge` checks are currently obsolete but might become relevant again if a pending PR to revive `SuperchainTokenBridge` lands. The main blocker for archiving is permissions.

# ethereum-optimism/superchain-registry Weekly Report (Jul 12 - 18, 2026)

## 🚀 Highlights
This week focused on refining registry configurations and streamlining internal CI/CD workflows to improve protocol team responsiveness. Significant effort was directed toward resolving architectural debt within the dispute game framework and the `op-e2e` testing suite. While operational maintenance remained steady, active technical discussions highlighted a push for better synchronization with the `revm` ecosystem and the eventual retirement of legacy testing components to improve long-term system stability.

## 🛠️ Key Developments

### Registry & Configuration Maintenance
The team performed routine but essential maintenance on registry configurations to ensure accuracy across devnets and improve operational visibility.
*   **Devnet Cleanup:** Removed the deprecated `protocol_versions_addr` from the `sepolia-devnet-2` configuration. This address was redundant as the devnet was initialized with OPCM v2 ([#1288](https://github.com/ethereum-optimism/superchain-registry/pull/1288)).
*   **CI/CD Optimization:** Updated CircleCI configurations to specifically tag the Protocol team for daily codegen jobs and run failures, ensuring faster intervention when automated tasks fail ([#1287](https://github.com/ethereum-optimism/superchain-registry/pull/1287)).

### Protocol & Tooling Evolution
Discussions progressed on aligning the Superchain's foundational tools with broader Ethereum ecosystem updates.
*   **`op-revm` Support:** Efforts are underway to ensure Hardhat 3’s OP Stack support (specifically for Glamsterdam) remains current. This involves coordinating new releases of the `op-revm` crate to stay in sync with upstream `revm` changes.

## 🐛 Issues & Triage

### Closed Issues
*   **RPC Binding Defaults:** The proposal to change the default RPC binding from `0.0.0.0` to `127.0.0.1` was closed as "not planned." The team determined that `0.0.0.0` is the standard for Docker-based deployments, and security risks are better mitigated by making privileged APIs opt-in rather than changing network defaults ([#16487](https://github.com/ethereum-optimism/superchain-registry/issues/16487)).

### Active Issues & Technical Debt
*   **Dispute Game Simplification:** A proposal is gaining traction to add `closeGame()` to the generic `IDisputeGame` interface. This would allow `op-challenger` to more efficiently handle permissioned dispute games and update the `AnchorStateRegistry` after finalization ([#21678](https://github.com/ethereum-optimism/superchain-registry/issues/21678), [#21708](https://github.com/ethereum-optimism/superchain-registry/issues/21708)).
*   **Testing Stability:** The `reth-optimism-node` integration tests continue to be plagued by non-deterministic SIGSEGVs during teardown ([#20973](https://github.com/ethereum-optimism/superchain-registry/issues/20973)). Additionally, work is being consolidated to retire the in-process `op-geth` L2 execution engine in `op-e2e` tests, which will likely involve deleting legacy pre-Regolith tests to unblock CI improvements ([#21451](https://github.com/ethereum-optimism/superchain-registry/issues/21451), [#21744](https://github.com/ethereum-optimism/superchain-registry/issues/21744)).
*   **Kona Soundness:** The review of host game input and witness generation was reopened following the discovery of missing retry logic in the `OPSuccinctDataFetcher` ([#18430](https://github.com/ethereum-optimism/superchain-registry/issues/18430)).

## 💬 Community & Collaboration
Collaboration this week was characterized by deep technical triage involving long-standing protocol issues. Contributors like **pauldowman** and **Wodann** were instrumental in driving discussions regarding the `IDisputeGame` interface and `op-revm` release cycles, respectively. The interaction between the Protocol team and tooling maintainers (such as the Hardhat team) remains a high priority to ensure the developer experience stays seamless as new network upgrades roll out.

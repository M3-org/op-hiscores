# ethereum-optimism/superchain-registry Weekly Report (Jun 28 - Jul 4, 2026)

## 🚀 Highlights
This week, the Superchain Registry focused on maintaining data integrity through consistent automated updates while addressing critical operational issues following the Karst hard fork. Development activity was characterized by routine codegen maintenance and deep-dive troubleshooting into gas estimation failures on Optimism Sepolia. Significant community attention was also directed toward refining node synchronization configurations for pruned execution clients to prevent sync failures in the Superchain ecosystem.

## 🛠️ Key Developments

### Automated Registry Maintenance
The primary technical activity this week involved routine maintenance of the registry's generated code. These updates ensure that the registry remains synchronized with the latest chain configurations and metadata across the Superchain.
*   **Codegen Updates**: A series of automated pull requests were opened to refresh the registry's codebase, including [#1270](https://github.com/ethereum-optimism/superchain-registry/pull/1270), [#1271](https://github.com/ethereum-optimism/superchain-registry/pull/1271), and [#1272](https://github.com/ethereum-optimism/superchain-registry/pull/1272).

## 🐛 Issues & Triage

### New & Active Issues
The week was marked by two significant technical hurdles affecting node operators and developers within the ecosystem:

*   **Optimism Sepolia Intrinsic Gas Anomalies**: Following the Karst hard fork, developers reported an "intrinsic gas too high" error ([#21457](https://github.com/ethereum-optimism/superchain-registry/issues/21457)). The issue specifically impacts `eth_estimateGas` for `depositToken` calls, returning a -32000 error code even when `staticCall` succeeds. While a workaround exists (manually setting a `gasLimit`), the team is tracking a potential fix in the core `optimism` repository ([#21574](https://github.com/ethereum-optimism/optimism/pull/21574)).
*   **Syncmode Configuration for Pruned Nodes**: A critical discussion emerged regarding the `syncmode.offset-el-safe` parameter ([#21465](https://github.com/ethereum-optimism/superchain-registry/issues/21465)). Contributors identified that the default 12-hour offset in `op-node/v1.19.1` causes sync failures for nodes using minimal/pruned execution layers. There is an active proposal to either automate this offset to 0 for pruned nodes or update documentation to prevent EL sync failures.

# ethereum-optimism/superchain-registry Weekly Report (Mar 22 - 28, 2026)

## 🚀 Highlights
This week, development focused on hardening the L2 Contract Management (L2CM) framework and ensuring the registry remains synchronized with the latest protocol releases. Key achievements included the integration of `op-contracts` v6.0.0 and `kona-client` 1.2.13 prestates into standard validation files for Mainnet and Sepolia. Significant progress was also made in stabilizing the CI/CD pipeline by addressing flaky tests and refining the tooling for deterministic JSON NUT bundles, which are critical for secure, verifiable L2 upgrades across the Superchain.

## 🛠️ Key Developments

### Registry & Validation Updates
The registry was updated to reflect the latest standard configurations, ensuring that downstream tools and chains have access to verified contract references and prestates.
*   **Op-Contracts v6.0.0:** Added v6.0.0 validation TOML files for both Mainnet and Sepolia, maintaining compatibility with the latest contract releases ([#1204](https://github.com/ethereum-optimism/superchain-registry/pull/1204)).
*   **Kona-Client Integration:** Added prestates for `kona-client` 1.2.13 to the `validation/standard` directory ([#1205](https://github.com/ethereum-optimism/superchain-registry/pull/1205)).

### L2CM Tooling & Infrastructure
Substantial work went into the L2 Contract Management (L2CM) system to improve the developer experience and upgrade safety.
*   **Deterministic Upgrade Bundles:** Resolved issues surrounding the generation of deterministic JSON NUT bundles. This included implementing a Solidity script and new `just` commands for the generation, update, and verification of these bundles ([#18834](https://github.com/ethereum-optimism/superchain-registry/issues/18834), [#18840](https://github.com/ethereum-optimism/superchain-registry/issues/18840)).
*   **Testing Enhancements:** Improved the testing infrastructure by adding a `just` command specifically for running L2 upgrade fork tests ([#18841](https://github.com/ethereum-optimism/superchain-registry/issues/18841)).
*   **Feature Flags:** Implemented support for developer feature flags within the L2 upgrade system, enabling more flexible testing on alphanets ([#18838](https://github.com/ethereum-optimism/superchain-registry/issues/18838)).

## 🐛 Issues & Triage

### Closed Issues
*   **Access Control & Refactoring:** Completed the addition of `ProxyAdminOwnedBase` access control to L2CM predeploy initialization ([#19313](https://github.com/ethereum-optimism/superchain-registry/issues/19313)). Conversely, a proposal to refactor `L2ProxyAdmin` to the `Initializable` pattern was closed after determining the change was unnecessary ([#19182](https://github.com/ethereum-optimism/superchain-registry/issues/19182)).
*   **Test Stability:** Two significant flaky tests, `TestCLELDivergence` and `TestPreinteropFaultProofs_TraceExtensionActivation`, were addressed. The latter involved resolving a specific nonce race condition ([#19681](https://github.com/ethereum-optimism/superchain-registry/issues/19681), [#19760](https://github.com/ethereum-optimism/superchain-registry/issues/19760)).

### New & Active Issues
*   **Breaking Change in op-geth:** A new issue was reported regarding a breaking change in `StorageKeys` within `op-geth` v1.101701.0, where empty arrays are returning `null` instead of `[]` ([#780](https://github.com/ethereum-optimism/superchain-registry/issues/780)).
*   **Upgrade Safety Concerns:** Ongoing analysis of L2CM ([#19260](https://github.com/ethereum-optimism/superchain-registry/issues/19260)) revealed a structural gap in how implementation deployments are tracked across data structures. While an initial bug regarding `L2DevFeatureFlags` was fixed, developers are investigating a "latent `ConditionalDeployer` issue" that could impact future upgrade safety.
*   **Protocol Logic:** Discussions continue regarding the transition to proving withdrawals using chain-specific root claims ([#18517](https://github.com/ethereum-optimism/superchain-registry/issues/18517)) and documenting mempool eviction behavior for interop transactions during reorgs ([#19351](https://github.com/ethereum-optimism/superchain-registry/issues/19351)).

## 💬 Community & Collaboration
The week's activity highlights a strong focus on technical debt and protocol correctness. Collaboration was particularly evident in the L2CM workstream, where deep architectural analysis was performed to identify structural risks in the upgrade pipeline. Maintainers also demonstrated active triage by closing out legacy refactoring proposals that no longer aligned with current project needs, ensuring the codebase remains lean and focused on the Superchain's security and interoperability goals.

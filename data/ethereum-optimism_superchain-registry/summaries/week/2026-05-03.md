# ethereum-optimism/superchain-registry Weekly Report (May 3 - 9, 2026)

## 🚀 Highlights
This week focused on hardening the infrastructure for interoperability (interop) and refining the supernode architecture. Significant progress was made in validating the interop expiry window through successful stress testing on Kona, confirming that a 7-day window is viable for production. The team also streamlined the protocol by removing legacy contracts and resolving critical synchronization issues in `op-node`. These efforts collectively advance the Superchain’s transition toward a more robust, multi-chain environment powered by super-roots and fault dispute games.

## 🛠️ Key Developments

### Interoperability and Supernode Infrastructure
The team addressed several foundational requirements for the upcoming interop release, focusing on chain creation and data handling.
*   **Chain Management:** Ensured that new chains can be successfully created in a post-interop environment ([#15884](https://github.com/ethereum-optimism/superchain-registry/issues/15884)).
*   **Supernode Enhancements:** Implemented "SuperRoots for the unsafe" to improve how `op-supernode` handles unfinalized data ([#19059](https://github.com/ethereum-optimism/superchain-registry/issues/19059)) and migrated missing "after head" tests to the supernode suite ([#20370](https://github.com/ethereum-optimism/superchain-registry/issues/20370)).
*   **Prestate Optimization:** Integrated a "fast Kona prestate build" process to accelerate development cycles ([#19057](https://github.com/ethereum-optimism/superchain-registry/issues/19057)).

### Protocol Cleanup and Maintenance
Routine maintenance and the removal of technical debt ensured the registry remains performant.
*   **Contract Deprecation:** Successfully removed the `ProtocolVersions` contract and its associated deployment paths, as `op-node` no longer requires this data ([#20309](https://github.com/ethereum-optimism/superchain-registry/issues/20309)).
*   **Automated Registry Updates:** A series of automated codegen updates were processed to keep `addresses.json` synchronized with the latest network state ([#1220](https://github.com/ethereum-optimism/superchain-registry/pull/1220), [#1221](https://github.com/ethereum-optimism/superchain-registry/pull/1221), [#1222](https://github.com/ethereum-optimism/superchain-registry/pull/1222)).

## 🐛 Issues & Triage

### Closed Issues
*   **Node Stability:** Resolved a critical bug where `op-node` would become stuck in Execution Layer (EL) sync mode after a restart, specifically improving stability when driving `op-reth` ([#18468](https://github.com/ethereum-optimism/superchain-registry/issues/18468)).
*   **Challenger Refinement:** Fixed a configuration error in `op-challenger` where `SuperPermissionedGameType` was incorrectly pointing to Cannon prestate URLs instead of Kona ([#20500](https://github.com/ethereum-optimism/superchain-registry/issues/20500)).

### New & Active Issues
*   **Superroot Support for Legacy Chains:** A new priority has emerged to support `superroot_atTimestamp` for non-interop chains ([#20552](https://github.com/ethereum-optimism/superchain-registry/issues/20552)). This is essential for enabling fault dispute games on existing chains before the full interop upgrade.
*   **Flag Consolidation:** Discussions are underway regarding consolidating per-VM flags into global flags within `op-challenger` ([#20547](https://github.com/ethereum-optimism/superchain-registry/issues/20547)). However, maintainers noted that distinct configurations for `op-program` and `kona` may necessitate keeping some flags separate.
*   **Interop Stress Testing:** Live devnet testing confirmed that Kona interop running in Cannon/MIPS scales linearly with message count, providing the green light for a 7-day expiry window ([#15285](https://github.com/ethereum-optimism/superchain-registry/issues/15285)).

## 💬 Community & Collaboration
Technical coordination this week was characterized by deep architectural discussions between core contributors like **ajsutton**, **inphi**, and **maurelian**. Notable collaboration occurred around the "Super Root Chain Update" runbook ([#20473](https://github.com/ethereum-optimism/superchain-registry/issues/20473)), where the team decided to defer documentation for permissionless transitions until after the interop launch to avoid blocking current releases. There is also ongoing coordination regarding `alloy-op-evm` field removals, where contributors are carefully checking cross-repository dependencies to avoid breaking ongoing PRs ([#20463](https://github.com/ethereum-optimism/superchain-registry/issues/20463)).

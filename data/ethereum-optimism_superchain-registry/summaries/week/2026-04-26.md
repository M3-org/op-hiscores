# ethereum-optimism/superchain-registry Weekly Report (Apr 26 - May 2, 2026)

## 🚀 Highlights
This week focused on hardening the Superchain's infrastructure through critical CI/CD reliability upgrades and refined configuration management. Key achievements included the integration of World Chain (Jovian Sepolia and Mainnet) into the registry and the completion of the Bundle Canonicalization process for L2CM upgrades to minimize human error during hardforks. While the team successfully resolved stability issues in the Kona testing suite, ongoing challenges remain regarding flaky reorg tests and trait conflicts in the `op-alloy` dependency.

## 🛠️ Key Developments

### Superchain Configuration & Registry Management
The registry underwent significant updates to reflect the current state of the ecosystem, focusing on both expansion and deprecation of chain configurations.
*   **World Chain Integration:** Successfully added configurations for World Chain Jovian Sepolia and Mainnet ([#1208](https://github.com/ethereum-optimism/superchain-registry/pull/1208)).
*   **Base Configuration Cleanup:** Removed outdated configurations for Base Mainnet, Sepolia, and Sepolia-dev-0 to maintain registry hygiene ([#1212](https://github.com/ethereum-optimism/superchain-registry/pull/1212)).
*   **L2CM Upgrade Refinement:** Completed the Bundle Canonicalization process, providing a manual trigger for updating bundled NUTs per hardfork with automated CI checks ([#19307](https://github.com/ethereum-optimism/superchain-registry/issues/19307)).

### CI/CD Infrastructure & Security
Efforts were made to increase the visibility of pipeline failures and strengthen the security of automated workflows.
*   **Pipeline Reliability:** Implemented Slack notifications for `daily-codegen` job failures to prevent silent regressions ([#1211](https://github.com/ethereum-optimism/superchain-registry/pull/1211)).
*   **Security Hardening:** Updated CircleCI configurations by upgrading the `circleci-utils` orb and implementing GitHub authentication contexts across jobs ([#1209](https://github.com/ethereum-optimism/superchain-registry/pull/1209)).
*   **Security Monitoring:** Initiated a new security scan overview for the `main` branch via Wiz ([#1213](https://github.com/ethereum-optimism/superchain-registry/issues/1213)).

### Protocol & Dependency Updates
*   **Optimism Dependency Bump:** Imported a critical fix for `op-fetcher` that prevents crashes by guarding against zero `mipsImpl` values before calling the oracle ([#1210](https://github.com/ethereum-optimism/superchain-registry/pull/1210)).

## 🐛 Issues & Triage

### Closed Issues
*   **Kona Test Stability:** Resolved a crash in the `kona-host-client-offline-cannon` test caused by an incorrect target specification in the cannon-builder. The fix involved correcting the MIPS target JSON and refreshing witness tars ([#19895](https://github.com/ethereum-optimism/superchain-registry/issues/19895)).

### New & Active Issues
*   **Flaky Test `TestReorgUnsafeHead`:** This remains a high-priority blocker. Investigations reveal that asynchronous updates between the StatusTracker and Sequencer lead to stale data. A proposed fix involving polling `SyncStatus` instead of using `time.Sleep` is under evaluation as previous attempts did not fully resolve the flakiness ([#20198](https://github.com/ethereum-optimism/superchain-registry/issues/20198)).
*   **Genesis Sync Issues:** A bug was identified where `safe_l2` and `finalized_l2` are reported as zero on fresh-genesis chains. The root cause appears to be logic that compares only block numbers, failing to distinguish "unset" states from "genesis" blocks ([#20295](https://github.com/ethereum-optimism/superchain-registry/issues/20295)).
*   **`op-alloy` Trait Conflict:** Users are reporting ongoing issues with conflicting `NetworkWallet` implementations. While a fix exists in the `optimism` repository, it has not yet been released to crates.io, leading to discussions regarding the maintainership of the `op-alloy` crate ([#20281](https://github.com/ethereum-optimism/superchain-registry/issues/20281)).

## 💬 Community & Collaboration
Collaboration this week was characterized by deep technical troubleshooting between maintainers (including ajsutton, pauldowman, and karlfloersch) on core protocol edge cases, particularly regarding sync status and reorg logic. There is active coordination between the registry maintainers and the broader Optimism ecosystem to ensure that dependency updates (like `op-alloy` and `op-fetcher`) are synchronized with the needs of downstream users.

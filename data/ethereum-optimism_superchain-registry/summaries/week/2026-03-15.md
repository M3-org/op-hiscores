# ethereum-optimism/superchain-registry Weekly Report (Mar 15 - 21, 2026)

## 🚀 Highlights
This week focused heavily on hardening the Superchain infrastructure through critical configuration corrections and a massive effort to stabilize the CI pipeline. Key achievements included the version correction of dispute games for upcoming contract releases and the resolution of several long-standing flaky tests that were impacting development velocity. Significant progress was also made in refining the Supernode’s reporting accuracy and optimizing test coverage for interoperability features, ensuring a more reliable foundation for the Superchain ecosystem.

## 🛠️ Key Developments

### Protocol Configuration & Bug Fixes
The team addressed a critical versioning discrepancy in the standard versions configuration files. This ensures that the registry accurately reflects the state of the OP Stack's fault proof systems.
*   **Dispute Game Version Correction:** Corrected `fault_dispute_game` and `permissioned_dispute_game` versions from 2.0.0 to 2.2.0 for the `op-contracts/v6.0.0-rc.1` and `op-contracts/v6.0.0-rc.2` releases across Mainnet and Sepolia ([#1202](https://github.com/ethereum-optimism/superchain-registry/pull/1202)).

### Supernode & Interoperability Enhancements
Work continued on improving the reliability and observability of the Supernode, particularly regarding L1 block processing and interop testing.
*   **Reporting Accuracy:** Fixed an issue where the `superroot_atTimestamp` API reported the minimum L1 block processed by derivation rather than the verified block, ensuring more accurate data for users ([#18651](https://github.com/ethereum-optimism/superchain-registry/issues/18651)).
*   **Test Suite Optimization:** Initiated a deduplication effort for Supernode test coverage. A draft PR removed redundant tests in `op-e2e` that are now covered by the shared `superfaultproofs` package in `op-acceptance-tests`, reducing maintenance overhead ([#19010](https://github.com/ethereum-optimism/superchain-registry/issues/19010)).

## 🐛 Issues & Triage

### Closed Issues: CI Stability & Infrastructure
A major push was made to resolve flaky tests that were causing intermittent failures in the CI pipeline.
*   **Flaky Test Resolution:** Resolved issues related to nonce races, sync propagation, and `RetryProxy` timeouts in tests such as `TestBreakTimestampInvariant`, `TestExpiredMessage`, and `TestImplementations`.
*   **Blob Archiver Migration:** Identified a deficiency in the `blob-archiver` regarding `/eth/v1/beacon/blobs/` endpoint support. The issue was triaged and moved to the dedicated `blob-archiver` repository for resolution ([#19623](https://github.com/ethereum-optimism/superchain-registry/issues/19623)).

### New & Active Issues
*   **CI Reliability Tracking:** New issues were opened to investigate persistent flakes in `TestSupernodeInteropChainLag` ([#19610](https://github.com/ethereum-optimism/superchain-registry/issues/19610)) and `TestBroadcastWithSlowClient` ([#19584](https://github.com/ethereum-optimism/superchain-registry/issues/19584)). Additionally, a non-terminating CI job (`memory-all-opn-op-geth`) is under investigation for potential hangs ([#19563](https://github.com/ethereum-optimism/superchain-registry/issues/19563)).
*   **EL Sync UX:** Ongoing discussions regarding `op-node` behavior during initial Execution Layer (EL) sync. The community is evaluating solutions for how the node marks the finalized head, including potential new CLI flags or trusted checkpoint providers ([#17631](https://github.com/ethereum-optimism/superchain-registry/issues/17631)).
*   **Kona-Interop:** Tracking remains open for the `kona-interop` block hash oracle to ensure integration tests cover historical block lookups correctly ([#18288](https://github.com/ethereum-optimism/superchain-registry/issues/18288)).

## 💬 Community & Collaboration
The week's activity demonstrates a high level of internal coordination focused on technical debt and protocol correctness. The discussion surrounding `op-node` synchronization ([#17631](https://github.com/ethereum-optimism/superchain-registry/issues/17631)) shows active collaboration between developers to refine the user experience for node operators. Furthermore, the systematic identification and tracking of CI flakes (over 100 instances across various tests) indicate a disciplined approach to maintaining a healthy contributor environment.

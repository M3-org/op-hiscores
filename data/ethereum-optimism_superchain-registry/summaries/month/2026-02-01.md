# ethereum-optimism/superchain-registry Monthly Report (February 2026)

## 🚀 Highlights
In February 2026, development focused on refining the reliability of the Supernode infrastructure and ensuring configuration parity across the Superchain. Key efforts addressed critical synchronization behaviors in `op-node`, specifically regarding Execution Layer (EL) sync correctness and the handling of unsafe data roots. The registry also saw essential updates to its global configuration to support new security tooling across both Sepolia and Mainnet environments.

## 🛠️ Key Developments

### Superchain Configuration Updates
The registry was updated to incorporate new infrastructure addresses, ensuring that the Superchain ecosystem remains synchronized with the latest security tools.
*   **SaferSafes Integration:** The SaferSafes address was added to the `superchain.toml` configuration files for both Sepolia and Mainnet. This update ensures that the registry accurately reflects the deployment of these security-focused contracts across the ecosystem ([#1197](https://github.com/ethereum-optimism/superchain-registry/pull/1197)).

## 🐛 Issues & Triage

### Resolved Issues
*   **Supernode L1 Polling:** A critical fix was implemented for `op-supernode` regarding L1 polling. Previously, certain HTTP L1 URLs could inadvertently disable polling, preventing virtual nodes from receiving vital L1 head updates. This issue was successfully resolved and closed ([#19012](https://github.com/ethereum-optimism/superchain-registry/issues/19012)).

### New & Active Discussions
*   **EL Sync UX and Correctness:** Significant technical debate continued regarding how `op-node` handles initial EL Sync. Contributors are investigating a bug where the target of an EL sync is marked as "finalized" prematurely. Discussions involve the technical limitations of `op-geth` snap sync versus `op-reth`, with proposed solutions focusing on running derivation from prior L1 blocks to verify alignment with the unsafe chain ([#17631](https://github.com/ethereum-optimism/superchain-registry/issues/17631)).
*   **Unsafe SuperRoots:** A new discussion was initiated regarding whether `op-supernode` should return "SuperRoots" for unsafe data when no verified data exists at a specific timestamp. The community is evaluating the semantic utility of these roots versus the potential for mechanical errors ([#19059](https://github.com/ethereum-optimism/superchain-registry/issues/19059)).
*   **Interop Proofs:** Work on interoperability remains a priority, as evidenced by the reopening of an issue related to skipped acceptance tests. The `TestInteropReadiness` suite currently awaits explicit output root support from the super DG before it can be fully enabled ([#18616](https://github.com/ethereum-optimism/superchain-registry/issues/18616)).

## ACTIVE ISSUES

### Op-Reth CL Sync Recovery Stalling
Discussions on [#21076](https://github.com/ethereum-optimism/superchain-registry/issues/21076) indicate that the `op-supernode/op-reth` CL sync recovery can stall when `SafeDB`/bookkeeping references an EL-missing block. The issue was reproduced and root-caused to a cyclic deadlock in `reth`'s `StateTrieOverlayManager` / `DeferredTrieData` machinery, specifically due to locks held across `rayon` compute operations. A two-patch fix has been implemented and is undergoing soak testing, showing promising results with continuous CL-sync without wedges. The problem is identified as `reth` `chain-state` code, suggesting a fix within `reth` itself.

### SDM Refund Limits
Issue [#20709](https://github.com/ethereum-optimism/superchain-registry/issues/20709) discusses adding a protocol-level upper bound for rebates that the sequencer can issue. The latest comments suggest enforcing `MAX_GAS_LIMIT` regardless of the refund amount, effectively capping the maximum computation the sequencer can perform, even with 100% refunds. It is believed this can be hardcoded in the node software.

### State-Persistent Partial DoS in OptimismPortal2
A comment on [#20820](https://github.com/ethereum-optimism/superchain-registry/issues/20820) regarding a state-persistent partial DoS in `OptimismPortal2` via `ResourceMetering` gas burn exceeding L1 block gas limit was made, but it did not provide further technical details or updates on the resolution.

### CrossDomainMessenger Gas Test
Issue [#14609](https://github.com/ethereum-optimism/superchain-registry/issues/14609) was reopened as there are still TODOs in the codebase referencing it. The issue concerns adding a test to the `CrossDomainMessenger` system that would fail if EVM gas schedule changes cause `relayMessage` to fail. The test requires a stable Foundry release that includes `foundry-rs/foundry#9904` to use `default.isolate = true`.

### Investigation into Flaky Test `TestSupernodeLightSequencerInteropInvalidMessageReplacement`
The issue "[#21635](https://github.com/ethereum-optimism/superchain-registry/issues/21635)" regarding a flaky test has seen significant discussion. The root cause has been identified as an ordering problem in `FollowSource` processing within the light sequencer, where an upstream local-safe head could be processed ahead of the current unsafe head. This led to stale queued build work causing `missing parent header` errors. A draft PR ([ethereum-optimism/optimism#21637](https://github.com/ethereum-optimism/optimism/pull/21637)) has been created to address this by forcing resets of active sequencers on upstream local-safe advances/divergences, emitting reset notifications, clearing stale build states, and dropping stale queued build-start events. The fix has been reviewed and verified with high confidence.

### Review and Decision on Fuzzing Strategy
The issue "[#21636](https://github.com/ethereum-optimism/superchain-registry/issues/21636)" discusses the future of fuzzing. An audit of all Go fuzz tests revealed that current CI jobs run time-bounded exploration without a committed corpus, leading to zero accumulated value. Seeds are sparse, and deterministic value is already covered by normal unit tests. The decision is to retire all six current fuzzing jobs, as they offer low value for their cost and maintenance. The fuzz functions themselves will be kept, running as deterministic seed tests in normal unit test jobs. A nightly fuzzing job is only considered valuable if paired with a committed seed corpus, meaningful fuzz time, and crash-artifact persistence/alerting, and would be scoped to high-value differential targets. This decision is being implemented via PR [#21639](https://github.com/ethereum-optimism/optimism/pull/21639).

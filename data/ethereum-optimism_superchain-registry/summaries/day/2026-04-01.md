# ethereum-optimism/superchain-registry Daily Update (Apr 1, 2026)
## OVERVIEW 
Today's development focused on adding Kona 1.2.12 prestates. Several new issues were opened, primarily addressing various bug fixes across `op-batcher`, `op-node`, `op-service`, and `contracts-bedrock` components. Additionally, three issues were closed, including one related to migrating FaultDisputeGame chains.

## KEY TECHNICAL DEVELOPMENTS

*   **Kona Prestate Updates**
    *   Added prestates for Kona client version 1.2.12, specifically targeting `validation/standard/standard-prestates.toml` [#1206](https://github.com/ethereum-optimism/superchain-registry/pull/1206).

## NEWLY OPENED PULL REQUESTS
No new pull requests were opened today.

## CLOSED ISSUES

*   **Dispute Game Migration**
    *   The issue concerning the migration of one or more FaultDisputeGame chains to SuperDisputeGame has been closed [#19013](https://github.com/ethereum-optimism/superchain-registry/issues/19013). The discussion indicated that this issue was a duplicate and has converged with other related tickets.
*   **Challenger Host Argument Fix**
    *   The issue regarding fixing host arguments in the Kona super executor for `op-challenger` has been closed, as the challenger runner is now successfully running `kona-interop` in tests [#18287](https://github.com/ethereum-optimism/superchain-registry/issues/18287).
*   **Interop Transaction Pool Eviction Documentation**
    *   The issue to document interop transaction pool eviction behavior on reorg has been closed [#19351](https://github.com/ethereum-optimism/superchain-registry/issues/19351).

## NEW ISSUES

*   **`op-batcher` and `op-node` Bug Fixes**
    *   An issue was opened to fix `op-batcher` where the oldest L1 origin was compared against the latest instead of the oldest [#19859](https://github.com/ethereum-optimism/superchain-registry/issues/19859).
    *   Another issue addresses an incorrect channel size calculation in `op-node/derive` when pruning frames after the last frame [#19858](https://github.com/ethereum-optimism/superchain-registry/issues/19858).
    *   A bug in `op-node/p2p` was reported where the gossip publisher does not close `blocksV3`/`blocksV4` on shutdown [#19860](https://github.com/ethereum-optimism/superchain-registry/issues/19860).
*   **`op-service` Type Handling and Error Messaging**
    *   Issues were created to correct `Bytes256.UnmarshalText` reporting the wrong type name (`Bytes32`) [#19862](https://github.com/ethereum-optimism/superchain-registry/issues/19862) and `Blob.UnmarshalText` using the wrong `hexutil` label (`Bytes32`) [#19864](https://github.com/ethereum-optimism/superchain-registry/issues/19864).
    *   A problem was identified in `EthClient.FetchReceipts` where an unused `ToBlockID` result is discarded [#19870](https://github.com/ethereum-optimism/superchain-registry/issues/19870).
    *   A bug in `CachingReceiptsProvider` was reported where it leaks fetching locks on `FetchReceipts` errors [#19875](https://github.com/ethereum-optimism/superchain-registry/issues/19875).
*   **`contracts-bedrock` Error Message Clarity**
    *   An issue highlights that `LivenessModule`'s `minOwners` error message contradicts its `require` statement [#19866](https://github.com/ethereum-optimism/superchain-registry/issues/19866).
    *   Another issue points out that `SystemConfig`'s base fee `require` message contradicts the `<= `check [#19868](https://github.com/ethereum-optimism/superchain-registry/issues/19868).
*   **`kona/protocol` Decoding Error**
    *   An issue was opened to address span batch gas decode errors being incorrectly reported as `TxNonces` in `kona/protocol` [#19873](https://github.com/ethereum-optimism/superchain-registry/issues/19873).

## ACTIVE ISSUES

*   **Document interop tx pool eviction behavior on reorg** [#19351](https://github.com/ethereum-optimism/superchain-registry/issues/19351)
    *   The discussion revolved around the intentional dropping of all interop executing messages from the transaction pool on any reorg, not just those caused by invalid executing messages. @karlfloersch clarified that `op-reth` (which will be canonical behavior) drops all interop transactions for implementation simplicity and stronger safety guarantees. He suggested that if the tx eviction behavior is re-evaluated, the team should consider whether to re-verify all interop transactions explicitly before re-adding them to the mempool.
*   **OPCM: Migrate one or more FaultDisputeGame chains to SuperDisputeGame** [#19013](https://github.com/ethereum-optimism/superchain-registry/issues/19013)
    *   The issue was confirmed to be a duplicate of another ticket and was subsequently closed. @stevennevins agreed to close it, stating that they have converged with other related tickets.
*   **op-challenger: Fix host args in kona super executor** [#18287](https://github.com/ethereum-optimism/superchain-registry/issues/18287)
    *   The issue was closed by @ajsutton, who confirmed that the challenger runner is now successfully running `kona-interop` in tests, indicating the fix has been implemented and verified.

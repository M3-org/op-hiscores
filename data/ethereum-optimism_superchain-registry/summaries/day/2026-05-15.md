**CI Performance Enhancements**

## ACTIVE ISSUES

**Flaky Test: `TestWithdrawal_CannonKona`**
Issue [#19964](https://github.com/ethereum-optimism/superchain-registry/issues/19964) is actively being investigated due to persistent flakiness. The latest comments indicate a new flake variant with a different root cause than previously identified. The current theory points to a race condition where the L2 EL (op-reth) hasn't persisted state at a specific block when a storage proof is immediately requested, leading to "no state found for block" errors. A fix has been opened in ethereum-optimism/optimism#20782 (draft) to wrap the `GetProof` call with a bounded `Eventually` and retry on transient EL errors.

**Flaky Test: `TestELSyncSafeRetractedByOffset`**
Issue [#20334](https://github.com/ethereum-optimism/superchain-registry/issues/20334) continues to experience flakiness related to CrossSafe sync timeouts during preset setup. Recent CI runs show the verifier's safe head lagging the sequencer, leading to an 8-minute timeout. This suggests a recurring timing issue with CrossSafe during ELSync, even after increasing retry attempts.

**Interop Proofs Devnet Deployment**
Issue [#20489](https://github.com/ethereum-optimism/superchain-registry/issues/20489) discusses the deployment of a devnet with SuperRootMigrations and InteropPortal contract feature flags. The latest comment confirms that this network will be used for long-term internal testing and is not planned for immediate shutdown.

**`op-challenger-runner` using `op-reth` for OP Mainnet**
Issue [#19517](https://github.com/ethereum-optimism/superchain-registry/issues/19517) tracks the setup of `op-challenger-runner` with Kona using an `op-reth` node for OP Mainnet to ensure readiness of `op-reth`'s historical proofs support. The latest update indicates that the team is still awaiting `op-reth` nodes with proofs history enabled for mainnet.

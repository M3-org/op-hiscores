# ethereum-optimism/superchain-registry Daily Update (Mar 26, 2026)

## ACTIVE ISSUES

*   **contracts: Prove withdrawals using chain-specific root claim** ([#18517](https://github.com/ethereum-optimism/superchain-registry/issues/18517))
    *   Discussion revolves around whether this issue can be closed, as the approach for proving withdrawals using `rootClaimByChainId` based on game type has reportedly changed and merged. The original plan to update `OptimismPortal2` after U19 execution and `FaultDisputeGames` support for the new method was noted, with a suggestion to move it to the backlog.
*   **[L2CM] Investigate adding an array of predeploys to increase upgrade safety** ([#19260](https://github.com/ethereum-optimism/superchain-registry/issues/19260))
    *   A detailed analysis was provided, highlighting a structural pipeline gap where `L2DevFeatureFlags` was initially omitted from the NUT bundle's deployment transaction list. While this specific bug was fixed, a deeper structural issue remains: the lack of a centralized source of truth for implementation deployments across multiple data structures. The analysis also points out a latent `ConditionalDeployer` issue that could lead to a worse failure mode in future upgrades if not addressed.

    *   A question was raised regarding the behavior of interop transactions already existing in the mempool during a reorg, specifically whether the mempool explicitly iterates and drops them, or if periodic re-evaluation handles this.

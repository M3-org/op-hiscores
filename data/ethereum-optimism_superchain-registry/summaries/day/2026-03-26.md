# ethereum-optimism/superchain-registry Daily Update (Mar 26, 2026)
## OVERVIEW 
Today's development focused on updating validation files for op-contracts and addressing several L2CM upgrade-related issues. Discussions also continued on a flaky test and a potential bug in interop transaction pool eviction.

## NEW ISSUES

### `op-geth` StorageKeys Breaking Change
A new issue was reported regarding a breaking change in `op-geth` `v1.101701.0` where `StorageKeys` values are now `null` instead of `[]`. This is attributed to `SortedFunc` in Go returning `nil` for empty slices. ([#780](https://github.com/ethereum-optimism/superchain-registry/issues/780))

### Flaky Test: `TestPreinteropFaultProofs_TraceExtensionActivation`

## ACTIVE ISSUES

### L2CM Upgrade Safety and Implementation Deployment
Discussion on [#19260](https://github.com/ethereum-optimism/superchain-registry/issues/19260) highlighted a "Structural Pipeline Gap" in the L2CM upgrade process, where `L2DevFeatureFlags` was initially omitted from the NUT bundle's deployment. While a fix has been merged, the deeper concern is the lack of a centralized source of truth for implementations and automated tests to validate completeness across multiple data structures. The issue also points out a latent problem with `ConditionalDeployer` that could lead to a critical failure in future upgrades if not addressed.

### Interop Transaction Pool Eviction Behavior
On [#19351](https://github.com/ethereum-optimism/superchain-registry/issues/19351), a question was raised regarding the behavior of interop transactions in the mempool during a reorg. Specifically, it asks whether the mempool explicitly iterates and drops interop transactions or if periodic re-evaluation handles this.

### Karst-Specific Upgrade Transactions Removal
Issue [#19369](https://github.com/ethereum-optimism/superchain-registry/issues/19369) discusses the removal of Karst-specific upgrade transactions from `GenerateNUTBundle.s.sol` after the Karst upgrade is deployed. The latest comment specifies that `UpgradeUtils.getTransactionCount()` and `GasLimits` struct must also be updated accordingly when these transactions are removed.

### Proving Withdrawals with Chain-Specific Root Claim
Discussion on [#18517](https://github.com/ethereum-optimism/superchain-registry/issues/18517) questioned whether the issue can be closed, suggesting that the approach might have changed to use `rootClaimByChainId` based on the game type. This implies a potential resolution or change in implementation strategy.

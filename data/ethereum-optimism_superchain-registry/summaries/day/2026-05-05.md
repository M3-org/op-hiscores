## CLOSED ISSUES

### `op-node` Sync Mode Stabilization
The issue where `op-node` would get stuck in EL sync mode after a restart, even with synced data, has been closed [#18468](https://github.com/ethereum-optimism/superchain-registry/issues/18468). This was due to implemented fixes aimed at stabilizing `op-node` when driving `op-reth`.

### ProtocolVersions Contract Removal
The task to remove the `ProtocolVersions` contract and its associated deployment paths has been completed and the issue closed [#20309](https://github.com/ethereum-optimism/superchain-registry/issues/20309). This removal was a sibling task under a larger parent issue and was completed via a specific pull request.

## NEW ISSUES

### `op-challenger` Flag Consolidation
A new issue, [#20547](https://github.com/ethereum-optimism/superchain-registry/issues/20547), was opened to consolidate per-VM flags into global flags within `op-challenger`. The problem highlights the current redundancy of having both global and per-game-type flags for similar configurations.

### `op-node` Superroot Support
An issue was created to address `op-node` support for `superroot_atTimestamp` for non-interop chains [#20552](https://github.com/ethereum-optimism/superchain-registry/issues/20552). This is crucial for fault dispute games on non-interop chains after the super-roots upgrade.

### Consolidate Per-VM Flags into Global Flags in `op-challenger` [#20547](https://github.com/ethereum-optimism/superchain-registry/issues/20547)
ajsutton commented on the newly opened issue, explaining that the current pattern of using per-VM flags is intentional because different game types sometimes require distinct configuration file formats, particularly regarding `l2-genesis` for `op-program` and `kona`.

### `op-node`: Support `superroot_atTimestamp` for Non-Interop Chains [#20552](https://github.com/ethereum-optimism/superchain-registry/issues/20552)
ajsutton provided further context and requirements for this new issue, suggesting using the same `--supernode-url` flag and `superroot_atTimestamp` for namespacing to ensure exact compatibility. It was also highlighted that the API should work and return a super root for the single chain `op-node` runs, both pre- and post-upgrade, as super dispute games need to be implemented before interop activation.

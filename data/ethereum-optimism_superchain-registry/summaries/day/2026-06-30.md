## ACTIVE ISSUES
Discussion continued on [#21465](https://github.com/ethereum-optimism/superchain-registry/issues/21465) regarding `default syncmode.offset-el-safe` failing for `--minimal` nodes. A new comment from Creamers158 highlighted that the release notes for `op-node/v1.19.1` are missing a critical detail: for pruned nodes using `--syncmode=execution-layer`, `--syncmode.offset-el-safe=0` is also required. Without this, the default 12-hour offset can reference pruned blocks, leading to EL sync failures. Creamers158 suggested that `offset-el-safe` should either adapt to the execution client's pruning configuration or automatically default to 0 for pruned ELs, or at least the release notes should be updated to reflect this requirement.

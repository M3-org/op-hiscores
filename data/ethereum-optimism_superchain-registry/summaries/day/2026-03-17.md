# ethereum-optimism/superchain-registry Daily Update (Mar 17, 2026)
## OVERVIEW 
Today's development focused on a critical bug fix correcting dispute game versions for v6.0.0 releases and significant progress in addressing several flaky tests across the Optimism ecosystem.

## KEY TECHNICAL DEVELOPMENTS

### Dispute Game Version Correction
A bug fix was implemented to correct the `fault_dispute_game` and `permissioned_dispute_game` versions from 2.0.0 to 2.2.0 in the `standard-versions-mainnet.toml` and `standard-versions-sepolia.toml` files for `op-contracts/v6.0.0-rc.1` and `op-contracts/v6.0.0-rc.2` releases. This ensures accurate versioning for critical dispute game components. ([#1202](https://github.com/ethereum-optimism/superchain-registry/pull/1202))

## NEWLY OPENED PULL REQUESTS
No new pull requests were opened today.

## CLOSED ISSUES

### Flaky Test Resolution
Several flaky tests were investigated and closed today. `TestExpiredMessage` ([#19588](https://github.com/ethereum-optimism/superchain-registry/issues/19588)) and `TestExecMsgDifferTxIndex` ([#19589](https://github.com/ethereum-optimism/superchain-registry/issues/19589)) were found to have a common root cause related to nonce races due to `IncludeTx` bypassing the transaction pool. `TestImplementations` ([#19583](https://github.com/ethereum-optimism/superchain-registry/issues/19583)) was closed after identifying overly tight timeouts in `RetryProxy` and a race condition in its `Start()` function. `TestSuperchain` ([#19586](https://github.com/ethereum-optimism/superchain-registry/issues/19586)) was closed, with the root cause being concurrent execution of subtests leading to resource contention. `TestBreakTimestampInvariant` ([#18137](https://github.com/ethereum-optimism/superchain-registry/issues/18137)) was closed after identifying two independent flake causes: a nonce race and missing sync propagation.

### Supernode Reporting and Glamsterdam Impacts
The issue regarding `op-supernode` reporting the current verified L1 instead of the current derived L1 ([#18651](https://github.com/ethereum-optimism/superchain-registry/issues/18651)) was closed, with a fix implemented in #19441. An investigation into Glamsterdam gas pricing impacts on precompile acceleration ([#19375](https://github.com/ethereum-optimism/superchain-registry/issues/19375)) was closed, with further work being tracked in a separate issue.

### Blob Archiver Endpoint
A newly opened issue regarding the `blob-archiver` not supporting the `/eth/v1/beacon/blobs/` endpoint ([#19623](https://github.com/ethereum-optimism/superchain-registry/issues/19623)) was immediately closed and moved to the `ethereum-optimism/blob-archiver` repository as it was determined to be a `blob-archiver` specific issue.

## ACTIVE ISSUES

### op-node: On the Initial EL Sync UX and Correctness ([#17631](https://github.com/ethereum-optimism/superchain-registry/issues/17631))
Discussion continues on the behavior of `op-node` marking the reached target as finalized after initial EL Sync, even if the block is not actually finalized. Recent comments propose solutions for setting the finalized head, including using a different finalization gadget, a command-line flag, an RPC URL for a trusted checkpoint provider, or an arbitrary delay of 12 hours to 10 days after EL sync finishes. The impact of light CL on this issue and the challenges of re-running derivation on snap-synced nodes were also discussed.

### [tracking]: Review kona-interop block hash oracle ([#18288](https://github.com/ethereum-optimism/superchain-registry/issues/18288))
The discussion on reviewing the `kona-interop` block hash oracle highlights the need for an integration/acceptance test to ensure that block lookups prior to the current history window function correctly.

### Supernode test coverage ([#19010](https://github.com/ethereum-optimism/superchain-registry/issues/19010))
Progress has been made on ensuring comprehensive test coverage for `supernode`. A draft PR has been opened to deduplicate tests in `op-e2e/actions/interop/proofs_test.go`, removing three tests that are already covered by `op-acceptance-tests`. Ten tests remain in `op-e2e` that cover unique scenarios not yet ported to the shared `superfaultproofs` package.

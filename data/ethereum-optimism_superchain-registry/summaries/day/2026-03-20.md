## ACTIVE ISSUES

### Flaky Test: TestCLELDivergence ([#19681](https://github.com/ethereum-optimism/superchain-registry/issues/19681))
- **Discussion:** An in-depth investigation by ajsutton suggests this might be a real bug rather than just a flaky test. The core issue revolves around the `SyncStatus()` polling in the test and how the event system processes `UnsafeUpdateEvent` and `ResetEvent`. The test expects the CL's unsafe head to persist at the target block, but intermittently, the derivation pipeline resets the unsafe head. The question for the team is whether this reset is correct behavior or a bug in the reset logic.

### op-reth: Recurring state root mismatch on Base mainnet ([#19532](https://github.com/ethereum-optimism/superchain-registry/issues/19532))
- **Discussion:** ngotchac suggests the issue might be linked to a known `reth` issue. sebastianst recommends opening the issue on the Base repository, especially since Base recently forked the OP Stack. InoMurko confirms similar issues on custom chains like Manta Pacific.

### non-terminating CI job: memory-all-opn-op-geth ([#19563](https://github.com/ethereum-optimism/superchain-registry/issues/19563))
- **Discussion:** This issue was closed today, but significant discussion occurred prior. ajsutton provided a detailed root cause analysis, identifying a mutex deadlock in `VirtualNode` during shutdown, involving `Test cleanup thread`, `Start()` goroutines, and `Event loop goroutines`. A fix PR ([ethereum-optimism/optimism#19680](https://github.com/ethereum-optimism/optimism/pull/19680)) was created to address this by releasing `v.mu` before calling `inner.Stop()` and adding a defensive timeout. The flakiness was attributed to the specific timing of event processing and mutex acquisition. Multiple occurrences of non-terminating tests were reported, including `TestChallengerRespondsToMultipleInvalidClaimsEOA`, `TestChallengerPlaysGame`, and `TestProposer`. Earlier, ajsutton also opened a draft fix ([https://github.com/ethereum-optimism/optimism/pull/19634](https://github.com/ethereum-optimism/optimism/pull/19634)) for a different aspect of the flakiness related to polling loops and RPC call timeouts. geoknee noted that several PRs might fix this, suggesting to re-evaluate in a few days.

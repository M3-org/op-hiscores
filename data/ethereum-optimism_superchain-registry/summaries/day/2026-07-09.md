# ethereum-optimism/superchain-registry Daily Update (Jul 9, 2026)
## OVERVIEW 
Today's development focused on critical bug fixes related to the Karst upgrade gas flag for several mainnets and significant cleanup by removing dead data related to `protocol_versions_addr`. Dependency updates were also initiated.

## KEY TECHNICAL DEVELOPMENTS

### Critical Bug Fixes for Karst Upgrade
A bug affecting the Karst upgrade gas flag on Metal, Mode, and Zora Mainnets was fixed. The issue stemmed from the `keep_karst_upgrade_gas` flag defaulting to `false` when not explicitly configured, leading to incorrect behavior for node operators. This fix ensures proper configuration for these networks. ([#1281](https://github.com/ethereum-optimism/superchain-registry/pull/1281))

### Superchain Definition Cleanup
The `protocol_versions_addr` field was removed from the `SuperchainDefinition` and all related configurations. This field was identified as dead data since `op-node` no longer reads the ProtocolVersions contract, streamlining the superchain configuration. ([#1280](https://github.com/ethereum-optimism/superchain-registry/pull/1280))

### Dependency Updates
An update to the `optimism` dependency was initiated to pick up updated `op-fetcher` artifacts. This work is currently in draft status due to Go module compatibility issues. ([#1279](https://github.com/ethereum-optimism/superchain-registry/pull/1279))

## ACTIVE ISSUES

### Default Syncmode Offset Failure for Minimal Nodes
Discussion on the issue of `default syncmode.offset-el-safe` failing for `--minimal` nodes continued. The root cause was identified as `--minimal` pruning block bodies, which are essential for `op-node`'s EL sync to read L1-info deposit transactions. The recommended fix is to never prune block bodies on an OP Stack node and to only prune state and receipt segments. Documentation is being updated to reflect supported pruning configurations and the `--syncmode.offset-el-safe` flag. The community also suggested that `offset-el-safe` should ideally depend on the execution client's pruning configuration or automatically fall back to `0` for pruned nodes, rather than relying on a static 12h default. ([#21465](https://github.com/ethereum-optimism/superchain-registry/issues/21465))

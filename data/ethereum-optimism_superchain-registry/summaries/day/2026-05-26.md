## ACTIVE ISSUES

### `op-supernode`: Track FCU retry-verify workaround in RewindToTimestamp ([#19772](https://github.com/ethereum-optimism/superchain-registry/issues/19772))
Discussion indicates that the `RewindToTimestamp` retry-verify loop is a workaround for an `op-reth` race condition. The upstream PR to fix `reth`'s engine API was closed as stale, suggesting that the current workaround might be a long-term solution due to a lack of interest in fixing the underlying `reth` issue.

### [L2CM] Investigate adding an array of predeploys to increase upgrade safety ([#19260](https://github.com/ethereum-optimism/superchain-registry/issues/19260))
This issue was reopened due to a remaining TODO in the codebase (`packages/contracts-bedrock/test/L2/L2ContractsManager.t.sol:1060`). The discussion highlights a structural gap in the upgrade pipeline where implementation knowledge is distributed across multiple data structures, leading to potential silent failures. A previous fix addressed an immediate bug where `L2DevFeatureFlags` was omitted from the NUT bundle's deployment. The issue also points out a latent problem with `ConditionalDeployer` that could lead to a bricked batch upgrade if its bytecode changes in a future upgrade. The current action is to either remove the TODO or repoint it to a follow-up issue before closing.

### L2CM: prevent silent drift between feature flag definitions and CI matrix ([#20340](https://github.com/ethereum-optimism/superchain-registry/issues/20340))
The decision has been made to address this by documenting all necessary update locations when adding new dev or system features. This documentation will be placed as comments in `DevFeatures.sol` and `devFeatures.go`.

### bug(op-reth): proofs-history exex SIGBUS crash and infinite retry loop during deep FCU rewinds ([#20934](https://github.com/ethereum-optimism/superchain-registry/issues/20934))
The issue was reopened as point 2 of the original problem (SIGBUS crash) still needs to be addressed. The current hypothesis suggests a race condition during unwind/reorg flows where `File::set_len(ftruncate)` truncates static-file mmap pages while another thread is reading them, causing a SIGBUS. The team is awaiting input from the Reth core team on this hypothesis. Fixes for claims 1 and 3 (retry/liveness behavior) have been proposed, but the SIGBUS crash is believed to be a separate, lower-level issue.

### C-flake: TestUnsafeChainNotStalling_CLSync family regressing again (post-#20950) ([#21041](https://github.com/ethereum-optimism/superchain-registry/issues/21041))
Adversarial review of a proposed test-side fix revealed that the root cause is an `op-reth` Engine API stall, not a test budget bug. Evidence from CI logs shows L2CL-b's verifier stalling at block 40 and `engine_newPayloadV3` / `forkchoiceUpdated` RPC calls timing out repeatedly. This suggests an `op-reth` Engine API issue, possibly related to an upstream `reth` mmap/ftruncate race. The next step is to rebase a failing branch onto `develop` to include a recent `op-reth` fix (`#21012`) and re-run tests to see if the flake reproduces. No test-side changes will be implemented for now.

## ACTIVE ISSUES

### Flaky Test: `TestFlashblocksStream`
The flaky test issue `TestFlashblocksStream` ([#19883](https://github.com/ethereum-optimism/superchain-registry/issues/19883)) was reopened today after resurfacing with a different failure mode. The latest comments from ajsutton indicate a fix has been proposed in a related `optimism` repository pull request. The root cause was identified as a mismatch between the test assertion and the flashblock protocol, where sequences are keyed by `payload_id` rather than `block_number`. Previous comments from ajsutton and wwared detailed earlier instances of the flake, including `rollup-boost` crashes and sequencer stop failures due to context cancellation.

### Supernode Functionality for Unsafe Data
Discussion continued on the `op-supernode: SuperRoots for the unsafe` issue ([#19059](https://github.com/ethereum-optimism/superchain-registry/issues/19059)). axelKingsley questioned the need for supernodes to rely on unsafe data and suggested alternative means to determine if a node has "observed" a given height or hash. He also mentioned a recent change allowing EL sync'd op-nodes to support proofs immediately by adjusting FCU targets. Inphi previously clarified that the "super root" returned for unsafe data would be purely mechanical without semantic meaning, only indicating observation by the supernode.

### Conditional Deployment of CrossL2Inbox
The issue `kona-node, interop: Conditionally deploy CrossL2Inbox` ([#19311](https://github.com/ethereum-optimism/superchain-registry/issues/19311)) saw recent activity. digorithm commented that the issue should be closed by a specific pull request. Inphi confirmed that an e2e test for this behavior passes locally with the changes in the referenced pull request and plans to merge the test after the fix. Earlier comments from Inphi and yoonchung8822 discussed the impact on `kona-derive` and `kona-proof` and the need to fix the core crates.

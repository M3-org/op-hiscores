# ethereum-optimism/docs Monthly Report (March 2026)

## 🚀 Highlights
In March 2026, the documentation team focused on aligning the knowledge base with significant protocol shifts, most notably the deprecation of `op-geth` and the transition toward `CANNON_KONA` as the default game type. Technical efforts centered on refining the developer experience through updated oracle integrations (Stork and DIA) and a comprehensive overhaul of bridging tutorials. Meanwhile, active discussions regarding `op-node` sync correctness and `op-reth` performance indicate a rigorous focus on protocol stability as the ecosystem prepares for the Glamsterdam upgrade.

## 🛠️ Key Developments

### Protocol Transitions & Deprecations
The documentation was updated to reflect major shifts in the OP Stack's execution and fault-proof layers.
*   **op-geth Deprecation:** A dedicated page was added to announce the deprecation of `op-geth`, ensuring users are informed of the transition path ([#1988](https://github.com/ethereum-optimism/docs/pull/1988)).
*   **Security & Risk Disclosure:** Documentation for privileged roles was updated to include specific details on guardian risks, providing better transparency regarding the security model ([#1993](https://github.com/ethereum-optimism/docs/pull/1993)).

### Developer Tools & Tutorials
Significant updates were made to the resources available for application developers, particularly regarding data availability and asset management.
*   **Oracle Integrations:** Documentation was expanded to include the Stork oracle ([#1982](https://github.com/ethereum-optimism/docs/pull/1982)) and the DIA oracle ([#1995](https://github.com/ethereum-optimism/docs/pull/1995)), providing developers with more diverse data feed options.
*   **Bridging Overhaul:** The bridging tutorials underwent a structural refresh to better explain deposited assets and improve the onboarding flow for new users ([#1980](https://github.com/ethereum-optimism/docs/pull/1980)).

### Repository Maintenance
Efforts were made to streamline the documentation repository and improve internal standards.
*   **Content Cleanup:** The team removed 25 unreferenced files, primarily from the tutorials directory, to reduce technical debt and clutter ([#1994](https://github.com/ethereum-optimism/docs/pull/1994)).
*   **Standardization:** A pull request was initiated to rename the glossary for better file organization ([#1992](https://github.com/ethereum-optimism/docs/pull/1992)).

## 🐛 Issues & Triage

### Closed Issues
*   **Feature Obsolescence:** Due to the deprecation of `op-geth`, issues related to Flashblocks support within that client were closed as obsolete ([#756](https://github.com/ethereum-optimism/docs/issues/756)).
*   **Test Suite Optimization:** The team resolved discussions around adding time controls to `op-acceptance-tests`, determining the feature was not currently required for the batcher and sequencer testing workflow ([#19009](https://github.com/ethereum-optimism/docs/issues/19009)).

### New & Active Issues
*   **Kona Protocol Discrepancies:** A cluster of high-priority issues emerged regarding the Kona protocol, including panics in `kona-protocol` ([#19334](https://github.com/ethereum-optimism/docs/issues/19334)), frame parsing mismatches ([#19335](https://github.com/ethereum-optimism/docs/issues/19335)), and brotli channel disagreements with `op-node` ([#19333](https://github.com/ethereum-optimism/docs/issues/19333)).
*   **Client Performance & UX:** Discussions are ongoing regarding a potential memory leak in `op-reth` related to long-running database transactions ([#19212](https://github.com/ethereum-optimism/docs/issues/19212)) and UX bugs in `op-node` concerning finalized block marking during initial EL sync ([#17631](https://github.com/ethereum-optimism/docs/issues/17631)).
*   **Glamsterdam Upgrade Preparation:** Technical analysis is underway regarding the impact of Glamsterdam gas pricing on precompile acceleration, specifically noting that `bn256Pairing` costs will need adjustment ([#19375](https://github.com/ethereum-optimism/docs/issues/19375)).

## 💬 Community & Collaboration
The month was characterized by strong technical engagement from contributors like `Moses-main`, who volunteered for several complex fixes within the Kona and `op-node` stack. Collaboration between maintainers (such as `ajsutton`, `maurelian`, and `stevennevins`) was evident in the strategic planning for the `CANNON_KONA` game type transition and the resolution of L2 Contracts Manager conventions ([#19391](https://github.com/ethereum-optimism/docs/issues/19391)). The community also provided vital feedback on infrastructure health, reporting rate-limiting issues with the Flashblocks WS endpoint ([#19366](https://github.com/ethereum-optimism/docs/issues/19366)).

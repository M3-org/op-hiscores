# ethereum-optimism/docs Monthly Report (April 2026)

## 🚀 Highlights
April marked a significant transition for the Optimism documentation strategy, culminating in the deprecation of the standalone `docs` repository in favor of a centralized resource within the main `optimism` monorepo. This structural shift aims to streamline the developer experience by co-locating documentation with the core protocol code. Despite this migration, the month saw active technical tracking of protocol-level bug fixes, improvements to supernode reliability during L1 reorganizations, and expanded documentation for the Actions SDK.

## 🛠️ Key Developments

### Documentation Centralization and Maintenance
The most impactful development this month was the formal deprecation of the `ethereum-optimism/docs` repository. All content was migrated to a new location within the primary `optimism` repository to centralize resources and simplify the contribution workflow ([#2019](https://github.com/ethereum-optimism/docs/pull/2019)). Additionally, maintenance work included the removal of `op-erigon` documentation ([#2017](https://github.com/ethereum-optimism/docs/pull/2017)) and the generation of comprehensive metrics reports for the previous month's activity ([#2015](https://github.com/ethereum-optimism/docs/issues/2015), [#2016](https://github.com/ethereum-optimism/docs/issues/2016)).

### Actions SDK Expansion
Efforts to improve the developer experience for the Actions SDK continued with the introduction of new documentation specifically covering Swap functionality ([#2018](https://github.com/ethereum-optimism/docs/pull/2018)). This addition provides builders with clearer guidance on integrating exchange features within the Optimism ecosystem.

## 🐛 Issues & Triage

### Closed Issues: Protocol Stability and Interoperability
Significant progress was made in refining how the Superchain handles L1 network events:
*   **Supernode L1 Reorg Handling:** Several issues were resolved to ensure supernode consistency during blockchain reorganizations. This included implementing Write-Ahead Logging (WAL) to clear verifications, prune the interop database, and manage denylists during reorgs ([#19245](https://github.com/ethereum-optimism/docs/issues/19245), [#19287](https://github.com/ethereum-optimism/docs/issues/19287), [#19289](https://github.com/ethereum-optimism/docs/issues/19289)).
*   **Fault Proofs and Interop:** The `op-challenger` host argument issues were resolved as the runner successfully integrated `kona-interop` in testing ([#18287](https://github.com/ethereum-optimism/docs/issues/18287)).

### New & Active Issues: Bug Tracking and Flaky Tests
The repository served as a critical hub for tracking technical debt and protocol bugs:
*   **Monorepo Bug Tracking:** A surge of issues was opened to track fixes across the OP Stack, including logic errors in `op-batcher` ([#19859](https://github.com/ethereum-optimism/docs/issues/19859)), channel size pruning in `op-node` ([#19858](https://github.com/ethereum-optimism/docs/issues/19858)), and various unmarshaling and memory leak fixes in `op-service` ([#19862](https://github.com/ethereum-optimism/docs/issues/19862), [#19875](https://github.com/ethereum-optimism/docs/issues/19875)).
*   **CI Reliability:** Two significant flaky tests were identified in the `optimism` monorepo: `TestFlashblocksStream` ([#19883](https://github.com/ethereum-optimism/docs/issues/19883)), which involves "address already in use" errors, and `TestUnsafeGapFillAfterUnsafeReorg_RestartL2CL` ([#19936](https://github.com/ethereum-optimism/docs/issues/19936)), which is failing during sync reorg tests.

## 💬 Community & Collaboration
The month's activity highlighted deep technical coordination regarding Interop specifications. A notable discussion occurred around **Interop Transaction Pool Eviction** ([#19351](https://github.com/ethereum-optimism/docs/issues/19351)), where contributors reached a consensus that `op-reth` will prioritize safety and simplicity by dropping all interop transactions during reorgs rather than attempting complex re-verification. This dialogue demonstrates the project's commitment to robust safety guarantees as the Superchain interoperability layer matures.

# ethereum-optimism/docs Weekly Report (Mar 29 - Apr 4, 2026)

## 🚀 Highlights
This week focused on refining the ecosystem's technical documentation and stabilizing the testing infrastructure for the Superchain. Significant efforts were directed toward updating production RPC provider lists and pruning deprecated components like `op-erigon`. While the team successfully resolved several long-standing flaky acceptance tests, new challenges emerged regarding Interop Fault Proofs and Kona integration. Additionally, a major administrative push resulted in the tracking of over a dozen bug fixes across the broader Optimism stack, ensuring the documentation repository remains a central hub for protocol health.

## 🛠️ Key Developments
The week's technical activity centered on infrastructure updates and documentation maintenance to reflect the current state of the OP Stack.

### RPC and Node Provider Updates
A coordinated effort was made to expand the available resources for developers by integrating new service providers into the documentation.
*   **Mobula RPC Integration:** Seven pull requests ([#2008](https://github.com/ethereum-optimism/docs/pull/2008) through [#2014](https://github.com/ethereum-optimism/docs/pull/2014)) were opened to add Mobula to the official list of production RPC providers, ensuring developers have access to diverse infrastructure options.

### Documentation Pruning and Maintenance
To maintain accuracy and reduce technical debt, the team began removing outdated components.
*   **Deprecating op-erigon:** PR [#2017](https://github.com/ethereum-optimism/docs/pull/2017) was initiated to remove `op-erigon` from the documentation, reflecting shifts in the supported execution client landscape.
*   **Metrics Reporting:** Automated reporting was finalized for the month of March, with issues [#2015](https://github.com/ethereum-optimism/docs/issues/2015) and [#2016](https://github.com/ethereum-optimism/docs/issues/2016) tracking the generation of monthly metrics for closed issues and opened pull requests.

## 🐛 Issues & Triage
The project saw a high volume of activity in issue management, particularly regarding cross-repo bug tracking and CI stability.

### Closed Issues
*   **Flaky Test Resolution:** Several persistent acceptance tests were closed after achieving consistent passes on the `develop` branch. These included issues related to database preservation during resyncs ([#19661](https://github.com/ethereum-optimism/docs/issues/19661), [#19673](https://github.com/ethereum-optimism/docs/issues/19673)) and CI hangs ([#19677](https://github.com/ethereum-optimism/docs/issues/19677)).
*   **Protocol Fixes:** The fix for host arguments in the Kona Super Executor was confirmed ([#18287](https://github.com/ethereum-optimism/docs/issues/18287)), and redundant tickets regarding Fault Dispute Game migrations were consolidated ([#19013](https://github.com/ethereum-optimism/docs/issues/19013)).

### New & Active Issues
*   **Cross-Repo Bug Tracking:** A significant number of new issues were opened to track fixes across the Optimism ecosystem, including `op-batcher` logic errors ([#19859](https://github.com/ethereum-optimism/docs/issues/19859)), `op-node` p2p shutdown bugs ([#19860](https://github.com/ethereum-optimism/docs/issues/19860)), and various unmarshaling errors in `op-service` and `kona`.
*   **Fault Proof Flakes:** New issues [#19828](https://github.com/ethereum-optimism/docs/issues/19828) and [#19829](https://github.com/ethereum-optimism/docs/issues/19829) identify a recurring failure in `TestInteropFaultProofs`. Investigations suggest a missing L1 head check in the Kona no-op transition path is causing unexpected program exits.
*   **Interop Transaction Behavior:** Discussion continues on [#19351](https://github.com/ethereum-optimism/docs/issues/19351) regarding how `op-geth` and `op-reth` should handle transaction pool evictions during reorgs to ensure safety in interoperable environments.

## 💬 Community & Collaboration
The week was characterized by high-intensity coordination between documentation maintainers and protocol engineers. The surge in "Bug Fix Tracking" issues indicates a tight feedback loop between the core development of the OP Stack and the documentation team. Technical discussions around Interop transaction pools ([#19351](https://github.com/ethereum-optimism/docs/issues/19351)) highlight active collaboration between client teams (Geth and Reth) to standardize behavior across the Superchain. The repetitive nature of the RPC provider PRs suggests a streamlined, albeit high-volume, process for onboarding new ecosystem partners.

# ethereum-optimism/docs Weekly Report (Jan 25 - 31, 2026)

## 🚀 Highlights
This week focused on refining protocol documentation and advancing technical specifications for the Superchain’s interoperability and sync infrastructure. Key efforts included finalizing documentation for OPCM v2 and Custom Gas Tokens (CGT), alongside critical architectural discussions regarding the `op-supernode` SyncStatus API. The team also prioritized protocol safety by coordinating the timing of `OptimismPortal2` upgrades to ensure uninterrupted withdrawal functionality during upcoming network transitions.

## 🛠️ Key Developments

### Protocol Documentation & Role Management
Updates were made to ensure documentation accurately reflects the current state of the protocol's smart contracts and administrative roles.
*   **Role Address Updates:** Added `operator_fee_vault_recipient` and `chain_fees_fee_recipient` to the registry of role addresses ([#1964](https://github.com/ethereum-optimism/docs/pull/1964)).
*   **Contract Pathing:** Updated the `DisputeGameFactory` path to correctly reference the `DisputeGameFactoryProxy` ([#1963](https://github.com/ethereum-optimism/docs/pull/1963)).
*   **ERC-20 Bridging:** Implemented minor clarifications and edits to the "Bridging ERC-20 tokens" guide to improve developer onboarding ([#1966](https://github.com/ethereum-optimism/docs/pull/1966)).

### Interoperability & Sync Infrastructure
Significant progress was made in defining how nodes and supernodes report their status within the Superchain ecosystem.
*   **Supernode SyncStatus API:** Developers reached a consensus on the `op-supernode` interface. The API will now include the `op-node` SyncStatus for every chain and the status of every verification activity. For interop, this includes the latest verified timestamp and current L1 status to streamline acceptance testing ([#18947](https://github.com/ethereum-optimism/docs/issues/18947)).
*   **EIP-1559 Parameter Decoding:** Work is underway in `op-alloy` to improve error handling by catching zero elasticities during EIP-1559 parameter decoding, enabling earlier failure detection ([#18951](https://github.com/ethereum-optimism/docs/issues/18951)).

## 🐛 Issues & Triage

### Closed Issues
*   **Protocol Upgrades:** The removal of OPCM v2 checks was finalized following the successful merge of the Custom Gas Token (CGT) pull request ([#18536](https://github.com/ethereum-optimism/docs/issues/18536)).
*   **Resource Management:** An issue regarding Resource Locators for v7.0.0 artifacts was closed as the referenced files were deprecated during the development process ([#18633](https://github.com/ethereum-optimism/docs/issues/18633)).

### New & Active Issues
*   **Flashblocks Tracking:** A new issue was opened to track supported features for flashblocks, aligning with ongoing development in the Reth execution client ([#1965](https://github.com/ethereum-optimism/docs/issues/1965)).
*   **Withdrawal Proof Coordination:** A critical discussion is ongoing regarding proving withdrawals via chain-specific root claims. While `OptimismPortalInterop` is ready, the `OptimismPortal2` upgrade must be delayed until after the U19 execution to prevent withdrawal failures. This requires `FaultDisputeGames` to first support the new `rootClaimByChainId` method ([#18517](https://github.com/ethereum-optimism/docs/issues/18517)).

## 💬 Community & Collaboration
The week was characterized by high-level technical coordination between protocol engineers. Notable collaboration occurred regarding the `op-supernode` API definitions, where contributors refined the interface requirements to better serve interop testing. Additionally, the community showed proactive engagement in the `op-alloy` repository, with contributors stepping up to handle specific decoding fixes, signaling a healthy and responsive contributor base for core library maintenance.

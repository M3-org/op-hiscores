# ethereum-optimism/docs Weekly Report (Feb 15 - 21, 2026)

## 🚀 Highlights
This week focused on expanding the Optimism ecosystem's integration resources and monitoring critical infrastructure stability. The primary documentation update involved the introduction of the Stork oracle, enhancing the available tooling for developers within the Superchain. Meanwhile, technical attention remained fixed on a significant memory leak affecting archive nodes on Base mainnet, highlighting ongoing efforts to maintain protocol reliability and performance for high-demand users.

### Ecosystem Integrations & Oracle Support
The documentation suite was expanded to include new third-party infrastructure providers, ensuring developers have the necessary guides to build on the OP Stack.
*   **Stork Oracle Integration:** Documentation was introduced to support the Stork oracle, providing the community with more diverse data feed options. This work was initiated via PR [#1982](https://github.com/ethereum-optimism/docs/pull/1982).

## 🐛 Issues & Triage

### New & Active Issues
The most critical technical discussion this week centered on infrastructure stability and resource management.
*   **`op-reth` Memory Leak:** Issue [#19212](https://github.com/ethereum-optimism/docs/issues/19212) remains the primary focus of active troubleshooting. Reports indicate a recurring memory leak in Base mainnet archive nodes triggered by long-running database read transactions. This issue appears to be systemic across multiple nodes, representing a potential blocker for operators requiring high-uptime archive data.

## 💬 Community & Collaboration
Collaboration this week was characterized by active technical troubleshooting between maintainers and node operators. The dialogue surrounding the `op-reth` memory leak (Issue [#19212](https://github.com/ethereum-optimism/docs/issues/19212)) shows a high degree of engagement, with contributors working to isolate the specific database triggers causing the leak. The addition of new oracle documentation also suggests ongoing coordination with external ecosystem partners to keep the developer experience current and comprehensive.

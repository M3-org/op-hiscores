# ethereum-optimism/docs Weekly Report (Jan 11 - 17, 2026)

## 🚀 Highlights
This week focused on significantly expanding the technical documentation for the OP Stack, with a particular emphasis on Custom Gas Token (CGT) v2 and fault proof mechanisms. Key updates included the integration of Kona proofs into the fault proofs explainer and the resolution of critical simulation errors in `op-geth`. The team also prioritized operational clarity by introducing new guides for gas configuration and operator fees, ensuring that chain operators have the necessary resources to manage post-Holocene upgrades and governance-approved features.

## 🛠️ Key Developments

### OP Stack Feature Documentation
The documentation for core OP Stack features saw major enhancements to support more complex chain configurations and proof systems.
*   **Custom Gas Token (CGT) v2:** Comprehensive guides were added covering features and deployment steps for chain operators, alongside an updated fact sheet ([#1914](https://github.com/ethereum-optimism/docs/pull/1914)).
*   **Fault Proofs & Kona:** Integrated Kona proofs into the fault proofs explainer to clarify the challenger mechanism ([#1922](https://github.com/ethereum-optimism/docs/pull/1922)).
*   **Historical References:** Added references for `op-reth` and historical proofs to broaden the scope of supported execution clients ([#1942](https://github.com/ethereum-optimism/docs/pull/1942)).

### Operator & Gas Management
New resources were developed to assist operators with network maintenance and fee structures.
*   **Gas Configuration:** Introduced a guide for changing gas target and limit configurations post-Holocene ([#1946](https://github.com/ethereum-optimism/docs/pull/1946)).
*   **Fee & Block Management:** New documentation was drafted for setting operator fees ([#1948](https://github.com/ethereum-optimism/docs/pull/1948)) and understanding flashblocks gas usage ([#1947](https://github.com/ethereum-optimism/docs/pull/1947)).

### Infrastructure & Maintenance
*   **Solidity Updates:** Initiated updates to Solidity versions across the documentation to maintain alignment with current development standards ([#1941](https://github.com/ethereum-optimism/docs/pull/1941)).
*   **UX Improvements:** Fixed broken links and disabled problematic drilldown functionality to improve site navigation ([#1945](https://github.com/ethereum-optimism/docs/pull/1945)).

## 🐛 Issues & Triage

### Closed Issues
*   **Simulation Fixes:** Significant progress was made on `eth_simulateV1` functionality. Issue [#739](https://github.com/ethereum-optimism/docs/issues/739) (DA footprint calculation errors) was resolved with the release of `op-geth v1.101605.0`, and related simulation challenges were addressed via [#14690](https://github.com/ethereum-optimism/docs/issues/14690).
*   **Monitoring & Integration:** The dispute-mon dashboard was updated to support multi-node metrics ([#18205](https://github.com/ethereum-optimism/docs/issues/18205)), and the challenger successfully integrated a supernode provider ([#18524](https://github.com/ethereum-optimism/docs/issues/18524)).

### New & Active Issues
*   **Safe-Head Advancement:** Discussion continues on [#15393](https://github.com/ethereum-optimism/docs/issues/15393) regarding excessive FCU messages. Recent analysis suggests a previous fix failed to properly buffer messages, leading to performance concerns when the batcher runs with long channel durations.
*   **Kona CI Simplification:** Ongoing debate regarding [#18773](https://github.com/ethereum-optimism/docs/issues/18773) focuses on how to manage `kona-host` releases in relation to `op-challenger` to ensure consistency across acceptance tests and Docker images.
*   **Governance Alignment:** A new task was opened to update documentation callouts for "u18" features following governance approval and the official `op-deployer` release ([#1943](https://github.com/ethereum-optimism/docs/issues/1943)).

# ethereum-optimism/docs Weekly Report (Mar 1 - 7, 2026)

## 🚀 Highlights
This week focused on aligning documentation with significant protocol shifts, most notably the deprecation of `op-geth` and the transition toward the `CANNON_KONA` game type. Technical discussions centered on resolving discrepancies within the Kona protocol and addressing the architectural implications of the Glamsterdam upgrade on gas pricing. The team also expanded developer resources by integrating new oracle documentation and refining security-related content regarding guardian risks and access control conventions.

## 🛠️ Key Developments

### Protocol Deprecations and Transitions
The documentation was updated to reflect major changes in the OP Stack node software.
*   **op-geth Deprecation:** A new dedicated page was added to announce the deprecation of `op-geth`, ensuring users are informed of the transition path ([#1988](https://github.com/ethereum-optimism/docs/pull/1988)).
*   **Fault Proof Game Updates:** Work is underway to set the default respected game type to `CANNON_KONA`, a move currently in progress to align with upcoming protocol changes ([#18640](https://github.com/ethereum-optimism/docs/issues/18640)).

### Developer Tooling and Infrastructure
New resources were added to improve the developer experience and provide clarity on ecosystem tools.
*   **Oracle Integration:** Documentation for the Stork oracle was added to the developer tools section, providing builders with updated data sourcing options ([#1982](https://github.com/ethereum-optimism/docs/pull/1982)).
*   **Security and Risk Documentation:** A new PR was initiated to update documentation regarding Guardian risks ([#1993](https://github.com/ethereum-optimism/docs/pull/1993)).
*   **L2ContractsManager (L2CM) Standards:** New documentation is being developed for the `no-storage-variables` convention to prevent storage slot collisions with `ProxyAdmin` ([#19391](https://github.com/ethereum-optimism/docs/issues/19391)).

## 🐛 Issues & Triage

### Closed Issues
*   **Flashblocks Support:** The issue regarding Flashblocks support in `op-geth` was closed as obsolete following the software's deprecation ([#756](https://github.com/ethereum-optimism/docs/issues/756)).

### New & Active Issues
*   **Kona Protocol Discrepancies:** A cluster of issues is being addressed regarding mismatches between `kona` and `op-node`. These include disagreements on brotli channels ([#19333](https://github.com/ethereum-optimism/docs/issues/19333)), panics from unknown batch types ([#19334](https://github.com/ethereum-optimism/docs/issues/19334)), and frame parsing mismatches ([#19335](https://github.com/ethereum-optimism/docs/issues/19335)).
*   **Glamsterdam Gas Pricing:** Technical investigation is ongoing regarding how Glamsterdam's increased gas costs for precompiles affect L1 execution and fault proofs. Key concerns include `bn256Pairing` costs and increased call data costs for large preimages ([#19375](https://github.com/ethereum-optimism/docs/issues/19375)).
*   **EL Sync UX:** Discussions continue on improving the `op-node` Execution Layer (EL) sync experience, specifically regarding how Snap Sync interacts with finalized L2 targets ([#17631](https://github.com/ethereum-optimism/docs/issues/17631)).

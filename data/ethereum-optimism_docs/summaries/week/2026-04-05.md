# ethereum-optimism/docs Weekly Report (Apr 5 - 11, 2026)

## 🚀 Highlights
This week marked a significant structural transition for the Optimism documentation as the standalone `docs` repository was officially deprecated and its content consolidated into the main `optimism` monorepo. Beyond this migration, development focused heavily on hardening the Supernode's resilience against L1 chain reorganizations through improved database pruning and Write-Ahead Logging (WAL) implementations. While core protocol stability improved, the week also saw the identification of new flaky tests in the CI pipeline, specifically targeting Flashblocks and L2 consensus layer synchronization.

## 🛠️ Key Developments

### Documentation Centralization
The primary focus for the repository this week was the deprecation of the `ethereum-optimism/docs` repository. All documentation resources have been migrated to a new location within the central `optimism` repository ([#2019](https://github.com/ethereum-optimism/docs/pull/2019)). This move is intended to streamline the contribution workflow and ensure that protocol changes and their corresponding documentation remain tightly coupled.

### Supernode Reliability & L1 Reorg Handling
Significant technical debt was addressed regarding how Supernodes handle L1 reorganizations. By leveraging Write-Ahead Logging (WAL), the team implemented more robust state-clearing mechanisms.
*   **State Consistency:** Improvements were made to ensure verifications and denied blocks are cleared correctly during L1 reorgs ([#19245](https://github.com/ethereum-optimism/docs/issues/19245)).
*   **Database Maintenance:** New logic was introduced to prune the interop database ([#19287](https://github.com/ethereum-optimism/docs/issues/19287)) and the denylist ([#19289](https://github.com/ethereum-optimism/docs/issues/19289)) following a reorganization, preventing stale data from impacting node performance.

## 🐛 Issues & Triage

### Closed Issues
*   **L1 Reorg Handling:** As detailed in the Key Developments, a suite of issues related to Supernode consistency during chain reorgs was resolved, specifically focusing on pruning and verification clearing ([#19245](https://github.com/ethereum-optimism/docs/issues/19245), [#19287](https://github.com/ethereum-optimism/docs/issues/19287), [#19289](https://github.com/ethereum-optimism/docs/issues/19289)).

### New & Active Issues
The week saw the emergence of stability issues within the CI environment, particularly affecting acceptance tests:
*   **Flashblocks Instability:** `TestFlashblocksStream` ([#19883](https://github.com/ethereum-optimism/docs/issues/19883)) continues to show flakiness, with `rollup-boost` crashing due to "Address already in use" errors, specifically within the `memory-all-opn-op-geth` job.
*   **Sync & Reorg Failures:** A new flaky test, `TestUnsafeGapFillAfterUnsafeReorg_RestartL2CL` ([#19936](https://github.com/ethereum-optimism/docs/issues/19936)), was identified. It involves failures in L2 consensus layer restarts where the head fails to match the expected "unsafe" state after multiple attempts. This issue appears to be surfacing primarily on the `aj/fix/build-kona-host` branch.

## 💬 Community & Collaboration
The activity this week reflects a high degree of coordination between protocol engineers and documentation maintainers to execute the repository migration. The technical discussions centered around the `aj/fix/build-kona-host` branch indicate active debugging of the new Kona host integration, as evidenced by the detailed CI context provided for the newly discovered flaky tests. The resolution of the Supernode reorg issues suggests a successful push toward protocol-level stability and data integrity.

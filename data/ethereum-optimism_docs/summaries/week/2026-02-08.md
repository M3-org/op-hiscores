# ethereum-optimism/docs Weekly Report (Feb 8 - 14, 2026)

## 🚀 Highlights
This week focused on strengthening the operational resources for the Superchain ecosystem, specifically targeting chain and node operators. Key achievements include the release of a comprehensive transaction fee guide for chain management and updated documentation for Reth snapshots to improve node synchronization workflows. While technical documentation matured, the team also addressed protocol-level tracking for blob fees and engaged in architectural discussions regarding sequencer reliability and failover strategies.

## 🛠️ Key Developments

### Operator Infrastructure & Fee Management
Significant effort was directed toward empowering chain operators with better control over their network parameters.
*   **Transaction Fee Guide:** A new, comprehensive guide was introduced for chain operators, detailing the technical parameters of transaction fees and providing clear procedures for adjustments ([#1961](https://github.com/ethereum-optimism/docs/pull/1961)).
*   **Blob Fee Tracking:** Documentation and tracking for `op-batcher/txmgr` blob priority fees were updated, confirming the resolution of fee tracking logic within the batcher ([#18737](https://github.com/ethereum-optimism/docs/issues/18737)).

### Node Operator Resources
Updates were made to ensure node operators have access to the latest synchronization methods and network information.
*   **Reth Snapshot Integration:** Documentation for node operators now includes detailed information on Reth snapshots. This update provides clearer guidance on managing network information and leveraging snapshots for faster node deployment ([#1976](https://github.com/ethereum-optimism/docs/pull/1976)).
*   **OP Mainnet Snapshot Organization:** Node snapshot documentation for OP Mainnet was reorganized to correctly reflect current availability for `op-reth` and moved to a more discoverable section of the docs ([#1973](https://github.com/ethereum-optimism/docs/issues/1973)).

## 🐛 Issues & Triage

### Closed Issues
*   **Protocol Refinement:** The team successfully closed issues related to blob priority fee tracking, ensuring the `txmgr` correctly handles fee data for batch submissions.
*   **Documentation Accuracy:** Discrepancies in the location and availability of node snapshots were resolved, improving the onboarding experience for new node operators.

### New & Active Issues
*   **Blob Tip Oracle Activation:** Issue [#18618](https://github.com/ethereum-optimism/docs/issues/18618) remains active and was reopened due to a pending `TODO` in the `op-batcher` codebase. The activation of the blob tip oracle is currently gated by production verification to ensure that the "blob savings" logic justifies the switch.
*   **Sequencer Reliability:** A significant architectural discussion is ongoing regarding support for multiple sequencer RPC endpoints ([#763](https://github.com/ethereum-optimism/docs/issues/763)). While the goal is to provide automatic failover to prevent outages, there is a debate between implementing client-side support for multiple URLs versus adhering to web2 reliability standards (like load balancers) for a single, highly available URL.

## 💬 Community & Collaboration
The week's activity highlights a strong feedback loop between protocol development and documentation. The reopening of the blob tip oracle issue ([#18618](https://github.com/ethereum-optimism/docs/issues/18618)) demonstrates a cautious, data-driven approach to protocol changes, requiring production evidence before final activation. Furthermore, the debate surrounding sequencer RPC endpoints ([#763](https://github.com/ethereum-optimism/docs/issues/763)) shows active collaboration on balancing technical redundancy with developer user-friendliness, ensuring that the infrastructure remains robust without becoming overly complex for end-users.

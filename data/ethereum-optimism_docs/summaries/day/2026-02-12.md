**Discussion on Binary Hint Format for Kona**
Discussion continued on [#19125](https://github.com/ethereum-optimism/docs/issues/19125) regarding the proposal to use a binary format for Kona hints instead of string serialization. The latest comment from kien-rise clarified understanding that the host program must continue to support string versions for backward compatibility with existing games. Earlier, ajsutton expressed skepticism about the performance benefits and the necessity of the change given the backward compatibility requirements. kien-rise responded that the motivation is primarily about "making things right" rather than speed, but expects performance improvements and is open to approaches that preserve compatibility.

**Sequencer RPC Endpoint Redundancy**
The discussion on [#763](https://github.com/ethereum-optimism/docs/issues/763) about supporting multiple sequencer RPC endpoints for transaction forwarding saw a new comment from brendontan03. They emphasized that while infrastructure-level redundancy is ideal, client-side failover across different CDNs/regions provides defense-in-depth against failures like Cloudflare outages. This builds on earlier comments where ajsutton questioned the user-friendliness of multiple URLs and suggested leveraging standard web2 reliability practices for a single URL, while brendontan03 highlighted past production incidents caused by single endpoint failures and confirmed the change is backward compatible.

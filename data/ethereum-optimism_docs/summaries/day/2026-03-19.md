## ACTIVE ISSUES

### Addressing Flaky Interop Proofs Tests
Discussions on [#19672](https://github.com/ethereum-optimism/docs/issues/19672) and [#19673](https://github.com/ethereum-optimism/docs/issues/19673) identified the root cause of `TestChallengerPlaysGame` and `TestProposer` hanging indefinitely in `op-acceptance-tests/tests/interop/proofs`. The issue stems from `FailNow` calls within `testify.Eventually` goroutines, causing silent goroutine termination and blocking `Eventually`. A fix has been proposed to replace fatal assertions with error-returning variants and to isolate packages to prevent hangs in one test from affecting others.

### Investigating Non-Terminating CI Job
Issue [#19563](https://github.com/ethereum-optimism/docs/issues/19563) continues to be active, with further occurrences of the `memory-all-opn-op-geth` CI job hanging. A detailed root cause analysis points to a mutex deadlock in `VirtualNode` during shutdown, involving the test cleanup thread, `Start()` goroutines, and event loop goroutines. A fix PR has been created to address this deadlock by releasing `v.mu` before calling `inner.Stop()` and adding a defensive timeout.

### Refining Initial EL Sync User Experience and Correctness
The discussion on [#17631](https://github.com/ethereum-optimism/docs/issues/17631) regarding the `op-node`'s initial EL sync UX and correctness saw further comments. The core problem is that the current implementation incorrectly sets safe and finalized heads to the unsafe head after initial EL sync, rather than respecting L1 finalization. Option 2, setting safe/finalized to "unsafe head minus sequencer window," is proposed as a balanced approach to maintain correctness while improving UX by reducing derivation time compared to starting from genesis.

### Reviewing Kona-Interop Block Hash Oracle
Issue [#18288](https://github.com/ethereum-optimism/docs/issues/18288) focuses on reviewing the `kona-interop` block hash oracle. The discussion highlights the need for an integration/acceptance test to verify block hash lookups prior to the current history window. It was noted that an existing action test covers this, and the goal is to potentially move this to an acceptance test, possibly utilizing time travel capabilities in `op-acceptance-test` to generate sufficient chain history.

### L2 Reorg Due to L1 Reorg in Kona
Discussion continued on the issue of L2 reorgs caused by L1 reorgs in Kona ([#18676](https://github.com/ethereum-optimism/docs/issues/18676)). A detailed root cause analysis was provided, identifying three main issues:
-   **L1 Origin Selector Caching:** The `self.next` cache in the L1 origin selector becomes stale during an L1 reorg and is not refreshed.
-   **Missing L1 Canonical Validation:** There is no check for L1 origin validity or orphan status in Kona's L1 origin selection, unlike `op-node`.
-   **No Proper Reset During Block Building:** Kona lacks a reset mechanism similar to `op-node` when L1 inconsistency is detected during block building.
Possible fixes suggested include strengthening Kona's L1 origin selector, adding unit tests for L1 inconsistency cases, revising the reset logic, and enabling more monorepo acceptance tests targeting Kona.

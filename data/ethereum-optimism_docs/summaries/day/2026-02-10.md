## ACTIVE ISSUES

### op-conductor: SEGFAULT when peer is killed during leader election ([#13363](https://github.com/ethereum-optimism/docs/issues/13363))
The issue describes a SEGFAULT occurring in `op-conductor` when a peer is killed during a leader re-election, potentially due to invalid data being written to raft logs. The latest comment confirms the problem persists in the current version, specifically when conductors are paused during migration from single to HA setups, causing snapshot attempts even when paused. Previous discussions suggested checking if conductors form a cluster and if unsafe payload commits have errors. The possibility of truncated or nil data in raft logs or snapshot files was also raised, with a potential link to the raft library's snapshotting behavior when "outstanding logs" exceed `SnapshotThreshold`.

### Support multiple sequencer RPC endpoints for transaction forwarding ([#763](https://github.com/ethereum-optimism/docs/issues/763))
This issue proposes supporting multiple sequencer RPC endpoints for `op-geth` with automatic failover to enhance reliability. The latest comments discuss the user-friendliness and necessity of this approach. One user argues that supporting multiple URLs is a backward-compatible and optional change that would prevent outages caused by single endpoint failures (e.g., CDN issues). Another user suggests that ensuring a single URL remains highly available through standard web2 practices (like Google's approach) might be a better option, as reliability should ideally be built into the sequencer operator's systems rather than requiring users to provide multiple URLs.

### Follow-up issue to activate blob tip oracle ([#18618](https://github.com/ethereum-optimism/docs/issues/18618))
This issue, originally closed, was reopened because a `TODO` marker referencing it still exists in the codebase. The `TODO` indicates that before activating the blob tip oracle, confirmation is needed in production that `newBlobSavings` is mostly true, otherwise using the oracle might not be worthwhile. The reopening was triggered by a CI check for `TODO` markers.

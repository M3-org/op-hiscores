*   **non-terminating CI job: memory-all-opn-op-geth** ([#19563](https://github.com/ethereum-optimism/docs/issues/19563))
    *   `ajsutton` reported another occurrence where `TestChallengerPlaysGame` timed out after 2 hours.
    *   An investigation was launched, and a draft fix ([#19634](https://github.com/ethereum-optimism/optimism/pull/19634)) was opened.
    *   The root cause was identified as `waitForClaim` and `WaitForCountered` polling loops using a 20-minute timeout context, but internal RPC calls using the base test context (2-hour deadline). This caused indefinite blocking when RPC calls to the in-memory L1 geth hung due to CI resource contention.
    *   The fix involves creating a context-bound copy of the `FaultDisputeGame` binding for polling loops so RPC calls respect the per-wait timeout.
    *   `ajsutton` also noted that the `interop/proofs` package is timing out in this job, with `TestProposer`, `TestChallengerPlaysGame`, and `TestChallengerRespondsToMultipleInvalidClaims` being reported as failures due to the package-level timeout. Recurring errors include `l2-proposer` stuck retrying and `supernode` errors.

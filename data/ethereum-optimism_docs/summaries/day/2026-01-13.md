### Simplifying Kona Proofs CI
Discussion on [#18773](https://github.com/ethereum-optimism/docs/issues/18773) revolves around simplifying Kona proof's CI by leveraging information from Kona's monorepo, following the merge of a related pull request. Key points include the dual use of `kona/version.json` for acceptance tests and `op-challenger` docker image inclusion. There's a debate on whether `kona-host` releases should be tied to `op-challenger` tags for consistency, as standalone `kona-host` releases might not add value if they aren't the version included in `op-challenger`.

# ethereum-optimism/design-docs Weekly Report (May 3 - 9, 2026)

## 🚀 Highlights
This week focused heavily on stabilizing the testing infrastructure and refining protocol migration logic. Significant effort was directed toward resolving race conditions and synchronization issues in flaky tests related to fault proofs and interop. The team also introduced a new design proposal for a Chainalysis-backed compliance module and made progress on gas accounting documentation. While some interop-related tasks are facing potential scheduling risks, critical healthcheck deployments for the Supernode and Light nodes were successfully finalized.

## 🛠️ Key Developments

### Testing Infrastructure & Stability
A major theme this week was the systematic resolution of flaky tests to improve CI reliability.
*   **Fault Proof & Challenger Fixes:** Root cause analysis led to a fix for `TestPreinteropFaultProofs_VariedBlockTimes` by reordering `freezeChains` to ensure `LocalSafe` is properly drained before stopping batchers ([#19804](https://github.com/ethereum-optimism/design-docs/issues/19804)). Additionally, a race condition in `TestChallengerRespondsToMultipleInvalidClaims` was resolved by introducing a `WithoutHonestProposer` preset to prevent collisions between test game creation and automated proposer submissions ([#20574](https://github.com/ethereum-optimism/design-docs/issues/20574)).
*   **Foundry Experimentation:** The team began testing the global application of `isolate = true` in Foundry to prevent state leakage between tests, alongside adding a new "Gas Accounting in Tests" section to the style guide ([#20388](https://github.com/ethereum-optimism/design-docs/issues/20388)).

### Protocol & Migration Logic
*   **OPCM Migration Updates:** Developers implemented a fix for `OPCM.migrate` to ensure that `SystemConfig` correctly reflects new shared addresses, specifically addressing the `delayedWeth()` return values for secondary chains ([#20511](https://github.com/ethereum-optimism/design-docs/issues/20511)).
*   **Compliance Module:** A new design document was proposed for an `ICompliance` module backed by Chainalysis, signaling a move toward standardized compliance interfaces within the stack ([#380](https://github.com/ethereum-optimism/design-docs/pull/380)).
*   **Interop Validation:** Work continued on adding unsafe head executing message validation, with plans to update `proxyd` for 'cross-unsafe' querying and adding reorg support to the interop filter ([#20553](https://github.com/ethereum-optimism/design-docs/issues/20553)).

## 🐛 Issues & Triage

### Closed Issues
*   **Supernode Healthchecks:** Two significant issues regarding monitoring were resolved. The `Proxyd-CL` deployment for Light nodes on Mainnet was completed ([#20573](https://github.com/ethereum-optimism/design-docs/issues/20573)), and healthchecks for `op-supernode` charts using chain-id subdomains are now functional ([#18451](https://github.com/ethereum-optimism/design-docs/issues/18451)).

### New & Active Issues
*   **Interop Scheduling:** The "Verification-Aware CurrentL1" issue ([#19944](https://github.com/ethereum-optimism/design-docs/issues/19944)) is currently queued behind high-priority devnet sync issues. It is flagged as "at risk" for meeting its end-of-month target.
*   **Kona Node:** While bugs exist in the `kona-node` Light CL implementation ([#18800](https://github.com/ethereum-optimism/design-docs/issues/18800)), maintainers have clarified that these are not blockers for the initial interop launch.

## 💬 Community & Collaboration
The week's activity shows a high degree of cross-repo coordination, particularly between the `design-docs` and the core `optimism` repository, as evidenced by the numerous PRs opened in the latter to address issues identified in design discussions. The collaboration is currently focused on technical debt and hardening, with maintainers actively triaging which bugs (like those in Kona) are launch-critical versus those that can be deferred. The introduction of the compliance module design ([#380](https://github.com/ethereum-optimism/design-docs/pull/380)) suggests ongoing engagement with external ecosystem partners like Chainalysis.

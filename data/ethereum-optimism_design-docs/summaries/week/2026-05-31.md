# ethereum-optimism/design-docs Weekly Report (May 31 - June 6, 2026)

## 🚀 Highlights
This week, the design-docs repository focused on hardening the Superchain’s interoperability framework and refining protocol governance structures. Key efforts centered on developing robust recovery procedures for interop-related failures and advancing the infrastructure for long-running devnets. Significant technical discussions also took place regarding the synchronization of `op-revm` with upstream releases to support the upcoming Amsterdam hardfork, ensuring the OP Stack remains aligned with the latest Ethereum Virtual Machine improvements.

## 🛠️ Key Developments
While no new code pull requests were merged this week, the project saw significant progress in defining technical specifications and operational strategies for the Superchain.

### Interoperability & Recovery Infrastructure
The team focused on the operational stability of interoperable chains, specifically addressing how the system handles invalid messages and failsafe triggers.
*   **Runbook Development:** Work began on a comprehensive runbook for chain recovery following reorgs triggered by invalid interop messages [#21161](https://github.com/ethereum-optimism/design-docs/issues/21161). This documentation aims to standardize the process for disabling failsafes and restoring chain health.
*   **Transaction Pool Resilience:** Technical analysis identified that restoring the interop transaction pool in `op-reth` after a failsafe event currently requires a coordinated restart of both `op-reth` and `op-rbuilder` [#21149](https://github.com/ethereum-optimism/design-docs/issues/21149). To improve observability, a new failsafe-state gauge metric has been proposed [#21151].

### Devnet & Execution Layer Evolution
Efforts to improve the developer experience and protocol compatibility continued through devnet scaling and EVM integration planning.
*   **Devnet Scaling:** The project successfully transitioned from local devnet instances to establishing a long-running devnet environment [#20691](https://github.com/ethereum-optimism/design-docs/issues/20691).
*   **`op-revm` Alignment:** Discussions finalized the strategy for keeping `op-revm` in sync with upstream `revm` and `reth` releases [#21069](https://github.com/ethereum-optimism/design-docs/issues/21069). This includes adopting REVM v111 to leverage shared type definitions and Work-in-Progress (WIP) support for the Amsterdam hardfork.

## 🐛 Issues & Triage
### Closed Issues
*   **Governance & Permissions:** The design review for improved Guardian permissions proposals was successfully concluded and closed [#169](https://github.com/ethereum-optimism/design-docs/issues/169), marking a milestone in refining the security model for the Optimism Collective.

### New & Active Issues
*   **Interop Stability:** New issues were opened to address specific failure modes in interoperability, focusing on ensuring that sequencers can resume normal operations without manual intervention after a failsafe event [#21161](https://github.com/ethereum-optimism/design-docs/issues/21161).
*   **Infrastructure Blockers:** The team is currently tracking the availability of `glamsterdam-devnet-4` images as a prerequisite for full-scale devnet testing [#20691](https://github.com/ethereum-optimism/design-docs/issues/20691).

## 💬 Community & Collaboration
The week was characterized by high-intensity technical coordination regarding the interaction between different OP Stack components. Collaboration was particularly evident between contributors working on `op-reth` and `op-rbuilder`, as they diagnosed the inter-dependencies required for transaction pool recovery. The conclusion of the Guardian permissions review [#169](https://github.com/ethereum-optimism/design-docs/issues/169) also highlights successful cross-functional alignment between protocol designers and governance stakeholders.

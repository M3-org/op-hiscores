# ethereum-optimism/design-docs Weekly Report (May 10 - 16, 2026)

## 🚀 Highlights
This week’s activity centered heavily on stabilizing the `op-acceptance-tests` suite by addressing a cluster of persistent flaky tests affecting the `memory-all` and `op-reth` environments. Developers focused on root cause analysis for synchronization timeouts and context deadline errors that have hindered CI reliability. Beyond testing infrastructure, significant progress was made on cross-ecosystem compatibility, specifically regarding how client libraries handle withdrawal proofs to ensure long-term protocol alignment.

## 🛠️ Key Developments

### Protocol & Client Library Integration
Work continued on refining the interface for withdrawal proofs to ensure compatibility with evolving protocol standards.
*   **Timestamp-Based Withdrawal Proofs:** Efforts are underway to transition client libraries from using block numbers to timestamps for proving withdrawals ([#18614](https://github.com/ethereum-optimism/design-docs/issues/18614)). This week, the team successfully pushed this requirement upstream, with a dedicated PR opened in the **Viem** repository to implement these changes at the library level.

### Test Suite Stabilization
While no new features were merged this week, significant engineering effort was directed toward refactoring and fixing the `op-acceptance-tests` suite to improve CI/CD health.
*   **Sync & Reorg Testing:** Work is in progress via PR #20651 to resolve failures in `TestUnsafeGapFillAfterSafeReorg` and `TestFollowL2_ReorgRecovery`. These tests have been plagued by `context deadline exceeded` errors during sequencer communication.
*   **Database Integrity:** A new fix is being developed in PR #20652 to address database truncation issues during node restarts, specifically targeting the `TestNotTruncateDatabaseOnRestartWithExistingDatabase` failure.

## 🐛 Issues & Triage

### New & Active Issues
The week saw a concentrated effort on triaging "flaky" tests that represent potential blockers for seamless integration and deployment:
*   **Execution Layer Sync Issues:** `TestELSyncSafeRetractedByOffset` ([#20334](https://github.com/ethereum-optimism/design-docs/issues/20334)) was reopened after failing despite a significant increase in retry attempts (120). The persistent `CrossSafe sync timeout` suggests a deeper timing or synchronization bug within the EL sync logic rather than a simple test flake.
*   **Sequencer Timeouts:** Issues [#19884](https://github.com/ethereum-optimism/design-docs/issues/19884) and [#19967](https://github.com/ethereum-optimism/design-docs/issues/19967) remain active. These are critical as they involve `op-reth` and indicate failures in satisfying conditions during L2 reorganization recovery, which is vital for Superchain stability.
*   **Database Persistence:** Issue [#20649](https://github.com/ethereum-optimism/design-docs/issues/20649) was opened to track unexpected database behavior in `safeheaddb_elsync`, highlighting a need for more robust state handling during restarts.

## 💬 Community & Collaboration
Collaboration this week extended beyond the internal repository to the broader Ethereum developer ecosystem. The primary highlight was the coordination with the **Viem** maintainers to align client-side withdrawal logic with Optimism's technical requirements. Internally, the focus on flaky tests indicates a high level of collaborative debugging, as seen in the linked PRs (#20651, #20652) which aim to resolve multiple issues simultaneously. The reopening of several older issues suggests a rigorous review process where "temporary fixes" (like increasing retry counts) are being rejected in favor of identifying true root causes.

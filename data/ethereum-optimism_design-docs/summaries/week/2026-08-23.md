# ethereum-optimism/design-docs Weekly Report (Aug 23 - 29, 2026)

## 🚀 Highlights
This week, development efforts focused on refining the technical documentation for the Superchain Deployment Manager (SDM) operator. The primary objective was to ensure parity between the `op-reth` implementation and its corresponding documentation, specifically regarding environment variable support. Additionally, the team streamlined the documentation architecture by aligning release-specific guides with the hardfork registry, ensuring that infrastructure operators have accurate references for upcoming network upgrades.

## 🛠️ Key Developments

### SDM Operator Documentation Refinement
Work was completed to resolve discrepancies in the SDM operator guides, ensuring they accurately reflect the current state of the OP Stack.
*   **Environment Variable Parity:** Confirmed that all `op-reth` SDM operator options are fully supported via environment variables. The documentation has been updated to include a comprehensive list of these variables, ensuring operators can configure their nodes without relying solely on CLI flags.
*   **Release Mapping & Registry Integration:** Updated the SDM guide to correctly reference the Lagoon hardfork. Instead of linking to a placeholder "Upgrade 20" page, the documentation now points directly to the centralized hardfork registry page. This change ensures a single source of truth for network upgrade specifications.

## 🐛 Issues & Triage

### Active Issues
*   **SDM Operator Documentation Revisit ([#21545](https://github.com/ethereum-optimism/design-docs/issues/21545)):** Discussion on this issue indicates that the primary blockers for the SDM documentation have been resolved. While the SDM guide remains hidden from the public-facing site for now, the internal links and environment variable details are now verified. A decision was made to omit a reverse link from the Lagoon page to the SDM guide until the guide is officially published.

## 💬 Community & Collaboration
Collaboration this week centered on technical verification between protocol developers and documentation maintainers. The focus was on ensuring that the documentation for `op-reth` and the SDM operator matches the actual software capabilities. The intentional decision to keep certain guides hidden while refining the hardfork registry links suggests a coordinated effort to manage the rollout of information regarding the Lagoon upgrade.

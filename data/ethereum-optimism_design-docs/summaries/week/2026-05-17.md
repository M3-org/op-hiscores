# ethereum-optimism/design-docs Weekly Report (May 17 - 23, 2026)

## 🚀 Highlights
This week focused on strengthening the security and interoperability frameworks of the OP Stack, specifically regarding the Osaka upgrade and ZK-based dispute mechanisms. Significant progress was made in formalizing Failure Mode Analysis (FMA) documentation and resolving long-standing infrastructure discrepancies, such as the Brotli channel synchronization between Kona and `op-node`. While development on the Interop Proofs Devnet continues, the team successfully migrated critical dispute game tests and refined RPC namespaces to better support the evolving Superchain architecture.

## 🛠️ Key Developments

### Security & Failure Mode Analysis (FMA)
The project continues to prioritize protocol security through rigorous documentation of potential failure vectors.
*   **Osaka on L2:** Completed and integrated the FMA for the Osaka upgrade on L2, providing a comprehensive map of mitigation strategies ([#375](https://github.com/ethereum-optimism/design-docs/pull/375)).
*   **Super ZK Dispute Game:** Initiated a new FMA specifically for the Super ZK Dispute Game, signaling a shift toward documenting advanced zero-knowledge proof-based security models ([#381](https://github.com/ethereum-optimism/design-docs/pull/381)).

### Interoperability & Protocol Infrastructure
Efforts to streamline the Superchain's interoperability layer resulted in several key technical refinements:
*   **RPC Namespace Migration:** Successfully replaced the supervisor RPC namespace with a dedicated interop filter namespace, improving the clarity and modularity of cross-chain communication ([#20005](https://github.com/ethereum-optimism/design-docs/issues/20005)).
*   **Brotli Channel Resolution:** Resolved a critical discrepancy between Kona and `op-node` regarding Brotli channels, which included upstream bug fixes to ensure data consistency across different node implementations ([#19333](https://github.com/ethereum-optimism/design-docs/issues/19333)).
*   **L2CM Implementation:** Closed the task for implementing the interop hard fork using the L2 Config Manager (L2CM) in `kona-node` and `op-node`, with further tracking moved to specialized protocol team workflows ([#20082](https://github.com/ethereum-optimism/design-docs/issues/20082)).

### Testing & Performance Optimization
*   **Test Migration:** Completed the migration of dispute game tests from `op-e2e` to the more specialized `op-acceptance-tests` suite ([#20814](https://github.com/ethereum-optimism/design-docs/issues/20814)).
*   **Payload Execution:** An investigation into `debug_executePayload` confirmed that these crates remain vital for the "fast-path" server implementation in `op-reth` and will not be removed as dead code ([#20879](https://github.com/ethereum-optimism/design-docs/issues/20879)).

## 🐛 Issues & Triage

### Closed Issues
The team successfully cleared several infrastructure hurdles this week:
*   **Documentation:** Finalized the Osaka FMA documentation task ([#374](https://github.com/ethereum-optimism/design-docs/issues/374)).
*   **Stability:** Resolved synchronization issues in Brotli compression and finalized the transition of RPC namespaces for the Supervisor.

### New & Active Issues
*   **Devnet Blockers:** The integration of Shared Sequencer (SDM) with flashblocks is currently stalled by a dependency on issue #20599, affecting `rollup-boost` and `op-rbuilder` ([#20175](https://github.com/ethereum-optimism/design-docs/issues/20175)).
*   **Infrastructure Readiness:** Devnet progress is currently gated by the availability of `glamsterdam-devnet-4` images; in the interim, the team is focusing on local environments using `bal-devnet-6` ([#20691](https://github.com/ethereum-optimism/design-docs/issues/20691)).
*   **Flaky Tests:** Two significant flakes were identified in the CI pipeline: `TestSupernodeInterop_SafeHeadProgression` ([#20851](https://github.com/ethereum-optimism/design-docs/issues/20851)) and a timing-related collision in `TestChallengerCountersPreGenesisGame` ([#20869](https://github.com/ethereum-optimism/design-docs/issues/20869)). Fixes involving increased delays and post-migration invariants are underway.

## 💬 Community & Collaboration
Collaboration this week was characterized by cross-team coordination between the security, protocol, and infrastructure units. The transition of L2CM tasks to the protocol team and the investigation into `op-reth` payload execution demonstrate active communication between maintainers of different components of the OP Stack. The focus on "Definition of Done" (DoD) for the Interop Proofs Devnet—requiring approvals from the Proofs Team and coordination with the Conductor Re-orgs team—highlights the highly integrated nature of current development efforts.

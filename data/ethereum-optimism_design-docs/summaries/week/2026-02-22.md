# ethereum-optimism/design-docs Weekly Report (Feb 22 - 28, 2026)

## 🚀 Highlights
This week focused on advancing the technical specifications for the Superchain’s interoperability and security frameworks. Key progress was made in defining Zero-Knowledge (ZK) dispute game mechanisms and refining the Superroot Service Level Agreement (SLA) to better handle optimistic versus verified outputs. Significant architectural discussions also addressed how downstream components should manage L1 reorgs and how "lite" nodes track safe heads during interop synchronization. These developments underscore a concerted effort to harden protocol security while improving the precision of cross-chain data handling.

## 🛠️ Key Developments

### Protocol Security & Dispute Mechanisms
The project continues to evolve its fraud-proofing capabilities by integrating more advanced cryptographic proofs into the dispute process.
*   **ZK Dispute Games:** A significant new feature was introduced to incorporate ZK dispute games into the design documentation, marking a step forward in the transition toward ZK-augmented security models ([#368](https://github.com/ethereum-optimism/design-docs/pull/368)).
*   **Compliance Module:** Initial design work began on a new compliance module, aimed at expanding the framework's regulatory and operational utility ([#367](https://github.com/ethereum-optimism/design-docs/pull/367)).

### Superchain Interoperability & State Management
Technical refinements were proposed to ensure the Superchain remains resilient during network fluctuations and reorgs.
*   **Superroot SLA Refinement:** Work is underway to enable the fetching of optimistic versus verified outputs. The proposed behavior suggests that optimistic roots should be treated as "best-effort," returning empty values when unavailable to maintain system stability.
*   **L1 Reorg Handling:** New specifications were discussed regarding how Chain Containers should prune Denylists when a Virtual Node detects an L1 reorg. This includes ensuring `Reset(chain, ts)` callbacks trigger even during uncontrolled regressions of the Local Safe ([#19289](https://github.com/ethereum-optimism/design-docs/issues/19289)).

## 🐛 Issues & Triage

### New & Active Issues
*   **`op/kona-node lite` Sync Logic:** A deep dive into `op-node` behavior in lite mode revealed a need to better distinguish between "unqualified safe" (`safe_l2`) and "qualified safe" (`local_safe_l2`). The current "follow source" protocol prevents these heads from syncing independently; the proposed fix ensures the lite CL accurately mirrors the source's specific head types to support interop invariants ([#19325](https://github.com/ethereum-optimism/design-docs/issues/19325)).
*   **op-geth Historical State Fallback:** Maintainers are investigating whether a reported issue with `makeEnv` historical state fallback is a specific bug within `op-geth` or an upstream issue that should be addressed in the core Geth repository ([#767](https://github.com/ethereum-optimism/design-docs/issues/767)).

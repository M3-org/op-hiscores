# ethereum-optimism/design-docs Weekly Report (Mar 22 - 28, 2026)

## 🚀 Highlights
This week’s development focused heavily on protocol security and stability, specifically regarding the ZK Dispute Game and the derivation pipeline. A major milestone was reached with the completion of a comprehensive Failure Mode Analysis (FMA) for the ZK Dispute Game, which outlines 30 actionable items to harden the system against potential vulnerabilities. Additionally, the team resolved critical execution panics within the Kona guest program and continued investigating complex synchronization logic to address persistent test flakiness in the derivation pipeline.

## 🛠️ Key Developments

### ZK Dispute Game Security & Hardening
The primary technical focus this week was the formalization of security requirements for the ZK Dispute Game. 
*   **Failure Mode Analysis (FMA):** A detailed FMA document was integrated, identifying 8 specific failure modes. The document provides a framework for risk assessment, mitigation strategies, detection mechanisms, and recovery paths. This effort resulted in a consolidated roadmap of 30 action items and defined audit requirements to ensure the robustness of the ZK components ([#369](https://github.com/ethereum-optimism/design-docs/pull/369)).

### Protocol & Batch Management
Work began on refining how the protocol handles data efficiency and batching logic.
*   **Span Batch Optimization:** A new initiative was launched to address the handling of overlapping span batches within the protocol, aimed at improving the consistency of data processing ([#371](https://github.com/ethereum-optimism/design-docs/pull/371)).

## 🐛 Issues & Triage

### Closed Issues
*   **Kona Guest Panic:** Developers resolved a critical bug where the Kona guest program panicked during Cannon VM execution. The root cause was identified as a missing `name` field during the deserialization of the superchain registry chain list ([#19654](https://github.com/ethereum-optimism/design-docs/issues/19654)).

### New & Active Issues
*   **Derivation Pipeline Flakiness:** The `TestCLELDivergence` test remains a point of active investigation due to intermittent failures ([#19681](https://github.com/ethereum-optimism/design-docs/issues/19681)). While a potential mitigation has been implemented, the team is debating whether observed resets are indicative of a bug in the reset logic or a standard part of the initial derivation pipeline lifecycle. The issue remains open to confirm if the recent PR successfully eliminates the flakiness.

## 💬 Community & Collaboration
The week was characterized by deep technical rigor, particularly in the collaborative review of the ZK Dispute Game's security posture. The transition from identifying failure modes to a structured 30-item action plan suggests strong coordination between security researchers and protocol engineers. Furthermore, the ongoing dialogue surrounding the `TestCLELDivergence` issue highlights a focused effort to distinguish between expected protocol behavior and edge-case bugs in the Execution Layer (EL) synchronization logic.

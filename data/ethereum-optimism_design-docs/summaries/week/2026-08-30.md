# ethereum-optimism/design-docs Weekly Report (Aug 30 - Sep 5, 2026)

## 🚀 Highlights
This week focused on refining the technical foundations of the Superchain ecosystem, specifically addressing protocol validation and Go module architecture. A significant milestone was reached with the resolution of span batch validation logic for the Holocene upgrade, ensuring consistency with legacy safety checks. Simultaneously, a deep architectural audit is underway to resolve consumability issues for `op-core/superchain`, aiming to streamline dependencies and improve the developer experience for downstream Go modules.

## 🛠️ Key Developments
While no new design documents were finalized this week, the project saw significant progress in refining existing protocol specifications and preparing for upcoming implementation changes in the core repository.

### Protocol Integrity & Validation
Work concluded on the specifications for **Holocene Span Batch Validation**. The focus was on ensuring that the `checkSpanBatchPrefix` function correctly validates batch elements that overlap with the safe chain. This alignment with legacy validation logic is critical for maintaining protocol security during the Holocene transition. The resolution of this design issue ([#22351](https://github.com/ethereum-optimism/design-docs/issues/22351)) directly informs implementation work currently occurring in the main Optimism repository.

## 🐛 Issues & Triage
The week was characterized by high-level technical triage regarding how the Superchain registry is consumed by external tools.

### Closed Issues
*   **Holocene Safety Checks:** Issue [#22351](https://github.com/ethereum-optimism/design-docs/issues/22351) was closed following the identification of necessary validation logic for span batch prefixes, ensuring that overlapping content is properly checked against the safe chain.

### Active Issues & Discussions
*   **Superchain Module Consumability ([#22678](https://github.com/ethereum-optimism/design-docs/issues/22678)):** A major ongoing discussion involves the inability of downstream Go modules to consume `op-core/superchain` because the required `superchain-configs.zip` is currently gitignored. 
    *   **Dependency Decoupling:** Contributors identified several "accidental dependencies" that bloat the module. Proposed fixes include splitting the `DependencySet` types from the `FromRegistry` loader in `op-core/interop/depset` and removing unused code in `interopgen`.
    *   **Storage Strategy:** There is an active debate between using Git-LFS (deemed impractical for `cmd/go`), submodules (which fail with `//go:embed`), or committing loose files. Quantitative analysis suggests that committing loose files offers better reviewability with a negligible impact on repository size (~3 MB/year).
    *   **Prevention:** New `depguard` tests are being introduced ([#22700](https://github.com/ethereum-optimism/optimism/pull/22700)) to prevent future accidental dependency edges from being created.

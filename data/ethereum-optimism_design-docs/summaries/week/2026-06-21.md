# ethereum-optimism/design-docs Weekly Report (Jun 21 - 27, 2026)

## 🚀 Highlights
This week’s activity focused on refining core protocol specifications and addressing technical debt within the Optimism stack's data handling layers. A significant technical investigation into blob encoding non-bijectivity highlighted potential discrepancies between `op-node` and `kona` implementations, sparking a critical discussion on data integrity and hardfork requirements. Additionally, new design documentation was introduced to address Post-Execution transactions within the Fault Proof / State Transition framework.

## 🛠️ Key Developments

The project continues to evolve its state transition and fault monitoring architectures.
*   **FMA: SDM / PostExec tx ([#388](https://github.com/ethereum-optimism/design-docs/pull/388)):** A new pull request was opened to document the design for Post-Execution transactions within the State Deposit Model (SDM). This work is essential for ensuring the integrity of the state transition function after transaction execution.

## 🐛 Issues & Triage

### New & Active Issues
*   **Blob Encoding Non-Bijectivity ([#21539](https://github.com/ethereum-optimism/design-docs/issues/21539)):** A deep-dive investigation into a flaky test in `op-service/eth` revealed a fundamental characteristic of the current blob encoding implementation. The analysis found that the top two bits of the first field element are masked out by both `op-node` and `kona`, meaning the encoding is not bijective. This allows different encoded inputs to result in the same decoded data.
    *   **Impact:** The discussion highlights a potential risk where changing this behavior to enforce strict bijectivity could invalidate existing on-chain blobs. 
    *   **Proposed Path:** Resolution may require a protocol hardfork or a formal acceptance that honest batchers will naturally avoid malformed blob construction.

## 💬 Community & Collaboration
Technical collaboration this week was centered on cross-implementation consistency. The detailed analysis of the blob encoding issue demonstrates active coordination between developers working on the Go-based `op-node` and the Rust-based `kona` implementations. This level of scrutiny ensures that the Superchain maintains a unified state transition logic across different client software, which is vital for the security of the optimistic rollup mechanism.

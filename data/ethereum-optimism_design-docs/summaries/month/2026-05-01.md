# ethereum-optimism/design-docs Monthly Report (May 2026)

## 🚀 Highlights
In May 2026, development activity focused on refining the technical specifications and operational logic of the Superchain infrastructure. Key efforts centered on troubleshooting non-deterministic panics in `op-reth` during version upgrades and addressing calculation logic within `op-supernode`. Security also remained a priority with the initiation of new branch scan overviews. The month's work underscores the project's commitment to protocol stability and the seamless integration of multi-chain monitoring tools.

## 🛠️ Key Developments
While no new code contributions were finalized in the provided timeframe, significant technical investigation was conducted regarding the stability of the OP Stack's execution layer and supernode logic.

### Protocol Stability & Execution Layer
- **`op-reth` Upgrade Path Analysis:** Technical investigation into `op-reth` version 2.0.0 revealed a persistent assertion failure in the `alloy-trie` crate. Despite testing the `--engine.legacy-state-root` flag to bypass the `StateRootTask` strategy, the panic persisted in parallel trie computation paths. This suggests a deeper issue with how 1.x database states are handled during parallel processing, rather than a single-block corruption.

### Superchain Infrastructure
- **Supernode Logic Refinement:** Developers identified a potential logic error in `op-supernode` regarding the calculation of `VerifiedRequiredL1`. The current implementation in `Superroot.atTimestamp` incorrectly utilizes the minimum of per-chain `verifiedL1` values; discussions are underway to correct this to the maximum value to ensure proper cross-chain synchronization.

## 🐛 Issues & Triage
The month saw a mix of configuration clarifications and the identification of complex bugs affecting the Superchain's reliability.

- **Closed Issues:**
    - **Monitoring Configuration:** Issue [#20476](https://github.com/ethereum-optimism/design-docs/issues/20476) was resolved with the clarification that `op-dispute-mon` is capable of simultaneously monitoring both CANNON and SUPER_CANNON_KONA games. This is achieved by passing both `rollup-rpc` and `supernode-rpc` arguments, with the `op-supernode` serving as a valid RPC provider.

- **New & Active Issues:**
    - **Security Auditing:** A new issue [#379](https://github.com/ethereum-optimism/design-docs/issues/379) was opened to track the Wiz 'main' Branch Scan Overview, maintaining the project's security posture.
    - **State Root Panics:** Issue [#20462](https://github.com/ethereum-optimism/design-docs/issues/20462) remains a high-priority active item as contributors work to isolate the non-deterministic trie computation bug in `op-reth`.
    - **Acceptance Testing:** Issue [#20481](https://github.com/ethereum-optimism/design-docs/issues/20481) regarding `op-supernode` logic is currently awaiting the migration of acceptance tests from action tests to provide a reproducible environment for the fix.

## 💬 Community & Collaboration
Collaboration this month was characterized by deep technical troubleshooting between maintainers and contributors. The dialogue surrounding the `op-reth` state root panic (involving `shokeeb-yaqub-vcc`) demonstrates an active effort to debug complex Rust-based execution layer issues. Additionally, coordination between `ajsutton` and other contributors regarding `op-supernode` highlights the ongoing transition toward more robust testing frameworks for the Superchain ecosystem.

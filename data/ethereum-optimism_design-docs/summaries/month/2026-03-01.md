# ethereum-optimism/design-docs Monthly Report (March 2026)

## 🚀 Highlights
In March 2026, the `design-docs` repository focused on advancing the OP Stack's security architecture and refining protocol implementations. The most significant milestone was the introduction of a comprehensive design for ZK-based dispute games, signaling a major step toward multi-proof capabilities. Additionally, the project saw active maintenance through the deprecation of legacy features and a concerted community effort to resolve technical discrepancies within the Kona protocol.

## 🛠️ Key Developments

### ZK Dispute Game Integration
The primary technical advancement this month was the introduction of the ZK-based dispute game architecture. This design outlines how zero-knowledge proofs will be integrated into the existing OP Stack fault-proof system.
*   **Architecture & Lifecycle:** A new design document details the contract architecture, lifecycle management, and Optimism Portal Contract Manager (OPCM) integration for ZK games. This allows ZK-based games to function as a parallel proof system alongside traditional fault proofs, enhancing the overall security and decentralization of the Superchain ([#368](https://github.com/ethereum-optimism/design-docs/pull/368)).

## 🐛 Issues & Triage

### Closed Issues
*   **Legacy Feature Deprecation:** The issue regarding Flashblocks support in Geth was closed due to the deprecation of `op-geth`, ensuring the design documentation remains aligned with the current state of the `op-stack` codebase ([#756](https://github.com/ethereum-optimism/design-docs/issues/756)).
*   **General Maintenance:** Several older bug reports ([#338](https://github.com/ethereum-optimism/design-docs/issues/338), [#339](https://github.com/ethereum-optimism/design-docs/issues/339)) were triaged and closed to clean up the repository backlog.

### New & Active Issues
*   **Kona Protocol Refinement:** Significant discussion focused on resolving discrepancies between Kona and `op-node`. Key areas of concern include:
    *   Orphaned sources in `kona-derive` ([#19340](https://github.com/ethereum-optimism/design-docs/issues/19340)).
    *   Brotli channel disagreements between Kona and `op-node` ([#19333](https://github.com/ethereum-optimism/design-docs/issues/19333)).
    *   Denial-of-Service (DoS) vulnerabilities in `kona-protocol` related to unknown batch types ([#19334](https://github.com/ethereum-optimism/design-docs/issues/19334)).
    *   Frame parsing mismatches ([#19335](https://github.com/ethereum-optimism/design-docs/issues/19335)).
*   **Access Control:** Discussions are ongoing regarding the implementation of `ProxyAdminOwnedBase` for L2CM (Layer 2 Contract Manager) to standardize access control for predeploy initialization ([#19313](https://github.com/ethereum-optimism/design-docs/issues/19313)).

## 💬 Community & Collaboration
The month was characterized by strong community engagement, particularly in the Kona ecosystem. Contributor **Moses-main** emerged as a key participant, volunteering to address multiple high-priority issues ranging from DoS vulnerabilities to protocol parsing mismatches. Collaboration between maintainers and contributors was evident in the triage of L2CM access control, where established L1 contract patterns were suggested as implementation guides. This proactive community involvement is critical as the project moves toward more complex proof systems and tighter protocol specifications.

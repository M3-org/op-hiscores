# ethereum-optimism/design-docs Monthly Report (January 2026)

## 🚀 Highlights
In January 2026, development activity focused on expanding the protocol documentation for the Kona rollup node and initiating designs for more flexible sequencer operations. A significant milestone was the integration of the Light CL (follow mode) design, which enhances the Kona node's capabilities. Additionally, the community began addressing technical debt regarding RPC accuracy and initiated a high-level design for sequencer-defined metering to improve resource management.

## 🛠️ Key Developments

### Protocol Documentation & Kona Node Enhancements
The primary technical advancement this month involved the formalization of the Kona Rollup Node's architecture.
*   **Light CL (Follow Mode):** A new design document was merged detailing the implementation of the Light CL feature within `kona-node`. This documentation provides the technical blueprint for how the node operates in "follow mode," contributing to the broader goal of diversifying rollup node implementations ([#359](https://github.com/ethereum-optimism/design-docs/pull/359)).

### Future Infrastructure Planning
*   **Sequencer-Defined Metering:** A new initiative was launched to design a metering system defined by the sequencer. This work aims to establish a v0 implementation plan and benchmarking framework to better handle resource allocation and cost management at the sequencer level ([#360](https://github.com/ethereum-optimism/design-docs/issues/360)).

## 🐛 Issues & Triage

### Closed Issues
*   **OP Stack Compatibility:** Documentation was clarified regarding the compatibility of Base-style minimal contracts on the OP Stack. The resolution confirmed that while smart contracts are generally compatible, developers should refer to specific documentation for nuances where L2 behavior diverges from Ethereum L1 ([#18709](https://github.com/ethereum-optimism/design-docs/issues/18709)).

### New & Active Issues
*   **SyncStatus RPC Accuracy:** Significant discussion occurred regarding the `optimism_syncStatus` RPC endpoint. It was identified that the `current_l1` field incorrectly references the latest L1 head rather than the derivation cursor. Maintainers are currently evaluating a fix that consolidates channels rather than adding further complexity ([#18673](https://github.com/ethereum-optimism/design-docs/issues/18673)).
*   **Super DA Error Codes:** Ongoing efforts to standardize error reporting within the Superchain ecosystem are underway, specifically focusing on adding missing error codes for Super DA ([#725](https://github.com/ethereum-optimism/design-docs/issues/725)).

## 💬 Community & Collaboration
Collaboration this month was characterized by focused technical reviews on protocol-level accuracy. Maintainers like `op-will` provided critical feedback on RPC behavior, ensuring that design documents remain aligned with actual node implementation. There is also evidence of cross-project coordination, as seen in the discussions regarding Super DA error codes and the integration of Kona-related features, which involve multiple stakeholders across the Optimism Collective.

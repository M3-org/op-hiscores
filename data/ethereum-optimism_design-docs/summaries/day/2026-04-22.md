# ethereum-optimism/design-docs Daily Update (Apr 22, 2026)
## OVERVIEW 
Today's development focused on refining naming conventions within the protocol documentation. Several long-standing issues related to batcher throttling and flaky tests were closed, indicating progress in stability and clarity.

## KEY TECHNICAL DEVELOPMENTS

*   **Protocol Naming Refinement**
    *   A naming convention was updated from "fusaka" to "osaka" in the `protocol/osaka-on-l2.md` file to improve clarity and consistency within the documentation [#376](https://github.com/ethereum-optimism/design-docs/pull/376).

No new pull requests were opened today.

## CLOSED ISSUES

*   **Batcher Throttling Implementation Confirmed**
    *   Issues related to `op-reth` and `op-rbuilder` batcher throttling were closed as the functionality was confirmed to be already supported [#18764](https://github.com/ethereum-optimism/design-docs/issues/18764), [#19023](https://github.com/ethereum-optimism/design-docs/issues/19023).
*   **Flaky Test Resolution**
    *   A flaky test concerning `TestInteropFaultProofs_VariedBlockTimes_FasterChainB/SuperRootInvalidIfUnsupportedByL1Data-fpp` was closed after being stable for a significant period and having its `MarkFlaky` tag removed [#19829](https://github.com/ethereum-optimism/design-docs/issues/19829).

## NEW ISSUES
No new issues were reported today.

## ACTIVE ISSUES

*   **Kona-Interop Block Access Review** [#19266](https://github.com/ethereum-optimism/design-docs/issues/19266)
    *   Discussion continues regarding how Kona-proofs interop handles internally created blocks, particularly concerning the generation and storage of receipts for replaced deposit-only blocks. The latest comment confirms a related issue where generated receipts for replaced blocks are not stored, potentially causing consolidation failures if other messages reference them.
*   **SDM Specs Documentation** [#20182](https://github.com/ethereum-optimism/design-docs/issues/20182)
    *   The issue tracks the addition of SDM specs to the official Optimism documentation. A reference to a relevant pull request was provided.
*   **op-reth vs. op-geth Usage** [#20203](https://github.com/ethereum-optimism/design-docs/issues/20203)
    *   A user inquired about the mandatory use of `op-reth` and the continued support for `op-geth`. While `op-geth` is supported until May 31st, the latest comment highlights that `simple-optimism-node` does not yet support `op-reth` as an execution client, and requests an official guide for running a node with `op-reth`.
*   **Flaky Test: `TestSequencingWindowExpiry`** [#20212](https://github.com/ethereum-optimism/design-docs/issues/20212)
    *   Investigation into a flaky `TestSequencingWindowExpiry` test revealed a race condition between two writers in `OpProofsExEx`. A draft fix has been opened, involving adding a write lock to eliminate the fatal race. Follow-up actions include addressing the lack of a regression test and a potential state-machine smell with `sync_target_tx`.
*   **SDM: Move PoC2 Functionality to `develop`** [#20216](https://github.com/ethereum-optimism/design-docs/issues/20216)
    *   The issue tracks the integration of PoC2 functionality into the `develop` branch. A pull request has been created and is awaiting review.
*   **Missing Finalized Docker Image Tags** [#20228](https://github.com/ethereum-optimism/design-docs/issues/20228)
    *   Users reported missing finalized Docker image tags for `op-reth v2.1.0`, `op-node v1.16.13`, and `kona-node v1.3.0`. The build for these tags failed, and users are advised to use the `-rc.1`-suffixed Docker images as a temporary workaround. The issue is expected to be resolved in the next release.

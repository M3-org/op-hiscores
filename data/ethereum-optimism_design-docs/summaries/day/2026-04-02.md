## ACTIVE ISSUES

### Flaky Test: `TestSuperCannonStepWithPreimage_nonExistingPreimage`
This issue ([#19892](https://github.com/ethereum-optimism/design-docs/issues/19892)) concerns a consistently flaky test in the `mt-cannon-next` suite. The latest investigation reveals the challenger intermittently steps at the wrong trace index, one position before the preimage load, leading to `containsOracleData=false` and a timeout. This non-deterministic behavior is attributed to resource contention in CI, causing the challenger's kona execution to fail or truncate. A fix involving serializing subtests and sharing one interop system, combined with a recent kona fix, is recommended to eliminate the flake. Further diagnostic logging has been added to `loadProof` to capture `lastStep` and trace index data for deeper analysis.

### Flaky Test: `TestExecutePayloadSuccess`
The `TestExecutePayloadSuccess` in `rust/op-reth/tests/proofs/core` is experiencing flakiness ([#19898](https://github.com/ethereum-optimism/design-docs/issues/19898)). The root cause has been identified as a race condition where the test queries the validator immediately after funding, but the validator's proofs ExEx may not have indexed block 1 yet, resulting in "no state found for block number 1". A proposed fix involves adding `WaitForBlockNumber` synchronization between the sequencer and validator to ensure the ExEx has processed the necessary block before the query.

### Flaky Tests: Database Resync Issues
The issue ([#19661](https://github.com/ethereum-optimism/design-docs/issues/19661)) tracking `TestPreserveDatabaseOnCLResync`, `TestTruncateDatabaseOnELResync`, and `TestCLUnsafeNotRewoundOnInvalidDuringELSync` was reopened today. While previously thought to be resolved, `TestTruncateDatabaseOnELResync` has resurfaced with a new failure: "expected head to match: safe". This new failure has a different root cause than the stale RPC address issue initially tracked, and a separate issue will be opened to track it. The original issue is now closed again.

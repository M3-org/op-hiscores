## ACTIVE ISSUES

### Kona Interop Block Access Review
- **[#19266](https://github.com/ethereum-optimism/design-docs/issues/19266) kona-interop: Review access of blocks created internally**
  - Discussion revolved around how `kona-proofs` interop handles internally created blocks during validation and replacement.
  - A key point raised is that if `kona` generates a replacement block when the canonical chain didn't, it indicates a problem.
  - A separate issue was identified: when a block replacement occurs, its generated receipts are not stored. If a deposit-only block is referenced by other messages, consolidation fails when the message graph resolution tries to read its receipts.

### Flaky Test Investigations
- **[#19936](https://github.com/ethereum-optimism/design-docs/issues/19936) flaky test: `TestUnsafeGapFillAfterUnsafeReorg_RestartL2CL`**
  - The test `TestUnsafeGapFillAfterUnsafeReorg_RestartL2CL` continues to be flaky, observed on both `op-geth` and `op-reth` configurations.
  - The error "18 is not greater than 18" indicates a race condition not specific to `reth`.
  - An investigation into a fix has been launched.
- **[#20198](https://github.com/ethereum-optimism/design-docs/issues/20198) flaky test: `TestReorgUnsafeHead`**
  - A proposed fix for this flaky test has been drafted.
  - The root cause was identified as asynchronous updates in `op-node`'s `StatusTracker.data.UnsafeL2` and `Sequencer.latestHead` compared to synchronous EL updates.
  - The fix involves replacing `time.Sleep` with a poll on `SyncStatus().UnsafeL2.Hash` against the EL's authoritative unsafe head before calling `StartSequencer`.
  - It was clarified that this test runs against `op-node`, despite the CI label.

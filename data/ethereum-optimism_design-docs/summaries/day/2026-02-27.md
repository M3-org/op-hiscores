## ACTIVE ISSUES
### `op/kona-node lite` Sync Status Discussion [#19325](https://github.com/ethereum-optimism/design-docs/issues/19325)
Discussions continued regarding the behavior of `op-node` in lite mode, specifically how it handles `local_safe` and `safe` heads from a source. The core of the discussion revolves around distinguishing between "unqualified safe" (`SyncStatus.safe_l2`), which represents fully verified safe blocks, and "qualified safe" (`SyncStatus.local_safe_l2`), which are blocks derived from L1 but not yet interop-verified.

The latest comments clarify the terminology, emphasizing the need for virtual CLs in the supernode to track both `local_safe_l2` and `safe_l2` for interop. A key invariant was highlighted: `safe_l2.number <= local_safe_l2.number <= unsafe_l2.number`. The problem identified is that the "follow source" protocol in lite CLs currently uses the source's `safe_l2` as the destination's `local_safe_l2`, preventing both heads from being synced independently. The proposed solution is to ensure that the `local_safe_l2` of the light CL matches the `local_safe_l2` of the source, and similarly for `safe_l2`.

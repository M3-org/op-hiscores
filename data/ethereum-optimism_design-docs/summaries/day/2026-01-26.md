## ACTIVE ISSUES

### op-deployer: "transaction gas limit too high"
Discussion continued on the issue of `op-deployer:v0.2.6` failing to deploy contracts due to "transaction gas limit too high" errors [#17912](https://github.com/ethereum-optimism/design-docs/issues/17912). A recent comment inquired about the fix and which `op-deployer` version to use for alt-da. Previously, it was noted that the Fusaka hardfork enforces a transaction gas limit cap, and transactions exceeding this limit need to be broken down or optimized. The use of `v0.5.0*` for the latest contract release was suggested, though its post-Fusaka behavior was not yet fully tested.

### op-batcher: stay in sync with op-node rollup config
The discussion around the `op-batcher` not fetching the rollup config after initial startup [#18178](https://github.com/ethereum-optimism/design-docs/issues/18178) saw a new suggestion to treat an outdated config as a critical error and restart the process, allowing the batcher to reload the config. Earlier suggestions included making the operator explicitly provide the rollup config to the batcher or hooking into the active endpoint provider to signal when the active endpoint changes, prompting a reload of the rollup config. The trade-off of requiring a new batcher release for each Superchain Registry config change was also noted.

### Add Sequencer-Defined Metering Design Doc
The scope of the issue to add a Sequencer-Defined Metering Design Doc [#360](https://github.com/ethereum-optimism/design-docs/issues/360) was expanded to include the initial Proof of Concept (PoC), as it is currently blocking the design document. The initial devnet deployment is planned for January 30, 2026, after which the design can be evaluated and basic benchmarking performed.

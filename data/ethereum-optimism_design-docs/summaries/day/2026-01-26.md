## ACTIVE ISSUES

### op-deployer: "transaction gas limit too high"
Discussion continues on the `op-deployer` issue where transactions are failing due to gas limits being too high ([#17912](https://github.com/ethereum-optimism/design-docs/issues/17912)). The latest comment from RISHABHAGRAWALZRA inquired about the fix status and which `op-deployer` version to use for alt-da, following up on a previous comment by sbvegan which attributed the issue to the Fusaka hardfork's enforcement of a transaction gas limit cap and suggested using `v0.5.0*` of `op-deployer`.

### op-batcher: stay in sync with op-node rollup config
The discussion around the `op-batcher` not staying in sync with the `op-node` rollup config ([#18178](https://github.com/ethereum-optimism/design-docs/issues/18178)) saw a new suggestion from geoknee to treat out-of-sync as a critical error and restart the process, allowing the batcher to reload the config. This builds on earlier suggestions from sebastianst and joshklop about making the rollup config dependency explicit, potentially by having the operator provide it to the batcher or by querying the chain ID at startup.

### Add Sequencer-Defined Metering Design Doc
The scope of the issue to add a Sequencer-Defined Metering Design Doc ([#360](https://github.com/ethereum-optimism/design-docs/issues/360)) has been expanded to include an initial Proof of Concept (PoC). joshklop noted that the PoC is currently blocking the design document, with an initial devnet deployment planned for January 30, 2026, after which the design can be evaluated and basic benchmarking performed.

# ethereum-optimism/design-docs Daily Update (May 6, 2026)
## OVERVIEW 
The day saw a new design document proposed for a compliance module. Significant progress was made on addressing flaky tests, with fixes submitted for two different issues. Discussions continued on several active issues, including those related to interop, gas accounting, and supernode healthchecks.

## KEY TECHNICAL DEVELOPMENTS

### Flaky Test Resolution
Multiple flaky tests were addressed today. A fix was submitted for `TestPreinteropFaultProofs_VariedBlockTimes` after a root cause analysis revealed issues with `freezeChains` not properly draining `LocalSafe` before stopping batchers. Another fix was opened for `TestChallengerRespondsToMultipleInvalidClaims`, which was found to be flaky due to a race condition between the proposer and test game creation. ([#19804](https://github.com/ethereum-optimism/design-docs/issues/19804), [#20574](https://github.com/ethereum-optimism/design-docs/issues/20574))

Progress was made on improving documentation around gas accounting edge cases and experimenting with global `isolate = true` settings in Foundry. A draft PR was created to add a "Gas Accounting in Tests" section to the style guide, and an experimental PR was opened to test the impact of a global `isolate = true` setting. ([#20388](https://github.com/ethereum-optimism/design-docs/issues/20388))

### SystemConfig Updates for OPCM.migrate
A fix was put in place to ensure that `SystemConfig` is correctly updated with new shared addresses during `OPCM.migrate` operations, specifically addressing the `delayedWeth()` return value for chain B. ([#20511](https://github.com/ethereum-optimism/design-docs/issues/20511))

## ACTIVE ISSUES

### Flaky Test: TestPreinteropFaultProofs_VariedBlockTimes ([#19804](https://github.com/ethereum-optimism/design-docs/issues/19804))
This flaky test was reopened after failing again with a different root cause. The new failure points to `advanceUnsafeToTimestamp` where `startTimestamp` can be less than the current unsafe head's timestamp on the faster chain, tripping an assertion. A fix has been submitted in `ethereum-optimism/optimism#20580` which reorders `freezeChains` to drain `LocalSafe` up to `LocalUnsafe` before stopping batchers, ensuring `LocalSafe == LocalUnsafe`.

### Interop + Batcher: Use Verification-Aware CurrentL1 ([#19944](https://github.com/ethereum-optimism/design-docs/issues/19944))
Discussion continues on this issue, with a relevant ticket `ethereum-optimism/optimism#20134` being linked. The issue is currently queued behind more immediate sync issues on devnets and is considered at risk for its notional end-of-month completion target.

### [M4] kona-node: Light CL: Further Testing and Fixes ([#18800](https://github.com/ethereum-optimism/design-docs/issues/18800))
A note was added clarifying that this ticket, while pointing to valid bugs, does not block the initial launch of interop.

### [L2CM retro] Go vs. EVM and Gas Accounting issues ([#20388](https://github.com/ethereum-optimism/design-docs/issues/20388))
Updates were provided on the status of both items. For better documentation, a draft PR (`#20570`) was created to add a "Gas Accounting in Tests" subsection to the style guide. For applying `forge-config: default.isolate = true` globally, an experimental draft PR (`#20572`) was opened to test the impact on CI, with the goal of gathering information on what breaks before deciding on a global change.

### OPCM.migrate: Ensure SystemConfig is updated with new addresses ([#20511](https://github.com/ethereum-optimism/design-docs/issues/20511))
A fix has been put up for this issue, addressing the concern that `SystemConfig` for both chains should be updated to return new shared addresses, particularly for `delayedWeth()`.

### Add unsafe head executing message validation ([#20553](https://github.com/ethereum-optimism/design-docs/issues/20553))
Further `TODO` items were outlined, including updating `proxyd` to point at the interop filter for querying 'cross-unsafe' and limiting head to 'cross-unsafe', and making failsafe optional by adding reorg support to the interop filter.

### Flaky test: `TestChallengerRespondsToMultipleInvalidClaims` ([#20574](https://github.com/ethereum-optimism/design-docs/issues/20574))
A fix has been opened in `ethereum-optimism/optimism#20575`. The root cause was identified as a race condition where the test's `StartSuperCannonKonaGame` could collide with the op-proposer's submissions, leading to `GameAlreadyExists` errors. The fix introduces a `presets.WithoutHonestProposer()` option to prevent these races in tests that don't exercise the proposer.

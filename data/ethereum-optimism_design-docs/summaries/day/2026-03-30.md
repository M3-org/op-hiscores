## ACTIVE ISSUES

### Addressing Flaky Interop Fault Proof Tests
Discussion on [#19804](https://github.com/ethereum-optimism/design-docs/issues/19804) identified the root cause of flaky `TestPreinteropFaultProofs_VariedBlockTimes` tests. The issue stemmed from `l1BlockWithLocalSafeBlocks()` polling the supernode's `RequiredL1` values, which shifted due to sequencer activity during batcher choreography. A fix has been submitted in #19805, replacing supernode polling with direct L1 head reads to maintain invariants.

### Investigating Flaky Super Cannon Tests
Issue [#19806](https://github.com/ethereum-optimism/design-docs/issues/19806) reported a flaky test `TestSuperCannonRootBeyondProposedBlock_ValidRoot/mt-cannon-next`. The latest comment indicates that the test failure was a false positive, as Claude incorrectly reported it as flaky after a local failure.

### Resolving Flaky `TestFollowSource_HeadsDivergeThenConverge`
On [#19821](https://github.com/ethereum-optimism/design-docs/issues/19821), the root cause for the flaky `TestFollowSource_HeadsDivergeThenConverge` test was identified. The `Interop.Stop()` function was not waiting for the `Start()` goroutine to exit before chain containers were stopped, leading to panics when `SafeHeadAtL1()` was called on a closed SafeDB. A fix has been proposed in #19824, which adds `ErrClosed` guards to SafeDB read/write methods to convert panics into graceful error returns.

## ACTIVE ISSUES
### `op-geth` Decoupling: Test Migration and L2 Transaction Representation
Discussions on [#20265](https://github.com/ethereum-optimism/design-docs/issues/20265) (opgeth-decoupling: migrate tests) highlighted two key considerations for test migration: receipt index-correlation breaking under class-partitioned accessors and Lagoon adding a trailing `0x7D` post-exec tx to L2 blocks. The conversation on [#20264](https://github.com/ethereum-optimism/design-docs/issues/20264) (opgeth-decoupling: make op-service/sources the OP-aware eth client) focused on a design resolution for L2 transaction representation, proposing to partition L2 tx accessors by tx class instead of using an `optypes.Transaction` wrapper. This approach aims to exclude synthetic OP types (`0x7E` deposits, `0x7D` post-exec) from standard Ethereum transaction lists and handle them with specific accessors. The discussion also noted that Lagoon makes `0x7D` routing load-bearing. For [#20262](https://github.com/ethereum-optimism/design-docs/issues/20262) (opgeth-decoupling: create op-core/types), a design note clarified that `*types.Transaction` helpers for `DepositTx` and `PostExecTx` are transition-only and will be deleted at the final cutover to upstream go-ethereum. It was also noted that `PostExecTx` is a canonical block transaction in Lagoon. Finally, on [#20263](https://github.com/ethereum-optimism/design-docs/issues/20263) (opgeth-decoupling: swap call-sites to op-core/*), it was emphasized that `optypes` helpers are transition scaffolding and should not be used for new long-lived APIs. Call sites should prefer decoding raw tx bytes to `optypes.DepositTx` over routing through `*types.Transaction` helpers where possible.

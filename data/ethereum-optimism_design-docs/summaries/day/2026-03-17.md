## ACTIVE ISSUES

### op-node: On the Initial EL Sync UX and Correctness [#17631](https://github.com/ethereum-optimism/design-docs/issues/17631)
Discussion continued on the behavior of `op-node` marking blocks as finalized after initial EL sync, even if they are not truly finalized. The latest comments propose solutions to address this, including continuing EL sync to the unsafe head but using a different finalization gadget. Options for the finalization gadget include a command-line flag, an RPC URL for a trusted checkpoint provider, looking at L1 for the last finalized head, or an arbitrary delay. The discussion also clarified that this issue might be exacerbated by light CL and that sequencer nodes are typically fully synced before service.

### [tracking]: Review kona-interop block hash oracle [#18288](https://github.com/ethereum-optimism/design-docs/issues/18288)
The discussion on reviewing the `kona-interop` block hash oracle highlighted the need for an integration or acceptance test. The remaining task is to ensure that the system can successfully look up a block prior to the current history window.

### Supernode test coverage [#19010](https://github.com/ethereum-optimism/design-docs/issues/19010)

Ten tests remain in `op-e2e` that cover scenarios not yet ported to the shared `superfaultproofs` package.

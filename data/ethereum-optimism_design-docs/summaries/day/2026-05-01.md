**Persistent Panic in `op-reth` StateRootTask During Upgrade**
Discussion on [#20462](https://github.com/ethereum-optimism/design-docs/issues/20462) continued with an update from `shokeeb-yaqub-vcc`. Testing the `--engine.legacy-state-root` flag during an upgrade from `op-reth` 1.11.5 to 2.0.0 did not resolve the fatal panic. The panic, an assertion failure in `alloy-trie-0.9.5/src/nodes/branch.rs`, still occurs, even though the flag successfully changed the strategy from `StateRootTask` to `Parallel`. This suggests the bug is not specific to a single block but is triggered non-deterministically during parallel trie computation against 1.x database states, affecting both parallel trie code paths.

**`op-supernode` Incorrectly Calculating `VerifiedRequiredL1`**
Issue [#20481](https://github.com/ethereum-optimism/design-docs/issues/20481) highlights a potential bug in `op-supernode` where `Superroot.atTimestamp` calculates `minVerifiedRequiredL1` using the minimum of per-chain `verifiedL1` values instead of the maximum. `ajsutton` noted that the referenced acceptance tests for this issue are not yet migrated from action tests but will be available soon.

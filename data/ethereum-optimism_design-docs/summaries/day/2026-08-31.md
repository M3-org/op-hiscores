## ACTIVE ISSUES
### Superchain Module Consumability
Discussion continued on issue [#22678](https://github.com/ethereum-optimism/design-docs/issues/22678), which addresses the problem of `op-core/superchain` being unconsumable by downstream Go modules due to `superchain-configs.zip` being gitignored.

The latest comment from `sebastianst` provided a detailed analysis:
- **Git-LFS is not an option**: Explained that `cmd/go` builds module zips from raw git data and `proxy.golang.org` does not run LFS smudge, making git-lfs impractical for this use case.
- **Import-graph measurement**: Presented a measurement of the monorepo packages that reach the bundle, identifying several accidental dependencies.
    - `op-core/interop/depset` couples `DependencySet` types with the `FromRegistry` loader, leading to ~70 packages unnecessarily reaching the bundle. Splitting the loader out is proposed.
    - `op-chain-ops/interopgen/config/registry_config.go` has no callers in the monorepo or external consumers, and its deletion would clear `interopgen`.
    - Mentioned that [#22700](https://github.com/ethereum-optimism/optimism/pull/22700) clears flags/config packages for several `op-*` tools.
    - Noted that `op-batcher/batcher` imports `chaincfg` solely for a log banner.
- **Cleanup PRs incoming**: Announced upcoming PRs ([#22709](https://github.com/ethereum-optimism/optimism/pull/22709), [#22712](https://github.com/ethereum-optimism/optimism/pull/22712)) to address the `depset` split, dead-code deletion, and extend `depguard` tests to prevent new accidental dependencies. These changes are orthogonal to the zip-shipping decision and aim to clarify which components genuinely need the bundle.

Previous comments from `geoknee` provided a quantitative analysis of the issue:
- **Rationale for gitignoring**: Quantified the `.git` growth avoided by gitignoring the bundle, noting that `op-geth` commits its copy without significant issues. The marginal cost of one bump was estimated at ~245 KB, leading to ~3 MB/year, which is much lower than implied by "`.git` growth."
- **Loose files vs. zip**: Compared the `.git` size for loose extracted files versus a zip bundle, finding them barely distinguishable in terms of storage. Loose files would offer better reviewability.
- **Submodule limitations**: Explained why embedding directly from the `superchain-registry` submodule does not work, as `//go:embed` cannot escape its package directory and submodule content is absent from published modules.
- **Reducing package reach**: Suggested reducing the number of packages that reach the bundle, highlighting `op-service/oppprof` and `op-service/{apis,dial,sources,testutils,txintent}` as examples of accidental dependencies.
- **`depguard` test**: Mentioned that [#22700](https://github.com/ethereum-optimism/optimism/pull/22700) adds a `depguard` test to prevent new accidental edges.

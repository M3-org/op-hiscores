## ACTIVE ISSUES

### Supernode Safe Label Adjustments
Discussions continued on [#18976](https://github.com/ethereum-optimism/design-docs/issues/18976) regarding `op-supernode: Safe Label Adjusting`. The latest comment from geoknee on February 2nd, 2026, provided an update after further consideration. The key points include:
- Controlling an EL through `Forkchoiceupdate` requires a stateful controller, making it prone to errors with multiple controllers.
- The `op-node` engine controller already possesses interop-aware data structures and hooks.
- Geoknee is leaning towards the CL maintaining the full set of pointers [U,S,C,F] and remaining the sole controller of the engine.
- This approach would allow virtual nodes to return rich sync statuses, addressing a point raised by axelKingsley.
- The main downside is that `op-node` would have an understanding of running interop, potentially breaking a desirable invariant, though this might align with the concept of an "authority" object within the virtual node.

### BlockNotFoundError in ETH Bridge Tutorial
Discussion on [#1956](https://github.com/ethereum-optimism/design-docs/issues/1956) regarding a `BlockNotFoundError` in Step 5 of the ETH bridge tutorial continued. On February 2nd, 2026, opfocus highlighted that while Optimism SDK packages include `isValidOutputRoot` validation, viem's `Withdrawals guide` and related actions (e.g., `getGame`, `getGames`, `getL2Output`) do not appear to perform equivalent output-root validation. This suggests a potential area for improvement in viem's implementation to prevent such errors.

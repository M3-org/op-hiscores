- **LightCL Synchronization Observation and Root Cause Analysis**
  On [#20295](https://github.com/ethereum-optimism/design-docs/issues/20295), `karlfloersch` provided a detailed root cause analysis for the observation that `safe_l2`, `local_safe_l2`, and `finalized_l2` are zero on a fresh-genesis boot for LightCL. The issue stems from genesis `L2BlockRef`s being treated as unset state due to comparisons relying solely on `Number`, where both the real genesis ref and the zero-value `eth.L2BlockRef{}` have `Number == 0`. This prevents valid upstream genesis refs from passing "is this ahead?" checks. A recommended fix involves distinguishing "unset" from "genesis" using a full zero-value check or block identity, not just block number, and adding a regression test. An earlier comment from `karlfloersch` also questioned if a related PR, #20352, addressed this specific genesis/follow-source case.

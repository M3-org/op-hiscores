## ACTIVE ISSUES

- **`op-supernode`: Track FCU retry-verify workaround in RewindToTimestamp** [#19772](https://github.com/ethereum-optimism/design-docs/issues/19772)
  Discussion indicates that the team has accepted living with the current workaround for the `op-reth` race condition in `RewindToTimestamp`. The upstream PR to fix `reth`'s engine API was closed as stale, and there has been no further interest in synchronously applying results.

- **[L2CM] Investigate adding an array of predeploys to increase upgrade safety** [#19260](https://github.com/ethereum-optimism/design-docs/issues/19260)
  The issue was reopened due to a persistent TODO in the codebase referencing it. The TODO, located at `packages/contracts-bedrock/test/L2/L2ContractsManager.t.sol:1060`, indicates that a refactor is still needed for a single source of truth for predeploys. The discussion emphasizes that if the remaining work is out of scope for this issue, the TODO should be removed or repointed to a new issue.

- **L2CM: prevent silent drift between feature flag definitions and CI matrix** [#20340](https://github.com/ethereum-optimism/design-docs/issues/20340)
  A decision was made to address this issue by documenting all necessary update locations when adding new dev or system features. This documentation will be placed as comments in `DevFeatures.sol` and `devFeatures.go`.

- **bug(op-reth): proofs-history exex SIGBUS crash and infinite retry loop during deep FCU rewinds** [#20934](https://github.com/ethereum-optimism/design-docs/issues/20934)
  The issue was reopened as point 2 of the original problem (SIGBUS crash) still needs to be addressed. The current hypothesis suggests that `File::set_len(ftruncate)` might be truncating static-file mmap pages while another thread is reading them, leading to SIGBUS. The team is awaiting input from the Reth core team regarding this hypothesis.

- **bug(contracts-bedrock): semver-lock generation is nondeterministic for duplicate compiler-profile artifacts** [#21032](https://github.com/ethereum-optimism/design-docs/issues/21032)
  A comment was added, unrelated to the technical issue, providing a security advisory about AI data exfiltration when developers use AI tools for contract debugging.

- **C-flake: TestUnsafeChainNotStalling_CLSync family regressing again (post-#20950)** [#21041](https://github.com/ethereum-optimism/design-docs/issues/21041)
  An adversarial review revealed that the root cause is not a test budget bug but an `op-reth` Engine API stall. Evidence from CI logs shows the L2CL-b verifier stalled at block 40, with `engine_newPayloadV3` / `forkchoiceUpdated` RPC calls timing out repeatedly. The implication is that the bug lies within the `op-reth` Engine API or the `op-node` ⇄ `op-reth` Engine handshake. The next step involves rebasing a failing branch onto `develop` to include a recent fix (`#21012`) and re-running tests to see if the flake reproduces. No test-side changes will be implemented for now.

# ethereum-optimism/specs Monthly Report (March 2026)

## 🚀 Highlights
In March 2026, development activity focused on refining the technical specifications to ensure alignment with evolving implementations across the OP Stack. Key efforts were directed toward documentation restructuring, specifically co-locating contract specs with their codebases, and updating fault-proof requirements to match new blob hint data standards. While protocol-level documentation saw steady refinement, active discussions also emerged regarding the feature parity of `op-reth` with `op-geth`, particularly concerning interoperability and memory management.

## 🛠️ Key Developments

### Documentation Alignment & Restructuring
A primary theme this month was ensuring that specifications accurately reflect the current state of the Optimism monorepo and improving the developer experience through better organization.
*   **Fault-Proof Specifications:** Documentation for fault-proofs was updated to align with the latest blob hint data specifications. This ensures that the specs remain a "source of truth" following recent implementation changes in the main repository ([#890](https://github.com/ethereum-optimism/specs/pull/890)).
*   **Contract Spec Co-location:** As part of a broader initiative to keep documentation close to the code it describes, the `l2-upgrades-2-contracts.md` specification was moved to the optimism monorepo, with the specs repository now providing a redirect ([#895](https://github.com/ethereum-optimism/specs/pull/895)).
*   **Pruning Clarifications:** Work began on refining the "Holocene" pruning specifications, specifically focusing on clarifying channel size metrics to provide better guidance for node operators ([#894](https://github.com/ethereum-optimism/specs/pull/894)).

## 🐛 Issues & Triage

### Closed Issues
*   **Testing Infrastructure:** An issue regarding the implementation of granular time controls for the batcher and sequencer within `op-acceptance-tests` was closed ([#19009](https://github.com/ethereum-optimism/specs/issues/19009)). The team determined that current testing requirements could be met without this additional complexity for the time being.

### New & Active Issues
*   **`op-reth` Feature Parity:** A significant new feature request was opened to bring `op-reth` closer to `op-geth` functionality. This includes implementing interop transaction pool filtering and reorg eviction, which involves validating transactions against the supervisor ([#19411](https://github.com/ethereum-optimism/specs/issues/19411)).
*   **Memory Management:** Discussions continued regarding a persistent memory leak in `op-reth` related to long-running database read transactions ([#19212](https://github.com/ethereum-optimism/specs/issues/19212)). While the issue appears stable on version `v1.10.2`, the team is monitoring whether an upgrade to `v1.11.0` is required to resolve the underlying behavior.

## 💬 Community & Collaboration
Collaboration this month was characterized by cross-repository synchronization. The updates to fault-proof specs ([#890](https://github.com/ethereum-optimism/specs/pull/890)) and the relocation of contract specs ([#895](https://github.com/ethereum-optimism/specs/pull/895)) demonstrate tight coordination between the specification maintainers and the core protocol engineers working on the Optimism monorepo. Technical discussions around `op-reth` indicate an active feedback loop between users identifying performance bottlenecks (like memory leaks) and contributors defining the roadmap for interoperability features.

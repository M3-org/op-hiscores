# ethereum-optimism/specs Daily Update (Mar 5, 2026)
## OVERVIEW
Today, development focused on updating fault-proof documentation to reflect recent changes in blob hint data specifications. An issue regarding `op-acceptance-tests` was closed, while discussions continued on a memory leak issue in `op-reth` and a new feature for `op-reth`'s transaction pool.

## KEY TECHNICAL DEVELOPMENTS

### Fault-Proof Documentation Updates
The documentation for fault-proofs was updated to align with the latest blob hint data specification, following a recent pull request in the main Optimism repository. This ensures the specifications accurately reflect current implementations. ([#890](https://github.com/ethereum-optimism/specs/pull/890))

## NEWLY OPENED PULL REQUESTS
No new pull requests were opened today.

## CLOSED ISSUES

### `op-acceptance-tests` Time Control
An issue concerning the addition of more time control for the batcher and sequencer in `op-acceptance-tests` was closed, as the team has managed to avoid needing this functionality for now. ([#19009](https://github.com/ethereum-optimism/specs/issues/19009))

## NEW ISSUES

### `op-reth` Interop Transaction Pool Features
A new feature request was opened for `op-reth` to implement interop transaction pool filtering and reorg eviction, which are currently present in `op-geth`. This includes validating interop transactions against the supervisor and handling interop transaction reorgs. ([#19411](https://github.com/ethereum-optimism/specs/issues/19411))

## ACTIVE ISSUES

### `op-reth` Database Read Transaction Memory Leak ([#19212](https://github.com/ethereum-optimism/specs/issues/19212))
Discussions continued regarding a memory leak issue in `op-reth` where "The database read transaction has been open for too long triggers memory leak" warning appears, leading to high memory usage. The latest update indicates that while the issue was observed on `v1.10.2`, the team has not yet upgraded to `v1.11.0` to test if the problem persists, but they haven't seen the behavior in the last 7 days on `v1.10.2`. There is also a question about the necessity of "Periodic re-validation" for the proposed interop tx pool filter.

## CLOSED ISSUES

### `op-node` Stability Improvements
*   The issue of `op-node` getting stuck in EL sync mode after a restart when Reth already has synced data has been closed, indicating successful implementation of fixes to stabilize `op-node` driving `op-reth` ([#18468](https://github.com/ethereum-optimism/specs/issues/18468)).

### Contract Removal and Simplification
*   The `ProtocolVersions` contract and its associated deployment paths have been removed, streamlining the contract landscape now that `op-node` no longer monitors it ([#20309](https://github.com/ethereum-optimism/specs/issues/20309)).

## NEW ISSUES

### `op-challenger` Flag Consolidation
*   A new issue proposes consolidating per-VM flags into global flags within `op-challenger` to simplify configuration, though it's noted that different game types may require distinct config file formats ([#20547](https://github.com/ethereum-optimism/specs/issues/20547)).

### `op-node` Superroot Support
*   An issue has been opened to add `superroot_atTimestamp` support in `op-node` for non-interop chains, which will be crucial for fault dispute games after the super-roots upgrade ([#20552](https://github.com/ethereum-optimism/specs/issues/20552)).

## ACTIVE ISSUES

### `op-node` Stuck in EL Sync Mode
*   The issue [#18468](https://github.com/ethereum-optimism/specs/issues/18468) regarding `op-node` getting stuck in EL sync mode after a restart was closed today. The latest comment from `sebastianst` confirms that fixes have been implemented to stabilize `op-node` when driving `op-reth`, and requests reopening the issue if the problem persists. Previously, `sebastianst` had indicated they were investigating the issue, and `louisliu2048` suggested a temporary workaround by changing the sync mode.

### `alloy-op-evm`: Drop Dead-on-Read Fields
*   Discussion on [#20463](https://github.com/ethereum-optimism/specs/issues/20463) concerns removing unused `sender` and `evm_gas_used` fields from `OpTxResult` in `alloy-op-evm`. The latest comment from `sebastianst` suggests that `evm_gas_used` might be utilized in an ongoing pull request, indicating a potential reason to retain it.

### SDM: Move PoC2 Functionality
*   Issue [#20216](https://github.com/ethereum-optimism/specs/issues/20216) tracks the progress of moving PoC2 functionality into the `develop` branch. The most recent update from `geoknee` notes that acceptance tests and benchmarking tooling are still outstanding, indicating that the work is not yet complete. Earlier, `geoknee` had linked a pull request for review.

### Consolidate per-VM flags in `op-challenger`
*   Issue [#20547](https://github.com/ethereum-optimism/specs/issues/20547) proposes consolidating per-VM flags in `op-challenger`. The latest comment from `ajsutton` highlights a key challenge: different game types may require distinct configuration file formats, which could complicate a simple consolidation and suggests that the current pattern of separate flags might be necessary.

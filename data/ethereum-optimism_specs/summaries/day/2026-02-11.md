# ethereum-optimism/specs Daily Update (Feb 11, 2026)
## OVERVIEW 
The day saw significant progress in consolidating Rust workspaces and updating CI processes, with several issues related to `op-reth` and `op-alloy` being closed. Discussions continued on Kona hints and L2CM risk modeling.

## KEY TECHNICAL DEVELOPMENTS

## NEWLY OPENED PULL REQUESTS
A new pull request, [#891](https://github.com/ethereum-optimism/specs/pull/891), was opened to simplify the Interop Spec and add Supernode functionality.

## CLOSED ISSUES

### Rust Monorepo Consolidation
Several issues related to the Rust monorepo migration were closed, indicating progress in unifying Rust crates and configurations. This includes removing the `reth` submodule and updating CI to use `op-reth` [#18919](https://github.com/ethereum-optimism/specs/issues/18919), unifying all Rust crates into a single workspace [#18930](https://github.com/ethereum-optimism/specs/issues/18930), and consolidating Zepter configs across Rust repositories [#18931](https://github.com/ethereum-optimism/specs/issues/18931).

### Documentation Porting
The task of porting documentation from `reth` to `op-reth` was closed [#18969](https://github.com/ethereum-optimism/specs/issues/18969), suggesting completion of this documentation migration.

## NEW ISSUES

### Development Feature Flags
A new issue, [#19151](https://github.com/ethereum-optimism/specs/issues/19151), was opened to address a cyclic dependency in development feature flags within `op-deployer`. The discussion suggests moving shared OP protocol-specific code to `op-core/devfeatures`.

## ACTIVE ISSUES

### Kona Proofs and Just Recipes
Discussion on [#18654](https://github.com/ethereum-optimism/specs/issues/18654) regarding the removal of outdated `just` recipes for Kona continued. @Inphi commented that these recipes are still needed for local testing and prestate building, despite a recent PR using the monorepo for prestate generation.

### L2CM Upgrades Risk Modeling
Issue [#18869](https://github.com/ethereum-optimism/specs/issues/18869) concerning risk modeling for the L2CM design saw a new comment from @maurelian providing templates and examples for Failure Mode Analysis (FMA).

### Kona Hints Binary Format
On issue [#19125](https://github.com/ethereum-optimism/specs/issues/19125), which proposes using a binary format for Kona hints, @ajsutton questioned the necessity and performance benefits, highlighting backward compatibility requirements for the host. @kien-rise clarified that the motivation is primarily about correctness rather than speed, and expressed willingness to propose a compatibility-preserving approach. @ajsutton further emphasized that the host must continue to support string versions due to existing games.

### op-alloy Documentation Deployment
Issue [#18929](https://github.com/ethereum-optimism/specs/issues/18929) about deploying `op-alloy` docs to the Optimism namespace and updating the README was commented on by @theochap, referencing a related pull request [#19101](https://github.com/ethereum-optimism/optimism/pull/19101).

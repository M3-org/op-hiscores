# ethereum-optimism/specs Daily Update (Jul 8, 2026)
## OVERVIEW 
Today's development focused on clarifying the Ecotone blob-encoding specification. An issue related to breaking cyclic dependencies was closed, and a new pull request was opened to remove `batchInbox` and `startBlock` from the system configuration.

## KEY TECHNICAL DEVELOPMENTS

*   **Ecotone Specification Clarification**
    *   Clarified the Ecotone blob-encoding specification to align with reference implementations, specifically noting that the top two bits of the first field element are not enforced during decoding, contrary to a previous statement in the spec ([#923](https://github.com/ethereum-optimism/specs/pull/923)).

## NEWLY OPENED PULL REQUESTS
*   A new pull request, [#922](https://github.com/ethereum-optimism/specs/pull/922), was opened to remove `batchInbox` and `startBlock` from the system configuration.

## CLOSED ISSUES

*   **PCD Technical Specification Defined**
    *   The issue [#912](https://github.com/ethereum-optimism/specs/issues/912) regarding the technical specifications for breaking cyclic dependencies in the `op-deployer` pipeline was closed. This included defining each stage of the new pipeline and outlining all assumptions and invariants.

## NEW ISSUES

No new issues were opened today.

## ACTIVE ISSUES

*   **Flaky `reth-optimism-node` Integration Test SIGSEGV**
    *   The issue [#20973](https://github.com/ethereum-optimism/specs/issues/20973) continues to be active, with recent comments highlighting recurring SIGSEGV errors during the teardown of the `peers_negotiate_eth_69` integration test.
    *   A recent occurrence on July 8, 2026, caused a merge-queue check to fail, despite the test body passing, indicating a non-deterministic teardown crash.
    *   The suspected root cause, identified on May 22, 2026, points to a race condition during runtime teardown due to an orphan OS thread accessing Tokio internals that are concurrently being freed. This is linked to a change in the payload builder service from `spawn_critical_task` to `spawn_critical_os_thread` in a previous PR.
    *   The test `peers_negotiate_eth_69` is particularly affected as it's the only one using two full OpNode stacks, leading to two orphan payload-builder threads.

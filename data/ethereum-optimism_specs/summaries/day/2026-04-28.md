# ethereum-optimism/specs Daily Update (Apr 28, 2026)
## OVERVIEW 
Today, the `specs` repository saw a key feature addition documenting a reduction in the `bn256Pairing` precompile input size for the Karst execution engine. Several issues were also closed, including a bug fix for the `kona-host-client-offline-cannon` test and the implementation of the Bundle Canonicalization process.

## KEY TECHNICAL DEVELOPMENTS

### Karst Execution Engine Updates
A new feature was added to document a significant change in the Karst execution engine. This update details the reduction of the `bn256Pairing` precompile input size limit from 81,984 bytes (427 pairs) to 57,600 bytes (300 pairs), enhancing efficiency. This change is part of the broader Karst protocol development. ([#906](https://github.com/ethereum-optimism/specs/pull/906))

## CLOSED ISSUES

### Kona Test Stability Improvements
A bug causing the `kona-host-client-offline-cannon` test to crash due to an incorrect target specification in `cannon-builder:v1.0.0` has been resolved. The fix involved bind-mounting a corrected `mips64-unknown-none.json` and refreshing the committed witness tar. ([#19895](https://github.com/ethereum-optimism/specs/issues/19895))

### L2CM Upgrades and Bundle Canonicalization
The issue related to implementing the Bundle Canonicalization process for L2CM upgrades has been closed. This indicates progress in defining a workflow for updating bundled NUTs per hardfork, balancing manual triggers with automation and CI checks. ([#19307](https://github.com/ethereum-optimism/specs/issues/19307))

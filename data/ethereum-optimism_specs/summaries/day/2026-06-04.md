# ethereum-optimism/specs Daily Update (Jun 4, 2026)
## OVERVIEW 
Today's focus was on defining new protocol specifications for post-execution transactions and Sequencer-Defined Metering (SDM) within the Optimism ecosystem. Several issues related to testing, sync, and transaction pool behavior were also addressed and closed.

## KEY TECHNICAL DEVELOPMENTS

### Protocol Specification Updates
- **Post-Execution Transaction and SDM Specs Defined:** New specifications were added for the `0x7D` Post-Execution Transaction envelope and version-1 Sequencer-Defined Metering (SDM) payload schema. This work involved updates to the glossary and various protocol overview documents, particularly within the `specs/protocol` directory. ([#908](https://github.com/ethereum-optimism/specs/pull/908))

## NEWLY OPENED PULL REQUESTS
No new pull requests were opened today.

## CLOSED ISSUES

### Testing and CI Improvements
- **Flaky Fuzz Test Addressed:** An intermittent "Too long with no output" failure in the `op-e2e-fuzz` CircleCI job was investigated. The root cause was identified as excessive CPU usage during binary startup due to a full genesis pipeline run for all alloc types and hardfork modes. A fix is underway to lazily generate alloc types, significantly reducing startup time and preventing future timeouts. ([#21191](https://github.com/ethereum-optimism/specs/issues/21191))
- **`op-up` Test Removal:** The `op-up` test (`TestRun`) was removed from consideration for CI integration as the `op-up` package itself was deleted. ([#21202](https://github.com/ethereum-optimism/specs/issues/21202))
- **Misfiled Flaky Test Report:** A report for a flaky `TestL2OutputSubmitter/honest` test was closed as it was determined to be filed in error, originating from a spurious cross-pipeline signal rather than an actual failure in the relevant PR's CI. ([#21231](https://github.com/ethereum-optimism/specs/issues/21231))

### Sync and Metrics Issues
- **Sequencer Sync Stability:** An issue where the follow-mode sequencer's `latestHead` failed to re-anchor past a `FollowSource` `forceReset` under EL-sync was closed. After extensive testing, the flake could not be reproduced, suggesting the issue was related to how a previous invalid message replacement test was written. ([#21125](https://github.com/ethereum-optimism/specs/issues/21125))
- **`op-supernode` Sync Test Integration:** The issue regarding integrating `op-supernode` with `op-sync-tester` and adding an extended nightly sync test was partially addressed and closed. The decision was made to skip further integration as longer-running tests should not rely on `sync-tester` due to its EL mocking. ([#21096](https://github.com/ethereum-optimism/specs/issues/21096))
- **Kona Metrics Cardinality:** A bug causing very high cardinality for exported metrics in Kona was fixed. ([#19927](https://github.com/ethereum-optimism/specs/issues/19927))

### Transaction Pool Behavior
- **Interop Tx Pool Failsafe:** An issue where `op-reth`'s transaction pool failed to resume accepting interop transactions after the failsafe was disabled (requiring a restart) was resolved. The fix involves restarting both `op-reth` and `op-rbuilder` on affected sequencers. A gauge metric is proposed to make the failsafe state observable. ([#21149](https://github.com/ethereum-optimism/specs/issues/21149))

## ACTIVE ISSUES

### `op-reth-test-engine` Development
- **Minimal In-Test EL for `op-e2e/actions`:** Progress is being made on creating a minimal in-test Execution Layer (EL) for `op-e2e/actions` and achieving Rust action-test parity. The implementation is underway as a stacked series of PRs. The first PR focuses on establishing the `op-reth-test-engine` foundation with an `EphemeralChain` and `TestEngine` wrapper. The approach reuses the real `op-reth` stack for storage, validation, and block building, avoiding reimplementation. Future PRs will cover one-shot block execution, stateful in-flight payload building, lib API finalization, and OP-semantics golden-vector tests. ([#20415](https://github.com/ethereum-optimism/specs/issues/20415))

## ACTIVE ISSUES

### Kona Node Service: EngineActor becomes ChainController ([#22527](https://github.com/ethereum-optimism/specs/issues/22527))
Discussion on renaming `EngineActor` to `ChainController` and extending its functionality. Key points from recent comments:
*   A read-only query handler was opened in [#22597](https://github.com/ethereum-optimism/specs/pull/22597), stacked on [#22596](https://github.com/ethereum-optimism/specs/pull/22596).
*   The single read for `EngineQueries::handle` was already available, and `EngineState` being `Copy` ensures atomicity.
*   The Go side's `ChainContainer.OptimisticAt` still has a structural gap, performing multiple reads for L2 block and L1 key, which can lead to inconsistencies.
*   The query handler needs to account for four verdicts for timestamp queries (ahead, head's timestamp, behind, below L2 genesis) rather than just two.
*   An incidental fix was made to `engine.mdx` to update `InsertTask` snippet from `is_payload_local_safe: bool` to the origin.
*   The bulk of the work was opened in [#22595](https://github.com/ethereum-optimism/specs/pull/22595), stacked on [#22586](https://github.com/ethereum-optimism/specs/pull/22586).
*   The "descends-from-local-safe" check cannot live in the controller due to potential state changes between enqueue and execution; it was implemented as a predicate on `InsertTask`.
*   The query handler for "Atomic local-safe-at-timestamp + L1-at-safe snapshot" is deferred due to complexities in where the L2→L1 pairing is reliably recorded. It was determined that the write hook belongs in `kona-engine`'s sync state.

### Lokahi-interop: stores (verifiedDB + WAL, logsDBs, invalidated-output archive) ([#22535](https://github.com/ethereum-optimism/specs/issues/22535))
Two follow-ups left out of [#22603](https://github.com/ethereum-optimism/optimism/pull/22603) to avoid a second base-merge round.
*   The archive decode path preallocates from an on-disk count before validating it, which could lead to large memory allocations with corrupt data.
*   An unrecognised WAL decision tag is reported as data corruption, but could also indicate a downgrade, warranting different operator advice.
*   Landed **PR #22603**, implementing the `lokahi-interop` crate with all three stores.
*   **Verified store**: one record per verified timestamp, committed one per second.
*   **Log store**: one per chain, mirroring op-supernode's `raftwallogdb` record layout.
*   **Invalidated-output archive**: outputs only, with idempotent `record` and `prune_at_or_after`.
*   Every store is generic over a small `Kv` trait, with rocksdb and in-memory backends.
*   Checksum computation lives in `lokahi-interop` for now, pinned to Go with golden vectors.
*   Binary rather than JSON encoding was chosen for efficiency.
*   WAL decision tags are allocated only for existing transitions.
*   The deny-list filter half was dropped.
*   The "O(1) `Contains`" property is not fully replicated due to rocksdb's nature.
*   Decision on retention

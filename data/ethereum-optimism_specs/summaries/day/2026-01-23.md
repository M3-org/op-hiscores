# ethereum-optimism/specs Daily Update (Jan 23, 2026)
## OVERVIEW 
Today, the `ethereum-optimism/specs` repository saw the addition of a new feature: the OPCMv2 specification. This marks a step forward in defining the Optimism Protocol Compatibility Module. An issue related to L1 beacon client logging was closed, and discussions continued on integrating `op-succinct` changes into Kona and adding Supernode support for `op-challenger` in devstack.

## KEY TECHNICAL DEVELOPMENTS

### OPCMv2 Specification Introduced
A new feature has been added to the repository, introducing the OPCMv2 specification. This new specification is located in the experimental contracts section and was developed with AI assistance. ([#875](https://github.com/ethereum-optimism/specs/pull/875))

## NEWLY OPENED PULL REQUESTS
No new pull requests were opened today.

## CLOSED ISSUES

### L1 Beacon Client Logging Behavior
An issue concerning the logging behavior of the L1 beacon client when encountering errors and falling back to sidecars endpoint has been closed. The discussion concluded that the fallback mechanism itself might be removed. ([#17749](https://github.com/ethereum-optimism/specs/issues/17749))

## NEW ISSUES
No new issues were reported today.

## ACTIVE ISSUES

### Kona Integration of `op-succinct` Changes
The integration of `op-succinct` changes into Kona is currently on hold and has been moved back to the backlog. This is due to the dependency on rebasing the `kona-sp1` PR in `op-rs` onto the monorepo. ([#18457](https://github.com/ethereum-optimism/specs/issues/18457))

### Devstack Supernode Support for `op-challenger`
Work on adding Supernode support for `op-challenger` in devstack is dependent on another issue, #18920. The goal is to update the `op-challenger` setup to utilize the Supernode, with configurable options for gradual migration during testing. ([#18911](https://github.com/ethereum-optimism/specs/issues/18911))

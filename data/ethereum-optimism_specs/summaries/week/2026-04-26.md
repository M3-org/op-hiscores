# ethereum-optimism/specs Weekly Report (Apr 26 - May 2, 2026)

## 🚀 Highlights
This week focused on refining protocol constraints and improving the stability of the development environment. Key achievements include the formal documentation of input size reductions for the Karst execution engine and the resolution of critical test crashes within the Cannon framework. Additionally, the team made progress on governance and upgrade workflows by finalizing the bundle canonicalization process for L2CM upgrades, ensuring a more structured approach to hardfork management.

## 🛠️ Key Developments

### Karst Execution Engine Refinement
The protocol specifications were updated to reflect technical adjustments to the Karst execution engine.
*   **Precompile Input Constraints:** Documentation was added to codify a reduction in the `bn256Pairing` precompile input size limit. The limit was lowered from 81,984 bytes to 57,600 bytes, a change that directly impacts the maximum number of supported pairs in a single call ([#906](https://github.com/ethereum-optimism/specs/pull/906)).

### Upgrade & Governance Infrastructure
Efforts to streamline how the Superchain handles upgrades and bundled network upgrades (NUTs) reached a milestone this week.
*   **Bundle Canonicalization:** The team closed the implementation phase for the Bundle Canonicalization process within L2CM upgrades. This establishes a formal workflow for updating bundles per hardfork, utilizing a hybrid approach of manual triggers and automated validation checks ([#19307](https://github.com/ethereum-optimism/specs/issues/19307)).

## 🐛 Issues & Triage

### Closed Issues
*   **Cannon Test Stability:** A significant bug causing the `kona-host-client-offline-cannon` test to crash was resolved. The issue stemmed from an incorrect target specification in `cannon-builder:v1.0.0`. The fix involved bind-mounting a corrected MIPS64 specification and refreshing the committed witness tar to ensure environment parity ([#19895](https://github.com/ethereum-optimism/specs/issues/19895)).

### Active Issues
*   **`op-alloy` Trait Conflicts:** A notable conflict persists regarding the implementation of traits for `alloy_network::EthereumWallet` within `alloy_network::NetworkWallet<Optimism>`. Community discussion indicates that while a fix was merged in a related repository, the issue continues to affect users. There are ongoing questions regarding the maintenance status of `op-alloy` as it relates to the broader Optimism ecosystem ([#20281](https://github.com/ethereum-optimism/specs/issues/20281)).

## 💬 Community & Collaboration
The week's activity highlights a strong focus on cross-repository maintenance and ecosystem health. The discussion surrounding the `op-alloy` trait conflict ([#20281](https://github.com/ethereum-optimism/specs/issues/20281)) demonstrates active community monitoring of dependency management and a desire for clarity on the long-term support of auxiliary tooling. Collaboration remains centered on ensuring that specification changes (like those for Karst) are accurately reflected across the stack to prevent drift between documentation and implementation.

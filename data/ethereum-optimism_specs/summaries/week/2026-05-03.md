# ethereum-optimism/specs Weekly Report (May 3 - 9, 2026)

## 🚀 Highlights
This week focused on validating the performance and stability of the Interop and Superchain infrastructure. Extensive stress testing of the interop devnet confirmed linear cost scaling for message validation, providing high confidence in the system's performance within the 7-day expiry window. Significant progress was made in streamlining developer workflows by optimizing Kona prestate builds and consolidating `op-node` stability. The introduction of the Superchain Data Model (SDM) and Post-Execution transaction specs marks a pivotal step toward formalizing the next phase of the Superchain ecosystem.

## 🛠️ Key Developments

### Interop Performance & Kona Optimizations
The team conducted rigorous performance analysis on the `interop-jnt-v1` devnet. Testing confirmed that message validation costs scale linearly, even when running Kona interop in Cannon/MIPS against historical initiating messages. 
*   **Kona Improvements:** A critical fix for EIP-2935 proof decoding was implemented. Additionally, the Kona prestate build process was refactored to remove the Docker dependency, significantly increasing local development velocity.
*   **Stress Testing:** Results suggest that the full 7-day message expiry window is performant and unlikely to face completion issues ([#15285](https://github.com/ethereum-optimism/specs/issues/15285)).

### Supernode & Acceptance Testing
Efforts to harden the `op-supernode` and its testing suite resulted in several architectural refinements.
*   **Test Migration:** "After head" tests were successfully migrated to the `op-acceptance-test` framework, leading to the discovery and resolution of a bug in `op-supernode` ([#20370](https://github.com/ethereum-optimism/specs/issues/20370)).
*   **Super Root Logic:** The team decided against implementing unsafe super roots in `op-supernode`, opting instead to handle super root fetching within the test environment to maintain a cleaner node implementation ([#19059](https://github.com/ethereum-optimism/specs/issues/19059)).

### Protocol Specifications & Data Models
New specifications were introduced to define the future state of transaction execution and data handling.
*   **SDM & Post-Execution:** PR [#908](https://github.com/ethereum-optimism/specs/pull/908) was opened to introduce the Superchain Data Model (SDM) and Post-Execution transaction specifications.
*   **Contract Cleanup:** The `ProtocolVersions` contract and its deployment paths were officially removed as `op-node` no longer requires this data ([#20309](https://github.com/ethereum-optimism/specs/issues/20309)).

## 🐛 Issues & Triage

### Closed Issues
*   **`op-node` Stability:** Resolved a long-standing issue where `op-node` would hang in Execution Layer (EL) sync mode after a restart when paired with Reth ([#18468](https://github.com/ethereum-optimism/specs/issues/18468)).
*   **Interop Chain Creation:** Closed discussions on post-interop chain creation, establishing that L2 genesis will be generated with interop enabled in a dependency set of 1 ([#15884](https://github.com/ethereum-optimism/specs/issues/15884)).

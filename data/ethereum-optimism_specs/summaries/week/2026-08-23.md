# ethereum-optimism/specs Weekly Report (Aug 23 - 29, 2026)

## 🚀 Highlights
This week focused on streamlining the OP Stack protocol by proposing the removal of the Alt-DA specification and introducing sequencer-defined fees for the Lagoon protocol. Significant effort was directed toward stabilizing `kona-node`, addressing critical sequencer stalling and forkchoice loop issues that impact network performance. Additionally, the team completed a comprehensive audit of the Superchain starter ecosystem, paving the way for repository consolidation and the archiving of abandoned projects without breaking live documentation.

## 🛠️ Key Developments

### Protocol Specification Updates
The project is moving toward a more refined protocol definition, focusing on fee structures and simplifying data availability strategies.
*   **Lagoon Sequencer Fees:** A new specification was introduced to define sequencer-defined fees at Lagoon, enhancing how transaction costs are managed within that protocol ([#934](https://github.com/ethereum-optimism/specs/pull/934)).
*   **Alt-DA Removal:** A significant proposal was opened to remove the Alt-DA specification, signaling a potential shift in the long-term data availability roadmap for the OP Stack ([#935](https://github.com/ethereum-optimism/specs/pull/935)).

### Kona-Node Stability & Performance
Technical discussions and fixes centered on resolving bottlenecks within `kona-node` to ensure sequencer reliability.
*   **Network Stalling:** Developers are investigating a bug where the `NetworkActor` stalls the p2p swarm during remote-signer HTTP calls. Proposed fixes include implementing overflow policies and deadline changes to prevent latency injection from halting the node ([#22646](https://github.com/ethereum-optimism/specs/issues/22646)).
*   **Sequencer Loop Fixes:** Work is underway to address a scenario where the sequencer becomes wedged in a `forkchoiceUpdated` loop. While a partial fix ([#22686](https://github.com/ethereum-optimism/specs/pull/22686)) introduced a backoff mechanism to reduce CPU pinning, gaps remain regarding `SealTask` error handling and watch channel synchronization ([#22681](https://github.com/ethereum-optimism/specs/issues/22681)).

## 🐛 Issues & Triage

### Closed Issues
*   **Rollup Configuration:** The team decided to maintain leniency in `kona-genesis` regarding unknown keys in `RollupConfig`. This ensures backward compatibility for older configurations with retired keys, as existing superchain-registry tests already provide sufficient coverage ([#22682](https://github.com/ethereum-optimism/specs/issues/22682)).
*   **Supernode Interoperability:** An investigation into a "cross-safe wedge" in `op-supernode` concluded that the issue was an isolated oscillation caused by a parent-hash mismatch on a specific chain (901), rather than a systemic cross-safety bug ([#22325](https://github.com/ethereum-optimism/specs/issues/22325)).

### New & Active Issues
*   **SuperchainERC20 Compatibility:** A new gap was identified regarding the lack of a supported method for developers to verify if a token address is SuperchainERC20 compatible. This is a high-priority item for the revival of the `SuperchainTokenBridge` ([#1020](https://github.com/ethereum-optimism/specs/issues/1020)).
*   **Documentation & Repo Maintenance:** A comprehensive audit ([#1014](https://github.com/ethereum-optimism/specs/issues/1014)) confirmed that several abandoned repositories can be safely archived. Plans are in motion to consolidate multiple `superchain-starter` repos into a single repository to improve developer experience, though execution is currently pending administrative permissions ([#1015](https://github.com/ethereum-optimism/specs/issues/1015), [#1017](https://github.com/ethereum-optimism/specs/issues/1017)).

## 💬 Community & Collaboration
The week was characterized by deep technical troubleshooting and organizational cleanup. Collaboration was particularly evident in the `kona-node` discussions, where contributors actively proposed testing strategies involving injected latency to reproduce p2p stalling. The documentation audit also demonstrated a cross-functional effort to ensure that the consolidation of starter examples does not negatively impact the external developer experience, despite the current administrative blocks on repository permissions.

# ethereum-optimism/specs Weekly Report (Feb 1 - 7, 2026)

## 🚀 Highlights
This week focused on refining the architectural boundaries of the `op-supernode` and expanding the protocol specifications to include L2 contract upgrades. Significant technical discourse centered on ensuring synchronization correctness between the Execution Layer (EL) and Consensus Layer (CL), particularly regarding safe label management and initial sync UX. Developers also addressed critical infrastructure stability, resolving an L1 polling issue in the supernode while exploring the integration of Flashblocks support within Geth to improve developer experience and resource efficiency.

## 🛠️ Key Developments

### Protocol Specifications & Invariants
The core protocol documentation saw significant expansions this week, focusing on upgradeability and build integrity.
*   **L2 Contract Upgrades:** Introduced comprehensive specifications detailing the execution and contract-specific aspects of L2 upgrades ([#884](https://github.com/ethereum-optimism/specs/pull/884)).
*   **Kona Build Determinism:** A new pull request was initiated to document the Kona build determinism invariant, ensuring reproducible builds within the ecosystem ([#889](https://github.com/ethereum-optimism/specs/pull/889)).
*   **Preimage Hints:** Updates were proposed for preimage hints to refine how data is requested and processed ([#888](https://github.com/ethereum-optimism/specs/pull/888)).

### Supernode & Interoperability Infrastructure
Work continued on the `op-supernode` to improve its reliability as a central component of the Superchain.
*   **L1 Polling Fix:** Resolved a bug where HTTP L1 URLs would disable polling in the `op-supernode`, which previously led to stale L1 head updates for virtual nodes ([#19012](https://github.com/ethereum-optimism/specs/issues/19012)).
*   **Flashblocks Support:** Discussions progressed regarding merging Flashblocks support into `op-geth`. This move is intended to provide a more user-friendly and disk-efficient alternative to running archive versions of Reth.

## 🐛 Issues & Triage

### Closed Issues
*   **Supernode Synchronization:** The primary resolution this week was the fix for L1 polling in the `op-supernode` ([#19012](https://github.com/ethereum-optimism/specs/issues/19012)), ensuring consistent state updates across virtual nodes.

### New & Active Issues
*   **Safe Label Management:** A deep dive into `op-supernode` architecture ([#18976](https://github.com/ethereum-optimism/specs/issues/18976)) explored how EL and CL safe labels should be controlled. The consensus is leaning toward the CL maintaining the "Local Safe" representation while the supernode manages the EL's safe and finalized states directly to avoid synchronization conflicts.
*   **Initial EL Sync UX:** Ongoing debate persists regarding `op-node` marking sync targets as finalized prematurely ([#17631](https://github.com/ethereum-optimism/specs/issues/17631)). Maintainers are weighing the trade-offs between Snap Sync compatibility in `op-geth` versus `op-reth`.
*   **Interop Testing:** Issue [#18616](https://github.com/ethereum-optimism/specs/issues/18616) was reopened and then moved to the backlog after it was discovered that `TestInteropReadiness` remains skipped in the codebase despite previous PRs.
*   **Infrastructure Anomalies:** New reports emerged regarding "Wiz" standard clusters not functioning correctly ([#887](https://github.com/ethereum-optimism/specs/issues/887)) and a potential `BlockNotFoundError` in the ETH bridge tutorial related to missing output root validation in certain SDKs ([#1956](https://github.com/ethereum-optimism/specs/issues/1956)).

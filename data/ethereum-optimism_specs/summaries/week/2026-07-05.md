# ethereum-optimism/specs Weekly Report (Jul 5 - 11, 2026)

## 🚀 Highlights
This week’s activity focused on refining the protocol's technical specifications to ensure alignment with reference implementations and streamlining system configurations. Key achievements include the clarification of Ecotone blob-encoding requirements and the formalization of the pipeline for breaking cyclic dependencies within the `op-deployer`. While progress was made on protocol cleanup, the team continues to investigate a persistent non-deterministic crash in integration testing related to the payload builder service.

## 🛠️ Key Developments

### Protocol Specification Refinements
Work this week focused on ensuring the written specifications accurately reflect the behavior of the OP Stack's reference implementations, particularly regarding data encoding.
*   **Ecotone Blob-Encoding Clarification:** The specification for Ecotone blob-encoding was updated to clarify that the top two bits of the first field element are not enforced during decoding. This change ([#923](https://github.com/ethereum-optimism/specs/pull/923)) corrects a previous statement in the spec that did not align with actual implementation behavior.

### System Configuration & Cleanup
Efforts are underway to simplify the system configuration by removing legacy or redundant parameters.
*   **Configuration Streamlining:** A new pull request ([#922](https://github.com/ethereum-optimism/specs/pull/922)) was introduced to remove `batchInbox` and `startBlock` from the system configuration, reducing the surface area of the protocol's configuration logic.

## 🐛 Issues & Triage

### Closed Issues
*   **PCD Technical Specification:** The team successfully defined the technical specifications for breaking cyclic dependencies in the `op-deployer` pipeline ([#912](https://github.com/ethereum-optimism/specs/issues/912)). This resolution included a comprehensive outline of pipeline stages, assumptions, and invariants, providing a clear roadmap for deployment infrastructure.

### New & Active Issues
*   **Flaky Integration Tests (SIGSEGV):** A significant ongoing concern is a recurring SIGSEGV error in the `reth-optimism-node` integration tests ([#20973](https://github.com/ethereum-optimism/specs/issues/20973)). The issue appears during the teardown of the `peers_negotiate_eth_69` test. 
    *   **Technical Context:** The root cause is suspected to be a race condition where an orphan OS thread attempts to access Tokio internals that have already been freed. This was likely introduced by a change from `spawn_critical_task` to `spawn_critical_os_thread` in the payload builder service. This remains a blocker for stable merge-queue checks as it causes non-deterministic failures even when test bodies pass.

## 💬 Community & Collaboration
The week's activity demonstrates a strong focus on cross-component consistency, particularly between the specifications and the `op-deployer` and `reth-optimism-node` implementations. The detailed investigation into the `reth-optimism-node` SIGSEGV indicates active collaboration between protocol architects and tooling engineers to resolve complex concurrency issues that affect the broader CI/CD pipeline and developer experience.

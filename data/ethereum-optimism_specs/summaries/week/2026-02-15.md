# ethereum-optimism/specs Weekly Report (Feb 15 - 21, 2026)

## 🚀 Highlights
This week, development on the Optimism protocol specifications focused on refining transaction execution sequences and streamlining data formats. Key updates included the integration of a new conditional deployment step within the protocol upgrade specifications and technical debt reduction in the NUT bundle format. These changes contribute to the ongoing evolution of the OP Stack's execution layer and data consistency.

## 🛠️ Key Developments

### Protocol Upgrade Specifications
The protocol's execution logic was updated to accommodate more complex deployment scenarios.
*   **Conditional Deployer Integration**: A significant update was made to the transaction execution sequence to include the `ConditionalDeployer` upgrade step. This specification details how the protocol handles this specific upgrade path during execution ([#892](https://github.com/ethereum-optimism/specs/pull/892)).

### Data Format Refinement
Work continued on perfecting the specifications for bundle formats used within the ecosystem.
*   **NUT Bundle Format Fix**: Developers addressed a technical requirement in the NUT bundle format by removing the `value` field. This change ensures the specification remains lean and aligned with the intended data structure for these bundles ([#893](https://github.com/ethereum-optimism/specs/pull/893)).

## 🐛 Issues & Triage

*   **New & Active Issues:** No new issues were reported, and there were no active discussions on existing issues with more than three comments, indicating a week of streamlined, targeted development.

Collaboration this week was characterized by precise, technical contributions to the core protocol specifications.

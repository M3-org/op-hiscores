# ethereum-optimism/optimism Daily Update (Jun 2, 2026)
## OVERVIEW 
Today's development focused on significant enhancements to the Superchain's capabilities, including flashblocks support for SDM, improved proofs backfilling, and critical bug fixes for `op-node` and `op-supernode` stability. Documentation was also substantially updated with new feature pages and release information.

## KEY TECHNICAL DEVELOPMENTS

### Superchain Data Management & Interoperability Enhancements
Flashblocks support has been integrated into the SDM (Superchain Data Management) system, significantly expanding its capabilities. This includes updates across various components like `op-acceptance-tests`, `op-chain-ops`, `op-devstack`, `op-node`, `op-service`, and `op-rbuilder` to enable and test this new functionality. Additionally, the `op-interop-filter` now includes correct and per-reason failsafe metrics and logs, improving observability and reliability of interop message processing. The `op-supernode` also received an update to pre-initialize interop decision metric series, ensuring comprehensive tracking of interop activity.

### `op-reth` Proofs and Node Stability Improvements
The `op-reth` proofs system now supports backfilling the proofs window backward, allowing nodes to extend their historical records to cover earlier blocks. This is a foundational step for more robust proof generation and verification. Critical bug fixes were also implemented for `op-node` to preserve the safedb across EL-sync restarts, preventing data loss on node reboots. Furthermore, `op-node` now correctly reorgs follow-mode sequencers onto the upstream chain upon divergence, enhancing chain consistency.
- [#20793](https://github.com/ethereum-optimism/optimism/pull/20793)

### `op-supernode` Reliability and Interop Fixes
Several fixes were deployed to improve the reliability of `op-supernode`. This includes blocking on Virtual Node readiness after resuming in rewind/invalidate scenarios, which addresses flakiness in interop message replacement tests. A fix was also implemented to lazily dial the interop engine controller, resolving issues where the controller was set up inside the VN restart loop and causing problems with separate EL connections.
- [#21163](https://github.com/ethereum-optimism/optimism/pull/21163)
- [#21152](https://github.com/ethereum-optimism/optimism/pull/21152)

### Documentation Updates
Significant updates were made to the documentation, including new feature pages for L2 Contract Manager (L2CM) and Osaka on L2, providing detailed explanations of these mechanisms and their importance for decentralization. The release pages on docs.optimism.io were also expanded to include per-component release information and refreshed with the latest GitHub releases.

# ethereum-optimism/optimism Daily Update (May 1, 2026)
## OVERVIEW 
Today's development focused on enabling new dev features like Cannon Kona and L2CM by default, alongside critical bug fixes for LightCL genesis sync and acceptance tests. Significant CI job downsizing also occurred.

## KEY TECHNICAL DEVELOPMENTS

### Core Protocol Feature Enablement
Key development features, Cannon Kona and L2CM, are now hardcoded as default paths in the devfeature bitmap for both Go and Solidity components. This streamlines their integration and testing.
- [#20470](https://github.com/ethereum-optimism/optimism/pull/20470)
- [#20439](https://github.com/ethereum-optimism/optimism/pull/20439)

### Dispute Monitoring Enhancements
The dispute monitoring system received an upgrade with a new Prometheus metric to break down monitored games by their specific dispute game type (e.g., cannon, permissioned).

Several bugs were addressed, including a fix for LightCL follow-source initialization when the L2 genesis block is reported as safe but the local state is zero. Acceptance tests were also improved to correctly use preset budgets and preserve quoting in arguments.

## CLOSED ISSUES

### Flaky Test Resolution
A persistent flaky test, `TestTruncateDatabaseOnELResync`, which experienced CrossSafe sync timeouts, has been closed. The issue was related to the safe head not advancing past genesis during the retry window.
- [#19897](https://github.com/ethereum-optimism/optimism/issues/19897)

### LightCL Genesis Sync Fix
An observation regarding LightCL reporting zero for `safe_l2`, `local_safe_l2`, and `finalized_l2` on fresh-genesis boot has been resolved. The problem stemmed from genesis `L2BlockRef`s being treated as unset state due to comparisons only on `Number`.
- [#20295](https://github.com/ethereum-optimism/optimism/issues/20295)

### Superchain Operations and Dev Feature Flag Updates
Issues related to deprecated base checks in superchain operations and the hardcoding of the L2CM devfeatures bitmap have been closed.
- [#20472](https://github.com/ethereum-optimism/optimism/issues/20472)
- [#20356](https://github.com/ethereum-optimism/optimism/issues/20356)

### Dispute Monitor Clarification
An issue concerning the `op-dispute-mon`'s ability to query supernode's VNs for output roots was closed with a clarification that a single `op-dispute-mon` instance can monitor both CANNON and SUPER_CANNON_KONA games by passing both rollup-rpc and supernode-rpc.

## ACTIVE ISSUES

### op-reth Upgrade Panic
Issue [#20462](https://github.com/ethereum-optimism/optimism/issues/20462) describes a fatal panic in `StateRootTask` when upgrading `op-reth` from 1.x to 2.x on OP Stack chains. The latest update confirms that the `--engine.legacy-state-root` flag does not resolve the panic. The crash block changed, suggesting the panic is not block-specific but triggered non-deterministically during parallel trie computation against 1.x database state. The panic occurs in `alloy-trie-0.9.5/src/nodes/branch.rs` with an assertion failure `left == right`. This indicates a shared bug in both `StateRootTask` and `Parallel` trie strategies.

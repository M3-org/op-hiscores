# ethereum-optimism/optimism Daily Update (Jun 10, 2026)
## OVERVIEW 
Today's development focused on enhancing interoperability monitoring, refining the Kona executor, and updating documentation to reflect the shift to op-reth. Key improvements include aligning `op-interop-mon` with the supernode architecture and making the Kona executor more generic for receipt building.

## KEY TECHNICAL DEVELOPMENTS

### Interoperability Monitoring and Metrics Refinement
The `op-interop-mon` tool has been updated to align with the current interop design, focusing on supernodes, light nodes, and `op-interop-filter`, making it strictly observe-only [#21283](https://github.com/ethereum-optimism/optimism/pull/21283). Additionally, `op-reth` interop filter metrics were consolidated into a single labeled decision counter for improved observability [#21302](https://github.com/ethereum-optimism/optimism/pull/21302).

### Kona Executor Enhancements and Fixes
The Kona executor received updates to make `StatelessL2Builder` and `KonaExecutor` generic over receipt builders, improving flexibility [#21275](https://github.com/ethereum-optimism/optimism/pull/21275). A critical bug fix was implemented to pin the blob base fee to 1 on the OP Stack within the Kona executor [#21328](https://github.com/ethereum-optimism/optimism/pull/21328).

### Documentation and Infrastructure Updates
Significant documentation updates were made, including defaulting chain operator guides to `op-reth` [#21179](https://github.com/ethereum-optimism/optimism/pull/21179) and archiving snap-sync pages as `op-reth` does not support it [#21318](https://github.com/ethereum-optimism/optimism/pull/21318). New AI agent guidance for derivation, execution, and fault proofs was added [#21293](https://github.com/ethereum-optimism/optimism/pull/21293). The CI configuration was improved by restoring the Go module cache in all Go-building jobs to prevent slow downloads and flakes [#21313](https://github.com/ethereum-optimism/optimism/pull/21313). The default `--l2.enginekind` for `op-node` was changed to `reth` following `op-geth`'s end-of-support [#21295](https://github.com/ethereum-optimism/optimism/pull/21295).

## ACTIVE ISSUES

### SDM Ecosystem Integration Review
The issue [#21110](https://github.com/ethereum-optimism/optimism/issues/21110) is actively discussing the ecosystem integration for the new 0x7d transaction type introduced by SDM. The latest comment from geoknee highlights the need to work with ecosystem partners (block explorers, wallets, etc.) to ensure proper visualization and processing of this new transaction type, and to communicate changes in `gasUsed` semantics. The discussion emphasizes the importance of ensuring downstream tools correctly interpret the new transaction type and its associated gas accounting.

# ethereum-optimism/optimism Daily Update (Feb 17, 2026)
## OVERVIEW 
Today's development focused on enhancing L2 contract management with a new `L2ProxyAdmin` for batch upgrades, streamlining deployment processes, and improving CI/CD reliability.

## KEY TECHNICAL DEVELOPMENTS

### L2 Contract Management and Upgrades
A significant feature was added to extend the `ProxyAdmin` predeploy, now named `L2ProxyAdmin`, to support batch upgrades of L2 predeploy contracts via the xFork L2ContractsManager. This enhancement improves the efficiency and flexibility of L2 contract management within the Superchain ecosystem. ([#19135](https://github.com/ethereum-optimism/optimism/pull/19135))

### Deployment Process Refinements
The deployment process saw improvements with the removal of default L1 and L2 PAOs and the relocation of associated documentation, preparing for future migration to `docs.optimism.io`. This streamlines the `op-deployer` and clarifies documentation. ([#19166](https://github.com/ethereum-optimism/optimism/pull/19166))

### CI/CD and Testing Infrastructure Improvements
Several fixes and enhancements were made to the CI/CD pipeline and testing infrastructure. This includes adjusting the `reproducible-prestate` target for parallel builds ([#19184](https://github.com/ethereum-optimism/optimism/pull/19184)), fixing a Devin client timeout issue by correctly populating `structured_output` ([#19219](https://github.com/ethereum-optimism/optimism/pull/19219)), and improving how `DelayedWETH` addresses are loaded for fork tests ([#19206](https://github.com/ethereum-optimism/optimism/pull/19206)). Additionally, a new acceptance test was added for block-level throttling ([#19079](https://github.com/ethereum-optimism/optimism/pull/19079)), and CI builds were optimized to only build specified Rust binaries ([#19204](https://github.com/ethereum-optimism/optimism/pull/19204)).

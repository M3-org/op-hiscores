# ethereum-optimism/optimism Daily Update (Jul 22, 2026)
## OVERVIEW 
Today's development focused heavily on documentation improvements, particularly for the OP Stack and node operators, alongside significant enhancements to `op-deployer` functionality and new acceptance tests for ZK dispute games. Several critical issues were also addressed, including a flaky test and a superchain-configs dependency.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced Deployment and Prestate Management
The `op-deployer` tool received a significant feature allowing prestates to be committed before chain deployment, improving the interop depset generation process. This change streamlines the setup of new chains by integrating prestate resolution earlier in the deployment pipeline. Additionally, `op-deployer` now verifies contracts by default on Etherscan and Blockscout, and deprecated `upgrade` and `manage migrate` commands were removed to simplify the CLI.

## CLOSED ISSUES

### Flaky Test Resolution
A persistent flaky test, `TestSingleChainSuperFaultProofsFromOpNode` ([#21952](https://github.com/ethereum-optimism/optimism/issues/21952)), was identified and fixed. The root cause was a transient 10-second RPC timeout during `sysgo.getSuperRoot` polling, which was resolved by refactoring the function to reuse polled responses and eliminate redundant RPC calls. This fix also addressed a related issue where the `op-node` driver event loop could starve the sequencer timer ([#21953](https://github.com/ethereum-optimism/optimism/issues/21953)).

### `op-deployer` Migration Streamlining
The issue of `op-deployer manage migrate` not building validator-complete OPCM V2 migration inputs ([#20447](https://github.com/ethereum-optimism/optimism/issues/20447)) was closed. This was addressed by removing the deprecated `manage migrate` command, as the underlying migration primitives are now handled through other, more robust mechanisms.

### Superchain Configuration Dependency Fix
A dependency issue related to `superchain-configs` for `superchain-registry` ([#21954](https://github.com/ethereum-optimism/optimism/issues/21954)) was resolved. This fix involved moving symbols to remove an unintended dependency that was breaking the `superchain-registry` ops tooling build chain.

### Interop Depset and Prestate Generation Reordering
The issue of re-ordering interop depset and prestate generation before deployment ([#20911](https://github.com/ethereum-optimism/optimism/issues/20911)) was closed. This was addressed by moving these stages earlier in the `op-deployer` pipeline, ensuring the prestate hash is available before `OPCM.deploy()` is called.

## NEW ISSUES

### Core Component Challenges
A new issue highlights a potential divergence between Go and Rust implementations regarding post-exec (0x7D) transaction payload validation ([#21961](https://github.com/ethereum-optimism/optimism/issues/21961)). This could lead to latent correctness problems if a misbehaving sequencer or batcher sends malformed data. Another issue points out that the light-sequencer configuration in `op-node` can oscillate during recovery from divergence, potentially leading to incorrect safe/finalized block relabeling ([#21964](https://github.com/ethereum-optimism/optimism/issues/21964)).

### ZK Proofing Exploration
A spike was opened to investigate manual proof generation via SPN ([#21965](https://github.com/ethereum-optimism/optimism/issues/21965)), indicating ongoing research and development into ZK proofing mechanisms.

# ethereum-optimism/optimism Daily Update (Feb 21, 2026)
## OVERVIEW 
Today's development focused on enhancing flashblock efficiency within `op-reth` by implementing transaction caching, which aims to reduce re-execution of unchanged transactions. Two new issues were opened, one concerning block building delays and another seeking the latest `op-reth` Docker image.

## KEY TECHNICAL DEVELOPMENTS

### Flashblocks Performance Enhancement
A significant feature was added to `op-reth`'s flashblocks, introducing transaction caching to prevent redundant execution of unchanged transactions. This improvement allows execution to resume from a cached state when a new flashblock shares a matching transaction prefix, thereby optimizing performance.
- Transaction caching implemented in `op-reth`'s flashblocks to avoid re-executing unchanged transactions ([#19030](https://github.com/ethereum-optimism/optimism/pull/19030)).
- Execution now resumes from cached state for flashblocks with matching transaction prefixes ([#19030](https://github.com/ethereum-optimism/optimism/pull/19030)).

# ethereum-optimism/optimism Daily Update (Jun 9, 2026)
## OVERVIEW 
Today's development focused on significant enhancements to the OP Stack, including new features for the op-reth test engine and block gas limit enforcement. Several bug fixes improved CI stability and interop cycle detection, alongside extensive documentation updates.

## KEY TECHNICAL DEVELOPMENTS

*   **OP Stack Execution Layer Improvements**
    *   Introduced an ephemeral, OP-flavored execution layer for `op-reth-test-engine`, enabling `op-e2e/actions` to run OP execution layers without embedding op-geth in-process ([#21216](https://github.com/ethereum-optimism/optimism/pull/21216)).
    *   Enforced the `SystemConfig`-derived block gas limit against pre-refund EVM gas under SDM/PostExec, addressing a previous issue where block gas accounting accumulated canonical/post-refund gas ([#21250](https://github.com/ethereum-optimism/optimism/pull/21250)).
    *   Added a public API for the op pool ([#21305](https://github.com/ethereum-optimism/optimism/pull/21305)).

*   **Operator Ergonomics and Proofs Enhancements**
    *   Improved `op-proofs` CLI with default backfill on `init`, shared CLI arguments, and window-based targets for better operator experience ([#21277](https://github.com/ethereum-optimism/optimism/pull/21277)).
    *   Rejected zero elasticity in EIP-1559 parameters decoding within op-alloy, pushing validation down to ensure early failure on invalid parameters ([#21292](https://github.com/ethereum-optimism/optimism/pull/21292)).

*   **Stability and Interoperability Fixes**
    *   Resolved a CI issue where stale binaries were served due to the rust target-dir build cache ([#21310](https://github.com/ethereum-optimism/optimism/pull/21310)).
    *   Deflaked `TestReorgUnsafeHead` batcher race in op-acceptance-tests ([#21307](https://github.com/ethereum-optimism/optimism/pull/21307)).
    *   Fixed `op-supernode` to error instead of silently dropping chains during interop cycle detection when `db.OpenBlock` failed, preventing invalid blocks from being treated as valid ([#21303](https://github.com/ethereum-optimism/optimism/pull/21303)).

*   **Documentation and Testing**
    *   Updated documentation with op-geth deprecation banners, refreshed op-reth/op-node references, and added a full op-reth JSON-RPC reference ([#21007](https://github.com/ethereum-optimism/optimism/pull/21007)).
    *   Refined "Talk to the Optimism team" CTAs based on feedback ([#21141](https://github.com/ethereum-optimism/optimism/pull/21141)).
    *   Migrated the op-challenger configuration guide to cannon-kona + op-reth ([#21144](https://github.com/ethereum-optimism/optimism/pull/21144)).
    *   Added a CI configuration review guide and reviewer agent ([#21246](https://github.com/ethereum-optimism/optimism/pull/21246)).
    *   Updated Upgrade 19 and Osaka-on-L2 documentation for Karst spec alignment, correcting `bn256Pairing` limits and adding missing EIP numbers ([#21316](https://github.com/ethereum-optimism/optimism/pull/21316)).
    *   Corrected a stale O(N²) note on `sdm_canonical_replay_duration` in op-rbuilder documentation ([#21297](https://github.com/ethereum-optimism/optimism/pull/21297)).
    *   Added `rollup-boost` and `op-rbuilder` release links to the Upgrade 19 notice ([#21294](https://github.com/ethereum-optimism/optimism/pull/21294)).
    *   Added deterministic regression coverage for near-max cross-domain relay payloads ([#21266](https://github.com/ethereum-optimism/optimism/pull/21266)).

## CLOSED ISSUES

*   **EVM Gas Limit Enforcement**
    *   The issue of enforcing a block gas limit on pre-refund EVM gas under SDM/PostExec has been resolved ([#20709](https://github.com/ethereum-optimism/optimism/issues/20709)). The solution involves enforcing `MAX_GAS_LIMIT` to cap the maximum computation a sequencer can perform, even with 100% refunds.

*   **EIP-1559 Parameter Decoding**
    *   The problem of properly catching zero elasticities during EIP-1559 parameter decoding has been addressed ([#18951](https://github.com/ethereum-optimism/optimism/issues/18951)). The fix pushes validation to the `op-alloy` level, ensuring early failure on invalid parameters.

## ACTIVE ISSUES

### `op-node` Synchronization with Pruned Execution Layers
Discussion continued on [#21465](https://github.com/ethereum-optimism/optimism/issues/21465) regarding `op-node` synchronization failures when using `--syncmode=execution-layer` with `--minimal` or similarly pruned execution clients. Creamers158 highlighted that the release notes for `op-node/v1.19.1` are missing a crucial detail: for pruned nodes, simply switching to `--syncmode=execution-layer` is insufficient. Users also need to set `--syncmode.offset-el-safe=0` because the default 12-hour offset can reference blocks that have already been pruned, leading to errors. It was suggested that `offset-el-safe` should either adapt to the execution client's pruning configuration or automatically default to 0 for pruned ELs, or at minimum, the release notes should explicitly mention the requirement for `--syncmode.offset-el-safe=0` for pruned nodes.

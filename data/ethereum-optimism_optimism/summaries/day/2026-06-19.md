# ethereum-optimism/optimism Daily Update (Jun 19, 2026)
## OVERVIEW 
Today's development focused on significant advancements in the Superchain ecosystem, including the implementation of the Super ZK Dispute Game and the renaming of the Interop hardfork to Lagoon. Documentation was also updated with security reviews and upgrade notices.

## KEY TECHNICAL DEVELOPMENTS

### Superchain Dispute Game Enhancements
The `ZKDisputeGame` has been migrated to super-root semantics, mirroring `SuperFaultDisputeGame`, to improve dispute resolution within the Superchain. This change reuses existing slots, ensuring seamless integration for callers. Additionally, the `nut` activation test has been decoupled from the git head state for more robust testing.
([#21011](https://github.com/ethereum-optimism/optimism/pull/21011), [#21298](https://github.com/ethereum-optimism/optimism/pull/21298))

### Superchain Registry and Hardfork Renaming
The Superchain Registry state is now coupled via a hoisted root submodule, ensuring a single canonical commit pin across `op-core/superchain`, `kona`, and `op-reth`. The Interop hardfork has also been officially renamed to Lagoon, with corresponding updates across the monorepo.
([#21474](https://github.com/ethereum-optimism/optimism/pull/21474), [#21370](https://github.com/ethereum-optimism/optimism/pull/21370))

### Documentation and Security Updates
Key documentation updates include the addition of the finalized Cantina security review for Interop L2 Contracts and a note regarding permissioned fault proof chains in the Upgrade 19 (Karst) notice. A developer workflow guide was also added to the AGENTS documentation.
([#21472](https://github.com/ethereum-optimism/optimism/pull/21472), [#21484](https://github.com/ethereum-optimism/optimism/pull/21484), [#21480](https://github.com/ethereum-optimism/optimism/pull/21480))

## ACTIVE ISSUES

### Kona-node and op-reth Metrics Version Discrepancy
The issue [#20832](https://github.com/ethereum-optimism/optimism/issues/20832) highlights a discrepancy in the version reported by `kona-node` and `op-reth` in Prometheus metrics. The current version is populated from `Cargo.toml`, but the goal is to align it with the git tag that triggered the build, similar to the Go stack. A recent comment notes that `op-reth`'s version reporting (via `web3_clientVersion` or `--version`) also shows an internal reth crate version, indicating a broader issue with consistent version reporting.

### Flaky reth-optimism-node Integration Test
The `reth-optimism-node` integration test `peers_negotiate_eth_69` is experiencing a flaky `SIGSEGV` on teardown, as reported in [#20973](https://github.com/ethereum-optimism/optimism/issues/20973). A recent comment confirms the recurrence of this flake, which caused a PR to be kicked out of the merge queue. The suspected root cause, identified by @ajsutton, is a race condition during runtime teardown due to the payload builder service switching from `spawn_critical_task` to `spawn_critical_os_thread` without proper `thread::JoinHandle` tracking. This leads to the orphan OS thread accessing Tokio internals while the main thread is freeing them.

### Optimism Sepolia Intrinsic Gas After Karst Hard Fork
Issue [#21457](https://github.com/ethereum-optimism/optimism/issues/21457) reports that Optimism Sepolia's intrinsic gas is too high after the Karst hard fork. A comment from @geoknee confirms this is a known issue and will be addressed in the next release, referencing the Upgrade 19 notice for app developers.

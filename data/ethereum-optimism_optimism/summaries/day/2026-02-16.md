# ethereum-optimism/optimism Daily Update (Feb 16, 2026)
## OVERVIEW 
Today's development focused on enhancing the `op-node` with a new JSON-based upgrade transaction parser and fixing a race condition in `op-challenger`'s shutdown process.

## KEY TECHNICAL DEVELOPMENTS

### Streamlining Network Upgrade Definitions
A new feature was added to the `op-node` to allow defining network upgrade transactions via JSON files, simplifying the process and reducing the need for dedicated Go files for each hardfork. This improves maintainability and flexibility for future upgrades.
- Implemented a NUT bundle parser for JSON-defined upgrade transactions ([#19165](https://github.com/ethereum-optimism/optimism/pull/19165)).

### Enhancing `op-challenger` Stability
A critical race condition in the `op-challenger`'s shutdown process was identified and fixed, preventing the scheduler workers from hanging indefinitely. This improves the robustness and reliability of the challenge game.
- Fixed a race condition in `op-challenger`'s scheduler workers during shutdown ([#19203](https://github.com/ethereum-optimism/optimism/pull/19203)).

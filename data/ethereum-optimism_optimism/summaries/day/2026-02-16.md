# ethereum-optimism/optimism Daily Update (Feb 16, 2026)
## OVERVIEW 
Today's development focused on enhancing the `op-node` with a new network upgrade transaction parser and fixing a race condition in `op-challenger`'s shutdown process.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced Network Upgrade Transaction Handling
The `op-node` now supports defining network upgrade transactions via JSON files, simplifying the process of managing hardforks and reducing the need for dedicated Go files for each upgrade. This improvement streamlines the configuration and deployment of network upgrades. ([#19165](https://github.com/ethereum-optimism/optimism/pull/19165))

### `op-challenger` Stability Improvements
A critical race condition in `op-challenger`'s shutdown mechanism was resolved, preventing it from hanging during termination. Additionally, logging was added to the `Stop` method to aid in diagnosing future shutdown issues in CI environments. ([#19203](https://github.com/ethereum-optimism/optimism/pull/19203), [#19199](https://github.com/ethereum-optimism/optimism/pull/19199))

# ethereum-optimism/optimism Daily Update (Feb 2, 2026)
## OVERVIEW 
Today's development focused on enhancing the robustness of production upgrades by preventing beta-tagged contracts, improving transaction manager logic for blob transactions, and updating Rust subtrees for `op-alloy` and `op-reth`.

## KEY TECHNICAL DEVELOPMENTS

### Production Upgrade Safeguards
*   A new feature was added to block contracts with beta tags from being used in production upgrades, ensuring stability and preventing premature deployment of unfinalized code ([#19035](https://github.com/ethereum-optimism/optimism/pull/19035)).

### Transaction Manager Improvements
*   The transaction manager now correctly uses the blob tip cap when increasing fees for blob transactions, aligning fee bumping logic with initial transaction creation ([#19028](https://github.com/ethereum-optimism/optimism/pull/19028)).

### Rust Subtree Updates and Build Fixes
*   All Rust subtrees, including `op-alloy` and `op-reth`, were updated to their latest versions, incorporating recent changes and improvements ([#19025](https://github.com/ethereum-optimism/optimism/pull/19025)).
*   A workaround was implemented to address issues with older `buildx` versions during prestate building, and the `just` version was added to the legacy Kona prestate build configuration to fix CI failures ([#19031](https://github.com/ethereum-optimism/optimism/pull/19031), [#19046](https://github.com/ethereum-optimism/optimism/pull/19046)).

## ACTIVE ISSUES

### Supernode Safe Label Adjusting
Discussion on [#18976](https://github.com/ethereum-optimism/optimism/issues/18976) revolves around how the `op-supernode` should manage and interpret "safe" labels across different layers (EL, CL, Superchain). The latest comments suggest that the CL should maintain a full set of pointers (Unsafe, Safe, Committed, Finalized) and remain the sole controller of the engine, with the supernode controlling the EL's Safe and Finalized states directly. This approach aims to prevent conflicts between multiple stateful controllers and aligns with the idea of an "authority" object within the virtual node. A key challenge is ensuring the CL's "local safe" state doesn't conflict with the supernode's "cross-safe" state, and how RPC responses from virtual nodes should reflect these different levels of safety.

### Flashblocks Support within Geth
Issue [#756](https://github.com/ethereum-optimism/optimism/issues/756) discusses the integration of flashblocks support into `op-geth`. The latest comment confirms that `op-geth` already has flashblocks support, along with Firehose Live Tracer, and provides a link to the relevant branch. This indicates progress towards enhancing `op-geth`'s capabilities for processing real-time block events.

### `BlockNotFoundError` in Withdrawal Proof
On [#1956](https://github.com/ethereum-optimism/optimism/issues/1956), users are encountering `BlockNotFoundError` during the withdrawal proof step in the ETH bridge tutorial. The latest comment highlights that while the Optimism SDK includes output root validation, Viem's withdrawal guide and actions do not appear to perform an equivalent validation. This suggests a potential gap in Viem's implementation that could lead to issues when the state root has not yet been published to L1. A temporary workaround involves manually retrieving and overriding output root data from Etherscan.

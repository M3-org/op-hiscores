# ethereum-optimism/optimism Daily Update (Jul 21, 2026)

## OVERVIEW
Today's development focused on enhancing fault proof systems with native SP1 super-range acceptance, improving deployment processes, and a significant push in documentation updates.

## KEY TECHNICAL DEVELOPMENTS

### Fault Proof System Enhancements
- **Native SP1 Super-Range Acceptance:** Integrated native SP1 super-range acceptance checks alongside existing FPVM scenarios, collecting real witnesses and replaying them for verification. ([#21857](https://github.com/ethereum-optimism/optimism/pull/21857))
- **Super Root Sourcing for Challengers:** Added acceptance test coverage for `op-challenger` sourcing super roots directly from `op-node` instead of `op-supernode`, and fixed a blocking `op-node` gap. ([#21889](https://github.com/ethereum-optimism/optimism/pull/21889))
- **SP1 Executor Rust Binary Path:** Replaced custom SP1 native-executor environment variables with the standard Rust binary-path mechanism. ([#21936](https://github.com/ethereum-optimism/optimism/pull/21936))

### Deployment and Infrastructure Improvements
- **Anchor Block Selection for Deployer:** Implemented a feature to pick an anchor block for the deployer's prepare phase. ([#21600](https://github.com/ethereum-optimism/optimism/pull/21600))
- **Flashblocks URL Fix for op-reth:** Resolved a bug where `op-reth` was unable to consume flashblocks when using a `wss://` flashblocks-url. ([#21898](https://github.com/ethereum-optimism/optimism/pull/21898))
- **Beacon Node Version Requirement Removal:** `op-node` no longer requires the beacon node version endpoint during startup, probing the beacon genesis endpoint instead. ([#21915](https://github.com/ethereum-optimism/optimism/pull/21915))
- **Maxperf Builds for Regression Testing:** Added `op-reth/bench-*` tags to trigger maxperf image builds for regression testing. ([#21900](https://github.com/ethereum-optimism/optimism/pull/21900))

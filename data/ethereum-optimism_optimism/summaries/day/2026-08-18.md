# ethereum-optimism/optimism Daily Update (Aug 18, 2026)
## OVERVIEW 
Today's development focused on critical security updates, significant enhancements to the Kona fault proof system, and improvements in CI/CD processes. Key updates include bumping `h2` to fix a security vulnerability, refining Kona's derivation pipeline and witness refreshing, and optimizing CI workflows for Rust and Docker.

## KEY TECHNICAL DEVELOPMENTS

### Security and Dependency Updates
Several security-related dependency bumps were implemented to enhance the overall robustness of the Optimism stack. This includes updating the `h2` library to address a known vulnerability and upgrading `pion/dtls/v2`, `pion/stun/v2`, `pion/stun`, and `golang.org/x/image` modules to their latest secure versions.
- Bumped `h2` to 0.4.16 to fix RUSTSEC-2026-0258 ([#22462](https://github.com/ethereum-optimism/optimism/pull/22462)).
- Updated `github.com/pion/dtls/v2` to v3 ([#22069](https://github.com/ethereum-optimism/optimism/pull/22069)).
- Updated `github.com/pion/stun/v2` to v3 ([#22181](https://github.com/ethereum-optimism/optimism/pull/22181)).
- Updated `github.com/pion/stun` to v2 ([#22180](https://github.com/ethereum-optimism/optimism/pull/22180)).
- Updated `golang.org/x/image` to v0.45.0 ([#22435](https://github.com/ethereum-optimism/optimism/pull/22435)).

### Kona Fault Proof System Enhancements
Significant work was done on the Kona fault proof system, focusing on improving its derivation pipeline, updating SP1, and refining witness handling. These changes aim to increase the reliability and efficiency of fault proofs.
- Updated SP1 to v6.4.0, including coordinated updates to `cargo-prove`, host SDK, guest libraries, and Docker build tags ([#22456](https://github.com/ethereum-optimism/optimism/pull/22456)).
- Refreshed the offline Cannon witness to include preimages required by a separate issue, moving the fixture boundary to block 47,600,000 ([#22488](https://github.com/ethereum-optimism/optimism/pull/22488)).
- Preserved reset errors during the initial walk-back in the Kona derivation pipeline, preventing the flattening of parent lookup failures into generic temporary provider errors ([#22475](https://github.com/ethereum-optimism/optimism/pull/22475)).
- Keyed the system config lookup by L2 block hash in Kona, aligning with `op-node`'s approach ([#22465](https://github.com/ethereum-optimism/optimism/pull/22465)).
- Removed addressed CI TODOs from the Kona SP1 README, indicating that relevant build, lint, test, and compatibility checks are now covered by CI ([#22449](https://github.com/ethereum-optimism/optimism/pull/22449)).

### CI/CD and Developer Tooling Improvements
Several updates were made to the CI/CD pipeline and developer tooling to streamline workflows, improve efficiency, and enhance documentation.
- Switched the Rust CI base image to the apko/Wolfi `circleci-runner-wolfi` image, aligning CI with apko images and reducing the package/CVE surface ([#22459](https://github.com/ethereum-optimism/optimism/pull/22459)).
- Dropped unused host clang installations from Docker-only Kona jobs in CircleCI, reducing build times and image sizes ([#22481](https://github.com/ethereum-optimism/optimism/pull/22481)).
- Targeted the previous day's nightly in the Rust bump CI job to ensure successful execution, as the current day's manifest lands later than the job's schedule ([#22480](https://github.com/ethereum-optimism/optimism/pull/22480)).
- Added `StandardValidator` reviewer agent documentation and clarified the cross-implementation parity rule for `op-geth` and `op-core` differential tests ([#22420](https://github.com/ethereum-optimism/optimism/pull/22420), [#22461](https://github.com/ethereum-optimism/optimism/pull/22461)).

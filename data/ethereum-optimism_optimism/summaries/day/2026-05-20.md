# ethereum-optimism/optimism Daily Update (May 20, 2026)

## OVERVIEW
Today's development focused on critical bug fixes, particularly addressing issues with L2CM upgrades and interop configurations. Significant refactoring improved interop message handling, and CI/CD pipelines saw updates for efficiency.

## KEY TECHNICAL DEVELOPMENTS

### Core Contracts and L2 System Enhancements
- **Resource Configuration Scaling**: Implemented a feature to scale `ResourceConfig` to accommodate smaller `gasLimits` in `DeployOPChain.s.sol` [#20919](https://github.com/ethereum-optimism/optimism/pull/20919).
- **L2CM Upgrade Fixes**: Addressed a bug in the L2CM upgrade path that silently dropped authorized minters on XLayer, ensuring minters are preserved across upgrades [#20816](https://github.com/ethereum-optimism/optimism/pull/20816).

### Interoperability and Supernode Stability
- **Superchain Registry Depsets**: Fixed an issue in Kona's registry to embed `superchain-registry` depsets, ensuring `BootInfo::load` correctly uses embedded dependency sets [#20837](https://github.com/ethereum-optimism/optimism/pull/20837).
- **Interop Message Refactoring**: Moved interop wire/message vocabulary from `op-supervisor/supervisor/types` to a new `op-core/interop/messages` package, enhancing modularity [#20887](https://github.com/ethereum-optimism/optimism/pull/20887).
- **Supernode Interop Configuration**: Fixed `op-supernode` to ignore `interop.log-backfill-depth` when no activation is configured, preventing startup rejections [#20894](https://github.com/ethereum-optimism/optimism/pull/20894).

### Testing and CI/CD Improvements
- **Acceptance Test Refinements**: Replaced sleep polling with condition-based waits and context-aware timers in acceptance tests to improve reliability [#20868](https://github.com/ethereum-optimism/optimism/pull/20868).
- **CI Job Migration**: Migrated 41 Docker jobs in CircleCI from Gen1 to same-size Gen2 resource classes, and resized the `fuzz-golang` job to `xlarge.gen2` for better performance [#20917](https://github.com/ethereum-optimism/optimism/pull/20917), [#20931](https://github.com/ethereum-optimism/optimism/pull/20931).

Documentation for `op-reth` was also updated [#20937](https://github.com/ethereum-optimism/optimism/pull/20937).

## CLOSED ISSUES
- **Supernode Interop Configuration**: The issue where `op-supernode` failed to start if `backfill depth > 0` and interop activation time was not set has been resolved [#20892](https://github.com/ethereum-optimism/optimism/issues/20892). The fix ensures that backfill depth is ignored under these conditions.

## NEW ISSUES
- **Permissionless Chain Deployment (PCD) Milestones**: A series of issues were opened outlining the phased development for a new deployment pipeline in `op-deployer` to enable permissionless dispute games from block 0. This includes design and architecture [#20897](https://github.com/ethereum-optimism/optimism/issues/20897), implementation and testing [#20898](https://github.com/ethereum-optimism/optimism/issues/20898), quality and benchmarking [#20900](https://github.com/ethereum-optimism/optimism/issues/20900), and Netchef integration [#20901](https://github.com/ethereum-optimism/optimism/issues/20901).
- **PCD Technical Challenges**: Specific technical challenges for PCD were identified, such as making anchor-block selection reorg-safe [#20906](https://github.com/ethereum-optimism/optimism/issues/20906), predicting L1 addresses via dry-run [#20908](https://github.com/ethereum-optimism/optimism/issues/20908), and computing the genesis output root [#20910](https://github.com/ethereum-optimism/optimism/issues/20910).
- **Flaky Tests and Crashes**: Several new issues report flaky tests, including `FuzzEncodeDecodeBlob` [#20935](https://github.com/ethereum-optimism/optimism/issues/20935) and `FuzzDetectNonBijectivity` [#20936](https://github.com/ethereum-optimism/optimism/issues/20936) in `op-service/eth`, and `TestSequenceWindowExpired` [#20941](https://github.com/ethereum-optimism/optimism/issues/20941). A bug causing `op-reth` proofs-history exex to crash with SIGBUS during deep FCU rewinds was also reported [#20934](https://github.com/ethereum-optimism/optimism/issues/20934).
- **Supernode Robustness**: An issue was opened regarding `op-supernode`'s rewind/invalidation path not being robust to partial-progress states or slow ELs, leading to synthetic-stuck loops and conflated retry signals [#20929](https://github.com/ethereum-optimism/optimism/issues/20929).

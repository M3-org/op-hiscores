# ethereum-optimism/optimism Daily Update (May 15, 2026)

## OVERVIEW
Today's development focused on enhancing interop functionality with a new raft-wal-backed LogsDB, fixing several critical bugs in Kona and op-node, and refining CI processes. Significant progress was made in stabilizing acceptance tests and streamlining infrastructure.

## KEY TECHNICAL DEVELOPMENTS

### Interoperability and Supernode Enhancements
A new raft-wal-backed LogsDB was implemented for `op-supernode` and `op-interop-filter`, ensuring atomic sealing of blocks and improving data integrity [#20688](https://github.com/ethereum-optimism/optimism/pull/20688). The default log backfill depth for `op-supernode` was set to 7 days, aligning with the interop message expiry constant [#20577](https://github.com/ethereum-optimism/optimism/pull/20577), [#20777](https://github.com/ethereum-optimism/optimism/pull/20777). Additionally, a fix was introduced to allow `op-supernode` to resume from `verifiedDB` on warm restarts, improving resilience [#20733](https://github.com/ethereum-optimism/optimism/pull/20733).

### Kona and Protocol Stability Improvements
Several critical bug fixes were deployed for Kona, including improved error handling for gas varint decode failures in batch transactions [#19874](https://github.com/ethereum-optimism/optimism/pull/19874) and correction of stale Reth path references in Kona test configurations [#19974](https://github.com/ethereum-optimism/optimism/pull/19974). A significant fix addressed an `InvalidClaim` error in `kona-client`'s interop `run()` function when dealing with `TransitionState` prestates [#20717](https://github.com/ethereum-optimism/optimism/pull/20717).

### Infrastructure and CI/CD Refinements
The CircleCI pipeline was refactored to use a custom shell-based approach for dynamic configuration, replacing the `path-filtering` orb for more flexible workflow execution [#20613](https://github.com/ethereum-optimism/optimism/pull/20613). Acceptance tests were stabilized by clearing the `WindowSyncPolicy` cache on session reset [#20783](https://github.com/ethereum-optimism/optimism/pull/20783) and by retrying `eth_getProof` calls to tolerate transient L2 EL state persistence issues [#20782](https://github.com/ethereum-optimism/optimism/pull/20782). Performance of Rust e2e CI jobs was improved by consolidating Rust builds and tightening restart-suite timing [#20788](https://github.com/ethereum-optimism/optimism/pull/20788).

### Op-Node and Contracts Updates
The `op-node` now caches the super authority finalized head to improve resilience against transient EL lookup failures [#20772](https://github.com/ethereum-optimism/optimism/pull/20772). A fix in `op-service/txplan` ensures that nonce-too-low errors in transaction submission retry loops are handled correctly by invalidating the Nonce node [#20736](https://github.com/ethereum-optimism/optimism/pull/20736). In `contracts-bedrock`, a critical fix ensures the INTEROP runtime flag is only activated at genesis for scheduled interop chains, preventing premature activation [#20813](https://github.com/ethereum-optimism/optimism/pull/20813).

## CLOSED ISSUES

### Kona Protocol and Interop Fixes
Several issues related to Kona's protocol and interop functionality were resolved. This includes fixing span batch gas decode errors that were incorrectly reported as `TxNonces` [#19873](https://github.com/ethereum-optimism/optimism/issues/19873) and addressing a bug where the Kona init-chain interop activation gate was disabled when `interop_time` was `None` [#20578](https://github.com/ethereum-optimism/optimism/issues/20578). A critical vulnerability in `kona-client` where the `SuperRoot` trace-extension boundary accepted malicious prestates was also patched [#20721](https://github.com/ethereum-optimism/optimism/issues/20721).

### Supernode Stability and Finalized Head Management
Issues concerning `op-supernode`'s stability and finalized head handling were closed. This includes resolving a flake in `TestSupernodeLogBackfill_HappyPath` where `latest.Number` equaled `first.Number` after restart and backfill [#20690](https://github.com/ethereum-optimism/optimism/issues/20690). Another fix addressed `op-supernode`'s `runLogBackfill` being anchored to stale cross-safe on cold start [#20693](https://github.com/ethereum-optimism/optimism/issues/20693). The `op-supernode`'s finalized head was made more tolerant to transient EL lookup failures [#20771](https://github.com/ethereum-optimism/optimism/issues/20771).

### CI/CD and Sync Tester Reliability
Improvements to CI/CD and sync tester reliability were implemented. A flake in `TestMultiELSync` was addressed [#20780](https://github.com/ethereum-optimism/optimism/issues/20780). An attempt to enable `eatmydata` in CI by baking it into `ci-base-clang` was closed as `eatmydata` does not apply to statically linked Go binaries, which constitute the majority of `fsync` pressure in CI [#20787](https://github.com/ethereum-optimism/optimism/issues/20787).

### Batcher and Superdispute Game Integration
The issue of `interop + batcher` using `Verification-Aware CurrentL1` was closed [#19944](https://github.com/ethereum-optimism/optimism/issues/19944). The broader initiative for all chains to use `SuperDisputeGame` was also closed [#19694](https://github.com/ethereum-optimism/optimism/issues/19694).

## NEW ISSUES

### Supernode Unsafe SuperRoots
A new issue highlights that fetching super roots from `op-supernode` via `atTimestamp` fails if no verified or safe data exists at the referenced timestamp. It suggests that `supernode` should return super roots even in this case, though the semantic meaning of such "unsafe" super roots is under discussion.
- [#19059](https://github.com/ethereum-optimism/optimism/issues/19059)

### Fast Kona Prestate Build
A problem has been identified regarding the slow generation of Kona prestate for acceptance testing, which currently uses Docker and hinders local development velocity. A proposal to add a faster prestate build is being considered.
- [#19057](https://github.com/ethereum-optimism/optimism/issues/19057)

### Supervisor Rewind Panic Consideration
A new issue suggests that `op-supervisor` should consider panicking if a rewind operation would affect finalized blocks, as the current implementation allows finalized heads to revert.
- [#19066](https://github.com/ethereum-optimism/optimism/issues/19066)

## ACTIVE ISSUES

### op-node: On the Initial EL Sync UX and Correctness
Discussion continues on the behavior of `op-node` during initial EL Sync, specifically regarding the marking of targets as finalized even if not truly finalized. Key points include:
- The current behavior is considered buggy, especially for non-archival nodes where prior state is not generally available.
- A suggestion was made to run derivation from a prior L1 block and then consolidation to verify alignment with the EL-synced unsafe chain.
- The idea of making Snap Sync follow the finalized L2 as a maximum target was proposed to ensure correctness and avoid incorrect data after finalization.
- The original design intent for EL sync, which allowed this behavior, is being re-evaluated.
- [#17631](https://github.com/ethereum-optimism/optimism/issues/17631)

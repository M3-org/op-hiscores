## ACTIVE ISSUES

### op-supernode/op-reth CL Sync Recovery Stall ([#21076](https://github.com/ethereum-optimism/optimism/issues/21076))
The issue describes how `op-supernode`'s CL sync recovery can stall when `SafeDB`/bookkeeping references an EL-missing block. Recent updates confirm the issue can be reproduced without `op-supernode` orchestration, using a standalone `op-node` and `op-reth` setup. The core problem appears to be a half-completed transition where `reth` logs "Block added to canonical chain" but fails to emit "Received new payload" or "Canonical chain committed" for the same block, leading to an Engine API timeout. This points to a failure within the `op-node`/`op-reth` CL derive/build Engine API path. Further investigation will focus on tracing around `engine::tree` and payload insertion, and adding focused regression tests.

### op-supervisor/op-supernode Cross-Safe Backlog ([#21117](https://github.com/ethereum-optimism/optimism/issues/21117))
This issue concerns `op-supervisor`/`op-supernode`'s cross-safe mechanism failing to drain a backlog faster than real-time after a stall. A recent comment suggests that a 12-hour delay in local safe catching up to unsafe could indicate the sequencing window expired, requiring manual intervention. If the sequencing window expires due to an extended batcher outage, the sequencer needs to enter recovery mode to generate blocks that match the force progression, allowing the batcher to get data on-chain without immediate reorgs.

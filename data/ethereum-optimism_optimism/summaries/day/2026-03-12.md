# ethereum-optimism/optimism Daily Update (Mar 12, 2026)
## OVERVIEW 
Today saw significant progress in refining the Rust-based derivation pipeline with a new scenario-oriented DSL and critical bug fixes, alongside a major cleanup of deprecated development tools and continued migration to `justfile` for build processes.

## KEY TECHNICAL DEVELOPMENTS

### Derivation Pipeline Enhancements and Bug Fixes
The Rust derivation pipeline received a new scenario-oriented DSL for derivation tests, improving readability and focus on test scenarios rather than implementation details ([#19496](https://github.com/ethereum-optimism/optimism/pull/19496)). Critical bug fixes were implemented in `BlobSource::load_blobs` to prevent silent over-fill issues ([#19364](https://github.com/ethereum-optimism/optimism/pull/19364)) and a new Claude Code skill was added to automate Rust formatting fixes ([#19488](https://github.com/ethereum-optimism/optimism/pull/19488)). Additionally, `#[ignore]` attributes were replaced with `nextest` binary filtering for integration tests ([#19489](https://github.com/ethereum-optimism/optimism/pull/19489)).

### Build System Modernization and Cleanup
Efforts continued to migrate build targets from `Makefile` to `justfile` across various components, including `op-e2e` ([#19475](https://github.com/ethereum-optimism/optimism/pull/19475)), `cannon` ([#19474](https://github.com/ethereum-optimism/optimism/pull/19474)), and `linter` ([#19473](https://github.com/ethereum-optimism/optimism/pull/19473)). A significant cleanup involved removing the deprecated `devnet-sdk` and `kurtosis-devnet` from the repository, re-homing remaining live pieces into `op-service`, `op-core`, and `op-devstack` ([#19506](https://github.com/ethereum-optimism/optimism/pull/19506)).

### `op-node` Derivation Error Handling Improvements
Several `op-node` derivation issues related to error propagation and handling of malformed data were addressed. This includes dropping malformed span batch transaction data as `NotEnoughData` ([#19502](https://github.com/ethereum-optimism/optimism/pull/19502)), classifying missing beacon endpoint errors as `CriticalError` after Ecotone activation ([#19501](https://github.com/ethereum-optimism/optimism/pull/19501)), and handling pre-Delta span batches and bad channel decompression as `NotEnoughData` for immediate drops ([#19500](https://github.com/ethereum-optimism/optimism/pull/19500), [#19499](https://github.com/ethereum-optimism/optimism/pull/19499)).

## CLOSED ISSUES

### Derivation Pipeline Error Handling
Several issues related to error handling in the `op-node` derivation pipeline were closed. This includes addressing cases where channel decompression failures were swallowed as `TemporaryError` ([#19492](https://github.com/ethereum-optimism/optimism/issues/19492)), pre-Delta span batches caused `O(N×backoff)` drain instead of immediate drops ([#19493](https://github.com/ethereum-optimism/optimism/issues/19493)), and malformed span batch transaction data propagated as unclassified errors ([#19494](https://github.com/ethereum-optimism/optimism/issues/19494)).

### Critical Error Classification
A critical issue regarding the classification of errors for a missing beacon endpoint after Ecotone activation was resolved, ensuring it returns a `CriticalError` instead of an unclassified error ([#19495](https://github.com/ethereum-optimism/optimism/issues/19495)).

### Kona Blob Handling
A bug in Kona's `BlobSource::load_blobs` where it silently ignored over-fill conditions was fixed ([#19363](https://github.com/ethereum-optimism/optimism/issues/19363)).

### Game Type Default
The issue to set the default respected game type to `CANNON_KONA` was closed ([#18640](https://github.com/ethereum-optimism/optimism/issues/18640)).

## NEW ISSUES

### Derivation Pipeline Invariant Analysis
New issues were opened to conduct a comprehensive audit of the derivation pipeline's external-input error handling in both `op-node` ([#19491](https://github.com/ethereum-optimism/optimism/issues/19491)) and `kona` ([#19510](https://github.com/ethereum-optimism/optimism/issues/19510)). The core invariant is that malformed or bad L1 inputs must never halt derivation.

### Kona Derivation Error Propagation
Specific error propagation problems within the `kona` derivation pipeline were identified, including system config update errors in `StatefulAttributesBuilder` returning `Critical` instead of being ignored ([#19512](https://github.com/ethereum-optimism/optimism/issues/19512)) and span batch extraction failures in `BatchQueue` returning `Critical` instead of flushing ([#19511](https://github.com/ethereum-optimism/optimism/issues/19511)).

### Node Stability and Crash Loops
A critical issue was reported where `CriticalErrorEvent` for deposits-only attributes failure causes a permanent node crash loop ([#19509](https://github.com/ethereum-optimism/optimism/issues/19509)).

### `op-challenger-runner` with `op-reth`
A new issue was created to ensure `op-challenger-runner` uses `op-reth` for OP Mainnet to validate historical proofs support and `L2PayloadWitness` hint in Kona ([#19517](https://github.com/ethereum-optimism/optimism/issues/19517)).

## ACTIVE ISSUES

### Repository Bloat and Cloning Time
Issue [#19241](https://github.com/ethereum-optimism/optimism/issues/19241) highlights the significant bloat of the `optimism` repository due to binaries and artifacts in its history, leading to long cloning times (over 2 hours). A recent comment from `incompleteloop` questions the prioritization of this issue, noting the difficulty it poses for developers to work on the codebase and integrate it as a dependency, especially concerning Rust crates not published to `crates.io`.

### Batcher Configuration Variable Mismatch
Issue [#1933](https://github.com/ethereum-optimism/optimism/issues/1933) points out a mismatch in the description for the batcher configuration variable `max-blocks-per-span-batch`, which incorrectly uses the description and example of `check-recent-txs-depth`. `romanito0410` has opened PR #2000 to address this specific issue.

# ethereum-optimism/optimism Daily Update (Mar 12, 2026)
## OVERVIEW 
Today's development focused on enhancing the Rust-based derivation test framework, addressing critical error handling in the `op-node`'s derivation pipeline, and migrating build systems from Make to Just across several components.

## KEY TECHNICAL DEVELOPMENTS

### Derivation Pipeline Robustness and Error Handling
Significant improvements were made to the `op-node`'s derivation pipeline to enhance its robustness against malformed or unexpected L1 inputs. This includes fixing an over-fill check in `BlobSource::load_blobs` ([#19364](https://github.com/ethereum-optimism/optimism/pull/19364)), classifying various channel and span batch processing failures as `NotEnoughData` for immediate dropping rather than indefinite retries ([#19502](https://github.com/ethereum-optimism/optimism/pull/19502), [#19500](https://github.com/ethereum-optimism/optimism/pull/19500), [#19499](https://github.com/ethereum-optimism/optimism/pull/19499)), and ensuring critical misconfigurations like a missing beacon endpoint after Ecotone activation result in a fatal error ([#19501](https://github.com/ethereum-optimism/optimism/pull/19501)).

### Rust Development Tooling and Testing Enhancements
The Rust ecosystem saw the introduction of a scenario-oriented DSL for derivation tests, simplifying test case descriptions ([#19496](https://github.com/ethereum-optimism/optimism/pull/19496)). Additionally, `#[ignore]` attributes were replaced with `nextest` binary filtering for more efficient test execution ([#19489](https://github.com/ethereum-optimism/optimism/pull/19489)), and a Claude Code skill was added to automate Rust formatting fixes ([#19488](https://github.com/ethereum-optimism/optimism/pull/19488)). The `reth` dependency was also bumped to v1.11.3 ([#19498](https://github.com/ethereum-optimism/optimism/pull/19498)).

### Build System Migration and Cleanup
Several components, including `op-program`, `op-e2e`, `cannon`, and `linter`, had their build targets migrated from Make to Just, standardizing the build process across the repository ([#19476](https://github.com/ethereum-optimism/optimism/pull/19476), [#19475](https://github.com/ethereum-optimism/optimism/pull/19475), [#19474](https://github.com/ethereum-optimism/optimism/pull/19474), [#19473](https://github.com/ethereum-optimism/optimism/pull/19473)). The `devnet-sdk` and `kurtosis-devnet` trees were removed, with remaining live pieces re-homed to `op-service`, `op-core`, and `op-devstack` ([#19506](https://github.com/ethereum-optimism/optimism/pull/19506)).

## CLOSED ISSUES

### Derivation Pipeline Error Handling Improvements
Several issues related to error handling in the `op-node`'s derivation pipeline were closed. This includes addressing the swallowing of channel decompression failures as `TemporaryError` ([#19492](https://github.com/ethereum-optimism/optimism/issues/19492)), preventing pre-Delta span batches from causing `O(N×backoff)` drain ([#19493](https://github.com/ethereum-optimism/optimism/issues/19493)), and ensuring malformed span batch transaction data doesn't propagate as unclassified errors ([#19494](https://github.com/ethereum-optimism/optimism/issues/19494)).

### Critical Error Classification
The issue of a missing beacon endpoint after Ecotone activation returning an unclassified error instead of a `CriticalError` was resolved ([#19495](https://github.com/ethereum-optimism/optimism/issues/19495)).

### Kona Blob Source Correction
A bug where `BlobSource::load_blobs` in Kona silently ignored over-fill was fixed ([#19363](https://github.com/ethereum-optimism/optimism/issues/19363)).

### Game Type Default Update
The issue to set the default respected game type to `CANNON_KONA` was closed ([#18640](https://github.com/ethereum-optimism/optimism/issues/18640)).

## NEW ISSUES

### Derivation Pipeline Invariant Analysis
New issues were opened to conduct invariant analysis on the derivation pipelines. This includes a general audit of `op-node`'s derivation pipeline external-input error handling ([#19491](https://github.com/ethereum-optimism/optimism/issues/19491)) and a similar invariant analysis for Kona's derivation pipeline, emphasizing that bad L1 input must never halt derivation ([#19510](https://github.com/ethereum-optimism/optimism/issues/19510)).

### Kona Derivation Error Handling
Specific error handling problems in Kona's derivation were identified, such as system config update errors in `StatefulAttributesBuilder` returning `Critical` instead of being ignored ([#19512](https://github.com/ethereum-optimism/optimism/issues/19512)) and span batch extraction failures in `BatchQueue` returning `Critical` instead of flushing ([#19511](https://github.com/ethereum-optimism/optimism/issues/19511)).

### Node Stability and Configuration
A critical issue regarding `DepositsOnlyPayloadAttributesRequestEvent` failure causing a permanent node crash loop was reported ([#19509](https://github.com/ethereum-optimism/optimism/issues/19509)).

### Op-Challenger Runner Integration
A new issue was created to configure `op-challenger-runner` to use `op-reth` for OP Mainnet, ensuring readiness for historical proofs support ([#19517](https://github.com/ethereum-optimism/optimism/issues/19517)).

## ACTIVE ISSUES

### Repository Size Bloat
Issue [#19241](https://github.com/ethereum-optimism/optimism/issues/19241) highlights that the `optimism` repo's `.git` directory is significantly bloated (1.04 GB packed) due to large binaries and artifacts in history, making cloning and dependency management difficult. A recent comment from `incompleteloop` expresses frustration, stating that cloning takes over 2 hours and questions why this issue isn't prioritized, given the impact on developer experience and the unceremonious inclusion of Rust crates.

### Batcher Configuration Variable Mismatch
Issue [#1933](https://github.com/ethereum-optimism/optimism/issues/1933) points out a mismatch in the description for the batcher configuration variable `max-blocks-per-span-batch`, where its description and example incorrectly refer to `check-recent-txs-depth`. `romanito0410` has opened PR [#2000](https://github.com/ethereum-optimism/optimism/pull/2000) to address this documentation error.

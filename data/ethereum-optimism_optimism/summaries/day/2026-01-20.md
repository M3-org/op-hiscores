# ethereum-optimism/optimism Daily Update (Jan 20, 2026)
## OVERVIEW 
Today's development focused on significant CI/CD improvements, including refactoring for continuations and fixing release triggers. Contract tests were updated to run U18, and several bug fixes and dependency upgrades were implemented, alongside new custom linters and challenger game handling improvements.

## KEY TECHNICAL DEVELOPMENTS

### CI/CD Enhancements and Fixes
The CI/CD pipeline saw substantial refactoring to incorporate CircleCI continuations, enabling more efficient workflow execution based on path filtering [#18812](https://github.com/ethereum-optimism/optimism/pull/18812). A critical fix was also deployed to address issues with git tag release triggers in dynamic config pipelines [#18880](https://github.com/ethereum-optimism/optimism/pull/18880).

### Contract Test Updates and Dependency Upgrades
Contract tests were updated to run U18, impacting several bedrock contract files and deployment scripts [#18768](https://github.com/ethereum-optimism/optimism/pull/18768). Additionally, the `op-geth` dependency was upgraded to upstream v1.16.6 [#18338](https://github.com/ethereum-optimism/optimism/pull/18338).

### Code Quality and Challenger Improvements
A new custom linter was introduced to prevent `big.Int Uint64` truncation issues, enhancing code quality [#18815](https://github.com/ethereum-optimism/optimism/pull/18815). The `op-challenger` also received improvements for better handling of corner cases in dispute games [#18860](https://github.com/ethereum-optimism/optimism/pull/18860). A minor bug fix corrected the acronym for Canon Kona Dispute Game [#18734](https://github.com/ethereum-optimism/optimism/pull/18734).

## NEWLY OPENED PULL REQUESTS
- **Feature Development**: New features include adding a feature flag for forge scripts [#18881](https://github.com/ethereum-optimism/optimism/pull/18881), a Conditional L2 Deployer [#18864](https://github.com/ethereum-optimism/optimism/pull/18864), and a Network Upgrade Transaction Lib [#18863](https://github.com/ethereum-optimism/optimism/pull/18863).

- **Refactoring and Cleanup**: Several PRs focus on refactoring `op-devstack` for unified component access and registry [#18876](https://github.com/ethereum-optimism/optimism/pull/18876), [#18875](https://github.com/ethereum-optimism/optimism/pull/18875), [#18874](https://github.com/ethereum-optimism/optimism/pull/18874), [#18873](https://github.com/ethereum-optimism/optimism/pull/18873), [#18872](https://github.com/ethereum-optimism/optimism/pull/18872), removing CGT instruction from OPCMv2 [#18878](https://github.com/ethereum-optimism/optimism/pull/18878), and removing backward compatibility type aliases [#18877](https://github.com/ethereum-optimism/optimism/pull/18877).

### op-supernode: Reset Handling [#18740](https://github.com/ethereum-optimism/optimism/issues/18740)
Recent comments discuss the challenges of resetting the unsafe head in `op-supernode`. @axelKingsley and @geoknee debated several options, including hacking around FCU behavior, making supernode-driven resets similar to regular reorgs, or adding new engine API methods. The current plan is to proceed with a temporary hack (option 1) while exploring other long-term solutions. There's confusion about how FCU previously worked given that it doesn't move the unsafe head back to a canonical block on `op-geth`.

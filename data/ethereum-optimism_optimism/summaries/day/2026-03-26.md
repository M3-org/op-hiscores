# ethereum-optimism/optimism Daily Update (Mar 26, 2026)
## OVERVIEW 
Today's development focused on optimizing `op-node` performance by batching FCU calls, enhancing Rust-based EVM and proof systems, and refining smart contract upgrade mechanisms. Significant CI/CD improvements were also implemented, alongside addressing several critical bug fixes.

## KEY TECHNICAL DEVELOPMENTS

### `op-node` Performance and Stability Improvements
The `op-node` saw significant updates aimed at improving performance and stability. A key feature introduced is the batching of safe-head `engine_forkchoiceUpdated` calls to one per derived L1 block, rather than per L2 block, which streamlines the consolidation path. This change also involved removing the `concluding` flag from the batch/attributes pipeline, simplifying the derivation process ([#19638](https://github.com/ethereum-optimism/optimism/pull/19638)).

### Rust Ecosystem Enhancements and Fixes
The Rust-based components received several updates. The `op-alloy-evm` now includes an `OpEvm::into_inner` method for better interoperability ([#19735](https://github.com/ethereum-optimism/optimism/pull/19735)). Critical fixes were applied to `kona-proof`'s derivation logic, particularly addressing trace-extension vulnerabilities and improving overall proof integrity ([#19775](https://github.com/ethereum-optimism/optimism/pull/19775)). Additionally, miscellaneous clippy warnings were resolved across various Rust crates ([#19736](https://github.com/ethereum-optimism/optimism/pull/19736)).

### Smart Contract and Upgrade Mechanism Refinements
Improvements were made to the `contracts-bedrock` suite, specifically addressing L2CM IR low fixes, including an upgrade edge case for `ConditionalDeployer` and correcting an inline comment ([#19785](https://github.com/ethereum-optimism/optimism/pull/19785)). A crucial fix ensures that contracts are built before generating the NUT bundle, preventing issues with uncompiled source contracts during bundle generation ([#19763](https://github.com/ethereum-optimism/optimism/pull/19763)).

### CI/CD and Tooling Updates
The CI/CD pipeline was enhanced with several updates. The factory workflow was bumped to enable SBOM attestation by default for all Docker image builds, ensuring automatic SPDX 2.3 SBOM attestations ([#19769](https://github.com/ethereum-optimism/optimism/pull/19769)). Rust CI jobs were downsized from `xlarge` to `medium` resource classes, significantly reducing credit consumption with minimal impact on wall-clock time ([#19777](https://github.com/ethereum-optimism/optimism/pull/19777)). Furthermore, `cargo-auditable` was integrated into Rust image builds to embed the full crate dependency tree into compiled binaries ([#19770](https://github.com/ethereum-optimism/optimism/pull/19770)).

## CLOSED ISSUES

### L2CM Upgrade System Refinements
Several issues related to the L2 Contract Manager (L2CM) upgrade system have been closed. This includes the creation of a Solidity script for deterministic JSON NUT bundle generation ([#18834](https://github.com/ethereum-optimism/optimism/issues/18834)), implementation of dev feature flag support ([#18838](https://github.com/ethereum-optimism/optimism/issues/18838)), and the addition of `just` commands for generating and running L2 upgrade fork tests ([#18840](https://github.com/ethereum-optimism/optimism/issues/18840), [#18841](https://github.com/ethereum-optimism/optimism/issues/18841)). These closures indicate significant progress in automating and securing the contract upgrade process.

### Flaky Test Resolution
The flaky test `TestCLELDivergence` has been closed ([#19681](https://github.com/ethereum-optimism/optimism/issues/19681)). Discussions revealed that the issue was likely due to noise introduced by node resets during initial derivation pipeline initialization rather than an EL sync bug. A proposed fix in PR #19733 is believed to have mitigated the flakiness.

### `op-reth` ChainID Issue Resolved
An issue where `op-reth` was sending `chainID=0` in the `supervisor_checkAccessList ExecutingDescriptor` has been closed ([#19768](https://github.com/ethereum-optimism/optimism/issues/19768)). This bug affected interop validation when `--rollup.supervisor-http` was configured.

## NEW ISSUES

### Flaky Test and Proof System Concerns
A new flaky test, `TestPreinteropFaultProofs_TraceExtensionActivation`, has been reported ([#19760](https://github.com/ethereum-optimism/optimism/issues/19760)). This indicates potential instability in the fault proof system, with discussions suggesting that PR #19745, which simplifies the migration process, might resolve the issue by eliminating nonce collision race conditions.

### `op-geth` Breaking Change and `StorageKeys`
A breaking change in `op-geth` version `v1.101701.0` has been identified, where `StorageKeys` values are `null` instead of `[]` ([#19764](https://github.com/ethereum-optimism/optimism/issues/19764), [#780](https://github.com/ethereum-optimism/optimism/issues/780)). This issue is linked to how `SortedFunc` in Go handles empty slices, returning `nil` instead of an empty array, which affects JSON serialization.

### L2CM Upgrade and Security Concerns
New issues highlight concerns regarding L2CM upgrades, specifically the need for weekly fork testing of L2CM upgrades for all supported chains ([#19766](https://github.com/ethereum-optimism/optimism/issues/19766)). This is driven by a review finding that the ProxyAdmin owner can upgrade predeploys without version checks, posing a risk if an implementation with a higher semver version than the next NUT bundle is introduced.

### `op-supernode` and `op-reth` Interoperability
An issue has been opened to track the `op-supernode` workaround for `op-reth`'s FCU retry-verify loop in `RewindToTimestamp` ([#19772](https://github.com/ethereum-optimism/optimism/issues/19772)). This workaround addresses a race condition in `op-reth` where back-to-back forkchoice updates for sibling blocks at the same height can cause a safe head mismatch panic.

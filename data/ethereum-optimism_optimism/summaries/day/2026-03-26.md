# ethereum-optimism/optimism Daily Update (Mar 26, 2026)
## OVERVIEW 
Today's development focused on optimizing `op-node` performance by batching `safe-head FCU` calls, enhancing `op-alloy-evm` functionality, and addressing several critical bug fixes across `contracts-bedrock` and `kona-proof`. Significant efforts were also made to improve CI efficiency and Rust tooling.

## KEY TECHNICAL DEVELOPMENTS

### `op-node` Performance and `op-alloy-evm` Enhancements
The `op-node` saw a significant performance improvement by batching `safe-head engine_forkchoiceUpdated` calls to one per derived L1 block, reducing overhead on the consolidation path [#19638](https://github.com/ethereum-optimism/optimism/pull/19638). Additionally, the `op-alloy-evm` now includes an `OpEvm::into_inner` method, mirroring `alloy_evm`'s `EthEvm::into_inner` for better interoperability [#19735](https://github.com/ethereum-optimism/optimism/pull/19735).

### Critical Bug Fixes and Contract Stability
Several bug fixes were implemented to enhance system stability. This included addressing `l2cm IR low` fixes in `contracts-bedrock`, resolving an upgrade edge case with `ConditionalDeployer`, and correcting an inline comment [#19785](https://github.com/ethereum-optimism/optimism/pull/19785). `kona-proof` received multiple important fixes to its derivation logic, particularly preventing malicious trace-extension challenges [#19775](https://github.com/ethereum-optimism/optimism/pull/19775). A crucial fix was also applied to ensure contracts are built before generating NUT bundles, preventing issues with uncompiled source contracts [#19763](https://github.com/ethereum-optimism/optimism/pull/19763).

### CI/CD and Rust Tooling Improvements
CI workflows were updated to enable SBOM attestation by default for Docker image builds, enhancing supply chain security [#19769](https://github.com/ethereum-optimism/optimism/pull/19769). Rust CI jobs were downsized from `xlarge` to `medium` to reduce resource consumption without impacting performance [#19777](https://github.com/ethereum-optimism/optimism/pull/19777). The `op-reth` project now includes `chain_id` in its `ExecutingDescriptor` for supervisor txpool validation [#19771](https://github.com/ethereum-optimism/optimism/pull/19771), and `cargo-auditable` is being used for Rust image builds to embed full crate dependency trees [#19770](https://github.com/ethereum-optimism/optimism/pull/19770).

## CLOSED ISSUES

### Resolution of Flaky Tests
The flaky test `TestCLELDivergence` [#19681](https://github.com/ethereum-optimism/optimism/issues/19681) was closed today. Discussions revealed that the test's expectation regarding CL-EL divergence persistence was incorrect, as the derivation pipeline resetting the unsafe head is expected behavior. The issue was mitigated by PR [#19733](https://github.com/ethereum-optimism/optimism/pull/19733), which addressed the underlying cause of the flakiness.

### L2CM Upgrade Scripting and Feature Flag Implementation
Several issues related to L2CM upgrades were closed, indicating significant progress in this area. This includes the creation of a Solidity script to generate deterministic JSON NUT bundles [#18834](https://github.com/ethereum-optimism/optimism/issues/18834), implementation of dev feature flag support in the L2 upgrade system [#18838](https://github.com/ethereum-optimism/optimism/issues/18838), and the addition of `just` commands for generating NUT bundles [#18840](https://github.com/ethereum-optimism/optimism/issues/18840) and running L2 upgrade fork tests [#18841](https://github.com/ethereum-optimism/optimism/issues/18841). These were closed by PRs [#19248](https://github.com/ethereum-optimism/optimism/pull/19248), [#19324](https://github.com/ethereum-optimism/optimism/pull/19324), and [#19464](https://github.com/ethereum-optimism/optimism/pull/19464).

### `op-reth` ChainID Issue Resolution
The issue where `op-reth` was sending `chainID=0` in `supervisor_checkAccessList ExecutingDescriptor` [#19768](https://github.com/ethereum-optimism/optimism/issues/19768) was closed today. This problem occurred when `--rollup.supervisor-http` was configured, leading to incorrect chain ID in the `ExecutingDescriptor`.

## NEW ISSUES

### `op-geth` Breaking Change and L2CM Upgrade Testing
A breaking change in `op-geth` v1.101701.0 was reported, where `StorageKeys` values are `null` instead of `[]` [#19764](https://github.com/ethereum-optimism/optimism/issues/19764). This is linked to an `op-geth` issue and will be surfaced in release notes. Additionally, weekly fork testing of L2CM upgrades for all supported chains has been proposed to prevent issues where the ProxyAdmin owner could upgrade predeploys without version checks [#19766](https://github.com/ethereum-optimism/optimism/issues/19766).

### `op-reth` and `op-supernode` Specific Issues
A new issue highlights that `op-reth` sends `chainID=0` in `supervisor_checkAccessList ExecutingDescriptor` when `--rollup.supervisor-http` is configured [#19768](https://github.com/ethereum-optimism/optimism/issues/19768). Another issue tracks the need for `op-supernode` to track the FCU retry-verify workaround in `RewindToTimestamp` to address an `op-reth` race condition [#19772](https://github.com/ethereum-optimism/optimism/issues/19772).

### SDM Tracking and `cannon-op-e2e-tests` Transition
A tracking issue has been opened for the productionization of SDM from PoC2, aiming to split it into small, reviewable PRs and merge production-ready pieces into `develop` [#19779](https://github.com/ethereum-optimism/optimism/issues/19779). There's also a plan to switch the `cannon-op-e2e-tests` CI job to use `kona-proof` instead of `op-program` for increased confidence in `kona-client` and `kona-host` [#19789](https://github.com/ethereum-optimism/optimism/issues/19789).

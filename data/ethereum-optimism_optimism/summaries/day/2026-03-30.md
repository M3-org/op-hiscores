# ethereum-optimism/optimism Daily Update (Mar 30, 2026)
## OVERVIEW 
Today's development focused on enhancing `op-conductor` functionality, resolving critical bugs in Kona and `op-node`, and improving CI processes. Key updates include a new Raft configuration option, fixes for message expiry and database stability, and streamlined documentation.

## KEY TECHNICAL DEVELOPMENTS

### Enhancements to `op-conductor` and Raft Consensus
A new feature was added to `op-conductor` allowing Raft to prevent shutdown when a node is removed from the cluster, improving operational resilience [#18699](https://github.com/ethereum-optimism/optimism/pull/18699).

### Critical Bug Fixes in Kona and `op-node`
Several significant bugs were addressed, including using a configurable message expiry window in Kona's `MessageGraph` instead of a hardcoded constant [#19765](https://github.com/ethereum-optimism/optimism/pull/19765). A race condition causing flaky test panics in `op-node` was fixed by guarding `SafeDB` methods against use after `Close` [#19824](https://github.com/ethereum-optimism/optimism/pull/19824). Additionally, Kona host tests were improved for isolation and deduplication of KV store creation [#19807](https://github.com/ethereum-optimism/optimism/pull/19807).

### CI/CD and Contract Management Improvements
CI processes were refined to correctly resolve target branches in the merge queue [#19822](https://github.com/ethereum-optimism/optimism/pull/19822) and report passing status checks for documentation-only pull requests [#19815](https://github.com/ethereum-optimism/optimism/pull/19815). Contract management saw a refactoring to separate v4/v5 initialization slot clearing in `L2ContractsManagerUtils` [#19797](https://github.com/ethereum-optimism/optimism/pull/19797).

## ACTIVE ISSUES

### Flaky Test: `TestPreinteropFaultProofs_VariedBlockTimes` [#19804](https://github.com/ethereum-optimism/optimism/issues/19804)
The test `TestPreinteropFaultProofs_VariedBlockTimes` and its `_FasterChainB` variant are reported as flaky. The root cause has been identified as `l1BlockWithLocalSafeBlocks()` polling the supernode's `RequiredL1` values, which can shift due to sequencer activity during Stage 2's batcher choreography. A fix has been submitted in PR #19805, proposing to replace supernode polling with direct L1 head reads at each batcher choreography stage to maintain invariants.

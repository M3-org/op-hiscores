# ethereum-optimism/optimism Daily Update (Mar 30, 2026)

## OVERVIEW 
Today's development focused on critical bug fixes across Kona and op-node, enhancing CI stability, and refining `op-conductor` functionality. Significant progress was made in addressing flaky tests and improving contract management.

## KEY TECHNICAL DEVELOPMENTS

### Enhancements to `op-conductor` and Kona Interoperability
A new feature was added to `op-conductor` allowing Raft to prevent shutdown when a node is removed from the cluster ([#18699](https://github.com/ethereum-optimism/optimism/pull/18699)). Additionally, Kona's `MessageGraph` was updated to use a configurable message expiry window, moving away from a hardcoded constant ([#19765](https://github.com/ethereum-optimism/optimism/pull/19765)).

### Critical Bug Fixes for Node Stability and CI
Several crucial bug fixes were implemented, including guarding `SafeDB` methods in `op-node` against use after closure to prevent panics during supernode shutdown ([#19824](https://github.com/ethereum-optimism/optimism/pull/19824)). CI stability was improved by resolving the correct target branch in the merge queue ([#19822](https://github.com/ethereum-optimism/optimism/pull/19822)) and reporting passing status checks for documentation-only PRs ([#19815](https://github.com/ethereum-optimism/optimism/pull/19815)). Kona host tests also received a fix to use `tempfile` for better isolation and to deduplicate KV store creation ([#19807](https://github.com/ethereum-optimism/optimism/pull/19807)).

### Contracts Refactoring and Documentation
Contract management was refined by separating v4/v5 initialization slot clearing in `L2ContractsManagerUtils` ([#19797](https://github.com/ethereum-optimism/optimism/pull/19797)). Documentation was enhanced with subdirectory pointers in `AGENTS.md` to guide AI agents to relevant `CLAUDE.md` files ([#19808](https://github.com/ethereum-optimism/optimism/pull/19808)).

## ACTIVE ISSUES

### Flaky Test: `TestPreinteropFaultProofs_VariedBlockTimes` ([#19804](https://github.com/ethereum-optimism/optimism/issues/19804))
This flaky test, `TestPreinteropFaultProofs_VariedBlockTimes`, remains active. The root cause has been identified as a race condition during L1 block polling, where `RequiredL1` values shift due to sequencer activity. A fix has been submitted in [#19805](https://github.com/ethereum-optimism/optimism/pull/19805), which replaces supernode polling with direct L1 head reads to ensure invariants are maintained.

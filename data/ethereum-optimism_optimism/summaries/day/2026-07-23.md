# ethereum-optimism/optimism Daily Update (Jul 23, 2026)
## OVERVIEW 
Today's development focused on significant documentation enhancements, bug fixes related to transaction receipts, and improvements in dispute game classification and SuperAuthority deny-list checks.

## KEY TECHNICAL DEVELOPMENTS

### Documentation Overhaul and Restructuring
Extensive work was done to improve and restructure the project's documentation. This included adding new curriculum hubs for fault proofs and interoperability ([#21982]), rolling out NormativeSpec callouts across various protocol pages ([#21981], [#21984]), and adding component hubs for `kona-client` and `kona-host` ([#21980]). The documentation also saw a major reorganization with the dissolution of the Rust tab ([#21989], [#21986]) and the relocation of `op-reth` CLI reference under node operators ([#21976]). Contradictory transaction finality timings were reconciled ([#21998]), and an empty interoperability page was delisted ([#21985]). A stale execution client list was also fixed ([#21996]).

### Bug Fixes and System Enhancements
A critical bug was fixed in `op-reth/rpc` where the `eth_getTransactionReceipt` returned an incorrect `contractAddress` for deposit contract-creation transactions when the L2 nonce was greater than 0 ([#21449]). The `op-node` was updated to apply SuperAuthority deny-list checks on the consolidation path, addressing a previous oversight where checks only occurred during block building ([#21970]).

### Dispute Game and Interoperability Improvements
The `op-fetcher` now supports `SUPER_PERMISSIONED` and `SUPER_CANNON_KONA` super-root game types, enabling discovery of these new game types after legacy game registrations are removed ([#21928]). Additionally, `op-dispute-mon` was updated to correctly classify `ZKDisputeGame` as a super-root game, ensuring it is validated through the appropriate path ([#21979]).

### CI and Codebase Refinements
CI configurations were updated to check SP1 guest lock before building ELFs and to refresh stale guest lockfiles, preventing build failures due to dependency drift ([#21978]). The `CODEOWNERS` file was also updated to replace removed teams, ensuring proper auto-requesting of reviews ([#21967]). A configurable post-execution refund policy seam was added to the SDM, allowing for more flexible refund inspection ([#21958]).

## ACTIVE ISSUES

### `op-node` Synchronization Challenges with `op-reth` Backend
Issue [#20974] continues to be active, discussing problems with `op-node` failing to sync when `--syncmode=execution-layer` is enabled with the `op-reth` backend. The latest comment from jlynch1 highlights similar issues, noting frequent `ecies auth failed`, `stream closed due to not being readable`, and `TooManyPeers` disconnects when using `execution-layer` sync mode. The user observed that `consensus-layer` sync mode is more successful but results in a lower reported block height due to L1 batch-posting lag. The discussion also suggests the need for a list of trusted peers to bootstrap the node.

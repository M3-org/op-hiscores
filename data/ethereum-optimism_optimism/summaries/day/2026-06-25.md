# ethereum-optimism/optimism Daily Update (Jun 25, 2026)
## OVERVIEW 
Today's development focused on enhancing the robustness and testability of the Kona SP1 range program, improving `op-devstack` lifecycle management, and addressing critical superchain configuration issues.

## KEY TECHNICAL DEVELOPMENTS

### Kona SP1 Enhancements and Refactoring
The Kona SP1 range program saw significant refactoring to improve native testability, reducing execution costs for coverage cases. A bug fix was also implemented to ensure the BlobStore's soundness is self-contained by adding local asserts for invariants.
- Refactoring: [#21554](https://github.com/ethereum-optimism/optimism/pull/21554)
- Bug Fix: [#21561](https://github.com/ethereum-optimism/optimism/pull/21561)

### `op-devstack` and Superchain Configuration Improvements
`op-devstack` now supports controlled lifecycle management, allowing external callers to start and stop services with error-returning semantics. Additionally, a critical update ensures `op-node` correctly loads `keep_karst_upgrade_gas` from the superchain registry for networks like op-sepolia and op-mainnet.
- `op-devstack` Lifecycle: [#21286](https://github.com/ethereum-optimism/optimism/pull/21286)
- Superchain Configuration: [#21566](https://github.com/ethereum-optimism/optimism/pull/21566)

### Build Process Streamlining
The project streamlined its build process by removing standalone `cannon` and `cannon-builder` image entries, while maintaining existing `op-challenger` image build behavior.
- Image Build Removal: [#21556](https://github.com/ethereum-optimism/optimism/pull/21556)

Several issues related to Kona SP1 and its host were closed.

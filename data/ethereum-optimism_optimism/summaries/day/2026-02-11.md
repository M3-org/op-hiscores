# ethereum-optimism/optimism Daily Update (Feb 11, 2026)

## OVERVIEW 
Today's development focused on CI/CD pipeline improvements, significant documentation porting for `op-reth`, and general code cleanup, alongside addressing several critical issues.

## KEY TECHNICAL DEVELOPMENTS

### CI/CD Pipeline Enhancements and Fixes
Multiple bug fixes and improvements were implemented in the CI/CD pipelines. This included renaming continuation config parameters to avoid naming conflicts, fixing prestate artifact publication for Kona, and correcting syntax errors in the Rust CI configuration. Additionally, the `main` and `acceptance-test` workflows were merged to reduce redundant work and optimize compute time.
- Bug Fixes: [#19142](https://github.com/ethereum-optimism/optimism/pull/19142), [#19130](https://github.com/ethereum-optimism/optimism/pull/19130), [#19144](https://github.com/ethereum-optimism/optimism/pull/19144)
- Tests Added: [#19108](https://github.com/ethereum-optimism/optimism/pull/19108)

### `op-reth` Documentation Porting
Extensive documentation from the upstream `reth` repository was ported into `op-reth/docs/vocs/`, encompassing the OP Stack running guide, sync FAQ, and a comprehensive CLI reference. This effort significantly enhances the developer experience for `op-reth` users.
- Documentation Enhancements: [#18968](https://github.com/ethereum-optimism/optimism/pull/18968)

### Codebase Cleanup and Refinements
The `kona-batcher-comp` crate and its associated files were removed due to being unused, streamlining the codebase. Updates were made to `op-acceptor` to include fixes for capturing logs during test timeouts, and metrics recording was added to `op-batcher` before throttling to ensure better tracking. Furthermore, `check-no-std` recipes were consolidated into the root justfile for improved organization.
- Other Work: [#18972](https://github.com/ethereum-optimism/optimism/pull/18972), [#19120](https://github.com/ethereum-optimism/optimism/pull/19120), [#19138](https://github.com/ethereum-optimism/optimism/pull/19138), [#19154](https://github.com/ethereum-optimism/optimism/pull/19154)

## CLOSED ISSUES

### Kona Prestate and Cannon Integration
The issue of using the monorepo cannon to build Kona prestates was resolved, moving away from a pinned version of cannon in `cannon-repro.dockerfile` now that Kona is part of the monorepo [#19143](https://github.com/ethereum-optimism/optimism/issues/19143). Relatedly, the CI configuration was updated to use a single bucket and path for both `op-program` and Kona prestates [#18782](https://github.com/ethereum-optimism/optimism/issues/18782).

### `op-reth` and Rust Monorepo Migration
Several issues related to the `op-reth` migration and Rust monorepo consolidation were closed. This included migrating example crates dependent on `op-reth` from `paradigmxyz/reth` [#18918](https://github.com/ethereum-optimism/optimism/issues/18918), removing the `reth` submodule and updating CI to use `op-reth` [#18919](https://github.com/ethereum-optimism/optimism/issues/18919), unifying all Rust crates into a single workspace [#18930](https://github.com/ethereum-optimism/optimism/issues/18930), and consolidating zepter configs between Rust repositories [#18931](https://github.com/ethereum-optimism/optimism/issues/18931). The porting of documentation from `reth` to `op-reth` was also completed [#18969](https://github.com/ethereum-optimism/optimism/issues/18969).

### Kona Audit and Feature Flags
The issue to enable `CANNON_KONA` as a respected game type after the Kona audit was closed, indicating progress towards updating the `RESPECTED_GAME_TYPE_CANNON_KONA` dev feature flag [#19116](https://github.com/ethereum-optimism/optimism/issues/19116).

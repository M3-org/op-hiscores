# ethereum-optimism/optimism Daily Update (Jul 24, 2026)
## OVERVIEW 
Today's development focused on enhancing the `op-reth` transaction pool, improving documentation clarity and consistency, and strengthening testing infrastructure for the Superchain. Significant progress was also made on `op-deployer` and `op-challenger` functionalities.

## KEY TECHNICAL DEVELOPMENTS

### `op-reth` Transaction Pool Enhancements
The `op-reth` transaction pool received critical updates to ensure accurate fee and gas limit reservations. This includes reserving the Isthmus operator fee in pool balance checks ([#21609](https://github.com/ethereum-optimism/optimism/pull/21609)) and reserving L1-info deposit gas in the tx-pool gas limit, achieving parity with `op-geth` ([#21548](https://github.com/ethereum-optimism/optimism/pull/21548)).

### Documentation Streamlining and Consistency
Extensive work was done to improve the clarity and reduce duplication in the documentation. This involved single-sourcing `op-challenger` setup guides ([#22007](https://github.com/ethereum-optimism/optimism/pull/22007)), cutting duplicated bridging mechanics ([#22002](https://github.com/ethereum-optimism/optimism/pull/22002)), extracting shared setup snippets for app developer tutorials ([#22001](https://github.com/ethereum-optimism/optimism/pull/22001)), and single-sourcing the `op-geth` EOL warning ([#22000](https://github.com/ethereum-optimism/optimism/pull/22000)). Additionally, shared OP Enterprise callouts were added to chain operator surfaces ([#21999](https://github.com/ethereum-optimism/optimism/pull/21999)) and decision-point sentences were added to solution guides ([#22006](https://github.com/ethereum-optimism/optimism/pull/22006)).

### Superchain Infrastructure and Testing Improvements
Key updates were made to the Superchain's underlying infrastructure and testing. This included building continuation deploy input from prepared state in `op-deployer` ([#21897](https://github.com/ethereum-optimism/optimism/pull/21897)), gating unsafe ingestion during invalidation recovery in `op-supernode` ([#21991](https://github.com/ethereum-optimism/optimism/pull/21991)), and migrating the ZK dispute game actor to super roots in `op-challenger` ([#21983](https://github.com/ethereum-optimism/optimism/pull/21983)). Testing was also enhanced with `op-acceptance-tests` taking safe-head DB baseline at L1-origin granularity ([#21975](https://github.com/ethereum-optimism/optimism/pull/21975)) and extracting a reusable SDM acceptance harness ([#21987](https://github.com/ethereum-optimism/optimism/pull/21987)).

## CLOSED ISSUES

### `op-reth` Transaction Pool Issues Resolved
Several issues related to the `op-reth` transaction pool's handling of fees and gas limits were closed. This includes fixing the admission of under-funded transactions due to omitted Isthmus operator fees ([#21608](https://github.com/ethereum-optimism/optimism/issues/21608)) and addressing the failure to reserve L1-info deposit gas, which led to transactions that could never be included on OP chains ([#21546](https://github.com/ethereum-optimism/optimism/issues/21546)).

### `op-challenger` and `op-reth` Functionality Updates
The `op-challenger` was updated to align with the new contracts API/ABI for the ZK game type ([#21415](https://github.com/ethereum-optimism/optimism/issues/21415)). Additionally, a TLS issue with `op-reth` v1.11.0 failing to connect to the flashblocks WebSocket endpoint was resolved ([#19322](https://github.com/ethereum-optimism/optimism/issues/19322)).

### Test Flakiness and Spike Completion
A flaky test, `TestNotTruncateDatabaseOnRestartWithExistingDatabase`, which intermittently failed its pre-restart setup, has been addressed ([#20028](https://github.com/ethereum-optimism/optimism/issues/20028)). The spike to figure out how to sanitize the `op-program` for Cannon has also been completed ([#12954](https://github.com/ethereum-optimism/optimism/issues/12954)).

## NEW ISSUES

### `op-deployer` and `op-supernode` Stability Concerns
New issues highlight potential stability problems, including a flaky test `TestDeployOPChain_WithForge` where `op-deployer` forge-script tests hang ([#22010](https://github.com/ethereum-optimism/optimism/issues/22010)), and a flaky `TestSupernodeEngineControllerConnectsAfterELUnavailableAtStartup` test ([#22013](https://github.com/ethereum-optimism/optimism/issues/22013)). A critical issue was also identified where `op-supernode`'s live logsDB parent mismatch after an L2 reorg causes infinite verification retry ([#22022](https://github.com/ethereum-optimism/optimism/issues/22022)).

### `kona-sp1-proposer` Development and Design
Several issues outline future development and design considerations for the `kona-sp1-proposer`. These include supporting super permissioned proposals in the ZK rust challenger ([#22015](https://github.com/ethereum-optimism/optimism/issues/22015)), decomposing `sync_games` after the defend path lands ([#22019](https://github.com/ethereum-optimism/optimism/issues/22019)), detecting a second instance running with the same key ([#22020](https://github.com/ethereum-optimism/optimism/issues/22020)), and deciding the multi-ZK-VM shape and crate location after the defend path ([#22021](https://github.com/ethereum-optimism/optimism/issues/22021)).

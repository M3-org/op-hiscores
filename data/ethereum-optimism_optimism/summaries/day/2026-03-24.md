# ethereum-optimism/optimism Daily Update (Mar 24, 2026)
## OVERVIEW 
Today's development focused on enhancing testing infrastructure, fixing critical Kona-related bugs, and improving CI processes. Several long-standing flaky tests were also resolved.

## KEY TECHNICAL DEVELOPMENTS

### Kona Bug Fixes and Infrastructure Updates
- Corrected an incorrect `target-c-int-width` in the MIPS64 target specification for Kona, ensuring proper prestate builds ([#19730](https://github.com/ethereum-optimism/optimism/pull/19730)).
- Fixed a CI issue where Kona prestate metadata files were incorrectly named, preventing them from being picked up by `vm-runner` ([#19732](https://github.com/ethereum-optimism/optimism/pull/19732)).
- Upgraded the `op-challenger` base image to Ubuntu 24.04 to align with Kona's upgraded `glibc` requirements ([#19734](https://github.com/ethereum-optimism/optimism/pull/19734)).

### Enhanced Testing and CI Stability
- Added a multi-iteration EIP-2935 test to `kona-proof-interop` to cover cases where the target block is beyond the 8,191-block history window ([#19738](https://github.com/ethereum-optimism/optimism/pull/19738)).
- Deflaked the `TestCLELDivergence` in `op-acceptance-tests` to improve test reliability ([#19733](https://github.com/ethereum-optimism/optimism/pull/19733)).
- Enabled the Ecotone fees test in `op-acceptance-tests` which was previously skipped ([#19740](https://github.com/ethereum-optimism/optimism/pull/19740)).
- Introduced a CI gate job to streamline GitHub required status checks for the `develop` branch ([#19535](https://github.com/ethereum-optimism/optimism/pull/19535)).
- Implemented auto-disabling of color in test logs when not printing to a terminal, useful for CI logs ([#19741](https://github.com/ethereum-optimism/optimism/pull/19741)).

## ACTIVE ISSUES

### Flaky Test: TestCLELDivergence ([#19681](https://github.com/ethereum-optimism/optimism/issues/19681))
The `TestCLELDivergence` test remains active, with recent discussions focusing on the root cause of its flakiness. A potential mitigation has been implemented via [#19733](https://github.com/ethereum-optimism/optimism/pull/19733), but the issue will remain open until the flakiness is confirmed to have disappeared. The core of the discussion revolves around whether a derivation pipeline reset is expected behavior or a bug, and how it impacts the test's expectation of CL-EL divergence persistence.

### Flaky Test: TestPreserveDatabaseOnCLResync, TestTruncateDatabaseOnELResync, TestCLUnsafeNotRewoundOnInvalidDuringELSync ([#19661](https://github.com/ethereum-optimism/optimism/issues/19661))
Two out of three tests tracked in this issue, `TestPreserveDatabaseOnCLResync` and `TestCLUnsafeNotRewoundOnInvalidDuringELSync`, appear to be fixed with 113 consecutive passes. However, `TestTruncateDatabaseOnELResync` still shows recent failures, and the issue remains open pending more data to confirm its stability.

### Interop Phase 3: Removing Chains From Shared Dispute Games ([#19692](https://github.com/ethereum-optimism/optimism/issues/19692))
Discussions clarify that this issue focuses on implementing support within the proofs system for removing chains from the interop set, specifically from a shared dispute game. It does not encompass all related problems for interop in general.

### dispute-mon: Implement monitoring for ZK games ([#18424](https://github.com/ethereum-optimism/optimism/issues/18424))
A new specific monitoring detail was identified: when `ZKDisputeGame` resolves with `CHALLENGER_WINS` and no challenger exists, bond credit is assigned to `address(0)`. This ETH remains stranded as no one calls `claimCredit(address(0))`. This has led to the creation of a new issue ([#19743](https://github.com/ethereum-optimism/optimism/issues/19743)) to address this, suggesting `dispute-mon` may need to detect and automatically claim/withdraw such credits.

### feat(op-reth): implement interop tx pool filter and reorg eviction ([#19411](https://github.com/ethereum-optimism/optimism/issues/19411))
An upstream Reth issue ([https://github.com/paradigmxyz/reth/issues/23205](https://github.com/paradigmxyz/reth/issues/23205)) has been identified as necessary to enable supernode's rewind operations to work correctly under `op-reth`, which is relevant to the implementation of interop-related tx pool features.

# ethereum-optimism/optimism Daily Update (Jun 24, 2026)
## OVERVIEW 
Today's development focused on enhancing FeeVault security, refining the op-node's P2P sync client, and integrating SP1 range-executor for Kona. Documentation was also significantly updated with new protocol explainers and a guide for Sequencer Defined Metering.

## KEY TECHNICAL DEVELOPMENTS

### FeeVault Security and Withdrawal Route Management
A new feature was added to the FeeVault to allow proxy admin owners to atomically update recipient and withdrawal networks, enhancing security and preventing partial updates. This is a safer alternative to separate calls for setting recipient and withdrawal network.
- [#20982](https://github.com/ethereum-optimism/optimism/pull/20982)

### op-node P2P Sync Client Refinement and Kona SP1 Integration
The deprecated Req/Resp CL P2P sync client was removed from the op-node in a phased rollout to ensure a safe upgrade path. Additionally, a new `kona-sp1` range-executor was introduced, enabling end-to-end testing of the range guest with op-e2e action tests.
- [#21498](https://github.com/ethereum-optimism/optimism/pull/21498)
- [#21528](https://github.com/ethereum-optimism/optimism/pull/21528)

### Documentation and Operator Guides
Significant updates were made to the documentation, including the migration of protocol explainers and network design to op-reth/kona. A new chain-operator guide for Sequencer Defined Metering (SDM) was also added, detailing its functionality and how it extends EVM warming.
- [#21146](https://github.com/ethereum-optimism/optimism/pull/21146)
- [#21211](https://github.com/ethereum-optimism/optimism/pull/21211)

## ACTIVE ISSUES

### Flaky Test: FuzzDetectNonBijectivity Mutates Non-Encoded Bit
The `FuzzDetectNonBijectivity` test in `op-service/eth/blob_test.go` is flaky because it mutates a non-encoded bit, leading to incorrect assertions. The discussion indicates that the test's premise might be flawed as the blob code is not bijective on the top two bits of the first field element. Both `op-node` and `kona` silently renormalize these bits instead of returning an error, which causes the test to fail when these bits are flipped. A potential fix would involve changing the encoding/decoding functions to return an error, but this would require a hardfork/upgrade boundary to avoid breaking existing on-chain blobs. Alternatively, the test harness could be adjusted to account for this non-bijective behavior.
- [#21539](https://github.com/ethereum-optimism/optimism/issues/21539)

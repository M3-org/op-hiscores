# ethereum-optimism/optimism Daily Update (Jun 14, 2026)
## OVERVIEW 
The day's development focused on a significant refactoring within the `op-e2e` testing suite, transitioning L2 EL to `op-reth` by default. This change addresses compatibility issues with deprecated `op-geth` and ensures robust interop super-cannon tests.

## KEY TECHNICAL DEVELOPMENTS

### `op-e2e` Test Suite Modernization
The `op-e2e` testing framework underwent a substantial refactoring to default to `op-reth` for L2 Execution Layer operations. This change resolves issues with the deprecated `op-geth` not supporting newer block sealing mechanisms, particularly for Karst/Osaka blocks, which caused interop super-cannon tests to hang. The update impacts various `op-e2e` sub-packages, including `system`, `e2eutils`, `faultproofs`, `opgeth`, and `interop`. ([#21363](https://github.com/ethereum-optimism/optimism/pull/21363))

### Permissionless Codepath Enhancements
Two new issues were opened concerning Milestone 4 of the Permissionless Codepath (PCD). These issues outline critical development needs for the deployment process:
- **Artifacts Persistence:** The need for artifacts to persist across different phases of the permissionless codepath workflow, especially during the prestate calculation and subsequent run, was highlighted. ([#21376](https://github.com/ethereum-optimism/optimism/issues/21376))

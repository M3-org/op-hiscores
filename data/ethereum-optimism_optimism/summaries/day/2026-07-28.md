# ethereum-optimism/optimism Daily Update (Jul 28, 2026)
## OVERVIEW 
Today's development focused on enhancing testing infrastructure, porting the `kona-sp1-proposer`, and refining CI/CD processes, alongside critical security updates for dependencies.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced Testing and CI/CD Reliability
Significant efforts were made to improve the robustness and efficiency of the testing suite and continuous integration pipelines. This included bounding forge subprocess waits and slow test broadcasts in `op-deployer` to prevent test hangs ([#22011](https://github.com/ethereum-optimism/optimism/pull/22011)), and bounding validator resync and reorg waits in `op-reth` proofs e2e tests ([#22056](https://github.com/ethereum-optimism/optimism/pull/22056)). Additionally, Rust test-tooling configuration was consolidated and individual test results are now surfaced in CircleCI ([#22076](https://github.com/ethereum-optimism/optimism/pull/22076)). CI builds were optimized with fast linkers and split `op-reth`/`kona` builds ([#22042](https://github.com/ethereum-optimism/optimism/pull/22042)), and external `kona` clones in prestate reproducibility builds were made more resilient with retries ([#22084](https://github.com/ethereum-optimism/optimism/pull/22084)).

### `kona-sp1-proposer` Port and `op-reth` Improvements
The `kona-sp1-proposer` was ported from `succinctlabs/op-succinct` into the `rust/kona/sp1/crates/proposer` directory, integrating its fault-proof proposer functionality ([#22018](https://github.com/ethereum-optimism/optimism/pull/22018)). For `op-reth`, local transaction-pool admission for RPC-submitted transactions forwarded to a sequencer was made opt-in, providing more control over transaction handling ([#22053](https://github.com/ethereum-optimism/optimism/pull/22053)).

### Dependency Management and Security Updates
Several dependency updates were implemented to address security vulnerabilities and improve overall system stability. This included updating `quinn-proto` to v0.11.16 to resolve an advisory ([#22072](https://github.com/ethereum-optimism/optimism/pull/22072)), updating `golang.org/x/text` to v0.39.0 ([#22067](https://github.com/ethereum-optimism/optimism/pull/22067)), and `github.com/quic-go/webtransport-go` to v0.11.1 ([#22066](https://github.com/ethereum-optimism/optimism/pull/22066)). The Go toolchain directive was also updated to v1.25.12 for security ([#22065](https://github.com/ethereum-optimism/optimism/pull/22065)). A new Renovate CVE-autobump workflow was added to automate vulnerability advisories ([#22061](https://github.com/ethereum-optimism/optimism/pull/22061)), and Renovate's commit titles were configured to align with scoped-commit standards ([#22071](https://github.com/ethereum-optimism/optimism/pull/22071)).

## CLOSED ISSUES

### Resolution of Flaky Tests and Hanging Processes
Several issues related to test instability and hanging processes were addressed. This includes the resolution of a flaky `TestDeployOPChain_WithForge` test where `forge script` processes would hang ([#22010](https://github.com/ethereum-optimism/optimism/issues/22010)).

### `kona-sp1-proposer` Instance Management
An issue concerning the `kona-sp1-proposer` and the detection of multiple instances running with the same key was closed ([#22020](https://github.com/ethereum-optimism/optimism/issues/22020)). The discussion concluded that the impact of such an occurrence is minor, and the complexity of implementing a detection mechanism was deemed unnecessary.

### Precompile Gas Reservation and Super-root Game Type Support
The issue regarding increasing `PreimageOracle.PRECOMPILE_CALL_RESERVED_GAS` before Glamsterdam (EIP-8037) was closed as stale, with analysis indicating the current value is sufficient for correctness and that a higher value would require a stronger, documented invariant ([#19380](https://github.com/ethereum-optimism/optimism/issues/19380)). Additionally, support for super-root game types 5 and 9 in `op-fetcher` and `superchain-registry` was implemented, resolving a previous limitation ([#21711](https://github.com/ethereum-optimism/optimism/issues/21711)).

# ethereum-optimism/optimism Daily Update (May 12, 2026)

## OVERVIEW 
Today's development focused on significant enhancements to the `op-reth` trie engine, interop tooling, and critical bug fixes across `op-supernode` and `op-proposer` for improved stability and recovery.

## KEY TECHNICAL DEVELOPMENTS

### `op-reth` Trie Engine Enhancements
Major progress was made on the `op-reth` trie engine, wiring up the engine in Exex and introducing the core `EngineState`, `Engine`, and `EngineHandle` components. This work establishes a channel-based engine for background trie state mutations and typed message exposure, improving performance and reliability.

## CLOSED ISSUES

### Flaky Acceptance Test Resolution
Several flaky acceptance tests related to L1 EL stalls and reorg recovery were identified and fixed. The root cause for `TestUnsafeGapFillAfterSafeReorg` [#19884](https://github.com/ethereum-optimism/optimism/issues/19884) and `TestFollowL2_ReorgRecovery` [#19967](https://github.com/ethereum-optimism/optimism/issues/19967) was analyzed and addressed, preventing tests from wedging. `TestWithdrawal_Cannon` [#19963](https://github.com/ethereum-optimism/optimism/issues/19963) was also addressed, with a fix implemented to wait for the L1 head past the dispute game creation timestamp before attempting prove transactions.

### Kona Protocol and Supernode Stability Fixes
A bug in Kona's frame parsing, where invalid `is_last` bytes were not rejected, was resolved [#19335](https://github.com/ethereum-optimism/optimism/issues/19335). Additionally, a critical issue preventing `op-supernode`'s `logs.db` from recovering after L2 reorgs while offline was fixed [#20627](https://github.com/ethereum-optimism/optimism/issues/20627).

### Interop Proofs and Supernode Logic Clarification
The issue regarding `kona-host`'s preimage server returning fetcher data without verification was closed with a fix implemented [#20659](https://github.com/ethereum-optimism/optimism/issues/20659). The `op-supernode` issue concerning `superroot_atTimestamp` reporting cross-safe L1 instead of local-safe L1 was closed, confirming no bug after re-evaluation and test rewrites [#20657](https://github.com/ethereum-optimism/optimism/issues/20657).

### Deployment Tooling and Upgrade Support
The issue related to deployment tooling for merging chains into a shared dispute game was closed [#19703](https://github.com/ethereum-optimism/optimism/issues/19703). Work on implementing past upgrade handling for L2 forks was also completed [#20524](https://github.com/ethereum-optimism/optimism/issues/20524), alongside an upgrade template supporting transitions from permissioned to permissionless chains [#20562](https://github.com/ethereum-optimism/optimism/issues/20562).

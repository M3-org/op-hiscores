# ethereum-optimism/optimism Daily Update (Jun 5, 2026)
## OVERVIEW 
Today's development focused on enhancing `op-node`'s superroot serving capabilities, optimizing `op-reth`'s trie backfill performance, and significant documentation updates for releases and upgrades. Several bug fixes addressed CI typos and `op-e2e` genesis allocation, alongside refactoring for `op-service/kzg`.

## KEY TECHNICAL DEVELOPMENTS

### `op-node` Superroot and `op-reth` Trie Performance Improvements
A new `superroot` JSON-RPC namespace was added to `op-node` to serve `superroot_atTimestamp` for non-interop chains, mirroring `op-supernode`'s wire contract for existing dispute infrastructure ([#20581](https://github.com/ethereum-optimism/optimism/pull/20581)). Additionally, `op-reth/proofs` now snapshots hashed-leaf tables to accelerate backfill, addressing bottlenecks in `compute_block_backfill_diff` ([#21088](https://github.com/ethereum-optimism/optimism/pull/21088)).

### Critical Bug Fixes and CI Enhancements
Several bug fixes were implemented, including pointing to a corrected Reth commit ([#21247](https://github.com/ethereum-optimism/optimism/pull/21247)), correcting a `BASE_REVISION` typo in CI configuration ([#21244](https://github.com/ethereum-optimism/optimism/pull/21244)), and lazily generating genesis allocations in `op-e2e` to reduce test startup times ([#21238](https://github.com/ethereum-optimism/optimism/pull/21238)). CI jobs also saw improvements with de-duplicated command definitions and the introduction of a shared `sccache` compile cache for Rust, significantly speeding up builds ([#21245](https://github.com/ethereum-optimism/optimism/pull/21245), [#21227](https://github.com/ethereum-optimism/optimism/pull/21227)).

### Documentation and Contract Updates
Documentation was updated to reflect the `op-batcher v1.16.10` release ([#21264](https://github.com/ethereum-optimism/optimism/pull/21264)) and `op-reth v2.3.1` for Upgrade 19, including fixes for a deadlock bug ([#21263](https://github.com/ethereum-optimism/optimism/pull/21263)). The `SuperchainConfig` contract was marked as audited and its version bumped to `v2.4.3` ([#21265](https://github.com/ethereum-optimism/optimism/pull/21265)).

## CLOSED ISSUES

### `op-node` Superroot Support for Non-Interop Chains
The issue of `op-node` supporting `superroot_atTimestamp` for non-interop chains has been closed ([#20552](https://github.com/ethereum-optimism/optimism/issues/20552)). This was crucial for moving to super dispute games before interop activation, ensuring `op-challenger` and `op-dispute-mon` could consume super roots.

### Devstack Interop and Sequencer Bootstrap Fixes
Several issues related to devstack interop and sequencer bootstrapping were resolved. This includes a fix where the devstack interop preset incorrectly shared the EL between the light node sequencer and supernode ([#21158](https://github.com/ethereum-optimism/optimism/issues/21158)). Additionally, a problem where a follow-mode ELSync sequencer could not bootstrap a chain from genesis, leading to deadlocks, has been addressed ([#21164](https://github.com/ethereum-optimism/optimism/issues/21164)).

### `op-conductor` Interop Reorg Recovery
The issue concerning `op-conductor` gracefully recovering from interop reorgs has been closed ([#20006](https://github.com/ethereum-optimism/optimism/issues/20006)). The decision was made not to implement auto-recovery, instead focusing on developing runbooks for manual intervention during sequencer pauses.

## ACTIVE ISSUES

### `op-supervisor`/`op-supernode` Cross-Safe Backlog Drainage
Discussion continues on the issue where `op-supervisor`/`op-supernode` cross-safe cannot drain a backlog faster than real-time after a stall ([#21117](https://github.com/ethereum-optimism/optimism/issues/21117)). The latest comments suggest that the observed 12-hour delay aligns with sequencer window expiry behavior, implying that manual intervention might be expected in such scenarios. If this is the intended behavior, no further action might be needed on this ticket.

### `op-supernode`/`op-reth` CL Sync Recovery Stalls
The issue regarding `op-supernode`/`op-reth` CL sync recovery stalling when SafeDB/bookkeeping references an EL-missing block is still active ([#21076](https://github.com/ethereum-optimism/optimism/issues/21076)). Recent updates indicate that a candidate fix in Reth ([paradigmxyz/reth#24875](https://github.com/paradigmxyz/reth/pull/24875)) did not resolve the wedge, with 5 out of 5 cold-start arms still experiencing stalls due to `libmdbx` timeouts. The root cause has been identified as a cyclic deadlock in Reth's `StateTrieOverlayManager` / `DeferredTrieData` machinery, with two distinct "lock held across a `rayon` compute" sites. Two validated fixes, which remove the guard from across the compute, have been proposed and are currently being tested, showing promising results with continuous CL-sync for extended periods without wedges. The issue is being flagged for the Reth team for an upstream fix.

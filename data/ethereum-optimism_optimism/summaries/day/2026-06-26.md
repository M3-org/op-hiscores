# ethereum-optimism/optimism Daily Update (Jun 26, 2026)
## OVERVIEW 
Today's development focused on critical bug fixes across `op-reth` and `op-node`, addressing issues with `eth_estimateGas` and consensus-layer sync. A new feature was added to `op-alloy-network` for opt-in `reqwest` HTTP transport.
## KEY TECHNICAL DEVELOPMENTS

### `op-reth` and `op-node` Stability Improvements
Critical fixes were implemented to enhance the stability of `op-reth` and `op-node`. This includes setting `tx_gas_limit_cap` for Osaka to ensure `eth_estimateGas` functions correctly under Karst [#21574]. Additionally, `op-node` was updated to tolerate EL-expired genesis history during L2 configuration validation, resolving issues with consensus-layer sync after `op-reth` upgrades [#21587].

### `op-alloy-network` Feature Enhancement
A new feature was introduced to `op-alloy-network` that makes `alloy-provider`'s `reqwest` HTTP transport an opt-in feature, while maintaining current behavior by enabling it in default configurations [#21175].

### Contract Test Reliability and Documentation Updates
A bug affecting `OptimismMintableERC20Factory` CREATE2 prediction across different compiler profiles was fixed in the contracts test suite [#21592]. Documentation for Upgrade 19 was also updated, including removal of the OP Sepolia genesis.json workaround and revisions to component versions and gas-limit actions [#21544].

### L2 Genesis Integration
Work continued on integrating `l2cm` into the L2 genesis process, involving updates to several contract files and test cases [#21477].

## CLOSED ISSUES

### `op-reth` Consensus-Layer Sync Fix
An issue where consensus-layer sync failed after upgrading `op-reth` to v2.3.2 due to pruned history unavailability was identified and resolved [#21584]. The problem stemmed from a reth dependency bump that introduced an expiry guard for `recovered_block`, which rejected block 0. A fix was implemented to tolerate EL-expired genesis history.

### L2 Contracts Manager Enhancements
The `L2ContractsManager` was updated to include a `deploy(FullConfig)` function, intended to serve as the L2Genesis code path, moving initialization logic from the genesis script into the manager [#21342].

### ZK Proving Spike Completed
The ZK proving spike, aimed at establishing baseline latency and cost for a real super-root state-transition proof, has been completed with a full report posted to Notion [#21411].

### Portal Chain-ID Check Fix
A bug in `OptimismPortal2.proveWithdrawalTransaction` was fixed, addressing a missing chain-ID check for non-super game roots, ensuring proper binding of super-game roots to the portal's L2 chain ID [#20883].

## NEW ISSUES

### `eth_estimateGas` Workaround Removal
A new issue was created to track the removal of the OP EIP-7825 `estimateGas` workaround once an upstream reth fix is integrated [#21583].

## ACTIVE ISSUES

### `op-node` Compatibility with EIP-4444
Discussion continues on fixing `op-node` compatibility with EIP-4444 enabled L1 nodes [#13570]. A recent comment highlights that with `op-reth v2.3.2`, `CheckL2GenesisBlockHash` in `op-node v1.19.1` might also need to be updated to handle "pruned history unavailable" errors when trying to get the L2 genesis blockhash.

### Flaky Test: `TestReorgUnsafeHead`
The `TestReorgUnsafeHead` continues to be a flaky test, with recent failures showing the test waiting for an unsafe head reorg that never occurred, leading to timeouts [#20198]. The expected and actual head hashes were identical, indicating the reorg did not happen as anticipated. This issue was encountered during work on `klopfenstein/karst-estimategas-tx-gas-cap`.

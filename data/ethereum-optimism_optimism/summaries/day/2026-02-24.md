# ethereum-optimism/optimism Daily Update (Feb 24, 2026)
## OVERVIEW 
Today's development focused on enhancing fault proof testing, refining `op-devstack` capabilities, and integrating the Karst hard fork. Significant progress was also made on a new policy engine for stake-aware transaction ordering.

## KEY TECHNICAL DEVELOPMENTS

### Fault Proof Testing and Stability
Efforts were made to improve the robustness and coverage of fault proof tests. This included porting an interop fault proof test to `devstack` ([#19254](https://github.com/ethereum-optimism/optimism/pull/19254)), adding a missing consolidation step case to `op-acceptance-tests` ([#19296](https://github.com/ethereum-optimism/optimism/pull/19296)), and increasing the timeout for a supernode interop activation test to address flakiness in CI ([#19297](https://github.com/ethereum-optimism/optimism/pull/19297)).

### Core Infrastructure and Hard Fork Integration
The Karst hard fork activation logic was added, following the pattern of previous upgrades ([#19250](https://github.com/ethereum-optimism/optimism/pull/19250)). Additionally, `op-devstack` saw an update to introduce capability interfaces for polymorphic lookups, marking Phase 3 of the ID type system refactor ([#18874](https://github.com/ethereum-optimism/optimism/pull/18874)).

### Supernode Stability and Contract Development
Improvements were made to `op-supernode` to prevent hangs on shutdown by ensuring the metrics service always decrements ([#19293](https://github.com/ethereum-optimism/optimism/pull/19293)). A new `PolicyEngineStaking` periphery contract was introduced to enable stake-aware transaction ordering in `op-rbuilder` ([#19192](https://github.com/ethereum-optimism/optimism/pull/19192)).

### CI/CD Enhancements
CI configurations were updated to disable incremental compilation for Rust jobs and bump the Rust cache version, aiming to reduce cache size and improve reproducibility ([#19278](https://github.com/ethereum-optimism/optimism/pull/19278)).

## CLOSED ISSUES

### RPC Performance Vulnerability Addressed
A critical RPC performance issue related to `eth_getLogs` memory exhaustion was closed ([#769](https://github.com/ethereum-optimism/optimism/issues/769)). This issue, which could lead to OOMs on RPC nodes, was closed as a duplicate of an existing issue.

## NEW ISSUES

### `op-reth` P2P Sync Test Failure
An issue was reported regarding the `p2p::can_sync` e2e test in `reth-optimism-node` crashing due to an incorrect `debug_assert!` in upstream reth v1.11.1 ([#19298](https://github.com/ethereum-optimism/optimism/issues/19298)). The test is currently ignored.

### `op-proposer` Sepolia Devnet Timestamp Discrepancy
A bug was identified in `op-proposer` where the `anchorStateRegistry` on the Sepolia devnet uses a timestamp-like value instead of a block number for the current anchorState, leading to unexpected root claim checks ([#19301](https://github.com/ethereum-optimism/optimism/issues/19301)).

## ACTIVE ISSUES

### `op-batcher` Post-Holocene Ordering in Concurrent Mode
Issue [#18507](https://github.com/ethereum-optimism/optimism/issues/18507) highlights that `op-batcher` fails to account for post-Holocene ordering in concurrent mode. A comment from `kien-rise` on Feb 24, 2026, links this issue to a previous pull request, suggesting a potential connection or dependency.

### `op-supernode` Superroot SLA Updates
Issue [#19180](https://github.com/ethereum-optimism/optimism/issues/19180) discusses the ill-defined and currently misbehaving SLA of the Superroot object. `axelKingsley` commented on Feb 24, 2026, suggesting that Optimistic Roots should be a best-effort by all, and any unobtainable roots should either be excluded or included with empty values. The core idea is that a superroot should be available whenever output roots for all chains can be obtained.

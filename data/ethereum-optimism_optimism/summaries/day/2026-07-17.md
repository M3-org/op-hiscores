# ethereum-optimism/optimism Daily Update (Jul 17, 2026)
## OVERVIEW 
Today's development focused on enhancing the Superchain ecosystem with a new interop migration path, refining the Kona SP1 proving system, and significantly improving documentation quality and tooling.

## KEY TECHNICAL DEVELOPMENTS

### Superchain Interoperability and Contract Management
A new migration path (Path C) was added to `OPContractsManagerV2` to facilitate the re-pointing of shared dispute games to a new super game in a single transaction, improving interop migration flexibility [#21518]. The L2CM development feature flag was also removed, streamlining the contract management system [#21591].

### Kona SP1 Proving System Enhancements
The Kona SP1 proving system saw significant updates, including embedding range and super-range vkeys directly into aggregation guests at compile time, enhancing security and simplifying the proof process [#21851]. Related CI improvements were made to build guest ELFs and align guest lints with the root workspace [#21673], [#21856].

### Documentation Infrastructure and Quality
Extensive work was done to improve documentation, including adding a cross-repo link policy page and a CI linter to enforce it [#21846], fixing numerous link-policy violations [#21866], and updating super root migration runbooks [#21810]. New tooling was introduced to generate `op-batcher` flag references directly from source with CI drift checks [#21847], and content-type contracts were published for various documentation types [#21844].

## CLOSED ISSUES

### Dispute Game and L2CM Development
The issue regarding the removal of DevFeatures for L2CM auditor review has been closed [#20084], indicating progress in streamlining L2 contract management. The "Path C: SFDG → SZKDG" issue, which focused on multi-chain dispute game integration, was also closed [#20759].

### Kona SP1 Proving System Refinements
Several issues related to the Kona SP1 proving system were closed, including combining range and aggregation proofs into a single guest program [#21412], linting guest programs [#21512], building SP1 guest ELFs in CI [#21553], and replacing vkey input with embedded vkeys [#21858]. An issue to isolate Kona custom registry builds from tracked snapshots was also closed [#21881].

### Uniswap Devnet Progress
The Uniswap Joint Devnet 4 issue has been closed [#21260], with a note that it is on hold due to ongoing migration efforts for Unichain into OPE.

## NEW ISSUES

### Kona Node Liveness and Upgrade Needs
A new issue highlights a liveness bug in `op-node`'s `follow-source` mode, where synchronous L1 lookups on the driver's main event loop could cause stalls [#21880]. Another issue points out that Kupcake requires an upgrade to support Lagoon, Blockscout, and the latest OP stack, along with a refactor of its slow integration tests [#21879].

### Challenger Role Cleanup
An issue has been opened to remove the `challenger-role` configuration after the `PermissionedDisputeGame` is retired, as the `SuperPermissionedDisputeGame` does not have this role [#21888].

## ACTIVE ISSUES

### Kona Node Superroot Implementation
The issue [#21861] concerns implementing the `superroot_atTimestamp` RPC API in `kona-node`, aiming for equivalence with the `op-node` implementation. The latest comment indicates that this task is currently blocked until `kona-node` gains support for a safe database.

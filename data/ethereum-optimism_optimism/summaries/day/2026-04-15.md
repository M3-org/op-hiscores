## ACTIVE ISSUES

### L2CM Audit Finding #15
Issue [#20077](https://github.com/ethereum-optimism/optimism/issues/20077) discusses an informational audit finding regarding CGT upgrades not being able to replay a renounced LiquidityController owner. The latest comment confirms that this issue has been fixed by [#20095](https://github.com/ethereum-optimism/optimism/pull/20095).

### L2CM Interop Hard Fork Implementation
Issue [#20082](https://github.com/ethereum-optimism/optimism/issues/20082) tracks the implementation of the interop hard fork activation using the L2CM upgrade mechanism in `kona-node` and `op-node`. The latest comment clarifies that this is a simple task requiring `L1Block.setFeature(Features.INTEROP)` if `depset.len > 1`.

### SuperDisputeGame Deployment Support
Issue [#19652](https://github.com/ethereum-optimism/optimism/issues/19652) focuses on adding support for deploying the SuperDisputeGame contract type via `op-deployer` and `netchef`. The latest discussion indicates a decision to use a dedicated directory for `netchef` to pull a custom `op-deployer` build, allowing it to utilize the latest contracts and feature flags for SuperDisputeGame deployment.

### L2CM Support for op-chain-ops
Issue [#19102](https://github.com/ethereum-optimism/optimism/issues/19102) addresses the current hardcoding of `UseL2CM: false` in `interopgen` when building L2 genesis, which prevents interop/test deployments from enabling the L2 Contract Messenger (L2CM) feature. The latest comment notes that this issue is related to [#20079](https://github.com/ethereum-optimism/optimism/pull/20079).

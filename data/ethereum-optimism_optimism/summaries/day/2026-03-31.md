# ethereum-optimism/optimism Daily Update (Mar 31, 2026)
## OVERVIEW 
Today's development focused on significant upgrades to the dispute game system, enhancements to the Kona host and op-reth for improved interoperability, and critical bug fixes across various components, including L2 contracts and fault proof tests. Documentation was also updated with security reviews and deprecation notices.

## KEY TECHNICAL DEVELOPMENTS

### Dispute Game System Migration and Contract Upgrades
A major feature was introduced to migrate from legacy `FaultDisputeGame` types to `SuperDisputeGame` types, enabling individual chain upgrades via `OPContractsManagerV2`. This is a significant step towards enhancing the flexibility and capabilities of the Optimism dispute resolution mechanism. ([#19253](https://github.com/ethereum-optimism/optimism/pull/19253))

### Kona Host and op-reth Interoperability Improvements
The Kona host now includes a directory-based key-value store compatible with `op-program` for preimage handling, improving data storage and retrieval. Additionally, `op-reth` was updated to drop interop transactions after a reorg, preventing the re-injection of invalid cross-chain messages. ([#19803](https://github.com/ethereum-optimism/optimism/pull/19803), [#19814](https://github.com/ethereum-optimism/optimism/pull/19814))

### Critical Bug Fixes for Contracts and Fault Proofs
Several crucial bugs were addressed, including resolving a `NetworkWallet<Optimism>` conflict in `op-alloy` with alloy 1.8 ([#19756](https://github.com/ethereum-optimism/optimism/pull/19756)) and fixing `L2ContractsManagerUtils` to revert instead of silently skipping non-upgradeable predeploys ([#19798](https://github.com/ethereum-optimism/optimism/pull/19798)). Fault proof tests received multiple fixes to eliminate race conditions in L1 head capture, align `endTimestamp` to block boundaries, and mark flaky tests. ([#19805](https://github.com/ethereum-optimism/optimism/pull/19805), [#19831](https://github.com/ethereum-optimism/optimism/pull/19831), [#19830](https://github.com/ethereum-optimism/optimism/pull/19830), [#19825](https://github.com/ethereum-optimism/optimism/pull/19825))

### Documentation and Chore Updates
Documentation was enhanced with the addition of the Coinbase Kona security review ([#19811](https://github.com/ethereum-optimism/optimism/pull/19811)) and a deprecation notice for `op-deployer upgrade` and `manage` commands ([#19838](https://github.com/ethereum-optimism/optimism/pull/19838)). Minor chores included anchoring Semgrep path patterns for v2 compatibility ([#19725](https://github.com/ethereum-optimism/optimism/pull/19725)) and removing dead code related to `interop_message_expiry_window` from `RollupConfig` in Kona ([#19810](https://github.com/ethereum-optimism/optimism/pull/19810)).

## CLOSED ISSUES

### Resolution of Flaky Acceptance Tests
Several flaky acceptance tests related to database preservation, truncation, and CL/EL resyncs were closed after consistent passes on `develop`, indicating the underlying issues have been resolved. ([#19661](https://github.com/ethereum-optimism/optimism/issues/19661))

### Interop and Supernode Test Stability
Flaky tests concerning `TestProposer` hanging indefinitely in interop/proofs and `TestSupernodeInteropInvalidMessageReplacement` were closed. Root causes were identified and fixed, primarily related to `FailNow` calls within `Eventually` conditions and issues with message re-injection after reorgs. ([#19673](https://github.com/ethereum-optimism/optimism/issues/19673), [#19677](https://github.com/ethereum-optimism/optimism/issues/19677), [#19567](https://github.com/ethereum-optimism/optimism/issues/19567))

### `op-alloy` Compilation and `contracts-bedrock` Test Stability
A compilation issue in `op-alloy` due to conflicting `NetworkWallet<Optimism>` implementation with alloy 1.8 was resolved and closed. ([#19755](https://github.com/ethereum-optimism/optimism/issues/19755)) Additionally, a flaky `contracts-bedrock-tests-upgrade` proptest/fuzz failure, which lacked diagnostic output, was closed due to no further reports. ([#19577](https://github.com/ethereum-optimism/optimism/issues/19577))

### Fault Proof Test Flakiness
The flaky `TestPreinteropFaultProofs_VariedBlockTimes` was closed after a root cause was identified and a fix submitted, addressing issues with `l1BlockWithLocalSafeBlocks()` polling and race conditions during batcher choreography. ([#19804](https://github.com/ethereum-optimism/optimism/issues/19804))

### OPCM Upgrade for SuperDisputeGame
The issue tracking the OPCM upgrade to convert a single chain to `SuperDisputeGame` was closed, indicating the completion of this feature. ([#18992](https://github.com/ethereum-optimism/optimism/issues/18992))

## NEW ISSUES

### Flaky Fault Proof Tests
Multiple new issues were opened to track flaky fault proof tests, specifically `TestInteropFaultProofs_VariedBlockTimes_FasterChainB/SuperRootInvalidIfUnsupportedByL1Data-fpp` ([#19829](https://github.com/ethereum-optimism/optimism/issues/19829)) and `TestInteropFaultProofs_VariedBlockTimes_FasterChainB/FirstChainReachesL1Head-fpp` ([#19828](https://github.com/ethereum-optimism/optimism/issues/19828)). These failures are attributed to the Kona interop program exiting unexpectedly or failing to validate progressed transition states, with a suspected root cause being a missing L1 head check in the Kona no-op transition path.

### CI Test Failures and Timeouts
New issues highlight CI test failures, including a `test-upgrade` proptest failure with no diagnostic output ([#19835](https://github.com/ethereum-optimism/optimism/issues/19835)), `op-deployer/pkg/deployer/pipeline` tests timing out with a panic ([#19834](https://github.com/ethereum-optimism/optimism/issues/19834)), and `TestEthSimulateV1` failing ([#19836](https://github.com/ethereum-optimism/optimism/issues/19836)). These issues were encountered during work on the `superdispute game` migration.

A new issue was opened regarding the supernode's behavior of invalidating/replacing data due to database issues, specifically when the first block in the database isn't the expected one. ([#19841](https://github.com/ethereum-optimism/optimism/issues/19841))

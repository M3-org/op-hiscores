# ethereum-optimism/optimism Daily Update (Mar 31, 2026)
## OVERVIEW 
Today's development focused on migrating to the SuperDisputeGame, enhancing `op-reth` with reorg-aware transaction handling, and improving `kona-host`'s KV store. Several critical bug fixes addressed `op-alloy` conflicts, L2CM upgrade logic, and fault proof race conditions. Documentation was also updated with a security review and deprecation notices.

## KEY TECHNICAL DEVELOPMENTS

### Superchain Dispute Game Migration & Contract Upgrades
A significant feature was added to migrate from legacy `FaultDisputeGame` types to `SuperDisputeGame` types, gated by a DevFeature flag. This also enables individual chain upgrades via `OPContractsManagerV2.upgrade()`, laying groundwork for more flexible Superchain evolution. ([#19253](https://github.com/ethereum-optimism/optimism/pull/19253))

### `op-reth` and `kona-host` Enhancements
`op-reth` now includes a wrapper to drop interop transactions after a reorg, preventing invalid cross-chain message references. ([#19814](https://github.com/ethereum-optimism/optimism/pull/19814)) Additionally, `kona-host` gained a directory-based key-value store compatible with `op-program`'s data format, improving preimage handling. ([#19803](https://github.com/ethereum-optimism/optimism/pull/19803))

### Critical Bug Fixes and Test Stability
Multiple bug fixes were implemented to enhance system stability. This includes resolving `NetworkWallet<Optimism>` conflicts in `op-alloy` ([#19756](https://github.com/ethereum-optimism/optimism/pull/19756)), ensuring `L2ContractsManagerUtils` reverts for non-upgradeable predeploys ([#19798](https://github.com/ethereum-optimism/optimism/pull/19798)), and eliminating race conditions in super fault proof L1 head capture ([#19805](https://github.com/ethereum-optimism/optimism/pull/19805)). Fault proof tests were also made more robust by aligning `endTimestamp` to block boundaries ([#19831](https://github.com/ethereum-optimism/optimism/pull/19831)) and using the `super_atTimestamp` API for optimistic block output roots ([#19825](https://github.com/ethereum-optimism/optimism/pull/19825)).

### Documentation and Chore Updates
Documentation was updated with the Coinbase Kona security review ([#19811](https://github.com/ethereum-optimism/optimism/pull/19811)) and deprecation notices for `op-deployer upgrade` and `manage` commands ([#19838](https://github.com/ethereum-optimism/optimism/pull/19838)). Minor chores included anchoring Semgrep path patterns for v2 compatibility ([#19725](https://github.com/ethereum-optimism/optimism/pull/19725)) and removing dead code related to `interop_message_expiry_window` from `RollupConfig` in Kona ([#19810](https://github.com/ethereum-optimism/optimism/pull/19810)).

## CLOSED ISSUES

### Resolution of Flaky Acceptance Tests
Several intermittently failing acceptance tests related to database handling and proposer behavior have been resolved. `TestPreserveDatabaseOnCLResync`, `TestTruncateDatabaseOnELResync`, and `TestCLUnsafeNotRewoundOnInvalidDuringELSync` are now consistently passing after a period of observation. The `TestProposer` test, which previously hung indefinitely, has also been fixed. ([#19661](https://github.com/ethereum-optimism/optimism/issues/19661), [#19673](https://github.com/ethereum-optimism/optimism/issues/19673))

### Supernode Interop and `op-reth` Flake Fixes
The `TestSupernodeInteropInvalidMessageReplacement` test, which was prone to flakiness, has been stabilized. Additionally, the issue of conflicting `NetworkWallet<Optimism>` implementation in `op-alloy` with alloy 1.8 has been addressed. The feature to implement interop transaction filtering on reorgs in `op-reth` has also been completed. ([#19677](https://github.com/ethereum-optimism/optimism/issues/19677), [#19755](https://github.com/ethereum-optimism/optimism/issues/19755), [#19567](https://github.com/ethereum-optimism/optimism/issues/19567))

### Fault Proof Test Stability
Flaky fault proof tests, specifically `TestPreinteropFaultProofs_VariedBlockTimes`, have been resolved. The underlying cause was identified as a race condition in L1 head capture during batcher choreography, which has now been fixed. ([#19804](https://github.com/ethereum-optimism/optimism/issues/19804))

### OPCM Upgrade and CI Flake Closure
The issue regarding the OPCM upgrade converting a single chain to SuperDisputeGame without resetting withdrawals has been closed, with the first step being a design document. A CI flake related to `contracts-bedrock-tests-upgrade` proptest/fuzz failure, which lacked diagnostic output, was also closed due to lack of actionable information and no recent recurrence. ([#18992](https://github.com/ethereum-optimism/optimism/issues/18992), [#19577](https://github.com/ethereum-optimism/optimism/issues/19577))

## NEW ISSUES

### Flaky Fault Proof Tests
Multiple new flaky test issues have been reported concerning `TestInteropFaultProofs_VariedBlockTimes_FasterChainB` variants. These tests, related to super fault proofs, are intermittently failing with errors indicating unexpected program exits or state mismatches in Kona. The root cause is suspected to be a missing L1 head check in Kona's no-op transition path. ([#19829](https://github.com/ethereum-optimism/optimism/issues/19829), [#19828](https://github.com/ethereum-optimism/optimism/issues/19828))

### CI Test Failures and Timeouts
New issues highlight CI failures, including a `test-upgrade` proptest failure with no diagnostic output ([#19835](https://github.com/ethereum-optimism/optimism/issues/19835)), `op-deployer/pkg/deployer/pipeline` tests timing out with a panic ([#19834](https://github.com/ethereum-optimism/optimism/issues/19834)), and a flaky `TestEthSimulateV1` ([#19836](https://github.com/ethereum-optimism/optimism/issues/19836)). These failures were encountered during work on the SuperDisputeGame migration.

### Supernode Database Invalidation Logic
A new issue points out that the supernode's activity algorithm might incorrectly invalidate or replace data due to database issues if the first block in the database isn't the expected one. ([#19841](https://github.com/ethereum-optimism/optimism/issues/19841))

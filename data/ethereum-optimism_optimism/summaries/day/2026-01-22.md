# ethereum-optimism/optimism Daily Update (Jan 22, 2026)
## OVERVIEW 
Today's development focused on enhancing the `op-deployer` with a new feature flag for forge scripts and improving testing stability. Significant internal refactoring was also completed across `op-challenger`, `op-dispute-mon`, and `op-program` components.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced Deployment with Forge Script Feature Flag
A new feature flag has been added to the `op-deployer` to enable the execution of forge scripts, starting with the already implemented Deplo. This enhancement streamlines the deployment process by integrating forge capabilities. [#18881](https://github.com/ethereum-optimism/optimism/pull/18881)

### Improved Test Stability
The timeout for contracts tests has been increased to prevent flakes, addressing instances where test durations were nearing or exceeding the previous 15-minute limit. This change improves the reliability of the CI/CD pipeline. [#18914](https://github.com/ethereum-optimism/optimism/pull/18914)

### Internal Refactoring for Strict Uint64 Conversion
Across `op-challenger`, `op-dispute-mon`, and `op-program` components, calls to `big.Int.Uint64()` have been replaced with `bigs.Uint64Strict`. This refactoring satisfies new lint checks and enhances the robustness of integer conversions within these critical modules. [#18902](https://github.com/ethereum-optimism/optimism/pull/18902)

## NEWLY OPENED PULL REQUESTS
- A new feature to migrate `op-reth` to the monorepo has been proposed. [#18917](https://github.com/ethereum-optimism/optimism/pull/18917)
- A feature to skip protocol versions deployment when `opcmv2` is enabled has been opened. [#18912](https://github.com/ethereum-optimism/optimism/pull/18912)
- A fix to use enode URI when removing a peer has been submitted. [#18906](https://github.com/ethereum-optimism/optimism/pull/18906)

## CLOSED ISSUES

### Forge Deployer Enhancements Completed
Two issues related to the Forge Deployer have been closed. This includes the conversion of `DeploySuperchain` to use Forge [#17215](https://github.com/ethereum-optimism/optimism/issues/17215) and the creation of a default flag for using Forge in `op-deployer` [#18761](https://github.com/ethereum-optimism/optimism/issues/18761). These closures mark significant progress in integrating Forge into the deployment process.

## NEW ISSUES

### `op-reth` Monorepo Migration Planning
Several new issues outline the next steps for migrating `op-reth` into the monorepo. This includes removing the `reth-trie-common` dependency [#18909](https://github.com/ethereum-optimism/optimism/issues/18909), re-exporting proofs exex in `reth-op` [#18910](https://github.com/ethereum-optimism/optimism/issues/18910), removing the patch section and inter-dependencies on optimism crates [#18916](https://github.com/ethereum-optimism/optimism/issues/18916), migrating example crates [#18918](https://github.com/ethereum-optimism/optimism/issues/18918), and finally removing the `reth` submodule and updating CI [#18919](https://github.com/ethereum-optimism/optimism/issues/18919).

### `op-devstack` and `op-node` Monitoring Improvements
New issues address enhancements for `op-devstack` and monitoring. This includes making `op-reth` proof flags configurable in `op-devstack` [#18908](https://github.com/ethereum-optimism/optimism/issues/18908) and adding supernode support for `op-challenger` in `devstack` [#18911](https://github.com/ethereum-optimism/optimism/issues/18911). Additionally, a request for useful Grafana dashboards to monitor `op-node` components has been opened [#18907](https://github.com/ethereum-optimism/optimism/issues/18907).

## ACTIVE ISSUES

### Withdrawal Proofs and Interoperability
Discussion on [#18517](https://github.com/ethereum-optimism/optimism/issues/18517) highlights the need to update `OptimismPortal2.proveWithdrawalTransaction` to use `IDisputeGame.rootClaim(uint256)` for verifying output root proofs. A recent comment clarifies that the `OptimismPortalInterop` contract should also be updated similarly.

Related to this, [#18615](https://github.com/ethereum-optimism/optimism/issues/18615) discusses updating the `op-chain-ops/cmd/withdrawal` script. The latest comment indicates that implementing this script would be simpler after [#18517](https://github.com/ethereum-optimism/optimism/issues/18517) is completed, as the codepath for proving pre-interop and post-interop withdrawal transactions would become identical.

# ethereum-optimism/optimism Daily Update (Jan 22, 2026)
## OVERVIEW 
Today's development focused on enhancing the `op-deployer` with a new feature flag for forge scripts, improving test stability, and migrating to `Uint64Strict` across several components for stricter type handling.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced Deployment with Forge Scripts
A new feature flag has been added to `op-deployer` to enable the use of forge scripts, starting with the already implemented Deplo. This enhancement aims to integrate forge execution more broadly within the deployment process. ([#18881](https://github.com/ethereum-optimism/optimism/pull/18881))

### Improved Test Stability
The timeout for contracts tests has been increased to prevent flakes, addressing instances where test execution times were approaching or exceeding the previous 15-minute limit. ([#18914](https://github.com/ethereum-optimism/optimism/pull/18914))

### Stricter Integer Handling
Calls to `big.Int.Uint64()` have been replaced with `bigs.Uint64Strict` across `op-challenger`, `op-dispute-mon`, and `op-program` components. This change satisfies new lint checks and ensures more rigorous handling of `uint64` values. ([#18902](https://github.com/ethereum-optimism/optimism/pull/18902))

## NEWLY OPENED PULL REQUESTS
Several new pull requests were opened, including a significant feature to migrate `op-reth` to the monorepo ([#18917](https://github.com/ethereum-optimism/optimism/pull/18917)). Other notable PRs involve supporting `op-validator v6.0.0` ([#18915](https://github.com/ethereum-optimism/optimism/pull/18915)), adding a forge flag to `op-deployer` for bootstrap and apply operations ([#18913](https://github.com/ethereum-optimism/optimism/pull/18913)), and skipping protocol versions deployment when `opcmv2` is enabled ([#18912](https://github.com/ethereum-optimism/optimism/pull/18912)). Additional PRs address using enode URIs for peer removal ([#18906](https://github.com/ethereum-optimism/optimism/pull/18906)), adding test coverage for `MIPS64Memory` ([#18905](https://github.com/ethereum-optimism/optimism/pull/18905)), migrating more components to `Uint64Strict` ([#18904](https://github.com/ethereum-optimism/optimism/pull/18904)), and restricting proposed block numbers to `uint64` in contracts ([#18903](https://github.com/ethereum-optimism/optimism/pull/18903)).

## CLOSED ISSUES

### Forge Deployer Integration
Two issues related to the Forge Deployer have been closed. This includes the conversion of `DeploySuperchain` to use Forge ([#17215](https://github.com/ethereum-optimism/optimism/issues/17215)) and the creation of a default flag for using Forge in `op-deployer` ([#18761](https://github.com/ethereum-optimism/optimism/issues/18761)).

## NEW ISSUES

### Monitoring and Configuration
New issues were opened to discuss the availability of useful Grafana dashboards for monitoring `op-node` components ([#18907](https://github.com/ethereum-optimism/optimism/issues/18907)) and to make `op-reth` proof flags configurable within `op-devstack` ([#18908](https://github.com/ethereum-optimism/optimism/issues/18908)).

### Reth Integration and Refinement
Several issues focus on refining `reth` integration, including replacing the `reth-trie-common` dependency in `reth-optimism-trie` ([#18909](https://github.com/ethereum-optimism/optimism/issues/18909)), re-exporting proofs exex in `reth-op` ([#18910](https://github.com/ethereum-optimism/optimism/issues/18910)), and removing the patch section and `reth` inter-dependencies on optimism crates in `op-reth` once it's migrated to the monorepo ([#18916](https://github.com/ethereum-optimism/optimism/issues/18916)).

### Devstack Enhancements
An issue was created to add supernode support for `op-challenger` within `devstack`, with a focus on making this configurable for gradual migration ([#18911](https://github.com/ethereum-optimism/optimism/issues/18911)).

## ACTIVE ISSUES

### Withdrawal Proofs and Interoperability
Discussions on [#18517](https://github.com/ethereum-optimism/optimism/issues/18517) (contracts: Prove withdrawals using chain-specific root claim) indicate that `OptimismPortalInterop` should also be updated to use the `IDisputeGame.rootClaim(uint256)` interface for verifying output root proofs. This is a dependency for [#18615](https://github.com/ethereum-optimism/optimism/issues/18615) (op-chain-ops: Update prove withdrawals script to use output roots for interop), where it was noted that the script would be significantly simplified once [#18517](https://github.com/ethereum-optimism/optimism/issues/18517) is implemented, as the codepath for proving pre-interop and post-interop withdrawal transactions would become identical. The plan is to implement [#18615](https://github.com/ethereum-optimism/optimism/issues/18615) after [#18517](https://github.com/ethereum-optimism/optimism/issues/18517) is complete.

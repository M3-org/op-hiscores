# ethereum-optimism/optimism Daily Update (May 18, 2026)
## OVERVIEW 
Today's development focused on critical bug fixes in `op-node` and `op-service`, significant refactoring of `SafeDB` for improved performance, and extensive updates to `op-e2e` tests to align with the `op-supernode` migration.

## KEY TECHNICAL DEVELOPMENTS

### Core Node Stability and Transaction Handling
Several bug fixes were implemented to enhance the stability of the `op-node` and improve transaction submission reliability. This includes tolerating `NotFound` errors during `Finalized` lookups in `ELSync` ([#20798](https://github.com/ethereum-optimism/optimism/pull/20798)) and handling `nonce-too-low` errors in the transaction submission retry loop within `txplan` ([#20796](https://github.com/ethereum-optimism/optimism/pull/20796)).

### Supernode Enhancements and Refactoring
The `op-supernode` received updates to log cold-start backfill progress for better visibility ([#20843](https://github.com/ethereum-optimism/optimism/pull/20843)). Additionally, the `SafeDB` logic was refactored to move `L1AtSafeHead` lookups directly into `SafeDB`, optimizing performance by using a single Pebble cursor pass instead of repeated point queries ([#20845](https://github.com/ethereum-optimism/optimism/pull/20845)).

### E2E Testing and Supervisor Migration
Significant work was done to update end-to-end tests, including the deletion of `op-supervisor` action tests ([#20826](https://github.com/ethereum-optimism/optimism/pull/20826)) and replacing `op-supervisor` with `op-supernode` in the `super_test` path ([#20825](https://github.com/ethereum-optimism/optimism/pull/20825)). New acceptance tests were also added for interop startup-rework resync scenarios ([#20824](https://github.com/ethereum-optimism/optimism/pull/20824)).

## ACTIVE ISSUES

### Flaky Test: `TestELSyncSafeRetractedByOffset` ([#20334](https://github.com/ethereum-optimism/optimism/issues/20334))
The discussion on this flaky test continues, with recent comments suggesting that the `OffsetELSafe` configuration might be causing the test to fail by making the "expected head to match: safe" condition unreachable during the preset's baseline sync gate. A contributor noted that if the offset is unconditionally active, the equality target is unreachable, leading to consistent timeouts. This hypothesis is supported by the observation that the `verifier.safe` head lags the `sequencer` by a consistent amount, rather than drifting. Further investigation is proposed to log the delta between `sequencer.safe` and `verifier.safe` at the moment of timeout to confirm if the offset is indeed the blocker.

### `op-e2e/super_test.go` Migration ([#20814](https://github.com/ethereum-optimism/optimism/issues/20814))
The discussion revolves around migrating remaining dispute game tests from `op-e2e/super_test.go` to `op-acceptance-tests` to facilitate the deletion of `op-supervisor`. A recent comment suggests an alternative approach: instead of porting all tests, it might be faster to integrate `op-supernode` into `op-e2e` directly in place of `op-supervisor`. This would avoid the time-consuming process of migrating tests while still achieving the goal of removing `op-supervisor`.

# ethereum-optimism/optimism Daily Update (Apr 6, 2026)
## OVERVIEW 
The day saw significant progress in fixing bugs related to Kona's interop host and acceptance tests, alongside refactoring efforts to remove native rollup-boost support. Several new pull requests were opened, focusing on flashblocks tests, interop validation, and error handling.

## KEY TECHNICAL DEVELOPMENTS

### Kona Interop Host and Build Fixes
Several bug fixes were implemented to enhance the stability and determinism of the Kona interop host. This included replacing `HashMap` with `BTreeMap` for deterministic JSON serialization in the interop host to prevent VM state divergence ([#19906](https://github.com/ethereum-optimism/optimism/pull/19906)). Additionally, the `kona-host` was added to the `build-rust-release` target in the `justfile` to ensure proper compilation within the acceptance test dependency chain ([#19931](https://github.com/ethereum-optimism/optimism/pull/19931)).

### Acceptance Test Improvements
The `TestInteropFaultProofs_InvalidBlock` acceptance test was unskipped ([#19932](https://github.com/ethereum-optimism/optimism/pull/19932)) following the merge of prerequisite PRs, indicating progress in fault proof validation. Furthermore, flashblocks tests were refactored to introduce a reusable `FlashblockClient` for improved handling of WebSocket connections and `Flashblock` values ([#19942](https://github.com/ethereum-optimism/optimism/pull/19942)).

### Rollup-Boost Removal and Documentation Updates
Native `rollup-boost` support was removed from the Kona workspace, with Engine API v3/v4 calls now routed directly to the L2 execution engine ([#19900](https://github.com/ethereum-optimism/optimism/pull/19900)). This streamlines the architecture by eliminating external crate dependencies. Documentation references to the old docs repository were also updated across various files ([#19943](https://github.com/ethereum-optimism/optimism/pull/19943)).

## CLOSED ISSUES

### Interop and Supernode Enhancements
Several issues related to the `op-supernode` and interop implementation were closed, indicating significant progress in this area. This includes the core `Interop Implementation` ([#18741](https://github.com/ethereum-optimism/optimism/issues/18741)) and `Interop Algo` ([#18743](https://github.com/ethereum-optimism/optimism/issues/18743)). The ability to `Invalidate Block` within the supernode ([#18944](https://github.com/ethereum-optimism/optimism/issues/18944)) was also addressed.

### L1 Reorg Handling in Supernode
Issues concerning L1 reorgs within the `op-supernode` were resolved, with comments indicating that these are now handled by WAL (Write-Ahead Logging) implementation. This includes `Clear Verifications and Denied Blocks on L1 Reorg` ([#19245](https://github.com/ethereum-optimism/optimism/issues/19245)), `Prune Interop Database on L1 Reorg` ([#19287](https://github.com/ethereum-optimism/optimism/issues/19287)), and `Prune Denylist on L1 Reorg and Alert` ([#19289](https://github.com/ethereum-optimism/optimism/issues/19289)).

### Flaky Test and Interop Testing
A flaky test, `TestSuperCannonStepWithPreimage_nonExistingPreimage` ([#19892](https://github.com/ethereum-optimism/optimism/issues/19892)), was closed after a deep investigation revealed resource contention in CI as the root cause. Additionally, a test for invalid executing messages on the interop devnet ([#19566](https://github.com/ethereum-optimism/optimism/issues/19566)) was closed, confirming the correct detection and invalidation path.

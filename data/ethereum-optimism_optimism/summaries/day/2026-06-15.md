# ethereum-optimism/optimism Daily Update (Jun 15, 2026)
## OVERVIEW 
Today's development focused on critical bug fixes in `op-reth` and contracts, enhancing documentation, and centralizing hardfork mappings in the Rust stack. Key improvements include fixing PostExec transaction reproduction and clearing proxy admin owner nonces in L2 genesis.

## KEY TECHNICAL DEVELOPMENTS

### `op-reth` Stability and Hardfork Management
Significant progress was made in `op-reth` with a fix for reproducing trailing SDM PostExec transactions during derived block rebuilding, ensuring consensus requirements are met ([#21321](https://github.com/ethereum-optimism/optimism/pull/21321)). Additionally, a new upstream trait for `ValidatingPool` was implemented in `OpPool`, adding validation capabilities ([#21378](https://github.com/ethereum-optimism/optimism/pull/21378)). The Rust stack also saw a centralization of the OP fork to implied L1 fork mapping, improving consistency across the codebase ([#21368](https://github.com/ethereum-optimism/optimism/pull/21368)).

### Contract and Genesis Fixes
A critical bug in contracts was addressed by clearing residual proxy admin owner nonces in L2 genesis, preventing unintended nonce bumps during `setPredeployImplementations` calls ([#21343](https://github.com/ethereum-optimism/optimism/pull/21343)).

### Documentation and Release Updates
Documentation was enhanced with a warning for `op-reth` operators regarding a Superchain Registry loading bug on OP Sepolia ([#21381](https://github.com/ethereum-optimism/optimism/pull/21381)). The `proxyd` v4.28.1 release was added to the release notes ([#21373](https://github.com/ethereum-optimism/optimism/pull/21373)), and a new section was added to the Rust development guide noting the canonical OP to L1 fork mapping ([#21384](https://github.com/ethereum-optimism/optimism/pull/21384)).

# ethereum-optimism/optimism Daily Update (Apr 17, 2026)
## OVERVIEW 
Today's development focused on significant feature additions to op-reth, including a block builder failsafe and EIP-7951 support, alongside critical bug fixes in flashblocks and L2ContractsManager. Refactoring efforts removed revenue sharing code, and CI improvements were implemented.

## KEY TECHNICAL DEVELOPMENTS

### Core Protocol Enhancements & Hardfork Preparation
Significant features were added to `op-reth`, including a block builder failsafe and integration with the `op-interop-filter` for enhanced testing and stability ([#20001](https://github.com/ethereum-optimism/optimism/pull/20001)). Support for EIP-7951 (P256VERIFY Osaka precompile) was also integrated into `op-reth`, with updated gas costs for the Karst activation ([#20071](https://github.com/ethereum-optimism/optimism/pull/20071)). Additionally, NUT bundle types and deposit transaction conversion logic were added to `kona-hardforks` to facilitate future network upgrades ([#20062](https://github.com/ethereum-optimism/optimism/pull/20062)).

### Stability and Reliability Improvements
Several critical bug fixes were implemented to improve system stability. The `TestFlashblocksStream` flakiness was addressed by fixing compounding bugs that caused hangs and misleading errors under CI load ([#19976](https://github.com/ethereum-optimism/optimism/pull/19976)). The `op-supernode` now allows for configurable L1 HTTP poll intervals, reducing unnecessary RPC requests ([#20093](https://github.com/ethereum-optimism/optimism/pull/20093)). A follow-up fix for `L2ContractsManager` added a missing `ProxyAdminOwnedBase` guard and per-predeploy atomicity regression tests ([#20108](https://github.com/ethereum-optimism/optimism/pull/20108)).

### Codebase Refinement and CI/CD Optimization
The codebase underwent significant refactoring with the complete removal of all revenue sharing code from the monorepo, as it is no longer needed ([#19750](https://github.com/ethereum-optimism/optimism/pull/19750)). CI workflows were optimized by stopping redundant contract tests in both main and contracts-feature-tests ([#20132](https://github.com/ethereum-optimism/optimism/pull/20132)) and by implementing retries for `apt-get update` to mitigate transient mirror sync failures ([#20129](https://github.com/ethereum-optimism/optimism/pull/20129)).

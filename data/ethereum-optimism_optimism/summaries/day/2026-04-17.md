# ethereum-optimism/optimism Daily Update (Apr 17, 2026)
## OVERVIEW 
Today's development focused on enhancing `op-reth` with failsafe mechanisms and EIP-7951 support, refining hardfork processes with NUT bundles, and significant cleanup in contracts and CI. Several critical bugs were addressed, improving stability and efficiency across the ecosystem.

## KEY TECHNICAL DEVELOPMENTS

### `op-reth` Enhancements and Hardfork Preparations
`op-reth` saw significant updates, including the implementation of a block builder failsafe and integration with the `op-interop-filter` for robust acceptance testing ([#20001](https://github.com/ethereum-optimism/optimism/pull/20001)). Additionally, support for the EIP-7951 P256VERIFY Osaka precompile was added, along with corresponding tests to ensure correct gas cost increases at Karst activation ([#20071](https://github.com/ethereum-optimism/optimism/pull/20071)). The `kona-hardforks` also received new NUT bundle types and deposit transaction conversion logic, streamlining future hardfork definitions ([#20062](https://github.com/ethereum-optimism/optimism/pull/20062)).

### Contract Stability and Refactoring
Several critical fixes and refactorings were applied to the contracts. A bug in `VerifyOPCM` was addressed to skip ZKDisputeGame when the feature is disabled, preventing silent failures in `contracts-bedrock-tests-develop` ([#20140](https://github.com/ethereum-optimism/optimism/pull/20140)). A follow-up fix for `l2cm` added a missing `ProxyAdminOwnedBase` guard on `OptimismMintableERC20Factory.initialize()` and introduced atomicity regression tests ([#20108](https://github.com/ethereum-optimism/optimism/pull/20108)). Furthermore, all revenue sharing code was removed from the monorepo, simplifying the codebase ([#19750](https://github.com/ethereum-optimism/optimism/pull/19750)). Unused `SchemaResolver` and seven unreferenced interfaces were also removed, reducing code bloat ([#20142](https://github.com/ethereum-optimism/optimism/pull/20142), [#20141](https://github.com/ethereum-optimism/optimism/pull/20141)).

### CI/CD and Testing Improvements
CI workflows were optimized to prevent redundant contract tests ([#20132](https://github.com/ethereum-optimism/optimism/pull/20132)) and to stabilize flaky tests like `TestFlashblocksStream` by addressing underlying bugs related to sequencer EL block production and resource contention ([#19976](https://github.com/ethereum-optimism/optimism/pull/19976)). CI was also updated to retry `apt-get update` on transient mirror sync failures ([#20129](https://github.com/ethereum-optimism/optimism/pull/20129)) and to bump the factory workflow to a Node.js 24-compatible version ([#20126](https://github.com/ethereum-optimism/optimism/pull/20126)). A new `ci-base-clang` Docker image was added and registered for factory builds, enhancing build environments ([#20121](https://github.com/ethereum-optimism/optimism/pull/20121)).

## CLOSED ISSUES

### Flaky Test Stabilization
Several issues related to flaky acceptance tests were closed, indicating improved test suite reliability. This includes `TestFlashblocksStream` ([#19883](https://github.com/ethereum-optimism/optimism/issues/19883)), `base/TestTransfer` ([#18081](https://github.com/ethereum-optimism/optimism/issues/18081)), and `ecotone/TestFees` ([#18082](https://github.com/ethereum-optimism/optimism/issues/18082)). Investigations into why Burst tests took too long with many EOAs were also resolved ([#16448](https://github.com/ethereum-optimism/optimism/issues/16448)), alongside addressing instances where onchain balance depleted before offchain budget in load tests ([#16536](https://github.com/ethereum-optimism/optimism/issues/16536)).

### `op-reth` Interoperability and Failsafe Implementation
The issue tracking the implementation of the interop tx pool filter and reorg eviction in `op-reth` was closed ([#19411](https://github.com/ethereum-optimism/optimism/issues/19411)), signifying the successful integration of these critical features for enhanced transaction handling and network stability.

### Contract Management and Cleanup
Key issues related to contract management and cleanup were resolved. This includes adding a missing access control guard on `OptimismMintableERC20Factory` ([#20080](https://github.com/ethereum-optimism/optimism/issues/20080)) and reviewing `L2ContractsManager` for error swallowing patterns ([#19392](https://github.com/ethereum-optimism/optimism/issues/19392)). The removal of revenue sharing features from `L2ContractsManager` was also completed ([#19600](https://github.com/ethereum-optimism/optimism/issues/19600)).

### CI/CD and Development Environment Improvements
Improvements to the CI/CD pipeline and development environment were finalized. This includes registering `ci-base-clang` in `docker-images.json` for factory builds ([#20119](https://github.com/ethereum-optimism/optimism/issues/20119)). Several issues related to `op-devstack` were closed, focusing on auditing retries and timeouts ([#18061](https://github.com/ethereum-optimism/optimism/issues/18061)) and fixing acceptance test flake root-causes ([#18060](https://github.com/ethereum-optimism/optimism/issues/18060)).

# ethereum-optimism/optimism Daily Update (Aug 11, 2026)
## OVERVIEW 
Today's development focused on enhancing the Optimism ecosystem with significant updates to Kona's engine and gossip protocols, improving op-deployer's capabilities, and expanding acceptance tests for future L1 forks. Several long-standing issues were closed, particularly around SDM devnet rollout and op-reth configuration.

## KEY TECHNICAL DEVELOPMENTS

### Kona Engine and Gossip Protocol Enhancements
Significant work was done to refine Kona's engine and gossip protocols. This included moving signed gossip framing and SSZ codecs to private wire types, authenticating payload bytes before decoding for improved security, and reusing inserted block information to optimize sealing and canonicalizing payloads. Additionally, `OpExecutionPayloadEnvelope` was introduced to centralize V1-V4 execution payload abstractions and structurally encode fork invariants.
[#22305](https://github.com/ethereum-optimism/optimism/pull/22305), [#22306](https://github.com/ethereum-optimism/optimism/pull/22306), [#22304](https://github.com/ethereum-optimism/optimism/pull/22304)

### Op-Deployer Improvements for ZK and PCD
The op-deployer received updates to enhance its functionality, particularly for Zero-Knowledge (ZK) deployments and the PCD (Prepare, Continue, Deploy) process. This involved selecting the release SP1 verifier for ZK-enabled applications and implementing PCD record implementations and a game mode to address gaps in the prepare stage, ensuring `state.ImplementationsDeployment` is populated.
[#22367](https://github.com/ethereum-optimism/optimism/pull/22367), [#22337](https://github.com/ethereum-optimism/optimism/pull/22337)

### Expanded Acceptance Testing and Protocol Hardening
Acceptance tests were expanded to include matrix tests across future L1 forks, incorporating L1 fork configuration and blob schedules through Glamsterdam, and adding required Engine API and RPC-header support. Furthermore, deposit gas accounting was hardened against upstream changes in `alloy-op-evm` and `kona` to ensure deposit transactions are not subject to EIP-7825's per-transaction gas limit cap.
[#21920](https://github.com/ethereum-optimism/optimism/pull/21920), [#22372](https://github.com/ethereum-optimism/optimism/pull/22372)

## CLOSED ISSUES

### SDM Devnet Rollout and Benchmarking Completed
The rollout of the SDM devnet (`sdm-net-0`) has been successfully completed, with SDM active and verified. This included running a continuous SDM-exercising workload and verifying SDM dashboards in OPE Grafana. Baseline benchmarks were performed, showing significant gas refunds with SDM enabled and negligible overhead for payload building and execution.
[#21273](https://github.com/ethereum-optimism/optimism/issues/21273), [#22343](https://github.com/ethereum-optimism/optimism/issues/22343), [#22345](https://github.com/ethereum-optimism/optimism/issues/22345), [#22344](https://github.com/ethereum-optimism/optimism/issues/22344)

### Op-Reth Configuration and Documentation Updates
Issues related to `op-reth` configuration and documentation were closed. This included addressing missing hardfork override flags for superchain nodes and updating documentation that incorrectly referenced Base-related parameters for `op-reth` and `op-node` startup examples.
[#20224](https://github.com/ethereum-optimism/optimism/issues/20224), [#20597](https://github.com/ethereum-optimism/optimism/issues/20597)

### Acceptance Test and Deployer Gaps Addressed
Several issues concerning acceptance tests and the PCD deployer were resolved. This involved ensuring all tests run against the latest L1 fork if relevant, populating `state.ImplementationsDeployment` in the PCD process, and preventing deployments with incorrect game families from failing at late stages.
[#21221](https://github.com/ethereum-optimism/optimism/issues/21221), [#22333](https://github.com/ethereum-optimism/optimism/issues/22333), [#22334](https://github.com/ethereum-optimism/optimism/issues/22334)

### Op-Supernode Invalidation Recovery Fixed
An issue where `op-supernode` invalidation recovery could repeatedly reset when unsafe sync resumed before EL convergence was closed, indicating that the loop is now prevented by other fixes.
[#21948](https://github.com/ethereum-optimism/optimism/issues/21948)

## ACTIVE ISSUES

### SDM Coverage in `rust/kona/tests/proofs`
Discussion on [#21344](https://github.com/ethereum-optimism/optimism/issues/21344) regarding adding SDM coverage in `rust/kona/tests/proofs` concluded that existing coverage for invalid PostExec transactions and deposits-only fallback is already present in other tests. The specific scenario of an invalid PostExec payload triggering the deposits-only fallback via real SDM payload validation is not currently testable in `rust/kona/tests/proofs` due to the `op-geth` action-test engine not supporting SDM execution. The suggestion is to close the issue as the components are individually tested, and the combined scenario is dependent on a future engine swap to `op-reth`.

# ethereum-optimism/optimism Daily Update (Jan 21, 2026)
## OVERVIEW 
Today's development focused on refining the OPCMv2 by removing an unnecessary instruction, enhancing CI stability, and improving op-node configurability. Several test improvements were also implemented, alongside the removal of legacy L2OO support.

## KEY TECHNICAL DEVELOPMENTS

### OPCMv2 Refinements and Protocol Adjustments
A key feature update involved removing the CGT instruction from OPCMv2, streamlining the contract manager as it's no longer needed with U18 ([#18878](https://github.com/ethereum-optimism/optimism/pull/18878)). Additionally, remnants of L2OO support were deleted from the op-proposer, further cleaning up the codebase ([#18884](https://github.com/ethereum-optimism/optimism/pull/18884)).

### Enhanced Node Configuration and Stability
The op-node now allows for configurable sequencer sealing duration, providing greater flexibility for different setups ([#18777](https://github.com/ethereum-optimism/optimism/pull/18777)). A new `SupervisorEnabled` configuration was also added to the op-node, enhancing its operational control ([#18808](https://github.com/ethereum-optimism/optimism/pull/18808)).

### CI/CD and Testing Improvements
A critical fix was implemented to address broken tag creation in CircleCI releases, ensuring smoother continuous integration processes ([#18883](https://github.com/ethereum-optimism/optimism/pull/18883)). Testing efforts included an update to op-acceptor v3.8.2 ([#18890](https://github.com/ethereum-optimism/optimism/pull/18890)), documentation on using the flake-shake gate ([#18889](https://github.com/ethereum-optimism/optimism/pull/18889)), and temporarily skipping a flaky batcher test to investigate a "nonce too high error" ([#18887](https://github.com/ethereum-optimism/optimism/pull/18887)).

Other PRs include standardizing OPCMv2 version checks ([#18893](https://github.com/ethereum-optimism/optimism/pull/18893)), fixing mgas calculation ([#18892](https://github.com/ethereum-optimism/optimism/pull/18892)), deprecating a Kurtosis CI job ([#18891](https://github.com/ethereum-optimism/optimism/pull/18891)), using a bufferSize parameter in `NewFinder` for `op-interop-mon` ([#18888](https://github.com/ethereum-optimism/optimism/pull/18888)), and adding a Quick Start section to the README ([#18885](https://github.com/ethereum-optimism/optimism/pull/18885)).

## CLOSED ISSUES

### OPCM Input Streamlining
The issue regarding the removal of `proxyAdmin` input from the `OpChainConfig` struct for OPCM.upgrade() was closed ([#16728](https://github.com/ethereum-optimism/optimism/issues/16728)). This field is no longer required as it can be derived from `systemConfigProxy.proxyAdmin()`.

## NEW ISSUES

### Batcher Test Flakiness
A new issue was opened to re-enable the `TestBatcherFullChannelsAfterDowntime` test for the batcher ([#18886](https://github.com/ethereum-optimism/optimism/issues/18886)). This test is currently disabled due to flakiness caused by a "nonce too high error."

## ACTIVE ISSUES

### OPCMv2 Custom Gas Token Override
The issue concerning the removal of the `SystemConfig::isCustomGasToken` override allowance for OPCMv2 ([#18502](https://github.com/ethereum-optimism/optimism/issues/18502)) has been addressed. The latest comment confirms that this issue is fixed by PR [#18878](https://github.com/ethereum-optimism/optimism/pull/18878), which removed the CGT instruction from OPCMv2. This override was temporarily needed until U18 shipped, making `isCustomGasToken` available on the SystemConfig.

# ethereum-optimism/optimism Daily Update (Jan 26, 2026)
## OVERVIEW 
Today's development focused on significant monorepo migrations for `op-alloy` and `op-hardforks`, alongside critical bug fixes for the superchain registry and `op-node`'s yParity calculation. Several new pull requests were opened, addressing dispute game interfaces and test coverage.

## KEY TECHNICAL DEVELOPMENTS

### Monorepo Migration for Rust Components
The `op-alloy` and `op-hardforks` repositories have been successfully upstreamed into the main monorepo as part of the ongoing Rust migration efforts. This consolidates development and streamlines the build process for these critical components.
- [#18811](https://github.com/ethereum-optimism/optimism/pull/18811)
- [#18825](https://github.com/ethereum-optimism/optimism/pull/18825)

### Critical Bug Fixes for Stability and Safety
Improvements were made to the superchain registry's retry and caching mechanisms to enhance reliability and prevent CI flakes. A significant bug in `op-node`'s yParity calculation was fixed, switching to `Uint64Strict` to prevent `uint64` overflows and improve safety.
- [#18933](https://github.com/ethereum-optimism/optimism/pull/18933)
- [#18921](https://github.com/ethereum-optimism/optimism/pull/18921)

The issue tracking acceptance tests against the first Glamsterdam devnet (bal-devnet-1) has been closed. Challenges included unsupported custom L1 setup, inconsistent RPC responses, and premature devnet failure due to misconfiguration. Next steps involve addressing L1 setup support.

## ACTIVE ISSUES

### `op-deployer`: Transaction Gas Limit Too High
The issue regarding `op-deployer:v0.2.6` failing to deploy contracts due to "transaction gas limit too high" is still active. The problem stems from the Fusaka hardfork enforcing a transaction gas limit of 16,777,216. The latest comment asks if the issue is fixed and which `op-deployer` version to use for alt-da.
- [#17912](https://github.com/ethereum-optimism/optimism/issues/17912)

### `op-batcher`: Staying in Sync with `op-node` Rollup Config
Discussion continues on how `op-batcher` can stay in sync with `op-node`'s rollup configuration. The batcher currently only fetches the config at startup. Recent comments suggest making the operator explicitly provide the rollup config to the batcher or restarting the batcher on critical errors to force a config reload.
- [#18178](https://github.com/ethereum-optimism/optimism/issues/18178)

### Sequencer-Defined Metering Design Doc
The scope of this issue has been expanded to include an initial Proof of Concept (PoC) for Sequencer-Defined Metering, which is currently blocking the design document. The initial devnet deployment is planned for January 30, 2026, after which the design can be evaluated and basic benchmarking performed.
- [#360](https://github.com/ethereum-optimism/optimism/issues/360)

# ethereum-optimism/optimism Daily Update (Jan 26, 2026)
## OVERVIEW 
Today's development focused on migrating key components like `op-alloy` and `op-hardforks` to the monorepo, alongside critical bug fixes for the superchain registry and `op-node`'s yParity calculation.

## KEY TECHNICAL DEVELOPMENTS

### Monorepo Migration for Core Components
Significant progress was made in consolidating core Optimism components into the monorepo. This includes the upstreaming of `op-alloy`, a crucial part of the Rust migration effort ([#18811](https://github.com/ethereum-optimism/optimism/pull/18811)), and the migration of `op-hardforks` from `alloy-rs/hardforks` ([#18825](https://github.com/ethereum-optimism/optimism/pull/18825)).

### Enhanced Stability and Safety
Bug fixes were implemented to improve the robustness of the superchain registry with better retries and caching mechanisms, preventing CI flakes ([#18933](https://github.com/ethereum-optimism/optimism/pull/18933)). Additionally, a critical fix addressed a `uint64` overflow in `op-node`'s yParity calculation by switching to `Uint64Strict` for increased safety ([#18921](https://github.com/ethereum-optimism/optimism/pull/18921)).

## CLOSED ISSUES

### Monorepo Migration Progress
The tracking issue for migrating `kona` and `op-reth` crates into the monorepo has been closed, indicating successful completion of this migration phase ([#18575](https://github.com/ethereum-optimism/optimism/issues/18575)).

### Acceptance Test Dry Run Conclusion
The issue concerning running acceptance tests against the first glamsterdam devnet (bal-devnet-1) has been closed. Challenges were encountered, including unsupported custom L1 setup, inconsistent RPC responses, and premature devnet failure due to misconfiguration. Next steps involve addressing these issues, particularly supporting custom L1 setup ([#18755](https://github.com/ethereum-optimism/optimism/issues/18755)).

### Gas Configuration Guide Published
A guide on how to change gas config values on the system config post-Holocene has been added to the documentation, resolving the need for this guide ([#1944](https://github.com/ethereum-optimism/optimism/issues/1944)).

## NEW ISSUES

### Hardfork Validation Concerns
An investigation is needed into `OpChainHardforks` fork list validation, specifically regarding potential issues with `OpChainHardforks::new` storing arbitrary `(OpHardfork, ForkCondition)` lists, as flagged by a security review ([#18941](https://github.com/ethereum-optimism/optimism/issues/18941)).

### OPCM v2 Support Expansion
There is a need to extend OPCM v2 support to packages beyond `op-deployer`, as current work in `op-deployer` impacts other components that require updates ([#18942](https://github.com/ethereum-optimism/optimism/issues/18942)).

### Dispute Game Interface Refinement
The `AnchorStateRegistry` currently assumes games implement `IFaultDisputeGame`, which is no longer true with interop and ZK. The issue proposes ensuring `AnchorStateRegistry` only uses `IDisputeGame` and adding necessary methods ([#18943](https://github.com/ethereum-optimism/optimism/issues/18943)).

### Supernode Block Invalidation
A new feature is required for `op-supernode` to invalidate blocks, involving a denylist in the Chain Container with DB persistence and a mechanism for verifiers to call `invalidate block` ([#18944](https://github.com/ethereum-optimism/optimism/issues/18944)).

## ACTIVE ISSUES

### op-deployer: "transaction gas limit too high"
Discussion continues on the `op-deployer` issue where transactions fail due to "transaction gas limit too high" ([#17912](https://github.com/ethereum-optimism/optimism/issues/17912)). The latest comment from @RISHABHAGRAWALZRA asks if the issue is fixed and which `op-deployer` version to use for alt-da. Previously, @sbvegan confirmed that the Fusaka hardfork enforces a transaction gas limit, requiring transactions to be broken down or optimized.

### op-batcher: stay in sync with op-node rollup config
The issue of `op-batcher` not updating its rollup configuration after initial startup is being actively discussed ([#18178](https://github.com/ethereum-optimism/optimism/issues/18178)). @geoknee suggested treating an outdated config as a critical error and restarting the batcher, allowing it to reload the configuration. Earlier, @sebastianst proposed making the operator explicitly provide the rollup config to the batcher, especially for non-Superchain Registry chains, to ensure consistency. @joshklop agreed with this approach, noting it avoids unnecessary concurrency.

### Add Sequencer-Defined Metering Design Doc
The scope of this issue has been expanded to include an initial Proof of Concept (PoC) for Sequencer-Defined Metering, as it is currently blocking the design document ([#360](https://github.com/ethereum-optimism/optimism/issues/360)). The initial devnet deployment is planned for January 30, 2026, after which the design can be evaluated and basic benchmarking performed.

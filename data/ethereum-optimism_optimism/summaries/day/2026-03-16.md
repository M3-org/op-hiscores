# ethereum-optimism/optimism Daily Update (Mar 16, 2026)

## OVERVIEW
Today's development focused on critical bug fixes across various components, including staking, supernode synchronization, and interop filtering. Significant refactoring efforts were also made to enhance consistency and maintainability.

## KEY TECHNICAL DEVELOPMENTS

### Core Bug Fixes and Stability Improvements
Several critical bugs were addressed to improve the stability and reliability of the Optimism ecosystem. This includes fixing misleading error information in `op-alt-da` ([#19276](https://github.com/ethereum-optimism/optimism/pull/19276)), resolving issues with staking audit fixes ([#19449](https://github.com/ethereum-optimism/optimism/pull/19449)), and correcting `op-supernode` errors on uninitialized chain sync status ([#19543](https://github.com/ethereum-optimism/optimism/pull/19543)). The `op-interop-filter` was also updated to handle zero start timestamps in the lockstep validator ([#19541](https://github.com/ethereum-optimism/optimism/pull/19541)).

### CI/CD and Build Process Enhancements
Improvements were made to the continuous integration and deployment (CI/CD) pipeline. This involved fixing CI issues by installing `just` via `mise` in GitHub Actions `docker-build-prep` ([#19560](https://github.com/ethereum-optimism/optimism/pull/19560)) and replacing stale `make` calls with `just` in CI, Dockerfile, and Go errors ([#19526](https://github.com/ethereum-optimism/optimism/pull/19526)).

### Interoperability and Supernode Refactoring
Significant work was done to enhance interoperability and the supernode's consistency guarantees. This included refactoring the supernode interop activity around a single persisted transition model for strong consistency ([#19505](https://github.com/ethereum-optimism/optimism/pull/19505)). Additionally, `op-devstack` was updated to support `op-rbuilder` runtime ruleset updates ([#19562](https://github.com/ethereum-optimism/optimism/pull/19562)).

### Contract Refactoring and Test Improvements
A previous refactoring that caused CI issues was reverted ([#19555](https://github.com/ethereum-optimism/optimism/pull/19555)). Test cases were also improved by removing duplicate `require.NoError` calls ([#18861](https://github.com/ethereum-optimism/optimism/pull/18861)).

## NEWLY OPENED PULL REQUESTS
- **Contract Features and Fixes**: A new feature to add `ProxyAdminOwnedBase` to L2 proxied contracts with `initialize()` was proposed ([#19564](https://github.com/ethereum-optimism/optimism/pull/19564)). A fix for `op-devstack` to add a 5m timeout to transactions in `GameHelper` was also opened ([#19556](https://github.com/ethereum-optimism/optimism/pull/19556)).
- **Supernode Stability**: A fix for `op-supernode` was opened to pause all chains before rewinding on invalid messages ([#19558](https://github.com/ethereum-optimism/optimism/pull/19558)).
- **Test Coverage**: An improvement to `LegacyMintableERC20` test coverage and quality was submitted ([#19557](https://github.com/ethereum-optimism/optimism/pull/19557)).

## ACTIVE ISSUES

### `op-reth` Memory Leak and Sync Stalls ([#19212](https://github.com/ethereum-optimism/optimism/issues/19212), [#19532](https://github.com/ethereum-optimism/optimism/issues/19532))
Discussions continue regarding `op-reth`'s database read transaction memory leak and recurring state root mismatch issues. A user reported experiencing the memory leak on World Chain v1.10.1, causing nodes to go down. Another user confirmed the issue on custom chains like Manta Pacific. For the state root mismatch, it was suggested that Base has forked the OP Stack and users should check their latest release or open an issue with Base directly if it's a Base-specific problem.

### `op-supernode` Acceptance Tests ([#19403](https://github.com/ethereum-optimism/optimism/issues/19403))
There's an ongoing discussion about reinstating `interop/activation/...` tests for `op-supernode`. It was noted that the test setup/teardown code itself can be problematic, causing hangs when tests fail. A useful existing test in `op-supernode/supernode/shutdown_test.go` was highlighted as a potential extension point.

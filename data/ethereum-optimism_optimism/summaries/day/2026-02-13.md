# ethereum-optimism/optimism Daily Update (Feb 13, 2026)

## OVERVIEW
Today's development focused on enhancing L2 deployment mechanisms, streamlining Rust crate releases, and improving fault proof testing. Significant progress was made in unifying Rust documentation and optimizing Kona prestate builds.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced L2 Deployment and Rust Release Process
A Conditional L2 Deployer was added to enable non-reverting deterministic deployments during network upgrades, even with address collisions [#18864](https://github.com/ethereum-optimism/optimism/pull/18864). Additionally, a new release process for Rust crates was set up, including tag classification and a `publish-crates` CI job [#19155](https://github.com/ethereum-optimism/optimism/pull/19155).

### Improved Fault Proof and Interoperability Testing
Acceptance tests were introduced to replicate the `TestInteropFaultProofs` action test scenario within a supernode devstack, and the Kona prestate build script was restored for easier local development [#19163](https://github.com/ethereum-optimism/optimism/pull/19163). A coordinated interop pause mechanism was also added to the DSL for more precise acceptance testing [#19179](https://github.com/ethereum-optimism/optimism/pull/19179).

### Rust Ecosystem Refinements
The documentation for Kona, op-reth, and op-alloy was unified, and repository links were updated [#19101](https://github.com/ethereum-optimism/optimism/pull/19101). Furthermore, Kona now builds cannon from local monorepo source instead of cloning a pinned tag, optimizing the prestate build process [#19183](https://github.com/ethereum-optimism/optimism/pull/19183).

## CLOSED ISSUES

### Kona Prestate Build Optimization
The issue regarding building Kona prestates with the current version of cannon instead of a hard-coded tag has been resolved [#18965](https://github.com/ethereum-optimism/optimism/issues/18965). This change aligns Kona prestate builds with op-program prestates, utilizing the latest cannon version.

## NEW ISSUES

### Internal Bug Reports and Naming Conventions
An investigation into three internal bug reports has been initiated [#19185](https://github.com/ethereum-optimism/optimism/issues/19185). Additionally, a proposal to rename `CrossSafe` to `VerifiedSafe` in `op-node` has been raised for better clarity [#19187](https://github.com/ethereum-optimism/optimism/issues/19187).

A new issue addresses the need for Supernode Finalized Label SuperAuthorization, requiring additional rules for block finalization beyond the CL's current process [#19188](https://github.com/ethereum-optimism/optimism/issues/19188).

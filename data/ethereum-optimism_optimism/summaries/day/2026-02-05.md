# ethereum-optimism/optimism Daily Update (Feb 5, 2026)
## OVERVIEW 
The day saw significant bug fixes across contract deployments and the op-program, alongside enhancements in testing for OptimismMintableERC721. Interoperability and supernode validation also received attention with new features and acceptance tests.

## KEY TECHNICAL DEVELOPMENTS

### Contract Security and Deployment Improvements
Several critical bug fixes were implemented to enhance the security and reliability of contract deployments. This includes addressing gaps in `VerifyOPCM` to prevent variable manipulation ([#19073](https://github.com/ethereum-optimism/optimism/pull/19073)), improving the `SaferSafes` interface and deployment script ([#19067](https://github.com/ethereum-optimism/optimism/pull/19067)), and refining `SuperchainConfig` comments and test refactoring ([#19065](https://github.com/ethereum-optimism/optimism/pull/19065)).

### Enhanced Testing and Interoperability Validation
Test coverage was significantly boosted with fuzz tests for `OptimismMintableERC721` to improve robustness ([#19094](https://github.com/ethereum-optimism/optimism/pull/19094)). Additionally, new acceptance tests were added to verify chain interoperability with Kona proofs, ensuring successful validation of claims by the fault proof program ([#19078](https://github.com/ethereum-optimism/optimism/pull/19078)).

### Supernode and Program Reproducibility Fixes
A crucial fix was applied to the `op-program` to ensure reproducibility by removing the 'v' prefix from the short version, aligning it with standard prestate files ([#19090](https://github.com/ethereum-optimism/optimism/pull/19090)). The `op-supernode` also saw work on interop message validation ([#19051](https://github.com/ethereum-optimism/optimism/pull/19051)) and the Blob Tip Oracle was converted from subscription to polling for broader compatibility ([#19095](https://github.com/ethereum-optimism/optimism/pull/19095)).

## NEWLY OPENED PULL REQUESTS
Ten new pull requests were opened today, focusing on various aspects of the Optimism ecosystem. Key themes include implementing alloy traits for OP types ([#19104](https://github.com/ethereum-optimism/optimism/pull/19104), [#19103](https://github.com/ethereum-optimism/optimism/pull/19103)), unifying Rust documentation ([#19101](https://github.com/ethereum-optimism/optimism/pull/19101)), and dependency updates for `time` in Kona and op-alloy ([#19100](https://github.com/ethereum-optimism/optimism/pull/19100), [#19099](https://github.com/ethereum-optimism/optimism/pull/19099)). ## CLOSED ISSUES

The issue regarding running Kona proofs in native mode against op-acceptance-test generated chains has been successfully closed ([#18990](https://github.com/ethereum-optimism/optimism/issues/18990)). This indicates progress in integrating and validating Kona's proof capabilities within the testing framework.

## NEW ISSUES

### Interoperability and L2 Contract Messenger Support
A new issue highlights the need to enable Cannon-Kona game types by default in `op-acceptance` now that Kona is in the monorepo and U18 is enabling it in production ([#19092](https://github.com/ethereum-optimism/optimism/issues/19092)). Another issue proposes adding L2 Contract Messenger (L2CM) support for `op-chain-ops`, as `interopgen` currently hardcodes `UseL2CM: false`, preventing its use in interop/test deployments ([#19102](https://github.com/ethereum-optimism/optimism/issues/19102)).

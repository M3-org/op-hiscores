# ethereum-optimism/optimism Daily Update (Jan 28, 2026)
## OVERVIEW 
The day saw significant progress in op-deployer tooling with new Forge conversions and `runWithBytes` additions, alongside critical bug fixes for `UInt64` lint violations. CI/CD pipelines were also enhanced with a complete migration of Docker builds to GitHub Actions.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced Deployment Tooling and Contract Management
Improvements were made to the `op-deployer` with the addition of `runWithBytes` to several contracts for Forge compatibility and the porting of `DeployMIPS` to Forge, unifying it with `DeployMIPS2`. The `DisputeGameFactory` was also updated to use `CREATE2` for game creation, improving address determinism during reorgs.
- [#18957](https://github.com/ethereum-optimism/optimism/pull/18957)
- [#18963](https://github.com/ethereum-optimism/optimism/pull/18963)
- [#18958](https://github.com/ethereum-optimism/optimism/pull/18958)

### CI/CD and Proofs DSL Improvements
The CI/CD pipeline saw a complete migration of Docker builds from CircleCI to GitHub Actions, enhancing cross-platform verification. Additionally, a `SuperRootsSource` interface was introduced in the proofs DSL to abstract super-root sources, supporting both `op-supervisor` and `op-supernode`.
- [#18821](https://github.com/ethereum-optimism/optimism/pull/18821)
- [#18955](https://github.com/ethereum-optimism/optimism/pull/18955)

### Code Quality and Bug Fixes
The `UInt64` lint check was enabled across the codebase, and all remaining violations were fixed, improving code quality and consistency.
- [#18948](https://github.com/ethereum-optimism/optimism/pull/18948)

## ACTIVE ISSUES

### Withdrawal Proofs with Chain-Specific Root Claim
Discussion on [#18517](https://github.com/ethereum-optimism/optimism/issues/18517) focuses on updating `OptimismPortal2.proveWithdrawalTransaction` to use `IDisputeGame.rootClaim(uint256)` for verifying output root proofs. The latest comment suggests moving this to the backlog, as `OptimismPortalInterop` changes are complete, but `OptimismPortal2` cannot be updated until U19 is executed. This change requires a separate protocol upgrade after `FaultDisputeGames` support the new `rootClaimByChainId(uint256)` method to avoid disrupting withdrawals.

### op-supernode SyncStatus API
Issue [#18947](https://github.com/ethereum-optimism/optimism/issues/18947) is discussing the design of a `SyncStatus` API for `op-supernode`. Recent comments clarify that the interface should include the `op-node` SyncStatus for every chain and the sync status of each verification activity. For interop activity, this includes the latest verified timestamp and the current L1. It was also suggested that `SyncStatus` should report the latest verified L2 to simplify acceptance tests.

### EIP-1559 Parameters Decoding in op-alloy
Issue [#18951](https://github.com/ethereum-optimism/optimism/issues/18951) addresses fixing EIP-1559 parameters decoding in `op-alloy` to properly catch zero elasticities. A community member has offered to take on this task.

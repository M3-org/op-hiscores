# ethereum-optimism/optimism Daily Update (Jan 28, 2026)
## OVERVIEW 
The day saw significant progress in op-deployer tooling with new Forge conversions and `runWithBytes` additions, alongside critical bug fixes for `UInt64` lint violations. CI/CD was also enhanced with a full migration of Docker builds to GitHub Actions.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced Deployment Tooling and Contract Management
- Added `runWithBytes` to several missing contracts for improved Forge compatibility, streamlining contract interactions during deployment and testing ([#18957](https://github.com/ethereum-optimism/optimism/pull/18957)).
- Ported `DeployMIPS` to Forge and unified it with `DeployMIPS2`, simplifying the deployment process for MIPS-related components ([#18963](https://github.com/ethereum-optimism/optimism/pull/18963)).
- Switched `DisputeGameFactory` to use `CREATE2` for game creation, ensuring unique addresses even with reorgs and different parameters ([#18958](https://github.com/ethereum-optimism/optimism/pull/18958)).

### Improved Code Quality and CI/CD Infrastructure
- Enabled and fixed all violations for the `UInt64` lint check, enhancing code robustness and preventing potential issues across various packages ([#18948](https://github.com/ethereum-optimism/optimism/pull/18948)).
- Completed the migration of Docker builds from CircleCI to GitHub Actions, improving CI/CD efficiency and adding cross-platform verification for `amd64/arm64` architectures ([#18821](https://github.com/ethereum-optimism/optimism/pull/18821)).

### Supernode Abstraction for Proofs DSL
- Introduced a `SuperRootsSource` interface in `op-devstack` to abstract the source of super-roots in the proofs DSL, allowing the dispute game factory to work with either `op-supervisor` or `op-supernode` ([#18955](https://github.com/ethereum-optimism/optimism/pull/18955)).

## ACTIVE ISSUES

### Withdrawal Proofs and OptimismPortal Updates
- Discussion on [#18517](https://github.com/ethereum-optimism/optimism/issues/18517) (contracts: Prove withdrawals using chain-specific root claim) indicates that while `OptimismPortalInterop` changes are complete, updating `OptimismPortal2` is dependent on the U19 execution. The team decided to move this to the backlog, as `OptimismPortal2` must be upgraded separately from `FaultDisputeGame` to avoid disrupting withdrawals immediately after the upgrade. This ensures users don't face additional delays in finalizing withdrawals.

### Supernode Sync Status API
- For [#18947](https://github.com/ethereum-optimism/optimism/issues/18947) (op-supernode: Introduce SyncStatus API), the discussion has clarified that the `SyncStatus` interface should include the `op-node` SyncStatus for every chain and the sync status of every verification activity. Specifically for interop activity, it should report the latest verified timestamp and the current L1. Additionally, it was suggested that `SyncStatus` should report the latest verified L2 to simplify acceptance tests that need to propose on the latest verified state without waiting.

### EIP-1559 Parameter Decoding in op-alloy
- On [#18951](https://github.com/ethereum-optimism/optimism/issues/18951) (op-alloy: Fix EIP-1559 params decoding), a community member has offered to take on the task, indicating active engagement and potential for a quick resolution. The issue aims to properly catch zero elasticities during EIP-1559 parameter decoding at the `op-alloy` level to ensure early failure detection.

# ethereum-optimism/optimism Daily Update (Jan 6, 2026)
## OVERVIEW 
Today's development focused on enhancing dispute game interoperability with a new `rootClaim` function, improving test coverage for contract upgrades and library functions, and streamlining the batcher by removing outdated Pectra checks.

## KEY TECHNICAL DEVELOPMENTS

### Dispute Game Interoperability Enhancements
- Added an overloaded `rootClaim` function to the `IDisputeGame` interface, allowing claims to be retrieved by L2 chain ID, which is crucial for future interop support in dispute game contracts. ([#18559](https://github.com/ethereum-optimism/optimism/pull/18559))

### Contract Testing and Developer Experience Improvements
- Enhanced test coverage for the `UpgradeOPChain` script, specifically for the OPCM V2 upgrade path, by adding fuzzing, input encoding verification, and revert case testing. ([#18704](https://github.com/ethereum-optimism/optimism/pull/18704))
- Added revert tests for `Preinstalls` library functions to cover error conditions when called with unknown addresses. ([#18712](https://github.com/ethereum-optimism/optimism/pull/18712))
- Improved skip messages for tests that are skipped due to feature enablement or disablement, aiding in clearer test reporting. ([#18661](https://github.com/ethereum-optimism/optimism/pull/18661))

### Batcher Simplification and CI Optimization
- Removed `isPectra` checks from the batcher code, simplifying it by assuming Pectra is always active since the fork has long occurred. ([#18534](https://github.com/ethereum-optimism/optimism/pull/18534))
- The last self-hosted runner was removed from the CI configuration. ([#18722](https://github.com/ethereum-optimism/optimism/pull/18722))

# ethereum-optimism/optimism Daily Update (May 5, 2026)
## OVERVIEW 
Today's development focused on enhancing Superchain interoperability with new features for `op-supernode` and `op-devstack`, alongside critical bug fixes for dispute game management and Kona interop. Significant refactoring efforts streamlined contract management and `op-service/eth` components.

## KEY TECHNICAL DEVELOPMENTS

### Superchain Interoperability & Node Enhancements
Improvements were made to `op-supernode` to honor user-supplied p2p listen ports, allowing for fixed port pinning [#20448](https://github.com/ethereum-optimism/optimism/pull/20448). Additionally, `op-supernode` now avoids engine rewinds on L1 reorgs and passes `observeRound` L1 heads to `l1Inclusion` for consistency [#20505](https://github.com/ethereum-optimism/optimism/pull/20505), [#20538](https://github.com/ethereum-optimism/optimism/pull/20538).

### Dispute Game and Kona Improvements
The `op-devstack` now supports SDM acceptance tests by configuring `op-reth` with the `--rollup.sdm-enabled` flag [#20516](https://github.com/ethereum-optimism/optimism/pull/20516). A critical fix was implemented to disallow `SUPER_CANNON` as a starting respected game type in the `OPContractsManagerMigrator` [#20363](https://github.com/ethereum-optimism/optimism/pull/20363). The `debug_executePayload` witness collection is now the default for Kona, graduating it from experimental status [#20498](https://github.com/ethereum-optimism/optimism/pull/20498). A bug in `op-challenger`'s `create-game` CLI for super root encoding was also resolved [#20545](https://github.com/ethereum-optimism/optimism/pull/20545).

### Contract and Service Refactoring
The `ProtocolVersions` Solidity contract and related `OPContractsManager` remnants were removed, streamlining the contract codebase [#20527](https://github.com/ethereum-optimism/optimism/pull/20527). The `BlockInfo Header()` and `HeaderRLP()` escape hatches were removed from `op-service/eth` to improve abstraction and reduce leaky implementations [#20531](https://github.com/ethereum-optimism/optimism/pull/20531). Stale U15 fork guards were removed from `contracts-bedrock` [#20330](https://github.com/ethereum-optimism/optimism/pull/20330).

## CLOSED ISSUES

### Dispute Game Migration and Interop Readiness
Several issues related to dispute game migration and interop readiness were closed. This includes the completion of acceptance testing on Betanet for L2CM upgrades [#20089](https://github.com/ethereum-optimism/optimism/issues/20089) and updating devstack to use `SUPER_CANNON_KONA` while disabling `SUPER_CANNON` as a starting respected game type [#20030](https://github.com/ethereum-optimism/optimism/issues/20030). A fix was also implemented for `MessageGraph::check_single_dependency` to guard against executing-chain interop activation [#20528](https://github.com/ethereum-optimism/optimism/issues/20528).

### ProtocolVersions Deprecation
The deprecation of the `ProtocolVersions` mechanism was fully addressed, with the removal of the Solidity contract and all associated deployment paths [#20451](https://github.com/ethereum-optimism/optimism/issues/20451), [#20308](https://github.com/ethereum-optimism/optimism/issues/20308), [#20309](https://github.com/ethereum-optimism/optimism/issues/20309). This streamlines the codebase by eliminating an unused component.

### `op-node` Stability with `op-reth`
An issue where `op-node` would get stuck in EL sync mode after a restart when `reth` already had synced data was closed [#18468](https://github.com/ethereum-optimism/optimism/issues/18468). This indicates improved stability for `op-node` driving `op-reth`.

## NEW ISSUES

### SDM and Challenger Configuration
New issues highlight the need for an admin RPC to enable/disable SDM after activation [#20542](https://github.com/ethereum-optimism/optimism/issues/20542). There's also a discussion around consolidating per-VM flags into global flags in `op-challenger` to simplify configuration [#20547](https://github.com/ethereum-optimism/optimism/issues/20547).

### Interop and Superroot Support
Future changes to `op-challenger`'s `GameTypesFlag` defaults are proposed to align with interop game types [#20549](https://github.com/ethereum-optimism/optimism/issues/20549). Additionally, `op-node` needs to support `superroot_atTimestamp` for non-interop chains to facilitate the transition to super dispute games [#20552](https://github.com/ethereum-optimism/optimism/issues/20552).

## ACTIVE ISSUES

### `op-challenger` Flag Consolidation [#20547](https://github.com/ethereum-optimism/optimism/issues/20547)
Discussion revolves around consolidating per-VM flags in `op-challenger`. Ajsutton commented that the current pattern of having both global and per-game-type flags is necessary because different game types (like `op-program` and `kona`) require distinct configuration file formats, especially concerning `l2-genesis`.

### `op-node` Superroot Support for Non-Interop Chains [#20552](https://github.com/ethereum-optimism/optimism/issues/20552)
Ajsutton provided detailed requirements for `op-node` to support `superroot_atTimestamp` for non-interop chains. Key points include using the same `--supernode-url` flag, maintaining exact compatibility with supernode namespacing for `superroot_atTimestamp`, and ensuring the API works and returns a super root for the single chain `op-node` runs, both pre- and post-upgrade. This is crucial for transitioning to super dispute games before interop activates.

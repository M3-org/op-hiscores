# ethereum-optimism/optimism Daily Update (Feb 26, 2026)
## OVERVIEW 
The day saw a key refactoring in `op-devstack` to streamline genesis interop activation. Discussions on active issues focused on Superroot SLA updates, denylist pruning on L1 reorgs, and an `op-geth` historical state fallback issue. Several new pull requests were opened, including features for L2 Dev Flags and cross-chain transaction screening.

## KEY TECHNICAL DEVELOPMENTS

### Genesis Interop Activation Refactoring
A significant refactoring was completed in `op-devstack` to improve the genesis interop activation process. This involved adding a `UseGenesisInterop` flag to `SupernodeConfig` and a corresponding option, deferring genesis timestamp resolution to where the rollup configuration is already available. This change impacts several files related to `op-devstack` and `op-acceptance-tests` ([#19302](https://github.com/ethereum-optimism/optimism/pull/19302)).

## ACTIVE ISSUES

### Superroot SLA Updates ([#19180](https://github.com/ethereum-optimism/optimism/issues/19180))
Discussion continued on defining and improving the Superroot SLA. The latest comment indicates that a database update is ready for review to allow fetching of optimistic versus verified outputs. This update is expected to be merged soon, followed by API updates. It was also noted that optimistic roots should be best-attempted by all, with empty values or exclusion for those that cannot be obtained.

### Pruning Denylist on L1 Reorg and Alert ([#19289](https://github.com/ethereum-optimism/optimism/issues/19289))
The discussion revolved around ensuring that the `Denylist` in Chain Containers is pruned when an L1 reorg occurs to prevent legitimate Unsafe chains from being inappropriately denied. It was suggested that activities need to be notified via the existing `Reset` callback. The issue also touched upon the need for the Chain Containers themselves to eliminate data from their Denylists if the Local Safe regresses, as an L1 reorg could make a previously invalid block valid.

### miner: makeEnv historical state fallback is unreachable on full nodes using path-based state scheme ([#767](https://github.com/ethereum-optimism/optimism/issues/767))
The issue concerns `op-geth` (path-based state scheme) failing to connect to the flashblocks WebSocket endpoint due to a TLS support error. The latest comment suggests that this issue might be applicable to upstream Geth and would be better fixed there and pulled through in a future update, questioning if there's anything specific to `op-geth` causing it.

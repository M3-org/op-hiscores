# ethereum-optimism/optimism Daily Update (Feb 26, 2026)
## OVERVIEW 
Today's development focused on refactoring the op-devstack for genesis interop activation, with significant activity in acceptance tests. Several new pull requests were opened, including features for L2 Dev Flags and cross-chain transaction screening, alongside new issues concerning op-reth TLS and op-node lite mode.

## KEY TECHNICAL DEVELOPMENTS

### Genesis Interop Activation Refactoring
The `op-devstack` has been refactored to use a `UseGenesisInterop` flag for genesis interop activation. This change defers genesis timestamp resolution, improving the flexibility and clarity of the system configuration. This work involved modifications across `op-devstack/sysgo` and `op-acceptance-tests/tests` to integrate the new flag and associated logic. ([#19302](https://github.com/ethereum-optimism/optimism/pull/19302))

## ACTIVE ISSUES
### op-supernode: Superroot SLA Updates ([#19180](https://github.com/ethereum-optimism/optimism/issues/19180))
Discussion continues on defining the Superroot SLA. The latest comment from axelKingsley indicates that a database update is ready for review to store the full `OutputV0` in the denylist, which is expected to facilitate fetching optimistic vs. verified outputs. This update is seen as a direct edit due to changing a data type. Previous comments highlighted the need for "best-attempt" optimistic roots and the skipping of certain tests due to missing `OptimisticAtTimestamp` data.

### op-supernode: Prune Denylist on L1 Reorg and Alert ([#19289](https://github.com/ethereum-optimism/optimism/issues/19289))
The discussion revolves around ensuring that downstream components, particularly Chain Containers, prune their `Denylist` in response to L1 reorgs to prevent legitimate unsafe chains from being inappropriately denied. axelKingsley suggests that this issue supersedes a prior ticket and proposes that activities need to be notified via the `Reset` callback, even for uncontrolled regressions of the Local Safe. It's also noted that Chain Containers themselves might need to clear data from their Denylists if the Local Safe regresses, as an L1 reorg could make a previously invalid block valid. geoknee questioned if this was a duplicate of [#19245](https://github.com/ethereum-optimism/optimism/issues/19245).

### miner: makeEnv historical state fallback is unreachable on full nodes using path-based state scheme ([#767](https://github.com/ethereum-optimism/optimism/issues/767))
The conversation focuses on a potential issue with `op-geth`'s `makeEnv` historical state fallback when using a path-based state scheme. ajsutton suggests that this issue might be more relevant to upstream Geth and should ideally be fixed there and pulled into `op-geth` with the next update, questioning if there's anything specific to `op-geth` causing it. sentientpanic previously followed up, offering to submit a PR if the behavior is unintended.

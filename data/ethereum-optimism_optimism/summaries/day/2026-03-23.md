# ethereum-optimism/optimism Daily Update (Mar 23, 2026)
## OVERVIEW 
Today's development focused on enhancing testing infrastructure with flaky test tracking, critical bug fixes in Kona and interop-filter, and deploying ETH bridge contracts for interop activation.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced Testing and Flaky Test Tracking
A new feature was added to improve flaky test tracking by introducing `FLAKY_FAIL`/`FLAKY_PASS` annotations. This provides structured markers in JUnit XML skip messages, making it easier to identify and manage flaky tests. ([#19719](https://github.com/ethereum-optimism/optimism/pull/19719))

### Critical Bug Fixes in Kona and Interop-Filter
Several significant bug fixes were implemented, including resolving an issue where the `action-tests-single` CI job in Kona was not running tests ([#19689](https://github.com/ethereum-optimism/optimism/pull/19689)). Another fix addressed malformed logs in `SystemConfig::update_with_receipts` within Kona's genesis protocol, preventing silent dropping of valid updates ([#19688](https://github.com/ethereum-optimism/optimism/pull/19688)). Additionally, a `uint64` underflow in `calculateStartingBlock` was prevented in `op-interop-filter`, ensuring correct L2 genesis block fallback. ([#19720](https://github.com/ethereum-optimism/optimism/pull/19720))

### Interop Network Upgrade and Dependency Updates
Deployment and funding of `SuperchainETHBridge` and `ETHLiquidity` contracts were added as interop network upgrade transactions at activation time, crucial for cross-chain interoperability ([#19648](https://github.com/ethereum-optimism/optimism/pull/19648)). Rust dependencies were also bumped to resolve `deny` failures, improving overall stability ([#19721](https://github.com/ethereum-optimism/optimism/pull/19721)).

## ACTIVE ISSUES

### Kona Guest Panic with ChainList.json
The `kona guest` program is panicking during Cannon VM execution when deserializing the superchain registry chain list, specifically due to a missing `name` field. This was observed in `TestChallengerPlaysGame` when the challenger invoked cannon/kona. A Notion link with further details has been saved for investigation. ([#19654](https://github.com/ethereum-optimism/optimism/issues/19654))

### Flaky Test: TestCLELDivergence
The `TestCLELDivergence` test continues to be flaky, with recent failures on `develop`. The core issue appears to be related to the derivation pipeline resetting the `UnsafeL2` head after an `UnsafeUpdateEvent`, which conflicts with the test's expectation that the CL's unsafe head should persist at the target block despite the EL returning `SYNCING`. The team is investigating whether this reset is correct behavior or a bug in the reset logic. ([#19681](https://github.com/ethereum-optimism/optimism/issues/19681))

### Interop Phase 3: Removing Chains From Shared Dispute Games
Discussion is ongoing regarding the ability to remove a chain from a shared dispute game as part of Interop Phase 3. Clarification was sought on the necessity and implications of this feature, specifically if it means chains are actually being removed from the interop set. ([#19692](https://github.com/ethereum-optimism/optimism/issues/19692))

### CGT Chains and Shared Dispute Games
Consideration is being given to potential issues with Custom Gas Token (CGT) chains forming interop sets. A key point raised is the need for workarounds to enable the correct predeploys in the interop fork for CGT chains, specifically by not deploying or enabling the current `SuperchainETHBridge`/`ETHLiquidity` contracts. ([#19711](https://github.com/ethereum-optimism/optimism/issues/19711))

### Kona-Interop Block Hash Oracle Review
Progress has been made on reviewing the `kona-interop` block hash oracle, which uses EIP-2935 for efficient block hash lookups. A new fixture-based integration test ([#19726](https://github.com/ethereum-optimism/optimism/pull/19726)) has been opened to validate `OracleInteropProvider::header_by_number`. This test uses real OP Mainnet state/storage trie proof data to exercise the EIP-2935 block hash lookup path, avoiding the impractical 60+ minute runtime of a full acceptance test. The goal is to ensure lookups prior to the current history window work correctly. ([#18288](https://github.com/ethereum-optimism/optimism/issues/18288))

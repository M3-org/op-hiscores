# ethereum-optimism/optimism Daily Update (Apr 2, 2026)
## OVERVIEW 
Today's development focused on enhancing fault proof interoperability and stability, with significant bug fixes in Kona and op-devstack, alongside new documentation for acceptance tests.

## KEY TECHNICAL DEVELOPMENTS

### Fault Proof System Enhancements & Interoperability
Significant progress was made in porting interop fault proof tests to the acceptance test framework, specifically for `DepositMessage` and `PreForkActivation` scenarios ([#19631](https://github.com/ethereum-optimism/optimism/pull/19631), [#19630](https://github.com/ethereum-optimism/optimism/pull/19630)). Several critical bug fixes were implemented in Kona to improve consolidation logic, including removing obsolete replacement deposit transactions and skipping re-validation of deposit-only blocks during consolidation ([#19894](https://github.com/ethereum-optimism/optimism/pull/19894), [#19890](https://github.com/ethereum-optimism/optimism/pull/19890)).

### Stability and Reliability Improvements
The `op-devstack` received a fix to increase the transaction inclusion timeout, addressing potential CI flakiness ([#19903](https://github.com/ethereum-optimism/optimism/pull/19903)). A flaky acceptance test, `TestUnsafeGapFillAfterSafeReorg`, was also addressed by adding a `WaitL1OriginHash` helper to the devstack DSL ([#19885](https://github.com/ethereum-optimism/optimism/pull/19885)). Additionally, bounds checks were added to `read_tx_data` in `kona/protocol` to prevent consensus divergence on oversized transaction payloads ([#19904](https://github.com/ethereum-optimism/optimism/pull/19904)).

### Documentation and Tooling Updates
New documentation was added for AI agents, including an acceptance test guide and a skill for running acceptance tests locally ([#19887](https://github.com/ethereum-optimism/optimism/pull/19887)). The `op-deployer` also received an update to support `op-validator v6.0.0` ([#19786](https://github.com/ethereum-optimism/optimism/pull/19786)).

## ACTIVE ISSUES

### Flaky Test: TestSuperCannonStepWithPreimage_nonExistingPreimage ([#19892](https://github.com/ethereum-optimism/optimism/issues/19892))
Investigation into this flaky test revealed that the `blob` variant consistently fails locally due to `cannon/kona` exiting with code 1 during `FindStep`, likely caused by stale local prestate artifacts. CI logs indicate that the challenger steps with `containsOracleData=false` because it steps at the wrong trace index (one position before the preimage load). This behavior is attributed to resource contention in CI, where CPU pressure can cause the challenger's `kona` execution to take longer or be killed, leading to incorrect claim values. The recommended fix involves serializing subtests and sharing one interop system to reduce resource contention, along with an assertion to verify the step's trace index.

### Flaky Test: TestExecutePayloadSuccess ([#19898](https://github.com/ethereum-optimism/optimism/issues/19898))
The root cause of this flaky test is a race condition where the `debug_executePayload` RPC on `op-reth` reads from a proofs ExEx store that may not have indexed block 1 yet when the validator is queried immediately after funding completes on the sequencer. This results in a "no state found for block number 1" error. The proposed fix involves adding `WaitForBlockNumber` synchronization between the sequencer and validator to ensure the ExEx has processed the necessary block.

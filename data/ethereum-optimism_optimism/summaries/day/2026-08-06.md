# ethereum-optimism/optimism Daily Update (Aug 6, 2026)
## OVERVIEW 
Today's development focused heavily on documentation improvements, particularly for `op-reth` and `kona-node`, alongside significant code refactoring in `op-core`, `op-service`, and `op-chain-ops` for receipt handling. Several CI/CD enhancements and `op-dispute-mon` updates were also completed.

## KEY TECHNICAL DEVELOPMENTS

### Documentation & CLI Enhancements
Extensive documentation updates were made across various components. This included adding a fault proofs reference page, regenerating `op-reth` CLI references to v2.4.1, correcting `kona-node` supervisor and conductor flag facts, and refining `op-batcher` throttling documentation. Additionally, the `op-reth` `--minimal` option was removed as it was unsupported, representing a breaking change.

### Core Code Refactoring & Dispute Monitoring
Significant code refactoring was performed in `op-core`, `op-service`, and `op-chain-ops` to clean up receipt wrapping constructors and codecs, following reviews of the `op-geth` decoupling stack. The `op-dispute-mon` component saw updates to normalize fault bond snapshots, improving its monitoring capabilities.

### Infrastructure & CI/CD Improvements
CI/CD pipelines were enhanced with new features, including paging `protocol-oncall` for `go-tests-full` develop failures and building the superchain bundle in `go-release`. All `apko` images now include `busybox` and `apk-tools` for better shell and package management capabilities. The upstream `reth` pin was also updated.

### Kona-SP1 Proposer Enhancements
The `kona-sp1-proposer` received updates to enable a fast finality mode, allowing it to prove games without waiting for a challenge. Additionally, the super root RPC configuration was renamed for clarity and consistency.

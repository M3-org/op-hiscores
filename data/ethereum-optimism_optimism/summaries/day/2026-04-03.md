# ethereum-optimism/optimism Daily Update (Apr 3, 2026)
## OVERVIEW 
Today's development focused on critical bug fixes, significant code refactoring to remove legacy components, and enhancements to testing infrastructure. Key achievements include resolving a flaky test in `op-reth` and streamlining contract management by removing OPCMv1.

## KEY TECHNICAL DEVELOPMENTS

### Contract Management Streamlined with OPCMv1 Removal
The legacy OPContractsManager v1 has been entirely removed from Solidity code, making OPContractsManagerV2 the sole contract manager. This refactoring involved deleting the v1 contract and gutting its interface, simplifying the contract architecture. ([#19795](https://github.com/ethereum-optimism/optimism/pull/19795))

### Enhanced Testing and CI Reliability
A flaky test, `TestExecutePayloadSuccess`, in `op-reth` was fixed by adding `WaitForBlockNumber` synchronization between the sequencer and validator, improving test stability. Additionally, the CI now runs reth and kona against all acceptance tests, expanding test coverage beyond the base gate. ([#19899](https://github.com/ethereum-optimism/optimism/pull/19899), [#19787](https://github.com/ethereum-optimism/optimism/pull/19787))

### Improved Contract Test Deployment Configuration
The requirement for deploy config JSON files when running Solidity unit tests has been removed. This was achieved by adding a `_initDefaults()` function to `DeployConfig.s.sol` with hardcoded defaults, simplifying the testing setup. ([#18922](https://github.com/ethereum-optimism/optimism/pull/18922))

# ethereum-optimism/optimism Daily Update (Jul 10, 2026)

## OVERVIEW 
Today's development focused on enhancing the Optimism Portal's security, optimizing proof backfilling, and refining the Superchain Registry for Karst gas compatibility. Significant progress was also made in enabling permissionless fault games from initial deployment.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced Security and Migration for Optimism Portal
Security for the Optimism Portal has been strengthened with new validation checks for inputs during the `migrateToSharedDisputeGame` function, preventing zero-address and unauthorized lockbox issues ([#20928](https://github.com/ethereum-optimism/optimism/pull/20928)). Additionally, the ability to launch new chains with permissionless fault games (Cannon and Cannon-Kona) enabled from genesis has been introduced, moving away from requiring a permissioned game type at initial deployment ([#21588](https://github.com/ethereum-optimism/optimism/pull/21588)).

### Performance Improvements for Proof Backfilling
The `op-proofs backfill` process has been significantly optimized by batching multiple blocks into a single MDBX transaction, reducing the number of commit/fsync operations and improving performance for large block extensions ([#21602](https://github.com/ethereum-optimism/optimism/pull/21602)).

### Superchain Registry and Node Configuration Updates
The Superchain Registry has been updated to sync Karst gas compatibility configurations, including bumping the registry gitlink and regenerating embedded artifacts for Go, Kona, and op-reth ([#21674](https://github.com/ethereum-optimism/optimism/pull/21674)). Furthermore, the base pool-builder configuration in `OpNode` has been extracted into a reusable method, allowing downstream nodes to easily reuse the standard configuration ([#21688](https://github.com/ethereum-optimism/optimism/pull/21688)).

### Code Refactoring in Kona
The `fetch_safe_head_hash` function in Kona has been refactored and hoisted into `kona-proof`, eliminating byte-identical copies and duplicate tests across the codebase ([#21696](https://github.com/ethereum-optimism/optimism/pull/21696)).

## CLOSED ISSUES

### Flaky Test Resolution
Several flaky tests related to reorgs and unsafe heads, specifically `TestReorgUnsafeHead` ([#20198](https://github.com/ethereum-optimism/optimism/issues/20198)) and `TestReorgInitExecMsg` ([#20943](https://github.com/ethereum-optimism/optimism/issues/20943)), have been closed. The root cause for `TestReorgUnsafeHead` was identified as the test picking the next block's parent by reading the EL's mutable `eth.Unsafe` label, which could lag under load, leading to the EL reorging back to the original chain. Fixes involved replacing sleeps with polls and using `ReorgExact` for assertions.

### Interop Audit and Portal Migration Issues Addressed
Issues identified during interop audits ([#20985](https://github.com/ethereum-optimism/optimism/issues/20985)) have been closed. Additionally, a critical fix for the `OptimismPortal2.migrateToSharedDisputeGame` function, which previously accepted bad targets without validation, has been implemented and the corresponding issue closed ([#20881](https://github.com/ethereum-optimism/optimism/issues/20881)).

### Permissioned Guard and Dead Anchor Placeholder Removal
The issue concerning the removal of the permissioned-only guard and dead anchor placeholder in `DeployOPChain.s.sol` has been closed ([#20913](https://github.com/ethereum-optimism/optimism/issues/20913)). This change allows for more flexible initial deployments beyond just `PERMISSIONED_CANNON`.

### Versioning Discrepancy in Kona and op-reth Resolved
The issue where the version reported by Kona and op-reth in Prometheus metrics did not align with the git/docker tag has been resolved ([#20832](https://github.com/ethereum-optimism/optimism/issues/20832)). The versioning now corresponds to the git tag that triggered the build.

Discussion continues on simplifying `op-challenger`'s handling of permissioned dispute games after the transition to `SuperPermissionedDisputeGame` ([#21678](https://github.com/ethereum-optimism/optimism/issues/21678)). A key point raised is the potential need for the challenger to still close the game after finalization to update the anchor state registry, even though `SuperPermissionedDisputeGame` resolves to `DEFENDER_WINS` immediately.

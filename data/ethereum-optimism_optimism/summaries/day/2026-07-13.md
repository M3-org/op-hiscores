# ethereum-optimism/optimism Daily Update (Jul 13, 2026)
## OVERVIEW 
Today's development focused on refining core infrastructure by removing deprecated features, enhancing observability with new metrics, and improving documentation.

## KEY TECHNICAL DEVELOPMENTS

### Infrastructure Refinements and Deprecation
The `CANNON_KONA` development feature toggle has been removed, streamlining the codebase while retaining the associated protocol game types. This cleanup affects various core components including CircleCI configurations, documentation, and contract libraries. Additionally, several `op-geth` CI variants were removed, further simplifying the continuous integration process.
[#21663](https://github.com/ethereum-optimism/optimism/pull/21663), [#21715](https://github.com/ethereum-optimism/optimism/pull/21715)

### Enhanced Observability and Metrics
New metrics have been introduced to expose chain hardfork activation data in Prometheus for `op-reth` and `op-node`. This allows for better monitoring of the L2 (OP Stack) hardfork schedule and configured hardfork activation times.
[#21704](https://github.com/ethereum-optimism/optimism/pull/21704), [#21701](https://github.com/ethereum-optimism/optimism/pull/21701)

### Documentation and Tooling Improvements
Documentation for rollup configuration fields has been updated to reflect how they are wired through `op-node` and `kona`. The `op-geth` decoupling plan documentation was also revisited, widening its scope to the entire monorepo and trimming it to a strategic overview. Furthermore, a new check was added to verify NUT pre-fork state snapshots, ensuring consistency.
[#21694](https://github.com/ethereum-optimism/optimism/pull/21694), [#21721](https://github.com/ethereum-optimism/optimism/pull/21721), [#21716](https://github.com/ethereum-optimism/optimism/pull/21716)

## ACTIVE ISSUES

### `op-revm` Support and Sync
Discussion on [#21069](https://github.com/ethereum-optimism/optimism/issues/21069) continues regarding the synchronization of `op-revm` with new `revm` releases. The latest comment from Wodann emphasizes the need for new `op-revm` crate releases to support Glamsterdam in Hardhat 3 and ensure up-to-date OP stack support. The team aims to stay in sync with `revm` releases, often aligning with `reth` dependency updates.

### `op-challenger` Permissioned Dispute Game Handling
On [#21678](https://github.com/ethereum-optimism/optimism/issues/21678), the conversation revolves around simplifying `op-challenger`'s handling of permissioned dispute games after the transition to `SuperPermissionedDisputeGame`. A key point raised by pauldowman is the potential to add `closeGame()` to the generic `IDisputeGame` interface to streamline the process of updating the anchor state registry. This is also linked to [#21708](https://github.com/ethereum-optimism/optimism/issues/21708).

### Advancing Anchor for Finalized `SuperPermissionedDisputeGame`
Issue [#21708](https://github.com/ethereum-optimism/optimism/issues/21708) discusses the challenge of advancing the `AnchorStateRegistry` for finalized `SuperPermissionedDisputeGame` games, as they lack a `closeGame()` method. The latest comment from pauldowman suggests adding `closeGame()` to the generic `IDisputeGame` interface as a potential solution, mirroring the discussion in [#21678](https://github.com/ethereum-optimism/optimism/issues/21678).

# ethereum-optimism/optimism Daily Update (Jul 2, 2026)
## OVERVIEW 
The day saw significant activity in the `op-deployer` and `op-reth` components with new feature development. Several security audit feedbacks were raised as new issues, and a long-standing `op-node` compatibility issue with EIP-4444 was closed.

## KEY TECHNICAL DEVELOPMENTS

No completed work was reported for this day.

## NEWLY OPENED PULL REQUESTS
Three new pull requests were opened today, all focusing on new features:
- [#21611](https://github.com/ethereum-optimism/optimism/pull/21611) introduces a feature to commit prestates before chain deployment in `op-deployer`.
- [#21610](https://github.com/ethereum-optimism/optimism/pull/21610) adds a feature to source permissionless deploy inputs from chain state, also within `op-deployer`.
- [#21609](https://github.com/ethereum-optimism/optimism/pull/21609) implements a feature in `op-reth/txpool` to reserve the Isthmus operator fee in the pool balance check.

## CLOSED ISSUES

### `op-node` Compatibility with EIP-4444 Resolved
The issue [#13570](https://github.com/ethereum-optimism/optimism/issues/13570), which addressed `op-node` compatibility with EIP-4444 enabled L1 nodes, was closed today. This issue previously caused errors when the L1 node pruned historic blocks or receipts, preventing the `op-node` from determining the L2 genesis blockhash.

## NEW ISSUES

### `op-reth` Transaction Pool Balance Check Discrepancy
A new issue [#21608](https://github.com/ethereum-optimism/optimism/issues/21608) highlights that the `op-reth` transaction pool balance check omits the Isthmus operator fee, potentially admitting under-funded transactions and causing parity issues with `op-geth`.

### Lumi Security Audit Feedback
Two new issues were opened based on security audit feedback from Lumi Beacon:
- [#21612](https://github.com/ethereum-optimism/optimism/issues/21612) provides security feedback for `solutil.go` within the `op-chain-op` component.
- [#21613](https://github.com/ethereum-optimism/optimism/issues/21613) provides security feedback for `mod.rs` within the `rust/kona/crate` component.

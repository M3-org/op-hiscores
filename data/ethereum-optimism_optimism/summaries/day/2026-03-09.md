# ethereum-optimism/optimism Daily Update (Mar 9, 2026)
## OVERVIEW 
Today's development focused on enhancing hardfork support with Karst integration and Network Upgrade Transaction (NUT) bundle generation, alongside critical bug fixes in `op-program` and `supernode` for improved stability and compatibility.

## KEY TECHNICAL DEVELOPMENTS

### Hardfork and Upgrade Infrastructure
Significant progress was made in preparing for future network upgrades. New infrastructure was added for generating Network Upgrade Transaction (NUT) bundles for L2 hardforks, streamlining the upgrade process ([#19248](https://github.com/ethereum-optimism/optimism/pull/19248)). Additionally, Karst hardfork support was integrated into Kona, positioning it between Jovian and Interop, with an empty NUT bundle and enforced empty activation blocks ([#19372](https://github.com/ethereum-optimism/optimism/pull/19372)).

### `op-program` Enhancements and Bug Fixes
The `op-program` saw improvements in its compatibility testing and debugging capabilities. A new Claude Code skill was added for triaging `analyze-op-program-client` CI failures, aiding in interactive review of syscall/opcode findings from `vm-compat` ([#19444](https://github.com/ethereum-optimism/optimism/pull/19444)). A critical bug fix involved regenerating the `vm-compat` baseline for geth v1.17.1 after an upgrade, ensuring accurate compatibility checks ([#19443](https://github.com/ethereum-optimism/optimism/pull/19443)).

### `supernode` Stability and Interoperability
Improvements to the `supernode` focused on enhancing its L1 progress tracking and overall stability. A bug fix addressed how `supernode` considers verifier L1 progress in `superroot CurrentL1`, ensuring more accurate L1 state tracking ([#19441](https://github.com/ethereum-optimism/optimism/pull/19441)). Furthermore, a change was implemented to include available optimistic blocks in `superroot_atTimestamp` responses, even if not all blocks are available, improving the RPC's utility ([#19348](https://github.com/ethereum-optimism/optimism/pull/19348)).

### Codebase Cleanup and Testing
Efforts were made to streamline the codebase and improve testing. Deprecated Kona supervisor crates, binaries, and associated tests were removed, simplifying the project structure ([#19290](https://github.com/ethereum-optimism/optimism/pull/19290)). In CI, "op" was added to the chain-specific upgrade test matrix, while "base" was removed from upgrade and sync test matrices, optimizing test execution ([#19448](https://github.com/ethereum-optimism/optimism/pull/19448)). A previous revert was also made to fix a broken `TestOutputCannon_ChallengeAllZeroClaim/mt-cannon` test ([#19445](https://github.com/ethereum-optimism/optimism/pull/19445)).

## CLOSED ISSUES

### L2 Contract Upgrades and Refactoring
Two issues related to L2 contract upgrades and refactoring were closed. This includes the implementation of an additional upgrade gas mechanism in `op-node` to handle gas allocation beyond systemTxMaxGas limits ([#18832](https://github.com/ethereum-optimism/optimism/issues/18832)). Additionally, the `OptimismMintableERC721Factory` was refactored to utilize the `Initializable` pattern, moving away from constructor-based initialization ([#19318](https://github.com/ethereum-optimism/optimism/issues/19318)).

### `op-proposer` Sepolia Devnet Issue Resolution
An issue concerning the `op-proposer` on the Sepolia devnet, where the `anchorStateRegistry` was using a timestamp instead of a block number, leading to incorrect `UnexpectedRoot` claim checks, has been closed ([#19301](https://github.com/ethereum-optimism/optimism/issues/19301)). The resolution noted that the specific devnet is no longer in use, and the issue stemmed from an invalid proposal on that deprecated environment.

### Supernode L1 Consistency Verification
The issue [#19420](https://github.com/ethereum-optimism/optimism/issues/19420) discusses adding L1 consistency verification to the supernode's cross-safety validation. The latest comment from karlfloersch points to a pull request for formatting the report, indicating ongoing work or a related discussion on how to present the findings or progress on this issue. The core problem is that the supernode's cross-safety validation operates on an asynchronous and unsynchronized global view of multiple L2 chains, and the interop verification pipeline needs to incorporate L1 consistency.

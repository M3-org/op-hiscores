# ethereum-optimism/optimism Daily Update (Jun 17, 2026)
## OVERVIEW 
Today's development focused on enhancing interop testing tools, fixing critical bugs related to block warming and L2 genesis upgrades, and updating documentation with security audit reports and important notices. Several new issues were opened concerning proving clusters and ZK dispute games.

## KEY TECHNICAL DEVELOPMENTS

### Interoperability and Testing Tools
New standalone interop test tools, `check-lagoon` and `interop-smoke`, were added to `op-chain-ops`. These tools utilize a shared cross-chain bridge implementation to facilitate round-trip bridging and interop filter failsafe testing, improving the robustness of the Superchain ecosystem. ([#21395](https://github.com/ethereum-optimism/optimism/pull/21395))

### Critical Bug Fixes for Block Processing and Upgrades
A bug in `alloy-op-evm` was fixed by rolling back SDM block-warming for declined `op-rbuilder` candidates, addressing an issue where `op-rbuilder`'s payload diverged from `op-node`'s. Additionally, a fix was implemented to skip interop L2 genesis upgrade tests under custom gas tokens, resolving issues introduced by changes in predeploy organization and L2CM upgrade paths. ([#21359](https://github.com/ethereum-optimism/optimism/pull/21359), [#21444](https://github.com/ethereum-optimism/optimism/pull/21444))

### Documentation and Security Updates
The documentation was updated to include the June 2026 Cantina OPCMv2 security review PDF and an important notice regarding a Sepolia `estimateGas` issue. These updates enhance transparency and provide crucial information for developers and node operators. ([#21458](https://github.com/ethereum-optimism/optimism/pull/21458), [#21456](https://github.com/ethereum-optimism/optimism/pull/21456))

## ACTIVE ISSUES

### SDM Operator Flag Consistency
Discussion on [#21360](https://github.com/ethereum-optimism/optimism/issues/21360) (SDM: improve consistency of opt in operator flag) indicates a narrowing of scope to `op-reth` and `op-node`. There's an ongoing effort to standardize the naming of the `protocol_active` gate, which is currently inconsistently named across `op-node`, `op-reth`, and `op-rbuilder`. The latest comments suggest aligning these names for better consistency.

### ZK Games Acceptance Tests and Proving
On [#18326](https://github.com/ethereum-optimism/optimism/issues/18326) (Add acceptance tests for ZK games), it was noted that a mock prover would be necessary for proposer acceptance tests, implying the need to provision GPUs in CI. This issue is closely related to [#21418](https://github.com/ethereum-optimism/optimism/issues/21418) (Local / mock proving for CI & local debugging), which is considered a duplicate.

### Kona Host Game Input and Witness Generation
For [#18430](https://github.com/ethereum-optimism/optimism/issues/18430) (kona: Review host game input and witness generation for soundness), the latest comment emphasizes the need to ensure that `kona-host` data fetchers retry indefinitely and are sufficiently reliable, similar to existing fetchers.

# ethereum-optimism/optimism Daily Update (Mar 18, 2026)
## OVERVIEW 
Today's development focused on enhancing L2 contract functionality, improving Supernode interoperability, and stabilizing CI tests. Key achievements include implementing L2 Dev Flags and refining Supernode's L1 block processing.

## KEY TECHNICAL DEVELOPMENTS

### L2 Contract Enhancements and Management
New L2 Dev Flags were implemented, allowing per-chain configuration for development features [#19324]. Additionally, L2 proxied contracts with initialization functions now inherit from `ProxyAdminOwnedBase`, standardizing contract ownership and management across L1 and L2 [#19564].

### Supernode Interoperability and Stability
The `check-super-root` script was updated to utilize a single Supernode RPC for fetching verified super roots, simplifying the process [#19454]. Critical fixes were applied to Supernode, including capping `CurrentL1` at the minimum of node `CurrentL1`s during interop advancement [#19620] and adding beacon fallback support for blob sidecar retrieval [#19645].

### CI/CD and Testing Improvements
Several flaky tests were addressed to improve CI stability. Timeouts for `GameHelper` transactions in `op-devstack` were increased to prevent hanging issues [#19556], and `TestCLIMigrate` tests in `op-deployer` also saw increased timeouts [#19625]. Retry logic was added to `TestAddressValidDeployment` in `op-validator` to handle intermittent RPC call failures [#19592]. The `TestSupernodeInteropActivationAfterGenesis` test was re-enabled after previous issues were resolved [#19615]. Furthermore, `gotestsum` logs are now split into per-test files for easier debugging [#19575], and redundant interop proof tests were removed from `op-e2e` [#19622].

## ACTIVE ISSUES

### Initial EL Sync UX and Correctness ([#17631](https://github.com/ethereum-optimism/optimism/issues/17631))
Discussions continue on the behavior of `op-node` during initial EL sync, particularly how it marks the reached target as finalized even if not truly finalized. @trianglesphere proposed using L1 finalized head timestamp minus the sequence window to ensure the finalized head is not set ahead of derivation, or using a different finalization gadget. @karlfloersch favored the operational simplicity of delaying safe/finalized by the sequencing window. The conversation also touched upon whether this bug is specific to light CL/interop or present without it, and how sequencer nodes are currently mitigating this. The potential deprecation of `op-geth` and `op-reth`'s ability to handle historical forks were also mentioned.

### Non-terminating CI job: memory-all-opn-op-geth ([#19563](https://github.com/ethereum-optimism/optimism/issues/19563))
This CI job continues to experience non-terminating runs, primarily due to flaky tests. @ajsutton identified `TestChallengerPlaysGame` as a recurring culprit, timing out after 2 hours. Investigation revealed that RPC calls within polling loops were using a base test context with a long deadline, causing indefinite blocking when individual RPC calls to the in-memory L1 geth hung due to CI resource contention. A draft fix has been opened to address this by ensuring RPC calls respect per-wait timeouts. Other observed issues include `l2-proposer` getting stuck retrying and `supernode` error loops, indicating broader acceptance test stability challenges.

### Flaky test: `TestSupernodeSameTimestampInvalidTransitive` ([#19570](https://github.com/ethereum-optimism/optimism/issues/19570))
This test continues to flake, consistently timing out at around 2m46s with the error "super-root at timestamp X was not validated in time". @maurelian provided a detailed root cause analysis, identifying a race condition in multi-chain transitive invalidation. The issue arises when the supernode attempts to insert a synthetic payload during a rewind, which is rejected by geth due to "links to previously rejected block" if a prior invalidation poisoned geth's block rejection cache. This leads to an infinite retry loop. Potential fixes include treating `ErrRewindSyntheticPayloadRejected` as critical, clearing geth's block rejection cache before rewind, or coordinating multi-chain rewinds to prevent cross-chain cache poisoning.

### [Base Mainnet] BAD BLOCK, invalid gas used ([#778](https://github.com/ethereum-optimism/optimism/issues/778))
This long-standing issue on Base Mainnet reports "BAD BLOCK, invalid gas used" errors. Logs provided by @qnduncan show `op-node` failing to insert payloads due to `execution payload was INVALID! Latest valid hash is ..., ignoring bad block: invalid gas used (remote: ... local: ...)`. The logs also indicate repeated warnings about "Dropping invalid unsafe payload" and "links to previously rejected block", suggesting a persistent issue with block validation and propagation. There are also instances of failed P2P sync requests due to peers not serving requests or protocols not being supported.

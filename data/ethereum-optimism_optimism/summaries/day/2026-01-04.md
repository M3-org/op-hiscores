# ethereum-optimism/optimism Daily Update (Jan 4, 2026)
## OVERVIEW 
Today's development focused on refining the `op-challenger` and `op-dispute-mon` components by removing deprecated game types and addressing a bug in prestate handling.

## KEY TECHNICAL DEVELOPMENTS

### `op-challenger` and `op-dispute-mon` Refinements
Significant work was done to streamline the `op-challenger` and `op-dispute-mon` components by removing support for the Asterisc, AsteriscKona, and SuperAsteriscKona game types, which were never shipped to production. This cleanup also involved removing related tests, simplifying the codebase. ([#18670](https://github.com/ethereum-optimism/optimism/pull/18670))

### Prestate Handling Bug Fix
A bug in `check-prestate` was resolved, specifically addressing its failure when `op-geth` was referenced as a Go pseudo-version. The fix also corrected the Kona prestate name. ([#18691](https://github.com/ethereum-optimism/optimism/pull/18691))

## NEWLY OPENED PULL REQUESTS
- [#18710](https://github.com/ethereum-optimism/optimism/pull/18710): Simplifies output game creation by auto-deriving `rootClaim` in `op-e2e`.
- [#18711](https://github.com/ethereum-optimism/optimism/pull/18711): Updates `op-dispute-mon` to use `supernode` instead of `supervisor`.

## CLOSED ISSUES

### ZK Game Integration Clarification
An inquiry regarding the relationship between `OptimisticZkGame` and `op-succinct`'s `OPSuccinctFaultDisputeGame` was closed. It was clarified that `OptimisticZkGame.sol` is not yet production-ready, and integration with `OPContractsManager` is ongoing, with no firm timeline for completion. ([#18692](https://github.com/ethereum-optimism/optimism/issues/18692))

A critical vulnerability report was closed. The reporter was advised to use the ImmuneFi escalation process if they believed the issue was resolved incorrectly. ([#18703](https://github.com/ethereum-optimism/optimism/issues/18703))

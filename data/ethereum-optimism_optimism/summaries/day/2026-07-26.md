## ACTIVE ISSUES
### Interoperability Migration and Contract Upgrades
Discussion on [#21731](https://github.com/ethereum-optimism/optimism/issues/21731) focuses on ensuring post-migration OPCM upgrades function correctly across all chains in an interoperability set. The latest comment from ajsutton outlines two primary approaches: resolving the `ProxyAdmin` during upgrade for all chains, or skipping shared component updates for chains that don't own the `ProxyAdmin`. The current leaning is towards the first approach, which ensures all chains upgrade shared components, despite potential minor gas waste, to avoid the risk of contracts silently failing to upgrade or configurations not being applied. The discussion also emphasizes the need for shared components to be backwards compatible or fail closed if upgraded independently.

# ethereum-optimism/optimism Daily Update (Jan 27, 2026)
## OVERVIEW 
Today saw significant feature additions, including the implementation of core filtering logic for interop, updates to withdrawal commands for super proposals, and the migration of `alloy-op-evm` and `op-reth` to the monorepo. Integrations between `op-deployer` and `op-validator` were also completed.

## KEY TECHNICAL DEVELOPMENTS

### Interoperability and Withdrawal Enhancements
- Implemented core filtering logic for `op-interop-filter` to enhance cross-chain interactions ([#18604](https://github.com/ethereum-optimism/optimism/pull/18604)).
- Updated the withdrawal command to support proving withdrawals using specific output roots in super proposals, removing the dependency on the supervisor-rpc ([#18733](https://github.com/ethereum-optimism/optimism/pull/18733)).
- Established a basic pattern for Interop Activity within `op-supernode` ([#18728](https://github.com/ethereum-optimism/optimism/pull/18728)).
- Updated `op-supernode` Chain Container Interfaces, including changes to `SafeBlockAtTimestamp` and removal of SafeDB accessors ([#18727](https://github.com/ethereum-optimism/optimism/pull/18727)).
- Added support for fetching proposals via `op-supernode` RPC in `op-proposer` for programmatic configuration ([#18940](https://github.com/ethereum-optimism/optimism/pull/18940)).

### Monorepo Migrations and Tooling Integration
- Ported `alloy-op-evm` to the monorepo, retaining its `op-evm` history and migrating CI ([#18826](https://github.com/ethereum-optimism/optimism/pull/18826)).
- Migrated `op-reth` to the monorepo, following a similar pattern to previous migrations ([#18917](https://github.com/ethereum-optimism/optimism/pull/18917)).
- Integrated `op-validator` with `op-deployer` for automatic validation after deployments ([#18934](https://github.com/ethereum-optimism/optimism/pull/18934)).

## CLOSED ISSUES

### System Configuration and Monorepo Migration
- The allowance for overriding `SystemConfig::isCustomGasToken` in OPCMv2 has been removed, as it is no longer required after U18 ships ([#18502](https://github.com/ethereum-optimism/optimism/issues/18502)).
- The `op-reth` `optimism` crates have been successfully migrated into the monorepo, following the pattern established by the Kona migration ([#18577](https://github.com/ethereum-optimism/optimism/issues/18577)).

### Proposer Functionality
- Support for fetching proposals via `op-supernode` has been added to `op-proposer`, moving away from exclusive reliance on `op-supervisor` RPCs ([#18920](https://github.com/ethereum-optimism/optimism/issues/18920)).

## NEW ISSUES

### Batcher and Reth Enhancements
- The `op-batcher` needs a configurable blob tip cap mechanism, as the current implementation only allows a static maximum priority fee ([#18949](https://github.com/ethereum-optimism/optimism/issues/18949)).
- A release flow for `op-reth` needs to be established, ideally mirroring the release process of other Go components ([#18950](https://github.com/ethereum-optimism/optimism/issues/18950)).

### Alloy EIP-1559 Decoding
- EIP-1559 parameter decoding in `op-alloy` requires a fix to properly catch zero elasticities, ensuring early failure during decoding ([#18951](https://github.com/ethereum-optimism/optimism/issues/18951)).

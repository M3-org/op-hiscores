# ethereum-optimism/optimism Daily Update (May 27, 2026)
## OVERVIEW 
Today's development focused on enhancing monitoring metrics, refining clock implementations, and improving node synchronization. Significant progress was also made in documentation, particularly for node operators transitioning to op-reth, and several critical bugs were addressed.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced Monitoring and Node Synchronization
New Prometheus gauges were added to `op-interop-filter` to track chain tip lag and ingestion lag, providing better visibility into chain synchronization status ([#20620](https://github.com/ethereum-optimism/optimism/pull/20620)). The `op-node` now defaults its `syncmode.offset-el-safe` to 12 hours, aligning with OP Mainnet's sequencing window for improved safety ([#21033](https://github.com/ethereum-optimism/optimism/pull/21033)). Additionally, the `AdvancingClock` in `op-service` was made continuous, replacing the tick-pumped implementation for more precise time progression ([#20995](https://github.com/ethereum-optimism/optimism/pull/20995)).

### Critical Bug Fixes and Deterministic Builds
A bug in `op-chain-ops` was fixed to correctly handle `check-prestate` after the Kona monorepo merge ([#21036](https://github.com/ethereum-optimism/optimism/pull/21036)). The `contracts-bedrock` package also received a fix to ensure deterministic `semver-lock` artifact selection, preventing issues when Forge emits multiple artifacts for the same source contract ([#21058](https://github.com/ethereum-optimism/optimism/pull/21058)).

### Documentation and Dependency Updates
Documentation for node operators was updated to default to `op-reth`, reflecting the upcoming End-of-Support for `op-geth` ([#21052](https://github.com/ethereum-optimism/optimism/pull/21052)). A new guide was added for safely updating Reth dependencies within the project ([#21009](https://github.com/ethereum-optimism/optimism/pull/21009)). The `op-deployer`'s `superchain-registry` dependency was updated to include `op-contracts/v7.0.0-rc.4` tags ([#21045](https://github.com/ethereum-optimism/optimism/pull/21045)).

## CLOSED ISSUES

### Supernode Stability and Interoperability Improvements
Several issues related to `op-supernode` stability and interoperability were closed. This includes addressing the `RewindToTimestamp` retry-verify workaround for op-reth race conditions ([#19772](https://github.com/ethereum-optimism/optimism/issues/19772)) and resolving issues where rewind/invalidation paths could deadlock ([#20929](https://github.com/ethereum-optimism/optimism/issues/20929)). The `TestSupernodeLogBackfill_HappyPath` flake was also addressed, with the underlying fix already present in `develop` ([#20690](https://github.com/ethereum-optimism/optimism/issues/20690)).

### Addressing Flaky Tests and Bootstrap Incompatibilities
A recurring flaky test, `TestSupernodeResyncResumesAtActivation_PostActivation`, was investigated and a fix was drafted to address the root cause of the assertion failure during supernode shutdown ([#20944](https://github.com/ethereum-optimism/optimism/issues/20944)). An incompatibility between `op-reth`'s minimal Bedrock bootstrap and storage v2 was resolved, preventing node panics on launch ([#20821](https://github.com/ethereum-optimism/optimism/issues/20821)).

### Contracts and Feature Flag Management
The issue of nondeterministic `semver-lock` generation for duplicate compiler-profile artifacts in `contracts-bedrock` was closed ([#21032](https://github.com/ethereum-optimism/optimism/issues/21032)). Additionally, the problem of silent drift between feature flag definitions and the CI matrix was closed with documentation ([#20340](https://github.com/ethereum-optimism/optimism/issues/20340)).

### Dispute Game and L2 Support
The task of merging chains into a shared dispute game, specifically regarding message invalidation, was closed ([#19702](https://github.com/ethereum-optimism/optimism/issues/19702)). Support for Osaka-on-L2 in `op-reth` was also completed ([#18751](https://github.com/ethereum-optimism/optimism/issues/18751)).

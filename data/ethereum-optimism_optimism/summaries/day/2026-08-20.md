# ethereum-optimism/optimism Daily Update (Aug 20, 2026)
## OVERVIEW 
Today's development focused on significant infrastructure improvements, including porting `op-node SafeDB` to Rust, refining Sequencer Defined Metering (SDM) testing, and enhancing documentation for developer workflows and security. Interoperability within the Superchain also saw updates with configurable AltDA input limits and ZK challenge support in `op-challenger`.

## KEY TECHNICAL DEVELOPMENTS

### Core Infrastructure & Interoperability Enhancements
- **Rust Port of SafeDB**: The `op-node SafeDB` was ported to Rust as `kona-safedb`, providing a 1-to-1 functional equivalent for tracking L2 safe heads per L1 block, crucial for fault proofs and interop systems ([#21522](https://github.com/ethereum-optimism/optimism/pull/21522)).
- **Configurable AltDA Input Limits**: The AltDA input size limit was made configurable, allowing operators to adjust it for Keccak derivation and batcher validation, ensuring alignment with Kona strict config parsing ([#22496](https://github.com/ethereum-optimism/optimism/pull/22496)).
- **ZK Challenge Support in op-challenger**: The `op-challenger move --attack` command now supports ZK challenges by detecting the on-chain game type before constructing transactions ([#22575](https://github.com/ethereum-optimism/optimism/pull/22575)).

### Developer Workflow & Documentation Improvements
- **Enhanced Developer Workflow Documentation**: New guidelines were added to `AGENTS.md`, requiring agents to watch CI after pushing to a PR and to run local review-agent passes before opening a PR, aiming to improve code quality and reduce CI failures ([#22574](https://github.com/ethereum-optimism/optimism/pull/22574), [#22572](https://github.com/ethereum-optimism/optimism/pull/22572)).
- **Security Review Publication**: The final Cantina security review report for Upgrade 20 was added to the documentation, providing transparency on protocol security ([#22559](https://github.com/ethereum-optimism/optimism/pull/22559)).
- **Go Code Reviewer Agent**: A new `go-code-reviewer` agent was added to Claude, mirroring the existing Rust reviewer, to enforce consistent code quality and style for Go contributions ([#22561](https://github.com/ethereum-optimism/optimism/pull/22561)).

### Protocol Refinements & Bug Fixes
- **SDM Testing Refinement**: Public warming production in Sequencer Defined Metering (SDM) was replaced with a test fixture, retaining mechanism coverage through an unpublished fixed-refund fixture node while maintaining derivation, stock-verifier, replay/accounting, and fault-proof coverage ([#22222](https://github.com/ethereum-optimism/optimism/pull/22222)).
- **Dispute Game Config Validation**: The `OPContractsManagerMigrator.migrate()` function was updated to validate dispute game configurations, preventing the registration of `SUPER_PERMISSIONED` games without proper checks ([#22441](https://github.com/ethereum-optimism/optimism/pull/22441)).
- **Removal of Cross-Unsafe Chain-Head Notion**: The `cross-unsafe` chain-head notion was removed from `op-node`, `op-service`, and `op-devstack`, as it was an `op-supervisor-era` vestige no longer relevant to the current interop design ([#22555](https://github.com/ethereum-optimism/optimism/pull/22555)).

## CLOSED ISSUES

### Interop and Proposer Improvements
- **Proposer Claim Data Anchoring**: The issue regarding the proposer claiming data fetched to anchor on a blockhash has been closed, indicating that the `kona-sp1` proposer now pins sync reads to the L1 block hash ([#18411](https://github.com/ethereum-optimism/optimism/issues/18411)).
- **Kona SafeDB Implementation**: The issue tracking the implementation of SafeDB in Kona has been closed, following the successful port of `op-node SafeDB` to Rust ([#20278](https://github.com/ethereum-optimism/optimism/issues/20278)).

### Removal of Legacy Interop Concepts
- **Cross-Unsafe Chain-Head Notion Removal**: The issue to remove the `cross-unsafe` chain-head notion from Go components (`op-node`, `op-service`, `op-devstack`) has been closed. This vestigial concept from the `op-supervisor-era` is no longer relevant to the current interop design ([#22550](https://github.com/ethereum-optimism/optimism/issues/22550)).

## NEW ISSUES

### Interoperability and Node Operation Challenges
- **Sequencer Performance Bottleneck**: A new issue highlights that `SimpleAsyncGossiper.Clear()` blocks the sequencer during remote-signer HTTP calls, shortening the block build window and potentially impacting performance ([#22554](https://github.com/ethereum-optimism/optimism/issues/22554)).
- **Dispute Game Retirement**: An issue proposes retiring non-super-root dispute games, making super-root games the default for new deployments once U20 ships ([#22571](https://github.com/ethereum-optimism/optimism/issues/22571)).
- **Kona Engine Cross-Safe Promotion Warning**: The `kona-engine` routinely warns about cross-safe promotion clamps after a reset rewinds local-safe, indicating a potential diagnostic issue under interop ([#22583](https://github.com/ethereum-optimism/optimism/issues/22583)).

### RPC and Deployment Configuration
- **`op-reth` Pre-Bedrock `eth_getLogs` Bug**: A bug has been reported where `op-reth` returns an empty result for pre-Bedrock `eth_getLogs` requests, even when logs exist and are returned by other methods ([#22573](https://github.com/ethereum-optimism/optimism/issues/22573)).
- **`op-deployer` Bond Configuration**: There is a need for `op-deployer` to support setting `initBond` separately from `challengerBond` via `netchef` ([#22584](https://github.com/ethereum-optimism/optimism/issues/22584)).

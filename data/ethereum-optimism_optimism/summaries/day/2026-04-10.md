# ethereum-optimism/optimism Daily Update (Apr 10, 2026)

## OVERVIEW
Today's development focused on significant Rust updates, including upgrading `reth` to v2.0.0 and enhancing `kona-genesis` with custom sequencer drift. Key bug fixes addressed flashblocks transfer flakiness and batch type handling. Documentation was improved with a deprecation notice, and new tests were added for fault proof programs.

## KEY TECHNICAL DEVELOPMENTS

### Rust Ecosystem Enhancements & Protocol Refinements
The Rust workspace saw a major upgrade with `reth` updated to `v2.0.0` ([#19989](https://github.com/ethereum-optimism/optimism/pull/19989)), ensuring alignment with `alloy` and `revm` dependencies. `kona-genesis` was enhanced with a `rollup_config_override` feature, allowing custom `fjord_max_sequencer_drift` for `RollupConfig` ([#19994](https://github.com/ethereum-optimism/optimism/pull/19994)). A critical fix in `kona` now returns an error instead of panicking on unknown batch types, improving robustness and matching the OP spec ([#20000](https://github.com/ethereum-optimism/optimism/pull/20000)).

### Testing and Documentation Improvements
Acceptance tests for flashblocks transfer were made more reliable by switching to `op-rbuilder` and resolving a cleanup deadlock ([#19985](https://github.com/ethereum-optimism/optimism/pull/19985)). A new proof test was added to `op-e2e` to verify correct handling of batcher address changes within the `channel_timeout` window ([#20021](https://github.com/ethereum-optimism/optimism/pull/20021)). Documentation was updated with a notice regarding the deprecation of Req/Res CL sync ([#19998](https://github.com/ethereum-optimism/optimism/pull/19998)).

### Infrastructure Cleanup and Maintenance
References to OPCMv1 were mechanically cleaned up across the codebase, including CI configurations, documentation, and various Go packages ([#19919](https://github.com/ethereum-optimism/optimism/pull/19919)). The `op-revm` crate received a new `README.md` and `no_std` CI coverage, improving its documentation and testability ([#19962](https://github.com/ethereum-optimism/optimism/pull/19962)).

## ACTIVE ISSUES

### Receipt Root Mismatch ([#19930](https://github.com/ethereum-optimism/optimism/issues/19930))
Discussion continues on the `receipt root mismatch` issue, which is causing syncing problems for older chains with specific hardforks. The core problem is identified in `op-reth/crates/consensus/src/proof.rs`, where the receipt trie was being built with `encode_2718`, which includes `deposit_nonce`, but pre-Canyon `op-geth` rules require this field to be omitted. A secondary issue is in `validation/mod.rs`, where `receipt_root_bloom` was unconditionally trusted. The fix requires both correcting trie encoding with Canyon-awareness and gating the `receipt_root_bloom` shortcut. The issue has been observed on other op-stack rollups similar to Manta Pacific, suggesting a broader impact from an upstream change.

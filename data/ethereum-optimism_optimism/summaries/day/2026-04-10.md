# ethereum-optimism/optimism Daily Update (Apr 10, 2026)

## OVERVIEW
Today's development focused on significant Rust updates, including upgrading `reth` to v2.0.0 and enhancing `kona-genesis` with custom sequencer drift. Key bug fixes addressed flashblocks transfer flakiness and batch type handling. Documentation was improved with a deprecation notice, and a new proof test was added for batcher changes.

## KEY TECHNICAL DEVELOPMENTS

### Core Protocol Enhancements & Rust Tooling
The `reth` dependency in the Rust workspace was updated to `v2.0.0` ([#19989](https://github.com/ethereum-optimism/optimism/pull/19989)), aligning with `alloy 1.8.2` and `revm 36.0.0`. A new `rollup_config_override` feature was added to `kona-genesis`, allowing for custom `fjord_max_sequencer_drift` ([#19994](https://github.com/ethereum-optimism/optimism/pull/19994)). Additionally, a `README` and `no_std` CI coverage were added to `op-revm` ([#19962](https://github.com/ethereum-optimism/optimism/pull/19962)).

### Bug Fixes and Test Improvements
A critical fix was implemented for `TestFlashblocksTransfer` by switching to the `op-rbuilder` flashblock stream, resolving flakiness and a cleanup deadlock ([#19985](https://github.com/ethereum-optimism/optimism/pull/19985)). The `kona` protocol was improved to return an error instead of panicking on unknown batch types, aligning with the OP spec ([#20000](https://github.com/ethereum-optimism/optimism/pull/20000)). A new `op-e2e` proof test was added to verify correct handling of batcher address changes within the `channel_timeout` window ([#20021](https://github.com/ethereum-optimism/optimism/pull/20021)).

### Documentation and Cleanup
A deprecation notice for Req/Res CL sync was added to the public documentation ([#19998](https://github.com/ethereum-optimism/optimism/pull/19998)). Mechanical cleanup removed `OpcmImpl` compatibility shims, `ReadSuperchainDeployment` v1 fields, and related CI and documentation references ([#19919](https://github.com/ethereum-optimism/optimism/pull/19919)).

## ACTIVE ISSUES

### Receipt Root Mismatch ([#19930](https://github.com/ethereum-optimism/optimism/issues/19930))
The discussion on the receipt root mismatch issue highlights that the core problem lies in `op-reth/crates/consensus/src/proof.rs`, where the receipt trie was incorrectly built with `encode_2718` for pre-Canyon op-geth rules. This led to the inclusion of `deposit_nonce` which should have been omitted. A secondary issue was identified in `validation/mod.rs`, where the precomputed `receipt_root_bloom` was unconditionally trusted, allowing incorrect roots to pass validation. The proposed fix requires both correcting the trie encoding with Canyon-awareness in `proof.rs` and gating the `receipt_root_bloom` shortcut to prevent its use for block validation. Testing on other old op-stack rollups like Aevo Mainnet and Manta Pacific confirmed the same receipt root mismatch issue, suggesting the problem was introduced from an upstream change about three months ago.

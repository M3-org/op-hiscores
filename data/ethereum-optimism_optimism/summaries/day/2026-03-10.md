# ethereum-optimism/optimism Daily Update (Mar 10, 2026)
## OVERVIEW 
Today's development focused on enhancing the OP Stack with new features for Kona, critical CI/CD pipeline fixes, and significant progress in Rust-based infrastructure. Several bug fixes addressed issues in batcher transactions and CI artifact capture, while new acceptance tests were introduced for the Rust stack.

## KEY TECHNICAL DEVELOPMENTS

### Kona Feature Development & Infrastructure
New scaffolding was added to make Kona the default respected game type, indicating a strategic shift towards Kona integration within the OP Stack ([#19117](https://github.com/ethereum-optimism/optimism/pull/19117)). This is complemented by the removal of dead code related to `EthereumDataSourceVariant` in Kona's derive module ([#19341](https://github.com/ethereum-optimism/optimism/pull/19341)) and the removal of `kona-supervisor` remnants ([#19470](https://github.com/ethereum-optimism/optimism/pull/19470)), streamlining the Kona codebase.

### CI/CD Pipeline Enhancements and Fixes
Significant work was done to improve the CI/CD pipelines. This includes adding required gate jobs for Rust CI ([#19453](https://github.com/ethereum-optimism/optimism/pull/19453)), fixing a SIGPIPE error in `kona-build-release` skip logic ([#19467](https://github.com/ethereum-optimism/optimism/pull/19467)), and ensuring `vm-compat` findings JSON is captured as a CI artifact ([#19442](https://github.com/ethereum-optimism/optimism/pull/19442)). Additionally, the `kona-build-release` job will now skip on PRs that don't touch Rust files, optimizing build times ([#19459](https://github.com/ethereum-optimism/optimism/pull/19459)).

### Rust Stack Testing and Bug Fixes
Acceptance tests were introduced to run against the Rust stack (Kona/op-reth), improving test coverage and reliability ([#19222](https://github.com/ethereum-optimism/optimism/pull/19222)). A critical bug fix was implemented in `CalldataSource` to accept EIP-4844 type-3 batcher transactions in Kona's derive module, preventing silent dropping of these transactions ([#19355](https://github.com/ethereum-optimism/optimism/pull/19355)). Another fix addressed the flashblocks preset sequencer EL selection in `op-devstack` ([#19458](https://github.com/ethereum-optimism/optimism/pull/19458)).

## CLOSED ISSUES

### Kona Codebase Cleanup
The orphaned `sources/variant.rs` file in `kona-derive`, which contained dead code and referenced a non-existent `AsyncIterator`, has been removed ([#19340](https://github.com/ethereum-optimism/optimism/issues/19340)). This cleanup improves code maintainability and removes unused components.

### Batcher Transaction Handling Fix
A critical issue where `CalldataSource` in Kona silently dropped EIP-4844 (type 3) batcher transactions pre-Ecotone has been resolved ([#19352](https://github.com/ethereum-optimism/optimism/issues/19352)). This fix ensures proper handling of all batcher transaction types, aligning Kona's behavior with `op-node`.

## NEW ISSUES

### Legacy Interface Call Removal
An issue has been opened to remove legacy interface calls in `L2ContractsManager` ([#19468](https://github.com/ethereum-optimism/optimism/issues/19468)). The `_loadFullConfig()` method currently uses all-caps function names for compatibility with production predeploys, which should be updated after the Karst Upgrade.

## ACTIVE ISSUES

### Kona Karst Hardfork Follow-up Cleanups
Discussion continues on follow-up cleanups from the Karst hardfork PR #19372 ([#19450](https://github.com/ethereum-optimism/optimism/issues/19450)). The latest comment from @sebastianst agrees that the implicit behavior of scheduling a fork while a prior one is not should be removed, and a rollup config should be considered invalid in such cases. This highlights a focus on robust fork scheduling and configuration validation.

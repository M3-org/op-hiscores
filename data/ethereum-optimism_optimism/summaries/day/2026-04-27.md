# ethereum-optimism/optimism Daily Update (Apr 27, 2026)
## OVERVIEW 
Today's development focused on optimizing precompile input sizes, enhancing Supernode metrics, improving `op-node`'s L1 beacon client, and refining dispute game logic. Several critical bug fixes were implemented, alongside significant refactoring of `ProtocolVersions` support across the stack.

## KEY TECHNICAL DEVELOPMENTS

### Precompile Optimization and Interoperability Enhancements
*   The `bn256Pairing` precompile's maximum input size was reduced for the Karst hardfork to improve efficiency ([#20250](https://github.com/ethereum-optimism/optimism/pull/20250)).
*   Cycle detection was added to `MessageGraph` in Kona to prevent circular dependencies in cross-chain messages, aligning with `op-supernode`'s behavior ([#20303](https://github.com/ethereum-optimism/optimism/pull/20303)).
*   A new contract, `OPContractsManagerMigrationValidator`, was introduced to validate L1 contract configurations post-interop migration ([#19946](https://github.com/ethereum-optimism/optimism/pull/19946)).

### Node Stability and Monitoring Improvements
*   `op-supernode` now includes Supernode-level Prometheus metrics for better monitoring and diagnostics ([#20242](https://github.com/ethereum-optimism/optimism/pull/20242)).
*   A `--l1.beacon.slot-duration-override` flag was added to `op-node` to bypass beacon spec fetches, useful for devnets ([#20288](https://github.com/ethereum-optimism/optimism/pull/20288)).
*   Bug fixes addressed `op-node` pipeline resets for graceful EL restarts ([#20310](https://github.com/ethereum-optimism/optimism/pull/20310)) and improved management of `e.localSafeHead` in the engine controller ([#20352](https://github.com/ethereum-optimism/optimism/pull/20352)).
*   A signer grace period was added to `op-node`'s P2P block signature verification to handle L1 unsafe block signer rotations smoothly ([#20063](https://github.com/ethereum-optimism/optimism/pull/20063)).

### Dispute Game and Fetcher Logic Refinements
*   `op-challenger`'s `run-trace` now ages game inputs to simulate dispute games created on proposals just above the anchor state ([#20252](https://github.com/ethereum-optimism/optimism/pull/20252)).
*   A fix in `op-fetcher` guards against zero `mipsImpl` before calling `oracle()` to prevent issues when the permissioned game slot holds an address of zero ([#20347](https://github.com/ethereum-optimism/optimism/pull/20347)).

### Core Stack Refactoring and Cleanup
*   Deprecated `ProtocolVersions` support was removed from the Rust stack (`op-alloy`, `kona`, `op-reth`) and remaining Go references were cleaned up, completing a significant refactoring effort ([#20317](https://github.com/ethereum-optimism/optimism/pull/20317)).

## CLOSED ISSUES

### Interoperability and Migration Validation
*   An issue regarding the validation of interop migration success was closed, indicating that mechanisms are now in place to check that two chains in the interop set have the same lockbox and other configurations after `opcm.migrate()` ([#16033](https://github.com/ethereum-optimism/optimism/issues/16033)).

### Precompile and Cycle Detection Consistency
*   The issue concerning the reduction of `bn256pairing` input length due to the upcoming Glamsterdam L1 hard fork and EIP-7904 was closed ([#20195](https://github.com/ethereum-optimism/optimism/issues/20195)).
*   The review of cycle detection implementations to ensure consistency between `supernode` and Kona-proofs was completed and the issue closed ([#20196](https://github.com/ethereum-optimism/optimism/issues/20196)).

### `op-node` Runtime Configuration and `op-interop-filter` Stability
*   The problem of `op-node` verifier nodes experiencing a stale signer window during L1 `SystemConfig` contract rotations was addressed and closed, likely by the implementation of a signer grace period ([#19981](https://github.com/ethereum-optimism/optimism/issues/19981)).
*   The issue where `op-interop-filter` could stall or take a long time on restart due to an unbounded backward scan when resuming from an existing logs DB was fixed and closed ([#20362](https://github.com/ethereum-optimism/optimism/issues/20362)).

### Deprecated ProtocolVersions Removal
*   The task to remove deprecated `ProtocolVersions` support from Kona, `op-reth`, and remaining Go references was successfully completed and the issue closed ([#20316](https://github.com/ethereum-optimism/optimism/issues/20316)).

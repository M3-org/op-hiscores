# ethereum-optimism/optimism Daily Update (Mar 27, 2026)
## OVERVIEW 
Today's development focused on enhancing L2 contract functionality with new feature flags, improving Superchain migration processes, and significant documentation migration. Several bug fixes and test improvements were also implemented.

## KEY TECHNICAL DEVELOPMENTS

### L2 Contract Enhancements and Customization
New feature flags were added to `L1Block` for production system customization, allowing depositor-only feature enablement and public checking. This enhances the flexibility and control over L2 contract behavior ([#19668](https://github.com/ethereum-optimism/optimism/pull/19668)). Additionally, informational findings from an internal review of L2 Contracts Manager were resolved, improving contract robustness ([#19783](https://github.com/ethereum-optimism/optimism/pull/19783)).

### Superchain Migration and Interoperability Improvements
The `op-devstack` now utilizes EIP-7702 SetCode for OPCM migration delegatecalls, streamlining the migration process and replacing a complex deploy-transfer-execute-restore pattern ([#19745](https://github.com/ethereum-optimism/optimism/pull/19745)). Weekly L2 fork tests were also introduced to ensure compatibility across different OP Stack chains and prevent unexpected reverts during upgrades ([#19793](https://github.com/ethereum-optimism/optimism/pull/19793)).

### Documentation and Testing Infrastructure
A major effort was completed to migrate Rust documentation from Vocs to Mintlify, unifying the documentation platform and improving accessibility ([#19778](https://github.com/ethereum-optimism/optimism/pull/19778)). Contract test coverage was significantly improved for `LegacyMintableERC20` and `ETHLiquidity` through fuzz tests and event emission assertions ([#19557](https://github.com/ethereum-optimism/optimism/pull/19557), [#19665](https://github.com/ethereum-optimism/optimism/pull/19665)). A new test was also added to verify double upgrade calls for OPCM, ensuring upgrade path resilience ([#19724](https://github.com/ethereum-optimism/optimism/pull/19724)).

## CLOSED ISSUES

### Flaky Test Resolution
The flaky test `TestPreinteropFaultProofs_TraceExtensionActivation` ([#19760](https://github.com/ethereum-optimism/optimism/issues/19760)) was closed. The issue was identified as a nonce race condition during the `migrateSuperRoots` process, where `PendingNonceAt` could return a stale value, leading to transaction collisions. The fix, implemented in [#19745](https://github.com/ethereum-optimism/optimism/pull/19745), replaces the problematic deploy-transfer-execute-restore pattern with EIP-7702 SetCode transactions, eliminating the multi-transaction window and nonce management issues.

### L2ProxyAdmin Refactoring and Access Control
The issue regarding refactoring `L2ProxyAdmin` to use the Initializable pattern ([#19182](https://github.com/ethereum-optimism/optimism/issues/19182)) was closed, with the conclusion that there was no strong reason to proceed with the refactor. Additionally, the task to add `ProxyAdminOwnedBase` access control to predeploy `initialize()` functions ([#19313](https://github.com/ethereum-optimism/optimism/issues/19313)) was closed, confirming that this functionality has been implemented as part of [#19668](https://github.com/ethereum-optimism/optimism/pull/19668).

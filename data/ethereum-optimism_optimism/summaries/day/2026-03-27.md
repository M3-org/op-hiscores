# ethereum-optimism/optimism Daily Update (Mar 27, 2026)
## OVERVIEW 
Today's development focused on enhancing L2 contract functionality with new feature flags, improving fault proof mechanisms, and significant documentation migration. Several bug fixes and test coverage improvements were also implemented.

## KEY TECHNICAL DEVELOPMENTS

### L2 Contract Enhancements and Customization
New feature flags were added to the `L1Block` contract for production system customization, allowing depositor-only feature enablement and public checking of feature status ([#19668](https://github.com/ethereum-optimism/optimism/pull/19668)). Bug fixes addressed informational findings in the L2 Contracts Manager, including a `code.length` check in `L2ProxyAdmin.upgradePredeploys()` to prevent reverts if `L2ContractsManager` is not deployed ([#19783](https://github.com/ethereum-optimism/optimism/pull/19783)). Specifications for the L2 Contracts Manager were also updated to include OZ slot clearing details and downgrade prevention invariants ([#19774](https://github.com/ethereum-optimism/optimism/pull/19774)).

### Fault Proof System Improvements
The `op-devstack` now utilizes EIP-7702 SetCode for OPCM migration delegatecalls, replacing the previous deploy-transfer-execute-restore pattern to streamline `migrateSuperRoots` and `addGameTypeForRuntime` operations ([#19745](https://github.com/ethereum-optimism/optimism/pull/19745)). A workaround was implemented in `op-supernode` to address an `op-reth` ForkchoiceUpdate rewind edge case by adding a 50ms sleep between back-to-back FCU calls in `RewindToTimestamp` ([#19773](https://github.com/ethereum-optimism/optimism/pull/19773)).

### Documentation and Testing Infrastructure
Documentation for Kona, `op-reth`, and `op-alloy` was migrated from Vocs to the unified Mintlify docs, converting 140 MDX files and updating CI configurations ([#19778](https://github.com/ethereum-optimism/optimism/pull/19778)). A new weekly CI job was added to run L2 upgrade fork tests against all supported OP Stack chains, addressing potential issues with chains running different contract versions ([#19793](https://github.com/ethereum-optimism/optimism/pull/19793)). Test coverage was improved for `LegacyMintableERC20` by converting hardcoded tests to fuzz tests and adding event emission assertions ([#19557](https://github.com/ethereum-optimism/optimism/pull/19557)), and for `ETHLiquidity` by fixing and fuzzing a test case related to `mint_moreThanAvailableBalance_fails` ([#19665](https://github.com/ethereum-optimism/optimism/pull/19665)). A new test was also added to verify that the OPCM upgrade function can be called twice without reverting ([#19724](https://github.com/ethereum-optimism/optimism/pull/19724)).

## CLOSED ISSUES

### Flaky Test Resolution
The flaky test `TestPreinteropFaultProofs_TraceExtensionActivation` ([#19760](https://github.com/ethereum-optimism/optimism/issues/19760)) was closed. The issue was identified as a nonce race condition in the old `migrateSuperRoots` code, where `PendingNonceAt` could return a stale value, leading to transaction collisions. The fix, implemented in PR [#19745](https://github.com/ethereum-optimism/optimism/pull/19745), replaces the problematic deploy-transfer-execute-restore pattern with EIP-7702 SetCode transactions, eliminating the multi-transaction window and nonce management issues.

### L2ProxyAdmin Refactoring and Access Control
The issue regarding refactoring `L2ProxyAdmin` to use the Initializable pattern ([#19182](https://github.com/ethereum-optimism/optimism/issues/19182)) was closed, with the conclusion that there is no strong reason to implement this change. Additionally, the issue concerning adding `ProxyAdminOwnedBase` access control to predeploy `initialize()` functions in L2CM ([#19313](https://github.com/ethereum-optimism/optimism/issues/19313)) was closed, confirming that this has been addressed by PR [#19668](https://github.com/ethereum-optimism/optimism/pull/19668).

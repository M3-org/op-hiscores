# ethereum-optimism/optimism Daily Update (May 7, 2026)

## OVERVIEW 
Today's development focused on significant enhancements to the `op-reth` trie engine with new persistence and buffer layers, alongside critical bug fixes across acceptance tests, devstack, and contract migrations.

## KEY TECHNICAL DEVELOPMENTS

### `op-reth` Trie Engine Enhancements
The `op-reth` component saw major architectural improvements with the introduction of a persistence service and an in-memory buffer layer. These additions are crucial for atomically writing block updates, pruning old state, and optimizing the block execution pipeline.
- Added a persistence service for the trie engine, enabling background writing of block updates and atomic pruning of old state ([#20414](https://github.com/ethereum-optimism/optimism/pull/20414)).
- Implemented an in-memory buffer layer (`TrieBufferState` + `MemoryOverlay`) to sit between block execution and persistence, improving engine architecture ([#20411](https://github.com/ethereum-optimism/optimism/pull/20411)).
- Introduced an optional `gas_limit_cap` argument to `execute_best_transactions` in `op-reth`'s payload builder ([#20584](https://github.com/ethereum-optimism/optimism/pull/20584)).

## ACTIVE ISSUES

### Kona and op-node Brotli Channel Disagreement ([#19333](https://github.com/ethereum-optimism/optimism/issues/19333))
The investigation into brotli channel disagreements between Kona and op-node has progressed significantly. The latest comments reveal that the Rust `brotli` crate used by Kona is not spec-compliant, silently accepting corrupted streams and producing incorrect output, which is a consensus-relevant issue. A proposed fix involves landing a Kona wrapper-bug fix to eliminate most divergences, followed by investigating residual corruption-only divergences. The discussion also clarified that a library swap is likely unnecessary, as both Go libraries behave identically and match the reference C library. The path forward includes landing the wrapper fix, investigating remaining divergences, and ensuring strict-mode parity for both sides.

### Kona Frame Parsing Mismatch ([#19335](https://github.com/ethereum-optimism/optimism/issues/19335))
This issue, concerning Kona's frame parsing mismatch against op-node and OP Stack Specs, has been acknowledged and a fix is in progress. The latest comment confirms that a fix is being implemented via pull request [#20590](https://github.com/ethereum-optimism/optimism/pull/20590).

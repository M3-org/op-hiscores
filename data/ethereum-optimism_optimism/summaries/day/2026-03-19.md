# ethereum-optimism/optimism Daily Update (Mar 19, 2026)
## OVERVIEW 
Today's development focused heavily on stability and performance, with numerous bug fixes addressing flaky tests, OOM issues in op-reth, and race conditions in the TCP proxy. Significant progress was also made on documentation migration and Docker build optimizations.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced Test Stability and Reliability
Multiple flaky acceptance tests were addressed, improving the robustness of the CI pipeline. This included fixing issues with `TestSupernodeInteropChainLag` by waiting for preconditions ([#19614](https://github.com/ethereum-optimism/optimism/pull/19614)), increasing timeouts in `ELSync` tests ([#19613](https://github.com/ethereum-optimism/optimism/pull/19613)), and resolving flake vectors in `TestUnsafeChainNotStalling_DisabledReqRespSync` ([#19612](https://github.com/ethereum-optimism/optimism/pull/19612)). A race condition in `TestBroadcastWithSlowClient` was also stabilized ([#19594](https://github.com/ethereum-optimism/optimism/pull/19594)).

### Critical Bug Fixes and Performance Improvements
Several critical bugs were resolved, enhancing the overall system's stability and performance. A fix was implemented in `op-node` to correctly validate span batches by adding a `SetCodeTxType` check ([#19150](https://github.com/ethereum-optimism/optimism/pull/19150)). `op-reth` saw significant performance improvements by replacing `HashMap` with sequential grouping in `store_entries` to prevent OOM errors ([#19664](https://github.com/ethereum-optimism/optimism/pull/19664)) and removing metrics wrappers from CLI commands ([#19663](https://github.com/ethereum-optimism/optimism/pull/19663)). A race condition in the TCP proxy's `Close()` method that caused test hangs was also fixed ([#19662](https://github.com/ethereum-optimism/optimism/pull/19662)).

### Infrastructure and Documentation Updates
Key infrastructure improvements include the migration of all public documentation into the monorepo ([#19616](https://github.com/ethereum-optimism/optimism/pull/19616)), streamlining the documentation process. Docker build workflows were optimized with per-image change detection ([#19603](https://github.com/ethereum-optimism/optimism/pull/19603)). Additionally, Go was bumped to version 1.24.13 to incorporate security fixes, though a revert was made from DHI to stock golang Docker images due to CI failures ([#19669](https://github.com/ethereum-optimism/optimism/pull/19669), [#19666](https://github.com/ethereum-optimism/optimism/pull/19666)).

## ACTIVE ISSUES

### op-node: Initial EL Sync UX and Correctness ([#17631](https://github.com/ethereum-optimism/optimism/issues/17631))
The discussion continues on the correct initialization of safe and finalized heads after initial EL sync. The current implementation is deemed incorrect as it sets safe/finalized to the unsafe head, rather than respecting L1 finalization. Option 2, proposed by @trianglesphere, suggests setting safe/finalized to the unsafe head minus the sequencer window (approx. 12 hours). This approach balances correctness with improved UX by reducing derivation time compared to starting from genesis. Option 3, allowing external sourcing of safe/finalized heads, offers the best UX but adds complexity and trust dependencies. The consensus leans towards Option 2 as a reasonable compromise.

### [tracking]: Review kona-interop block hash oracle ([#18288](https://github.com/ethereum-optimism/optimism/issues/18288))
The focus is on ensuring the `kona-interop` block hash oracle works correctly, especially for looking up blocks prior to the current history window. The goal is to transition an existing action test to an acceptance test using `op-supernode` instead of `op-supervisor`. The challenge lies in generating sufficient chain history for the test, with `op-acceptance-tests` offering time travel capabilities and `sys.AdvanceTime` as potential solutions.

### non-terminating CI job: memory-all-opn-op-geth ([#19563](https://github.com/ethereum-optimism/optimism/issues/19563))
The `memory-all-opn-op-geth` CI job continues to experience indefinite hangs, specifically with `TestChallengerPlaysGame` and `TestProposer` in `interop/proofs` hitting 2-hour subtest timeouts. The root cause has been identified as `FailNow` firing inside `testify.Eventually` goroutines within `WaitForGame()` and `awaitMinVerifiedTimestamp()`, causing the goroutine to die silently and `Eventually` to block indefinitely. A fix is proposed to replace fatal assertions with error-returning variants within `Eventually` conditions and to isolate test packages to prevent hangs in one test from affecting others.

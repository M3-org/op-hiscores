## ACTIVE ISSUES

### Initial EL Sync UX and Correctness ([#17631](https://github.com/ethereum-optimism/optimism/issues/17631))
Discussion continues on the initial EL Sync behavior, particularly regarding the correctness of setting safe and finalized heads. The current implementation is deemed incorrect as it sets safe/finalized to the unsafe head after initial sync, rather than respecting L1 finalization. Option 2 (setting safe/finalized to unsafe head minus sequencer window) is gaining traction as a balanced approach between correctness and UX, requiring derivation of approximately 12 hours of data. The possibility of using an external source for safe/finalized heads for optimal UX is also being considered, though it adds complexity.

### Review kona-interop block hash oracle ([#18288](https://github.com/ethereum-optimism/optimism/issues/18288))
The discussion revolves around ensuring the `kona-interop` block hash oracle works correctly, especially for looking up blocks prior to the current history window. The goal is to transition existing action tests to acceptance tests for better integration with `op-supernode`. Time travel capabilities in acceptance tests are being explored to generate sufficient chain history for testing, with a focus on `presets.WithTimeTravelEnabled()` and `sys.AdvanceTime`.

### Non-terminating CI job: memory-all-opn-op-geth ([#19563](https://github.com/ethereum-optimism/optimism/issues/19563))
This issue, which causes CI jobs to hang indefinitely, has seen significant progress. A root cause analysis identified a mutex deadlock in `VirtualNode` during shutdown, involving `VirtualNode.Start()`, `OpNode.Stop()`, and event loop goroutines. The deadlock occurs when the event system processes an event that calls `SyncStatus()` while `Start()` holds a mutex and begins `inner.Stop()`. A fix has been proposed in PR [#19680](https://github.com/ethereum-optimism/optimism/pull/19680) to release the mutex before calling `inner.Stop()` and add a defensive timeout to `Supernode.Stop()`. The issue is believed to be resolved with this fix.

# ethereum-optimism/optimism Daily Update (Jun 23, 2026)

## OVERVIEW 
Today's development focused on enhancing `op-reth` functionality, stabilizing the SDM PostExec consensus, and critical bug fixes across various components, including a significant update to Karst upgrade gas handling.

## KEY TECHNICAL DEVELOPMENTS

### `op-reth` Enhancements and Stability
Improvements to `op-reth` include making chainspec reth-codec opt-in ([#21483](https://github.com/ethereum-optimism/optimism/pull/21483)) and enabling `op-reth-premium` as a drop-in sequencer EL for devstack acceptance tests ([#21515](https://github.com/ethereum-optimism/optimism/pull/21515)). Critical fixes were implemented to evict invalid interop transactions during revalidation ([#21447](https://github.com/ethereum-optimism/optimism/pull/21447)) and to surface pruned block bodies as a typed error instead of a state-root mismatch ([#21495](https://github.com/ethereum-optimism/optimism/pull/21495)).

### SDM PostExec Consensus and `op-rbuilder` Improvements
The PostExec consensus surface was stabilized with a `0x7D` guard and opt-in TOCTOU ([#21502](https://github.com/ethereum-optimism/optimism/pull/21502)). Additionally, `op-rbuilder` now gates interop transactions during failsafe operations ([#21494](https://github.com/ethereum-optimism/optimism/pull/21494)).

### Core Protocol and CI/CD Fixes
A significant fix was applied to the derive component to ensure Karst upgrade gas applies only to the activation block ([#21441](https://github.com/ethereum-optimism/optimism/pull/21441)). Go dependencies were bumped to address CVEs ([#21450](https://github.com/ethereum-optimism/optimism/pull/21450)), and CI fuzz jobs were prevented from oversubscribing the CPU to avoid intermittent failures ([#21517](https://github.com/ethereum-optimism/optimism/pull/21517)). Docker builds in CI now retry package installs and network fetches for increased reliability ([#21478](https://github.com/ethereum-optimism/optimism/pull/21478)).

### Contracts and Documentation Refinements
The `SUPER_PERMISSIONED_CANNON` game type was renamed to `SUPER_PERMISSIONED` across contracts, deployer tools, and documentation ([#21513](https://github.com/ethereum-optimism/optimism/pull/21513)). The 2026-03 Kona audit was correctly attributed to Cantina in the security reviews documentation ([#21519](https://github.com/ethereum-optimism/optimism/pull/21519)).

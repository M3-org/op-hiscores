# ethereum-optimism/optimism Daily Update (Jan 7, 2026)
## OVERVIEW 
Today's development focused on enhancing contract functionality with interop migration support, improving test coverage for OptimismMintableERC20 contracts, and integrating a supernode trace provider into op-challenger.

## KEY TECHNICAL DEVELOPMENTS

### Core Contract Enhancements and Interoperability
A significant feature was added to support interop migration within OPCMv2, streamlining the process for contract upgrades and interoperability. This involved extensive changes across various contract files and deployment scripts. ([#18649](https://github.com/ethereum-optimism/optimism/pull/18649))

### Improved Test Coverage for ERC20 Contracts
Test coverage for `OptimismMintableERC20` and `OptimismMintableERC20Factory` contracts was substantially improved. This included converting focused tests to fuzz tests for broader coverage and adding tests for previously uncovered code paths, enhancing the robustness of these critical components. ([#18696](https://github.com/ethereum-optimism/optimism/pull/18696), [#18707](https://github.com/ethereum-optimism/optimism/pull/18707))

### Supernode Integration and Bug Fixes
The `op-challenger` now integrates a supernode trace provider, a step towards replacing `op-supervisor` support. Additionally, a critical bug in `op-batcher` was fixed, addressing a nil pointer dereference that could cause the batcher process to crash when `forcePublish` is true and `currentChannel` is nil. ([#18668](https://github.com/ethereum-optimism/optimism/pull/18668), [#18720](https://github.com/ethereum-optimism/optimism/pull/18720), [#18701](https://github.com/ethereum-optimism/optimism/pull/18701))

## ACTIVE ISSUES

### OPCM Version and Rollup Config Fields
Issue [#14816](https://github.com/ethereum-optimism/optimism/issues/14816) discusses the absence of Pectra rollup config fields in OPCM version 0.0.11, which introduced a new, backwards-incompatible data structure. DeborahOlaboye has requested to be assigned to this issue.

### Re-enabling Flaky Acceptance Tests
Issue [#16972](https://github.com/ethereum-optimism/optimism/issues/16972) is tracking the re-enabling of flaky acceptance tests that were previously skipped. DeborahOlaboye has requested to be assigned to this issue.

### Supernode Reporting and Consistency
Issues [#18651](https://github.com/ethereum-optimism/optimism/issues/18651) and [#18667](https://github.com/ethereum-optimism/optimism/issues/18667) highlight concerns with the `op-supernode`'s `superroot_atTimestamp` API. Specifically, [#18651](https://github.com/ethereum-optimism/optimism/issues/18651) notes that it reports the minimum L1 block processed by derivation, not necessarily by verifiers, and [#18667](https://github.com/ethereum-optimism/optimism/issues/18667) addresses potential inconsistencies due to race conditions. Both issues are noted to depend on interop support in the supernode.

### op-challenger VM Runner Update
Issue [#18669](https://github.com/ethereum-optimism/optimism/issues/18669) focuses on updating the `op-challenger` vm-runner to utilize the supernode instead of the supervisor, with no need for backwards compatibility. This change is dependent on a `syncStatus` API from the supernode.

### Kona Acceptance Test Support
Issue [#18675](https://github.com/ethereum-optimism/optimism/issues/18675) reports that `TestSequencerPreset` does not support the Kona sequencer, as discovered during attempts to run monorepo acceptance tests targeting `kona-node`. User crStiv has expressed interest in working on this issue.

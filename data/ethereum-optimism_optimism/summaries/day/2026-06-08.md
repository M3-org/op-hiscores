# ethereum-optimism/optimism Daily Update (Jun 8, 2026)
## OVERVIEW 
Today's development focused on enhancing interop filter validation, introducing a new CLI for cross-chain messaging smoke-testing, and significant progress in decoupling `op-program` from the monorepo. Documentation for chain operators also saw updates, particularly around `kona-client` prestate tutorials.

## KEY TECHNICAL DEVELOPMENTS

### Interoperability and Cross-Chain Messaging Enhancements
Significant work was done to improve the robustness of cross-chain messaging. A new feature was added to `op-reth` that enables multi-endpoint quorum validation for the interop filter, ensuring more reliable interop checks by fanning out requests to multiple endpoints concurrently and combining results by quorum agreement ([#21195](https://github.com/ethereum-optimism/optimism/pull/21195)). Additionally, a new CLI tool was introduced under `op-chain-ops` for smoke-testing interop cross-chain messaging against running L2 chains, including a `roundtrip` subcommand for bridging ETH between chains ([#21262](https://github.com/ethereum-optimism/optimism/pull/21262)).

### `op-program` Decoupling and Monorepo Cleanup
A major effort was made to remove `op-program` from the monorepo, marking the final step in a larger decoupling initiative. This involved decoupling `op-e2e` from `op-program` references ([#21257](https://github.com/ethereum-optimism/optimism/pull/21257)), removing the `op-program` docker image ([#21285](https://github.com/ethereum-optimism/optimism/pull/21285)), and dropping `op-program` from the `op-challenger` docker image ([#21284](https://github.com/ethereum-optimism/optimism/pull/21284)). The `op-program` directory was entirely deleted from the monorepo ([#21271](https://github.com/ethereum-optimism/optimism/pull/21271)), and `op-challenger` was updated to no longer require `--cannon-server` for the permissioned game type, as it doesn't utilize `op-program` ([#21270](https://github.com/ethereum-optimism/optimism/pull/21270)).

### Documentation Refocus and Updates
Documentation for chain operators was updated to refocus prestate tutorials on `kona-client`, archiving the `op-program` specific tutorials ([#21000](https://github.com/ethereum-optimism/optimism/pull/21000)). A draft for the Kona-client prestate verification step for Upgrade 19 was also added ([#21059](https://github.com/ethereum-optimism/optimism/pull/21059)). Furthermore, the releases index documentation was updated to display the latest stable versions for components ([#21280](https://github.com/ethereum-optimism/optimism/pull/21280)).

### Core Infrastructure Alignment
Work was done to align EVM hardfork to `OpSpecId` resolution and eth-base mapping across `kona-client`, `op-revm`, and `alloy-op-evm` to ensure consistency with `op-geth` ([#21291](https://github.com/ethereum-optimism/optimism/pull/21291)). A new `op-core/params` package was created to centralize OP-Stack chain configuration, including `OptimismConfig`, `ChainConfig`, and chain config loaders, as part of the `op-geth` decoupling plan ([#21287](https://github.com/ethereum-optimism/optimism/pull/21287)).

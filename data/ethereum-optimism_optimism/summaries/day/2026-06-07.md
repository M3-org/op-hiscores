# ethereum-optimism/optimism Daily Update (Jun 7, 2026)
## OVERVIEW 
Today's development focused on critical bug fixes, enhancing the robustness of the Kona host and improving the reliability of the op-challenger's VM process management.

## KEY TECHNICAL DEVELOPMENTS

### Kona Host Witness Fetching Improvements
The Kona host's witness fetching mechanism has been improved to retry witness fetches via the `get_preimage` loop instead of `debug_dbGet`. This change addresses issues where high-level hints like `debug_executePayload` and `L2BlockData` were not reliably re-fetching preimages upon initial errors, leading to more resilient optimistic-block re-execution. ([#21269](https://github.com/ethereum-optimism/optimism/pull/21269))

### Enhanced op-challenger VM Process Termination
A bug in the `op-challenger` was fixed to ensure that the VM process group is reliably torn down on timeout. Previously, the `--vm-timeout` did not consistently terminate wedged runs, especially when the VM (cannon) spawned the oracle/preimage server as a child process. This fix improves the stability and reliability of trace execution. ([#21268](https://github.com/ethereum-optimism/optimism/pull/21268))

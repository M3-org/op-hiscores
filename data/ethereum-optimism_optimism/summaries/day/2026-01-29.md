# ethereum-optimism/optimism Daily Update (Jan 29, 2026)
## OVERVIEW 
Today's development focused on enhancing the Optimism ecosystem with new features, including historical proof support for devstack, refined dispute game interfaces, and improved CI configurations. Significant progress was also made in contract testing and Docker image building for Rust-based components.

## KEY TECHNICAL DEVELOPMENTS

### Enhanced Dispute Game and Contract Management
The AnchorStateRegistry was updated to exclusively utilize the `IDisputeGame` interface, streamlining dispute game interactions [#18945](https://github.com/ethereum-optimism/optimism/pull/18945). Additionally, a new invariant test was implemented for `OPContractsManagerV2` to ensure batch upgrade operations can execute efficiently within a single transaction [#18954](https://github.com/ethereum-optimism/optimism/pull/18954).

### CI/CD and Build Process Improvements
CircleCI configurations were refactored to centralize Rust CI logic, simplifying individual project configurations for `alloy-op-evm`, `alloy-op-hardforks`, `kona`, `op-alloy`, and `op-reth` [#18956](https://github.com/ethereum-optimism/optimism/pull/18956). Docker build processes were also extended to include `op-rbuilder` and `kona-node` images [#18966](https://github.com/ethereum-optimism/optimism/pull/18966).

### Developer Tooling and Infrastructure Updates
Historical proof support was added to the devstack, improving development and testing capabilities [#18853](https://github.com/ethereum-optimism/optimism/pull/18853). The `txmgr` now offers configurable blob tip cap mechanisms, allowing for dynamic or static tip cap settings [#18981](https://github.com/ethereum-optimism/optimism/pull/18981). A fix was also implemented to increase retries for OPCM registry queries, addressing CI flakiness [#18983](https://github.com/ethereum-optimism/optimism/pull/18983).

## CLOSED ISSUES

### Dispute Game Interface Modernization
The issue of the `AnchorStateRegistry` relying on the `IFaultDisputeGame` interface was resolved, with the registry now exclusively using the more general `IDisputeGame` interface [#18943](https://github.com/ethereum-optimism/optimism/issues/18943).

### CI/CD Pipeline Streamlining
Efforts to unify and simplify Rust CI jobs were completed, leading to a more efficient and maintainable CI pipeline [#18928](https://github.com/ethereum-optimism/optimism/issues/18928).

### Batcher Configuration Flexibility
The `op-batcher` now supports configurable blob tip cap mechanisms, allowing for greater flexibility in managing transaction fees [#18949](https://github.com/ethereum-optimism/optimism/issues/18949).

## NEW ISSUES

### Supernode Integration and Testing
Several new issues were opened to integrate and test the Supernode, including integrating it into proofs acceptance tests [#18989](https://github.com/ethereum-optimism/optimism/issues/18989), running Kona proofs in native mode [#18990](https://github.com/ethereum-optimism/optimism/issues/18990), and adding Supernode support for `op-proposer` in devstack [#18991](https://github.com/ethereum-optimism/optimism/issues/18991).

### OPCM and SuperDisputeGame Enhancements
New issues focus on upgrading OPCM to convert single chains to `SuperDisputeGame` without resetting withdrawals [#18992](https://github.com/ethereum-optimism/optimism/issues/18992), designing the conversion process [#19007](https://github.com/ethereum-optimism/optimism/issues/19007), supporting merging two `SuperDisputeGame` chains [#19011](https://github.com/ethereum-optimism/optimism/issues/19011), and migrating `FaultDisputeGame` chains to `SuperDisputeGame` [#19013](https://github.com/ethereum-optimism/optimism/issues/19013).

### Rust Ecosystem Dependency Management
A series of issues were created to decouple various Rust components from `crates.io` versions of `op-alloy-rpc-types-engine` [#18996](https://github.com/ethereum-optimism/optimism/issues/18996), `op-alloy-consensus` [#18997](https://github.com/ethereum-optimism/optimism/issues/18997), `op-alloy-network` and `op-alloy-rpc-types` [#18999](https://github.com/ethereum-optimism/optimism/issues/18999), and `op-alloy` and `alloy-op-hardforks` [#19000](https://github.com/ethereum-optimism/optimism/issues/19000) to prevent type duplication.

### General Improvements and Migrations
Other new issues include adding `assertOnlyProxyAdminOrProxyAdminOwner` to L2 contracts [#19001](https://github.com/ethereum-optimism/optimism/issues/19001), supporting Supernode API in the VM runner [#19008](https://github.com/ethereum-optimism/optimism/issues/19008), and addressing an issue where HTTP L1 URLs disable polling in `op-supernode` [#19012](https://github.com/ethereum-optimism/optimism/issues/19012).

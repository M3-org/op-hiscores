# ethereum-optimism/optimism Daily Update (Jan 29, 2026)

## OVERVIEW 
Today's development focused on enhancing dispute game infrastructure, refining CI/CD processes, and improving contract upgrade mechanisms. Several new features were added, alongside a critical bug fix for OPCM registry retries.

## KEY TECHNICAL DEVELOPMENTS

### Dispute Game and Anchor State Registry Improvements
The AnchorStateRegistry was updated to exclusively use the `IDisputeGame` interface, removing its dependency on `IFaultDisputeGame` for broader compatibility. Historical proof support was also added for the devstack.
([#18945](https://github.com/ethereum-optimism/optimism/pull/18945), [#18853](https://github.com/ethereum-optimism/optimism/pull/18853))

### CI/CD and Docker Build Enhancements
CircleCI configurations were refactored to streamline Rust CI logic, and `op-rbuilder` and `kona-node` were integrated into the Docker build process, improving build efficiency and consistency.
([#18956](https://github.com/ethereum-optimism/optimism/pull/18956), [#18966](https://github.com/ethereum-optimism/optimism/pull/18966))

### Contract Upgrade Mechanism and Transaction Manager Configuration
An invariant test was added for `OPCMV2` batch upgrades, ensuring the ability to execute multiple upgrade operations in a single transaction. Additionally, the transaction manager's blob tip cap mechanism was made configurable.
([#18954](https://github.com/ethereum-optimism/optimism/pull/18954), [#18981](https://github.com/ethereum-optimism/optimism/pull/18981))

### Bug Fixes and Acceptance Test Refinements
A bug related to OPCM registry retries was fixed to prevent CI flakes. The `op-acceptance` tests were also updated to support only super nodes for super dispute games, with `op-supervisor` support removed.
([#18983](https://github.com/ethereum-optimism/optimism/pull/18983), [#18977](https://github.com/ethereum-optimism/optimism/pull/18977))

## CLOSED ISSUES

### Dispute Game Interface Modernization
The `AnchorStateRegistry` was updated to remove its dependency on `IFaultDisputeGame`, now exclusively using the more general `IDisputeGame` interface.
([#18943](https://github.com/ethereum-optimism/optimism/issues/18943))

### CI/CD Configuration Streamlining
Rust CI jobs were unified and simplified into reusable configurations, improving the efficiency of the CI pipeline.
([#18928](https://github.com/ethereum-optimism/optimism/issues/18928))

### Transaction Manager Flexibility
The blob tip cap mechanism in the `op-batcher`'s transaction manager was made configurable, allowing for more dynamic fee management.
([#18949](https://github.com/ethereum-optimism/optimism/issues/18949))

## NEW ISSUES

### Supernode and Dispute Game Integration
New issues were opened to integrate Super Node into proofs acceptance tests, run Kona proofs in native mode, and add Supernode support for `op-proposer`.
([#18989](https://github.com/ethereum-optimism/optimism/issues/18989), [#18990](https://github.com/ethereum-optimism/optimism/issues/18990), [#18991](https://github.com/ethereum-optimism/optimism/issues/18991))

### OPCM and SuperDisputeGame Upgrades
Several issues were created concerning the upgrade of OPCM to support `SuperDisputeGame`, including design docs, migration of existing chains, and launching new chains with the new game.
([#18992](https://github.com/ethereum-optimism/optimism/issues/18992), [#19007](https://github.com/ethereum-optimism/optimism/issues/19007), [#19011](https://github.com/ethereum-optimism/optimism/issues/19011), [#19013](https://github.com/ethereum-optimism/optimism/issues/19013), [#19014](https://github.com/ethereum-optimism/optimism/issues/19014), [#19015](https://github.com/ethereum-optimism/optimism/issues/19015), [#19016](https://github.com/ethereum-optimism/optimism/issues/19016), [#19017](https://github.com/ethereum-optimism/optimism/issues/19017))

### Rust Ecosystem Decoupling
A series of issues were opened to decouple various `reth` and `alloy-evm` dependencies from `crates.io` versions of `op-alloy` and `alloy-op-hardforks` to avoid type duplication within the monorepo.
([#18996](https://github.com/ethereum-optimism/optimism/issues/18996), [#18997](https://github.com/ethereum-optimism/optimism/issues/18997), [#18999](https://github.com/ethereum-optimism/optimism/issues/18999), [#19000](https://github.com/ethereum-optimism/optimism/issues/19000))

### General Improvements and Test Coverage
New issues include adding `assertOnlyProxyAdminOrProxyAdminOwner` to L2 contracts, supporting Supernode API in the VM runner, improving time control for batcher and sequencer in acceptance tests, and ensuring comprehensive Supernode test coverage.
([#19001](https://github.com/ethereum-optimism/optimism/issues/19001), [#19008](https://github.com/ethereum-optimism/optimism/issues/19008), [#19009](https://github.com/ethereum-optimism/optimism/issues/19009), [#19010](https://github.com/ethereum-optimism/optimism/issues/19010))

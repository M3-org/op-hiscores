# ethereum-optimism/optimism Daily Update (Feb 6, 2026)
## OVERVIEW 
Today's development focused on refining deployment processes, fixing critical contract logic, and enhancing documentation. Key efforts included dockerizing contract builds for `op-deployer` and addressing permissioning for game types in `OPContractsManagerV2`.

## KEY TECHNICAL DEVELOPMENTS

### Deployment Process Enhancements and Reverts
A feature was added to build contracts within Docker for the `op-deployer` release process ([#19088](https://github.com/ethereum-optimism/optimism/pull/19088)). However, this change was subsequently reverted due to CI failures in the `op-deployer-docker-build` job ([#19106](https://github.com/ethereum-optimism/optimism/pull/19106)).

### Contract Logic and Game Type Permissioning
A critical bug fix was implemented to ensure that only permissioned game types can be enabled in `OPContractsManagerV2` deployments. This involved modifications to `IOPContractsManagerStandardValidator.sol` and `OPContractsManagerV2.sol`, along with updates to deployment scripts and tests ([#19077](https://github.com/ethereum-optimism/optimism/pull/19077)).

### Deprecated Blob Sidecars Client Removal
The deprecated blob sidecars client and related code were removed from `op-service` and `op-program`, with careful consideration for backward compatibility when parsing the now deprecated blob hint format ([#19080](https://github.com/ethereum-optimism/optimism/pull/19080)).

### Documentation and Acceptance Test Updates
Documentation for the `docs/README.md` was completed, including descriptions for `ai/` and `handbook/` directories. The `CODEOWNERS` pattern for security reviews was also refined ([#19096](https://github.com/ethereum-optimism/optimism/pull/19096)). Additionally, `op-acceptance` tests were updated to create super cannon-kona games instead of super cannon, aligning with the intention to support cannon-kona with interop ([#18979](https://github.com/ethereum-optimism/optimism/pull/18979)).

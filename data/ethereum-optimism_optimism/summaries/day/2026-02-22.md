# ethereum-optimism/optimism Daily Update (Feb 22, 2026)
## OVERVIEW 
Today's development focused on CI/CD improvements, specifically addressing issues with publishing Kona prestates. A new issue was opened to review access of internally created blocks in Kona-proofs interop.

## KEY TECHNICAL DEVELOPMENTS

### CI/CD Pipeline Enhancements
- The authentication scope for publishing Kona prestates was switched to align with the one used for Cannon, aiming to resolve job failures related to publishing access. ([#19268](https://github.com/ethereum-optimism/optimism/pull/19268))

## NEWLY OPENED PULL REQUESTS
Six new pull requests were opened today, primarily focusing on contract improvements and CI/CD fixes. These include adding non-idempotent initializer review rules ([#19273](https://github.com/ethereum-optimism/optimism/pull/19273)), implementing `onlyDelegateCall` with tests for audit fixes ([#19272](https://github.com/ethereum-optimism/optimism/pull/19272)), and adding documentation for several audit findings ([#19271](https://github.com/ethereum-optimism/optimism/pull/19271), [#19269](https://github.com/ethereum-optimism/optimism/pull/19269)). Additionally, a fix for Kona-publish-prestates triggering on scheduled builds was proposed ([#19270](https://github.com/ethereum-optimism/optimism/pull/19270)), and a change to use a devnet per test in `op-acceptance-tests` was introduced ([#19267](https://github.com/ethereum-optimism/optimism/pull/19267)).

## CLOSED ISSUES

### Docker Image Availability
- An inquiry regarding the location of the public Docker image for the newest `op-reth` version (v1.11.0) was resolved. The user was directed to the release notes where the Docker image is consistently listed. ([#19264](https://github.com/ethereum-optimism/optimism/issues/19264))

## NEW ISSUES

### Kona-Interop Review
- A new issue was opened to review the access of internally created blocks within Kona-proofs interop. The concern is that if the initial validation pass identifies blocks needing replacement, the current process builds and sets them as the chain head before a second validation pass, which requires review. ([#19266](https://github.com/ethereum-optimism/optimism/issues/19266))

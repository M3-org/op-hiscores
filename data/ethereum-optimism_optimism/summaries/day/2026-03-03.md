# ethereum-optimism/optimism Daily Update (Mar 3, 2026)
## OVERVIEW 
Today's development focused on refining smart contract migration logic, enhancing supernode stability, and improving documentation. Several new issues were opened concerning Kona's derivation pipeline and L2 contract upgrades.

## KEY TECHNICAL DEVELOPMENTS

### Smart Contract Enhancements and Migrator Fixes
Significant work was done on smart contracts, including a fix to require the interop dev feature for the `migrate` function in `OPContractsManagerMigrator` ([#19285](https://github.com/ethereum-optimism/optimism/pull/19285)). Additionally, duplicated mock logic for unoptimized proxy implementations was refactored into a shared helper function ([#19349](https://github.com/ethereum-optimism/optimism/pull/19349)). Documentation was also added for several audit findings related to contract behavior ([#19271](https://github.com/ethereum-optimism/optimism/pull/19271)).

### Supernode Stability and Testing Improvements
Efforts to improve the stability of the `op-supernode` continued with a fix addressing a stuck pause state that caused shutdown hangs in the chain container ([#19365](https://github.com/ethereum-optimism/optimism/pull/19365)). A critical acceptance test, `TestSupernodeInteropActivationAfterGenesis`, was also added to the flake-shake gate to ensure its reliability ([#19350](https://github.com/ethereum-optimism/optimism/pull/19350)).

### AI Review Rules for Contract Development
New guidelines for AI agents were added to address non-idempotent initializers in contract development, populating the `docs/ai/contract-dev.md` and `ops/ai-eng/graphite/rules.md` files ([#19273](https://github.com/ethereum-optimism/optimism/pull/19273)).

## NEW ISSUES

### Kona Derivation Pipeline Anomalies
Several new issues highlight potential problems within Kona's derivation pipeline. These include the `CalldataSource` silently dropping EIP-4844 (type 3) batcher transactions pre-Ecotone ([#19352](https://github.com/ethereum-optimism/optimism/issues/19352)), a fatal system config update failure in L1 traversal ([#19353](https://github.com/ethereum-optimism/optimism/issues/19353)), and `BlobSource` wrapping all errors as Temporary, losing Reset classification on L1 reorg ([#19354](https://github.com/ethereum-optimism/optimism/issues/19354)). Further issues point to `BatchProvider.attempt_update()` not copying the origin field on Holocene transition ([#19356](https://github.com/ethereum-optimism/optimism/issues/19356)), `BlobData::fill` returning Critical on blob under-fill instead of Reset ([#19359](https://github.com/ethereum-optimism/optimism/issues/19359)), and `BlobSource::load_blobs` silently ignoring over-fill ([#19363](https://github.com/ethereum-optimism/optimism/issues/19363)).

### Interop and Gas Pricing Concerns
New issues also address interop transaction pool eviction behavior on reorgs ([#19351](https://github.com/ethereum-optimism/optimism/issues/19351)), the need to remove gas introspection from `CrossL2Inbox` ([#19374](https://github.com/ethereum-optimism/optimism/issues/19374)), and an investigation into Glamsterdam gas pricing impacts on precompile acceleration ([#19375](https://github.com/ethereum-optimism/optimism/issues/19375)).

### Flashblocks and Karst Upgrade Cleanup
A user reported unexpected rate limiting on the flashblocks WS endpoint ([#19366](https://github.com/ethereum-optimism/optimism/issues/19366)). Additionally, there's a task to remove Karst-specific upgrade transactions from `GenerateNUTBundle` after the upgrade is deployed ([#19369](https://github.com/ethereum-optimism/optimism/issues/19369)).

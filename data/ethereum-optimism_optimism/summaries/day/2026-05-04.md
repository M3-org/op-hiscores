# ethereum-optimism/optimism Daily Update (May 4, 2026)
## OVERVIEW 
Today's development focused on critical bug fixes across `op-reth`, `op-supernode`, and `op-challenger`, alongside significant refactoring of proof-related tests and updates to documentation. Several new pull requests were opened, covering refactoring, new features, and documentation.

## KEY TECHNICAL DEVELOPMENTS

### Critical Bug Fixes in `op-reth` and `op-supernode`
Several crucial bugs were addressed, including a fix for `op-reth` to wait for proofs ExEx store before `eth_getProof` ([#20487](https://github.com/ethereum-optimism/optimism/pull/20487)) and resolving a stall issue during `init-state` by committing RW transactions earlier ([#20485](https://github.com/ethereum-optimism/optimism/pull/20485)). Additionally, `op-supernode` was updated to correctly use the MAX of per-chain L1s for `VerifiedRequiredL1` ([#20484](https://github.com/ethereum-optimism/optimism/pull/20484)).

### Kona Proof and Challenger Enhancements
A fix was implemented in `kona-proof` to correctly decode EIP-2935 storage slot values as U256 ([#20518](https://github.com/ethereum-optimism/optimism/pull/20518)). The `op-challenger` now correctly routes `SuperCannonKonaGameType` to the `KonaSuperExecutor` in `run-trace` ([#20512](https://github.com/ethereum-optimism/optimism/pull/20512)) and `SuperPermissionedGameType` through `cannon-kona` ([#20501](https://github.com/ethereum-optimism/optimism/pull/20501)).

### Proofs Test Refactoring and Documentation Updates
Proof-related tests were refactored to use a `SkipIfKona` helper, improving test selection and reducing coupling ([#20519](https://github.com/ethereum-optimism/optimism/pull/20519)). Documentation for `op-deployer` was refreshed, linking to current `docs.optimism.io` resources and updating relocated docs ([#20521](https://github.com/ethereum-optimism/optimism/pull/20521)).

## ACTIVE ISSUES

### Interop Stress Testing and Expiry Window ([#15285](https://github.com/ethereum-optimism/optimism/issues/15285))
Discussion on stress testing the interop expiry window continues. Latest updates from live devnet stress testing on `interop-jnt-v1` indicate that a Kona EIP-2935 proof decoding issue was found and fixed. Stress tests with up to 4096 repeated executing messages completed cleanly in Cannon/MIPS, showing linear cost scaling. The practical upper bound appears to be L2 gas/block limits rather than interop validation or Cannon non-termination. The analysis suggests that extending the expiry window from ~4.6 days to 7 days is unlikely to cause completion issues.

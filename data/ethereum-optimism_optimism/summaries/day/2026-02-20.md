# ethereum-optimism/optimism Daily Update (Feb 20, 2026)
## OVERVIEW 
Today's development focused on enhancing flashblock building efficiency, migrating Docker images to a new GCP registry, and refining CI/CD processes. Significant progress was also made on the Supernode's finalized L2 head authority and the op-devstack's component registry.

## KEY TECHNICAL DEVELOPMENTS

### Flashblock Performance and Infrastructure Improvements
A new feature was added to enable speculative building on pending blocks, reducing latency for flashblocks ([#18995](https://github.com/ethereum-optimism/optimism/pull/18995)). Additionally, all Docker image references were migrated to the `oplabs-tools-artifacts` GCP registry, and prestate artifact generation was fixed ([#19251](https://github.com/ethereum-optimism/optimism/pull/19251)).

### CI/CD Pipeline Enhancements
Several updates were made to the CI/CD pipeline to improve reliability and efficiency. This included adding `go-binaries-for-sysgo` as a dependency for `go-tests-full` to fix post-merge failures ([#19262](https://github.com/ethereum-optimism/optimism/pull/19262)), removing `kona-client` from the cross-platform smoke test due to its nature as an FPVM guest program ([#19256](https://github.com/ethereum-optimism/optimism/pull/19256)), and adding a `readonly-github-token` context to prevent GitHub rate limiting issues during `mise install` ([#19261](https://github.com/ethereum-optimism/optimism/pull/19261)).

### Supernode and Devstack Refinements
The `op-devstack` saw the introduction of a unified `Registry` for component storage, replacing multiple `locks.RWMap` instances, as part of a larger ID type system refactor ([#18873](https://github.com/ethereum-optimism/optimism/pull/18873)). The `op-supernode` was updated to defer to the `superAuthority` regarding the finalized L2 head, addressing a key issue related to Supernode finalization ([#19189](https://github.com/ethereum-optimism/optimism/pull/19189)).

## ACTIVE ISSUES

### L2CM Upgrades: Implementing Additional Upgrade Gas Mechanism
Discussion on [#18832](https://github.com/ethereum-optimism/optimism/issues/18832) revolves around implementing an additional upgrade gas mechanism in `op-node` (go client) to handle gas allocation beyond the `systemTxMaxGas` limit. The latest comment from `maurelian` discusses metadata considerations for the `current_nut_bundle.json` file, specifically whether to include a `forkName` (deemed redundant) and a `generatedFromCommit` field. While `generatedFromCommit` is not suitable for `current_nut_bundle.json` due to potential toil, it is considered appropriate for when the bundle is updated and moved, with a future PR expected to introduce a script for canonicalizing this file.

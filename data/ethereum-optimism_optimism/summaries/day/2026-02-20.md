# ethereum-optimism/optimism Daily Update (Feb 20, 2026)
## OVERVIEW 
Today's development focused on enhancing flashblock building efficiency, migrating Docker images to a new GCP registry, and refining CI/CD processes. Significant progress was also made on the Supernode's finalized L2 head authority and the op-devstack's component registry.

## KEY TECHNICAL DEVELOPMENTS

### Flashblock Performance and Infrastructure Improvements
A new feature was added to enable speculative building on pending blocks, reducing latency for flashblocks ([#18995](https://github.com/ethereum-optimism/optimism/pull/18995)). Additionally, all Docker image references were migrated to the `oplabs-tools-artifacts` GCP registry, and prestate artifact generation was fixed ([#19251](https://github.com/ethereum-optimism/optimism/pull/19251)).

### CI/CD Pipeline Enhancements
Several updates were made to the CI/CD pipeline to improve reliability and efficiency. This included adding `go-binaries-for-sysgo` as a dependency for `go-tests-full` to fix post-merge failures ([#19262](https://github.com/ethereum-optimism/optimism/pull/19262)), removing `kona-client` from the cross-platform smoke test due to its nature as an FPVM guest program ([#19256](https://github.com/ethereum-optimism/optimism/pull/19256)), and adding a `readonly-github-token` context where `checkout-with-mise` is used to prevent GitHub rate limiting issues ([#19261](https://github.com/ethereum-optimism/optimism/pull/19261)).

### Supernode and Devstack Refinements
The `op-devstack` saw the introduction of a unified `Registry` for component storage, replacing multiple `locks.RWMap` instances ([#18873](https://github.com/ethereum-optimism/optimism/pull/18873)). The `op-supernode` was updated to defer to the `superAuthority` regarding the finalized L2 head, addressing a related issue ([#19189](https://github.com/ethereum-optimism/optimism/pull/19189)). A new `release-notes` recipe and helper tag queries were also added to the `justfile` for improved release management ([#19258](https://github.com/ethereum-optimism/optimism/pull/19258)).

### L2CM Upgrades: `op-node` Gas Mechanism
Discussion continues on implementing an additional upgrade gas mechanism in `op-node` to handle gas allocation beyond the `systemTxMaxGas` limit ([#18832](https://github.com/ethereum-optimism/optimism/issues/18832)). The latest comments focus on the metadata for the `current_nut_bundle.json` file, specifically whether to include a `forkName` (deemed redundant) and a `generatedFromCommit` field (considered useful when the bundle is updated and moved, but not for the `current_nut_bundle.json` itself to avoid unnecessary toil).

# ethereum-optimism/optimism Daily Update (Apr 22, 2026)
## OVERVIEW 
Today's development focused on enhancing dispute resolution with a new SP1Adapter feature, stabilizing acceptance tests, and improving documentation. Several critical bug fixes were implemented across Kona, op-devstack, and alloy-op-evm, alongside significant dependency updates.

## KEY TECHNICAL DEVELOPMENTS

### Dispute Resolution and ZK Proof Integration
A new `SP1Adapter` feature was added to `contracts-bedrock`, introducing interfaces and implementations for ZK verifiers, including `ISP1Adapter`, `IZKVerifier`, and `ISP1PlonkAdapter`. This enhancement is crucial for integrating zero-knowledge proofs into the dispute system. ([#19987](https://github.com/ethereum-optimism/optimism/pull/19987))

### Stability and Reliability Improvements
Multiple bug fixes addressed critical issues, including ensuring `chain_id` is always set for trie hints in Kona's interop provider ([#20164](https://github.com/ethereum-optimism/optimism/pull/20164)), retrying transient SyncStatus RPC errors in op-devstack's DSL wait loops ([#20209](https://github.com/ethereum-optimism/optimism/pull/20209)), and stabilizing the `TestUnsafeGapFillAfterUnsafeReorg_RestartL2CL` acceptance test ([#20199](https://github.com/ethereum-optimism/optimism/pull/20199)). Additionally, a discrepancy in `OpTx` usage within `alloy-op-evm` was resolved ([#20231](https://github.com/ethereum-optimism/optimism/pull/20231)).

### Documentation and Developer Experience
New documentation was added to recommend migrating to a specialized op-node topology for improved performance and scalability ([#20192](https://github.com/ethereum-optimism/optimism/pull/20192)). A comprehensive guide for writing new acceptance tests was also introduced, covering philosophy, principles, and DSL patterns ([#20225](https://github.com/ethereum-optimism/optimism/pull/20225)).

### Dependency Updates and Test Enhancements
The project saw a significant update to `alloy` to version 2.0 across various Rust crates, including `kona`, `op-alloy`, and `op-reth` ([#20060](https://github.com/ethereum-optimism/optimism/pull/20060)). Acceptance tests were enhanced to verify that deposits bypass the EIP-7825 transaction gas limit cap ([#20222](https://github.com/ethereum-optimism/optimism/pull/20222)), and `op-reth` is now prebuilt for acceptance tests to speed up test startup times ([#20247](https://github.com/ethereum-optimism/optimism/pull/20247)).

## CLOSED ISSUES

### Flaky Test Resolution
Several flaky tests were addressed and closed. `TestInteropFaultProofs_VariedBlockTimes_FasterChainB/SuperRootInvalidIfUnsupportedByL1Data-fpp` ([#19829](https://github.com/ethereum-optimism/optimism/issues/19829)) was closed as it has been stable for a while. The `TestUnsafeGapFillAfterUnsafeReorg_RestartL2CL` test ([#19936](https://github.com/ethereum-optimism/optimism/issues/19936)) was also fixed, with the underlying race condition identified and resolved.

### Batcher Throttling and RPC Support
Issues related to batcher throttling in `op-reth` and `op-rbuilder` were closed. It was confirmed that `op-reth` already supports the necessary throttling mechanisms ([#18764](https://github.com/ethereum-optimism/optimism/issues/18764)) and that `op-rbuilder` also implements the block throttling functionality with RPC support ([#19023](https://github.com/ethereum-optimism/optimism/issues/19023)).

### Deposit Handling and Gas Limits
The issue concerning the implementation and testing of deposit handling with the EIP-7825 gas limit ([#20217](https://github.com/ethereum-optimism/optimism/issues/20217)) was closed, indicating that deposits with gas limits exceeding the L2 max cap are now correctly handled.

### Kona NUT Bundle Management
Several issues related to Kona NUT bundles were closed, including moving nut bundles to `op-core/nuts` ([#20237](https://github.com/ethereum-optimism/optimism/issues/20237)), Kona NUT bundle parsing ([#20238](https://github.com/ethereum-optimism/optimism/issues/20238)), and adding Karst fork scaffolding to Kona ([#20240](https://github.com/ethereum-optimism/optimism/issues/20240)).

# ethereum-optimism/optimism Daily Update (Mar 2, 2026)
## OVERVIEW 
Today's development focused on critical bug fixes across `op-supernode`, `op-interop-filter`, and `kona-node` to enhance stability and performance. Significant work was also done on CI/CD improvements and the introduction of new fault proof smoke tests.

## KEY TECHNICAL DEVELOPMENTS

### Stability and Performance Enhancements for Interoperability Components
Several bug fixes were implemented to improve the stability and performance of interoperability-related components. This includes fixing initial block sealing in `op-supernode` ([#19308](https://github.com/ethereum-optimism/optimism/pull/19308)), optimizing cross-validation and reorg detection in `op-interop-filter` ([#19304](https://github.com/ethereum-optimism/optimism/pull/19304)), and correcting L1 inclusion logic in `op-supernode` ([#19343](https://github.com/ethereum-optimism/optimism/pull/19343)).

### CI/CD and Build Process Streamlining
Improvements to the CI/CD pipeline were made, such as removing GCS-based artifact caching from `contracts-bedrock` CI to prevent stale artifacts and non-deterministic resolutions ([#19332](https://github.com/ethereum-optimism/optimism/pull/19332)). Additionally, the `cannon-builder` Docker image was added to CI builds ([#19295](https://github.com/ethereum-optimism/optimism/pull/19295)), and an unnecessary Rust build step was removed to save time ([#19280](https://github.com/ethereum-optimism/optimism/pull/19280)).

### Kona Node Robustness and Fault Proof Testing
The `kona-node` saw fixes to handle `BlockNotFound` errors by mapping them to `ResetError` for better reorg recovery ([#19344](https://github.com/ethereum-optimism/optimism/pull/19344)) and correctly handling "blob not found" scenarios to prevent safe head stalls ([#19328](https://github.com/ethereum-optimism/optimism/pull/19328)). New smoke tests were also introduced to sanity-check super fault proofs for single-chain interop and preinterop scenarios ([#19299](https://github.com/ethereum-optimism/optimism/pull/19299)).

### Karst Fork Activation and NUT Bundle Execution
Work was completed to add the Karst fork activation, enabling the execution of NUT bundles within the derivation pipeline at the Karst activation point ([#19220](https://github.com/ethereum-optimism/optimism/pull/19220)).

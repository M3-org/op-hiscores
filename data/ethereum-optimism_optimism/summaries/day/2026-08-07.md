# ethereum-optimism/optimism Daily Update (Aug 7, 2026)
## OVERVIEW 
Today's development focused on refining the Sequencer Defined Metering (SDM) implementation, enhancing CI test infrastructure, and significantly improving documentation clarity and navigation. Several critical issues related to sequencer performance and test flakiness were also addressed and closed.

## KEY TECHNICAL DEVELOPMENTS

### Sequencer Performance and Stability
- Isolated SDM refund production to a test-only fixture, removing it from public production binaries while retaining generic policy hooks and verifier support ([#22289](https://github.com/ethereum-optimism/optimism/pull/22289)).
- Sequencer now runs on its own goroutine, eliminating starvation by the shared event loop and preventing block production from competing with derivation ([#22241](https://github.com/ethereum-optimism/optimism/pull/22241)).
- Registered the `l2.follow.source.rpc-timeout` flag in `op-node` to ensure it's properly recognized and configurable ([#22297](https://github.com/ethereum.optimism/optimism/pull/22297)).

### CI/CD and Testing Improvements
- Sharded test jobs by historical timing and widened parallelism to improve CI efficiency and reduce test run times ([#22202](https://github.com/ethereum-optimism/optimism/pull/22202)).
- Resolved a metrics port collision issue in `kona-sp1-proposer` that caused test flakes, ensuring more reliable test execution ([#22300](https://github.com/ethereum-optimism/optimism/pull/22300)).

### Documentation Enhancements
- Fixed unreachable root links, dead in-tree links, and mis-archived snap-sync guides to improve documentation navigation and accuracy ([#22317](https://github.com/ethereum-optimism/optimism/pull/22317)).
- Disambiguated colliding frontmatter page titles across various documentation sections for better clarity ([#22314](https://github.com/ethereum-optimism/optimism/pull/22314)).
- Corrected the `kona-node` actor list and extension mechanism on the mechanics page ([#22313](https://github.com/ethereum-optimism/optimism/pull/22313)).
- Added a new "Choose how to run your chain" fork page to guide users ([#22312](https://github.com/ethereum-optimism/optimism/pull/22312)).
- Replaced the "Notices Archive" sidebar group with a more organized archive index ([#22319](https://github.com/ethereum-optimism/optimism/pull/22319)).
- Retired the stale imported `op-reth` OP Stack run page to remove outdated information ([#22316](https://github.com/ethereum-optimism/optimism/pull/22316)).

## CLOSED ISSUES

### Sequencer Performance and Stability Resolved
- The long-standing issue of sequencer starvation by derivation in the single-threaded event loop has been addressed and closed ([#22232](https://github.com/ethereum-optimism/optimism/issues/22232)).
- A bug causing block building to be delayed by up to 2 seconds during L1 batch derivation, impacting block production, has been resolved ([#19263](https://github.com/ethereum-optimism/optimism/issues/19263)).

### Test Flakiness Eliminated
- A flake in `TestProposerDefendsMultipleChallengedGamesConcurrently` due to a `kona-sp1-proposer` metrics port collision has been fixed and the issue closed ([#22299](https://github.com/ethereum-optimism/optimism/issues/22299)).

### Protocol Validation and Tooling Updates
- An issue regarding the lack of validation for post-exec (0x7D) transaction payloads on decode, highlighting a latent Go↔Rust divergence, has been closed as it's now considered an EL responsibility ([#21961](https://github.com/ethereum-optimism/optimism/issues/21961)).
- The PCD Milestone 3 updates for `op-deployer` and its associated tooling runbook have been completed and the issue closed ([#22114](https://github.com/ethereum-optimism/optimism/issues/22114)).

## NEW ISSUES

### Sequencer and Node Operation Challenges
- The `op-node` sequencer's sealing deadline currently uses a static constant, leading to potential inaccuracies; a proposal suggests compensating with measured seal duration instead ([#22320](https://github.com/ethereum-optimism/optimism/issues/22320)).
- The `Sequencer.Stop` function in `op-node` can block indefinitely if it waits for an L2 head that never arrives, posing a potential deadlock risk ([#22318](https://github.com/ethereum-optimism/optimism/issues/22318)).

### Supernode Interoperability and Recovery
- The `op-supernode`'s cross-safe head can wedge after an invalid-message replacement, particularly when a local-safe chain stalls, leading to potential consensus issues ([#22325](https://github.com/ethereum-optimism/optimism/issues/22325)).

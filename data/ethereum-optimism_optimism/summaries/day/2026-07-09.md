## ACTIVE ISSUES

### `default syncmode.offset-el-safe` for `--minimal` nodes [#21465](https://github.com/ethereum-optimism/optimism/issues/21465)
The discussion on `default syncmode.offset-el-safe` failing for `--minimal` nodes highlights that `--minimal` pruning removes block bodies, which are essential for `op-node`'s EL sync to read L1-info deposit transactions. The current `12h` offset can cause issues if it references blocks whose bodies have been pruned. The recommended solution is to **never prune block bodies** on an OP Stack node. Instead, prune only state and receipt segments using flags like `--prune.minimum-distance`, `--prune.receipts.distance`, `--prune.account-history.distance`, and `--prune.storage-history.distance`. A documentation update [#21672](https://github.com/ethereum-optimism/optimism/pull/21672) is in progress to clarify supported pruning configurations and the `offset-el-safe` flag, while relaxing the previous strict "no pruning" guidance.

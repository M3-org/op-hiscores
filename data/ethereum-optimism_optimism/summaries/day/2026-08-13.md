# ethereum-optimism/optimism Daily Update (Aug 13, 2026)
## OVERVIEW 
Today's development focused on enhancing the robustness and security of the Optimism ecosystem, with significant updates to ZK bond accounting, dispute game implementations, and improved stability for various components.

## KEY TECHNICAL DEVELOPMENTS

### ZK Dispute Game Enhancements and Security
Significant progress was made in refining the ZK dispute game mechanisms. This includes normalizing ZK bond accounting to align with `ZKDisputeGame.sol` records and ensuring complete ZK snapshots are routed through all bond consumers without altering Fault output ([#22228](https://github.com/ethereum-optimism/optimism/pull/22228)). Security was further bolstered by checking the identity of registered dispute game implementations ([#22365](https://github.com/ethereum-optimism/optimism/pull/22365)) and binding the `AnchorStateRegistry` to the portal ([#22412](https://github.com/ethereum-optimism/optimism/pull/22412)). Additionally, `msg.value` is now rejected in `SuperPermissionedDisputeGame` initialization to prevent trapped ETH ([#22410](https://github.com/ethereum-optimism/optimism/pull/22410)).

### Kona SP1 Proposer and Interoperability Improvements
The `kona-sp1-proposer` saw updates to standardize environment variables with prefixed configuration styles ([#22411](https://github.com/ethereum-optimism/optimism/pull/22411)) and implement fallover for superroot RPCs to prevent proposal stalls ([#22416](https://github.com/ethereum-optimism/optimism/pull/22416)). Interoperability within Kona was improved by defaulting chains without explicit interop configuration to a self-only dependency set ([#22408](https://github.com/ethereum-optimism/optimism/pull/22408)) and expanding super-root acceptance coverage ([#22392](https://github.com/ethereum-optimism/optimism/pull/22392)).

### SDM Post-Execution and EVM Stability
Work continued on refining the handling of SDM post-execution transactions. This included reporting zero DA footprint on PostExec receipts ([#22220](https://github.com/ethereum-optimism/optimism/pull/22220)), synthesizing post-exec transaction results on replay paths to fix `debug_traceBlockByNumber` failures ([#22374](https://github.com/ethereum-optimism/optimism/pull/22374)), and ensuring SDM post-exec refunds are applied exactly once ([#22399](https://github.com/ethereum-optimism/optimism/pull/22399)).

### Testing and Infrastructure Stability
Several updates focused on improving testing reliability and infrastructure. This included isolating `apply` subtest deadlines in `op-deployer` to prevent cumulative budget issues ([#22389](https://github.com/ethereum-optimism/optimism/pull/22389)) and stabilizing queued failure ordering in `txmgr` ([#22388](https://github.com/ethereum-optimism/optimism/pull/22388)). Vestigial Docker files and scripts were removed to streamline the repository ([#22375](https://github.com/ethereum-optimism/optimism/pull/22375)), and a CI fix was implemented to avoid SIGPIPE errors in the super-aggregation vkey gate ([#22415](https://github.com/ethereum-optimism/optimism/pull/22415)).

## CLOSED ISSUES

### Resolution of Flaky Tests
Several flaky tests were addressed and closed today. This includes `TestEndToEndApply` ([#22380](https://github.com/ethereum-optimism/optimism/issues/22380)), which previously suffered from shared context deadlines, and `TestQueue_Send/subsequent_txs_fail_after_tx_failure` ([#22382](https://github.com/ethereum-optimism/optimism/issues/22382)), which had inconsistent failure ordering.

### Dispute Game and Deployer Updates
Issues related to dispute game configurations and the `op-deployer` were resolved. This includes the closure of [#21429](https://github.com/ethereum-optimism/optimism/issues/21429) concerning `op-deployer` changes and new OPCM options, and [#22348](https://github.com/ethereum-optimism/optimism/issues/22348) regarding the restoration of permissionless fault proofs on `sdm-net-0`, which was closed with the decision to use permissioned fault proofs instead.

### Kona SP1 Proposer and Sequencing Window Stability
The `kona-sp1-proposer` now supports superroot RPC failover, resolving [#22403](https://github.com/ethereum-optimism/optimism/issues/22403). Additionally, the long-standing issue of sequencing-window expiry recovery with span-batches in `op-batcher` ([#16036](https://github.com/ethereum-optimism/optimism/issues/16036)) was closed as "wontfix," with the understanding that recovery mode is supported only with singular batches.

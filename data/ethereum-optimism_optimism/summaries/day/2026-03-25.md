# ethereum-optimism/optimism Daily Update (Mar 25, 2026)
## OVERVIEW 
Today's development focused on significant advancements in the ZK dispute game, improvements to the op-devstack for single-chain runtimes, and critical bug fixes in the Kona derivation process. Several interop and spamming tests were also enhanced and migrated.

## KEY TECHNICAL DEVELOPMENTS

*   **ZK Dispute Game Integration and Enhancements**
    *   Replaced `OptimisticZkGame` with a spec-compliant `ZKDisputeGame` as game type `10`, implementing the full game lifecycle within the OP Stack dispute infrastructure. ([#19606](https://github.com/ethereum-optimism/optimism/pull/19606))
    *   Removed interop bridge contracts from the L2ContractsManager upgrade flow, updating `IMPLEMENTATION_COUNT` from 28 to 23. ([#19650](https://github.com/ethereum-optimism/optimism/pull/19650))

*   **Devstack and Derivation Improvements**
    *   Introduced central dispatch functions (`startL2ELForKey`, `startL2CLForKey`) in `op-devstack` to respect `DEVSTACK_L2EL_KIND` and `DEVSTACK_L2CL_KIND` across all single-chain runtimes. ([#19653](https://github.com/ethereum-optimism/optimism/pull/19653))
    *   Fixed a bug in Kona's L1Retrieval stage where the data availability provider was not cleared on re-orgs, preventing stale calldata or blobs from persisting. ([#19687](https://github.com/ethereum-optimism/optimism/pull/19687))
    *   Enabled the L1 Geth client in `op-devstack` to expose its user RPC over HTTP for Kona connectivity. ([#19742](https://github.com/ethereum-optimism/optimism/pull/19742))

*   **Testing Infrastructure and CI/CD Refinements**
    *   Updated `op-acceptance-tests` to make spamming tests compatible with `op-reth` by extracting relevant logic from existing throttling tests. ([#19676](https://github.com/ethereum-optimism/optimism/pull/19676))
    *   Migrated interop acceptance tests to use supernode-based presets and added a flag to `op-up` for spinning up a 2-chain interop devnet. ([#19754](https://github.com/ethereum-optimism/optimism/pull/19754), [#19747](https://github.com/ethereum-optimism/optimism/pull/19747))
    *   Removed the `TestInteropFaultProofs_DeepCanonicalBlockQuery` action test, as it used `op-supervisor` instead of `op-supernode` for EIP-2935 block hash verification. ([#19753](https://github.com/ethereum-optimism/optimism/pull/19753))
    *   Optimized CI by skipping Rust gate and devnet workflows for documentation-only pull requests and removed the `devnet-metrics-collect` job and workflow. ([#19739](https://github.com/ethereum-optimism/optimism/pull/19739), [#19744](https://github.com/ethereum-optimism/optimism/pull/19744))

## ACTIVE ISSUES

*   **Flaky Test: `TestCLELDivergence`** ([#19681](https://github.com/ethereum-optimism/optimism/issues/19681))
    *   The `TestCLELDivergence` test continues to exhibit flakiness, with recent discussions focusing on the root cause of unexpected resets in the derivation pipeline.
    *   Initial assessment suggested the reset was part of normal startup, not an in-progress EL sync, and that the test comment might be misleading.
    *   Further investigation revealed that the test's expectation of a persistent CL-EL divergence might be incorrect if the derivation pipeline resetting the unsafe head is intended behavior. The issue highlights a potential race condition where the `StatusTracker`'s `UnsafeL2` is reset shortly after being updated, making the intermediate state unobservable.
    *   A proposed fix ([#19733](https://github.com/ethereum-optimism/optimism/pull/19733)) aims to mitigate the flakiness, but there's ongoing debate whether to keep the issue open until the flakiness completely disappears or close it if the fix is believed to be effective, relying on `/report-flake` to reopen if necessary.

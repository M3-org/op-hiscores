# ethereum-optimism/optimism Daily Update (Feb 25, 2026)
## OVERVIEW 
Today's development focused on enhancing L2 contract management with a new L2CM implementation, refactoring the Orchestrator to a unified Registry, and addressing various CI and supernode lifecycle issues.

## KEY TECHNICAL DEVELOPMENTS

### L2 Contracts Manager (L2CM) Implementation
- Added the L2ContractsManager contract for upgrading L2 predeploys via `DELEGATECALL` from ProxyAdmin, based on updated L2ContractsManager specifications ([#19111](https://github.com/ethereum-optimism/optimism/pull/19111)).
- Fixed various CI issues related to contracts-bedrock, including updates to `main.yml` and `justfile` ([#19300](https://github.com/ethereum-optimism/optimism/pull/19300)).

### Orchestrator Refactoring and Supernode Enhancements
- Migrated the Orchestrator in `op-devstack` to a unified `*stack.Registry`, completing Phase 4 of the ID type system refactor by replacing 15 separate `locks.RWMap` fields ([#18875](https://github.com/ethereum-optimism/optimism/pull/18875)).
- Eliminated duplicated lifecycle management in `op-devstack/supernode` ([#19306](https://github.com/ethereum-optimism/optimism/pull/19306)).
- Ensured the application context is closed before stopping services in `op-devstack` and `op-supernode` ([#19305](https://github.com/ethereum-optimism/optimism/pull/19305)).
- Replaced reflection with interop names in `op-supernode` activities ([#19310](https://github.com/ethereum-optimism/optimism/pull/19310)).

## NEW ISSUES

### L2CM Upgrade Mechanism Enhancements
- An interop migration path needs to be added to L2CM for upgrades ([#19309](https://github.com/ethereum-optimism/optimism/issues/19309)).
- Access control for `initialize()` functions in predeploys needs to be added using `ProxyAdminOwnedBase` ([#19313](https://github.com/ethereum-optimism/optimism/issues/19313)).
- Investigation is needed to automate enforcement that `L2ContractsManager` has no storage variables to prevent collision with `ProxyAdmin` slots during `DELEGATECALL` ([#19315](https://github.com/ethereum-optimism/optimism/issues/19315)).
- `L2ProxyAdmin` should reuse `ProxyAdmin` tests to ensure backward compatibility for existing L2 contracts that call `owner()` for access control ([#19316](https://github.com/ethereum-optimism/optimism/issues/19316)).
- The Bundle Canonicalization process needs to be implemented for L2CM upgrades, including a manual trigger for updating the bundled NUT per hardfork and CI checks to prevent errors ([#19307](https://github.com/ethereum-optimism/optimism/issues/19307)).

### Superchain Interoperability and Configuration
- The `CrossL2Inbox` deployment in `kona-node` and interop needs to be conditional, as `kona` currently generates 4 transactions unconditionally, while Go's `InteropNetworkUpgradeTransactions()` conditionally adds `CrossL2Inbox` transactions ([#19311](https://github.com/ethereum-optimism/optimism/issues/19311)).

### Contract Refactoring
- `OptimismMintableERC721Factory` needs to be refactored to use the `Initializable` pattern instead of a constructor, which is currently encoded in `L2Genesis.s.sol` ([#19318](https://github.com/ethereum-optimism/optimism/issues/19318)).

## ACTIVE ISSUES

### L2ContractsManager Implementation and Testing
- **[#18830](https://github.com/ethereum-optimism/optimism/issues/18830) Implement L2ContractsManager contract with upgrade() function:** A follow-up from the FMA (FM6) emphasizes the need for explicit error checking in the L2CM implementation to prevent silent failure swallowing. All individual upgrade calls should revert on failure to ensure atomicity. Another FMA follow-up (FM2) states that `L2ContractsManager` must not declare storage variables to avoid corrupting `L2ProxyAdmin` storage during `DELEGATECALL` execution, a convention already followed in PR [#19111](https://github.com/ethereum-optimism/optimism/pull/19111) and needing explicit documentation.

### L2CM Upgrade Gas Mechanism
- **[#18832](https://github.com/ethereum-optimism/optimism/issues/18832) [L2CM Upgrades] Implement additional upgrade gas mechanism in op-node (go client):** No new comments.

### Deterministic JSON NUT Bundles
- **[#18834](https://github.com/ethereum-optimism/optimism/issues/18834) [L2CM Upgrades] Create Solidity script to generate deterministic JSON NUT bundles:** A follow-up from the FMA (FM7) suggests that the NUT bundle generation script should include a CI job to regenerate and verify the bundle against the committed version on every PR, preventing tampered or incorrectly generated bundles. Previous discussions included the idea of recording the commit source for future validations.

- **[#18837](https://github.com/ethereum-optimism/optimism/issues/18837) [L2CM Upgrades] Set up L2 upgrade fork testing infrastructure:** A follow-up from the FMA (FM1) highlights the need for the fork testing infrastructure to include a test that verifies the initialization state of all predeploys post-upgrade, ensuring they are properly initialized after the upgrade bundle executes.

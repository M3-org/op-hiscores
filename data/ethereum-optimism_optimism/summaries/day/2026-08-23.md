## ACTIVE ISSUES
### op-supernode: Observations from Mirroring its Behaviour in Lokahi ([#22636](https://github.com/ethereum-optimism/optimism/issues/22636))
The latest comments detail discrepancies between the Dafny model (`op-supernode/dafny-models/`) and `op-supernode`'s Go implementation, surfaced during the `lokahi` mirroring work. These discrepancies are recorded for future triage, with `lokahi` continuing to mirror `op-supernode`'s behavior in the interim. Key points include:
*   **Verification Gaps**:
    *   Executing messages in the first sealed block are never verified in Go, a violation of the model. The model's approach is preferred.
    *   The model requires the frontier view for same-timestamp initiating messages, while Go falls through to the `logsDB`. Go's approach is deemed more suitable due to varied block times.
    *   Frontier view correctness is an axiom in the model but not checked in Go. `lokahi` checks this at runtime, discharging the axiom.
*   **Logs Store Discrepancies**:
    *   Virtual-parent first-block seal in Go violates the `UpdatedLogsDB` axiom in the model. The model's approach (no virtual-parent seal) is preferred.
*   **Rewind Plan Differences**:
    *   `buildRewindPlan` in Go produces plan shapes that `ValidRewindPlan` in the model cannot express. The model likely needs generalization.
    *   Rewind apply order differs between the model (engines-first) and Go (engines-last). A decision on partial-failure semantics is needed.
*   **Observation and Decision Logic**:
    *   `observeRound`'s two-flag L1 split in Go has no model analog, and `ValidRoundObservation` is violated on an empty `verifiedDB`. The two-flag split in Go is preferred.
    *   `obs.L2sConsistent` is never set in Go, making the model's gating on it vacuously discharged. Semantics need alignment.
    *   `checkChainsReady`'s at-most-one-block advance is assumed in the model but not checked in Go. A runtime check or precondition is needed.
*   **Commit and Lifecycle**:
    *   `VerifiedDB.Commit` in the model requires exactly the next timestamp, while Go accepts idempotent replay. Go's approach is preferred for crash recovery.
    *   The all-chain VN freeze during invalidation in Go is not modeled. The model should incorporate this concept.
    *   Go's I/O-error paths are outside the model's scope, leading to partially-written states not describable by the model's invariants. A scope decision is needed.
*   **Sibling Gaps**:
    *   `kona-node` lacks the `superroot` namespace present in `op-node`, leading to "Method not found" errors when dispute infrastructure points to a standalone `kona-node` RPC.
    *   `kona-node` also implements none of `op-node`'s `opstack` block-building namespace, causing failures in tests that drive block building through the CL.
*   **CI Job Naming**: A `memory-all-kona-lokahi-op-reth-<fork>` CI job was found to be running `op-supernode` instead of `lokahi`, leading to false positives. This has been addressed in [#22639](https://github.com/ethereum-optimism/optimism/pull/22639) by renaming the job and ensuring the correct implementation is measured.

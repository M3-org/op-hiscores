# ethereum-optimism/optimism Daily Update (Mar 13, 2026)
## OVERVIEW 
Today's development focused on enhancing interop mode with L2PayloadWitness hint support, critical CI/CD pipeline fixes, and significant documentation improvements for AI development workflows. Several core components were refactored, and a number of issues related to sync stalls and uninitialized states were addressed.

## KEY TECHNICAL DEVELOPMENTS

### Interoperability and Execution Witness Enhancements
A new feature was added to Kona's interop mode, enabling support for the `L2PayloadWitness` hint. This allows for execution witness pre-fetching via the `debug_executePayload` RPC, improving the efficiency and capabilities of interop operations. This change involved modifications across various components, including Kona host configurations, acceptance tests, and challenger implementations.
- [#19408](https://github.com/ethereum-optimism/optimism/pull/19408)

### CI/CD Pipeline and Build System Improvements
Multiple fixes were implemented to address issues within the CI/CD pipeline, particularly concerning the migration from `make` to `just`. These fixes include restoring `compute-git-versions` as a native make target, updating `.semgrepignore` to prevent CI failures, and ensuring `just` is correctly installed in Dockerfiles. Additionally, the root `Makefile` was migrated to a `justfile`, streamlining build processes.

### Developer Experience and Documentation
Documentation for AI agents was significantly enhanced with new guidance for Go and Rust development workflows. This includes details on tool versions, build/test/lint commands, and pre-commit/pre-PR checklists, aiming to improve the developer experience for AI-assisted contributions.

## CLOSED ISSUES

### Interoperability Feature Implementation
The issue concerning the implementation of the `L2PayloadWitness` hint for interop mode has been successfully closed. This feature enables `debug_executePayload` for `op-reth` support, addressing historical state performance problems.
- [#19407](https://github.com/ethereum-optimism/optimism/issues/19407)

### Derivation Pipeline Error Handling
An audit of the derivation pipeline's external-input error handling was completed, ensuring that malformed or bad external L1 inputs do not halt derivation and are instead dropped.
- [#19491](https://github.com/ethereum-optimism/optimism/issues/19491)

### Batch Queue Behavior in Kona
A problem where span batch extraction failure in `BatchQueue` returned `Critical` instead of flushing was addressed and closed. The decision was made to preserve the historical behavior for invalid batch data, as these cases were not encountered in production.
- [#19511](https://github.com/ethereum-optimism/optimism/issues/19511)

### Supernode Sync Status Initialization
An issue where `ChainContainer.SyncStatus()` in `op-supernode` returned an empty sync status when the virtual node was uninitialized has been closed. This ensures callers receive an error instead of silently consuming invalid state.
- [#19538](https://github.com/ethereum-optimism/optimism/issues/19538)

## NEW ISSUES

### CI/CD and Build System Problems
New issues have been identified regarding the CI/CD pipeline, specifically related to the `Make` to `Just` migration. The `docker-build-prep` GitHub Actions composite action is failing because `just` is not installed, preventing proper execution of build steps.
- [#19524](https://github.com/ethereum-optimism/optimism/issues/19524)

### `op-reth` Sync and State Mismatch Issues
Several critical issues have emerged concerning `op-reth`'s synchronization capabilities. These include instances where `op-reth` stalls and gets stuck behind the chain head, and recurring state root mismatches on Base mainnet leading to permanent sync stalls and fatal crashes.
- [#19529](https://github.com/ethereum-optimism/optimism/issues/19529)
- [#19532](https://github.com/ethereum-optimism/optimism/issues/19532)

### `op-supernode` and `op-interop-filter` Logic Flaws
Problems have been reported in `op-supernode` and `op-interop-filter` related to timestamp handling and uninitialized states. Specifically, `LockstepCrossValidator` in `op-interop-filter` can stall if `startTimestamp` is zero, and `op-supernode`'s `BlockNumberToTimestamp` helpers have duplicated logic and do not correctly respect `Genesis.L2.Number`.

# ethereum-optimism/optimism Daily Update (Apr 30, 2026)
## OVERVIEW 
Today's development focused on significant improvements to the `op-reth` proof storage system, enhancing its efficiency and robustness. Key updates also include refining `op-reth` bootnode configurations and critical bug fixes across various components, alongside substantial refactoring efforts to streamline the codebase.

## KEY TECHNICAL DEVELOPMENTS

### `op-reth` Proof Storage and Bootnode Enhancements
The `op-reth` subsystem saw a major feature addition with the introduction of `MdbxProofsStorageV2`, which refactors the proof storage schema for improved performance and scalability ([#19928](https://github.com/ethereum-optimism/optimism/pull/19928)). Additionally, default bootnodes for OP Stack chains were implemented in `op-reth` to facilitate easier bootstrapping of new nodes ([#20458](https://github.com/ethereum-optimism/optimism/pull/20458)). A critical bug was also fixed to correctly detect `reth` storage layout during initialization, preventing panics on nodes synced with older storage formats ([#20396](https://github.com/ethereum-optimism/optimism/pull/20396)).

### Core Infrastructure Refactoring and CI Improvements
Significant refactoring efforts were made to remove deprecated `ProtocolVersions` Go plumbing, streamlining the codebase and eliminating an outdated on-chain mechanism ([#20441](https://github.com/ethereum-optimism/optimism/pull/20441)). The `cannon-builder` was also refined to use an apt-only MIPS64 cross-toolchain, simplifying its dependencies ([#20253](https://github.com/ethereum-optimism/optimism/pull/20253)). CI configurations for contracts were cleaned up, and RPC secrets were moved behind CircleCI contexts for enhanced security ([#20465](https://github.com/ethereum-optimism/optimism/pull/20465)).

### `op-supernode` Stability and CLI Flags
A bug fix was implemented in `op-supernode` to guard chain container virtual nodes against torn interface reads, preventing potential panics ([#20211](https://github.com/ethereum-optimism/optimism/pull/20211)). Furthermore, CLI flags were added to `op-proposer` and `op-challenger` to support `supernode` RPCs, enabling direct integration with the `op-supernode` ([#20460](https://github.com/ethereum-optimism/optimism/pull/20460)).

## CLOSED ISSUES

### `op-reth` and `op-supernode` Stability Fixes
Several critical stability issues were resolved today. A data race in `op-supernode` related to the `simpleChainContainer.vn` field was fixed ([#19573](https://github.com/ethereum-optimism/optimism/issues/19573)). The `op-reth` issue where it shipped zero default bootnodes for OP Stack chains, preventing discv5 bootstrapping without explicit `--bootnodes`, has been addressed ([#20453](https://github.com/ethereum-optimism/optimism/issues/20453)). Additionally, a panic in `op-reth` proofs init when dealing with nodes synced with v1 storage format was resolved ([#20394](https://github.com/ethereum-optimism/optimism/issues/20394)).

### `op-proposer`/`op-challenger` Supernode Integration
The issue concerning the integration of `op-proposer` and `op-challenger` with `op-supernode` CLI flags has been closed, enabling direct use of `op-supernode` while maintaining existing `op-supervisor` support ([#20457](https://github.com/ethereum-optimism/optimism/issues/20457)).

### SDM Policy Review
The issue regarding the review of how to allow for multiple policies within the SDM framework has been closed, with a draft branch implementing basic support for multiple policies ([#20218](https://github.com/ethereum-optimism/optimism/issues/20218)).

## NEW ISSUES

### Superchain Operations and OPCM Updates
New issues highlight the need to update superchain operations. This includes updating the super root upgrade script to use the latest OPCM, which now supports the zk dispute game ([#20471](https://github.com/ethereum-optimism/optimism/issues/20471)). There's also a need to remove deprecated base checks from superchain ops that are broken due to the removal of base from the superchain registry ([#20472](https://github.com/ethereum-optimism/optimism/issues/20472)).

### `op-reth` and `alloy-op-evm` Improvements
Several issues were opened concerning `op-reth` and `alloy-op-evm`. This includes the need to remove the `ProtocolVersions` Solidity contract and OPCM remnants as part of a larger refactoring effort ([#20451](https://github.com/ethereum-optimism/optimism/issues/20451)). A fatal panic in `StateRootTask` when upgrading `op-reth` from 1.x to 2.x on OP Stack chains was reported ([#20462](https://github.com/ethereum-optimism/optimism/issues/20462)). Additionally, there's a proposal to drop dead-on-read `sender` and `evm_gas_used` fields from `OpTxResult` in `alloy-op-evm` as they have no consumers ([#20463](https://github.com/ethereum-optimism/optimism/issues/20463)). An issue was also reported where `op-reth init-state` stalls for OPM ([#20464](https://github.com/ethereum-optimism/optimism/issues/20464)).

### SDM and Supernode Related Tasks
A tracking issue for the SDM code complete milestone was created, aiming for feature flag/timestamp readiness for the next hardfork ([#20452](https://github.com/ethereum-optimism/optimism/issues/20452)). New runbook documentation is needed for updating a super root chain from permissioned to permissionless with OPCMv2 ([#20473](https://github.com/ethereum-optimism/optimism/issues/20473)). Finally, a new feature request for `op-dispute-mon` is to add the ability to query supernode's VNs to get output roots ([#20476](https://github.com/ethereum-optimism/optimism/issues/20476)).

This test continues to exhibit flakiness, with a reported success rate of approximately 91.3% on the `op-reth-e2e-sysgo-tests` job. This suggests a deeper, intermittent problem within the proof generation or state retrieval mechanisms that needs further investigation.

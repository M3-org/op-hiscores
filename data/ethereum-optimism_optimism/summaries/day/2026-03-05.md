# ethereum-optimism/optimism Daily Update (Mar 5, 2026)
## OVERVIEW 
Today's development focused on critical bug fixes in contracts, enhancing testing for L2ProxyAdmin, and improving monitoring for multi-supernode support in op-dispute-mon.

## KEY TECHNICAL DEVELOPMENTS

### Contract Bug Fixes and Security Enhancements
Significant bug fixes were implemented in the bedrock contracts. This included enforcing `onlyDelegateCall` in critical upgrade and migration functions, preventing cross-caller CREATE2 collisions, and adding duplicate instruction key detection in upgrade validation ([#19272](https://github.com/ethereum-optimism/optimism/pull/19272)). Additionally, a fix was introduced to make `OPContractsManagerUtils.upgrade()` forward-compatible with OpenZeppelin v5's `Initializable` storage layout ([#19286](https://github.com/ethereum-optimism/optimism/pull/19286)).

### Enhanced Testing and CI Improvements
Test coverage for the `L2ProxyAdmin` contract was expanded by reusing existing `ProxyAdmin` tests to ensure backwards compatibility ([#19377](https://github.com/ethereum-optimism/optimism/pull/19377)). Flaky acceptance tests related to ELSync stalling and `supernode/interop/activation` were temporarily disabled to allow for root cause investigation and focused fixes ([#19415](https://github.com/ethereum-optimism/optimism/pull/19415), [#19402](https://github.com/ethereum-optimism/optimism/pull/19402)). CI notifications for `contracts-bedrock` jobs were updated to include `@security-oncall` mentions on failure ([#19367](https://github.com/ethereum-optimism/optimism/pull/19367)).

### Monitoring and Infrastructure Updates
Metrics were added to `op-dispute-mon` to support multi-supernode functionality, tracking errors and disagreements ([#19105](https://github.com/ethereum-optimism/optimism/pull/19105)). The `op-acceptor` was updated to v3.10.1 ([#19390](https://github.com/ethereum-optimism/optimism/pull/19390)), `op-geth` was updated across the board ([#19414](https://github.com/ethereum-optimism/optimism/pull/19414)), and `make` was pinned to a specific version in `mise.toml` for consistent tooling ([#19396](https://github.com/ethereum-optimism/optimism/pull/19396)).

New issues were opened to determine if interop predeploys should be deployed on all chains regardless of interop activation ([#19406](https://github.com/ethereum-optimism/optimism/issues/19406)). This highlights a strategic decision point for the Superchain ecosystem.

### `op-reth` Interop Features
Two new issues focus on enhancing `op-reth` for interop. One is to implement the `L2PayloadWitness` hint for interop to support `op-reth` ([#19407](https://github.com/ethereum-optimism/optimism/issues/19407)), and the other is to implement interop tx pool filter and reorg eviction, which are currently present in `op-geth` but not `op-reth` ([#19411](https://github.com/ethereum-optimism/optimism/issues/19411)).

## ACTIVE ISSUES

### `op-reth` Memory Leak Investigation
The issue [#19212](https://github.com/ethereum-optimism/optimism/issues/19212) concerning a memory leak triggered by long-open database read transactions in `op-reth` is still active. The latest comments indicate that the issue has not recurred in the last 7 days on v1.10.2 for one user, but they have not yet upgraded to v1.11.0. The team is awaiting confirmation on whether the issue persists in the newer version. The problem has been observed repeatedly across multiple nodes.

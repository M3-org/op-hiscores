# ethereum-optimism/optimism Daily Update (Mar 5, 2026)
## OVERVIEW 
Today's development focused on critical bug fixes in contracts-bedrock, addressing audit findings and improving compatibility. Significant work was also done on testing infrastructure and dispute monitoring metrics.

## KEY TECHNICAL DEVELOPMENTS

### Contract Security and Compatibility Enhancements
Several critical bug fixes were implemented in the contracts-bedrock, addressing security audit findings and improving compatibility. This included enforcing `onlyDelegateCall` in key functions, preventing CREATE2 collisions, and ensuring forward-compatibility with OpenZeppelin v5's `Initializable` storage layout. Additionally, existing `DelayedWETH` from `SystemConfig` is now reused in the Migrator to avoid deploying new proxies.
- [#19272](https://github.com/ethereum-optimism/optimism/pull/19272)
- [#19286](https://github.com/ethereum-optimism/optimism/pull/19286)
- [#19281](https://github.com/ethereum-optimism/optimism/pull/19281)

### Improved Testing and CI Reliability
Efforts were made to enhance testing coverage and CI stability. This involved adding backwards-compatibility test coverage for the `L2ProxyAdmin` contract by reusing existing `ProxyAdmin` tests. Flaky ELSync stalling tests were quarantined in `op-acceptance-tests` for investigation, and problematic `supernode/interop/activation` tests were temporarily disabled to unblock other PRs. Security on-call mentions were also added to contracts-bedrock CI job failure notifications.

The `op-dispute-mon` now includes metrics for multi-supernode support, tracking errors and disagreements. Infrastructure updates included bumping `op-acceptor` to v3.10.1, updating `op-geth`, and pinning the `make` version in `mise.toml` for consistent tooling.

The user `jonathanudd` reported that the issue has not reoccurred in the last 7 days on v1.10.2, but they have not yet upgraded to v1.11.0. `geoknee` inquired if the issue recurs on v1.11.0.

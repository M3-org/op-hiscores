# ethereum-optimism/optimism Weekly Report (May 17 - 23, 2026)

## 🚀 Highlights
This week, development focused heavily on the transition from `op-supervisor` to `op-supernode`, marking a significant shift in the Superchain's architectural infrastructure. Engineering efforts prioritized core node stability, with critical fixes for transaction handling and execution layer synchronization. The team also made substantial progress in refining the interop startup process and enhancing the performance of `SafeDB` through optimized database lookups. Despite these advancements, the project is currently navigating several complex CI flakes related to safe head progression and synchronization offsets.

## 🛠️ Key Developments

### Supernode Migration and Interop Refinement
The project is aggressively moving toward `op-supernode` as the primary supervisor component.
*   **Architectural Shift:** Support for `op-supervisor` is being systematically removed from `op-challenger` ([#20850](https://github.com/ethereum-optimism/optimism/pull/20850)) and the devstack ([#20849](https://github.com/ethereum-optimism/optimism/pull/20849), [#20848](https://github.com/ethereum-optimism/optimism/pull/20848)).
*   **Startup Logic:** A major rework of the interop activity startup was introduced ([#20823](https://github.com/ethereum-optimism/optimism/pull/20823)), alongside fixes for backfill startup handoffs ([#20822](https://github.com/ethereum-optimism/optimism/pull/20822)) and requirements to wait for initial EL sync before cold starts ([#20833](https://github.com/ethereum-optimism/optimism/pull/20833)).
*   **Performance:** `SafeDB` was refactored to move `L1AtSafeHead` lookups directly into the database logic, replacing repeated point queries with a single Pebble cursor pass to improve efficiency ([#20845](https://github.com/ethereum-optimism/optimism/pull/20845)).

### Core Node Stability and Kona Integration
Improvements were made to the reliability of transaction submission and the integration of the Kona Rust-based stack.
*   **Transaction Handling:** The `txplan` retry loop now correctly handles `nonce-too-low` errors ([#20796](https://github.com/ethereum-optimism/optimism/pull/20796)), and `ELSync` now tolerates `NotFound` errors during finalized lookups ([#20798](https://github.com/ethereum-optimism/optimism/pull/20798)).
*   **Kona Progress:** Work continued on the Kona node deriver migration (Phase 4/6) ([#20829](https://github.com/ethereum-optimism/optimism/pull/20829)) and the composition of prestates from per-component packages ([#20836](https://github.com/ethereum-optimism/optimism/pull/20836)).
*   **Proof of Concept:** A new batcher consensus proof of concept was introduced under the "codex" initiative ([#20844](https://github.com/ethereum-optimism/optimism/pull/20844)).

### Testing and CI Infrastructure
*   **E2E Updates:** End-to-end tests were updated to replace `op-supervisor` with `op-supernode` ([#20825](https://github.com/ethereum-optimism/optimism/pull/20825)).
*   **Acceptance Testing:** New tests were added for interop resync scenarios involving execution layer wipes ([#20827](https://github.com/ethereum-optimism/optimism/pull/20824)).

## 🐛 Issues & Triage

### Closed Issues
*   **Flaky Tests:** `TestWithdrawal_Permissioned` ([#20345](https://github.com/ethereum-optimism/optimism/issues/20345)) was closed following a resolution to its intermittent CI failures.
*   **Documentation:** An issue regarding interop transaction pool eviction ([#19351](https://github.com/ethereum-optimism/optimism/issues/19351)) was closed as the logic is now natively implemented in `op-reth`.

### New & Active Issues
*   **Synchronization Flakes:** A new race condition was identified in `TestSupernodeInterop_SafeHeadProgression` ([#20851](https://github.com/ethereum-optimism/optimism/issues/20851)). Additionally, investigation continues into `TestELSyncSafeRetractedByOffset` ([#20334](https://github.com/ethereum-optimism/optimism/issues/20334)), where the `OffsetELSafe` configuration may be making the sync target unreachable.
*   **Bootstrap Incompatibility:** `op-reth` currently panics during minimal Bedrock bootstrap when using storage v2 ([#20821](https://github.com/ethereum-optimism/optimism/issues/20821)).
*   **Metrics Discrepancy:** `kona-node` and `op-reth` are reporting versions from `Cargo.toml` rather than git tags in Prometheus, leading to inconsistent monitoring data ([#20832](https://github.com/ethereum-optimism/optimism/issues/20832)).
*   **Dispute Game Development:** New tasks were opened to develop a simplified super permissioned dispute game ([#20834](https://github.com/ethereum-optimism/optimism/issues/20834)) and refine ZKDG scripts ([#20841](https://github.com/ethereum-optimism/optimism/issues/20841)).

## 💬 Community & Collaboration
The week's activity shows a high level of coordination regarding the deprecation of `op-supervisor`. Discussions in [#20814](https://github.com/ethereum-optimism/optimism/issues/20814) reveal a strategic pivot: rather than porting all dispute game tests to a new suite, contributors are opting to integrate `op-supernode` directly into existing `op-e2e` paths to accelerate the migration. Maintainers also actively moderated the repository by closing AI-generated spam ([#20847](https://github.com/ethereum-optimism/optimism/issues/20847)) and consolidating duplicate issues related to the `OPContractsManagerMigrator` ([#20502](https://github.com/ethereum-optimism/optimism/issues/20502)).

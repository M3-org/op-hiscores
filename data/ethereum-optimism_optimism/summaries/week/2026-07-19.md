# ethereum-optimism/optimism Weekly Report (Jul 19 - 25, 2026)

## 🚀 Highlights
This week, the Optimism ecosystem focused on advancing the **op-geth decoupling initiative** and hardening the **Kona-first fault proof** infrastructure. Significant progress was made in migrating core components like `op-node` and `op-batcher` toward `op-core` to ensure byte-identical behavior without internal dependencies on Geth. Additionally, the project underwent a major documentation overhaul, introducing automated flag-reference generation and new solution guides for custom deposit flows and fault-proof challengers.

## 🛠️ Key Developments

### Protocol Decoupling & `op-core` Migration
A primary focus this week was the ongoing effort to decouple the OP Stack from `op-geth` internals.
- **Core Logic Migration:** Swapped remaining one-off fork symbols to `op-core` and added OP transaction JSON codecs and consensus receipt encoding ([#21904](https://github.com/ethereum-optimism/optimism/pull/21904), [#21907](https://github.com/ethereum-optimism/optimism/pull/21907)).
- **OP-Aware Client:** Work began on making `op-service/sources` the primary OP-aware Ethereum client, including a design pivot for `op-batcher` to fetch execution payloads via `PayloadByNumber` rather than `InfoAndUserTxs` ([#21908](https://github.com/ethereum-optimism/optimism/pull/21908)).

### Fault Proofs & `op-challenger` Refinements
The team improved the reliability of dispute games and the transition to Kona-based proofs.
- **Lifecycle Management:** Fixed a critical bug in `op-challenger` to allow advancing anchors for finalized `SuperPermissionedDisputeGame` games without enabling full playability for specific game types ([#21811](https://github.com/ethereum-optimism/optimism/pull/21811)).
- **Kona Integration:** Cannon was removed from default game types in favor of Cannon Kona. `kona` itself received fixes for span-batch transaction type prefixes and improved gossip message metering to reduce log spam ([#21912](https://github.com/ethereum-optimism/optimism/pull/21912), [#21808](https://github.com/ethereum-optimism/optimism/pull/21808)).

### Developer Experience & Documentation
The project saw a massive push toward automated and comprehensive documentation.
- **Automated Flag References:** A new generator was rolled out to `op-node`, `op-proposer`, `op-challenger`, and `op-conductor` to ensure configuration docs stay in sync with the codebase ([#21873](https://github.com/ethereum-optimism/optimism/pull/21873)).
- **New Guides:** Introduced a component hub skeleton for `op-batcher` and `cannon`, alongside solution guides for custom deposit flows and a persona-based router for the documentation homepage ([#21865](https://github.com/ethereum-optimism/optimism/pull/21865), [#21848](https://github.com/ethereum-optimism/optimism/pull/21848)).
- **Tutorial Updates:** The `create-l2-rollup` tutorial was updated to reflect the shift from `op-geth` to `op-reth` ([#21899](https://github.com/ethereum-optimism/optimism/pull/21899)).

### CI & Infrastructure
- **Commit Hygiene:** CI now mandates scoped commits to improve the readability of the project's history ([#21855](https://github.com/ethereum-optimism/optimism/pull/21855)).
- **Devstack Improvements:** `op-devstack` now dynamically discovers OS-assigned service ports, eliminating race conditions during local port preallocation ([#21872](https://github.com/ethereum-optimism/optimism/pull/21872)).

## 🐛 Issues & Triage

### Closed Issues
- **Dispute Games:** Resolved issues regarding anchor advancement for finalized games and completed the `kona-sp1` Super program ([#21708](https://github.com/ethereum-optimism/optimism/issues/21708), [#21459](https://github.com/ethereum-optimism/optimism/issues/21459)).
- **Tooling:** Upgraded `kupcake` to support Lagoon and Blockscout ([#21879](https://github.com/ethereum-optimism/optimism/issues/21879)).

### New & Active Issues
- **Decoupling Blockers:** New issues were opened to migrate the `kona` proof harness off the in-process L2 execution engine, which is a critical step for further `op-geth` decoupling ([#21905](https://github.com/ethereum-optimism/optimism/issues/21905)).
- **Acceptance Testing:** There is an active push to expand `op-acceptance-tests` to cover `op-conductor` interactions with `kona-node` ([#21903](https://github.com/ethereum-optimism/optimism/issues/21903)).
- **Ongoing Discussions:** Technical debate continues regarding how `op-batcher` should handle L1-info deposit transactions and post-execution transactions when Superchain Dependency Manager (SDM) is active ([#20264](https://github.com/ethereum-optimism/optimism/issues/20264)).

## 💬 Community & Collaboration
The week was characterized by high-intensity internal refactoring and documentation cleanup. The transition to scoped commits indicates a tightening of contribution standards. Collaboration was particularly evident in the "scrubbing" of stale `op-program` guidance, which involved multiple rounds of reviews to ensure developer-facing information remains accurate during the transition to Kona-first fault proofs. Significant coordination is also visible between the protocol and documentation teams to ensure that technical shifts (like the move to `op-reth` in tutorials) are reflected immediately for the community.

# ethereum-optimism/optimism Weekly Report (May 3 - 9, 2026)

## 🚀 Highlights
This week focused on hardening the **Superchain interoperability** layer and refining the **Fault Proof** ecosystem. Significant progress was made in transitioning to deterministic testing environments and integrating the `kona-host` environment into standard acceptance suites. Developers successfully addressed critical stalling issues in `op-reth` and resolved several configuration bugs in `op-supernode`, while simultaneously streamlining the codebase by removing deprecated `ProtocolVersions` components. The project is moving toward a more robust "interop-by-default" stance, evidenced by the graduation of Kona witness collection from experimental status and the implementation of new SDM (Superchain Dependency Manager) features.

## 🛠️ Key Developments

### Fault Proofs & Kona Integration
The team significantly enhanced the reliability and scope of fault proof testing.
*   **Deterministic Testing:** Transitioned `SuperFaultProofs` to use `TestSequencer` for deterministic block production, allowing for the removal of "flaky" tags on several tests ([#20482](https://github.com/ethereum-optimism/optimism/pull/20482)).
*   **Kona Enhancements:** Integrated `kona-host` into Osaka acceptance tests ([#20509](https://github.com/ethereum-optimism/optimism/pull/20509), [#20530](https://github.com/ethereum-optimism/optimism/pull/20530)) and graduated `debug_executePayload` witness collection to the default setting for Kona ([#20498](https://github.com/ethereum-optimism/optimism/pull/20498)).
*   **Bug Fixes:** Resolved a critical EIP-2935 storage slot decoding error in `kona-proof` ([#20518](https://github.com/ethereum-optimism/optimism/pull/20518)) and fixed trace dispatching issues where `op-challenger` incorrectly routed super-chain game types to single-chain executors ([#20512](https://github.com/ethereum-optimism/optimism/pull/20512)).

### Supernode & Interoperability Infrastructure
Work continued on the foundational components of the Superchain, focusing on node stability and cross-chain consistency.
*   **op-supernode Stability:** Implemented fixes to prevent engine rewinds during L1 reorgs ([#20505](https://github.com/ethereum-optimism/optimism/pull/20505)) and corrected the logic for `VerifiedRequiredL1` to use the maximum per-chain L1 value ([#20484](https://github.com/ethereum-optimism/optimism/pull/20484)).
*   **SDM Development:** Added support for SDM (Superchain Dependency Manager) acceptance tests in `op-devstack` ([#20516](https://github.com/ethereum-optimism/optimism/pull/20516)) and introduced an admin RPC toggle for sequencer SDM opt-in ([#20541](https://github.com/ethereum-optimism/optimism/pull/20541)).
*   **Metrics & Networking:** Added effective safe/finalized metrics for `op-node` in supernode mode ([#20551](https://github.com/ethereum-optimism/optimism/pull/20551)) and enabled user-supplied P2P ports for `op-supernode` ([#20448](https://github.com/ethereum-optimism/optimism/pull/20448)).

### Protocol Refactoring & Cleanup
The codebase underwent significant maintenance to reduce technical debt.
*   **Contract Removal:** The `ProtocolVersions` Solidity contract and associated OPCM remnants were fully decommissioned to simplify the contract architecture ([#20527](https://github.com/ethereum-optimism/optimism/pull/20527)).
*   **Code Hygiene:** Removed unused `deploy.sh` scripts ([#20534](https://github.com/ethereum-optimism/optimism/pull/20534)) and refactored `op-service/sources` to optimize minimal-fetch paths ([#20532](https://github.com/ethereum-optimism/optimism/pull/20532)).

## 🐛 Issues & Triage

### Closed Issues
*   **Execution Layer Stability:** Resolved a critical `op-reth` stalling issue during `init-state` caused by transaction commitment timing ([#20464](https://github.com/ethereum-optimism/optimism/issues/20464)).
*   **Dispute Game Migration:** Fixed a security-relevant issue to disallow `SUPER_CANNON` as a respected game type during migration, enforcing the use of `KONA` variants ([#20030](https://github.com/ethereum-optimism/optimism/issues/20030)).
*   **Developer Experience:** Addressed slow Kona prestate builds, significantly improving local development velocity ([#19057](https://github.com/ethereum-optimism/optimism/issues/19057)).

### New & Active Issues
*   **Fault Proof Divergence:** A potential divergence was identified in `MessageGraph` where the Kona client lacks an interop activation guard present in `op-program` ([#20528](https://github.com/ethereum-optimism/optimism/issues/20528)).
*   **Interop Stress Testing:** Ongoing discussions regarding the interop expiry window suggest that extending the window to 7 days is safe, as costs scale linearly and are primarily limited by L2 gas limits rather than validation logic ([#15285](https://github.com/ethereum-optimism/optimism/issues/15285)).
*   **API Consistency:** New requirements emerged for `op-node` to support `superroot_atTimestamp` for non-interop chains to ensure API uniformity across the ecosystem ([#20552](https://github.com/ethereum-optimism/optimism/issues/20552)).

## 💬 Community & Collaboration
The week saw heavy collaboration between protocol engineers working on the "Kona" stack and the "op-node" maintainers. The rapid identification and resolution of the EIP-2935 decoding bug during live devnet stress testing ([#15285](https://github.com/ethereum-optimism/optimism/issues/15285)) highlights a tight feedback loop between infrastructure testing and client development. Additionally, the transition of SDM functionality into the `develop` branch remains a high-engagement area, with ongoing work required for benchmarking and final acceptance testing ([#20216](https://github.com/ethereum-optimism/optimism/issues/20216)).

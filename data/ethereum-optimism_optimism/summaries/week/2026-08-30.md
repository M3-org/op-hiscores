# ethereum-optimism/optimism Weekly Report (Aug 30 - Sep 5, 2026)

## 🚀 Highlights
This week focused on hardening the **Super ZK dispute game** and advancing **cross-chain interoperability** infrastructure. Significant progress was made in refining the security of withdrawal finalization through enhanced `StandardValidator` assertions and resolving critical bugs in `op-challenger` regarding game L1 head selection. The team also addressed monorepo maintainability by refactoring `op-core/superchain` to improve Go module consumability and optimizing `kona-sp1` proving reliability to retain progress across retries.

## 🛠️ Key Developments

### Super ZK & Dispute Game Security
Work centered on remediating internal review findings to bolster the robustness of the ZK dispute game and contract validation.
*   **Robustness Enhancements**: Added a solvency invariant and migration boundary tests for `ZKDisputeGame`, while bounding ZK durations within the `OPContractsManagerStandardValidator` ([#22328](https://github.com/ethereum-optimism/optimism/pull/22328)).
*   **Withdrawal Finalization**: Improved the `StandardValidator` in `contracts-bedrock` by adding assertions to ensure the `AnchorStateRegistry` respected game type is correctly registered, a critical gate for secure withdrawals ([#22471](https://github.com/ethereum-optimism/optimism/pull/22471)).
*   **Tooling Updates**: `op-challenger` now supports deriving super-root game inputs directly from `op-node` when a supernode is absent, simplifying the exercise of super-root prestates ([#22642](https://github.com/ethereum-optimism/optimism/pull/22642)).

### Interoperability & Kona Improvements
The ecosystem continues to prepare for interop launches with significant updates to the `kona` stack and private interop implementations.
*   **Proving Reliability**: The `kona-sp1` prover was updated to retain proving progress across retries, preventing the loss of completed chunks if a subsequent chunk fails ([#22717](https://github.com/ethereum-optimism/optimism/pull/22717)).
*   **Private Interop**: Introduced a private interop cleanroom implementation and logic to derive public projections from a single genesis ([#22720](https://github.com/ethereum-optimism/optimism/pull/22720), [#22729](https://github.com/ethereum-optimism/optimism/pull/22729)).
*   **Bug Fixes**: Resolved a critical `op-challenger` bug where the interop VM runner picked unusable L1 heads, which previously blocked claim serving ([#22727](https://github.com/ethereum-optimism/optimism/pull/22727)).

### Infrastructure & Refactoring
Efforts to streamline the monorepo and CI/CD pipelines were a major theme this week.
*   **Dependency Decoupling**: Refactored `op-service` to move `PathFlag` to a leaf package and removed `op-batcher`'s dependency on the registry edge to simplify configuration parsing ([#22700](https://github.com/ethereum-optimism/optimism/pull/22700), [#22712](https://github.com/ethereum-optimism/optimism/pull/22712)).
*   **CI/CD Maintenance**: Updated Rust nightly pins ([#22701](https://github.com/ethereum-optimism/optimism/pull/22701)), bumped `circleci-utils` to fix stale-PR timing ([#22723](https://github.com/ethereum-optimism/optimism/pull/22723)), and restored version stamping via apko factory updates ([#22722](https://github.com/ethereum-optimism/optimism/pull/22722)).

## 🐛 Issues & Triage

### Closed Issues
*   **ZK Development**: Successfully automated ZK devnet setup and Netchef support ([#21428](https://github.com/ethereum-optimism/optimism/issues/21428), [#22110](https://github.com/ethereum-optimism/optimism/issues/22110)).
*   **Protocol Validation**: Closed issues regarding Holocene span batch validation against the safe chain ([#22351](https://github.com/ethereum-optimism/optimism/issues/22351)) and the implementation of migration paths via `OPCMv2.upgrade()` ([#20757](https://github.com/ethereum-optimism/optimism/issues/20757)).

### New & Active Issues
*   **Interoperability Edge Cases**: A new issue identifies a risk where sanctioned addresses on one chain (but not others) in an interop set could lead to trapped funds, requiring a recovery mechanism ([#22719](https://github.com/ethereum-optimism/optimism/issues/22719)).
*   **Performance & Reliability**: Tracking potential inefficiencies in `alloy-op-evm` regarding DA scalar caching ([#22708](https://github.com/ethereum-optimism/optimism/issues/22708)) and the need for `kona-sp1-proposer` to be resilient to restarts to avoid losing in-flight proof requests ([#22726](https://github.com/ethereum-optimism/optimism/issues/22726)).
*   **Linter Bug**: A bug in the `bigint` custom linter was reported, causing unbound qualifiers when `op-service/bigs` is aliased ([#22702](https://github.com/ethereum-optimism/optimism/issues/22702)).

## 💬 Community & Collaboration
The most active technical discussion centered on **[#22678](https://github.com/ethereum-optimism/optimism/issues/22678)**, regarding the consumability of `op-core/superchain` by downstream Go modules.

# ethereum-optimism/optimism Weekly Report (Mar 22 - 28, 2026)

## 🚀 Highlights
This week focused on hardening the OP Stack's testing infrastructure and advancing the Interop and Kona workstreams. Significant progress was made in integrating a spec-compliant ZK Dispute Game and deploying critical ETH bridge contracts for interop activation. A major push to resolve long-standing flakiness in acceptance tests resulted in the closure of several persistent issues, driven by a shift toward deterministic block advancement and improved tracking annotations. Meanwhile, the Kona guest program saw critical bug fixes regarding MIPS64 architecture and metadata handling, ensuring better stability for Cannon VM execution.

## 🛠️ Key Developments

### Interoperability & Superchain Infrastructure
The foundation for cross-chain interoperability saw significant updates this week, focusing on contract deployment and devstack tooling.
*   **Bridge Deployment:** Integrated the deployment and funding of `SuperchainETHBridge` and `ETHLiquidity` contracts into the interop network upgrade path ([#19648](https://github.com/ethereum-optimism/optimism/pull/19648)).
*   **Devstack Tooling:** Enhanced `op-up` with an `--interop` flag to launch 2-chain devnets backed by `op-supernode` ([#19747](https://github.com/ethereum-optimism/optimism/pull/19747)).
*   **Protocol Refinement:** Removed several interop bridge contracts from the `L2ContractsManager` upgrade flow to streamline management ([#19650](https://github.com/ethereum-optimism/optimism/pull/19650)).

### Kona & Fault Proofs
Kona received several critical fixes to improve its reliability as a ZK/Fault proof components.
*   **Architecture Fixes:** Corrected MIPS64 target specifications, specifically masking `rs` to 32 bits for count loops and adjusting `target-c-int-width` ([#19717](https://github.com/ethereum-optimism/optimism/pull/19717), [#19730](https://github.com/ethereum-optimism/optimism/pull/19730)).
*   **Data Integrity:** Fixed a bug in `L1Retrieval` to ensure the data availability provider is cleared on reset, preventing stale data leaks ([#19687](https://github.com/ethereum-optimism/optimism/pull/19687)).
*   **ZK Integration:** Successfully integrated a new spec-compliant ZK Dispute Game, replacing the legacy `OptimisticZkGame` ([#19606](https://github.com/ethereum-optimism/optimism/pull/19606)).

### Testing Infrastructure & CI/CD
A concerted effort was made to eliminate non-deterministic test failures and improve developer feedback loops.
*   **Deterministic Testing:** Replaced `time.Sleep` with deterministic block advancement in `op-acceptance-tests` to ensure consistent execution ([#19683](https://github.com/ethereum-optimism/optimism/pull/19683)).
*   **Flaky Test Tracking:** Introduced `FLAKY_FAIL`/`FLAKY_PASS` annotations in JUnit XML to better identify and manage unstable tests ([#19719](https://github.com/ethereum-optimism/optimism/pull/19719)).
*   **CI Optimization:** Introduced a new CI gate job for `develop` branch status checks and implemented logic to skip Rust/Devnet workflows for documentation-only PRs ([#19535](https://github.com/ethereum-optimism/optimism/pull/19535), [#19739](https://github.com/ethereum-optimism/optimism/pull/19739)).

## 🐛 Issues & Triage

### Closed Issues
*   **Acceptance Test Stability:** A suite of long-standing flaky tests were closed following successful de-flaking efforts, including `TestChallengerPlaysGame` ([#19672](https://github.com/ethereum-optimism/optimism/issues/19672)), `TestSyncUnsafe` ([#19731](https://github.com/ethereum-optimism/optimism/issues/19731)), and `TestSuperchain` ([#19586](https://github.com/ethereum-optimism/optimism/issues/19586)).
*   **Kona Guest Panics:** Resolved an issue where the Kona guest program panicked due to a missing `name` field in the superchain registry's `chainList.json` ([#19654](https://github.com/ethereum-optimism/optimism/issues/19654)).
*   **ZK Dispute Game:** Closed several issues related to ZK contract MCP compatibility and L2 ChainID mapping ([#18417](https://github.com/ethereum-optimism/optimism/issues/18417), [#18421](https://github.com/ethereum-optimism/optimism/issues/18421)).

### New & Active Issues
*   **Alloy 1.8 Conflict:** A new conflict was identified in `op-alloy-network` where a blanket implementation in `alloy-network` 1.8 clashes with existing `NetworkWallet<Optimism>` code ([#19755](https://github.com/ethereum-optimism/optimism/issues/19755)).
*   **TestCLELDivergence:** This remains the most active "problem" test. While PR [#19733](https://github.com/ethereum-optimism/optimism/pull/19733) attempted a fix, discussions continue regarding whether the derivation pipeline's reset behavior is a bug or intended protocol logic ([#19681](https://github.com/ethereum-optimism/optimism/issues/19681)).
*   **Interop Phase 3:** Ongoing technical discussion regarding the ability to remove chains from shared dispute games and the implications for the proof system ([#19692](https://github.com/ethereum-optimism/optimism/issues/19692)).

## 💬 Community & Collaboration
Collaboration this week was characterized by high-intensity debugging of the testing suite. Maintainers worked closely on "deep scans" of CI pipelines to validate fixes for flaky tests, indicating a strong focus on repo health. There was also significant cross-component coordination between the Kona (Rust) and OP Stack (Go) teams to align on MIPS64 target specifications and EIP-2935 block hash oracle testing. The introduction of free Base L2 developer APIs ([#19718](https://github.com/ethereum-optimism/optimism/issues/19718)) suggests an active effort to engage the broader developer community in testing new L2 toolkits.

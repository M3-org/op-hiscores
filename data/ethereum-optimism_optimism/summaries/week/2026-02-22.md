# ethereum-optimism/optimism Weekly Report (Feb 22 - 28, 2026)

## 🚀 Highlights
This week focused on advancing the **L2 Contracts Manager (L2CM)**, a critical infrastructure component for enabling seamless L2 predeploy upgrades via `DELEGATECALL`. Significant progress was made on **Interoperability (Interop)** stability, including the integration of the Karst hard fork and the refinement of fault proof testing within `op-devstack`. Development also prioritized CI/CD reliability, addressing Kona prestate publishing permissions and optimizing Rust compilation workflows to improve contributor experience and build reproducibility.

## 🛠️ Key Developments

### L2 Upgradeability & Smart Contracts
The foundational **L2ContractsManager (L2CM)** was implemented ([#19111](https://github.com/ethereum-optimism/optimism/pull/19111)), allowing for the upgrade of L2 predeploys through a ProxyAdmin. This was accompanied by several audit-related fixes and documentation updates:
*   **Audit Remediation:** Addressed findings related to non-idempotent initializers ([#19273](https://github.com/ethereum-optimism/optimism/pull/19273)), `onlyDelegateCall` protections ([#19272](https://github.com/ethereum-optimism/optimism/pull/19272)), and forward-compatibility with OpenZeppelin v5 ([#19286](https://github.com/ethereum-optimism/optimism/pull/19286)).
*   **Testing Enhancements:** Significantly improved `DelayedWETH` coverage by converting existing tests to fuzz tests ([#19275](https://github.com/ethereum-optimism/optimism/pull/19275)).

### Interoperability & Core Infrastructure
The ecosystem moved closer to robust cross-chain functionality with the integration of the **Karst hard fork** ([#19250](https://github.com/ethereum-optimism/optimism/pull/19250)) and several Interop-specific updates:
*   **Fault Proofs:** Ported interop fault proof tests to `devstack` ([#19254](https://github.com/ethereum-optimism/optimism/pull/19254)) and added single-chain smoke tests to validate super fault proofs ([#19299](https://github.com/ethereum-optimism/optimism/pull/19299)).
*   **op-supernode:** Improved lifecycle management to prevent hangs on shutdown ([#19293](https://github.com/ethereum-optimism/optimism/pull/19293)) and addressed "Initial Block Seal" logic ([#19308](https://github.com/ethereum-optimism/optimism/pull/19308)).
*   **op-devstack:** Refactored the Orchestrator to use a unified registry, simplifying the ID type system ([#18875](https://github.com/ethereum-optimism/optimism/pull/18875)).
*   **Transaction Ordering:** Introduced `PolicyEngineStaking` to enable stake-aware transaction ordering in `op-rbuilder` ([#19192](https://github.com/ethereum-optimism/optimism/pull/19192)).

### CI/CD & Tooling
Efficiency and reliability in the development pipeline were key priorities:
*   **Kona Publishing:** Resolved failures in Kona prestate publishing by aligning authentication scopes with Cannon ([#19268](https://github.com/ethereum-optimism/optimism/pull/19268)) and fixing workflow triggers ([#19270](https://github.com/ethereum-optimism/optimism/pull/19270)).
*   **Rust Optimization:** Disabled incremental compilation in CI to reduce cache size and prevent "Internal Compiler Errors" (ICE) ([#19274](https://github.com/ethereum-optimism/optimism/pull/19274), [#19278](https://github.com/ethereum-optimism/optimism/pull/19278)).
*   **Dependency Management:** Bumper `reth`/`op-reth` to v1.11.1 and updated the Minimum Supported Rust Version (MSRV) to 1.92 ([#19292](https://github.com/ethereum-optimism/optimism/pull/19292)).

## 🐛 Issues & Triage

### Closed Issues
*   **RPC Performance:** Resolved critical concerns regarding `eth_getLogs` memory exhaustion and potential OOM vulnerabilities by deferring to upstream Geth fixes ([#768](https://github.com/ethereum-optimism/optimism/issues/768), [#769](https://github.com/ethereum-optimism/optimism/issues/769)).
*   **Kona Optimization:** Closed discussions on Kona hint formatting, opting to prioritize backward compatibility over string-to-binary serialization changes ([#19125](https://github.com/ethereum-optimism/optimism/issues/19125)).

### New & Active Issues
*   **L2CM Security:** A surge of new issues focuses on the security of the L2 Contracts Manager, including preventing storage variable collisions during `DELEGATECALL` ([#19315](https://github.com/ethereum-optimism/optimism/issues/19315)) and ensuring atomicity in upgrades ([#18830](https://github.com/ethereum-optimism/optimism/issues/18830)).
*   **Supernode Reorgs:** New issues were opened to address the need for pruning the Interop Database and Denylist during L1 reorgs to maintain data consistency ([#19287](https://github.com/ethereum-optimism/optimism/issues/19287), [#19289](https://github.com/ethereum-optimism/optimism/issues/19289)).
*   **Superroot SLA:** Ongoing debate regarding the "Superroot" object's availability, with proposals to treat missing roots as "best-effort" or empty values to prevent system stalls ([#19180](https://github.com/ethereum-optimism/optimism/issues/19180)).

## 💬 Community & Collaboration
Collaboration this week was characterized by high-intensity technical reviews of the L2CM and Interop frameworks. Maintainers and contributors engaged in deep architectural discussions regarding the "Network Upgrade Transactions" (NUT) bundles and the necessity of deterministic JSON generation to prevent tampering ([#18834](https://github.com/ethereum-optimism/optimism/issues/18834)). User support was also active, notably resolving Docker image availability queries for `op-reth` v1.11.0, ensuring the community has access to the latest stable releases.

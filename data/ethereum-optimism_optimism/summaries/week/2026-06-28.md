# ethereum-optimism/optimism Weekly Report (Jun 28 - 4, 2026)

## 🚀 Highlights
This week, development focused heavily on maturing the infrastructure for the Optimism Collective’s technical roadmap, specifically regarding the new deployment pipeline and L2 genesis processes. Significant milestones were reached in enabling permissionless dispute games from block zero and centralizing predeploy logic via the `L2ContractsManager`. While core protocol maintenance continued through dependency updates and CLI refinements, the community remains focused on resolving critical synchronization and gas estimation issues affecting the Karst hard fork and pruned node configurations.

## 🛠️ Key Developments

### Deployment Infrastructure & op-deployer
Significant work was dedicated to streamlining the deployment process and resolving architectural bottlenecks.
*   **Deployment Pipeline:** Completed the design for a new pipeline that resolves cyclic dependencies and supports permissionless dispute games from the initial block ([#20897](https://github.com/ethereum-optimism/optimism/issues/20897)).
*   **op-deployer Enhancements:** Introduced new features for depset and prestate generation ([#21601](https://github.com/ethereum-optimism/optimism/pull/21601)) and implemented anchor block selection for the prepare phase ([#21600](https://github.com/ethereum-optimism/optimism/pull/21600)).
*   **L2 Genesis Refactor:** Integrated `L2ContractsManager` as the primary source of truth for predeploy setups, moving away from independent logic in `L2Genesis.s.sol` ([#20903](https://github.com/ethereum-optimism/optimism/issues/20903)).

### Protocol Maintenance & Tooling
Refinements were made to monitoring, proof generation, and core libraries.
*   **Proof Systems:** A new feature for proof backfill batching was introduced ([#21602](https://github.com/ethereum-optimism/optimism/pull/21602)), and Prometheus metric bucket handling was improved in the `op-proofs` CLI ([#21596](https://github.com/ethereum-optimism/optimism/pull/21596)).
*   **Error Handling:** Fixed a bug in `op-preimage` to ensure read and write close errors are properly preserved ([#21597](https://github.com/ethereum-optimism/optimism/pull/21597)).
*   **Dependency Updates:** Updated critical libraries including `gnark-crypto` to v0.20.1 ([#21598](https://github.com/ethereum-optimism/optimism/pull/21598)) and `go-datastore` to v0.9.2 ([#21599](https://github.com/ethereum-optimism/optimism/pull/21599)).
*   **Testing:** Moved scheduled tests to a daily cadence to improve monitoring consistency ([#21595](https://github.com/ethereum-optimism/optimism/pull/21595)).

## 🐛 Issues & Triage

### Closed Issues
The team successfully closed major architectural issues related to the **New Deployment Pipeline** ([#20897](https://github.com/ethereum-optimism/optimism/issues/20897)) and **L2 Genesis Integration** ([#20903](https://github.com/ethereum-optimism/optimism/issues/20903)), effectively centralizing the predeploy logic and paving the way for more robust L2 chain launches.

### New & Active Issues
*   **Optimism Sepolia Gas Anomalies:** Users continue to report "intrinsic gas too high" errors on Optimism Sepolia following the Karst hard fork ([#21457](https://github.com/ethereum-optimism/optimism/issues/21457)). While `staticCall` succeeds, `eth_estimateGas` fails across multiple RPC providers. A fix is anticipated in the upcoming release ([#21574](https://github.com/ethereum-optimism/optimism/pull/21574)).
*   **Node Sync Failures:** There is an ongoing technical discussion regarding `op-node` sync modes ([#21465](https://github.com/ethereum-optimism/optimism/issues/21465)). Specifically, nodes using execution-layer sync with pruning must manually set `--syncmode.offset-el-safe=0` to avoid referencing pruned blocks. Contributors are advocating for better defaults or more explicit documentation in release notes.

## 💬 Community & Collaboration
Collaboration this week was characterized by deep technical troubleshooting between node operators and maintainers. The discussion surrounding issue [#21465](https://github.com/ethereum-optimism/optimism/issues/21465) highlights an active feedback loop regarding the usability of `op-node` configurations. Additionally, the steady stream of dependency updates via Dependabot and the transition of tests to a daily cadence indicate a strong focus on automated maintenance and project health.

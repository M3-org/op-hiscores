# ethereum-optimism/optimism Weekly Report (Mar 15 - 21, 2026)

## 🚀 Highlights
This week focused on hardening the **Supernode** infrastructure and advancing **interoperability (interop)** features through a massive stabilization effort. Developers successfully migrated the build system from Makefiles to **Justfiles**, streamlined CI pipelines by moving Docker builds to GitHub Actions, and addressed dozens of flaky tests to improve development velocity. Significant architectural progress was made in L2 contract management with the introduction of **L2 Dev Flags** and the universal refactoring of proxy administration, while official releases were cut for critical Supernode and interop filter binaries.

## 🛠️ Key Developments

### Supernode & Interoperability
The team prioritized the consistency and reliability of the Supernode, which is central to the Superchain's cross-chain functionality.
*   **Consistency Guarantees:** Refactored the Supernode interop activity around a single persisted transition model for strong consistency ([#19505](https://github.com/ethereum-optimism/optimism/pull/19505)).
*   **L1 Sync & Safety:** Implemented logic to cap `CurrentL1` at the minimum of node `CurrentL1`s during interop advancement to prevent state inconsistencies ([#19620](https://github.com/ethereum-optimism/optimism/pull/19620)).
*   **Error Handling:** Added beacon fallback support for blob sidecar retrieval ([#19645](https://github.com/ethereum-optimism/optimism/pull/19645)) and fixed issues where the Supernode failed to pause chains before rewinding on invalid messages ([#19558](https://github.com/ethereum-optimism/optimism/pull/19558)).
*   **Interop Filtering:** Updated `op-interop-filter` to handle zero start timestamps and added a passthrough mode for development flexibility ([#19541](https://github.com/ethereum-optimism/optimism/pull/19541), [#19565](https://github.com/ethereum-optimism/optimism/issues/19565)).

### Protocol & Smart Contracts
Refactoring efforts aimed to standardize how L1 and L2 contracts are managed and deployed.
*   **Universal Inheritance:** Refactored `ProxyAdminOwnedBase` into a universal contract in `contracts-bedrock`, allowing both L1 and L2 contracts to share the same modular ownership logic ([#19478](https://github.com/ethereum-optimism/optimism/pull/19478), [#19564](https://github.com/ethereum-optimism/optimism/pull/19564)).
*   **L2 Dev Flags:** Introduced per-chain configuration for development features, enabling more granular control over experimental L2 functionalities ([#19324](https://github.com/ethereum-optimism/optimism/pull/19324)).
*   **ZK Proofs:** Initial work began on `opcm` ZK proofs and a new ZK dispute game, signaling a push toward zero-knowledge fault proof integration ([#19607](https://github.com/ethereum-optimism/optimism/pull/19607), [#19606](https://github.com/ethereum-optimism/optimism/pull/19606)).

### Tooling & Infrastructure
A major overhaul of the developer experience and CI/CD pipelines was completed.
*   **Build System Migration:** Completed the transition from `make` to `just` across the repository, including CI, Dockerfiles, and documentation ([#19526](https://github.com/ethereum-optimism/optimism/pull/19526), [#19546](https://github.com/ethereum-optimism/optimism/issues/19546)).
*   **CI Optimization:** Migrated Docker builds to GitHub Actions and implemented per-image change detection to reduce redundant build times ([#19603](https://github.com/ethereum-optimism/optimism/pull/19603)).
*   **Rust/EVM Refactoring:** Moved OP-specific EVM implementations into newtypes within `alloy-op-evm` for better maintainability ([#19536](https://github.com/ethereum-optimism/optimism/pull/19536)).

## 🐛 Issues & Triage

### Closed Issues
*   **Flaky Test Resolution:** A concerted effort resolved long-standing flakiness in `TestSupernodeInteropActivationAfterGenesis`, `TestChallengerPlaysGame`, and various `op-e2e` tests by addressing nonce races and tightening timeouts ([#18137](https://github.com/ethereum-optimism/optimism/issues/18137), [#19615](https://github.com/ethereum-optimism/optimism/pull/19615)).
*   **Infrastructure:** Resolved issues with `just` installation in Docker build prep and updated the `check-super-root` script to work with the new Supernode RPC ([#19524](https://github.com/ethereum-optimism/optimism/issues/19524), [#19454](https://github.com/ethereum-optimism/optimism/pull/19454)).

### New & Active Issues
*   **`op-reth` Stability:** New reports surfaced regarding database integrity errors during Ink Sepolia backfills ([#19639](https://github.com/ethereum-optimism/optimism/issues/19639)) and Out-Of-Memory (OOM) errors during proof initialization on Base Mainnet ([#19640](https://github.com/ethereum-optimism/optimism/issues/19640)).
*   **Kona Panics:** A critical issue was identified where the Kona guest program panics during Cannon VM execution when deserializing the superchain registry ([#19654](https://github.com/ethereum-optimism/optimism/issues/19654)).
*   **Deployment Gaps:** Concerns were raised that interop activation transactions currently omit the deployment of `SuperchainETHBridge` and `ETHLiquidity` ([#19646](https://github.com/ethereum-optimism/optimism/issues/19646)).

## 💬 Community & Collaboration
The week was characterized by high-intensity internal collaboration on CI/CD reliability. The transition to `just` and the migration of Docker builds required coordinated updates across multiple sub-teams (Node, Contracts, and Infrastructure). There is significant ongoing technical discussion regarding `op-reth` memory leaks, with users from World Chain and Manta Pacific providing data to help debug database read transaction issues ([#19212](https://github.com/ethereum-optimism/optimism/issues/19212)). The cutting of official releases for the Supernode and interop filter binaries marks a key milestone for external contributors looking to run the latest interoperability stack.

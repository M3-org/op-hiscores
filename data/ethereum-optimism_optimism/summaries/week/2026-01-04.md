# ethereum-optimism/optimism Weekly Report (Jan 4 - 10, 2026)

## 🚀 Highlights
This week's development focused heavily on advancing the Superchain's interoperability and refining the dispute game mechanism. Key progress was made by implementing interop migration support in OPCMv2 and enhancing the `IDisputeGame` interface to support cross-chain claim retrieval. A significant architectural shift is underway, with components like `op-challenger` beginning to integrate the `op-supernode` in place of the older `op-supervisor`. Concurrently, the team is actively diagnosing and addressing stability issues within the Kona node, particularly concerning its handling of L1 reorgs and data availability.

## 🛠️ Key Developments
Work this week centered on protocol enhancements for interoperability, bug fixes for core components, and a major push in improving test coverage.

-   **Dispute Game & Interop Enhancements:**
    -   To prepare for future Superchain interoperability, the `IDisputeGame` interface was updated with an overloaded `rootClaim` function, allowing claims to be retrieved by L2 chain ID ([#18559](https://github.com/ethereum-optimism/optimism/pull/18559)).
    -   The `op-challenger` was updated to integrate the `supernode` trace provider, a key step in phasing out `op-supervisor` ([#18668](https://github.com/ethereum-optimism/optimism/pull/18668)).
    -   The codebase was simplified by removing support for deprecated and unshipped game types (Asterisc, AsteriscKona, SuperAsteriscKona) from `op-challenger` and `op-dispute-mon` ([#18670](https://github.com/ethereum-optimism/optimism/pull/18670)).

-   **Core Protocol & Contract Improvements:**
    -   Interop migration functionality was implemented within OPCMv2, a foundational piece for enabling cross-chain operations ([#18649](https://github.com/ethereum-optimism/optimism/pull/18649)).
    -   The `op-batcher` was streamlined by removing `isPectra` checks, as the Pectra L1 fork is now assumed to be universally active ([#18534](https://github.com/ethereum-optimism/optimism/pull/18534)).

-   **Bug Fixes & Stability:**
    -   A critical nil pointer dereference in `op-batcher` that occurred when `forcePublish` was enabled was resolved, preventing potential crashes ([#18701](https://github.com/ethereum-optimism/optimism/pull/18701)).
    -   A bug in `check-prestate` that caused failures when `op-geth` was referenced as a Go pseudo-version has been fixed ([#18691](https://github.com/ethereum-optimism/optimism/pull/18691)).
    -   An issue with environment variable prefix handling in `op-supernode` was corrected to ensure proper configuration ([#18720](https://github.com/ethereum-optimism/optimism/pull/18720)).

-   **Testing & Developer Experience:**
    -   Test coverage was significantly improved for the `OptimismMintableERC20` contract and its factory by converting focused tests into more robust fuzz tests ([#18696](https://github.com/ethereum-optimism/optimism/pull/18696), [#18707](https://github.com/ethereum-optimism/optimism/pull/18707)).
    -   The `UpgradeOPChain` script for the OPCM V2 upgrade path received enhanced test coverage, including fuzzing and revert case testing ([#18704](https://github.com/ethereum-optimism/optimism/pull/18704)).

## 🐛 Issues & Triage
Discussions this week were dominated by Kona node stability and the ongoing transition to `op-supernode`.

-   **Closed Issues:**
    -   Key preparatory work for interoperability was completed with the closure of the issue to add `rootClaim(uint256 l2ChainId)` to the `IDisputeGame` interface ([#18516](https://github.com/ethereum-optimism/optimism/issues/18516)).
    -   The effort to simplify the batcher by removing now-redundant `isPectra` checks was concluded ([#18479](https://github.com/ethereum-optimism/optimism/issues/18479)).
    -   An inquiry about ZK game integration was clarified, noting that `OptimisticZkGame.sol` is not yet production-ready ([#18692](https://github.com/ethereum-optimism/optimism/issues/18692)).

-   **New & Active Issues:**
    -   **Kona Node Stability:** A cluster of active issues points to a focus on improving Kona's robustness. Discussions are ongoing to address L2 reorgs caused by L1 reorgs ([#18676](https://github.com/ethereum-optimism/optimism/issues/18676)), a safe head stall due to blob fetching failures ([#18716](https://github.com/ethereum-optimism/optimism/issues/18716)), and an incorrect `current_l1` value in the `optimism_syncStatus` RPC response ([#18673](https://github.com/ethereum-optimism/optimism/issues/18673)).
    -   **Supernode Transition:** Several issues track the work needed to fully replace `op-supervisor` with `op-supernode`. This includes updating the `op-challenger` vm-runner ([#18669](https://github.com/ethereum-optimism/optimism/issues/18669)) and ensuring the `superroot_atTimestamp` API is consistent and reflects verified L1 blocks ([#18651](https://github.com/ethereum-optimism/optimism/issues/18651), [#18667](https://github.com/ethereum-optimism/optimism/issues/18667)).
    -   **Critical Bug:** A long-standing issue with `eth_simulatev1` returning an error for missing deposit transactions since the Jovian fork remains active and critical for backrunning strategies ([#739](https://github.com/ethereum-optimism/optimism/issues/739)).

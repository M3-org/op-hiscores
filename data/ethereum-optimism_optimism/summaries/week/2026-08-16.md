# ethereum-optimism/optimism Weekly Report (Aug 16 - 22, 2026)

## 🚀 Highlights
This week, development focused on hardening core infrastructure and advancing the Rust-based ecosystem, notably through the rebranding and initial scaffolding of **Lokahi** (formerly the Rust supernode). Significant progress was made in protocol integrity with the implementation of centralized Holocene span batch validation across `op-node` and `kona`. The team also prioritized system stability by resolving critical data races in `op-batcher` and fixing sequencer shutdown blockers, while simultaneously streamlining CI/CD pipelines through the adoption of Wolfi runner images and optimized test suites.

## 🛠️ Key Developments

### Kona & Rust Ecosystem Evolution
The project made significant strides in its Rust-based stack, focusing on modularity and multi-chain readiness.
*   **Lokahi (Rust Supernode):** The `rust-supernode` was officially renamed to `lokahi`. Initial work included publishing container images, sharing version accessors with `op-version`, and establishing a CLI skeleton ([#22509](https://github.com/ethereum-optimism/optimism/pull/22509), [#22504](https://github.com/ethereum-optimism/optimism/pull/22504)).
*   **Kona Protocol Enhancements:** Implemented hash-keyed L2 block info lookups for reset walk-backs ([#22465](https://github.com/ethereum-optimism/optimism/pull/22465)) and consolidated `kona-safedb` versions to reduce technical debt ([#22511](https://github.com/ethereum-optimism/optimism/pull/22511)).
*   **Kona SP1:** Modularized proposer functionality by introducing crate-private ports for `SuperRootSource` and `ProofEngine`, and decomposed game synchronization into distinct phases ([#22483](https://github.com/ethereum-optimism/optimism/pull/22483), [#22497](https://github.com/ethereum-optimism/optimism/pull/22497)).

### Protocol Integrity & Core Infrastructure
Refinements to the OP Stack focused on derivation accuracy and sequencer reliability.
*   **Holocene Validation:** Centralized Holocene span batch checks were implemented in both `op-node` and `kona` to ensure span batch overlap content aligns with the safe chain ([#22215](https://github.com/ethereum-optimism/optimism/pull/22215)).
*   **Stability Fixes:** Addressed eleven data races in `op-batcher` throttling tests ([#22470](https://github.com/ethereum-optimism/optimism/pull/22470)) and resolved a bug where `Sequencer.Stop` would block indefinitely during shutdown ([#22458](https://github.com/ethereum-optimism/optimism/pull/22458)).
*   **op-devstack:** Fixed a critical unit error where L1 HTTP poll intervals were interpreted as nanoseconds instead of milliseconds ([#22499](https://github.com/ethereum-optimism/optimism/pull/22499)).

### CI/CD & Developer Experience
The team optimized the development lifecycle to reduce friction and improve security.
*   **Pipeline Optimization:** Switched Rust CI base images to Wolfi runners for a smaller security footprint ([#22459](https://github.com/ethereum-optimism/optimism/pull/22459)) and implemented logic to skip merge queue tests for documentation-only changes ([#22434](https://github.com/ethereum-optimism/optimism/pull/22434)).
*   **Dependency Security:** Performed a security rollup for Rust dependencies (including `lru` and `anyhow`) and updated Go toolchains to `v1.26.6` ([#22500](https://github.com/ethereum-optimism/optimism/pull/22500), [#22424](https://github.com/ethereum-optimism/optimism/pull/22424)).

## 🐛 Issues & Triage

### Closed Issues
*   **Performance Benchmarking:** The SDM performance benchmarking ([#20176](https://github.com/ethereum-optimism/optimism/issues/20176)) was closed after production data confirmed negligible CPU/RSS impact under load.
*   **P2P Stability:** Resolved long-standing flakiness in `op-reth` <-> `op-geth` connections by normalizing peer-ID formats and re-enabling P2P connection checks ([#18570](https://github.com/ethereum-optimism/optimism/issues/18570)).
*   **Milestone Completion:** Formally closed PCD Milestone 3 (Quality and Benchmarking) and Milestone 4 (Network Automated Deployment) ([#20900](https://github.com/ethereum-optimism/optimism/issues/20900), [#22359](https://github.com/ethereum-optimism/optimism/issues/22359)).

### New & Active Issues
*   **Lokahi Roadmap:** A major tracking issue was opened to outline the development of the Rust multi-chain interop node, including phases for N-chain scaffolding and interop actor implementation ([#22547](https://github.com/ethereum-optimism/optimism/issues/22547)).
*   **Signer Rotation Discrepancy:** A new issue highlights a potential inconsistency between `kona-node` and `op-node` regarding the three-hour grace period for unsafe signer rotations ([#22447](https://github.com/ethereum-optimism/optimism/issues/22447)).

## 💬 Community & Collaboration
Collaboration this week was characterized by a heavy emphasis on cross-implementation parity, particularly between Go and Rust components. The introduction of the `StandardValidator` reviewer agent for documentation ([#22420](https://github.com/ethereum-optimism/optimism/pull/22420)) and the removal of the `FlakyOnOpReth` helper—signaling that all acceptance tests now pass on `op-reth`—demonstrates a maturing multi-client ecosystem. The team also formalized a process for flagging breaking changes in PR titles to improve the quality of automated release notes ([#22510](https://github.com/ethereum-optimism/optimism/pull/22510)).

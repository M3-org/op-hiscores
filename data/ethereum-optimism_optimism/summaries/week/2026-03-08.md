# ethereum-optimism/optimism Weekly Report (Mar 8 - 14, 2026)

## 🚀 Highlights
This week, development focused heavily on the maturation of the **Kona** and **Rust-based infrastructure**, signaling a strategic shift toward making Kona the default respected game type. Significant progress was made on the **Karst hardfork** integration, including the implementation of Network Upgrade Transaction (NUT) bundle generation and inlined derivation pipelines. Beyond feature expansion, the team prioritized protocol stability by resolving critical bugs in the `op-supernode` L1 tracking and the Kona derivation pipeline, while simultaneously modernizing the developer experience by migrating legacy Makefiles to `justfiles`.

## 🛠️ Key Developments

### Kona & Rust Stack Integration
The project is aggressively moving toward a Rust-centric stack. Key milestones include:
*   **Default Game Type:** Scaffolding was introduced to establish Kona as the default respected game type ([#19117](https://github.com/ethereum-optimism/optimism/pull/19117)).
*   **Derivation Pipeline Robustness:** Multiple fixes addressed critical halts in Kona's derivation, including handling blob under-fills ([#19362](https://github.com/ethereum-optimism/optimism/pull/19362)), ensuring non-fatal system config updates ([#19361](https://github.com/ethereum-optimism/optimism/pull/19361)), and adding bounds checks for span batch decoding ([#19358](https://github.com/ethereum-optimism/optimism/pull/19358)).
*   **Karst Hardfork:** Support for the Karst hardfork was integrated into Kona ([#19372](https://github.com/ethereum-optimism/optimism/pull/19372)), followed by the introduction of an inlined derivation pipeline for `karst-derive` ([#19487](https://github.com/ethereum-optimism/optimism/pull/19487)).

### Supernode & Interoperability
Enhancements to the `op-supernode` focused on RPC utility and L1 state consistency:
*   **New RPC Endpoints:** Introduced `superroot_syncStatus` to replace the supervisor in the VM runner ([#19439](https://github.com/ethereum-optimism/optimism/pull/19439)) and improved `superroot_atTimestamp` to include available optimistic blocks even during partial availability ([#19348](https://github.com/ethereum-optimism/optimism/pull/19348)).
*   **Stability Fixes:** Resolved a startup bug where `VerifiedBlockAtL1` would incorrectly iterate with zero values ([#19405](https://github.com/ethereum-optimism/optimism/pull/19405)) and improved L1 progress tracking accuracy ([#19441](https://github.com/ethereum-optimism/optimism/pull/19441)).

### Protocol Upgrades & Tooling
*   **NUT Bundles:** New infrastructure was added for generating and verifying Network Upgrade Transaction (NUT) bundles, streamlining L2 hardforks ([#19248](https://github.com/ethereum-optimism/optimism/pull/19248), [#19463](https://github.com/ethereum-optimism/optimism/pull/19463)).
*   **ZK Foundations:** A new feature flag for the ZK proof system was registered within `contracts-bedrock`, marking early-stage integration of zero-knowledge capabilities ([#19388](https://github.com/ethereum-optimism/optimism/pull/19388)).
*   **Build System Migration:** A sweeping effort is underway to migrate the repository's build system from `make` to `just`, affecting the root, `op-program`, `op-e2e`, and `cannon` packages ([#19477](https://github.com/ethereum-optimism/optimism/pull/19477), [#19474](https://github.com/ethereum-optimism/optimism/pull/19474)).

## 🐛 Issues & Triage

### Closed Issues
*   **Kona Bug Fixes:** Resolved a critical issue where `CalldataSource` silently dropped EIP-4844 type-3 batcher transactions ([#19352](https://github.com/ethereum-optimism/optimism/issues/19352)).
*   **Contract Refactoring:** The `OptimismMintableERC721Factory` was refactored to use the `Initializable` pattern ([#19318](https://github.com/ethereum-optimism/optimism/issues/19318)), and an additional upgrade gas mechanism was implemented in `op-node` ([#18832](https://github.com/ethereum-optimism/optimism/issues/18832)).
*   **Infrastructure:** Sporadic acceptance test timeouts and Docker publishing bottlenecks were addressed to improve CI reliability ([#18261](https://github.com/ethereum-optimism/optimism/issues/18261)).

### New & Active Issues
*   **L2 Predeploys:** New discussions have emerged regarding the `ETHLiquidity` contract, specifically whether to re-add it as a predeploy and how it overlaps with Custom Gas Token (CGT) logic ([#19460](https://github.com/ethereum-optimism/optimism/issues/19460)).
*   **Supernode Consistency:** Work continues on adding L1 consistency verification to the supernode’s cross-safety validation to ensure the interop pipeline handles asynchronous global views correctly ([#19420](https://github.com/ethereum-optimism/optimism/issues/19420)).
*   **Legacy Cleanup:** Post-Karst upgrade tasks include removing legacy interface calls in `L2ContractsManager` that currently use all-caps function names for compatibility ([#19468](https://github.com/ethereum-optimism/optimism/issues/19468)).

## 💬 Community & Collaboration
The week saw significant internal reorganization and tool adoption. The "platforms-team" was officially renamed to the **"core-team"** in the CODEOWNERS file, reflecting a broader scope of responsibility ([#19436](https://github.com/ethereum-optimism/optimism/pull/19436)). Collaboration was highly visible in the transition to Rust-based testing, with new acceptance tests introduced for the Kona/op-reth stack ([#19222](https://github.com/ethereum-optimism/optimism/pull/19222)). Additionally, the integration of **Claude Code** skills for triaging CI failures suggests an increasing reliance on AI-assisted developer workflows to maintain the `op-program` compatibility baseline ([#19444](https://github.com/ethereum-optimism/optimism/pull/19444)).

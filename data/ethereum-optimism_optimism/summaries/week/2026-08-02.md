# ethereum-optimism/optimism Weekly Report (Aug 2 - 8, 2026)

## 🚀 Highlights
This week focused on hardening the Superchain infrastructure through significant advancements in fault proof mechanisms and zero-knowledge (ZK) monitoring. A major milestone was reached with the Kona SP1 proposer now capable of defending challenged games using super-aggregation proofs, alongside the introduction of typed monitor lanes for ZK dispute games. Parallel efforts significantly optimized CI/CD pipelines, reducing execution times for ZK tests and Forge builds, while a comprehensive overhaul of the public documentation improved information architecture and developer accessibility.

## 🛠️ Key Developments

### Fault Proofs & ZK Infrastructure
The project made substantial strides in the robustness of the Superchain's security model.
*   **Kona SP1 Proposer:** Implemented the ability to defend challenged games using super-aggregation proofs, a critical step for fault proof reliability [#22121](https://github.com/ethereum-optimism/optimism/pull/22121), [#22196](https://github.com/ethereum-optimism/optimism/pull/22196).
*   **Dispute Monitoring:** Introduced "typed monitor lanes" in `op-dispute-mon` to handle different game types. This includes normalized ZK bond accounting and the ability to extract and forecast ZK-specific games [#22225](https://github.com/ethereum-optimism/optimism/pull/22225), [#22228](https://github.com/ethereum-optimism/optimism/pull/22228).
*   **Kona Protocol:** Added support for extended transaction envelopes in `L2BlockInfo` to facilitate broader interoperability [#22196](https://github.com/ethereum-optimism/optimism/pull/22196).

### Protocol Operations & Deployment
Refinements to chain deployment and node stability were a core focus.
*   **op-deployer Enhancements:** Added support for continuing interrupted deployments by snapshotting canonical intent and predicted addresses [#21974](https://github.com/ethereum-optimism/optimism/pull/21974). The deployer now also explicitly reverts on game configuration mismatches [#22128](https://github.com/ethereum-optimism/optimism/pull/22128).
*   **op-reth Recovery:** Updated `op-reth` to automatically recover proof history gaps on startup by seeding the engine from the durable execution head [#22177](https://github.com/ethereum-optimism/optimism/pull/22177).
*   **Gas & DA Accounting:** Improved gas estimation by allowing target nodes to cap gas at $2^{24}$ for state gas and refined DA footprint accounting to exclude PostExec transactions from Jovian accounting [#22217](https://github.com/ethereum-optimism/optimism/pull/22217), [#22219](https://github.com/ethereum-optimism/optimism/pull/22219).

### CI/CD & Developer Experience
Significant work was done to reduce developer friction and pipeline latency.
*   **Pipeline Optimization:** Implemented parallel execution for ZK dispute game tests [#22208](https://github.com/ethereum-optimism/optimism/pull/22208) and cached Forge build artifacts in `contracts-bedrock-build` [#22199](https://github.com/ethereum-optimism/optimism/pull/22199).
*   **Documentation IA:** Restructured public docs by unifying the tools namespace, normalizing navigation slugs, and creating new index pages for OP Mainnet [#22059](https://github.com/ethereum-optimism/optimism/pull/22059), [#22185](https://github.com/ethereum-optimism/optimism/pull/22185).
*   **Observability:** Enhanced `op-node` logging to better track "follow source" and "super authority" reorg events [#22106](https://github.com/ethereum-optimism/optimism/pull/22106).

## 🐛 Issues & Triage

### Closed Issues
*   **Deployment & Sync:** Resolved long-standing issues regarding the sequencer stalling during ELSync [#17654] and enabled permissionless deployment with a continuation command [#21669].
*   **Kona Stability:** Closed critical bugs where `op-reth` proof history could lag after shutdowns [#22089] and completed the porting of the defend/prove path for the proposer [#22147].

### New & Active Issues
*   **CI Infrastructure:** A major concern was raised regarding `mise tool` installations, which have become the primary source of infrastructure failures in 2026, requiring a structural fix rather than simple retries [#22223].
*   **Architectural Bottlenecks:** New tracking for `op-node` sequencer starvation caused by derivation thread contention in the single-threaded event loop [#22232].
*   **Kona-Node Validation:** Several new issues highlight the need for better validation of admin unsafe payload block hashes and fixing failures in multi-EL sync for `kona-node` [#22250], [#22248].

## 💬 Community & Collaboration
The week showed high levels of coordination between protocol engineers and the DevOps team, particularly in the rapid integration of the `kona-sp1-proposer` into Netchef [#22240]. There is an ongoing technical discussion regarding performance benchmarking for Sub-block Data Availability (SDM), with contributors moving toward using the `op-benchmark` tool on SSD devnets to quantify overhead [#20176]. The focus on "IA slices" in documentation PRs suggests a systematic, multi-stage collaboration to improve the onboarding experience for new Superchain developers.

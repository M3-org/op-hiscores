# ethereum-optimism/optimism Weekly Report (Feb 15 - 21, 2026)

## 🚀 Highlights
This week, development focused on streamlining protocol upgrades and hardening the Superchain infrastructure. A major milestone was reached in L2 contract management with the implementation of batch upgrades via the `L2ProxyAdmin`, alongside the introduction of JSON-based network upgrade transaction (NUT) parsing in `op-node`. Significant effort was also directed toward `op-reth` stability, porting historical proofs and addressing critical memory leaks. Meanwhile, the "Safe Label Adjusting" initiative for the Supernode saw substantial progress, further refining how interoperable chains manage state labels.

## 🛠️ Key Developments

### Protocol Upgrades & L2 Management
The project transitioned toward more automated and flexible upgrade mechanisms.
*   **Batch Predeploy Upgrades:** The `L2ProxyAdmin` now supports batch upgrades of L2 predeploy contracts by delegating to the `L2ContractsManager`, significantly reducing manual overhead ([#19135](https://github.com/ethereum-optimism/optimism/pull/19135)).
*   **JSON-Defined Upgrades:** `op-node` was enhanced to support defining network upgrade transactions via JSON files. This reduces the reliance on hardcoded Go files for each hardfork, simplifying configuration ([#19165](https://github.com/ethereum-optimism/optimism/pull/19165)).
*   **Deployment Refinements:** Default Proxy Admin Owners (PAOs) were removed, and documentation was reorganized to support the upcoming migration to `docs.optimism.io` ([#19166](https://github.com/ethereum-optimism/optimism/pull/19166)).

### op-reth & Kona Enhancements
Substantial work was done to align `op-reth` with upstream developments and improve proof reliability.
*   **Historical Proofs:** Historical proof capabilities were ported from `op-rs/op-reth` to the main repository, expanding data verification options ([#19191](https://github.com/ethereum-optimism/optimism/pull/19191)).
*   **Dependency Updates:** `op-reth` was updated to Reth revision `2c5d00f` and version 1.11.0, with accompanying bumps to Alloy and other core dependencies ([#19194](https://github.com/ethereum-optimism/optimism/pull/19240)).
*   **Kona Proof Fixes:** Resolved a critical bug in Kona proofs regarding interop header lookups for blocks within the current history window ([#19230](https://github.com/ethereum-optimism/optimism/pull/19230)).

### Supernode & Interoperability
Progress continued on the foundational components of the Superchain.
*   **Safe Label Adjusting:** The `superAuthority` wiring was implemented in both `op-node` and `supernode`, marking a key step in how the ecosystem manages chain state labels ([#19110](https://github.com/ethereum-optimism/optimism/pull/19110)).
*   **Interop Refinements:** The `op-interop-filter` was updated to a standard admin RPC pattern ([#19083](https://github.com/ethereum-optimism/optimism/pull/19083)), and blob handling in Kona was simplified by removing `IndexedBlobHash` ([#19081](https://github.com/ethereum-optimism/optimism/pull/19081)).

### CI/CD & Testing Infrastructure
The team focused on reducing CI flakiness and improving build efficiency.
*   **Parallel Builds:** The `reproducible-prestate` process now allows parallel building of `op-program` and `kona` prestates ([#19184](https://github.com/ethereum-optimism/optimism/pull/19184)).
*   **Stability Fixes:** A race condition causing `op-challenger` to hang during shutdown was resolved ([#19203](https://github.com/ethereum-optimism/optimism/pull/19203)).
*   **Test Promotions:** Ongoing "flake-shaking" efforts aimed to stabilize and promote `op-acceptance-tests` ([#19198](https://github.com/ethereum-optimism/optimism/pull/19198), [#19214](https://github.com/ethereum-optimism/optimism/pull/19214)).

## 🐛 Issues & Triage

### Closed Issues
*   **L2 Upgrades:** Successfully closed the task for adding `upgradePredeploys()` to `L2ProxyAdmin` ([#18829](https://github.com/ethereum-optimism/optimism/issues/18829)) and finalized specifications for L2CM smart contract changes ([#18867](https://github.com/ethereum-optimism/optimism/issues/18867)).
*   **Supernode Progress:** The "Safe Label Adjusting" initiative for `op-supernode` was officially closed following the implementation of state label management logic ([#18976](https://github.com/ethereum-optimism/optimism/issues/18976)).

### New & Active Issues
*   **Memory Leak in op-reth:** A high-priority bug report identifies a memory leak triggered by long-running database read transactions in `op-reth`, which has been observed across multiple nodes ([#19212](https://github.com/ethereum-optimism/optimism/issues/19212)).
*   **Workflow Optimization:** New issues were opened to migrate the `op-deployer` Docker build from CircleCI to GitHub Actions and to optimize Docker workflows to prevent redundant builds on every commit ([#19208](https://github.com/ethereum-optimism/optimism/issues/19208), [#19209](https://github.com/ethereum-optimism/optimism/issues/19209)).
*   **Interop Standardization:** A new task was created to migrate Interop upgrade transactions to the NUT bundle approach to ensure consistent gas accounting ([#19239](https://github.com/ethereum-optimism/optimism/issues/19239)).

## 💬 Community & Collaboration
This week showed strong internal coordination on the transition from CircleCI to GitHub Actions and the migration of documentation. There was significant activity around the `op-reth` and `kona` stacks, with contributors working across multiple repositories (including `op-rs`) to port features and fix cross-stack bugs. The focus on "flake-shaking" acceptance tests indicates a concerted effort by maintainers to improve the developer experience for all contributors by providing a more reliable CI environment.

# ethereum-optimism/optimism Weekly Report (Aug 23 - 29, 2026)

## 🚀 Highlights
This week focused heavily on hardening the **Kona** protocol and improving the robustness of the **Superchain** infrastructure. Significant efforts were directed toward refining interop message validity, expanding multi-chain support in the L1 watcher, and addressing critical Go module consumption issues for downstream developers. While the team made strides in protocol security and developer experience, new challenges emerged regarding `kona-node` stability and the reliability of contract artifact publishing.

## 🛠️ Key Developments

### Kona Protocol & Interoperability
The Kona protocol saw significant refinements to its core logic and networking layers:
*   **Validity Rules:** Consolidated interop message validity rules to improve consistency and robustness across the protocol ([#22565](https://github.com/ethereum-optimism/optimism/pull/22565)).
*   **L1 Watcher Enhancements:** Refactored the `L1WatcherActor` in `kona-node-service` to support multiple chains simultaneously, moving away from a single rollup configuration per chain ([#22567](https://github.com/ethereum-optimism/optimism/pull/22567)).
*   **Networking Security:** Updated `kona-gossip` to use an allowlist for gossip subscription topics, replacing the permissive `AllowAllSubscriptionFilter` ([#22661](https://github.com/ethereum-optimism/optimism/pull/22661)).
*   **Actionable Logging:** Clarified proof replay warnings in `kona-sp1-proposer` to assist operators during L1 rewinds ([#22623](https://github.com/ethereum-optimism/optimism/pull/22623)).

### Infrastructure & Deployment Tooling
Improvements to the OP Stack deployment and node performance included:
*   **op-deployer Genesis:** Reduced the default genesis time offset to 3 hours (with a 1-hour minimum), resolving long-standing benchmarking TODOs ([#22512](https://github.com/ethereum-optimism/optimism/pull/22512)).
*   **Node Maintenance:** Updated `op-geth` to version `v1.101702.3-rc.7` ([#22694](https://github.com/ethereum-optimism/optimism/pull/22694)) and updated the Rust nightly toolchain to `nightly-2026-08-22` ([#22650](https://github.com/ethereum-optimism/optimism/pull/22650)).
*   **Testing & CI:** Added a regression test to `alloy-op-evm` for dropped state-invalid transactions ([#22427](https://github.com/ethereum-optimism/optimism/pull/22427)) and introduced a new skill for drafting house-style release notes ([#22548](https://github.com/ethereum-optimism/optimism/pull/22548)).

## 🐛 Issues & Triage

### Closed Issues
*   **Supernode Stability:** Resolved a cross-safe wedge issue in `op-supernode` ([#22325](https://github.com/ethereum-optimism/optimism/issues/22325)). Investigation showed the root cause was a parent-hash mismatch on a specific chain rather than a supervisor bug.
*   **Configuration Leniency:** Closed the discussion on `kona-genesis` unknown key parsing ([#22682](https://github.com/ethereum-optimism/optimism/issues/22682)). The team decided to maintain leniency to ensure backward compatibility with retired keys.
*   **Documentation Audits:** Completed audits for starter examples ([#1014](https://github.com/ethereum-optimism/optimism/issues/1014)) and abandoned repositories ([#1017](https://github.com/ethereum-optimism/optimism/issues/1017)), clearing the way for repository archiving without breaking live links.

### New & Active Issues
*   **Module Unconsumability:** A critical issue was identified where `op-core/superchain` is unconsumable by downstream Go modules because `superchain-configs.zip` is gitignored ([#22678](https://github.com/ethereum-optimism/optimism/issues/22678)). This led to a refactor of `op-service` ([#22700](https://github.com/ethereum-optimism/optimism/pull/22700)) to improve importability.
*   **Kona Node Stability:** Several reports surfaced regarding `kona-node` sequencers getting stuck in `forkchoiceUpdated` loops ([#22681](https://github.com/ethereum-optimism/optimism/issues/22681)) and ignoring certain CLI flags like `--sequencer.max-safe-lag` ([#22667](https://github.com/ethereum-optimism/optimism/issues/22667)).
*   **SuperchainERC20 Gap:** A new issue highlights the lack of a supported method for developers to verify SuperchainERC20 compatibility ([#1020](https://github.com/ethereum-optimism/optimism/issues/1020)), which is becoming a priority for upcoming interoperability features.

## 💬 Community & Collaboration
The week was marked by deep technical synchronization between the Go and Dafny modeling teams. Extensive analysis of `op-supernode` surfaced discrepancies between the formal Dafny models and the Go implementation regarding message execution and rewind plans ([#22636](https://github.com/ethereum-optimism/optimism/issues/22636)). 

There is also active community engagement in the "Archive Sweep," with contributors coordinating the consolidation of starter repositories and auditing external links to ensure a clean developer experience as the ecosystem evolves. New contributors have expressed interest in picking up Holocene-related batch retention tasks ([#22629](https://github.com/ethereum-optimism/optimism/issues/22629)).

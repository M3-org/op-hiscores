# ethereum-optimism/optimism Weekly Report (Jan 25 - 31, 2026)

## 🚀 Highlights
This week, the Optimism monorepo underwent a major structural evolution with the successful upstreaming of several critical Rust components, including `op-alloy`, `op-hardforks`, and `op-reth`. Development heavily prioritized the Superchain and interoperability, marked by the implementation of core filtering logic for `op-interop-filter` and the introduction of supernode abstractions for the proofs DSL. Significant strides were also made in developer experience and deployment tooling, specifically through the conversion of multiple deployment scripts to Forge and the migration of Docker builds to GitHub Actions for improved CI/CD reliability.

## 🛠️ Key Developments

### Rust Monorepo Migration
A major effort to consolidate the Rust ecosystem into the main monorepo reached several milestones this week.
*   **Component Upstreaming:** Successfully migrated `op-alloy`, `op-hardforks`, `alloy-op-evm`, and `op-reth` into the monorepo, streamlining the build process and CI management ([#18811](https://github.com/ethereum-optimism/optimism/pull/18811), [#18825](https://github.com/ethereum-optimism/optimism/pull/18825), [#18826](https://github.com/ethereum-optimism/optimism/pull/18826), [#18917](https://github.com/ethereum-optimism/optimism/pull/18917)).
*   **Documentation:** Began porting documentation from the upstream Reth repository to `op-reth` within the monorepo ([#18968](https://github.com/ethereum-optimism/optimism/pull/18968)).

### Interoperability & Supernode Infrastructure
The team advanced the technical foundation for cross-chain interactions and the Supernode architecture.
*   **Interop Filtering:** Implemented core filtering logic for `op-interop-filter` to enhance cross-chain interaction safety ([#18604](https://github.com/ethereum-optimism/optimism/pull/18604)).
*   **Supernode Enhancements:** Updated `op-supernode` chain container interfaces and introduced a `SuperRootsSource` interface to abstract super-root sources for the proofs DSL ([#18727](https://github.com/ethereum-optimism/optimism/pull/18727), [#18955](https://github.com/ethereum-optimism/optimism/pull/18955)).
*   **Withdrawal Logic:** Updated withdrawal commands to support proving via specific output roots in super proposals, reducing dependency on `supervisor-rpc` ([#18733](https://github.com/ethereum-optimism/optimism/pull/18733)).

### Deployment Tooling & Smart Contracts
Refinement of the `op-deployer` and core bridge contracts focused on gas efficiency and Forge compatibility.
*   **Forge Conversion:** Ported `DeployMIPS`, `DeployAltDA`, `DeployAlphabetVM`, and `DeployDisputeGame` scripts to Forge to unify deployment workflows ([#18963](https://github.com/ethereum-optimism/optimism/pull/18963), [#18964](https://github.com/ethereum-optimism/optimism/pull/18964)).
*   **StandardBridge Refactor:** Initiated a refactor of the `StandardBridge` to optimize gas usage and modernize error handling ([#18937](https://github.com/ethereum-optimism/optimism/pull/18937)).
*   **Predictability:** Updated `DisputeGameFactory` to use `CREATE2` for game creation, ensuring address predictability during reorgs ([#18958](https://github.com/ethereum-optimism/optimism/pull/18958)).

### CI/CD and Code Quality
*   **GitHub Actions Migration:** Completed the migration of Docker builds from CircleCI to GitHub Actions, enabling cross-platform verification ([#18821](https://github.com/ethereum-optimism/optimism/pull/18821)).
*   **Type Safety:** Enabled `UInt64` lint checks across the codebase and resolved all violations, including a critical fix in `op-node`'s yParity calculation to prevent overflows ([#18948](https://github.com/ethereum-optimism/optimism/pull/18948), [#18921](https://github.com/ethereum-optimism/optimism/pull/18921)).

## 🐛 Issues & Triage

### Closed Issues
*   **Rust Migration Tracking:** Closed tracking issues for `kona` and `op-reth` migrations as they are now integrated into the monorepo ([#18575](https://github.com/ethereum-optimism/optimism/issues/18575), [#18577](https://github.com/ethereum-optimism/optimism/issues/18577)).
*   **Documentation:** Completed the gas configuration guide for post-Holocene system configs ([#1944](https://github.com/ethereum-optimism/optimism/issues/1944)).
*   **Testing:** Resolved challenges with the Glamsterdam devnet acceptance tests, identifying L1 setup support as a future requirement ([#18755](https://github.com/ethereum-optimism/optimism/issues/18755)).

### New & Active Issues
*   **Batcher Configuration:** New issues highlight the need for a configurable blob tip cap in `op-batcher` ([#18949](https://github.com/ethereum-optimism/optimism/issues/18949)) and better synchronization with `op-node` rollup configs ([#18178](https://github.com/ethereum-optimism/optimism/issues/18178)).
*   **Supernode API:** Ongoing discussion regarding the `SyncStatus` API for `op-supernode` to provide comprehensive verification status across all chains ([#18947](https://github.com/ethereum-optimism/optimism/issues/18947)).
*   **Blockers:** The `op-deployer` gas limit issue (related to Fusaka hardfork limits) remains active, impacting contract deployments ([#17912](https://github.com/ethereum-optimism/optimism/issues/17912)).
*   **Protocol Upgrades:** Updating `OptimismPortal2` to use chain-specific root claims is currently backlogged until the U19 upgrade to avoid disrupting active withdrawals ([#18517](https://github.com/ethereum-optimism/optimism/issues/18517)).

## 💬 Community & Collaboration
The week showed high levels of technical coordination, particularly around the Rust migration and the transition to Forge-based tooling. Community members have been active in troubleshooting tutorial errors, such as the `BlockNotFoundError` in the ETH bridge tutorial, where detailed workarounds were shared ([#1956](https://github.com/ethereum-optimism/optimism/issues/1956)). There is also evidence of external contribution interest in `op-alloy`, with community members offering to fix EIP-1559 parameter decoding ([#18951](https://github.com/ethereum-optimism/optimism/issues/18951)). Collaboration between the `op-deployer` and `op-validator` teams was also evident in the new automatic validation integration ([#18934](https://github.com/ethereum-optimism/optimism/pull/18934)).

# ethereum-optimism/optimism Weekly Report (Apr 5 - 11, 2026)

## 🚀 Highlights
This week, development centered on hardening the **Superchain interoperability layer** and streamlining the **Kona** execution stack. Significant progress was made in migrating dispute game logic to `OptimismPortal2` and enhancing the Supernode's robustness through improved L1 reorg handling and Denylist integration. While the team successfully unskipped several critical interop acceptance tests, a concerted effort was also directed toward stabilizing the CI pipeline, which faced persistent flakiness in Flashblocks and sync-related test suites.

## 🛠️ Key Developments

### Interoperability & Supernode Infrastructure
The "Supernode" saw several upgrades to ensure consistency across the ecosystem.
*   **Denylist Integration:** The Supernode now verifies "OptimisticOutputRoot" against the Denylist before providing outputs, enhancing security for optimistic rollups ([#19880](https://github.com/ethereum-optimism/optimism/pull/19880)).
*   **Timestamp & Sync Logic:** Consolidated block-to-timestamp helpers to respect genesis offsets ([#19542](https://github.com/ethereum-optimism/optimism/pull/19542)) and forced virtual nodes to use consensus-layer sync by default ([#19940](https://github.com/ethereum-optimism/optimism/pull/19940)).
*   **RPC & Tooling:** Added new RPC methods like `getBlockHashByNumber` to `op-interop-filter` ([#19969](https://github.com/ethereum-optimism/optimism/pull/19969)) and introduced `update-nuts` commands for managing NUT bundles during fork verification ([#19463](https://github.com/ethereum-optimism/optimism/pull/19463)).

### Kona & Rust Stack Refinement
Efforts to optimize the Rust-based components focused on determinism and architectural simplification.
*   **Deterministic Execution:** Replaced `HashMap` with `BTreeMap` in the Kona interop host to prevent VM state divergence during serialization ([#19906](https://github.com/ethereum-optimism/optimism/pull/19906)).
*   **Rollup-Boost Removal:** Native `rollup-boost` support was removed from the Kona workspace, routing Engine API calls directly to the L2 execution engine to reduce external dependencies ([#19900](https://github.com/ethereum-optimism/optimism/pull/19900)).
*   **Error Handling:** The `kona-node` sequencer was updated to handle missing L1 origin blocks gracefully with an `OriginNotFound` error instead of panicking ([#19945](https://github.com/ethereum-optimism/optimism/pull/19945)).

### Smart Contracts & Fault Proofs
*   **Portal Migration:** Shared dispute game functionalities were migrated from `OptimismPortalInterop` to `OptimismPortal2` to unify the target for upcoming interop migrations ([#19840](https://github.com/ethereum-optimism/optimism/pull/19840)).
*   **ZK & Dispute Games:** Added unit and integration test coverage for `ZKDisputeGame` ([#19955](https://github.com/ethereum-optimism/optimism/pull/19955)) and refined contract test helpers by removing unused internal functions ([#19926](https://github.com/ethereum-optimism/optimism/pull/19926)).

### CI & Developer Experience
*   **Workflow Optimization:** Implemented path-based gating for contract feature matrix jobs, ensuring CI only runs relevant tests when contract files change ([#19780](https://github.com/ethereum-optimism/optimism/pull/19780)).
*   **Documentation:** Published a comprehensive guide on Fee Vaults, detailing mechanics, configuration, and withdrawal processes ([#19952](https://github.com/ethereum-optimism/optimism/pull/19952)).

## 🐛 Issues & Triage

### Closed Issues
*   **L1 Reorg Handling:** Successfully resolved multiple issues regarding the Supernode's ability to prune databases and denylists during L1 reorgs, now managed via Write-Ahead Logging (WAL) ([#19245](https://github.com/ethereum-optimism/optimism/issues/19245), [#19287](https://github.com/ethereum-optimism/optimism/issues/19287)).
*   **Interop Milestones:** Core interop implementation and algorithm issues were closed as the project moves toward advanced testing phases ([#18741](https://github.com/ethereum-optimism/optimism/issues/18741), [#18743](https://github.com/ethereum-optimism/optimism/issues/18743)).
*   **Sync Fixes:** Addressed a recurring "mismatched block state root" error in `op-reth` that previously caused sync stalls on Base mainnet ([#19532](https://github.com/ethereum-optimism/optimism/issues/19532)).

### New & Active Issues
*   **Critical DoS Vulnerability:** A security researcher proposed a fix for a critical DoS vulnerability in `Kona-Protocol` related to unknown batch type panics. The fix involves replacing panics with proper `Result` error propagation ([#19334](https://github.com/ethereum-optimism/optimism/issues/19334)).
*   **Persistent Test Flakiness:** The `TestFlashblocksStream` ([#19883](https://github.com/ethereum-optimism/optimism/issues/19883)) and `TestFlashblocksTransfer` ([#19934](https://github.com/ethereum-optimism/optimism/issues/19934)) suites remain problematic due to port conflicts ("address already in use") and timing races between block times and flashblock times.
*   **Sync Discrepancies:** A new issue was opened to track receipt root mismatches when syncing older chains with hard forks ([#19930](https://github.com/ethereum-optimism/optimism/issues/19930)).

## 💬 Community & Collaboration
The week was marked by high-intensity technical coordination on security and performance. A security researcher, *zhuzhushiwojia*, actively engaged with the team to claim a bounty and implement a fix for the Kona protocol DoS issue. Collaboration between the Reth and Optimism teams was evident in the troubleshooting of state root mismatches on Base Mainnet. Additionally, the migration of interop action tests from `op-e2e` to `op-acceptance-tests` indicates a coordinated effort to improve the long-term maintainability of the testing infrastructure.

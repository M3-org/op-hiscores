# ethereum-optimism/optimism Monthly Report (July 2026)

## 🚀 Highlights
In July 2026, development focused heavily on hardening the Superchain infrastructure through rigorous security audits and the refinement of deployment tooling. Significant progress was made on the `op-deployer` and `op-reth` components, alongside critical compatibility fixes for `op-node` regarding EIP-4444. The month was characterized by a transition toward production readiness for the SuperZKDG (Zero-Knowledge Data Generation) and Isthmus-related features, supported by comprehensive quality assurance reviews and security feedback integration from external auditors.

## 🛠️ Key Developments

### Deployment Tooling & Infrastructure
Significant enhancements were made to `op-deployer` to streamline chain launches and improve state management.
*   **Prestate Management:** A new feature was introduced to commit prestates before chain deployment ([#21611](https://github.com/ethereum-optimism/optimism/pull/21611)).
*   **Permissionless Inputs:** Development began on sourcing permissionless deploy inputs directly from chain state ([#21610](https://github.com/ethereum-optimism/optimism/pull/21610)).
*   **Developer Experience:** A new tutorial was added to assist developers in deploying contracts to the OP Sepolia testnet ([#21607](https://github.com/ethereum-optimism/optimism/pull/21607)).

### Protocol Security & SuperZKDG
The project prioritized the security of the SuperZKDG components in preparation for upcoming audits.
*   **Super ZK Game:** A fix was proposed to address quality assurance issues identified during internal reviews of the Super ZK game ([#21615](https://github.com/ethereum-optimism/optimism/pull/21615)).
*   **Audit Integration:** Feedback from Lumi Security was actively integrated into the codebase, specifically targeting `lib.rs`, `l2_el.go`, `solutil.go`, and `kona` ([#21604](https://github.com/ethereum-optimism/optimism/issues/21604), [#21606](https://github.com/ethereum-optimism/optimism/issues/21606), [#21612](https://github.com/ethereum-optimism/optimism/issues/21612), [#21613](https://github.com/ethereum-optimism/optimism/issues/21613)).

### Node Performance & Compatibility
Refinements to `op-reth` and `op-node` addressed both network compatibility and transaction pool logic.
*   **EIP-4444 Compatibility:** A long-standing issue was resolved where `op-node` failed to determine the L2 genesis blockhash when L1 nodes pruned historic data ([#13570](https://github.com/ethereum-optimism/optimism/issues/13570)).
*   **Transaction Pool Logic:** Work began on `op-reth/txpool` to reserve Isthmus operator fees during balance checks, ensuring parity with `op-geth` ([#21609](https://github.com/ethereum-optimism/optimism/pull/21609)).
*   **TLS Fixes:** A TLS issue in `op-reth` was addressed by installing the default rustls CryptoProvider for flashblocks ([#21605](https://github.com/ethereum-optimism/optimism/pull/21605)).

## 🐛 Issues & Triage

### Closed Issues
*   **L1 Node Pruning:** The resolution of [#13570](https://github.com/ethereum-optimism/optimism/issues/13570) marks a significant milestone for node operators using EIP-4444 enabled L1 nodes, preventing errors during block synchronization.

### New & Active Issues
*   **Contract Upgrade Risks:** A critical issue was identified in the `op-contracts/v7.0.0-rc.4` upgrade, which reportedly overrides the `SystemConfig.batchInbox` value ([#21614](https://github.com/ethereum-optimism/optimism/issues/21614)).
*   **Transaction Pool Discrepancies:** Issue [#21608](https://github.com/ethereum-optimism/optimism/issues/21608) highlights a potential vulnerability where `op-reth` might admit under-funded transactions due to omitting operator fees in balance checks.
*   **QA & Feature Removal:** Ongoing work includes an end-to-end QA review of all `SuperZKDG` components ([#21603](https://github.com/ethereum-optimism/optimism/issues/21603)) and the planned removal of the L2CM Dev Feature ([#21616](https://github.com/ethereum-optimism/optimism/issues/21616)).

## 💬 Community & Collaboration
The month showed a strong collaborative link between the core development team and external security auditors (Lumi Security and Lumi Beacon). This is evidenced by the rapid translation of audit feedback into actionable GitHub issues across multiple repositories (Go and Rust). Additionally, the ecosystem continues to expand its developer resources, as seen by the inclusion of NodeFlare in the OP Stack RPC directory ([#21618](https://github.com/ethereum-optimism/optimism/pull/21618)) and updated deployment documentation.

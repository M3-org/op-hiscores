- **DevFeatures Removal Progress**: In [#20084](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20084), `yoonchung8822` suggested inserting comments in the code with flags to track future "to-do" or "close" actions, and requested `maurelian` to establish a standard process for the Engineering Organization. The merge of the DevFeatures removal PR is currently delayed until all audit fixes are in.

- **Flaky Test `TestFollowL2_ReorgRecovery` Resurfaces**: Issue [#19967](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19967) was reopened by `maurelian` due to the `TestFollowL2_ReorgRecovery` test flaking again. The latest failure, observed on May 19, 2026, on the `fix/l2cm-xlayer-minters-preserve` branch, showed a different error signature (sequencer RPC deadline exceeded) but pointed to the same underlying timing/sync issue.

- **Flaky Fuzz Test Root Cause Identified**: For [#20935](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20935), `ajsutton` identified the root cause of the `FuzzEncodeDecodeBlob` flake: `Blob.FromData` was formatting the entire payload into its error message, leading to large error strings that caused the fuzzing process to hang. A fix has been drafted in a pull request.

- **Non-Deterministic Fuzz Test Resolved**: In [#20936](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20936), `ajsutton` found that the `FuzzDetectNonBijectivity` test was flaky because it captured `*rand.Rand` outside the `f.Fuzz` closure, making the fuzz target non-deterministic. A fix has been drafted in a pull request to derive the bit flip from a SHA256 hash of the input.

- **`op-reth` Bedrock Bootstrap Incompatibility**: `einar-oplabs` is attempting to reproduce the issue described in [#20821](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20821), where a minimal Bedrock bootstrap with `op-reth init-state --without-ovm` is incompatible with storage v2. Initial attempts to reproduce the panic on launch did not show the reported error, with the node starting and connecting to peers successfully.

- **`debug_executePayload` Necessity Confirmed**: Issue [#20879](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20879), which investigated the removal of `debug_executePayload`, was closed on May 19, 2026. `ajsutton` commented on May 20, 2026, that `debug_executePayload` is strictly required for `op-reth` to function as a source for `kona-proofs`, otherwise it would fall back to `debug_dbGet` which only works with `geth` tree-schema nodes. The issue was closed as "wontfix" because it's an active, opt-in fast-path with a maintained server implementation in `op-reth`, crucial for fault-proof witness prefetching.

- **`op-supernode` Backfill Depth Fix in Progress**: For [#20892](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20892), `tiaraimpex410-sudo` submitted a pull request ([https://github.com/ethereum-optimism/optimism/pull/20895](https://github.com/ethereum-optimism/optimism/pull/20895)) to address the issue where `op-supernode` fails to start if backfill depth is greater than 0 and the interop activation time is not set. The proposed fix aims to ignore the backfill depth in such cases.

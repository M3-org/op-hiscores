## ACTIVE ISSUES

### Flaky Test: `TestCLELDivergence` ([#19681](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19681))
This issue, initially reported as a flaky test, was closed today. The discussion revolved around whether the observed reset behavior was a bug or an expected part of the initial derivation pipeline lifecycle. `ajsutton` suggested closing the issue, noting that `/report-flake` would reopen it if the flake reappeared, preventing a backlog of non-actionable issues. `pcw109550` initially advocated for keeping it open until the flakiness disappeared, citing mitigation by a pull request. Ultimately, the issue was closed based on the assessment that the reset was likely not a bug and the test's expectation might have been incorrect.

### Contracts: Prove withdrawals using chain-specific root claim ([#18517](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18517))
The discussion on this issue, which aims to ensure `OptimismPortal2.proveWithdrawalTransaction` uses `IDisputeGame.rootClaim(uint256)`, saw `ajsutton` inquire about its closure. They suggested that the approach might have changed to use `rootClaimByChainId` based on the game type. Earlier comments from `Inphi` indicated that this change was dependent on the U19 upgrade and would need to be executed well after FaultDisputeGames support the new method to avoid disrupting withdrawals.

### [L2CM] Investigate adding an array of predeploys to increase upgrade safety ([#19260](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19260))
`maurelian` provided a detailed analysis of a "Structural Pipeline Gap" related to missing implementation deployments in the NUT Bundle. The immediate bug, where `L2DevFeatureFlags` was omitted from the deployment transaction list, was fixed by PR #19464. However, the analysis highlighted a deeper structural issue: the lack of a centralized source of truth for implementations and automated completeness tests across multiple data structures. The report detailed how the fork tests introduced by PR #19464 would have caught the `L2DevFeatureFlags` bug but have limitations, particularly regarding non-proxy implementations and validating pipeline completeness. A latent issue with `ConditionalDeployer` was also identified, where a similar gap could lead to a more severe failure mode in future upgrades.

### Remove Karst-specific upgrade transactions from GenerateNUTBundle ([#19369](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19369))
`0xOneTony` added a comment outlining the necessary updates to `UpgradeUtils.getTransactionCount()` when removing the Karst-specific transactions. This includes changing the `txnCount_` calculation and removing Karst-specific fields from the `GasLimits` struct and its associated function.

### Document interop tx pool eviction behavior on reorg ([#19351](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19351))
`pcw109550` raised a question regarding the eviction of interop transactions from the mempool during reorgs. Specifically, they asked whether the mempool explicitly iterates and drops interop transactions or if periodic re-evaluation handles this, following the change in `op-geth#772` to drop executing messages.

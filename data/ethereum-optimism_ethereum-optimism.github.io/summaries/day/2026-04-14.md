### Support for Multiple Sequencer RPC Endpoints [#763](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/763)
Discussion continued on supporting multiple sequencer RPC endpoints for transaction forwarding. The latest comments suggest using existing generic proxy solutions like HAProxy, Nginx, or Envoy Proxy instead of implementing a bespoke fallback client within `op-geth`. It was argued that such tools are battle-tested, widely available, and allow operators to use familiar infrastructure, avoiding the need to maintain failover/retry/health-check logic within `op-geth`. The original proposal for client-side failover was presented as an optional defense-in-depth measure against CDN failures, not a replacement for proper sequencer high availability.

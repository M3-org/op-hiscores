## CLOSED ISSUES

- **Post-Execution Transaction Payload Validation**: Issue [#21961](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/21961), concerning the lack of validation for post-execution (0x7D) transaction payloads on decode, was closed. The resolution confirms that both `op-node` and Kona treat `PostExecTxs` as opaque bytes during derivation, with further validation being the responsibility of the Execution Layer.

## ACTIVE ISSUES

- **Flaky Test: `TestSequencerFailover_ConductorRPC`**: Issue [#22094](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22094) was marked as closed by a recent PR. The PR removes the rapid back-to-back leadership-transfer sequence from the test after replacing the user-visible transfer behavior with focused acceptance coverage. The underlying `op-conductor` availability bug exposed by this test is now documented separately.

- **Porting `op-e2e` Conductor System Coverage**: Issue [#21902](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/21902) was marked as closed by a recent PR. This PR ports selected user-visible conductor behaviors to focused acceptance tests and removes the superseded `op-e2e` coverage. The underlying `op-conductor` availability bug exposed by the flaky leadership-transfer coverage is documented separately.

- **Flake: `TestSupernodeLightSequencerInteropInvalidMessageReplacement`**: Issue [#22234](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22234) is actively being investigated. The root cause has been identified as a real race in the test's final assertions, not an environmental failure.
    - **Signature A**: The `Reached(eth.Safe, N)` gate checks the wrong postcondition, leading to a race where `AssertTxInBlock` reads from a transiently divergent canonical chain. A fix is proposed to replace the single-shot assertion with a retrying check that polls until the canonical block at N contains (or does not contain) the transaction. A draft PR [#22321](https://github.com/ethereum-optimism/optimism/pull/22321) is up for this fix.
    - **Signature B**: The `ResendUntilSafe` budget is exhausted under merge-queue load due to the light path's cross-safe recovery pace. This is considered a lower priority but points to the same underlying oscillation.
    - A separate issue, [#22325](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22325), has been created to address a potential supervisor/cross-safety issue where cross-safe stops following local-safe post-replacement.

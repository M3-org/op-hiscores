### Investigation into Flaky Blob Encoding Test
Discussion continued on the flaky test [#21539](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/21539), "FuzzDetectNonBijectivity mutates a non-encoded bit (op-service/eth)". A detailed comment from wwared provided an in-depth analysis of the issue. The test asserts that if a bit is flipped in an encoded blob, the decoded data should either result in an error or be different from the original. However, both `op-node` and `kona` implementations silently mask out the top two bits of the first field element during decoding, meaning that flipping these specific bits does not cause an error and the data decodes to the same value. This behavior makes the test's premise incorrect for these specific bits, as the blob code is not bijective in this regard. The comment also highlighted that a correct fix might require a hardfork/upgrade boundary to avoid breaking existing on-chain blobs that might have been leniently decoded previously.

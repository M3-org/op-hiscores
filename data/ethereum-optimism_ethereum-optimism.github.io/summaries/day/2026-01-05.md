## ACTIVE ISSUES

- **Addressing L1 Reorg Handling in Kona**
  Discussion on [#18676](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18676) highlighted a root cause analysis of L2 reorgs due to L1 reorgs in Kona. Key issues identified include the L1 Origin Selector caching stale values, a lack of L1 canonical validation at the L1 Origin, and the absence of a proper reset mechanism during block building when L1 inconsistency is detected. Comparisons were drawn with `op-node`'s more robust handling of these scenarios, and potential fixes were proposed, including strengthening Kona's L1 origin selector, adding unit tests for L1 inconsistency, revising reset logic, and enabling more monorepo acceptance tests targeting Kona.

- **Investigating `eth_simulatev1` Issue**
  The issue [#739](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/739) regarding `eth_simulatev1` returning "error calculating DA footprint: missing deposit transaction" since the Jovian fork is being actively discussed. A comment from ajsutton suggests that op-geth pull request [#732](https://github.com/ethereum-optimism/op-geth/pull/732) aims to fix this critical issue, which is impacting backrunning strategies on OP Stack-based EVM chains.

- **Enhancing `IDisputeGame` Interface**
  Issue [#18516](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18516) concerns extending the `IDisputeGame` interface with a `rootClaim(uint256 l2ChainId)` method for interop. The issue was reopened by ajsutton due to remaining TODOs in the code referencing it, and stevennevins confirmed that he would address these points.

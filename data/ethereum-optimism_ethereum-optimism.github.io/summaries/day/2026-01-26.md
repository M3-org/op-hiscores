## ACTIVE ISSUES

### op-deployer Transaction Gas Limit
In issue [#17912](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/17912), a user inquired if the "transaction gas limit too high" error for `op-deployer:v0.2.6` has been fixed and which version should be used for alt-da. A previous comment noted that the Fusaka hardfork enforces a transaction gas limit of 16,777,216, which can cause issues for large transactions. It was also suggested to use `v0.5.0*` for the latest contract release, though its post-Fusaka behavior is untested.

### op-batcher Rollup Config Synchronization
Discussion on issue [#18178](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18178) centered on the `op-batcher`'s inability to re-fetch the rollup config after startup. A recent comment suggested that a critical error and process restart could be a small and effective solution, allowing the batcher to reload the config. Earlier suggestions included making the operator explicitly provide the rollup config to the batcher or having the active endpoint provider signal when the endpoint changes to trigger a reload.

### Sequencer-Defined Metering Design Doc
Issue [#360](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/360), concerning the "Sequencer-Defined Metering Design Doc," saw an update expanding its scope to include an initial Proof of Concept (PoC). This PoC is currently blocking the design document, with an initial devnet deployment planned for January 30, 2026, after which design evaluation and basic benchmarking can occur.

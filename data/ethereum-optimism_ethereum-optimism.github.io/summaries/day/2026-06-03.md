## ACTIVE ISSUES
- **op-reth CL Sync Recovery Stall**
    - The issue [#21076](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/21076) concerning `op-supernode/op-reth` CL sync recovery stalling due to EL-missing blocks saw significant progress. The root cause was identified as a cyclic deadlock in reth's `StateTrieOverlayManager` / `DeferredTrieData` machinery, specifically due to locks being held across `rayon` compute operations. A two-patch fix has been implemented and successfully soaked for 6 hours, confirming its effectiveness. The fix prevents the engine from wedging and ensures continuous CL-sync. The issue is now being flagged for the reth team for an upstream fix.
- **SDM Refund Limit**
    - Discussion on [#20709](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20709) regarding adding a limit for SDM refunds suggests enforcing `MAX_GAS_LIMIT` regardless of the refund amount. This would cap the maximum computation the sequencer can perform, even with 100% refunds. It was also suggested that the max block gas used (before refunds) could be hardcoded in the node software.
- **State-Persistent Partial DoS in OptimismPortal2**
    - A comment on [#20820](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20820) regarding a state-persistent partial DoS vulnerability in OptimismPortal2 simply states "Wtf man", indicating ongoing concern or surprise about the issue.
- **Gas Changes and `relayMessage` Failure**
    - Issue [#14609](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/14609) was reopened because TODOs referencing it still exist in the codebase. The issue is to add a test that would trigger a failure if EVM gas schedule changes would cause `relayMessage` to fail. The test requires a new stable Foundry release that includes `foundry-rs/foundry#9904` to use `default.isolate = true`.

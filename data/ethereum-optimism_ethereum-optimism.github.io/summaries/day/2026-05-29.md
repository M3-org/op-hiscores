## ACTIVE ISSUES

*   **Flaky Test: `TestReorgUnsafeHead` ([#20198](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20198))**
    *   A root cause for the flaky `TestReorgUnsafeHead` was identified, and a fix has been opened in a separate PR. The issue stemmed from the test picking the next block's parent by reading the EL's mutable `eth.Unsafe` label, which could lag and return the original head, causing reorgs to be silently undone. The fix involves using a DSL poll to wait for the divergence height to reorg and taking the confirmed conflicting block as the explicit parent.
    *   Earlier discussions highlighted different symptoms of the flake, including a failure in setup where `WaitForBalance` never saw faucet-funded balances arrive, and previous attempts to fix the issue that didn't fully cover the flake.

*   **Interop Proofs Devnet ([#20489](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20489))**
    *   The team is currently working on fixing the `op-chain-ops` script for proving withdrawals, as it is not functioning correctly.
    *   A withdrawal was initiated last week on `inphi-devnet-0`, and the remaining task is to prove and finalize it on L1.
    *   Previously, playing a SuperFaultDisputeGame was completed, but a new withdrawal initiated on the devnet required waiting another 7 days for finalization, which is the last verification step for proofs.

*   **[L2CM] Add `setWithdrawalRoute` to FeeVaults ([#20806](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20806))**
    *   A significant blocking issue has been identified regarding modifying semvers on L2 contracts. The `TestActivationBlockNUTBundle` in Go, which starts from the `L2Genesis.s.sol` generated state, fails when an L2 contract's semver is bumped. This is because the L2CM code prevents upgrading a contract to a lower semver, and the bundle can no longer be executed against the locally generated genesis state. This is considered a deficiency in the test rather than a bug in L2CM, and a solution is pending.

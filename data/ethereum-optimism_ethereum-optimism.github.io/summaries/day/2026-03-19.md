## NEW ISSUES
Three new issues were opened, all related to flaky tests in the `interop/proofs` package:
- **Flaky Test: Challenger Plays Game**
  - [#19672](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19672) This issue reports that `TestChallengerPlaysGame` in `op-acceptance-tests/tests/interop/proofs` hangs indefinitely, hitting the 2-hour subtest timeout. The root cause was identified as `TestProposer` hanging, causing `TestChallengerPlaysGame` to be killed as collateral damage. A fix involving package isolation was proposed.
- **Flaky Test: Proposer Hangs Indefinitely**
  - [#19673](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19673) This issue describes `TestProposer` in `op-acceptance-tests/tests/interop/proofs` hanging indefinitely. The root cause was identified as `FailNow` being called inside `testify.Eventually` goroutines, leading to silent goroutine death and `Eventually` blocking forever. A fix to replace fatal assertions with error-returning variants was proposed.

## ACTIVE ISSUES

- **op-node: On the Initial EL Sync UX and Correctness** [#17631](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/17631)
  - Discussion continued on the correctness and user experience of the `op-node`'s initial EL sync. The core problem is that the current implementation incorrectly sets safe and finalized heads to the unsafe head after initial sync, rather than respecting L1 finalization.
  - Three options were discussed: setting safe/finalized to genesis (simplest, but slow), setting safe/finalized to `unsafe head minus sequencer window` (better UX, maintains correctness), or allowing external sourcing of safe/finalized heads (best UX, but complex and relies on trusted values).
  - Option 2 was highlighted as a reasonable balance between correctness and UX, though it still requires derivation time.

- **[tracking]: Review kona-interop block hash oracle** [#18288](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18288)
  - The discussion focused on ensuring an integration/acceptance test exists to verify block hash lookups prior to the current history window.
  - It was noted that an existing action test covers this case, and the goal is to transition this to an acceptance test using `op-supernode`.
  - Suggestions were made to use `presets.WithTimeTravelEnabled()` and `sys.AdvanceTime` in acceptance tests to generate sufficient chain history for testing.

- **non-terminating CI job: memory-all-opn-op-geth** [#19563](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19563)
  - The issue was reopened as the `memory-all-opn-op-geth` job hung again, with `TestChallengerPlaysGame` and `TestProposer` in `interop/proofs` hitting the 2-hour subtest timeout.
  - These specific test flakiness issues are now being tracked individually in [#19672](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19672) and [#19673](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19673).
  - Previously, a root cause for other timeouts in this job was identified as RPC calls hanging due to CI resource contention, and a fix was proposed to ensure RPC calls respect per-wait timeouts.

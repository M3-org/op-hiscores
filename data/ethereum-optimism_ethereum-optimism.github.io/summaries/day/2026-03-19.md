## ACTIVE ISSUES

### Flaky Interop Fault Proofs Test
Discussion on [#19656](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19656) (Flaky: TestInteropFaultProofs_ConsolidateValidCrossChainMessage) continued with ajsutton providing a detailed root cause analysis and a fix. The flake was attributed to a race condition in `op-service/testutils/tcpproxy/proxy.go` where `handleConn` held a mutex while dialing upstream, preventing `Close()` from properly tracking connections during test cleanup. This led to untracked goroutines blocking and causing test timeouts. A fix PR was created to release the mutex before dialing and check `p.stopped` before registering connections.

### `op-node` Initial EL Sync UX and Correctness
The discussion on [#17631](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/17631) (op-node: On the Initial EL Sync UX and Correctness) saw significant input from pcw109550 and trianglesphere. pcw109550 reiterated that the current implementation is incorrect as it sets safe and finalized heads to the unsafe head after initial EL sync, rather than respecting L1 finalization. Three options were discussed for initializing safe/finalized heads:
1.  **Set to genesis:** Simplest but requires long derivation.
2.  **Set to (unsafe head minus sequencer window):** Balances correctness and UX, requiring ~12 hours of derivation.
3.  **External source:** Best UX but adds complexity and trust assumptions.
Option 2 was favored as a reasonable balance.

### Review of `kona-interop` Block Hash Oracle
Discussion on [#18288](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18288) ([tracking]: Review kona-interop block hash oracle) focused on ensuring an integration/acceptance test for looking up blocks prior to the current history window. ajsutton suggested moving the existing action test to an acceptance test and leveraging `op-acceptance-test`'s time travel capabilities (`presets.WithTimeTravelEnabled()` and `sys.AdvanceTime`) to generate sufficient chain history for testing.

### Non-terminating CI Job: `memory-all-opn-op-geth`
Issue [#19563](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19563) (non-terminating CI job: memory-all-opn-op-geth) was reopened after the job hung again. ajsutton provided a detailed root cause analysis, identifying a mutex deadlock in `VirtualNode` during shutdown. This deadlock occurred when `VirtualNode.Start()` held a mutex while calling `OpNode.Stop()`, which in turn waited for the event system to drain, while the event system itself tried to acquire the same mutex. A fix PR was created to address this by releasing the mutex before calling `inner.Stop()` and adding a defensive timeout to `Supernode.Stop()`.

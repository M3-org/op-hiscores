## ACTIVE ISSUES

*   **Kona-Interop Block Access Review** ([#19266](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19266))
    *   Discussion continues regarding the handling of internally created blocks during Kona-proofs interop validation. The latest comments clarify that while the specific issue of re-querying replaced non-canonical blocks is not a concern due to overwriting references, a separate issue was discovered: when a block is replaced, its generated receipts are not stored, which can cause consolidation failures if other messages reference the deposit-only block. A test is being written to confirm this.
*   **SDM Specifications** ([#20182](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20182))
    *   The latest comment provides a reference to a pull request in the `design-docs` repository, indicating ongoing work to add SDM specifications to `specs.optimism.io`.
*   **Flaky Test: `TestSequencingWindowExpiry`** ([#20212](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20212))
    *   Investigation into this flaky test has led to a draft fix. The root cause was identified as a race condition between two writers in `OpProofsExEx` (`rust/op-reth/crates/exex/src/lib.rs`), leading to an `OutOfOrder` error and sequencer shutdown. The fix involves adding a write lock to `OpProofsExEx` to eliminate the fatal race. Follow-up actions include addressing the lack of a regression test and a potential state-machine smell related to `sync_target_tx` not being reset.
*   **SDM: Move PoC2 Functionality to `develop`** ([#20216](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20216))
    *   A pull request has been opened and is awaiting review to move the PoC2 functionality into the `develop` branch.
*   **Missing Finalized Docker Image Tags** ([#20228](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20228))
    *   Users are reporting missing finalized Docker image tags for `op-reth v2.1.0`, `op-node v1.16.13`, and `kona-node v1.3.0`. The build for these tags failed. As a temporary workaround, users are advised to use the `-rc.1`-suffixed Docker images, which were built from the same commit. The release notes have been updated, and a fix is expected in the next release later this week.

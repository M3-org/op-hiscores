## CLOSED ISSUES

**Node Synchronization Protocol Deprecation**
Issue [#14108](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/14108), concerning the removal of `req-resp` p2p sync in `op-node`, was closed in favor of a new issue in the protocol team repository. This change aims to resolve sync problems associated with the older `req-resp` protocol.

**Flaky Test Resolution**
Issue [#20254](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20254), reporting a flaky `TestRelayWithInvalidMessagesSteady` test due to transient EL dial timeouts, was closed. A draft fix has been opened in `ethereum-optimism/optimism#20255` to address the root cause, which involved the sampler goroutine not properly handling non-context errors during dial timeouts.

## NEW ISSUES

**Sequencer LightCL Engine Reset Issue**
A new issue, [#20294](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20294), was opened to report that the `op-node` configured as a "sequencer LightCL" performs a needless engine reset on every restart, which may lead to EL heads rewinding. This issue is related to [#20295](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20295).

## ACTIVE ISSUES

**Kona Interop Block Access Review**
Discussion on [#19266](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19266) continues regarding the review of access to internally created blocks during Kona-proofs interop validation. The latest comments from Inphi confirm that replacement block receipts are accessed during consolidation, even if the original block was invalid. A test has been created to confirm this behavior. A separate issue was identified where generated receipts for replacement blocks are not stored, potentially causing consolidation failures if deposit-only blocks are referenced by other messages.

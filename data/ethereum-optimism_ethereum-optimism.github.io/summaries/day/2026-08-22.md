## ACTIVE ISSUES

Discussion on [#22636](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22636) ("op-supernode: observations from mirroring its behaviour in lokahi") continued with significant insights into discrepancies between the Dafny model and the Go implementation of `op-supernode`, as well as identified "sibling gaps" in `kona-node`.

**Discrepancies between Dafny Model and Go Implementation:**
A detailed comment from "claude" on August 23rd, 2026, at 00:18 UTC, outlined several points where the `op-supernode`'s Go implementation deviates from its Dafny model. Key observations include:
- **Message Verification:** The Go implementation silently skips verification for executing messages in the first sealed block, a behavior that violates the Dafny model's intent for comprehensive verification.
- **Same-Timestamp Initiating Messages:** The model requires the frontier view for same-timestamp messages, while Go falls through to the logsDB. The Go approach is considered more robust for varied block times.
- **Frontier View Correctness:** The model assumes the correctness of the frontier verification view, an axiom not explicitly checked in the Go implementation.
- **Logs Store Axiom Violation:** The Go implementation's virtual-parent first-block seal violates an axiom in the `UpdatedLogsDB` model.
- **Rewind Plan Generation:** Go's `buildRewindPlan` produces plan shapes that the Dafny model's `ValidRewindPlan` cannot express, suggesting the model needs generalization.
- **Rewind Apply Order:** The model applies rewind by resetting chain engines before logsDB steps, while Go resets engines after store rewinds, which could lead to non-idempotent behavior under partial failure.
- **Round Observation Flags:** Go uses a two-flag L1 split (`L1NeedsRewind` and `L1Consistent`) for `observeRound`, which has no direct analog in the model, and `obs.L2sConsistent` is never set in Go, making its gated obligations vacuously discharged.
- **`checkChainsReady` Assumption:** The model assumes a single-block advance for `OptimisticAt` in `checkChainsReady`, which is not checked in Go.
- **VerifiedDB Commit:** The model requires a strictly-next timestamp for `VerifiedDB.Commit`, whereas Go allows idempotent replay, crucial for WAL crash-recovery.
- **VN Freeze during Invalidation:** The Go implementation includes a validation node freeze during invalidation to prevent race conditions, a critical lifecycle aspect not modeled in Dafny.
- **I/O Error Paths:** The model axiomatically assumes no failure for operations like `ProcessBlock`, while Go's implementations can fail midway, leading to partially-written states that the model's invariants cannot describe.

**Sibling Gaps in `kona-node`:**
Earlier comments from "claude" on August 22nd, 2026, highlighted two significant gaps in `kona-node`'s RPC implementation compared to `op-node`:
- **Missing `superroot` Namespace:** `kona-node` lacks the `superroot` RPC namespace that `op-node` registers unconditionally. This means that dispute infrastructure pointing at a standalone `kona-node` will encounter "Method not found" errors when expecting `superroot` functionality.
- **Missing `opstack` Block-Building Namespace:** `kona-node` does not implement the experimental `opstack` block-building namespace (`opstack_openBlockV1`, `sealBlockV1`, etc.) that `op-node` provides. This leads to "Method not found" errors when the `op-test-sequencer` attempts to build blocks through `kona-node`'s CL, causing test failures.

**CI Job Naming and Reporting Issues:**
A comment from "claude" on August 21st, 2026, at 22:54 UTC, detailed issues with a CI job named `memory-all-kona-lokahi-op-reth-<fork>` that was actually running `op-supernode` instead of `lokahi`. This led to false-green results and misinterpretations of `lokahi`'s performance. The comment suggests two lessons: `test -x` on a binary does not guarantee it ran, and green runs should accurately name the implementation measured. These issues are being addressed in [#22639](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/22639).

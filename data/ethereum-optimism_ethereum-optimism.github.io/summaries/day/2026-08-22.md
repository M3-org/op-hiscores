## ACTIVE ISSUES

### Observations from mirroring `op-supernode` behavior in `lokahi` [#22636](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22636)
Discussions continued regarding discrepancies and observations found while mirroring `op-supernode`'s functional behavior in `lokahi`. Key points from the latest comments include:
- **`opstack` Block-Building Namespace Gap**: It was noted that `kona-node` does not implement `op-node`'s `opstack` block-building namespace (`opstack_openBlockV1`, `sealBlockV1`, etc.), leading to "Method not found" errors when `op-test-sequencer` attempts to drive block building. This is considered a real feature gap for CL-side block building.
- **`superroot` Namespace Gap**: `kona-node` also lacks the `superroot` namespace present in `op-node`'s RPC, which could cause "Method not found" errors for dispute infrastructure pointing at a standalone CL's RPC when running under `l2cl_kind=kona-node`.
- **Residual Case after Stability Gate**: A deep post-commit L1 reorg that resets derivation below the first stable `SafeDB` entry can still permanently halt verification, mirroring existing `op-supernode` behavior.
- **Misleading Job Name in CI**: A detailed observation highlighted that the CI job `memory-all-kona-lokahi-op-reth-<fork>` was actually running `supernode_kind: op-supernode` instead of `lokahi`, leading to false-positive green runs for `lokahi`. This issue is being addressed in [#22639](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/22639) by renaming the job and ensuring the measured implementation is reported.

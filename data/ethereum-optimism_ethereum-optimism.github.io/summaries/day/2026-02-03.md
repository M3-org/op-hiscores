## ACTIVE ISSUES

### op-node: Initial EL Sync UX and Correctness ([#17631](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/17631))
Discussion continues on the behavior of `op-node` marking the reached target as finalized after initial EL Sync, even if the block is not actually finalized. The latest comments suggest that Snap Sync should follow the finalized L2 as a maximum target to ensure correctness. There's also a debate on whether derivation can be run from a prior L1 block with consolidation to verify alignment with the EL-synced unsafe chain, and the need to fix code to only advance the unsafe ref while keeping safe and finalized at genesis.

### op-supernode: SuperRoots for the unsafe ([#19059](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19059))
The discussion revolves around whether `op-supernode` should return super roots for unsafe data when fetching via `atTimestamp` fails due to a lack of verified or safe data. The key question is the expected verification work on this unsafe data. It was clarified that the "super root" returned in this case would be purely mechanical, carrying no semantic meaning or assumption of valid data, only that it was observed by the supernode. The scope of this issue regarding data prior to the safe head db starting point is also being considered.

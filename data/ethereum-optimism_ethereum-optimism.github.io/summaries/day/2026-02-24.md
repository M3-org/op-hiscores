## ACTIVE ISSUES

### Superchain Interoperability and Root Updates
Discussion on [#19180](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19180) regarding "op-supernode: Superroot SLA Updates" highlighted that the SLA for the Superroot object is ill-defined and not behaving as expected. A recent comment from axelKingsley suggests that Optimistic Roots should be best-effort, and any unavailable roots should either be excluded or included with empty values.

### Batcher Functionality and Ordering
On [#18507](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18507), "op-batcher [altda]: handle post-holocene ordering in concurrent mode," kien-rise commented that this issue is related to a pull request in the main Optimism repository ([#13169](https://github.com/ethereum-optimism/optimism/pull/13169)), indicating ongoing work to address how the `op-batcher` handles ordering in concurrent modes, particularly concerning post-holocene events.

### RPC Performance and Memory Management
Issue [#769](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/769), "RPC Performance: Prevent eth_getLogs memory exhaustion (Upstream Geth fixes available)," was closed by locoholy as a duplicate of [#768](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/768). This issue described how `op-geth` is vulnerable to `eth_getLogs` memory exhaustion, similar to upstream `go-ethereum`, which can lead to OOMs on RPC nodes due to unbounded state scans.

## ACTIVE ISSUES

### Flaky Test: TestPreinteropFaultProofs_VariedBlockTimes
Discussion on this flaky test continued with a re-opening of the issue after a new failure with a different root cause. The new root cause was identified as an assertion failure in `advanceUnsafeToTimestamp` due to `endTimestamp` being computed from `LocalSafeL2.Number + 1` while the unsafe head could be several blocks ahead. A fix has been submitted to reorder `freezeChains` to drain `LocalSafe` up to `LocalUnsafe` before stopping batchers, ensuring `LocalSafe == LocalUnsafe` for subsequent operations. ([#19804](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19804))

### Flaky test: `TestChallengerRespondsToMultipleInvalidClaims`
A new flaky test was reported and a fix has been opened. The root cause was identified as a race condition where the test's `Create` call for a game could revert with `GameAlreadyExists` if the `safeTimestamp()` landed on a value the op-proposer had already used. The fix introduces a `presets.WithoutHonestProposer()` option to prevent proposer races in tests that don't exercise the proposer. ([#20574](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20574))

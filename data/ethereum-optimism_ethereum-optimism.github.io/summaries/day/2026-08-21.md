## ACTIVE ISSUES

### Kona Node Service: EngineActor becomes ChainController ([#22527](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22527))
Discussion on this issue focused on the renaming of `EngineActor` to `ChainController` and extending its functionality. Key points from the latest comments include:
*   A read-only query handler was opened in a new PR, with detailed notes on its implementation. The atomicity of the L2 block and L1 key pairing was confirmed to be achieved by the pairing living in the state and a single borrow, not requiring new synchronization.
*   The Go side's `OptimisticAt` function was identified as having a structural gap in atomicity, despite comments suggesting it as a fix.
*   The query handler's response for timestamp queries was clarified to have four distinct verdicts (ahead, head's timestamp, behind, below L2 genesis) to avoid misinterpretations.
*   An incidental fix was made to `engine.mdx` to correct an outdated snippet.
*   Earlier discussions highlighted that the `descends-from-local-safe` check cannot live in the controller due to potential race conditions and was implemented as a predicate on `InsertTask`.
*   The query handler was deferred, with the L2→L1 pairing needing to be recorded in `kona-engine`'s sync state rather than the `ChainController` due to complexities in queue order, partial drains, and cases where no L1 key is available.

### Kona Node Service: shared single-chain composition entry point ([#22530](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22530))
Notes from the implementation of this issue were provided:
*   The key to reusability was splitting `RollupNode::start` into `compose` (connecting actors) and `run_actors` (spawning actors), rather than just extracting wiring.
*   `spawn_and_wait!` was refactored from a macro to handle N chains with different error types.
*   The L1 watcher is deliberately not part of a chain's composition, allowing a multi-chain host to share it.
*   `RollupNode` remains the per-chain unit to avoid duplicating configuration fields.
*   Spawn order changed but is not expected to cause issues.
*   A sequencing note for [#22532](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22532) highlighted that it will be a merge point for several parallel branches.
*   A gap was identified: a dying actor cannot say which chain it belonged to, which will become problematic with N chains.

### Lokahi: N-chain service composition and config ([#22532](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22532))
This issue was landed as a new PR, enabling `lokahi node --config <file>` to run N chains in one process. Key aspects of the implementation and decisions include:
*   One `RollupNode::compose` per chain, all actors under a single `run_actors` call, and one L1 watcher over every chain's `L1WatcherPorts`.
*   Layered config (global + per-chain overlay), per-chain data directories, RPC sockets, and metric registration.
*   The L1 head watch is now published per chain, and the RPC `current_l1` reads the chain's own watch.
*   `RollupNode::build_l1_watcher` became `L1Config::l1_watcher(Vec<L1WatcherPorts>)`.
*   The engine's chain ID now runs through the promotion path.
*   A latent test bug related to chain-label assertions was fixed.
*   `NodeActor::Error` now includes chain labels for better debugging in multi-chain setups.
*   A hand-off for [#22533](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22533) was noted regarding the CI job for `lokahi` binaries.

### op-devstack: sysgo component and admin/test RPC for lokahi ([#22533](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22533))
This issue landed a new PR for the sysgo component and the first slice of the admin/test RPC.
*   The 2-chain smoke test is now in `op-acceptance-tests/tests/supernode/lokahi` and runs in every acceptance variant. A faster stub-backed version runs in `rust/lokahi/tests/two_chains.rs`.
*   The admin/test RPC includes `lokahi_chains` and `lokahi_version` on a process-wide socket.
*   Two blocking issues were found and handled: `NetworkConfig::new` causing `GossipsubCreationFailed` and `lokahi` not being a workspace default member.
*   Two gaps remain: shared-supernode presets still turn lokahi away, and lokahi cannot resolve a chain's unsafe block signer from its `SystemConfig` contract.

### Lokahi: cross-safe promotion lifecycle and finality ([#22537](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22537))
This issue was implemented in a new open PR.
*   The main gap was wiring the interop verifier into the node; `lokahi` now depends on `lokahi-interop`.
*   Promotions route through kona's existing external promoter entry point, ensuring the interop actor is the only cross-safe writer for that chain.
*   `kona-safedb` now has a writer, recording paired local-safe advances and rewinding across resets.
*   Interop activation is all-or-nothing across the hosted set; anything in between is a startup error.
*   A decision was deliberately left to the team regarding clamping internal actor writes versus rejecting them.
*   A suspected finality gap was confirmed not to exist, as L2 finality is gated.

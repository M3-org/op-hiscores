# ethereum-optimism/ethereum-optimism.github.io Monthly Report (January 2026)

## 🚀 Highlights
In January 2026, development focused on hardening the OP Stack's resilience against L1 reorgs and refining interoperability interfaces. Significant technical discussions centered on resolving critical bugs in the `eth_simulatev1` RPC method and correcting L1 origin selection logic within the Kona stack. Beyond protocol stability, the project continued to expand its ecosystem footprint through the integration of new token assets across Base and Celo networks, while clarifying compatibility standards for minimal contract deployments on the OP Stack.

## 🛠️ Key Developments
While much of the month was dedicated to architectural discussions and troubleshooting, the following areas saw active pull request activity:

### Ecosystem Expansion & Token Integration
The project continues to serve as a registry for the growing Superchain ecosystem, with several PRs focused on asset availability:
*   **Base Network:** Integration of the DUAL token ([#1252](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1252)) and the DeepNode token ([#1253](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1253)).
*   **Celo Network:** Addition of liquid staking tokens, specifically weETH and wstETH, to the Celo network addresses ([#1251](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1251)).

## 🐛 Issues & Triage
The month was characterized by deep-dive investigations into protocol-level synchronization and simulation issues.

### Closed Issues
*   **OP Stack Compatibility:** Developers resolved concerns regarding the compatibility of Base-style minimal contracts ([#18709](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18709)). The resolution confirmed that standard smart contracts are supported, pointing contributors toward documentation that highlights specific differences between L2 and L1 Ethereum environments.

### New & Active Issues
*   **L1 Reorg Handling in Kona:** A critical analysis is underway regarding L2 reorgs triggered by L1 reorgs ([#18676](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18676)). The team identified that Kona’s L1 Origin Selector can cache stale values and lacks a proper reset mechanism. Proposed fixes include aligning Kona's logic more closely with the robust handling found in `op-node`.
*   **RPC Reliability (`eth_simulatev1`):** Investigation continues into a regression since the Jovian fork where `eth_simulatev1` fails due to missing deposit transactions ([#739](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/739)). This is a high-priority issue as it impacts backrunning strategies across the OP Stack.
*   **SyncStatus Accuracy:** Discussions are ongoing to fix the `optimism_syncStatus` endpoint ([#18673](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18673)), which currently points to the L1 head rather than the derivation cursor.
*   **Interoperability Interfaces:** The `IDisputeGame` interface is being extended with a `rootClaim` method to better support interop requirements ([#18516](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18516)).

## 💬 Community & Collaboration
The month showed strong collaborative troubleshooting between core maintainers. Notable interactions included:
*   **Technical Peer Review:** Maintainers like **ajsutton** and **op-will** provided critical feedback on RPC logic and interface extensions, ensuring that fixes for the `eth_simulatev1` issue and `syncStatus` align with broader design documents.
*   **Cross-Project Coordination:** Discussions frequently referenced the `op-geth` and `op-node` repositories, demonstrating the tight integration required between the documentation/frontend layer and the underlying protocol implementations.
*   **Contributor Guidance:** The closure of compatibility issues ([#18709](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18709)) highlights an active effort to guide external developers on the nuances of deploying to the OP Stack.

# ethereum-optimism/ethereum-optimism.github.io Weekly Report (Aug 9 - 15, 2026)

## 🚀 Highlights
This week focused on significant advancements in the State Bloat Mechanism (SDM) and critical maintenance of the OP Stack's node infrastructure. The team successfully verified SDM performance benchmarks on the `sdm-net-0` testnet, demonstrating substantial gas savings for warm-access workloads without execution overhead. Efforts also centered on refining documentation for `op-reth` and resolving stability issues within `op-supernode` and P2P networking. Additionally, the circulating supply was updated to reflect the latest ecosystem figures, ensuring transparency for the Optimism Collective.

## 🛠️ Key Developments

### State Bloat Mechanism (SDM) Progress
The development of the State Bloat Mechanism saw major milestones this week, moving from implementation toward comprehensive verification.
*   **Performance Benchmarking:** Baseline benchmarks on `sdm-net-0` confirmed that SDM provides significant gas savings for workloads heavy on warm-access, while maintaining neutral performance for payload building and execution.
*   **Continuous Testing:** A standing workload was successfully implemented on `sdm-net-0` to continuously exercise the mechanism and ensure long-term stability ([#22343](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22343)).
*   **Monitoring Infrastructure:** SDM-specific dashboards were integrated into OPE Grafana, providing real-time visibility into the mechanism's impact on the network ([#22345](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22345)).

### Node Infrastructure & Documentation
Updates were made to ensure the OP Stack remains compatible with current software releases and network configurations.
*   **`op-reth` Configuration:** Missing hardfork override flags for Superchain nodes were addressed, ensuring `op-reth` users have the necessary tools for network transitions ([#20224](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20224)).
*   **Documentation Cleanup:** Outdated startup examples using Base-related parameters were removed from `op-reth` and `op-node` documentation, as Base is no longer supported with the current software versions ([#20597](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20597)).

### Ecosystem Transparency
*   **Circulating Supply:** The circulating supply was updated to **2,287,994,831**, synchronized with the latest maintained financial records ([#1348](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1348)).

## 🐛 Issues & Triage

### Closed Issues
*   **`op-supernode` Stability:** A critical issue where the invalidation recovery process entered a repeated reset cycle was resolved through recent PRs, preventing potential node downtime ([#21948](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/21948)).
*   **SDM Verification:** Several issues related to the initial setup and verification of SDM workloads and dashboards were closed following successful testnet deployment.

### New & Active Issues
*   **P2P Networking Flakes:** A new issue was opened to track `TestP2PFull` failures, which have occurred 6 times in the last 14 days ([#22381](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/22381)). Initial investigations suggest a race condition during disconnect/reconnect cycles, but a definitive root cause remains elusive.
*   **Testing Constraints:** Discussion continues regarding SDM test coverage in `rust/kona/tests/proofs` ([#21344](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/21344)). The team is weighing whether to close this issue, as the `op-geth` action-test engine currently lacks the SDM support required for combined scenario testing.

## 💬 Community & Collaboration
The week's activity highlights a strong focus on cross-component coordination, particularly between the SDM development team and the infrastructure monitoring team. The investigation into the `TestP2PFull` flake demonstrates a rigorous approach to CI/CD health, with contributors opting for improved logging and bounded test fixtures rather than applying "narrow" fixes that do not address the underlying race conditions. Documentation updates also reflect a commitment to maintaining a high-quality developer experience by removing deprecated parameters that could lead to user confusion.

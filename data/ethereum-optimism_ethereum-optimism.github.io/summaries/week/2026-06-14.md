# ethereum-optimism/ethereum-optimism.github.io Weekly Report (Jun 14 - 20, 2026)

## 🚀 Highlights
This week’s activity focused on refining the technical infrastructure for ZK-based dispute games and maintaining ecosystem data accuracy. Significant progress was made in streamlining the development workflow for ZK proofs, with a shift toward using mock provers for CI to manage costs. Additionally, the project addressed critical bond credit claiming logic within the `ZKDisputeGame` and updated core ecosystem metrics, including the circulating supply and token listings on Base.

## 🛠️ Key Developments
While no major technical features were fully merged during this period, several pull requests were initiated to maintain the ecosystem's data integrity and financial transparency.

### Ecosystem Data & Token Management
- **Circulating Supply Update:** A new pull request was opened to update the circulating supply to 2,156,237,058, ensuring accurate financial reporting for the Optimism Collective ([#1330](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1330)).
- **Base Token Integration:** Work began on adding the SINC token to the Base network registry, expanding the supported asset list within the Superchain ecosystem ([#1329](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1329)).

## 🐛 Issues & Triage
The week saw a strategic reorganization of how ZK-related issues are tracked, moving specific implementation tasks to the primary `optimism` repository while maintaining high-level architectural discussions here.

### Closed Issues
- **Bond Credit Claiming:** Issues [#19743](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19743) and [#21420](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/21420), which addressed how `ZKDisputeGame` handles `address(0)` bond credit claiming, were closed. These tasks have been migrated to the main `optimism` repository for better alignment with the core protocol development.

### Active Issues
- **ZK Proof Strategy for CI/Local Dev:** Discussion continues on the optimal proof mechanism for development environments ([#21409](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/21409)). The current consensus leans toward using a mock prover for CI due to the high computational cost of generating actual proofs, while reserving op-sepolia for testing fast-finality paths.
- **VM-Runner ZK Support:** Efforts to update the `vm-runner` to support ZK execution are ongoing ([#18325](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18325)). Contributors are exploring ways to extract proposer logic to minimize code bloat and are debating whether to embed a Rust-based executor within Docker images.

## 💬 Community & Collaboration
Collaboration this week was characterized by cross-repository coordination. The decision to move specific ZK implementation bugs to the core `optimism` repository suggests a tightening of the workflow between documentation/ecosystem tracking and protocol engineering. Technical discussions regarding ZK execution ([#18325](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18325)) show active engagement in optimizing the developer experience by balancing the need for Rust-based execution with the constraints of existing CI/CD infrastructure.

# ethereum-optimism/ethereum-optimism.github.io Weekly Report (May 3 - 9, 2026)

## 🚀 Highlights
This week focused on stabilizing interoperability (interop) functionality and refining developer tooling ahead of major releases. Significant progress was made in stress testing the interop expiry window, where live devnet testing successfully identified and resolved a critical Kona EIP-2935 proof decoding bug. The team also streamlined the Superchain ecosystem's growth by finalizing policies for new chain deployments and improving the efficiency of prestate builds. Overall, the week's activity transitioned from feature development toward rigorous validation and security monitoring.

## 🛠️ Key Developments
While the repository primarily serves as a coordination and documentation hub, several technical milestones were reached regarding the underlying OP Stack infrastructure and ecosystem expansion.

### Ecosystem Expansion
- **New Asset Integration:** A new pull request was opened to add the ET10 (EventTrader 10 Index) on Base, continuing the expansion of the Superchain's financial ecosystem ([#1312](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1312)).

### Developer Tooling & Testing Improvements
- **Kona Prestate Builds:** The process for building Kona prestates was optimized to allow builds outside of Docker environments. While this improves speed and flexibility, the team noted that Mac support for linux/mips64 targets remains an ongoing technical challenge ([#19057](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19057)).
- **Test Migration:** The migration of "after head" tests to `op-supernode` and `op-acceptance-test` was completed. This migration was instrumental in discovering and fixing a bug within the supernode implementation ([#20370](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20370)).

## 🐛 Issues & Triage
The week saw a high volume of issue resolution, particularly around defining the architectural boundaries for interoperable chains.

### Closed Issues
- **Interop & Supernode Functionality:** A key architectural decision was reached regarding chain creation: new chains will be deployed into their own dependency sets of one, with L2 genesis supporting interop by default ([#15884](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/15884)). Additionally, the requirement for SuperRoots for unsafe data in `op-supernode` was closed as "won't fix" following the implementation of a testing workaround ([#19059](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19059)).
- **Triage & Cleanup:** Several issues were consolidated or closed as duplicates, including a fix for `SuperPermissionedGameType` prestate URLs ([#20500](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20500)) and L2CM acceptance testing on Betanet ([#20089](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20089)).

### New & Active Issues
- **Security Monitoring:** A new tracking issue was established for Wiz 'master' branch scans, ensuring continuous security oversight of the repository's main branch ([#1311](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/1311)).
- **Interop Stress Testing:** Ongoing discussions in [#15285](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/15285) revealed that interop validation costs scale linearly with message count (approx. 5.77M VM steps per message). Following a fix for RLP decoding, the team expressed confidence that performance is bounded by L2 gas limits rather than interop validation logic.
- **Documentation Deferral:** Updates to the runbook for transitioning super root chains from permissioned to permissionless were deferred until after the interop launch, as they are not considered blockers for the current release ([#20473](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20473)).

## 💬 Community & Collaboration

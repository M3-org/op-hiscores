# ethereum-optimism/ethereum-optimism.github.io Weekly Report (Jan 25 - 31, 2026)

## 🚀 Highlights
This week focused on refining the post-Holocene and Fusaka upgrade landscapes, with a heavy emphasis on protocol configuration and deployment tooling. Key progress was made in documenting gas management strategies and addressing technical debt within the `op-deployer` and `op-supernode` components. While some interoperability tasks were placed on hold pending broader architectural shifts, the team successfully closed several legacy issues and advanced the design for sequencer-defined metering, setting the stage for upcoming devnet milestones.

## 🛠️ Key Developments

### Protocol Documentation & Configuration
Efforts were concentrated on providing clarity for chain operators navigating recent upgrades.
*   **Gas Management:** A significant documentation update was completed to guide operators on changing gas configuration values (target and limit) post-Holocene ([#1944](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/1944)).
*   **EIP-1559 Refinement:** Technical discussions advanced on ensuring `op-alloy` correctly handles EIP-1559 parameter decoding, specifically catching zero elasticities to ensure early failure and protocol stability ([#18951](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18951)).

### Infrastructure & Deployment Tooling
The project continues to evolve its deployment and monitoring stack for the Superchain.
*   **OPCM v2 Expansion:** Following the functional updates to `op-deployer`, work has begun to expand OPCM v2 support across the broader package ecosystem ([#18942](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18942)).
*   **Supernode Monitoring:** The interface for the `op-supernode` SyncStatus API was defined. It will now provide a comprehensive view of the sync status for every chain and verification activity, including L1 interop timestamps, to streamline acceptance testing ([#18947](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18947)).
*   **Token Integration:** New pull requests were submitted to expand the ecosystem's asset support, including XRAY (Base) ([#1256](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1256)) and BADGER ([#1257](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1257)).

## 🐛 Issues & Triage

### Closed Issues
*   **Devnet Testing:** Issue [#18755](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18755) regarding acceptance tests on the Glamsterdam devnet was closed. The process identified critical blockers in custom L1 tooling and RPC consistency, which will be addressed in follow-up tasks.
*   **Technical Debt Cleanup:** Several obsolete tasks were cleared, including the removal of redundant OPCM v2 checks ([#18536](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18536)) and the deletion of outdated resource locators for v7.0.0 artifacts ([#18633](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18633)).

### New & Active Issues
*   **Fusaka Compatibility:** A known issue in `op-deployer` ([#17912](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/17912)) involving high transaction gas limits due to EIP-7825 remains active. Users are currently advised to use the `v0.5.0` release candidate for alt-da configurations.
*   **Sequencer Metering:** The design doc for Sequencer-Defined Metering ([#360](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/360)) is currently blocked by the initial Proof of Concept (PoC), with a devnet deployment targeted for late January to facilitate benchmarking.
*   **Withdrawal Mechanism:** Proving withdrawals via chain-specific root claims ([#18517](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18517)) has been moved to the backlog to avoid delaying user withdrawals during the upcoming U19 execution.
*   **Interoperability Blockers:** Work on Super DA errors ([#725](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/725)) is officially "on ice" until the new interoperability design is finalized.

## 💬 Community & Collaboration
The week saw active engagement from community members, particularly regarding the `op-alloy` decoding logic, where a contributor stepped forward to handle the EIP-1559 parameter fixes. Discussions between maintainers (such as `sbvegan`, `geoknee`, and `emhane`) highlight a disciplined approach to sequencing upgrades, ensuring that protocol changes like the Fusaka hardfork or new interop designs do not disrupt existing user flows or withdrawal safety.

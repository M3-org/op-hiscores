# ethereum-optimism/ethereum-optimism.github.io Weekly Report (May 24 - 30, 2026)

## 🚀 Highlights
This week, the Optimism ecosystem focused heavily on protocol stability and code hygiene, marked by a systematic reopening of issues to address lingering TODOs identified by CI checks. Significant engineering effort was directed toward diagnosing complex synchronization and Engine API failures in `op-reth`, particularly addressing SIGBUS crashes and flaky test regressions. Meanwhile, the ecosystem continued to expand its footprint on Base with new token listings and advanced proposals for enhancing developer tooling and user metrics.

## 🛠️ Key Developments
While no major features were fully merged this week, significant progress was made in ecosystem expansion and infrastructure maintenance:

*   **Ecosystem Expansion & Token Listings**
    *   New pull requests were opened to expand the token offerings on Base, including EFIX RWA tokens (BRLE, sBRLE, efixDI) in [#1322](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1322) and the IRON governance token in [#1323](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1323).
*   **Infrastructure & Tooling Improvements**
    *   A fix for `Dockerfile.bot` was initiated in [#1324](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1324) to ignore lifecycle scripts, streamlining the build process.
    *   Proposals were introduced to support **Deployment Factories** ([#12](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/12)), involving a new `FactoryDependency` link type and `CREATE2` opcode indexing to improve the dependency graph for developers.
*   **User Metrics & Sybil Resistance**
    *   Work began on broadening the **Eval Algo** beyond Farcaster IDs ([#13](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/13)). The proposed blended user score will incorporate Gnosis Pay/KYC attestations and organic on-chain activity to improve ecosystem governance and funding distribution.

## 🐛 Issues & Triage
The week was characterized by a rigorous "cleanup" phase, with a focus on resolving technical debt and intermittent protocol failures.

*   **Closed Issues:**
    *   The team successfully completed the cleanup and deletion of the `op-supervisor` component ([#20124](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20124)).
*   **New & Active Issues:**
    *   **CI-Driven Reopenings:** A large volume of issues (e.g., [#16141](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/16141), [#14129](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/14129), [#19182](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19182)) were reopened due to unresolved TODOs in the codebase. These span Interop activation, `L2ProxyAdmin` refactoring, and event system cleanup.
    *   **`op-reth` Stability:** Critical investigations are ongoing regarding SIGBUS crashes during deep FCU rewinds ([#20934](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20934)) and Engine API stalls in the `TestUnsafeChainNotStalling_CLSync` test family ([#21041](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/21041)).
    *   **Nondeterministic Builds:** A new bug ([#21032](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/21032)) was identified where `generate-semver-lock` produces inconsistent output when multiple Forge artifacts map to the same semver key.
    *   **Supernode Resync:** Work continues on [#20944](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20944) to prevent the premature closing of `verifiedDB` during shutdown, which currently causes issues with finalized block acceptance.

## 💬 Community & Collaboration
Collaboration this week was centered on deep technical troubleshooting between the Optimism and Reth core teams. The adversarial review of test flakiness demonstrated a high level of technical rigor, pivoting from "test budget" theories to identifying genuine Engine API stalls. 

There is also a notable emphasis on security and documentation; the team decided to formalize feature flag update locations in `DevFeatures.sol` ([#20340](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20340)) and issued a security warning regarding the use of AI tools for debugging to prevent the exfiltration of proprietary rollup configurations.

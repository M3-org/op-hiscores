# ethereum-optimism/ethereum-optimism.github.io Weekly Report (Feb 1 - 7, 2026)

## 🚀 Highlights
This week focused on expanding the Superchain's footprint through significant documentation updates and asset integrations, alongside deep technical refinements to the `op-supernode` and `op-node` architectures. Key progress was made in formalizing contribution guidelines and synchronizing supported chain data across the repository's schema and README. Meanwhile, core developers engaged in critical architectural discussions regarding state management for interoperability, specifically addressing "Safe" label consistency and Execution Layer (EL) sync correctness to ensure protocol security as the ecosystem scales.

## 🛠️ Key Developments

### Superchain Ecosystem & Asset Integration
The repository saw a flurry of updates to reflect the growing number of chains and tokens within the Optimism ecosystem.
- **Chain Expansion:** Added nine missing supported chains to the README and internal mappings, including Unichain, Soneium, Swellchain, Ink, and Worldchain (and their respective testnets) ([#1268](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1268), [#1270](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1270), [#1269](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1269)).
- **Token Management:** Integrated the RNBW token ([#1264](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1264)) and initiated PRs for XAN, SKL, and RealGold tokens ([#1266](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1266), [#1276](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1276), [#1275](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1275)).
- **Data Hygiene:** Removed duplicate 'LDO' entries from the default token list ([#1273](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1273)) and updated circulating supply data ([#1277](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1277)).

## 🐛 Issues & Triage

### Closed Issues
- **L1 Polling Fix:** Resolved a critical issue in `op-supernode` where HTTP L1 URLs caused disabled polling, preventing virtual nodes from receiving head updates ([#19012](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19012)).

### New & Active Technical Challenges
- **`op-supernode` State Management:** Discussions are ongoing regarding how to manage "Safe" labels across layers to prevent deadlocks. A proposed solution involves the Consensus Layer (CL) maintaining a full set of pointers (U, S, C, F) to act as the sole engine controller ([#18976](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18976)). Additionally, a new issue was raised regarding the inability to fetch super roots via `atTimestamp` when verified data is missing ([#19059](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19059)).
- **EL Sync Correctness:** A debate continues over `op-node` incorrectly marking initial EL sync targets as finalized. Contributors are weighing whether to restrict snap sync to finalized content or implement derivation-based consolidation to verify the unsafe chain ([#17631](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/17631)).
- **Flashblocks & Tooling:** Community members are exploring merging Flashblocks support into `op-geth` to improve event tracing and reduce disk usage compared to archive nodes ([#756](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/756)).
- **Withdrawal Validation:** A `BlockNotFoundError` in the ETH bridge tutorial highlighted a potential discrepancy between the Optimism SDK and Viem’s withdrawal guides regarding output root validation ([#1956](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/1956)).

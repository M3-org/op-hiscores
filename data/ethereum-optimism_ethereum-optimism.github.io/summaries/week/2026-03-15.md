# ethereum-optimism/ethereum-optimism.github.io Weekly Report (Mar 15 - 21, 2026)

## 🚀 Highlights
This week, the development team focused heavily on enhancing the stability of the CI pipeline and investigating critical node performance issues. A significant effort was made to resolve flaky tests, resulting in the closure of multiple long-standing issues related to race conditions and timeouts. Meanwhile, the community is actively troubleshooting memory leaks and state root mismatches in `op-reth`, particularly on Base and World Chain, while also refining the `op-node` initial sync behavior and expanding `op-supernode` test coverage.

## 🛠️ Key Developments

### Ecosystem Asset Integration
The repository continues to serve as a registry for the growing Superchain ecosystem, with new tokens being integrated into the Base List.
*   **Token Additions:** Pull requests were opened to add the **SYNA** token ([#1287](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1287)) and the **ALIGN** token ([#1288](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1288)).

### Infrastructure & API Refinement
Technical improvements were made to the reporting accuracy of the Supernode and the architectural placement of blob services.
*   **Supernode Reporting:** Fixed an issue where the `superroot_atTimestamp` API was incorrectly reporting the minimum L1 block processed by derivation instead of verified L1 blocks ([#18651](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18651)).
*   **Blob Archiver Migration:** A critical compatibility issue regarding the `/eth/v1/beacon/blobs/` endpoint was identified and moved to the dedicated `blob-archiver` repository to ensure proper beacon fallback for `op-node` ([#19623](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19623)).

## 🐛 Issues & Triage

### Closed Issues: CI Stability and Flaky Tests
A major push on March 17th led to the resolution of several flaky tests that were hampering the CI pipeline. These fixes addressed nonce races, tight timeouts, and concurrent execution conflicts.
*   **Resolved Tests:** Issues [#18137](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18137), [#19588](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19588), [#19583](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19583), [#19586](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19586), [#19589](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19589), and [#19375](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19375).

### New & Active Issues: Node Performance and Sync Logic
*   **op-reth Stability:** Investigation continues into memory leaks caused by database read transactions ([#19212](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19212)) and state root mismatches on Base mainnet ([#19532](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19532)). These issues have caused node crashes on World Chain and Manta Pacific.
*   **Sync UX & Correctness:** Discussion is ongoing regarding `op-node` marking initial EL sync targets as finalized prematurely. A proposal is on the table to use a different finalization gadget to improve reliability ([#17631](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/17631)).
*   **Test Suite Maintenance:** New issues ([#19610](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19610), [#19608](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19608)) were opened to track further flaky tests, while work progresses on deduplicating tests between `op-e2e` and `op-acceptance-tests` ([#19010](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19010)).

## 💬 Community & Collaboration
The week was characterized by high-level technical troubleshooting between maintainers and node operators. There is significant cross-project collaboration, as evidenced by the coordination with the Base team regarding `op-reth` forks and the migration of issues to the `blob-archiver` repository. The community is also actively engaged in refining the "interop" testing framework, specifically focusing on the `kona-interop` block hash oracle and `op-supernode` acceptance tests to ensure the Superchain's interoperability layer remains robust.

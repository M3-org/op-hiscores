# ethereum-optimism/ethereum-optimism.github.io Weekly Report (Feb 22 - 28, 2026)

## 🚀 Highlights
This week, development efforts focused on refining the Superchain’s operational reliability and improving the developer experience (DevX) by addressing protocol-level inconsistencies. Key activities included updates to cross-chain token infrastructure for Celo, Base, and Optimism, alongside critical discussions regarding Superroot Service Level Agreements (SLAs) and batcher ordering logic. The team also prioritized node stability by triaging RPC memory exhaustion vulnerabilities, ensuring that the infrastructure remains resilient as the ecosystem scales.

## 🛠️ Key Developments
While no major technical features were finalized this week, significant progress was made in maintaining the accuracy of the Superchain’s asset layer and preparing for protocol upgrades.

### Ecosystem Asset Management
Work was initiated to ensure consistent token representation across the Superchain. 
*   **WETH Address Updates:** A new pull request, [#1283](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1283), was opened to update WETH token addresses and overrides for Celo, Base, and Optimism, ensuring that developers and users have accurate contract information across these interoperable layers.

### Protocol & Batcher Refinement
Ongoing work continues on the underlying components that power L2 data availability and ordering.
*   **Post-Holocene Ordering:** Technical discussions on [#18507](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18507) indicate active coordination with the main Optimism repository ([#13169](https://github.com/ethereum-optimism/optimism/pull/13169)). The focus is on how `op-batcher` handles concurrent mode ordering following the Holocene upgrade.

## 🐛 Issues & Triage
The week saw a focus on identifying "papercuts" in the developer experience and addressing potential stability risks for RPC providers.

### Closed Issues
*   **RPC Stability:** Issue [#769](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/769) regarding `eth_getLogs` memory exhaustion was triaged and closed as a duplicate of [#768](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/768). This resolution points toward implementing upstream Geth fixes to prevent Out-of-Memory (OOM) errors during unbounded state scans on `op-geth` nodes.

### New & Active Issues
*   **L2 State Root Latency:** A new DevX "papercut" was identified in [#1282](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/1282), highlighting inconsistent latencies in L2 state root verification. This fluctuation creates friction for developers relying on predictable state change confirmations.
*   **Superroot SLA Definitions:** Significant discussion persists on [#19180](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19180) regarding the `op-supernode`. Contributors are debating the expected behavior of the Superroot object, with a consensus forming that Optimistic Roots should be treated as "best-effort" to maintain system liveness even when certain roots are unavailable.

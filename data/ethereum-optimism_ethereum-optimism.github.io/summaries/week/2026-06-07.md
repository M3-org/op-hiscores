# ethereum-optimism/ethereum-optimism.github.io Weekly Report (Jun 7 - 13, 2026)

## 🚀 Highlights
This week focused on streamlining the Optimism protocol stack by finalizing the deprecation of legacy components and enhancing the developer simulation environment. A major theme was the transition from `op-program` to `kona-proof` within CI workflows, signaling a shift toward more modern proof infrastructure. Significant progress was also made in refining developer tooling, specifically around storage layout lookups and proposal simulation accuracy. With the U19 contracts audit now complete, the project is moving toward removing temporary feature flags, further stabilizing the production environment.

## 🛠️ Key Developments
While no new technical developments were initiated this week, the focus remained on refining existing infrastructure and documentation to support the Superchain ecosystem.

### Developer Tooling & Simulation Enhancements
Efforts were concentrated on improving the accuracy of local development tools and the simulation of complex transactions.
*   **Storage & Access Parsing:** Improvements were made to the `AccountAccessParser` to better handle dynamic slot finding ([#1064](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/1064)) and to `tryStorageLayoutLookup` to correctly manage tightly packed variables ([#909](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/909)).
*   **CLI Improvements:** The `just sign-stack` command was updated to ensure owner safe addresses are correctly displayed, improving the developer experience for multisig operations ([#1295](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/1295)).
*   **Simulation Documentation:** Documentation for `NESTED.md` and `SINGLE.md` was updated to integrate two-step simulation links, providing clearer paths for testing governance proposals ([#789](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/789)).

## 🐛 Issues & Triage
The week saw a significant cleanup of the backlog, with a focus on removing technical debt and closing out stale tracking issues.

### Closed Issues
*   **`op-program` Deprecation:** A suite of issues was closed to finalize the deprecation of `op-program`. This included migrating CI jobs to `kona-proof` ([#19789](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/19789)), removing prestate rebuild requirements ([#17867](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/17867)), and ensuring compatibility with go1.25 ([#18334](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/18334)).
*   **Protocol Maintenance:** Several maintenance tasks were resolved, including moving `DisputeGameUpgrade` checks ([#444](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/444)), implementing CI checks for domain hashes in `Validation.md` ([#717](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/717)), and optimizing the execution of multiple proposals via a single command ([#432](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/432)).
*   **Security & Health:** A Wiz security scan of the 'main' branch was completed with no findings reported ([#1411](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/1411)).

### Active Issues
*   **Feature Flag Removal:** A key active discussion ([#20249](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20249)) involves the removal of the `CANNON_KONA` feature flag. Following the completion of the U19 contracts audit, the team is currently awaiting final confirmation to proceed with the removal, which will further unify the proof stack.

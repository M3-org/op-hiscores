# ethereum-optimism/ethereum-optimism.github.io Weekly Report (Apr 26 - May 2, 2026)

## 🚀 Highlights
This week’s activity focused on refining the technical infrastructure of the Superchain, specifically addressing critical stability issues in node upgrades and clarifying configuration logic for dispute monitoring. A significant effort was directed toward diagnosing a non-deterministic panic in `op-reth` upgrades that affects state root computation. Additionally, developers identified potential logic errors in the `op-supernode` verification process, while maintaining project health through essential development dependency updates.

## 🛠️ Key Developments

### Infrastructure & Tooling Maintenance
Work this week focused on keeping the development environment current and ensuring the robustness of the Superchain's node architecture.
*   **Dependency Management:** The project’s development environment was updated by upgrading the `@typescript-eslint/parser` from version 4.33.0 to 6.21.0, ensuring better linting and type-checking capabilities for contributors ([#1309](https://github.com/ethereum-optimism/ethereum-optimism.github.io/pull/1309)).
*   **Dispute Monitor Integration:** Technical clarification was provided regarding the interoperability of `op-dispute-mon` with the Supernode. It was confirmed that a single instance can monitor both CANNON and SUPER_CANNON_KONA games simultaneously by leveraging both `rollup-rpc` and `supernode-rpc` endpoints.

## 🐛 Issues & Triage

### Closed Issues
*   **Configuration Clarifications:** A key issue regarding `op-dispute-mon`'s ability to query supernode Virtual Nodes (VNs) for output roots was resolved. The resolution clarified that `op-supernode` can expose `op-node` RPC endpoints, streamlining the monitoring process for different game types ([#20476](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20476)).

### New & Active Issues
*   **Critical op-reth Upgrade Panic:** A high-priority investigation is underway regarding a fatal panic occurring during the upgrade of `op-reth` from version 1.x to 2.x. The crash occurs in the `StateRootTask` during parallel trie computation. Current findings suggest the issue is a non-deterministic assertion bug in `alloy-trie-0.9.5` triggered by 1.x database states, and notably, the `--engine.legacy-state-root` flag does not mitigate the failure ([#20462](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20462)).
*   **Supernode Verification Logic:** A new concern was raised regarding the `VerifiedRequiredL1` function within `op-supernode`. The current implementation utilizes the minimum of per-chain L1 values, which may incorrectly calculate verification requirements; developers are investigating a shift to using the maximum value instead ([#20481](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20481)).

## 💬 Community & Collaboration
The week was characterized by deep technical troubleshooting between maintainers regarding the `op-reth` state root panic. The discussion in issue [#20462](https://github.com/ethereum-optimism/ethereum-optimism.github.io/issues/20462) demonstrates a highly collaborative effort to isolate a complex bug within the `alloy-trie` dependency. Furthermore, the prompt resolution of configuration queries indicates an active focus on supporting node operators as they navigate the complexities of the Supernode and dispute monitoring systems.
